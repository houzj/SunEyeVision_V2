# 调研报告：节点编辑器"连线跟随节点移动"的架构设计

- **调研日期**: 2026-09-06
- **调研者**: CodeBuddy
- **关联方案**: 连线架构治本重构（多选拖动刚体平移 v2）
- **状态**: 已完成

## 1. 调研背景

SunEyeVision 画布多选拖动连线的实现反复修补（缓存几何挂 Transform 不重绘 → 坐标级平移克隆 → 箭头锚点同步），用户指出"其实是链接线的设计问题"。本调研回答：**成熟节点编辑器/流程图产品里，连线如何随节点移动，批量拖动时怎么处理**，以确定本项目连线架构的正确方向。

## 2. 关键问题清单

1. 连线路径是"端点的派生数据"还是"独立缓存快照"？
2. 节点被拖动时，连线由谁触发更新（拖拽代码挑线 vs 线自己订阅端点）？
3. 批量/分组拖动时，组内连线与跨组连线分别如何处理？
4. 主流 WPF 节点编辑器（Nodify 类）的具体绑定机制？
5. 对我们现有 ConnectionPathCache + 手动 MarkDirty 架构的启示？

**完成判据**: 4+ 业界来源，机制清晰可对比。

## 3. 业界做法调研

### 3.1 Nodify（WPF 开源节点编辑器，技术栈最贴近）
- [来源] 博客园《WPFNodfy》：https://www.cnblogs.com/zt199510/collections/18436
  - 做法: "Source 和 Target 依赖属性是 Point 类型，通常绑定到连接器的 Anchor 点"
  - 关键决策: 连线（BaseConnection）只持有源点/目标点两个 Point 依赖属性，绑定到节点连接器（Anchor）上；节点移动 → Anchor DP 变化 → Source/Target DP 变化 → 线的几何由 WPF 数据绑定自动重算
  - 启示: **连线是两端点的声明式派生**，不需要任何拖拽代码挑线
- [来源] Nodify 仓库：https://github.com/miroiu/nodify（Nodes + Connections 各为 ObservableCollection 的 MVVM 骨架）

### 3.2 React Flow（React 生态主流节点库）
- [来源] https://reactflow.dev/examples/nodes/update-node（官方 Updating Nodes）
- [来源] https://reactflow.nodejs.cn/
  - 做法: 节点 position 与 edges 同在全局 store；Edge 组件通过 store 读两端 handle 绝对位置，路径是其派生值；拖动节点 = 更新 store position → 相关 Edge 自动重算
  - 关键决策: 数据单向流动（状态 → 渲染），不存在"拖拽时手动遍历 edge 缓存刷新"
  - 启示: 用响应式状态（WPF 等价物：绑定/订阅）代替"缓存快照 + 主动失效"

### 3.3 mxGraph / draw.io（流程图引擎）
- [来源] https://jgraph.github.io/mxgraph/docs/js-api/files/view/mxEdgeStyle-js.html（mxEdgeStyle 官方文档）
  - 做法: 边带 mxEdgeStyle（orthogonal 等路由），路由按源/目标顶点驱动；移动 cell 后 framework 使受影响边 reroute，组内边随 cell group 移动
  - 关键决策: "只对受影响边做路由重算" + "组内边随组整体移动"
  - 启示: 本项目"只算跨组边界线"与 mxGraph 同构

### 3.4 Figma / Sketch（设计器多选拖动思想）
- [来源] 业界共识：多选 = 组子场景父级单次变换，组内对象坐标不逐个更新
  - 启示: "拖 N 个 ≈ 拖 1 个"的最终形态

## 6. 结论与建议

### 6.1 业界共识
1. 连线是"端点的派生数据"，不是独立缓存快照——节点位置是源、线是结果；由统一机制（订阅/绑定）驱动自动刷新。
2. 批量拖动 = 组平移：组内相对几何不变；强优化用组整体变换（Figma/mxGraph），弱化版至少"组内线只平移、跨组线 reroute"（已实证可行）。
3. 箭头是线的附着产物，应随线末端/切线从同一派生产出（SVG marker / Nodify 一体几何），而非独立状态手动同步。

### 6.2 对本项目的硬性约束
- 约束 1（应当）：线刷新从 Node_MouseMove 挪出，归属统一连接刷新机制（Connection 订阅端点 或 ConnectivityRefreshService）。
- 约束 2（应当）：线体与箭头同一"渲染产出"（同一分支同步写入），杜绝双派生源。
- 约束 3（应当）：拖组会话（组内线坐标平移零重算 + 跨组 reroute）作为通用加速保留并内聚。
