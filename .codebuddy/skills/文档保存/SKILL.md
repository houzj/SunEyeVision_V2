# 文档保存技能（文档保存）

当你需要把一份 markdown 文档保存到本仓库 `docs/` 时，**必须**先按本技能与 rule-006 完成归类与命名，再写入，最后更新索引。本技能是 rule-006 的落地执行器。

## 触发条件

用户表达以下意图之一即触发：
- 保存/写入/生成/落地一份方案、设计、总结、报告、测试报告、工具设计、框架/架构、指南、参考、配置类文档
- "把这次方案存到 docs"、"生成测试报告"、"记录实施总结"

## 六类目录映射（类型优先 + 年/月/日颗粒度）

> **颗粒度说明**：新增文档统一保存到 `年/月/日` 三级目录；历史存量文档（年/月 两级）原样保留不迁移，新旧两种深度混存自动兼容。

| 类型 | 顶层目录 | 子目录 | 命名模板 |
|------|---------|--------|---------|
| 方案/设计 | `01-方案设计` | `<年>/<月>/<日>/` | `<中文主题>-YYYYMMDD-HHMMSS.md` |
| 实施总结/报告 | `02-实施总结` | `<年>/<月>/<日>/` | `<主题>-实施总结-YYYYMMDD-HHMMSS.md` |
| 测试报告 | `03-测试报告` | `<年>/<月>/<日>/` | `测试报告-<主题>-YYYYMMDD-HHMMSS.md` |
| 工具专项设计 | `04-工具设计` | `<工具类型>/<年>/<月>/<日>/` | `<工具名><核心算法\|UI>设计方案-YYYYMMDD-HHMMSS.md` |
| 框架/架构 | `05-框架架构` | `<年>/<月>/<日>/` | `<主题>架构-YYYYMMDD-HHMMSS.md` |
| 指南/参考/配置 | `06-指南参考` | `guides/\|configs/<年>/<月>/<日>/` | `guide_`/`config_` + 蛇形 + `_YYYYMMDD_HHMMSS.md` |

识别关键词（用于判定类型）：
- 实施总结/实施报告/完成总结/完成报告/功能报告/进度报告/工作总结/报告 → `02-实施总结`
- 测试报告/测试结果/测试分析 → `03-测试报告`
- 使用指南/快速开始/快速运行/快速参考/指南/参考/说明/详解/帮助文档/迁移指南/安装指南 → `06-指南参考/guides`
- 框架/架构/系统架构/软件架构/模块职责/文件结构/依赖关系/架构图/架构总览 → `05-框架架构`
- Git/团队/工作树/Camera/编码规范/构建 等配置 → `06-指南参考/configs`
- 其余方案/设计/计划/优化/重构/治理/绑定/契约/策略 → `01-方案设计`
- 纯英文文件名 → 一律归 `06-指南参考`（蛇形前缀），**禁止**进入 01–05

## 执行步骤

1. **判定类型**：按上表关键词与文件名判定，确定顶层目录与（如有）子目录。
2. **确定年/月/日**：从文件名 `-YYYYMMDD` 取；无则用 `git log --diff-filter=A --format=%ad --date=format:%Y-%m-%d -- <文件>` 取首次入库日期；再无则用文件 LastWriteTime。时间为文件保存时刻（`HHMMSS`）。
3. **套用命名**：中文类带 `-YYYYMMDD-HHMMSS`；指南类用 `guide_`/`config_` 前缀 + 小写蛇形 + `_YYYYMMDD_HHMMSS`。文件名日期时间缺失必须补齐。
4. **创建目录并写入**：确保 `docs/<顶层>/<子目录>/<年>/<月>/<日>/` 存在，写入文件。
5. **更新索引**：运行 `docs/00-索引/更新索引.ps1`（PowerShell，需 `-ExecutionPolicy Bypass`）。
6. **先确认后写**：写入前必须就"类型/目录/文件名"与用户确认（rule-006 原有要求）。

## 禁止

- 禁止在 `docs/` 根散落文件
- 禁止英文文件名进入 01–05
- 禁止 0 字节 / 测试垃圾文档入库
- 禁止手动编辑 `docs/00-索引/文档索引.md`（由脚本生成）

## 与方案类技能协作

`方案设计` / `方案实施` / `方案测试` 技能产出文档后，**必须**调用本技能完成落地保存，确保符合 rule-006。
