| 代码合规审查 | 修改文件 + 调用方 | search_content 检查 rule-014/015/002 等 | 实施完成后 |

## 自检清单（输出前必跑）

```
□ 0. 用户功能性视角（改前/改后/依据）写在最前
□ 1. 方案对比 ≥3 候选 + 长期 ROI
□ 2. Bug 模式分析（真因 + 同类潜伏 + 治本点）
□ 3. 业界对标 ≥3 成熟产品（每条决策有可追溯引用）
□ 4. 防御机制 ≥2 项（契约测试 / 顺序控制 / Fail-Forward / 失败兜底）
□ 5. 验收标准覆盖"启动 → 用户看到结果"完整路径
□ 6. 没有"先打补丁"话术
□ 7. 所有结论有代码来源标注
□ 8. 推荐方案有明确理由（依据 X、Y、Z 条款）
```

任一项未通过 → 重新修改方案，不要输出。
