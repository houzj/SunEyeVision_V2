# 算法逻辑对齐（代码层）

用于判断工具的算法链是否按原厂参数、顺序、区域和结果语义实现。**代码层对齐不等于数值等价**；精度、舍入和黄金对照留给工程验证。

## 判定边界

- 代码层：输入解析、区域/掩膜、格式准入、核心算子顺序、判定、输出结构、取消与资源释放。
- 工程验证：数值精度、舍入、直方图公式、颜色空间量化、位置修正变换。
- 没有黄金样本时，算法等价只能写 `AlgorithmUnconfirmed`，不能写「已对齐」。

原厂模块多为 native，`ilspycmd` 反编译为空；代码层结论只能基于参数/结果声明、配置和运行快照，并在证据文件注明等级。

## 通用检查表

1. **输入**
   - 图像、ROI、掩膜是否都进入同一个有效统计域？
   - 本地 ROI 文档是否物化为执行区域，而不是只做预览？
   - 未连接的可选输入是整图，还是报错？与原厂一致吗？
2. **格式**
   - 支持的像素格式是否与原厂一致？
   - 不支持的格式是明确失败，还是静默转换？
3. **核心算子**
   - 顺序：灰度/颜色空间 → 区域裁剪 → 阈值/统计 → 判定 → 输出。
   - 区间是闭区间还是半开区间？
   - 反色、面积筛选、连通域合并的基准域是什么？
4. **判定**
   - 判据开关、上下限、未启用时的结果状态。
   - 全部关闭时是 NotEvaluated，还是默认通过？
5. **输出**
   - 结果端口、行结构、图像/区域/掩膜资源的所有权。
   - 空结果是否输出空域，而不是整幅输入。
6. **生命周期**
   - 取消点是否覆盖长算子。
   - 失败路径是否释放 HALCON 对象和输出资源。

## 本批工具

| 工具 | 链路 | 未闭合项 |
|---|---|---|
| PixelCount | 灰度 → ROI/掩膜 → 闭区间阈值 → 计数/比例 | 比例分母语义待工程验证 |
| IntensityMeasure | 灰度 → ROI/掩膜 → 最小/最大/均值/标准差 → 256 级直方图 → 判据 | 对比度公式、位置修正变换 |
| FrameMean | 命令分支 → real 累加 → 除帧数 → byte 均值 | 原厂舍入/清空后输出语义 |
| ColorExtract | RGB/HSV/HSI → 三通道闭区间 → 交集 → 反色补集 → 连通域面积筛选 | HSV/HSI 量化与色相环回 |

## 常见错误

- 只对齐 UI 行，没有把 ROI/位置修正接到执行输入。
- 用可选输入缺省值掩盖原厂要求的错误。
- 把 `max-min` 之类的推断写成「原厂公式」。
- 只改工具代码，不同步声明测试和执行测试。
- 用一次运行结果证明算法等价。

## 闭口写法

- 代码链完成 + 构建 + 自测：`code-logic-aligned-build-tested`。
- 黄金样本通过：`algorithm-verified`。
- 没有黄金样本：`AlgorithmUnconfirmed`，不得省略。
