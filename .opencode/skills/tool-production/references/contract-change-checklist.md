# 合同变更检查表

改动共享声明、字段模型、持久化或编辑器时，先填完这张表再动代码。任何一项没有答案，就停在设计阶段。

## 1. 字段身份

- 新字段的稳定 id 是什么？是否与既有字段冲突？
- 字段属于设置、执行输入还是显示字段？三者不能混。
- 数量是固定的，还是随保存状态变化？
- 如果是变化的：选择**固定槽位 + 显隐**，还是**动态声明**？默认选固定槽位。

> 已踩坑：直接做动态声明，会在节点创建、方案加载、成对提交三处同时失败。

## 2. 声明与呈现

- 参数 XML / 代码声明是否包含全部端口？
- 每个端口是否有且仅有一个 `FieldPresentation`？
- 成对字段是否只在一端声明 `PairWith` 和 `PairDisplayName`？
- 隐藏行用 `SuppressedFieldRows`、`SetFieldRowsVisibility` 还是 `visibleWhen`？
  - 数量驱动：`SetFieldRowsVisibility`（可恢复）
  - 条件驱动：`visibleWhen`
  - 永久隐藏：`SuppressFieldRows`

## 3. 持久化

- 保存键是什么？旧键是否废弃？
- 旧方案加载时：未知字段是忽略、迁移还是报错？
- 加载顺序是否需要先读数量再展开声明？
- 是否需要读取器层面的展开回调？

## 4. 引用与成对提交

- 端点是否允许 `Constant | Reference`？
- 成对行退出引用模式时，是否走范围组提交而不是单字段提交？
- 引用候选来源从哪里注入？

## 5. 编辑器与生命周期

- 参数页由哪个接缝挂载（锚定字段、页内容、专属面板）？
- 数量变化后，行显隐由谁刷新？是否需要重绑？
- 关闭/重开时，草稿、会话、租约是否释放？

## 6. 执行

- 执行期读取哪些字段？未启用槽位如何处理？
- 未解析引用是否阻止执行并给出诊断？
- 默认值是否在执行前补齐，且不会静默覆盖用户值？

## 7. 测试与验证

- 声明测试（字段数、成对关系、页签）是否同步？
- 执行测试（数量、边界、引用）是否同步？
- `ControlNamingProbe` 是否覆盖新面板/新页签？
- Release 构建 → 封存 → 启动 → 目标页截图，是否都做过？
- 新增设置字段后，已保存的测试方案是否还能打开？工具是否在 `Bind` 前补默认值？
- 结果页/基本页的行顺序是否按 `FieldPresentation.Order` 和标准基本参数页声明，而不是按控件创建顺序？

## 8. 证据

- 原厂证据路径与行号是什么？
- 哪些行为是已证实、推断、未确认？
- 未确认项是否写入清单，而不是写成已实现？
