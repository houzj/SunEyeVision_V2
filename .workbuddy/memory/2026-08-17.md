### 解决方案概况
- **定位**：工业视觉检测平台（类似 VisionPro/Halcon 的可视化流程搭建软件），基于 .NET 9.0 + WPF + Halcon，目标框架 net9.0-windows
- **规模**：8 个 src 主项目 + 11 个工具插件 + 13 个测试项目 + 203 个文档

### 项目结构（8 个 src 主项目）
1. **Core** (SunEyeVision.Core)：事件总线（EventBus/AsyncEventBus）、配置管理（JsonConfigManager）、日志（LogManager）、插件管理接口（IPluginManager）、设备管理接口（IDeviceManager）、文件访问管理（FileAccessManager 安全沙箱）
2. **Plugin.SDK** (SunEyeVision.Plugin.SDK)：插件开发 SDK，核心是 `IToolPlugin<TParams,TResult>` 接口（一个类就是一个工具插件，[Tool] 特性声明元数据）；参数系统 ParamValue<>/RoiParameters/ToolParameters；结果系统 ToolResults/OutputVariable（输出变量契约 SSOT）；VisionAdapters 视觉适配层（CvImage/CvRegion/CvContour/HalImage 等）；SDK 自带 UI（Controls/Previews/Themes/Windows）
3. **Plugin.Infrastructure**：插件加载（PluginLoader）、工具注册（ToolRegistry）、属性元数据适配
4. **SunEyeVision.CvEngine**：Halcon 算子封装层，CvOp.* 分部类（Threshold/Filter/Morphology/ShapeMatch/Statistics/Display/Connection/SetOperations/Labels/ImageConversion/Convert）
5. **DeviceDriver**：设备驱动（海康相机 MvCamera/HikvisionCameraService、模拟相机 SimulatedCameraDriver、相机池 CameraPoolManager、DeviceManager）
6. **UI**：WPF 主程序（MVVM），Features 下分 Camera/WorkflowUI/GlobalVariableManager/ParameterSetting/CommunicationManager/Dialogs；Shell 含 MainWindow/主界面产品级重构
7. **Workflow**：工作流引擎（WorkflowEngine/WorkflowExecutionEngine 拓扑排序并行执行）、节点模型（WorkflowNode/AlgorithmNode）、解决方案系统（Solution/SolutionManager/SolutionRepository/解决方案卡片）、全局变量（GlobalVariable）、事件驱动执行（EventDrivenExecutor）、触发管理（TriggerManager）、子程序支持
8. **Tools 工具插件（11 个）**：BlobAnalysis、Threshold、ImageLoad、ImageThreshold、ImageFilter、Morphology、ShapeMatch、Subroutine、Condition（条件分支）、Script（脚本）
   - 每个工具标准结构：Tool.cs + Parameters.cs + Results.cs + Views/DebugControl + Views/DataAnalysisControl + Converters + Models

## 提交驱动的计划自动同步（v3.1）

用户需求：**以 git 提交作为更新驱动**，自动根据提交修改 plan.json（不靠手动改），因为可能有临时任务插入，不完全按计划开发。

### 产物
1. **plans/sync_plan.ps1**（v1.0）：post-commit 触发后：
   - 读最近提交 message + 文件清单（git log / git diff-tree）
   - 匹配规则：keywordMap（26 组关键词→模块ID）+ pathMap（文件路径→模块ID）
   - 状态推断：完成/实现→done；开始/开发中→in_progress；修复/优化/重构→仅记日志
   - 匹配到 → 更新第一个未完成子任务状态 + 追加开发日志（含提交hash）
   - 未匹配 → 插入 **tempTasks 临时任务池**（不丢失计划外工作）
   - 同步前自动备份 plan.json → plans/backup/；幂等标记 .last_synced_commit
2. **.git/hooks/post-commit**（common dir: D:/MyWork/SunEyeVision_V2/.git/hooks/）：git commit 后自动调 sync_plan.ps1，后台静默执行，日志进 plans/sync.log。注意是 worktree 结构（.git 是指针文件），hook 要放 common dir，且用 `git rev-parse --show-toplevel` 动态定位
3. **generate_plan.ps1** 增加主控「临时任务池」区块（temp-card，粉色系 #993556）

### 踩坑记录（重要，PowerShell 5.1）
- **ConvertFrom-Json 的 PSCustomObject 不能直接赋值新属性**（静默失败，ConvertTo-Json 输出丢失该字段）→ 必须先 `Add-Member -NotePropertyName -NotePropertyValue`（Ensure-Property 函数）再赋值。log/tempTasks 都是这个坑
- **控制台编码**：PowerShell 默认 gb2312，git 输出 UTF-8 中文乱码（钟舵€佹爮...）→ 脚本开头 `[Console]::OutputEncoding = UTF8` + `$OutputEncoding = UTF8`
- **执行策略**：每次 PowerShell 调用是新进程，Bypass 不持久 → 测试/调用都要带 `Set-ExecutionPolicy -Scope Process Bypass` 或 `-ExecutionPolicy Bypass`；hook 已带该参数
- **测试样本选择**：匹配路径用真实提交（99a6998 含 tools/...ShapeMatch 文件→匹配 T-SHAPEMATCH）；临时任务路径用 b6e78cd（Initial commit 仅 README，必不匹配）
- ps1 修改后必须重新加 UTF-8 BOM（Write 工具写的是无 BOM，PowerShell 5.1 按 ANSI 解析中文会错）

### 验证结果
- 匹配路径：99a6998 → T-SHAPEMATCH，log 追加 `[99a6998] 修复主题系统遮蔽问题...` ✅
- 临时任务路径：b6e78cd → tempTasks 写入 TMP-b6e78cd，主控显示临时任务池 ✅
- 全链路：bash 执行 post-commit hook → sync 自动匹配 M-SRC-RUNUI（src/UI/Shell 路径命中）+ log 追加 + 看板重建 ✅ 中文无乱码

### 重要说明（误判教训）
- 测试中发现"未匹配→临时任务池"首次没触发，**不是 bug 而是提交确实匹配到了模块**（99a6998 的文件含 tools/SunEyeVision.Tool.ShapeMatch 的 XAML，pathMap 命中 T-SHAPEMATCH）——匹配逻辑比想象中精准，这是设计意图而非缺陷
