本项选择与代价

借鉴VM发布订阅与索引显式化；自研重做稳定身份和类型约束

强类型工具＋稳定FieldId的流程schema；类型/形状/单位/坐标域/Quality明确。

收益与成本

替换内部节点不破坏客户；schema演进和转换器增加维护。

为什么不选替代路线

纯反射路径轻便但脆弱；借鉴VM索引/订阅显式化并自建稳定身份，承担schema和转换器维护成本。

拟议接口与数据字段

FieldSchema { FieldId, Name, TypeId, Shape, Unit, CoordinateSpaceId, Nullability, SchemaVersion }
BindingDefinition { SourceScope, NodeId, SourceFieldId, TargetFieldId, IndexPolicy, ConverterVersion }
ReadOutcome Read(FieldAddress address) = Value(ValueRecord) | Missing | Invalid(Diagnostic);

状态与生效时点

编译时校验类型/数组/坐标域及环，运行时校验动态长度与质量。重命名保留FieldId；删除产生断链诊断；不偷取首项或回退0。

Owner与释放责任

SchemaCatalog拥有字段定义，Run结果仓拥有值；绑定仅持地址，不能获得裸图像所有权。

失败、取消与幂等

Missing/Invalid/Expired显式传播，转换失败不读旧轮值。读取无副作用且可重试，需持有资源时通过Acquire取得lease。

版本与兼容

字段删除/类型或形状破坏变更升级schema主版本；别名迁移显式登记，保留旧SourceFieldId，不持久化GetHashCode。
