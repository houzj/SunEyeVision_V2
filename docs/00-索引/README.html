本目录是 docs/ 的唯一入口。你不需要翻 01-06 的日期目录，先从这里找到你需要的答案。

一、先看哪张表

你想知道 打开哪个 规模
这件事现在是怎么定的？ 有没有权威说明？ 主题台账.html 16 个主题 / 356 篇历史
某个具体文件在哪？什么时候建的？ 文档索引.html 全量文件清单
现在在做什么、卡在哪？ ../collaboration/CURRENT_TASK.md 当前批次
某件事以前怎么演进的？ 主题台账.html 里对应主题的「历史版本」 356 篇

绝大多数情况先看 主题台账.html。 它一行告诉你：这个主题有没有现行文档、合并了多少篇历史、整合状态是什么。

二、主题台账怎么读

| 主题 | 现行文档 | 历史版本 | 最近日期 | 整合状态 |
| 相机与采集 | 09-现行文档/相机与采集.html | 14 | 2026-09-25 | 已整合 |
  • 现行文档：点开就是「这件事现在是什么样、为什么这样、还没做什么」
  • 历史版本：这个主题被合并了多少篇按日期的旧文档
  • 整合状态：
    • 已整合 = 有 09-现行文档 权威篇，可直接看
    • 未整合 = 只有 01-06 的日期文档，需要顺着清单自己读，且不知道哪篇是准的

三、四个脚本（都由脚本生成，禁止手改产物）

脚本 产物 什么时候跑
更新索引.ps1 文档索引.html 保存/迁移任何文档后
生成主题台账.ps1 主题台账.html 保存/迁移任何文档后，或改完 09-现行文档
生成工具预览.ps1 ../08-工具预览/（162 页） 工具参数或调试窗变化后
拆分任务账本.ps1 ../collaboration/history/ 分卷 任务账本积累过多批次后

运行方式（PowerShell 5.1）：

powershell -NoProfile -ExecutionPolicy Bypass -File "docs/00-索引/更新索引.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "docs/00-索引/生成主题台账.ps1"

脚本内以 $PSScriptRoot 定位 docs 根，与当前工作目录无关，在任何目录执行都正确。

产物统一 UTF-8 无 BOM；脚本源码中 生成主题台账.ps1 / 更新索引.ps1 若含中文需带 BOM。

四、主题台账的口径

  • 主题归属：先按文件名与首行标题的关键词匹配，匹配不到按所在目录兜底
  • 日期：文件名日期 > 路径 年/月/日 > 文件修改时间（三级兜底，避免把「搬运时间」当文档日期）
  • 不参与统计：archive/ 归档目录、各目录下的 README.md 说明文件
  • 已知局限：纯关键词聚类会误判。已发现 2 篇（多边形方案、区域编辑器卡尺 ROI 扩展）被归到「脚本工具」，实际属区域/测量；这类误判在各现行文档的「历史演进」末尾有过说明

五、维护规则

  1. 改完文档就跑两个索引脚本，否则台账的整合状态不会更新
  2. 不要手改 文档索引.html、主题台账.html——下次运行会被覆盖
  3. 已有主题不要再新建日期文档，改 09-现行文档/<主题>.html（见 rule-006 与「文档保存」技能）
  4. 新增主题时，先确认它真的不属现有 16 个主题之一
