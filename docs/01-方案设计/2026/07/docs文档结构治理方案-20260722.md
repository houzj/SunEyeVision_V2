# docs 文档结构治理方案

## 改前 → 改后 → 依据

### 改前（用户视角）
`docs/` 是一锅粥：根目录散落 10 个英文文件，`开发过程方案文档/` 一个目录塞了 130 个文件，方案/总结/测试/指南全混在一起。还残留 8 个空目录和 2 个 0 字节垃圾文件（如 `encoding_test.md`）。想找一篇历史方案，只能肉眼翻文件名，没法按类型或时间检索。

### 改后（用户视角）
`docs/` 只剩 7 个编号目录，191 个文件全部归位，路径带"类型 / 年 / 月"颗粒度：

```
docs/
├── 00-索引/              文档索引.md（自动生成）+ 更新索引.ps1
├── 01-方案设计/          按 2026/02 … 2026/07 分月下沉
├── 02-实施总结/
├── 03-测试报告/
├── 04-工具设计/          再分 测量工具/ 查找工具/
├── 05-框架架构/
└── 06-指南参考/          再分 guides/ + configs/
```

每个文件命名强制带创建日期，例如：
`docs/01-方案设计/2026/07/检测区域RoI多图形统一绑定与按类型单图形绑定方案-20260720.md`

需要找文档时，只开 `docs/00-索引/文档索引.md` 一个文件，搜关键词（路径/类型/日期/首行标题摘要）即可定位，不用翻目录树。

### 依据（业界参考）
- 借鉴成熟文档系统（如 Diátaxis 文档框架、Azure Docs 仓库）的"按类型分桶 + 单一索引入口"做法：内容按用途分类，检索只依赖一个生成的索引，避免散落。
- 路径年/月下沉对齐文件系统的自然归档习惯（类似日志目录 `logs/2026/07/`），让同批文档天然聚团。
- 文件名带创建日期保证"同名不同事"也能区分，且 git 历史负责追溯修订，索引只记录创建日与最后更新日两个静态锚点。

## 治理内容与结果

### 目录结构（类型优先 + 年月颗粒度）
| 目录 | 用途 | 文件数 |
|------|------|------|
| 00-索引 | 自动生成的检索入口 + 索引脚本 | 2 |
| 01-方案设计 | 方案/设计类 | 41 |
| 02-实施总结 | 实施总结/报告 | 39 |
| 03-测试报告 | 测试报告/结果 | 1 |
| 04-工具设计 | 工具专项设计（分测量/查找） | 22 |
| 05-框架架构 | 框架/架构 | 11 |
| 06-指南参考 | 指南/参考/配置（分 guides/configs） | 77 |

### 命名规范（强制）
- 中文类文档（01–05）：中文主题 + `-YYYYMMDD.md`，禁止英文文件名。
- 指南类（06）：`guide_`/`config_` 蛇形前缀 + 小写 + `_YYYYMMDD`。
- 摘要取自正文首行 `#` 标题；文件名日期固定不变，修订靠 git 历史追溯。

### 清理掉的脏东西
- 删除 0 字节 `reference_solution_serialization_clarification.md`、22B 测试垃圾 `encoding_test.md`。
- 清空并删除 8 个旧目录：`开发过程方案文档`、`框架设计文档`、`测量工具设计方案`、`查找工具设计方案`、`区域管理系统优化`、`优化记录`、`design`、`refactor`。

### 索引自动生成
`docs/00-索引/更新索引.ps1` 扫描全部文档，提取首行标题作摘要，输出 `文档索引.md`（189 条 .md）。每次保存/迁移文档后重跑该脚本即可，索引由脚本生成，禁止手动编辑。

### 规则与技能配套（保证以后自动合规）
- **重写 rule-006**：固定"6 类目录映射 + 年/月下沉 + 文件名带 `-YYYYMMDD` + 索引维护 + 五步保存法 + 禁止项"。
- **新建 `doc-save` 技能**：以后保存任何方案/总结/测试报告/指南，AI 先按它归类、命名、建年/月目录、更新索引，再写入。
- **方案设计 / 方案实施 / 方案测试** 三个技能已在文末引用 `doc-save`，产出文档自动走 rule-006 落地。

## 迁移方法（可复现）

1. 用 PowerShell 枚举 `docs` 全部文件真实清单与最后修改日期（绕开 .gitignore 对 dev/ 的屏蔽，但 docs/ 本就未被屏蔽，search_file 也可用）。
2. 编写带分类器的迁移脚本 `_migrate.ps1`：先跑**预览模式**输出每个文件的目标路径核对，修正重复日期/误分类后再跑 `-Mode run` 真正执行。
3. 分类优先级：测试报告 > 报告类 > 指南类 > 框架架构类 > 方案设计（默认）。
4. 已带日期的文件名不再重复追加日期；0 字节与已知测试垃圾在执行前删除。
5. 迁移后删除空旧目录与临时脚本，重跑索引脚本生成 `文档索引.md`。

## 使用约定（给后续 AI / 协作者）

- 任何需要保存的文档：**先确认类型 → 套命名模板 → 确定年/月 → 重跑索引 → 与用户确认再写**（rule-006 五步法）。
- 改了 `docs/` 下任何文件后，必须重跑 `docs/00-索引/更新索引.ps1` 更新检索入口。
- 索引脚本含中文，运行时需先加 UTF-8 BOM 再以 `-ExecutionPolicy Bypass` 执行（PowerShell 5.1 对无 BOM 脚本会按 GBK 解析导致乱码）。
