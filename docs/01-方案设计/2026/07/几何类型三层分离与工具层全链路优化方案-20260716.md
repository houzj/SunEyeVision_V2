# 几何类型三层分离 + 工具层全链路优化方案

## 🔄 改前 → 改后 → 依据

### 改前（用户视角）
1. **ROI 编辑器画的形状无法被下游绑定**：画个圆 → 存成 `ShapeParameters{ShapeType=Circle, 14个double字段}` → 下游只认 `SdkTypeVocabulary` 词目 → `Circle2d` 是 "Circle" 但存的是 `ShapeParameters` → 类型不匹配，下游使用被阻滞
2. **子程序/脚本工具实现臃肿**：`SubroutineTool.Run()` 160 行内嵌 4 个逻辑块，3 遍 `new ParameterResolver()` + 4 遍 `Split('.')`；`ScriptLifecycleManager` 反射读所有 public 字段当输出
3. **Condition 工具静默吞异常**：`TryConvertToDouble` 的 `catch { return false; }` 让用户完全不知道条件评估出错
4. **ScriptTypeMapper 和 SdkTypeVocabulary 打架**：脚本层 `Circle2d` → `ShapeParameters`，全局层 `Circle2d` → `"Circle"`，同一类型两个映射指向不同 CLR 类型

### 改后（用户视角）
1. **ROI 区域按形状类型输出 SDK 几何对象**：画圆 → `Geometry = Circle2d` → 变量类型 `"Circle"`；画旋转矩形 → `Geometry = RotatedRect2d` → 变量类型 `"RotatedRect"`。下游绑定系统直接识别、展开字段
2. **新增形状类型只需加 1 个 SDK 类型 + 3 行 if**：不需要改枚举、改字段、改 10 处 switch
3. **子程序/脚本工具简洁、fail-fast**：重复解析收归单一服务；3 套 Coerce 收敛为 1 套；类型不匹配直接报错
4. **一个类型映射权威**：`SdkTypeVocabulary` 唯一，`ScriptTypeMapper` 退化为"类型→C# 源码字符串"

### 依据（业界参考）
- **Halcon**：`gen_circle`/`gen_rectangle2`/`gen_region_polygon_filled` 各有独立算子；计量模型 `add_metrology_object(MeasureHandle, 'circle', ...)` 按类型创建
- **VisionPro**：`CogCircle`/`CogRectangle`/`CogRectangleAffine` 各自继承 `CogGraphic`，容器 `CogGraphicCollection` 统一管理
- **OpenCV**：`RotatedRect` 独立 struct，`cv::circle()`/`cv::rectangle()` 各为独立 API
- **MVVM 标准**：UI 模型（ViewModel）不混入领域逻辑，`ShapeParameters` 当前违反此原则

## 概念澄清与决策记录（2026-07-22 补充）

### 1. Region（区域）≠ Geometry（几何），是两回事

视觉软件里必须严格区分两类数据，混淆会导致类型系统错位：

| 维度 | Region（区域） | Geometry（几何/图形） |
|------|---------------|----------------------|
| 本质 | 算法图像处理结果，**像素级连通域/掩码/轮廓**（iconic 运行时数据） | 用户绘制的**参数化基元**：圆/直线/旋转矩形/多边形/弧 |
| 典型来源 | BlobAnalysis / Threshold / Morphology 算出的连通域 | ROI 编辑器里画的形状 |
| SDK 表示 | `IVisionRegion` / `CvRegion` / `HalRegion` | `Circle2d` / `Line2d` / `RotatedRect2d` / `Polygon2d` / `Arc2d` |
| 是否进契约 | **否**（本决策） | 是（6 几何概念） |
| 业界对标 | Halcon `HRegion` 与 `smallest_circle` 产出的 `Circle` 严格分开 | VisionPro `CogCircle`/`CogRectangle` 各自独立类 |

> 误区纠正：把处理后的特征区域（Region）强制桥接成 `Polygon2d`（几何基元）是概念错位——连通域轮廓只是"轮廓点集"，没有圆心/半径这类几何语义，下游若按"多边形"理解会错位。这正是 Halcon 把 `HRegion` 与 `smallest_circle` 结果分开的原因。

### 2. 用户决策（2026-07-22）

- **处理后的特征区域（Region）不进工作流契约**：不支持绑定、不支持跨工具传递。
- 真有下游要消费区域时，走 **"图像 → Region" 转换**（在脚本中或专用转换工具里做），而不是把 Region 当作全局变量传来传去。
- **词汇表维持 12 概念（6 基础 + 6 几何），不含 Region / Contour**（与 Module D 一致）。
- 历史存量 `RoI` 类型按 rule-008 零兼容直接报错，用户重配。

### 3. OutputRegions 的来龙去脉（为何之前在契约里）

`OutputRegions`（`ShapeParameters[]`）原本被 `GetPropertyMap()` 声明为输出变量，目的是在**数据分析面板**里列出、便于**调试过程参数**（查看每个 Blob 的区域形状）。它现在确实出现在数据分析里，用于过程参数调试。

按决策 2，它从 `GetPropertyMap()` 摘掉：

- 不再作为可绑定变量、不再出现在结果树/数据分析面板；
- 字段本身保留，仍通过 `RegionConverter.RegionToRoi` 把区域画到**图像叠加层**做可视化调试；
- 若后续需在数据分析里调试区域参数，使用"图像→Region"转换工具或重新评估，而非恢复契约变量。

> 影响说明：摘掉后变量列表/数据分析面板不再有此变量项，但区域仍画在图像上，可视化调试能力不丢。需要变量级调试时按第 2 条走转换通道。

### 4. 与 Module E 的关系

- **`InspectionGeometries`（Module E1）**：用户在 ROI 编辑器画的**输入检测区**，作为几何对象外发（6 几何类型）。这是用户绘制的形状，本质是 Geometry。
- **`OutputRegions`（Module E2，本文新增）**：算法算出的**处理后的特征区域**，本质是 Region。**不进契约**，仅内部显示。
- 二者不可混淆：原 Module E 的示例"找圆工具画 1 个 ROI、找到 3 个圆 → `InspectionGeometries=[Circle2d×3]`"是错的——`InspectionGeometries` 遍历的是 `InspectionRegions`（输入），应输出所画 ROI 的几何；找到的 3 个圆是工具的**检测结果**（另一路输出），不是 `InspectionGeometries`。

## 问题分析（Phase 0）

### 需求拆解

- **表面需求**：整合对话上下文中所有优化诉求，输出最终全链路优化方案
- **根本问题**：`ShapeParameters` 三个职责（UI 样式/形状大 union/结果输出）混在一个类中，导致序列化冗余、类型映射打架、渲染/命中/算法三通道全部 `switch(ShapeType)`。工具层缺乏几何类型输出，下游绑定链断裂
- **问题分类**：
  1. **设计缺陷**（`ShapeParameters` 大 union 设计）→ 需重构
  2. **功能缺失**（工具无几何类型输出）→ 需增量
  3. **实现偏差**（子程序/脚本工具重复解析、Condition 静默吞异常）→ 需重构
  4. **架构冗余**（3 套 Coerce + `ScriptTypeMapper`/`SdkTypeVocabulary` 打架）→ 需收敛

### 架构分配检查

- 几何类型定义最自然的归属：**SDK 层** `src/Plugin.SDK/Models/Geometry/`
- ShapeParameters 当前归属：**SDK UI 层** `RegionDefinition.cs`（含 UI 样式）
- 已有类似机制：`Circle2d`/`Line2d`/`Annulus2d` 已在 SDK Geometry 目录下 — [来源] 文件系统
- 不改是否可覆盖：不可覆盖 — 不重构 ShapeParameters 则永远大 union
- 是否改变分层边界：不改变 — ShapeParameters 仍留在 UI 层，Geometry 类型委托给 SDK 类型

### 方法对比

| 维度 | 方案 A（推荐：三层分离+SDK 类型补齐） | 方案 B（仅加 ToCircle2d 补丁） | 方案 C（不动 ShapeParameters，仅工具层加几何输出） |
|------|:---:|:---:|:---:|
| 实现方式 | ShapeParameters 剥离形状字段→持有 SDK 几何对象；SDK 补 RotatedRect2d/Polygon2d/Arc2d；3 通道改为 `is` 模式匹配 | ShapeParameters 加 ToCircle2d()/ToLine2d() 等转换方法 | 工具 Run() 末尾手动构造几何对象 |
| 架构一致性 | ✅ 类型权归 SDK，UI 层只做包装 | ❌ 类型权仍在 ShapeParameters | ❌ 工具层绕过 SDK 直接构造几何 |

| 扩展性 | ✅ 新增形状独立类，零影响已有 | ❌ 永远大 union，永远 switch 漏改 | ❌ 工具层需要感知所有形状 |

## Bug 模式分析（Phase 0.5）

### 当前 bug

`ShapeParameters` 大 union 设计 + 3 条转换通道各写一套 `switch(ShapeType)` + `ScriptTypeMapper`/`SdkTypeVocabulary` 对同一类型映射打架。

### 真因分类

**设计缺陷** — `ShapeParameters` 天生就是 `ShapeType` + 14 个 double 字段的大 union，新增形状类型必然需要：

1. `ShapeType` 枚举加值
2. `ShapeParameters` 加字段（可能已有同名字段，语义冲突）
3. `CvRegion.CreateFromRegions` 加 case
4. `ShapeRenderer.CreateShape` 加 case + 创建方法
5. `RegionHitTester.IsPointInRegion` 加 case + 命中测试方法
6. `RegionHitTester.CreateHandles` 加 case + 手柄创建方法
7. `HandleManager.CreateHandles` 加 case + 手柄创建方法
8. `ShapeParameters.Clone` 加字段复制
9. `ShapeParameters.GetMonitorFields` 加 case
10. `SdkTypeVocabulary` 加注册

**每次新增形状类型，至少 10 处修改。** 这就是 bug 模式。

### 同类潜伏点

- `ShapeRenderer.cs:56-77` — switch(shape.ShapeType) 分发
- `RegionHitTester.cs:117-128` — switch 创建手柄
- `RegionHitTester.cs:132-143` — switch 命中测试
- `HandleManager.cs:138-162` — switch 创建手柄
- `CvRegion.cs:81-107` — switch 算法绘制
- `RegionDefinition.cs:382-458` — switch GetMonitorFields
- `ScriptTypeMapper.cs:34-74` — 与 SdkTypeVocabulary 不一致的第二套映射

### 治本点

**修复 `ShapeParameters` 的设计模式**，而非给它的每个新形状加补丁。消除 10 处 switch，改为 SDK 类型 `is` 模式匹配。

## 解决方案

### 方案概述

分 6 个模块（Module A~G），按 Phase A→E 分阶段实施，零兼容（rule-008）。

### 技术方案

#### Module A — SDK 几何类型补齐

在 `src/Plugin.SDK/Models/Geometry/` 下新增 3 个类型，与已有 `Circle2d`/`Line2d`/`Annulus2d` 同级。

```csharp

{
    public double CenterX { get; }
    public double CenterY { get; }
    public double Width { get; }
    public double Height { get; }
```

#### Module B — ShapeParameters 重构

```csharp
// 改后：只持 UI 样式 + SDK 几何类型
public class ShapeParameters : RegionDefinition, IMonitorable
{
    // 【删除】14 个形状字段
    // 【新增】Geometry
    private object? _geometry;
    public object? Geometry    // Circle2d / Line2d / RotatedRect2d / Polygon2d / Arc2d / Point2D / System.Windows.Rect
    {
        get => _geometry;
        set => SetProperty(ref _geometry, value);
    }

    // 【保留】UI 样式
    public uint FillColorArgb { get; set; }
    public uint StrokeColorArgb { get; set; }
    public double StrokeThickness { get; set; }
    public double Opacity { get; set; }

    // 【新增】类型转换
    public ShapeType ShapeType => GeometryToShapeType(Geometry);

    // 图形编辑操作委托给 SDK 类型
    public Point2D GetCenter() => Geometry switch {
        Circle2d c        => c.Center,
        Line2d l          => l.Point,
        RotatedRect2d rr  => new Point2D(rr.CenterX, rr.CenterY),
        ...
    };
}

// GetMonitorFields 改为 Geometry switch
public IReadOnlyList<(string, object?)> GetMonitorFields() => Geometry switch {
    Circle2d c     => [("中心X", c.Center.X), ("中心Y", c.Center.Y), ("半径", c.Radius)],
    RotatedRect2d r => [("中心X", r.CenterX), ("中心Y", r.CenterY), ("宽", r.Width), ("高", r.Height), ("角度", r.Angle)],
    ...
};
```

序列化变化：`{$type:"Shape", Geometry:{$type:"Circle2d", Center:{X:100,Y:200}, Radius:50}, FillColorArgb:0}`

**C4：三层数据流总览（Geometry 单一字段驱动，原子类型即数组）**

用户画的东西（几何对象）与算法要的东西（像素掩码）是同一块 ROI 的两种表示，方案用 `Geometry` 这一个字段统一驱动，不再各写一套 `switch`：

```
用户画 ROI（RegionDefinition）
   │  持 Geometry = Circle2d（SDK 几何类型）
   ▼
┌─────────────────────────────────────────────────────┐
│ 三层通道全部走 "Geometry is Xxx" 模式匹配              │
│                                                      │
│ ① 渲染层    ShapeRenderer          → WPF 矢量图形      │
│ ② 命中/编辑层 RegionHitTester / HandleManager → 命中判定/手柄 │
│ ③ 算法层    CvRegion.CreateFromRegions               │
│              → OpenCV/Halcon 像素掩码（Mat/HRegion）   │
└─────────────────────────────────────────────────────┘
   ▼ ③ 实时栅格化
Region（像素掩码）：每个像素"属于/不属于"区域
   │  下游算法：ReduceDomain / 阈值 / 连通域 / 统计
   ▼
InspectionGeometries（检测区域 = Geometry 几何对象，见 Module E）
```

> 关键确认（避免实施偏差）：**检测区域（几何对象 `Geometry`）与 Region（像素掩码）同时存在、各司其职**。
> - 几何对象：给下游绑定 / 测量 / 结果显示，字段可展开（如 `Circle2d.Center`/`Radius`）。
> - 像素掩码：给算法做图像处理（ReduceDomain/阈值/统计），由 `CvRegion` 把 `Geometry` 实时栅格化得到。
> 两者都由 `Geometry` 字段统一派生，新增形状只需 SDK 加类型 + 3 条 `is` 分支（渲染/命中/算法各 1 条），不再出现第 10 处 `switch`。

**E-示例：检测区域输出长什么样（避免实施偏差）**

`InspectionGeometries` 装的**不是** `ShapeParameters`，而是具体的 SDK 几何类型实例。即检测区域输出是"强类型几何对象数组"，下游一眼认得出类型、字段可展开。

| 用户在 ROI 编辑器画的形状 | 输出的几何对象（`Geometry`） | 主要字段（举例） |
|---|---|---|
| 圆 | `Circle2d` | Center(X,Y) + Radius |
| 直线 | `Line2d` | Point + 方向（或 起点/终点） |
| 旋转矩形 | `RotatedRect2d` | CenterX/Y + Width + Height + Angle(°) |
| 多边形 | `Polygon2d` | Vertices[] 顶点数组（≥3） |
| 弧 | `Arc2d` | Center + Radius + StartAngle/EndAngle(弧度) |
| 轴对齐矩形 | `System.Windows.Rect` | X/Y/Width/Height |

> 注（2026-07-22 修订）：轴对齐矩形在词汇表中**不单独建词目**，复用 `RotatedRect`（旋转矩形、角度=0 的特例）；词汇表最终只有 6 几何概念（Circle/Line/Annulus/RotatedRect/Polygon/Arc），不含 Point/Rectangle/Region/Contour（见 Module D 最终词汇表）。

**具体例子**：在 ROI 编辑器画了 1 个圆 → `InspectionGeometries = [Circle2d]`（长度 1 的 `Circle2d[]`）。注意：工具"找到的 3 个圆"是**检测结果**（另一路输出，`Circle2d[]` 形式），不是 `InspectionGeometries`。

#### Module E2 — 处理后的特征区域（OutputRegions，内部显示，不进契约）

`OutputRegions`（`ShapeParameters[]`，由 `RegionConverter.RegionToRoi` 把算法 Region 桥接而来）是**处理后的特征区域**，本质是 Region（像素级连通域），不是几何基元。

**决策（2026-07-22，详见「概念澄清与决策记录」）**：Region 不进工作流契约，不绑定、不传递。因此：

1. 从各工具 `Results` 类的 `GetPropertyMap()` 中**移除 `OutputRegions` 声明**（不再生成契约变量、不再出现在结果树/数据分析面板）。
2. `OutputRegions` **字段本身保留**，继续由 `RegionConverter.RegionToRoi` 产出，用于把区域画到**图像叠加层**做可视化调试（它当前在数据分析面板里列出正是为了调试过程参数，摘掉后该变量项消失，但图像上的区域不丢）。
3. 涉及工具：`BlobAnalysis` / `Threshold` / `ImageThreshold` / `Morphology` 四个 `Results` 类。
4. **不新增** `RegionToPolygon2d` 等桥接——Region 不是几何，无需转成几何类型。
5. 下游若需消费区域：使用"图像→Region"转换（脚本或专用转换工具），不在契约层传递 Region 变量。

**与改前对比（痛点 1）**：改前画圆存成 `ShapeParameters{ShapeType=Circle, 14个double}`，下游绑定系统（按 `SdkTypeVocabulary` 词目）只认 `Circle2d`，类型对不上 → 绑不上。改后直接是 `Circle2d` 实例，下游直接识别、字段可展开。

> **与输出变量契约方案（文档一）的对齐**：本 `InspectionGeometries` 在运行时 = 检测到的 `Circle2d[]`/`Line2d[]` 等；经输出变量契约包装后，变量 `VariableType="Circle"`（即 `Circle2d[]`，见文档一第十四章"原子类型即长度 1 的数组"），结果树/绑定树据此递归展开（见文档一 6.x / 14.2-E）。两文档共用同一套 `SdkTypeVocabulary` 词目，实施时不得各造一套。
