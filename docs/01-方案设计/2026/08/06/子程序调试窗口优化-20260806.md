# 子程序调试窗口优化

## 🔄 改前 → 改后 → 依据

### 改前（用户视角）
1. 调试窗口有 5 个标签页，其中"**运行参数**"是个**假页**：进去只有灰字说明和禁用的"编辑"按钮，怎么点都没反应，还误导人以为功能存在。
2. 子程序的输入/输出**可以一路删光**：新建时只有 `in_1` 输入、**没有输出**；输出删光后，下游节点在绑定列表里**看不到任何结果**，还得靠用户自己猜是子程序没配输出。
3. 运行时**零校验**：0 输入 0 输出的子程序能安静跑完，出错后查起来像大海捞针。
4. 调试窗口底部"**执行 / 连续执行**"两个按钮**点了没反应**：子程序控件没继承 `ToolDebugControlBase`，这两个按钮的路由命令没人接（子程序本质是一条子工作流，本就不该像阈值、滤波那样"单工具执行"）。

### 改后（用户视角）
1. 调试窗口只剩 4 个真有用的页：**输入设置 / 输出设置 / 显示设置 / 循环设置**，"运行参数"假页删除。
2. 子程序变成**有规矩的接口**：打开窗口自动补全——没输入补 `in_1 (Image)`、没输出补 `out_1 (Double)`；想删光？删到最后一个时 ✕ 直接拦下并提示"子程序至少保留一个输入/输出"。
3. 运行时 **Fail-Fast**：输入或输出为 0 直接报错（研发阶段零兼容，存量配方不做任何兜底），错误信息直接点名"子程序 XX 至少需要一个输出"。
4. 底部"执行 / 连续执行"按钮**对子程序隐藏**（保留"确定"），不再出现点了没反应的无效按钮。

### 依据
- 子程序本质是"大号工具"（代码注释原文），必须有明确的入参/出参契约——对齐 VisionMaster、基恩士等视觉软件"子流程必须声明入参出参"的通用设计。
- "执行/连续执行"隐藏的依据：`DefaultDebugWindow` 通用外壳里 `_toolControl = control as ToolDebugControlBase`，子程序控件 `SubroutineDebugControl` 是纯 `UserControl`（`_toolControl == null`），这两个按钮路由到 `ToolCommands.Execute` 但无人接收 → 无效按钮。脚本工具等继承了 `ToolDebugControlBase`（`_toolControl != null`），按钮有效必须保留。
- 遵守 rule-015 禁止兜底回退：运行时不满足直接报错，不静默。
- 遵守 rule-008 零兼容原则：研发阶段，存量不兼容直接报错。

## 问题分析（Phase 0）

### 需求拆解
- **表面需求**：子程序调试窗口的优化 + 至少一个输入和输出。
- **根本问题**：子程序作为"大号工具"，输入/输出契约缺失，导致下游绑定静默失败；窗口存在无效的"运行参数"假页和无效的"执行"按钮。
- **问题分类**：契约缺失（输入输出无下限）+ 实现有误（半成品页/半成品按钮）。

### 架构分配检查
- 最自然的归属层：子程序工具层（ViewModel + Tool）+ 通用外壳（DefaultDebugWindow）。
- 已有类似机制：新建时自动补 `in_1`（`MainWindowViewModel` 幂等逻辑），脚本工具的 `ToolDebugControlBase` 继承机制。
- 不改是否可覆盖：否。
- 是否改变分层边界：否。

### 方法对比（≥ 3 候选）

| 维度 | 方案 A（推荐：三层约束） | 方案 B（只做 UI） | 方案 C（只做运行时校验） |

## 解决方案

### 方案概述
对子程序调试窗口做 4 处优化：① 删除"运行参数"假页；② 打开窗口自动补输入/输出默认项（幂等）；③ UI 防删光；④ 运行时 Fail-Fast。另外在通用外壳 `DefaultDebugWindow` 对非单工具执行控件（`_toolControl == null`，含子程序）隐藏无效的"执行/连续执行"按钮。

### 技术方案
1. **删除运行参数 Tab**：删除 `SubroutineDebugControl.xaml` 264-282 行（纯占位 UI，无绑定逻辑）。
2. **打开窗口自动补齐（幂等）**：`SubroutineParameterDialogViewModel` 构造函数 `LoadAvailableSources()` 前新增 `EnsureMinimumInputsOutputs()`：`Inputs.Count == 0` → 补 `in_1 (Image)`；`Outputs.Count == 0` → 补 `out_1 (Double)`；重名递增。
3. **UI 防删光**：`ExecuteRemoveItem` 删除前判断——删输入时 `Inputs.Count <= 1`、删输出时 `Outputs.Count <= 1` → 弹提示并 return。
4. **运行时 Fail-Fast**：`SubroutineTool.Run` 前置验证区追加输入/输出数量校验。
5. **隐藏执行按钮**：`DefaultDebugWindow` 构造函数里，`_toolControl == null` 时 `RunButton` / `ContinuousRunButton` 设为 `Visibility.Collapsed`。

### 实施步骤
1. 修改 `SubroutineDebugControl.xaml`：删除运行参数 Tab。
2. 修改 `SubroutineParameterDialogViewModel.cs`：新增 `EnsureMinimumInputsOutputs` + 防删光。
3. 修改 `SubroutineTool.cs`：运行时校验。
4. 修改 `DefaultDebugWindow.xaml.cs`：隐藏执行按钮。
5. 构建验证 + 手动目视确认。
