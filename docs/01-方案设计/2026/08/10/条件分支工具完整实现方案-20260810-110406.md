## 三、解决方案

### 1. 参数模型（ConditionParameters）

```csharp
public class ConditionParameters : ToolParameters
{
    public List<ConditionRule> Rules { get; set; } = new();
    // ❌ 已删除 DefaultExecutionModuleId（不命中即终止）
}

public class ConditionRule
{
    public string RuleType { get; set; } = "Int";      // ★ "Int"/"Double"/"String"
    public string Name { get; set; } = string.Empty;   // 自动生成（int0/float0/string0），不可修改
    public string InputText { get; set; } = string.Empty;  // ★ 条件：绑定表达式 或 常量
    public double MinValue { get; set; }               // 有效范围下限
    public double MaxValue { get; set; } = 1000.0;     // 有效范围上限
    public string Judgment { get; set; } = "OK";       // OK / NG
    public string ExecutionModuleId { get; set; }      // 目标节点（下拉选下游）
}
```

### 2. 条件输入解析器（新增 `ConditionInputResolver`）

```
解析 InputText：
  ├─ 匹配"节点ID.属性名" 且 节点在工作流中 → 绑定模式：取上游输出属性值
  └─ 否则 → 常量模式：按 RuleType 解析（Int/Double→数值；String→字符串字面量）

判定（统一用解析出的"输入值"）：
  ├─ Int/Double 规则：值在 [MinValue, MaxValue] 内且 Judgment=OK（或范围外且 NG）→ 命中
  ├─ String 规则：输入值有效（非 null）→ 命中（不参与范围/判断）
  └─ 解析失败/类型不支持 → 抛异常（rule-015，禁止静默）
```

#### 2.1 解析层契约（实施前必须钉死，补充自多轮讨论）

> 这三条契约原方案未写死，是评审时收敛出的硬性设计决策，实施必须遵守。

**契约 C1：`InputText` 单轨存储（唯一真相源）**

- `ConditionRule` **只允许** `InputText` 一个文本字段，两种形态并存（绑定表达式 / 常量）
- **禁止**引入 `BindingSource` / `IsBound` 之类的第二存储位——没有状态可错位
- **所见 = 所存 = 所解析**：运行时解析 `InputText` 本身，**绝不**碰 `BindingSource` / `IsBound`

**契约 C2：`ParamBinding.SyncEditingToSource` SDK 扩展（堵两轨错位漏洞）**

- 现状 `ParamBinding` 编辑同步有坑：用户改显示文本时**只有含 `[]` 索引才回写绑定源**，改成 `123` 不会同步 → 会导致"先绑定后改常量仍判绑定"的错位
- SDK 层给 `ParamBinding` 增加 `SyncEditingToSource` 属性（**默认 false，保持现状，零影响其他工具**）
- 条件分支设 `SyncEditingToSource="True"`，编辑同步升级为：
  - 编辑文本能翻译为已知绑定路径（含索引微调）→ 回写机器路径（现有逻辑）
  - 翻译失败（如改成 `123` / `"OK"`）→ **原文回写**到 `InputText`，进入常量态

**契约 C3：模式判定 = GUID 格式 + 结果集取值，两层职责分离**

- 判定"是不是绑定表达式"**不看状态、不看是否绑定过**，只看文本结构：
  ① 文本含 `.` ② 按第一个 `.` 切出节点ID段 ③ 节点ID 非空且 `Guid.TryParse` 成功 → 三条件全满足 = **绑定模式**；任一不满足 = **常量模式**
- 依据：节点 ID 被设计钉死为 GUID（`[来源] src/Workflow/WorkflowNode.cs:45-52`），工具层够不着工作流静态节点集合（分层约束），故靠 GUID 格式这个**结构事实**判定，不靠查节点集合
- **GUID 格式管"是不是绑定"；`parameters.NodeResults` 管"取不取得到值"**：
  - 绑定已执行节点 → 取到值 ✅
  - 绑定未执行节点 → 仍判绑定，报"节点不在执行结果中"（准确提示上游没跑，而非误判常量）✅
  - 常量 `3.5`（含点）→ 节点段 `3` 不是 GUID → 常量 ✅ 防误判
  - 常量 `123` / `OK` → 无点 → 常量 ✅
- 工具调试模式 `NodeResults` 为空字典 → 绑定报"节点不在执行结果中"（调试无上游，合理）；常量正常

#### 2.2 常量解析（按 RuleType 转换，参照 `ScriptBindingResolver.CoerceValue`）

```
Int/Double → int.TryParse / double.TryParse（InvariantCulture）
             失败 → 抛异常（rule-015，带原文报错，不静默）
String     → 字面量原文即值（不剥引号，KISS）；空文本 → 抛异常（条件未配置）
复杂类型（Image 等）→ 抛异常（rule-015）
```

**新增栏算法**（参考 `ScriptVariableTab.AddVariable_Click`——`[来源] ScriptVariableTab.xaml.cs:571-581`）：

```csharp
private void AddRule_Click(object sender, RoutedEventArgs e)
{
    var ruleType = TypeCombo.SelectedValue as string ?? "Int";  // int/double/string
    var prefix = ruleType.ToLower();                            // "int"/"double"/"string"
    int maxIndex = Rules
        .Where(r => r.Name.StartsWith(prefix))
        .Select(r => int.TryParse(r.Name[prefix.Length..], out var n) ? n : -1)
        .DefaultIfEmpty(-1).Max();
    Rules.Add(new ConditionRule
    {
        RuleType = ruleType,
        Name = $"{prefix}{maxIndex + 1}",   // int0/int1/float0/string0
        MinValue = 0, MaxValue = 1000, Judgment = "OK"
    });
}
```

| 画布三态改动回归 | 其他工具节点受影响 | 转换器默认值（待运行）透明，不影响其他节点 |
| InputText 与旧 InputBinding 序列化兼容 | 旧文件加载 | 零兼容：InputBinding 删除，旧文件重新配置 |
| `SyncEditingToSource` 改动波及其他工具 | ParamBinding 行为变化 | 属性默认 false，仅条件分支显式开启，其他工具走原逻辑 |
