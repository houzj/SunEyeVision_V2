### D1图像源接纳整链实施合同（2026-10-28）

迁移前消费者证据：ImageInputSource修改→ConfigChanged→WorkflowNode/主窗重复回写→ConfigurationEdited只更新状态，不进入History；Host草稿的NodeEditSignature检测ImageSourceConfig，但Compose/SetParameters和Projection不安装该字段。因此不能只把源配置写入草稿，必须同步完成签名、复制、候选验证、原子安装和回滚。主线已明确本批不改Host/WorkflowNode，允许本分支整链实施后集成交接。

- 复用现NodeConfigurationEditHost.BeginEdit/CommitBatch和方案历史，不新增源历史或另一配置存储。源配置字段属于节点配置的一部分，深复制候选，接纳保正式节点身份，失败恢复原引用，Undo/Redo恢复配置而不重放运行。
- 模型编辑必须先建立候选再请求宿主接纳，成功后安装展示。删除/替换/清空不能先释放当前图像资源再请求接纳。集合只读展示，运行勾选同样走候选；拒绝时集合、选择、运行标记与资源均不变。
- 宿主回调检查当前方案/根/节点/源实例、编辑版本及可编辑状态；运行游标仍走TryPresentRuntimeCursor，不触发源配置编辑。接纳/观察通知异常不得把已接纳配置误记为失败重做。
- 导入枚举与文件引用准备脱离控件业务，取消/切源/关闭使旧候选无效；同次用户导入整批接纳，若未来保留分批接纳，必须显式说明撤销/取消的已接纳边界。此处不引入新文件格式。
- 跨次单步运行的下一张进度由WorkflowExecutionManager持有，不再依赖预览对象。每源游标按实际根实例（弱引用）、冻结列表/资源地址/正式起点签名匹配；成功后从现序列服务读取下一条，失败/取消不写新游标。输出格式、自动推进及末张停止使用本次计划，不另造推进算法。显式预览编辑接纳后只复位本源运行态游标，即使用户重新选择的起点等于原持久值；不复位同根其他源。相机模式切换保留本地进度，根/源删除、实例更换、方案换代及执行器释放清理运行态，运行进度不进保存或撤销历史。
- 运行计划以WorkflowRunConfiguration的冻结ImageSourceConfig为唯一列表/勾选/起点/模式来源，同时冻结当前方案资源基目录；纯ResolveAddress只归一化地址，实际文件可用性仍在后台运行准入检查。条目身份按冻结列表中的“索引+原引用”确定，重复引用各有身份；列表/起点/模式/资源基目录构成定义签名，预览对象ID及其EditVersion不构成运行定义。无预览也能按正式配置运行。运行完成仅按原位置找到当前展示条目，再核源实例、EditVersion、原引用和地址后投影游标，不把运行身份强塞成UI条目ID。
- 沿ExecuteWorkflowInternal继续查源，原CreateImageLoadParameterOverrides/CollectImageLoadParameterOverrides仍是实际后备调用，并非死代码；已统一改为本轮PublishedRunInputs.LocalImages.Overrides深复制，删除旧读取器及重复工具分类方法。序号和通信覆盖只写本轮副本，现LocalImageSequenceService继续唯一管理代次/迭代/成功推进/末张停止；未改Group或循环语义。根就绪状态按正式源配置报告空源/未选相机/选择不在运行集合等，不拿未注入FilePath的调用参数假报失败，正式执行校验仍保留。
- 正式配置Undo/Redo/打开后源展示投影刷新，保存从正式配置取值；不依靠ToConfig getter产生写副作用。由source持有稳定条目身份的本次生命周期，资源引用保存/重开依现行持久合同。
- 源设置面板同样是正式编辑入口：SourceKind、CameraDeviceId、CameraTimeoutMs、OutputFormat、SNInitialValue、StopAtLastImage与自动切换必须由Host候选接纳，不能直接改正式节点。当前采用即时接纳，每次设置行为进入同一方案历史，面板说明其边界；关闭不重放运行、不回滚已接纳修改。主界面嵌入页只允许当前选中面板；独立设置窗口只允许本窗口内的源设置页。运行、方案切换、其他参数窗口或待提交编辑均拒绝；旧方案页面不能写新方案。
- 编辑结构有效性与运行就绪分开：未选图/未选相机是可保存的未就绪配置。Host从正式基线比较工具参数、Runtime配置和ParamSettings签名，只有纯源配置修改才不重复验证未改变的调用参数；Source结构、身份、枚举、超时和序号及输入绑定仍校验。工具参数同时改变则照常严格Validate，不由调用者传“免检”选项。实际ImageLoad调用参数的FilePath/SN仍由运行输入快照注入，禁止为了通过编辑校验填假路径。空源不能因此变成可执行。

## 一、关键决策：不引入 Dock 系统（AvalonDock）

| 对比项 | 引入 AvalonDock | 自研可折叠分栏面板（选定） |
|-------|---------------|--------------------------|
| 需求匹配 | 我们是固定骨架+局部折叠，它 90% 能力要禁用 | 精准匹配：拖宽/折叠/隐藏/记忆 |
| 布局模型 | 主体换 `DockingManager`，XAML 推倒重写 | 延续现有 Grid 骨架，仅抽控件 |
| 主题 | VS2013 主题与 Token 打架，需重模板化 | 直接吃我们的 Token，天然统一 |
| 体积/依赖 | +3~4 个包（主程序+主题） | 1 个自研控件类（~200 行） |
| 参考项目实证 | 参考项目未用，20KB 控件足够 | 对齐 GridSplitterBox 三件套 |
| 长期 ROI | 中（版本碎片化、升级绑定） | 高（单一事实源、零依赖） |

> **结论**：不引入 AvalonDock。布局管理统一走自研控件（见阶段三 Step 3.0）。**本决策为最终决策，后续实施不再讨论。**
> 唯一例外场景：产品需求未来升级为"用户自由停靠/浮动/多屏"时再重新评估，届时需做主题重模板化 + 画布嵌套 POC。

### 参考项目布局方案 vs 我们的方案（对比结论沉淀）

**参考项目（VisionMaster OpenCV）主体与布局管理方案三件套：**
1. **窗口体系** `h:MainWindow` 自绘标题栏基类（WindowChrome + `CaptionTemplate` 可插拔），VisionMaster 主窗口 `CaptionHeight=85` 容纳"菜单行+工具栏行"两行。
2. **布局核心** 自研 `GridSplitterBox` 通用可拖拽分栏面板控件：`MenuDock` 四方向一套模板、`Mode` 双档（Extend 缩成图标条 / Hidden 完全隐藏）、`IMetaSetting` 布局持久化。
3. **内容组织** TabControl 多标签页 + Zoombox 画布。

**对比结论：**
- 大方向想到一块（都不引重型 Docking、都做一体化标题栏、都做可折叠面板）。
- 参考项目赢在一个"系统"：把分栏+折叠+图标条+记忆做成了通用控件四处复用；我们方案目前是工具箱/右侧面板各写各的。
- 我们更先进：Token 设计系统（参考项目散落 DynamicResource 无单一事实源）、工具箱双模已成型、架构解耦拆 VM（参考项目 119KB 巨型文件）、小地图/三段状态栏/流程管理条（参考项目全无）。

**本方案吸收的核心只有一条**：把"分栏面板"做成通用控件 `CollapsibleSplitterBox`（对齐 GridSplitterBox 的 MenuDock + Mode 双档 + IMetaSetting 持久化三件套）。

| `IMetaSetting` 拖完 Save、重启恢复 | `LayoutSettings` 服务保存到配置（JSON），拖完即存 |
| `MenuMinWidth` 折叠后露图标条 | 折叠后露 24px 图标条（含展开箭头） |

```
CollapsibleSplitterBox 使用（MainWindow 骨架中）：
├── <CollapsibleSplitterBox Dock="Left"   CollapseMode="IconStrip">  ← 工具箱
├── <CollapsibleSplitterBox Dock="Right"  CollapseMode="Hidden" InitialWidth="460">  ← 右侧面板
├── <CollapsibleSplitterBox Dock="Bottom" CollapseMode="Hidden">  ← 日志
└── 中间 ContentControl → ShellWorkspaceControl
```

**Step 3.1 一体化标题栏**：WindowChrome 自绘，logo 跨两行居中，菜单 5 个收敛（文件/设置/工具/系统/帮助），工具栏 15 方块图标。

**Step 3.2 左侧工具箱**：**双模机制原样保留**（60px 图标条 + 悬停 Popup + 展开分类树 + 切换按钮），仅视觉统一（选中色 `#667EEA`→`#0066CC`、28 处硬编码色 Token 化、emoji 换 Path 几何、圆角 4px 对齐全局样式）。回归重点：紧凑↔展开切换、Popup 悬停、工具拖拽。

**Step 3.3 右侧深色面板 + 专业结果表**：默认 460px，由 Step 3.0 控件管理折叠（竖条/隐藏/记忆）；Tab 结构 `图像|模块结果` + 图像源缩略条 + `当前结果|历史结果`；列名用机器视觉术语（序/转换坐标X/转换坐标Y/转换角度/重叠程度/平移X/平移Y/旋转/宽度/高度/斜切/宽高比）。

**Step 3.4 三段式状态栏**：`●状态 │ 流程0ms 模块0ms 算法0ms ── 80% │ 时间 消息 版本`，删假 CPU/FPS。

**Step 3.5 右下角小地图**：流程缩略图 + 红框标记当前视图位置。

**Step 3.6 画布顶部内嵌流程管理条**：流程名 + `≡` 菜单 + 搜索/适配按钮。

**Step 3.7 节点命名"编号+名"**：如"1.20 图像源1"，编号=执行顺序。

**Step 3.8 图标统一**：集中 `Icons.xaml` 资源字典，全部 Path 几何方块按钮。
