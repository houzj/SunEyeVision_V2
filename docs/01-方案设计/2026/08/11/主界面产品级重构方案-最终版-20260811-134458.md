## 一、关键决策：不引入 Dock 系统（AvalonDock）

| 对比项 | 引入 AvalonDock | 自研可折叠分栏面板（选定） |

**参考项目（VisionMaster OpenCV）主体与布局管理方案三件套：**
1. **窗口体系** `h:MainWindow` 自绘标题栏基类（WindowChrome + `CaptionTemplate` 可插拔），VisionMaster 主窗口 `CaptionHeight=85` 容纳"菜单行+工具栏行"两行。
2. **布局核心** 自研 `GridSplitterBox` 通用可拖拽分栏面板控件：`MenuDock` 四方向一套模板、`Mode` 双档（Extend 缩成图标条 / Hidden 完全隐藏）、`IMetaSetting` 布局持久化。
3. **内容组织** TabControl 多标签页 + Zoombox 画布。

**对比结论：**
- 大方向想到一块（都不引重型 Docking、都做一体化标题栏、都做可折叠面板）。
- 参考项目赢在一个"系统"：把分栏+折叠+图标条+记忆做成了通用控件四处复用；我们方案目前是工具箱/右侧面板各写各的。
- 我们更先进：Token 设计系统（参考项目散落 DynamicResource 无单一事实源）、工具箱双模已成型、架构解耦拆 VM（参考项目 119KB 巨型文件）、小地图/三段状态栏/流程管理条（参考项目全无）。

**本方案吸收的核心只有一条**：把"分栏面板"做成通用控件 `CollapsibleSplitterBox`（对齐 GridSplitterBox 的 MenuDock + Mode 双档 + IMetaSetting 持久化三件套）。

## 二、解决方案（三阶段，一次做完）

### 阶段一：设计系统主体（治"没有主体"）

**Step 1.1 新建 `src/UI/Resources/Styles/DesignTokens.xaml`**（单一事实源）
- 色板：主色 `#0066CC`（废弃 `#1890FF`/`#667EEA`）+ 语义色（Success `#00CC99`/Warning `#FF9900`/Danger `#FF4444`）+ 中性灰 5 档（白/亮 `#F5F5F5`/线 `#E0E0E0`/次文字 `#999999`/正文 `#333333`）
- 字号 10/12/13/14/16/18 六档、圆角 4/6/8 三档、间距 4/8/12/16 四档、阴影 1 档
- 每个 token 同时定义 `Color` + `Brush`（沿用 CanvasStyleResources 成对模式）

**Step 1.2 全局隐式样式（进 App 资源）**
- `Button/TextBox/ComboBox/TabItem/DataGrid/ScrollBar/CheckBox` 各一套隐式样式（统一高度 28、圆角、Padding、hover）
- 删除全部窗口内联 Button 模板（MainWindow 5 处 + 各 Dialog）

**Step 1.3 全仓硬编码色替换**（27 个 XAML，规则见附录）

**Step 1.4 清理**：删孤儿 `src/UI/Themes/AppResources.xaml`；SDK 层 `Generic.xaml:23-32` 的 `#1890FF` → `#0066CC`

### 阶段二：主界面解耦（治"巨石"）

**Step 2.1 拆 XAML**：MainWindow 留骨架，拆 6 个区域 UC：

```
MainWindow.xaml（骨架 ~100 行：ShellTopBar + 分栏面板 + ShellStatusBar）
├── ShellTopBarControl.xaml      ← 一体化标题栏（logo+菜单+工具栏，WindowChrome）
├── ShellToolboxControl.xaml     ← 左侧双模工具箱（收编现有 ToolboxControl）
├── ShellWorkspaceControl.xaml   ← 中间：流程管理条+多流程Tab+画布+小地图
├── ShellImagePanelControl.xaml  ← 右侧：图像/模块结果+图像源+结果表
├── ShellLogPanelControl.xaml    ← 底部：数据分析+日志
└── ShellStatusBarControl.xaml   ← 三段式状态栏
```

**Step 2.2 拆 ViewModel**：`ShellViewModel`（组合根）+ 6 个域 VM（TopBar/Toolbox/Workspace/ImagePanel/LogPanel/StatusBar）；60+ 事件处理器迁 RelayCommand；`WorkflowTabControlViewModel:242-249` 假运行 → 接真实引擎。

**Step 2.3 死 UI 治理**（rule-008/015）：菜单能接线的接线，没功能的删，禁止假功能占位。

### 阶段三：布局升级对标 VM（治"LOW"）——吸收参考项目 GridSplitterBox 思路

**Step 3.0 自研"可折叠分栏面板"控件 `CollapsibleSplitterBox`**（本方案核心新增，替代 AvalonDock）

新建 `src/UI/Controls/Common/CollapsibleSplitterBox.cs` + `Themes/CollapsibleSplitterBox.xaml`，吸收参考项目 `GridSplitterBox` 三件套（[来源] 参考项目 `GridSplitterBox.xaml.cs:595-598`、`GridSplitterBox.xaml:84-261`）：

| 参考项目特性 | 我们控件的映射 |
|-------------|--------------|
| `MenuDock` Left/Right/Top/Bottom 四方向一套模板 | 同样支持四方向，右侧面板用 Right、底部日志用 Bottom |
| `Mode` 双档：`Extend`（缩成图标条）/ `Hidden`（完全隐藏） | `CollapseMode`：`IconStrip` / `Hidden` |
| `MenuWidth` 双向绑定 + `GridSplitter` 拖宽 | 同样拖宽 + `MinWidth/MaxWidth` |
| `IMetaSetting` 拖完 Save、重启恢复 | `LayoutSettings` 服务保存到配置（JSON），拖完即存 |
| `MenuMinWidth` 折叠后露图标条 | 折叠后露 24px 图标条（含展开箭头） |

```
CollapsibleSplitterBox 使用（MainWindow 骨架中）：
├── <CollapsibleSplitterBox Dock="Left"   CollapseMode="IconStrip">  ← 工具箱
├── <CollapsibleSplitterBox Dock="Right"  CollapseMode="Hidden" InitialWidth="460">  ← 右侧面板
├── <CollapsibleSplitterBox Dock="Bottom" CollapseMode="Hidden">  ← 日志
└── 中间 ContentControl → ShellWorkspaceControl
```

**Step 3.1 一体化标题栏**：WindowChrome 自绘，logo 跨两行居中，菜单 5 个收敛（文件/设置/工具/系统/帮助），工具栏 15 方块图标。

**Step 3.2 左侧工具箱**：**双模机制原样保留**（60px 图标条 + 悬停 Popup + 展开分类树 + 切换按钮），仅视觉统一（选中色 `#667EEA`→`#0066CC`、28 处硬编码色 Token 化、emoji 换 Path 几何、圆角 4px 对齐全局样式）。回归重点：紧凑↔展开切换、Popup 悬停、工具拖拽。

**Step 3.3 右侧深色面板 + 专业结果表**：默认 460px，由 Step 3.0 控件管理折叠（竖条/隐藏/记忆）；Tab 结构 `图像|模块结果` + 图像源缩略条 + `当前结果|历史结果`；列名用机器视觉术语（序/转换坐标X/转换坐标Y/转换角度/重叠程度/平移X/平移Y/旋转/宽度/高度/斜切/宽高比）。

**Step 3.4 三段式状态栏**：`●状态 │ 流程0ms 模块0ms 算法0ms ── 80% │ 时间 消息 版本`，删假 CPU/FPS。

**Step 3.5 右下角小地图**：流程缩略图 + 红框标记当前视图位置。

**Step 3.6 画布顶部内嵌流程管理条**：流程名 + `≡` 菜单 + 搜索/适配按钮。

**Step 3.7 节点命名"编号+名"**：如"1.20 图像源1"，编号=执行顺序。

**Step 3.8 图标统一**：集中 `Icons.xaml` 资源字典，全部 Path 几何方块按钮。
