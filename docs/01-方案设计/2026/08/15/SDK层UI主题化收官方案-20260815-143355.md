# SDK 层 UI 主题化收官方案

创建日期：2026-08-15

## 概要

本文档为 SDK 层 UI 主题化改造的收官方案。上一轮改造已覆盖"SDK 自绘控件"（参数模板那套），但仍存在三类"漏网"不受主题系统控制：① 弹窗/下拉内部的标准控件白底；② 系统标准控件（下拉/输入框/复选框/单选框/树/滚动条/滑块）无隐式样式，走 WPF 默认白样式；③ 字符图标/裸文字缺前景色、彩色 emoji 字形自带色，深色主题下变黑或无法跟随主题。

本方案以"在 SDK `Generic.xaml` 补标准控件隐式样式 + 激活闲置 ScrollBar token"为治本思路，一次消灭整类问题。

## 🔄 改前 → 改后 → 依据

### 改前（用户视角）

上一轮改造后，**SDK 自己画的控件**（参数模板那套：输入框、开关、滑块、调色板…）已经能随主题切换。但还有三类东西"漏网"，深色主题下特别明显：

1. **弹窗/下拉里是"白瓤"**：比如图像源选择器的下拉，外框是深灰、里面列表却是**死白**，滚动条也是白的——一眼就看出来不是一套皮肤。
2. **系统标准控件全是"白底"**：参数面板里的下拉框、复选框、单选框、树形选择、输入框，以及 ROI 编辑面板里十几个输入框/复选框/滑块，全走 WPF 出厂白样式，深色主题下刺眼。
3. **图标颜色不听指挥**：参数面板的 ⚡ 切换按钮、数字框的 ▲▼、绑定图标 🔗 在深色下是**黑的**（没设颜色，继承了系统默认黑）；调色板的 🖌️、绑定的 🔗 是**彩色 emoji**（字形自带色，切主题完全没反应）。

### 改后（用户视角）

深色主题下所有角落都统一：

- 图像源下拉：**深灰列表 + 深灰滚动条 + 主题高亮选中**，和外框一个皮肤。
- 所有下拉/输入框/复选框/单选框/树/滚动条/滑块：**全部深色主题化**，一个白色控件都找不到。
- 图标：⚡▲▼ 变浅色可见、悬停变主题蓝；🖌️🔗 从彩色 emoji 换成**单色矢量图标**，随主题变色。
- 区域编辑面板里 15 个文字标签（名称/模式/X/Y/宽/高…）深色下**浅色可读**。
- ROI 画在**图像上**的蓝/橙框、白字标签**保持原样**——那是图像叠加层的对比度色，固定是有意设计（视觉软件惯例）。

### 依据（业界参考）

| 框架 | 做法 | 借鉴点 |
|------|------|--------|
| **WPF 官方**（MS Learn "Resources and themes"） | 主题字典（ResourceDictionary）+ `DynamicResource` + 隐式样式（`TargetType` 无 key）主题化标准控件 | 标准控件主题化 = 隐式样式，本项目 `Generic.xaml` 正是官方 theme dictionary 模式 |
| **Material Design In XAML**（开源） | `BundledTheme` 主题字典只存 token，控件样式集中在 Style 库，颜色全部 `DynamicResource` 引用 | 主题字典保持"纯 token"，样式单点维护——与现有 `Generic.xaml` + Light/Dark token 架构完全一致 |
| **Visual Studio / VS Code 深色主题** | 所有标准控件（含滚动条）重新模板化，深色下无白色残留 | 滚动条必须单独模板化（本项目 UI 主题已备好 4 组 token 但无人消费） |
| **Avalonia UI** | 主题资源统一管理 + 控件样式分层 | token 与样式分离，切换主题零代码改动 |

## 问题分析

- **表面需求**：深色主题下 SDK 控件仍有白底/黑字/彩图标，不统一。
- **根本问题**：**主题化只覆盖了"自绘控件"，没覆盖"标准控件 + 字符/文字层"**。标准控件缺隐式样式 → 全部落回 WPF 默认；字符图标/裸文字缺 Foreground → 继承链断在系统默认色。
- **问题分类**：功能缺失（主题系统未覆盖全量 UI 元素）。

### 架构分配检查

- 归属层：SDK `Generic.xaml`（已有样式库集中地）— [来源] Generic.xaml 全篇
- 已有类似机制：无（Generic.xaml 无标准控件隐式样式）— [来源] 全量 Style 检索
- 不改能否覆盖：不能（逐个 XAML 补 DynamicResource = 点对点补丁，正是当前"大量遗漏"的成因）
- 是否改变分层边界：否（保持 Light/Dark=纯 token、Generic.xaml=样式库的现状）

### 方法对比（3 候选）

| 维度 | 方案 A：Generic.xaml 补隐式样式（推荐） | 方案 B：逐控件模板补 DynamicResource | 方案 C：样式下沉到 Light/Dark 各一份 |
|------|------|------|------|
| 实现方式 | 标准控件隐式样式集中在 Generic.xaml，激活 ScrollBar 死 token | 每个弹窗/面板逐个补色 | Light/Dark 字典各放一套完整样式 |
| 架构一致性 | ✅ 与现状完全一致（样式库单点） | ❌ 点对点补丁 | ⚠️ 破坏"纯 token"设计，样式双份 |
| 复杂度 | 中（新增 9 类样式） | 低单点但总量大（10+ 文件逐个） | 高（两套模板重复维护） |
| 维护成本 | 低（一处改全应用生效） | 高（每次新增控件都可能漏） | 高（双份同步） |
| 覆盖范围 | SDK+UI 两层标准控件全解决 | 只解决当前点 | 仅 UI 宿主内，SDK 无宿主仍白 |
| 长期 ROI | 6月✅/1年✅/3年✅ | 6月⚠️/1年❌ | 6月✅/1年⚠️/3年❌ |

**推荐 A**：一次消灭"标准控件白底"整类问题，与现有"token 与样式分离"架构天然一致，并激活 8 个闲置 token（零新增 UI token）。B 是当前遗漏的成因，C 破坏分层。

## Bug 模式分析

**当前问题**：SDK 标准控件/字符图标/裸文字不受主题控制。

**真因分类**：**契约漏洞**（主题系统缺少"标准控件层"这一契约面）+ 实现偏差（token 已备但无样式消费）。

**同类潜伏点**：
- [来源] `Generic.xaml:107/239/1274/1423` — 模板内标准控件全部未接主题
- [来源] `RoiInfoPanel.xaml` / `RoiSubscribePanel.xaml` / `RoiEditorControl.xaml` — 视图层同 pattern
- [来源] `Generic.xaml:256/541/1385` + `ParamBinding.cs:98` — 字符/emoji 图标同 pattern
- [来源] `LightTheme.xaml:74-78` + `DarkTheme.xaml:74-78` — **8 个已定义 token 无人消费（死 token）**

**治本点**：在样式库集中地（Generic.xaml）补齐"标准控件隐式样式 + 字符默认色"，而非逐个弹窗打补丁。**死 token 是信号**——token 定义了却没样式消费，说明标准控件层从未被接入。

## 解决方案

### 技术方案

1. **SdkThemeKeys.cs 补 4 个 ScrollBar key**（字符串与 UI `ThemeKeys.cs:161-171` 一致）：`ScrollBarBackgroundBrush/ScrollBarThumbBrush/ScrollBarThumbHoverBrush/ScrollBarThumbPressedBrush` → 自动纳入 `ThemeManager.ValidateSdkThemeKeys` 反射校验（[来源] ThemeManager.cs:167）。
2. **DefaultTheme.xaml 补 4 个兜底值**（亮色基准对齐 UI Light 值，来自 ColorConstants 现有中性色）。
3. **Generic.xaml 新增标准控件隐式样式**（核心，一次解决 A 类全部）：
   - `ScrollBar`（模板化，消费新 token）
   - `ListBox`（背景 `InputBackgroundBrush`、ItemContainer 选中/悬停主题色）
   - `ComboBox`（输入框风格 + 下拉列表整体主题化）
   - `TextBox`（`InputBackgroundBrush` 底、主题色光标/选中块）
   - `CheckBox` / `RadioButton`（文字 `TextPrimaryBrush`、勾选 `AccentBrush`）
   - `TreeView` / `TreeViewItem`（背景透明、选中/悬停主题色）
   - `Expander`（头部 `TextPrimaryBrush`）
   - `Slider`：现有 `SliderStyle`（key 样式）升级为**隐式样式**，`NumericUpDown` 内 `StaticResource SliderStyle` 引用保留兼容
   - `TextBlock` 隐式样式：`Foreground=TextPrimaryBrush`（兜底解决 B 类裸文字/字符继承链，显式设置优先不打架）
4. **图标修复**（B 类）：
   - ⚡/▲▼/绑定图标：补 `Foreground={DynamicResource TextSecondaryBrush}` + 悬停 `AccentBrush`
   - 🖌️ ×2：换 `Path` 矢量图标 + `Fill` 主题色
   - 🔗（ParamBinding.cs:98/313 + Generic.xaml:1385）：emoji 默认值 → 模板内 `Path` 矢量 + 主题色 `Fill`
5. **ImageSourceSelector 弹窗**：`ListBox` 补 `Background={DynamicResource ContextMenuBackgroundBrush}`（隐式样式已含，此处仅兜底确认）。
6. **AllControlsPreview.xaml**：5 处硬编码色 → 语义 key。
7. **ROI 视图**：零改动（隐式样式自动生效）。
