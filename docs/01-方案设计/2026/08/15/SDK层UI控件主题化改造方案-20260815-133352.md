# SDK 层 UI 控件全面接入主题系统（Token 化改造）方案

## 🔄 改前 → 改后 → 依据

### 改前（你看到的痛点）
现在切到**暗色主题**后，主界面（顶栏、状态栏、工具箱）都变深色了，但**一旦打开工具的参数面板、ROI 编辑器、或点开"选择数据源"弹窗**，会突然跳出一大片**刺眼的白底**：
- ROI 编辑器的卡片、模式切换条是浅灰/白色底
- "选择数据源"弹窗整个是白底深字，确认按钮还是亮蓝
- 下拉框、滑块轨道、开关控件是白底/浅灰轨道
- 工具调试窗口（DefaultDebugWindow）反而是正常深色的——因为只有它和图像控件真正接了主题

### 改后（你将得到的）
任意工具的参数区、ROI 编辑器、弹窗**全部跟随明/暗主题**：暗色下是深底浅字，亮色下是白底深字，和主界面完全统一。切主题的一瞬间全部一起变，不再有"深色界面里突然一块白"。
同时，**画在图像上的 ROI 线（检测区域蓝、屏蔽区域橙）保持固定颜色**——这是行业惯例（叠加在图像上必须保证对比度），不随主题变化。

### 依据（业界参考）
- **WPF 官方机制**：`ResourceDictionary.MergedDictionaries` 顺序遍历、后定义者胜出——本项目 `ThemeManager` 已按此实现（[来源] ThemeManager.cs:22-26）
- **Avalonia UI ThemeVariants**：官方文档明确"主题变体专用资源 + `DynamicResource` 引用 + 同名 key 不同值"（[来源] docs.avaloniaui.net/docs/styling/theme-variants/ §ThemeDictionaries）——本项目 `SdkThemeKeys` + Light/Dark 双字典正是此模式
- **Material Design in XAML**：`BundledTheme BaseTheme="Light/Dark"` 统一主题基底 + 语义色板（[来源] MaterialDesignInXamlToolkit wiki Getting-Started）——控件样式只引用语义 token，不写死颜色
- **VisionMaster / Halcon**：ROI 叠加在图像上的区域色（检测/屏蔽）固定，不随 UI 主题切换（[来源] CSDN "VM图形收集显示ROI框及颜色"）

## 问题分析（Phase 0）

- **表面需求**：SDK 层 UI 控件也受主题系统管理
- **根本问题**：SDK 层 token 机制（`SdkThemeKeys`+`DefaultTheme`）已建好并被 `ImageControl`/`DefaultDebugWindow` 使用，但 **ROI 编辑器系列 + Generic.xaml 样式库是早期硬编码存量**，绕过 token → 不随主题切换
- **问题分类**：实现方式有误（机制先行、存量没跟上）+ 架构冗余风险（两套颜色来源：token vs 硬编码）

**架构分配检查**：主题归属天然在 SDK `UI/Themes/` 层（已有机制）；不改则 `ThemeManager.ValidateSdkThemeKeys` 契约保护空转（只保证 key 有定义，不保证控件真的用 key）；本次不改变分层边界，是"存量对齐现有机制"。

---

## Bug 模式分析（Phase 0.5）

**当前问题**：SDK 控件硬编码色 → 不随主题切换 → 暗色主题下刺眼白底。

**真因分类**：**契约漏洞**——主题系统与控件之间缺少"控件必须用 token 引用颜色"的强制契约。`ValidateSdkThemeKeys`（ThemeManager.cs:169-185）只校验 **key 定义存在**，不校验 **控件是否引用 key**；硬编码色控件可任意绕过。

**同类潜伏点**：
- [来源] `Generic.xaml:45-1694` — 17 个隐式样式 + 9 个命名样式全部或部分硬编码
- [来源] `NodeSelectorPopup.xaml:25-208` — 23 处全硬编码
- [来源] `RoiEditorControl.xaml:17-66` — 卡片/容器硬编码
- [来源] `ToggleSwitch.cs:144-192` — DP 默认值硬编码 + `IsDarkTheme` 手切属性（Generic.xaml:643）
- [来源] `RoiInfoPanel.xaml:26` + `RoiSubscribePanel.xaml:23-71` — 系统默认控件（GroupBox）无样式

**治本点**：修复"**SDK 控件必须通过语义 key 引用颜色**"这一契约漏洞，而非逐个弹窗打补丁。

## 解决方案（方案 A 实施步骤）

### 第一阶段：主题 key 扩充（4 个文件同步）
1. `src/UI/Themes/Base/ThemeKeys.cs` — 新增 `SliderTrackBackground` / `ToggleOffBackground` / `SuccessLightBackground` 三组 Color+Brush 常量
2. `src/UI/Themes/Light/LightTheme.xaml` + `src/UI/Themes/Dark/DarkTheme.xaml` — 补 3 个 key 的明/暗值
3. `src/Plugin.SDK/UI/Themes/SdkThemeKeys.cs` — 补 3 个 key 常量（与 ThemeKeys 字符串一致）
4. `src/Plugin.SDK/UI/Themes/DefaultTheme.xaml` — 补 3 个 key 兜底值

### 第二阶段：Generic.xaml 样式库去硬编码（约 41 处）
按映射表把 `White`/`#E0E0E0`/`#F0F7FF`/`#E6F7FF`/`#0066CC`/`#555`/`#999`/`#D0D0D0` 等全部换成 `{DynamicResource {x:Static themes:SdkThemeKeys.XXX}}`。范围：ParamComboBox、ParamTextBox、LabeledControl、ConfigSetting、ImageSourceSelector、ParamGroup、TabControl/TabItem、Slider、NumericUpDown、ToggleSwitch、RangeSlider、RangeInputControl、ColorPicker、ColorSelector、DispItemColorControl、DispTextColorControl、ParamBinding、ShapeButtonStyle、SegmentedToggleStyle、SliderStyle、ColorPicker 三样式。

### 第三阶段：ROI 视图系列去硬编码（5 个 xaml）
- `RoiEditorControl.xaml`：CardStyle 边框/底、模式切换容器、类型标签底 → token
- `ShapeToolBar.xaml`：选中态 `#E8F4FC/#0066CC` → `ControlHoverBackgroundBrush/AccentBrush`
- `NodeSelectorPopup.xaml`：23 处全量替换（白底→PanelBackground、文字→TextPrimary/Secondary/Disabled、确认按钮→Accent、匹配标签→Success+SuccessLight）
- `DrawingParameterPanel.xaml`：分隔线→Divider、标题→TextPrimary
- `RoiInfoPanel.xaml` / `RoiSubscribePanel.xaml`：`Gray`→TextSecondary；补 GroupBox 隐式样式（Generic.xaml 新增：背景 Transparent/InputBackground、边框 BorderBrush、Header 文字 TextPrimary）

### 第四阶段：ToggleSwitch 去硬编码（2 个文件）
- `ToggleSwitch.cs`：DP 默认值改为从主题取（OnBackground→AccentBrush、OffBackground→ToggleOffBackground、ThumbColor→TextOnDarkBrush），删除 `IsDarkTheme` 手切属性（绕开主题的旧机制，rule-008 零兼容直接删）
- `Generic.xaml` ToggleSwitch 模板：删 `IsDarkTheme` 触发器（646-647 行），统一走 token

### 第五阶段：ROI 语义内容色收敛（3 个文件，保持固定）
- `ColorConstants.cs` 新增：`InspectionBlue=#4488FF`、`MaskOrange=#FFA500`、`InspectionFill(30,0,120,215)`、`MaskFill(30,255,165,0)`、`LabelBg(180,0,0,0)`，注释"ROI 内容色固定，不随主题切换"
- `RoiEditorControl.xaml.cs`：`RegionTypeTitleBrush`（251/266-267）、handleColor（2125-2130）、橡皮筋（1331/1343）、标注（2269-2270）→ ColorConstants
- `RoiEditorManagerControl.xaml`：蓝/橙边框（14/22）→ `x:Static` ColorConstants
- `WpfShapeRenderer.cs`：Mask/Inspection 填充边框（343-351）、标注（625-627）→ ColorConstants

## 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 3 个新增 key 四处不同步导致启动抛异常 | 程序起不来 | 一次性同步四处；契约校验兜底并给出缺失 key 清单 |
