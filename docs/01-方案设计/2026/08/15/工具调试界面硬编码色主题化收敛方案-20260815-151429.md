# 工具调试界面硬编码色主题化收敛方案

> 日期：2026-08-15
> 类型：方案/设计（SDK 层主题化收官，工具层硬编码色收敛）

---

## 🔄 改前 → 改后 → 依据（写在最前面）

### 改前（用户视角）

把 BlobAnalysis（区域分析）等工具的调试窗口切换到深色主题后，**一批面板/分隔线/文字还是原来的浅色或白色**：
- "结果显示" Tab 整页是浅灰白底（`#F5F5F5`），里面三个折叠面板（结果判断/图形显示/文本显示）全是**死白底** + 浅灰边框——深色下这一页最扎眼
- 各工具的 Separator 分隔线在深色下是一条刺眼的浅灰亮线
- 部分说明文字（`#666`/`#888`）在深色背景下对比度不足，发灰看不清

这不是个例，**几乎每个工具的调试界面都有一批漏网的硬编码颜色**，导致"SDK 层都主题化了，工具层还白着"的断层。

### 改后（用户视角）

- 所有工具的调试窗口在浅色/深色主题下都跟随主题切换，面板底、边框、分隔线、说明文字颜色全部统一
- 深色主题下不再有死白面板、浅灰亮线、看不清的灰字
- 用户切换主题后，所有工具界面观感一致

### 依据（业界参考）

- WPF 主题化的标准做法是 `DynamicResource` + 语义化资源 key（微软 WPF 样式/模板最佳实践）
- WPF 资源优先级：**显式赋值 > 隐式样式**——这正是本次问题的根源：上一轮在 `Generic.xaml` 加的隐式样式盖不住显式硬编码的颜色
- 视觉软件（VisionMaster/VisionPro）惯例：UI 皮肤色随主题，图像叠加层/状态语义色（绿/红/蓝）不随主题，保持对比度

## 二、三类划分（决定改哪些）

| 类别 | 判定 | 建议 |
|------|------|------|
| **A 类：UI 皮肤硬编码（明确要修）** | `White`/`#FFFFFF`、`#F5F5F5`/`#FAFAFA`/`#F8F8F8`/`#F0F2F5` 面板底、`#E0E0E0`/`#D0D0D0`/`#EEEEEE` 边框分隔线、`#333333`/`#555555`/`#666`/`#888`/`#999` 文字、`#F0F0F0` 控件底 | **全部换语义 key**（见映射表） |
| **B 类：工具层配色约定（可商榷）** | DataAnalysis 面板统计数字 6 色 | 6 工具统一，浅色下无碍；深色下 `#FF9800`/`#E91E63` 刺眼。可暂缓或引入"数据色板" token |
| **C 类：有意固定（勿动）** | 图像叠加高亮黄、ROI 边框蓝/橙、图形 OkColor、`#107C10` 就绪绿/`#CC0000` 错误红/`#007ACC` 品牌蓝（语义状态色） | **保持原样**，是视觉软件惯例（对比度色不随主题） |
| **D 类：待确认** | `AssemblyReferenceDialog.xaml` 整窗 VS Code 固定深色 | 若是有意设计（编辑器场景固定深色）可不动；否则需整体主题化 |

## 五、修复原则

1. **治本**：把工具层 `#F5F5F5` / `White` / `#E0E0E0` 全部换成 SDK 语义 key 的 `DynamicResource`，而非点对点补丁。
2. **遵循 rule-004/008**：复用现有基础设施（SDK 语义 key），零兼容、报错优先、无回退机制。
3. **C 类不动**：图像叠加层/状态语义色保持原样（视觉软件惯例）。
