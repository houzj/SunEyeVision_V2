# 弹窗标题栏接入主题系统方案

## 🔄 改前 → 改后 → 依据（写在最前面）

### 改前（用户视角）
- 主窗口标题栏、打开解决方案窗口都是**自绘**的，跟着亮/暗主题变。
- 但其它弹窗（新建解决方案、编辑、另存为、关于、帮助、相机管理、通讯管理、全局变量管理、目标参数、添加相机）——**标题栏还是 Windows 系统默认的白色/灰色**，深色主题下一打开就"亮瞎眼"，和整体 UI 明显脱节。

### 改后（用户视角）
- 切到深色主题，所有弹窗的标题栏**同步变深灰、标题文字自动变白**；切回亮色主题，标题栏自动恢复浅色。
- 切主题的瞬间，已经打开着的弹窗标题栏**不用重启、立即跟着变**。
- 拖动窗口、点关闭按钮、Alt+F4 这些系统操作全部保持原样，一个都不破坏。

### 依据（业界参考）
- **微软官方文档**（[learn.microsoft.com/.../apply-windows-themes](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-windows-themes)）：Win32/WPF 应用让系统标题栏跟随明暗的标准 API 就是 `DwmSetWindowAttribute(hwnd, DWMWA_USE_IMMERSIVE_DARK_MODE=20, &value, 4)`，设置后标题栏底色和文字颜色由系统自动适配。Windows 10 1809 用属性值 19，1903+ 和 Win11 用 20。
- **Qt 生态**（CSDN TitleBarHelper 实践）：Qt 应用也是用同一个 DWM API 让系统标题栏颜色跟随主题动态切换——跨框架同一招，验证这是标准答案。
- **Visual Studio 2022 / VS Code 等**：深色主题时标题栏跟随应用暗色，要么用 DWM，要么用 `WindowChrome` 自绘（本项目主窗口已是自绘模式，弹窗无需再走重路）。

## 问题分析（Phase 0）

- **表面需求**：弹窗标题栏不受主题管理。
- **根本问题**：主题系统（ThemeManager + 语义色板）只覆盖了 WPF 客户区（控件内容靠 `DynamicResource` 自动变色），**Win32 非客户区（系统标题栏）由操作系统绘制，从不感知应用主题**。这是架构层面的覆盖空白。
- **问题分类**：设计缺陷（架构空白，非实现 bug）。

### 架构分配检查
- 最自然归属层：`ThemeManager`（主题状态的唯一真相源）+ 一个 DWM 工具类（标题栏明暗的应用器）。— src/UI/Services/ThemeManager.cs:84-106
- 已有类似机制：无（系统标题栏从未被主题化）。
- 不改是否能覆盖：不能，系统标题栏无任何 WPF 绑定入口。
- 是否改变分层边界：不改变。新增工具类放 Services 层（与 ThemeManager 同级），窗口基类放 Shell/Windows（与 MainWindow 同级）。

## 方案对比（≥3 候选）

| 维度 | 方案 A：DWM 沉浸式暗色（推荐） | 方案 B：全部自绘标题栏 | 方案 C：DWM + 系统级只读 |
|------|------------------------------|------------------------|------------------------|

| 维护成本 | 低：新窗口继承基类即自动生效 | 中高：每个弹窗独立维护标题栏 | 低但无效 |
| 长期 ROI | 6月✓ / 1年✓ / 3年✓ | 1年✓ / 3年✓（若追求品牌色标题栏） | ✗ |

**推荐方案 A**，理由：
1. 治本于"非客户区未纳入主题管理"这一架构空白（微软官方标准 API）。
2. 颜色实测协调：暗主题系统深灰 #202020 ≈ 主题 #2D2D30，亮主题白 ≈ #F5F5F5。
3. 改动最小、回归风险最低：**XAML 布局一行不动**，只动类继承和工具层。
4. 若未来想升级为品牌色自绘标题栏，`ThemeDialogWindow` 基类就是唯一改造点（单一控制点）。

## 解决方案与实施步骤

### 技术方案
1. **新增 `WindowTitleBarThemer`**（Services 层）：封装 DWM P/Invoke，`Apply(Window, bool isDark)` 只作用于 `WindowStyle != None` 的窗口；先试属性值 20，`E_INVALIDARG` 则试 19；失败记 Warning 日志（Fail-Forward）。同时暴露静态 `CurrentTheme` 供基类读取。
2. **新增 `ThemeDialogWindow : Window` 基类**（Shell/Windows 层）：`OnSourceInitialized` 里按 `WindowTitleBarThemer.CurrentTheme` 自动应用标题栏明暗。新弹窗继承即自动跟随主题（单一控制点）。
3. **11 个 Dialog 改继承**：`.cs` 的 `: Window` → `: ThemeDialogWindow`，`.xaml` 根元素 `<Window>` → `<themeWindows:ThemeDialogWindow>`（加 xmlns 指向 `SunEyeVision.UI.Shell.Windows`）。XAML 布局完全不动。
4. **ThemeManager 统一刷新**：`Initialize`/`ApplyTheme` 时更新 `WindowTitleBarThemer.CurrentTheme`；`ApplyTheme` 里遍历 `Application.Current.Windows`，对系统标题栏窗口即时重设 → 切主题瞬间所有已打开弹窗立即跟随。

## 附录：SDK 调试窗口主题化补充方案

> 本附录覆盖用户确认纳入改造的 SDK 层工具调试窗口（DefaultDebugWindow / CustomDebugWindow）。
> 与正文 DWM 系统标题栏方案并行，二者互不冲突：DWM 管系统非客户区，本方案管 SDK 自绘客户区。

### 改前（用户视角）
- 打开任何一个工具的调试窗口：**标题栏永远是深黑的**（`#1E1E1E`）、底部按钮栏也是深灰的，不管亮色还是暗色主题都一样。
- 切到亮色主题后整个界面都变亮了，**就工具调试窗口的标题栏还是黑的**，特别突兀。
- 隐藏 bug：`CustomDebugWindow`（无边框窗口壳）一创建就崩——它 `FindResource("SurfaceBrush")` 引用的资源键在整个项目里根本没定义。

### 改后（用户视角）
- 亮色主题下：标题栏变浅灰、文字变深色、底部按钮栏变白，与主界面浑然一体。
- 切暗色主题：标题栏自动变深、文字变白，**已打开的窗口不用重启，瞬间跟着变**（DynamicResource）。
- 所有工具（阈值、滤波、定位、脚本……）的调试窗口一次性全部受益——改的是 SDK 公共窗口。

### 依据（业界参考）
- **Fluent Design / VS Code 语义色板**：控件不写死颜色，只引用"标题栏背景""主文字"这类语义 Token，主题切换时 Token 值整体替换。本项目 UI 层已按此建好 `ThemeKeys` + Light/Dark 字典，SDK 层接入同一套契约即可。

**关键结论**：
1. SDK 语义色板机制已完整存在（SdkThemeKeys + DefaultTheme + ThemeManager 契约校验），`DefaultDebugWindow` 是漏网的"硬编码孤岛"。
2. UI 层 Light/Dark 字典已含所需 4 个键（经 ThemeKeys.cs 第 18/29/182/194 行核实），SDK 只需：补键 → 补兜底值 → XAML 改引用，**UI 层主题字典零改动**。
3. `CustomDebugWindow` 的 `SurfaceBrush` 键无定义 → 实例化即抛异常，本次一并修复。
4. `CustomDebugWindow` 无任何 `new` 调用方（仅 SDK 注释提及），属未使用公共 API。按 rule-008 可删除，但它是 SDK 对外窗口壳，**采用"保留 + 修复"**（用户已选一起改造）。

### SDK 层解决方案

**一、`SdkThemeKeys.cs` 补 4 个语义键**（键字符串与 UI `ThemeKeys` 完全一致 → 契约校验自动通过，UI 字典零改动）：

```csharp
// ============ 顶栏 / 标题栏 ============
/// <summary>标题栏背景，对应 UI ThemeKeys.TitleBarBackgroundBrush</summary>
public const string TitleBarBackgroundBrush = "ThemeTitleBarBackgroundBrush";
/// <summary>标题栏文字，对应 UI ThemeKeys.TitleBarTextBrush</summary>
public const string TitleBarTextBrush = "ThemeTitleBarTextBrush";
/// <summary>标题栏按钮悬停背景，对应 UI ThemeKeys.TitleBarButtonHoverBrush</summary>
public const string TitleBarButtonHoverBrush = "ThemeTitleBarButtonHoverBrush";
// ============ 控件底色 ============
/// <summary>控件默认背景（按钮/输入框等），对应 UI ThemeKeys.ControlBackgroundBrush</summary>
public const string ControlBackgroundBrush = "ThemeControlBackgroundBrush";
```

**二、`DefaultTheme.xaml` 补 4 个兜底值**（亮色基准，来自 `ColorConstants`）：

```xml
<SolidColorBrush x:Key="{x:Static themes:SdkThemeKeys.TitleBarBackgroundBrush}"
                 Color="{x:Static constants:ColorConstants.BackgroundGray}"/>
<SolidColorBrush x:Key="{x:Static themes:SdkThemeKeys.TitleBarTextBrush}"
                 Color="{x:Static constants:ColorConstants.TextPrimary}"/>
<SolidColorBrush x:Key="{x:Static themes:SdkThemeKeys.TitleBarButtonHoverBrush}"
                 Color="{x:Static constants:ColorConstants.BackgroundHover}"/>
<SolidColorBrush x:Key="{x:Static themes:SdkThemeKeys.ControlBackgroundBrush}"
                 Color="{x:Static constants:ColorConstants.Background}"/>
```

**三、`DefaultDebugWindow.xaml` 硬编码色 → 语义键**（映射表，引用方式同 `Generic.xaml`：`{DynamicResource {x:Static themes:SdkThemeKeys.X}}`）：

```csharp
// 改前（SurfaceBrush 无定义 → 运行即崩）
Background = (Brush)FindResource("SurfaceBrush"),
BorderBrush = (Brush)FindResource("BorderBrush"),
// 改后（语义键 + 动态绑定）
SetResourceReference(BackgroundProperty, SdkThemeKeys.PanelBackgroundBrush);
SetResourceReference(BorderBrushProperty, SdkThemeKeys.BorderBrush);
```
