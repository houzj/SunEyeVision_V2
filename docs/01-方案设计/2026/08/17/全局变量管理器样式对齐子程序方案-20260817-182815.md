# 全局变量管理器样式对齐子程序方案

## 🔄 改前 → 改后 → 依据（写在最前面）

### 改前（用户视角）
打开「全局变量管理器」表格，看到四个别扭的地方：
1. **「当前值」列显示的不是真实值**，而是一串 `System.Int64[]` 之类的类型名，根本看不出变量实际存了什么。
2. **「名称」「注释」必须双击才能编辑**，单击只是选中，和子程序的输入输出表体验不一致。
3. **选中的那一行背景色很丑**（刺眼的系统蓝），而且**窗口失焦切到别处再回来，选中行颜色变成系统灰**，不受主题管控。
4. 表格整体有分割线、列头有底线，视觉上比子程序的输入输出表"重"。

### 改后（用户视角）
全局变量管理器表格与子程序的输入输出表完全同一套视觉与交互：
1. **「当前值」显示真实值**：整型显示 `128`、双精度显示 `3.14`、布尔显示 `True`，图像类显示 `[图像]`、图形定义显示 `[图形定义]`，一眼看懂。
2. **「名称」「注释」单击即可编辑**，输入框就是带边框的编辑控件，无需再双击进入 DataGrid 编辑模式。
3. **选中行为主题蓝**，失焦后颜色不变、依然受主题管控，深浅主题下都统一。
4. 表格无分割线、列头无底线，视觉清爽。

### 依据（业界参考）
- 对齐本项目已有的「子程序输入输出设置」（`SubroutineDebugControl.xaml`）：每个单元格就是带边框的 `TextBox`/`ComboBox`，表格 `IsReadOnly=True`、`GridLinesVisibility=None`，交互直观、视觉统一。
- 选中/失焦颜色遵循主题资源 `ThemeTableRowSelectedBackground`（深色 `#0E639C` / 浅色 `#D6EAF8`），杜绝 Windows 系统默认高亮。

## 问题分析

### 需求拆解
- **表面需求**：把全局变量管理器的样式/交互对齐子程序输入输出表。
- **根本问题**：
  - 当前值列绑定 `object Value`，内存存数组形态（对齐 Halcon tuple 语义），WPF 对数组调 `ToString()` 显示 CLR 类型名。
  - 名称/注释用 `DataGridTextColumn`，默认单击选中、双击才进编辑。
  - 行样式定义了选中触发器，但单元格样式未覆盖选中/失焦状态，导致系统默认高亮叠加 + 失焦变灰。
- **问题分类**：实现有误（显示错误）+ 交互不一致（双击编辑）+ 样式缺陷（选中/失焦色）。

## 解决方案

### 技术方案

**外层表格（对齐子程序）：**
- `GridLinesVisibility="Horizontal"` → `None`
- `BorderThickness="1"` → `0`
- 移除 `HorizontalGridLinesBrush`
- `RowHeight="28"` → `32`
- 新增 `IsReadOnly="True"`（表格不进入 DataGrid 编辑模式，各单元格控件自己可编辑）
- 移除 `CellEditEnding="DataGrid_CellEditEnding"`
- 列头样式 `BorderThickness` `0,0,1,1` → `0`

**每列改为"带边框控件"：**
| 列 | 改法 |
|----|------|
| 序号 | 只读 `TextBox`（灰底不可改） |
| 名称 | 可编辑 `TextBox`（单击即改），失焦做重名校验 |
| 注释 | 可编辑 `TextBox`（单击即改） |
| 类型 | 下拉 `ComboBox`（加边框，去掉裸样式） |
| 当前值 | `TextBox` + 新转换器显示真实值；仅整型/双精度/字符串/布尔可编辑，图像/图形/矩阵只读占位 |
| 目标输出 | 保留不动 |
| 初始化 | 保留不动 |
| 操作 | 保留不动 |

**选中/失焦色修复：**
- 行样式补 `IsSelected` + 失焦（`IsKeyboardFocusWithin=False`）触发器，统一用 `TableRowSelectedBackground`。
- 单元格样式同样补选中/失焦触发器，杜绝系统默认高亮。

**重命名传播联动：**
- 名称列不再走 DataGrid 编辑模式，改由 `TextBox` 失焦事件触发。
- `ConfirmVariableRename` 增加显式 `oldName` 参数：因为名称 TextBox 绑定实时写回，进入校验时 `variable.Name` 可能已是新名，需以显式旧名判断是否发生改名，避免传播被跳过。

**死代码清理：**
- 删除 code-behind 里 `InverseBoolToVisibilityConverter`（与 `Converters/Visibility/` 下重复，XAML 实际引用后者）。
- 删除 `DataGrid_CellEditEnding`。

### 实施步骤
1. `GlobalVariableManagerViewModel.cs`：`ConfirmVariableRename` 加 `oldName` 参数。
2. `GlobalVariableManagerDialog.xaml.cs`：删死代码、删 `CellEditEnding`、加 3 个事件（名称失焦校验、名称聚焦记录旧名、当前值失焦解析）+ 显示转换器 `GlobalVariableValueTextConverter`（含 `ParseText`）。
3. `GlobalVariableManagerDialog.xaml`：改表格外层、改各列、补选中/失焦触发器、注册转换器。
4. 构建验证 UI 项目。

## 验收标准

### 功能验收
| # | 验收项 | 验收方法 |
|---|--------|---------|
| 1 | 「当前值」显示真实值（`128`/`3.14`/`True`），图像显示 `[图像]`，不再是 `System.Int64[]` | 目视 + 手动 |
| 2 | 「名称」「注释」单击即可编辑 | 手动 |
| 3 | 名称改名会校验重名，冲突弹窗并还原 | 手动 |
| 4 | 当前值可编辑列（整型/双精度/布尔/字符串）失焦后值正确保存 | 手动 |
| 5 | 图像/图形/矩阵等当前值为只读占位，不可误改 | 手动 |

### 边界/异常验收
| # | 验收项 | 验收方法 |
|---|--------|---------|
| 1 | 当前值输入非法（如整型填 `abc`）→ 弹窗提示并还原旧值 | 手动 |
| 2 | 名称输入为空 → 弹窗提示并还原旧值 | 手动 |
| 3 | 失焦后选中行颜色不变、深浅主题均为主题色 | 手动 |

### 数据一致性验收
| # | 验收项 | 验收方法 |
|---|--------|---------|
| 1 | 修改全局变量值 → 保存 → 重开方案，值保持一致（数组形态往返一致） | 手动 |
| 2 | 改名后所有引用处（节点参数绑定/模块结果）显示名同步更新 | 手动 |

## 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 名称列改 TextBox 后绑定时序导致重命名传播失效 | 引用处显示名不更新 | 显式 `oldName` 参数，失焦时比对文本与旧名 |
| 当前值解析失败静默 | 值未写入，用户无感 | 解析失败弹窗提示并还原显示 |
| 选中色触发器遗漏某状态 | 部分状态仍显示系统色 | 行 + 单元格都补选中/失焦触发器 |
