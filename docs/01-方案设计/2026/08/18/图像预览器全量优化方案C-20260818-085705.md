# 图像预览器全量优化方案（方案 C：纯 WPF 重建）

## 🔄 改前 → 改后 → 依据（写在最前面）

### 改前（用户视角）
图像源缩略图栏（`ImagePreviewControl`）为撑住上千张图，堆了 **6000+ 行自研代码**：1995 行优先级调度器、41KB 缓存管理、4 个解码器、3 套互相打架的缓存、内存压力监控。效果反而更差：
- **加载卡**：滚动时图片转圈，甚至 5 秒超时后**永久不显示**（`WicGpuDecoder.cs:86-94` 静默放弃）
- **内存没省**：三套缓存各管各的，`WeakReferenceCache` 存的其实是强引用，GC 收不掉
- **重开方案图像全丢**：用户选的图路径一个都没存进方案文件（`WorkflowNode.InputSource` 是运行时 `object?`，不序列化）
- **代码不可维护**：`goto`、空 catch、乱码注释遍布

### 改后（用户视角）
- **代码量砍 2/3**（6000 → 约 2000 行），删除 10 个重型文件
- **加载顺滑**：1000 张图用 WPF 内建虚拟化 + `DecodePixelWidth=100` 解码，每张缩略图 ≤50KB
- **重开方案图还在**：新增 `ImageSourceConfig` 随方案文件保存图路径，下次打开自动恢复（含当前索引、运行模式、勾选路径）
- **缓存干净**：只留 1 个极简磁盘缓存，不再三套互打架

### 依据（业界参考）
| 参考 | 做法 | 借鉴点 |
|------|------|--------|
| 参考项目 VisionMaster（本机源码 `MainWindow.xaml:303-414`） | `Expander + ListBox + VirtualizingStackPanel + DataTemplate` + `<Image Source="{Binding, Converter}">` + `DecodePixelWidth=100`，零自研调度/缓存 | 全盘采用组装式 + 信任 WPF 虚拟化 |
| 参考项目持久化（`SrcFilesVisionNodeData.cs:115-122`） | `SrcFilePaths`（路径集合）随流程文件 `[DataMember]` 序列化，`OnDeserializing` 恢复 | 只存路径、不存图片 |
| System.Runtime.Caching（.NET 官方） | 微软 LRU 缓存 | 参考其 LRU 语义（如需真 LRU） |
| WPF 虚拟化最佳实践 | `VirtualizingStackPanel` + `IsVirtualizing=True` 已足够，无需自写调度 | 砍掉 5 级优先级队列 |

## 三、Bug 模式分析

**当前问题**：缩略图加载慢、不显示、内存不省、重开方案图丢
**真因分类**：设计缺陷（过度调度/双轨缓存）+ 实现偏差（伪LRU/伪弱引用/死代码）+ 契约漏洞（无持久化）
**同类潜伏点**：
- `ImageSharpDecoder.cs:110` — 同款 5s 超时放弃（与 WicGpuDecoder 同 pattern）
- `WindowsShellThumbnailProvider.cs:191` — 缓存未命中静默返回 null
**治本点**：废弃整套自研加载链，回归 WPF 内建机制 + 只补持久化契约，而非逐个修症状
**证据**：`GPUCache.Instance` 全仓无引用（已确认）；`IImageLoadViewModelHandler` 无实现方（已确认空转）

## 五、最终方案（方案 C 完整设计）

### 新增文件

**① `FilePathToImageSourceConverter.cs`（~30 行）** — 替代全部解码器
```csharp
// src/UI/Converters/FilePathToImageSourceConverter.cs
public class FilePathToImageSourceConverter : IValueConverter
{
    public int DecodePixel { get; set; } = 100;
    public object? Convert(object value, Type targetType, object parameter, CultureInfo culture)
    {
        if (value is not string path || string.IsNullOrEmpty(path)) return null;
        if (!File.Exists(path)) return null;
        try
        {
            var bmp = new BitmapImage();
            bmp.BeginInit();
            bmp.UriSource = new Uri(path, UriKind.RelativeOrAbsolute);
            bmp.DecodePixelWidth = DecodePixel;
            bmp.CacheOption = BitmapCacheOption.OnLoad;
            bmp.EndInit();
            bmp.Freeze();
            return bmp;
        }
        catch { return null; }
    }
    public object ConvertBack(...) => throw new NotSupportedException();
}
```

**② `ThumbnailDiskCache.cs`（极简磁盘缓存，~60 行）** — 替代 ThumbnailCacheManager
```csharp
// src/UI/Services/Thumbnail/ThumbnailDiskCache.cs
public sealed class ThumbnailDiskCache
{
    private readonly string _dir;   // %LOCALAPPDATA%/SunEyeVision/ThumbnailCache
    public BitmapImage? GetOrCreate(string filePath, int size)
    {
        var key = $"{Path.GetFileName(filePath)}_{new FileInfo(filePath).LastWriteTime.Ticks}_{size}";
        var cacheFile = Path.Combine(_dir, $"{ComputeHash(key)}.jpg");
        if (File.Exists(cacheFile))
            return LoadFromDisk(cacheFile);
        var bmp = Decode(filePath, size);        // 同转换器逻辑
        if (bmp != null) SaveAsync(cacheFile, bmp);
        return bmp;
    }
}
```
（只留"读→命中返回 / 未命中解码+异步写盘"两个操作，无索引文件、无清理调度器）

**③ `Workflow/Models/ImageSourceConfig.cs`（可序列化模型，~20 行）**
```csharp
public class ImageSourceConfig
{
    public string NodeId { get; set; } = string.Empty;
    public List<string> FilePaths { get; set; } = new();
    public int CurrentIndex { get; set; } = -1;
    public bool AutoSwitchEnabled { get; set; } = true;
    public int RunMode { get; set; }   // 0=全部 1=选择
    public List<string> ForRunPaths { get; set; } = new();   // 运行选择模式勾选的路径（保留勾选路径）
}
```
