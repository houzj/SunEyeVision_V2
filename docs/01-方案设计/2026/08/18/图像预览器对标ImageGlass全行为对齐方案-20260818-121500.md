# 图像预览器对标 ImageGlass 全行为对齐优化方案

## 🔄 改前 → 改后 → 依据（写在最前面）

### 改前（用户视角，多轮反馈汇总）
1. 滚动到远端视口缩略图**不即时显示**（要等或永远不显示）
2. 部分缩略图**空白**——分不清是"加载中"还是"解码失败"
3. 加了缓存后**反而灾难**（串行解码）
4. 不同图片显示时机**不一致**
5. 从文件夹加载后**立刻拖动**，当前视口不优先

### 改后（用户视角）
1. 滚动到哪，视口缩略图**即时显示**（缓存命中秒出，未命中节流并行解码）
2. 空白项有**明确状态**：灰底=加载中、红叉=失败、图=成功
3. 快速拖动**流畅**，当前视口**永远优先**
4. 失败文件**可重试 + 日志定位**，WIC 解不了的**降级解码**

## 二、最终方案（对标 ImageGlass，4 阶段）

### Phase A：并发模型治本 —— SemaphoreSlim 节流并行（替代 lock 串行）

**对齐 ImageGlass `Photo.cs` 的核心设计**：

```csharp
// 全局并发节流：clamp(CPU-1, 4, 16)，避免线程池饱和也不串行
private static readonly int s_thumbnailConcurrency =
    Math.Clamp(Environment.ProcessorCount - 1, 4, 16);
private static readonly SemaphoreSlim s_thumbnailThrottle = new(s_thumbnailConcurrency, s_thumbnailConcurrency);

internal static async Task<BitmapImage?> LoadThumbnailAsync(string filePath, CancellationToken token)
{
    if (string.IsNullOrEmpty(filePath) || !File.Exists(filePath)) return null;

    // 快路径：缓存命中直接返回
    lock (s_thumbnailLock)
    {
        var cached = s_thumbnailCache.Get(filePath);
        if (cached != null) return cached as BitmapImage;
    }

    // 节流进入：最多 CPU-1 个并发解码
    await s_thumbnailThrottle.WaitAsync(token).ConfigureAwait(false);
    try
    {
        // 双检缓存（等待期间可能已被别人加载）
        lock (s_thumbnailLock)
        {
            var cached = s_thumbnailCache.Get(filePath);
            if (cached != null) return cached as BitmapImage;
        }

        BitmapImage? bitmap;
        try
        {
            bitmap = DecodeThumbnailCore(filePath);   // WIC 解码（锁外）
        }
        catch (Exception ex)
        {
            VisionLogger.Instance.Log(LogLevel.Warning, ...);   // rule-015
            return null;
        }

        lock (s_thumbnailLock) { s_thumbnailCache.Set(filePath, bitmap); }
        return bitmap;
    }
    finally
    {
        s_thumbnailThrottle.Release();
    }
}
```

**关键改动**：
- `lock` 只保护缓存字典（微秒级），解码在节流信号量内**并行**
- 并发上限 `clamp(CPU-1, 4, 16)`——快速滚动时不会线程池饱和

### Phase B：滚动取消 + 当前视口优先（对齐 `GalleryControl`）

**容器驱动的取消机制**：

```csharp
// ListBoxItem 的 Loaded/Unloaded 双事件
<EventSetter Event="Loaded" Handler="OnItemLoaded"/>
<EventSetter Event="Unloaded" Handler="OnItemUnloaded"/>
```

```csharp
// 每个 ImageInfo 持有自己的取消令牌
private CancellationTokenSource? _thumbnailCts;

public void EnsureThumbnail()
{
    if (Thumbnail != null) return;
    _thumbnailCts?.Cancel();        // 取消旧的（防重复）
    _thumbnailCts = new CancellationTokenSource();
    ThumbnailState = ThumbnailState.Loading;

    var path = FilePath;
    var token = _thumbnailCts.Token;
    var dispatcher = System.Windows.Application.Current?.Dispatcher;
    if (dispatcher == null) return;

    _ = LoadThumbnailAsync(path, token).ContinueWith(t =>
    {
        dispatcher.InvokeAsync(() =>
        {
            if (t.IsCanceled) return;              // 滚动离开已取消
            if (t.Result is { } thumb)
            {
                Thumbnail = thumb;
                ThumbnailState = ThumbnailState.Loaded;
            }
            else
            {
                _thumbnailCts = null;              // 失败重置，允许重试
                ThumbnailState = ThumbnailState.Failed;
            }
        });
    });
}

public void CancelThumbnail()   // Unloaded 时调用
{
    _thumbnailCts?.Cancel();
    _thumbnailCts = null;
}
```

**关键改动**：
- **滚动离开**（Unloaded）→ `CancelThumbnail()` 取消解码，后台不再空转
- **滚动进入**（Loaded）→ 新 CancellationToken，重新解码
- **当前视口优先**：节流信号量内，被取消的任务退出，新任务立即占位

### Phase C：失败可见 + 重试 + 降级解码

1. **失败日志**（已加）保留，但加**失败路径去重**（`HashSet<string> s_failedPaths`，同一文件只记一次 WARN）
2. **失败重试**：`_thumbnailCts = null` + `ThumbnailState.Failed`，滚动回来（Loaded 再触发）重新尝试
3. **解码器降级**（治本 WIC 局限）：对 WIC 解不了的（`NotSupportedException`）降级：
   - 优先：Halcon `HImage` 解码 → `ToBitmapSource()`（对齐主图路径）
   - 次选：`System.Drawing.Bitmap`（WPF 兼容）
   - 都不行才 Failed

### 实际实现与方案的差异（有意为之）
1. **降级顺序**：方案写"Halcon 优先 → System.Drawing 次选"，实际**只用 System.Drawing**——Halcon 解码到 `BitmapSource` 是重量级（走 HImage 对象生命周期），对本缩略图场景过度；System.Drawing 足以覆盖 BMP 变种（rule-008 YAGNI 裁剪）
2. **失败日志去重**（`HashSet<string>`）：未做——WIC 失败日志已带文件路径，能定位；去重属锦上添花，YAGNI 后置
3. **`_thumbnailRequested` 字段**：已删除（改由 `Thumbnail != null` + 取消令牌判断，消除死代码，rule-008）
