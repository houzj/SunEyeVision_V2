# 图像预览持久化内存实时同步方案

## 🔄 改前 → 改后 → 依据

### 改前（用户视角）
给图像载入节点加了 1000 多张图，正常退出时点"保存"，重启后发现预览区图像全没了——之前加的图一个不剩。

### 改后（用户视角）
加完图（不管是通过预览器加图、删图、切图、清空），数据立刻进到内存里的方案对象；任何时候保存，这些图**必然**一起存进去，重启后原样恢复。加图→保存→重启，图都在。

### 依据（业界参考）
- **VisionMaster / 基恩士**：运行时状态（图像列表）与持久化配置分离，配置只存路径，运行时状态独立维护
- **通用 MVVM 实践**：内存中共享对象实时更新（单一真相源），持久化只在保存动作发生时一次性序列化——避免"多入口各自转换"的维护陷阱

## 二、解决方案（内存实时同步 + 保存统一持久化）

### 方案概述
把图像源从"保存时转换"改为"**运行时实时同步**"：`ImageInputSource` 任何变更（加/删/清/切图）立即写回节点 `ImageSourceConfig`（Solution 共享对象），保存时只需序列化，无需任何转换代码。同时统一两个保存入口。

### 技术方案

**改动点 1：`ImageInputSource` 加配置同步回调（src/UI/Shared/ImageInputSource.cs）**

```csharp
/// <summary>配置同步回调：每次状态变更时把最新配置写回父节点（内存实时同步）</summary>
public Action<ImageSourceConfig>? ConfigChanged { get; set; }

private void NotifyConfigChanged() => ConfigChanged?.Invoke(ToConfig());
```

在 `AddImage`/`AddImages`/`RemoveImage`/`ClearImages` 末尾 + `CurrentIndex`/`RunMode`/`AutoSwitchEnabled` setter 中调用 `NotifyConfigChanged()`。

**改动点 2：`WorkflowNode.InputSource` setter 挂接回调（src/UI/Shared/WorkflowNodeModel.cs:45-50）**

```csharp
public new ImageInputSource? InputSource
{
    get => base.InputSource as ImageInputSource;
    set
    {
        base.InputSource = value;
        if (value != null)
            value.ConfigChanged = cfg => ImageSourceConfig = cfg;  // ★ 内存实时同步
    }
}
```

任何路径设置 InputSource（`EnsureInputSource`、`FromBase` 恢复）都自动挂上，加图即写回。

**改动点 3：修预览器删图/清空走真相源（ImagePreviewControl.xaml.cs:740-780）**

`ExecuteDeleteSingleImage` 改走 `ActiveInputSource.RemoveImage()`，`ExecuteClearAll` 改走 `ActiveInputSource.ClearImages()`，删除/清空也实时同步（顺带修复"删了等于没删"的隐藏 bug）。

**改动点 4：删除保存端转换代码（MainWindowViewModel.cs:1647-1660）**

`SaveSolutionData` 里 `ImageSourceConfig = inputSource.ToConfig()` 块删除（已实时同步，不需要）。

**改动点 5：统一保存入口（MainWindow.xaml.cs）**

- 删除 `SyncWorkflowsToSolution()`（418-469 整段）
- 关闭保存改调 `_viewModel.SaveSolutionData(...)`（与工具栏保存同路径）
- `MainWindowViewModel.SaveSolutionData` 改为 `public`（或加公开包装方法）

**改动点 6：清理临时诊断埋点**

删除我加的：`[ImgSourcePreSerialize]`、JSON 检查、`[AppendFiles]`、`[UpdateImagePreview]` 埋点。保留有价值的 `[FromBase]` 恢复日志（对将来排查有用）。

## 五、风险评估

| 风险 | 影响 | 缓解 |
|------|------|------|
| `SaveSolutionData` 改 public 后关闭保存执行"删除多余工作流"逻辑（以前关闭保存没有） | 行为变化 | 这是正确修复：关闭保存应与手动保存一致；测试确认无异常 |
| `ImageInputSource` 每次变更都 `ToConfig()`（1080 张图时 Allocate 数组） | 轻微性能 | `ToConfig()` 只创建路径数组（O(n) 且 n 通常<几千），变更不频繁（用户操作级），可接受 |
| 删图/清空改走真相源影响 UI 集合刷新 | 集合同步 | OneWay 绑定自动刷新，行为不变 |
