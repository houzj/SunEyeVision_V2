# 脚本编辑器语义着色与补全性能优化方案

> 创建：2026-08-20 10:15:07
> 模块：`tools/SunEyeVision.Tool.Script`（Script 脚本工具编辑器）
> 参考：RoslynPad-avalonedit（老版，Roslyn 2.x + AvalonEdit 语义着色/补全/签名帮助的唯一成熟参考）

## 一、问题全景

用户反馈脚本编辑器多项体验问题，且实测明显劣于 RoslynPad：

1. **语义着色失效**：`HOperatorSet` / `HalImage` / `UserScript` 没有显示类颜色（青色 `#267F99`）。
2. **流畅性差**：滚动、连续打字时补全弹窗与编辑明显卡顿，老版 RoslynPad 同样操作明显更流畅。
3. **诊断半成品**：错误只涂背景色块，无波浪线、无悬停详情、无分级、暗色主题写死。

经日志 + 源码交叉比对（日志 `logs/2026/08/20/SunEyeVision_093625.txt`），各项根因性质不同：着色失效是**行号基准 bug**；流畅性差异**滚动是设计差异、补全是实现差异**；诊断是**设计与交互缺失**。

## 二、语义着色失效根因（已确诊，可立即修复）

### 数据链路是正确的（日志证实）

- `[SemanticDiag] HOperatorSet: GetSymbolInfo.Symbol=NamedType` → 分析层把 HOperatorSet/HalImage 正确解析为类。
- `[Semantic] 已生成 88 个语义着色区间, 覆盖 32 行` → 着色区间确实生成，Type 青色 span 都在。
- 但日志中**一个 `[SemanticRender]` 都没有** → 渲染层根本没生效。

### 根因：行号基准错位 1（两套独立系统基准不同）

| | Roslyn（编译器后台） | AvalonEdit（编辑器控件） |
|---|---|---|
| 行号基准 | **0 开始** | **1 开始** |
| 文本模型 | `SourceText` / `TextLine` | `TextDocument` / `DocumentLine` |

两者内存中完全独立、互不知晓，文本内容经 `AvalonEditTextContainer` 增量同步，但行号语义各算各的。

桥接层用"按行号索引字典"中转，两端各做一次行号转换：

- **生成端**（`RunSemanticAsync`）：用 Roslyn 行号（0 起始）存 key
  ```csharp
  var lineGroups = spans.GroupBy(s => sourceText.Lines.GetLineFromPosition(s.Start).LineNumber);
  ```
- **消费端**（`SemanticColorizer.ColorizeLine`）：用 AvalonEdit 行号（1 起始）查 key
  ```csharp
  if (!byLine.TryGetValue(line.LineNumber, out var spans) ...) return;
  ```

同一文件里错误标记着色器（`ErrorMarkerColorizer`）已用 `+ 1` 对齐（`d.Location.GetLineSpan().StartLinePosition.Line + 1`），语义着色漏了这个 `+1` → 存的是"第 29 行"，渲染查的是"第 30 行" → 查不到 → 整行不上色。

### 参考做法：RoslynPad 全程用"偏移"做桥梁，不行号

`RoslynSemanticHighlighter`（`RoslynPad-avalonedit/src/RoslynPad.Editor.Shared/RoslynSemanticHighlighter.cs`）：
- 行号只在入口出现一次（`HighlightLine(int lineNumber)`），拿到行对象立刻转偏移。
- 请求/过滤/渲染全用 `documentLine.Offset` 与 `classifiedSpan.TextSpan`（偏移）——**偏移是两个系统都认的通用语言**，不存在 0/1 基准转换，天然避坑。

### 修复方案

- **方案 A（最小，立即）**：语义着色生成端补 `+ 1`，字段注释固化"key = AvalonEdit 1 起始行号"。
  ```csharp
  var lineGroups = spans.GroupBy(s => sourceText.Lines.GetLineFromPosition(s.Start).LineNumber + 1);
  ```
- **方案 B（治本，对齐 RoslynPad 偏移哲学）**：`SemanticSpan` 已有绝对偏移，把按行字典 `_semanticSpansByLine` 改为**按偏移排序的扁平数组 `_semanticSpans`**；`ColorizeLine` 拿到 `line.Offset` 后二分定位本行区间（O(log n + k)），彻底删除行号转换。
- **`UserScript` 声明不上色**（独立小问题）：类声明处是"声明"非"引用"，`GetSymbolInfo` 拿不到，需用 `GetDeclaredSymbol`：
  ```csharp
  if (node is BaseTypeDeclarationSyntax typeDecl)
  {
      var declared = model.GetDeclaredSymbol(typeDecl);
      return declared?.Kind == SymbolKind.NamedType ? SemanticBrushes.Type : null;
  }
  ```

## 三、滚动流畅性差异（设计差异）

### 参考（老版）：按需单行 + 行缓存

- `HighlightingColorizer` 插 `LineTransformers`，AvalonEdit 只对**可视行**调 `HighlightLine`。
- 每行单独 `Classifier.GetClassifiedSpansAsync(document, TextSpan(本行offset, 本行长度))`，**分析量永远与可见行数成正比**。
- 512 条 `CachedLine` 行缓存，滚过的行直接复用；编辑时用 `offsetShift` 平移区间（闪烁免疫）。

### 我们：全量一次算完 + 每次改动全量重算

- `RunSemanticAsync` 遍历**整棵语法树所有 token**，每个调 `GetSymbolInfo`。
- `OnCodeEditorTextChanged` → `ScheduleSemanticAsync`（100ms）+ `ScheduleDiagnosticAsync`（500ms），**每次打字都全量重算再全量重绘**。
- 文档越大成本越高，且按键即触发 → 滚动/打字卡顿根因。

### 借鉴方向（治本）

1. 语义分析**增量/按需化**：文档变化只重算变化行附近，或对齐 RoslynPad 可见行范围。
2. 至少先移除"每次打字全量重算"，改为基于文档版本判断是否真变了。

## 四、补全流畅性差异（实现差异）

### 设计已对齐的部分

窗口打开后继续输字母**不重查 Roslyn**，靠 AvalonEdit 内存过滤（两边一致，`OnTextEntering` 逻辑相同）。所以补全"设计"不是瓶颈。

### 差距在实现层面

| 差异点 | RoslynPad（老版） | 我们 |
|---|---|---|
| 节流延迟 | 无节流，后台查完立即回 UI 弹 | `ThrottledRefreshAndShow` 有节流，首帧有感知延迟 |
| 查询路径 | Roslyn 2.x 直接 `GetService<ISignatureHelpProvider>()` 一步到位 | Roslyn 4.12 签名帮助全 internal，靠 `IgnoresAccessChecksTo` + MEF 聚合，`GetSignatureHelpProviders()` 每次构建容器 |
| 后台竞争 | 语义逐行轻量任务，不抢 | 打字同时排队"补全 + 100ms 语义全量 + 500ms 诊断全量"，线程池被抢占 |
| 日志开销 | 几乎无（仅 `Debug.Assert`） | 补全一次查询打 6+ 条日志，语义每 `HOperatorSet` 打 3 条 `[SemanticDiag]`，同步写盘 + 刷 UI 日志面板 |

**当前诊断日志是性能放大的显著因素**（`[SemanticDiag]` 每 token 3 条，日志文件 200+ 行全是），修复后应降级/移除。

### 补全弹窗样式差异

- 老版 `CustomCompletionWindow` 提供 **`UseHardSelection`（软/硬选择）** 机制：suggestion mode 下不硬选中当前项，避免弹窗抢走用户自打的字。我们直接用 `new CompletionWindow(...)`，缺失该语义。
- 老版通过 `CompletionBackground` 依赖属性注入背景色（对齐我们已用 `ThemeResource.GetBrush` 的方式）。

### 借鉴方向

1. 补全查询从"节流"改"取消-立即查"（老版模式），减首帧延迟。
2. 弹窗对齐 `UseHardSelection` 软选择 + `CompletionBackground` 样式注入点。

## 五、诊断样式与设计改进（新确认，尚未实施）

### 现状（半成品：能报错，但"错在哪"界面上看不见）

- **生成**：500ms 节流后手动 `model.GetDiagnostics()`，只留 `Error` 严重级，构建行号字典 `_diagnosticsByLine`（`ScriptDebugControl.xaml.cs:1639-1647`）。
- **渲染**：`ErrorMarkerColorizer` 把错误 span 涂成**浅红背景色块**（`ScriptDebugControl.xaml.cs:2060-2067`）。
- **交互**：**无**——无 ToolTip、无波浪线、无滚动条标记。错误详情只能翻日志面板。

### 硬伤（对比 RoslynPad 的差距）

**硬伤 1：错误信息界面上完全不可见。**
写错代码只涂红文字，鼠标悬停无任何提示。RoslynPad 每个错误 marker 挂 `ToolTip = diagnosticData.Message`（`RoslynCodeEditor.cs:157`），配 `TextMarkerToolTipProvider` 悬停即见错误详情。这是编辑器基本体验，我们缺失。

**硬伤 2：背景色块是最差的错误呈现方式。**
`SetBackgroundBrush` 把错误文字整段涂红，**盖住语法着色**（关键字蓝/类型青全没），视觉污染严重。RoslynPad 用**波浪线**（`TextMarkerService.cs:229-252` 沿文字底部画折线），不挡字、精准定位，VS/VSCode/RoslynPad 全是波浪线。

**硬伤 3：暗色主题被写死失效。**
构造硬编码 `false`（`ScriptDebugControl.xaml.cs:209` `new ErrorMarkerColorizer(..., false)`），内部 `_isDark` 决定浅红/深红背景，暗色主题下永远用浅红 `#FFE0E0`，深色底上刺眼。

**硬伤 4：级联误报过滤是症状级补丁，不是治本。**
手动跳过 `CS0246/CS0234/CS0103`（`ScriptDebugControl.xaml.cs:2050`）——根因是"整段背景色块"导致缺引用错误污染整行看着像误报。RoslynPad 不需要这过滤，因为波浪线只画在真正出错的 span 上，`Foo` 只在 `Foo` 下画波浪，用户能看懂"是这个名字找不到"。

### 其他差距（非硬伤）

| 维度 | RoslynPad | 我们 |
|---|---|---|
| 更新机制 | Workspace 事件增量（`DiagnosticsUpdatedArgs`）删旧建新 | 手动全量 `GetDiagnostics` + 全量 `Redraw` |
| 错误分级 | Error 红 / Warning 蓝 / Info 绿 三色波浪 | 只有 Error，警告完全不可见 |
| 数据锚定 | `TextSegmentCollection` 偏移锚定，编辑自动跟踪 | 行号字典（同语义着色 `+1` 基准风险） |
| 数据模型 | `TextMarker : TextSegment`（色/字体/斜体/背景/Tag/ToolTip） | 裸 `Diagnostic` 列表 + 行号字典 |

### 借鉴方向（按优先级）

1. **波浪线替代背景色块**：精准 span 不污染整行 → 顺带删掉 CS0246 过滤补丁（治本）。
2. **ToolTip 悬停显示错误消息**（交互闭环，最重要）。
3. **Warning/Info 分级**（RoslynPad 三色，至少补 Warning）。
4. **暗色主题随主题色走**（修掉硬编码 `false`）。
5. **数据结构对齐 `TextSegmentCollection` 偏移锚定**：一劳永逸消除行号基准问题（与方案 B 同一哲学）。

## 六、验收标准

| # | 验收项 | 验收方法 |
|---|--------|---------|
| 1 | `HOperatorSet`/`HalImage` 所有出现处显示青色（Type） | 手动 + 日志出现 `[SemanticRender] line=... 应用了 N 个 Type 色 span` |
| 2 | `class UserScript` 声明处也显示青色 | 手动 |
| 3 | 连续打字/滚动无明显卡顿 | 手动对比 RoslynPad |
| 4 | 补全弹窗首帧延迟降低、滚动不抢占补全 | 手动 |
| 5 | 日志 `[SemanticDiag]`/`[SemanticRender]` 高频埋点已降级或移除 | 代码审查 |

## 七、实施顺序建议

1. **立即**：行号 `+1`（方案 A 或 B）+ `GetDeclaredSymbol` + 诊断日志清理 → 修好着色、消除性能放大。
2. **后续独立轮**：诊断改进——波浪线替代色块 + 悬停 ToolTip + Warning 分级 + 暗色主题修复 + 删 CS0246 补丁。
3. **后续独立轮**：语义分析增量/按需化（滚动治本）。
4. **后续独立轮**：补全节流改取消-立即查 + `UseHardSelection` 软选择。
