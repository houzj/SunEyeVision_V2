## 第一部分：语义着色设计迁移（✅ 已完成并构建验证）

### 根因（已实证）

- **日志证据**：首帧渲染（40.12s）早于 `RebuildWorkspace`（40.90s），worker 拿 `document==null` 丢弃全部可视行，行已缓存白色空行、`CompareAge==0` 永不重分类 → 直到用户编辑才变青
- **探针实证**：Roslyn 语法分类器对 `UserScript`（声明处）给 `class name`（青），对 `Script`/`HOperatorSet`（引用处）给 `identifier`（白）——**分类器没问题，是 workspace 时序问题**

### 核心结论（对话收敛）

| 问题 | 结论 |
|------|------|
| 分类器是否有问题？ | **没有**。语法分类器能力完备：声明处（`class UserScript`）给青，引用处（`Script`/`HOperatorSet`）只给白，必须语义模型 `GetSymbolInfo` 解析成功才补青 |
| 为什么"打开白、编辑才变青"？ | **workspace 时序问题**：首帧渲染早于 `RebuildWorkspace`，worker 拿 `document==null` 丢弃全部可视行 |
| 为什么"字段有的白有的金"？ | Roslyn 语法分类器对声明处直接给 `FieldName`（金），引用处依赖语义模型（白/金不定），两处行为不对称。已通过"字段统一基础色"根治 |
| 为什么"文档一变化就变青"？ | 编辑 → 版本变化 → 缓存失效 → 重新入队 → 此时 workspace 就绪 → 分类成功 |

### 技术原理：语法分类器 vs 语义分类器

| token 位置 | 语法分类器（不依赖语义模型） | 语义分类器（依赖语义模型） |
|-----------|--------------------------|--------------------------|
| **声明处** `class UserScript` 的 `UserScript` | ✅ 直接给 `ClassName`（青） | 不用调用 |
| **声明处** `void Init()` 的 `Init` | ✅ 直接给 `MethodName`（紫） | 不用调用 |
| **声明处** `int _invokeCount` 的 `_invokeCount` | ✅ 直接给 `FieldName` | 不用调用 |
| **引用处** `HOperatorSet.GetImageSize(...)` 的 `HOperatorSet` | ❌ 只给 `Identifier`（白） | ✅ 才给 `ClassName`（青） |
| **引用处** `.GetImageSize`、`input1.Channels`、`_invokeCount++` | ❌ 只给 `Identifier`（白） | ✅ 才给 `MethodName`/`PropertyName`/`FieldName` |

**语法分类器靠"声明表达式"（`class`/`void`/`int` 关键字前缀）识别 → 只能覆盖声明处；引用处必须语义模型。**

## 第二部分：全局脚本功能（📋 待实施）

### 需求（用户确认的形态）

- 主界面"工具"菜单 + 顶栏按钮 → 打开**全局脚本编辑器**
- 编辑器里维护一份 **`public partial class UserScript` 成员定义**（不需要全局静态类）
- 全局脚本挂在**解决方案级**（随 `Solution` 保存/加载，对齐全局变量的方案级现状）

### 全局脚本内容约定

```csharp
public partial class UserScript
{
    // 共享字段（每个脚本自动有）
    public int _globalCount;

    // 共享方法（每个脚本自动有，可访问脚本上下文）
    public void LogRect(int w, int h) => LogInfo($"尺寸 {w}x{h}");
}
```

> ⚠️ 必须是**非 static** partial（C# 规则：partial 各部分 static 声明必须一致；且实例方法才能调 `LogInfo`）

### 工具脚本里的使用（用户视角）

```csharp
public partial class UserScript : Script
{
    public override void Process()
    {
        _globalCount++;              // 直接用全局 partial 字段
        LogRect(100, 200);           // 直接用全局 partial 方法
    }
}
```

### 合并逻辑（现有机制，只是加一段）

```
GeneratedCode:  public partial class UserScript : Script { input1/output1 字段 }
全局脚本:       public partial class UserScript        { _globalCount/LogRect/... }   ← 新增
用户代码:       public partial class UserScript        { Init/Process }
        ↓ C# partial 合并
UserScript = { input1, output1, _globalCount, LogRect, Clamp01, Init, Process }
```

### 全局脚本编辑器 UI 设计

```
┌─────────────────────────────────────────────────────────────┐
│ 工具栏：[编译检查] [格式化] | 状态: 就绪/有错误                │
├─────────────────────────────────────────────────────────────┤
│  AvalonEdit 代码编辑器（全宽，无左侧变量面板）                │
│  public partial class UserScript                             │
│  {                                                           │
│      public int _globalCount;                                │
│      public void LogRect(int w, int h)                       │
│          => LogInfo($"尺寸 {w}x{h}");                        │
│  }                                                           │
│  - 语义着色（类型青/方法紫/字段基础色）——同一套高亮器           │
│  - 补全/诊断/错误波浪线——同一套分析管道                         │
├─────────────────────────────────────────────────────────────┤

```

### 编辑器内核抽离（关键：避免维护两套编辑器系统）

脚本工具编辑器与全局脚本编辑器**共享 90% 能力**，只有"变量面板"和"执行逻辑"是工具特有的。为不维护两套系统，把通用能力抽成一个共享的**脚本编辑器内核**：

```
                    ┌─────────────────────────────────────┐
                    │        共享编辑器内核 ScriptEditorCore│
                    │  AvalonEdit + xshd + 语义高亮         │
                    │  + 补全 + 诊断波浪线 + ToolTip        │
                    │  + AvalonEditTextContainer           │
                    │  + ScriptWorkspace + 引用管理         │
                    └────────────┬────────────────────────┘
                    ┌────────────┴───────────┐
                    ▼                        ▼
         ┌──────────────────┐    ┌──────────────────────┐
         │ 脚本工具编辑器     │    │ 全局脚本编辑器        │
         │ ScriptDebugControl│    │ GlobalScriptEditor  │
         │ + 变量面板         │    │ （无变量面板）        │
         │ + 运行/执行        │    │ + 编译检查            │
         └──────────────────┘    └──────────────────────┘
```

**可复用能力盘点**（当前内嵌在 `ScriptDebugControl.xaml.cs`，需一并搬进内核）：

| 能力 | 当前位置 | 是否工具特有 | 复用方式 |
|------|---------|:---:|---------|
| `AvalonEditTextContainer`（编辑器↔Roslyn 增量桥） | `Views/AvalonEditTextContainer.cs` | ❌ | 直接共用 |
| `RoslynSemanticHighlighter` + `RoslynHighlightingColorizer` + `ClassificationHighlightColors` | `Views/SemanticHighlighter.cs` | ❌ | 直接共用 |
| `ErrorMarkerColorizer`（诊断波浪线） | `ScriptDebugControl.xaml.cs` 内部类 | ❌ | **抽进内核** |
| 补全（`TextArea_TextEntered` → Roslyn 补全） | `ScriptDebugControl.xaml.cs` | ❌ | **抽进内核** |
| 诊断悬停 ToolTip（MouseMove 命中） | `ScriptDebugControl.xaml.cs` | ❌ | **抽进内核** |
| xshd 语法高亮加载（`LoadCustomHighlighting`） | `ScriptDebugControl.xaml.cs` | ❌ | **抽进内核** |
| `ScriptWorkspace` + `MetadataReferenceProvider` + `SharedMetadataReferenceProvider` | `ScriptEngine/` | ❌ | 直接共用 |
| **变量面板（输入/输出 Tab）** | `ScriptVariableTab.xaml` | ✅ 工具特有 | 留在脚本工具 |
| **执行/运行逻辑**（`Run`/`Process`） | `ScriptDebugControl.xaml.cs` | ✅ 工具特有 | 留在脚本工具 |

**内核设计**（`ScriptEditorCore : UserControl`）：

```csharp
public class ScriptEditorCore : UserControl
{
    // 已内置：xshd 加载、语义高亮、补全、诊断波浪线、ToolTip、
    //         AvalonEditTextContainer、ScriptWorkspace、引用管理
    public ScriptEditorCore(ScriptEditorCoreOptions options) { ... }

    public void LoadCode(string code);                     // 设置代码
    public void SetWorkspaceProvider(Func<Document?>);     // workspace 文档提供者
    public IReadOnlyList<Diagnostic> GetDiagnostics();     // 诊断
    public event Action<IReadOnlyList<Diagnostic>>? DiagnosticsUpdated;
}
```

- **`ScriptDebugControl`** = 组合 `ScriptEditorCore` + 变量面板 + 执行逻辑
- **`GlobalScriptEditor`** = 组合 `ScriptEditorCore` + 编译检查按钮（无变量面板）

**关键点**：
1. `ErrorMarkerColorizer`、补全、ToolTip、`LoadCustomHighlighting` 目前**内嵌在 `ScriptDebugControl.xaml.cs`**，抽离时一并搬进 `ScriptEditorCore`，否则全局脚本编辑器还得复制一遍（那就是两套）
2. workspace 差异：脚本工具有 `genDoc + userDoc` 双文档；全局脚本编辑器只有自己一个文档。`ScriptWorkspace` 本身通用（`SetCurrentSolution` 模式），内核需支持"注入文档列表"，两端都满足
3. 收益：两个编辑器**高亮/补全/诊断完全一致**（同代码天然同步）；以后改进编辑器改一处两处生效；不维护两套 xshd/高亮器/workspace

### 防御机制（≥2 项）

1. **编译缓存天然防陈旧**：`ScriptCompiler` 缓存键 = `codeHash|hostFingerprint`，全局脚本进 codeParts 改变 combinedCode → 自动重新编译（`ScriptCompiler.cs:94-95`）
2. **诊断可见性**：全局脚本编译错误在工具编辑器标 `[GlobalScript]` 来源，日志明确；全局脚本文件缺失直接报错（rule-015）
3. **契约测试**：新增测试断言"全局脚本加入后，工具脚本引用全局 partial 成员编译 0 错误"

## 实施建议

**第二部分分三步走**：
- **Step 0（内核抽离）**：先抽 `ScriptEditorCore`（把 `ErrorMarkerColorizer`/补全/ToolTip/`LoadCustomHighlighting` 从 `ScriptDebugControl` 搬进共享内核），`ScriptDebugControl` 改为组合内核——为复用打地基，避免两套系统
