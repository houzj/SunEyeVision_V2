# 脚本编辑器内核异步架构优化方案

> 方案日期：2026-08-21
> 范围：src/CommonControl/（脚本编辑器共享内核）
> 技术栈：WPF + AvalonEdit 6.3.1.120 + Roslyn 4.12.0（**不做 Avalonia 版本迁移**）
> 状态：已实施并验证通过（红波浪线恢复）

---

## 🔄 改前 → 改后 → 依据（写在最前面）

### 改前（用户视角）

你在脚本编辑器里写代码时，会遇到两个烦人的问题：

1. **编译报错不画红波浪线了。** 你删掉一个分号、把代码写错，编辑器应该在被删的地方画一条红波浪线提醒你，但现在它不画了——你完全不知道代码错在哪，只能点"运行"等编译报错。
2. **代码颜色会"跳变"。** 打开调试窗口、滚动代码、或者打着字的时候，同一行代码的颜色会在"白/默认色"和"正确的语义色（类型青色、方法黄色、字符串橙色等）"之间闪一下。滚动越快、代码越长，跳变越明显，看着很晃眼。

### 改后（用户视角）

1. **红波浪线正常出现。** 你删掉分号，约 0.5 秒内错误位置就画上红波浪线，鼠标移上去还能看到报错内容。编译错误立刻可见。（已实现并验证）
2. **颜色稳定不跳变。** 打开窗口、滚动、打字时，已经算过的行颜色保持不变；没算过的行先显示上一个位置的颜色（或默认色），语义颜色"安静地"到位，不闪白、不闪默认色。（用户实测：打字/滚动不闪，打开窗口先白后着色为正常异步行为）

### 依据（业界参考）

| 参考对象 | 做法 | 借鉴点 |
|---------|------|-------|
| 旧版 RoslynPad（`RoslynPad-avalonedit`，与 SunEyeVision 同源的 WPF 版） | `RoslynSemanticHighlighter` 用**纯异步 worker**：UI 线程只做"旧色平移 + 入队"，后台线程 `GetClassifiedSpansAsync` 计算，`SynchronizationContext.Post` 切回 UI 更新 | 零同步阻塞 + 缓存平移防跳变 |
| 新版 RoslynPad（`Morgania`，Avalonia + 重编译 Roslyn EditorFeatures） | 语义分类/诊断全走**后台 tagger**，UI 线程只通过 `Dispatcher.UIThread.Post` 接收结果重绘（`SquiggleAdornmentManager.cs:60-62`） | 印证"后台算 + UI 重绘"是唯一不卡 UI 的路径 |
| Visual Studio 编辑器 | 语义着色先显示语法色，语义分析后台完成后平滑更新，不闪白 | 接受"先可用色、后正确色"的异步延迟，追求平滑而非同步零跳变 |

## 问题分析

### 需求拆解

- **表面需求**：① 诊断红波浪线失效；② 语义/语法配色跳变。
- **根本问题**：诊断代码在**后台线程**读取了 WPF 界面对象 `CodeEditor.Text`，触发跨线程 `InvalidOperationException`，异常被静默吞掉 → 诊断结果丢失，波浪线永远画不出来。
- **问题分类**：实现方式有误（后台线程访问 UI 对象，WPF 跨线程访问约束的典型违规）。

### 架构分配检查

- 语义高亮属于 CommonControl 内核（`RoslynSemanticHighlighter`），已是异步 worker 骨架（`SemaphoreSlim` + `ConcurrentQueue`）。
- 诊断链路属于 `ScriptEditorCore`（`ScheduleDiagnosticAsync` → `RunDiagnosticAsync`），已用 `Task.Run` 后台计算 + `Dispatcher.InvokeAsync` 重绘。
- **不改是否可覆盖**：否。后台线程读 UI 对象不修复，诊断必然抛异常，波浪线必然失效。
- **是否改变分层边界**：否。都在内核层内修复，不动 UI 层（`ScriptDebugControl`）和 workspace 逻辑。

### 方法对比（≥3 候选）

| 维度 | 方案 A（推荐） | 方案 B（备选） | 方案 C（备选） |
|------|--------------|--------------|--------------|
| 实现方式 | 诊断代码不在后台线程读 UI 对象，改为 UI 线程捕获快照传给后台 | 换新版 Avalonia 技术栈，重编译 Roslyn EditorFeatures | 保留后台读 UI 对象，仅加大诊断优先级 |
| 架构一致性 | 符合现有 WPF+AvalonEdit 分层 | 与现有 WPF 软件冲突，需整体迁移框架 | 在现有架构上打补丁 |
| 复杂度 | 低：`ScheduleDiagnosticAsync` 捕获快照 + `RunDiagnosticAsync` 改用快照 | 极高：换 UI 框架 + 重编译 Roslyn | 低但治标 |
| 维护成本 | 低，符合 WPF 线程模型 | 高，维护两套 UI 体系 | 中，跨线程异常风险仍在 |
| 长期 ROI | 高：根治波浪线失效 | 极高成本，长期收益不确定 | 低：跨线程异常迟早再出现 |

**推荐方案 A**：不迁移框架，在 UI 线程捕获用户代码快照，后台任务只消费快照。理由：符合 WPF 跨线程访问约束（UI 对象只能在 UI 线程访问），是治本；新版（Avalonia）与现有 WPF 软件体系互斥（`WpfTextView : Avalonia.Panel`，`src/Morgania.Editor/Editor/WpfTextView.cs:28`），迁移风险远超收益。

## Bug 模式分析

**当前 bug**：诊断红波浪线失效。

**真因分类**：实现偏差（诊断代码在后台线程访问 WPF UI 对象，违反 WPF 跨线程访问约束，异常被静默吞掉）。

**同类潜伏点**：
- [来源] `src/CommonControl/ScriptEditorCore.xaml.cs:423`（已修）— `var userCode = _getUserCode?.Invoke() ?? CodeEditor.Text;` 在后台 `Task.Run` 里读 `CodeEditor.Text`（WPF UI 对象）→ 跨线程异常。这是波浪线失效的**直接根因**。
- [来源] `src/CommonControl/ScriptEditorCore.xaml.cs:84` — `GetCode() => CodeEditor.Text`，被 `_getUserCode` 委托引用，后台线程经此访问 UI 对象。

**治本点**：修复"后台线程读 UI 对象"（治本），而非仅删同步阻塞（治标——删同步块对本次问题无实际作用）。

> 补充说明：方案初期曾推测"语义高亮同步阻塞卡 UI"是根因并删除了同步块，但经日志定位，真正根因是后台线程读 `CodeEditor.Text` 的跨线程异常。同步块删除方向无害（防未来卡顿），保留。

## 解决方案

### 方案概述

在现有 WPF + AvalonEdit 内核内，修复诊断代码后台线程读 UI 对象的跨线程异常：在 UI 线程调度诊断时捕获用户代码快照，后台任务只消费快照。不迁移框架。

### 技术方案

1. **`ScheduleDiagnosticAsync` 在 UI 线程捕获用户代码快照**（已实施）：
   - [来源] `src/CommonControl/ScriptEditorCore.xaml.cs:387` — `var userCodeSnapshot = _getUserCode?.Invoke() ?? CodeEditor.Text;`
   - 效果：`ScheduleDiagnosticAsync` 总在 UI 线程被调用（`OnCodeEditorTextChanged` / `InitializeWorkspace`），此时读 `CodeEditor.Text` 安全，快照传给后台任务。

2. **`RunDiagnosticAsync` 改用快照，不再读 UI 对象**（已实施）：
   - [来源] `src/CommonControl/ScriptEditorCore.xaml.cs:405` — 签名改为 `RunDiagnosticAsync(string userCodeSnapshot, CancellationToken token)`。
   - [来源] `src/CommonControl/ScriptEditorCore.xaml.cs:413-421` — 用 `userCodeSnapshot` 替代原 `CodeEditor.Text`，`_lastDiagnosedCode` 比较逻辑不变。
   - 效果：后台线程不再访问 `CodeEditor.Text`，跨线程异常消除。

3. **删除 `DoHighlightLine` 里的 UI 线程同步分类块**（已实施，防未来卡顿）：
   - [来源] `src/CommonControl/SemanticHighlighter.cs:159-186` → 改为仅"旧 sections 平移 + `EnqueueLine` + `CacheLine`"。
   - 效果：`HighlightLine`（AvalonEdit 渲染管线强制的同步调用）不再阻塞，UI 线程立即返回。

4. **保留缓存命中 + 平移兜底**（已有，确认保持）：
   - [来源] `src/CommonControl/SemanticHighlighter.cs:107-112` — `CompareAge==0 且长度相同` 直接复用旧色（不闪白）。
   - [来源] `src/CommonControl/SemanticHighlighter.cs:135-157` — 未命中时旧色平移对准。
   - 效果：编辑/滚动时旧色保留，语义色异步到位，无"白→色"空档。

### 实施步骤

1. 修改 `ScheduleDiagnosticAsync`：在 UI 线程捕获 `userCodeSnapshot`，传给后台任务。
2. 修改 `RunDiagnosticAsync(string userCodeSnapshot, ...)`：用快照替代 `CodeEditor.Text`。
3. 删除 `SemanticHighlighter.cs` 的同步分类块，恢复纯异步 worker。
4. 构建 CommonControl + 工具项目 + 主程序 UI，确认 0 错误。
5. 手动验证：删分号画红波浪线。

## 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 用户代码快照与编辑器实际文本有极短时间差（500ms 节流窗口内） | 诊断基于快照，但真正诊断用 workspace 增量通道的最新文本，影响可忽略 | workspace 增量通道实时同步，快照仅用于"代码是否变化"判断 |
| 语义色异步延迟（用户可能觉得色到位慢） | 已算行有旧色/缓存，几乎不可感知 | 预热 + 缓存平移保证平滑 |
| 其它后台线程访问 UI 对象点未覆盖 | 偶发跨线程异常 | 方案聚焦核心，后续按"后台线程访问 UI 对象"pattern 扫描 |
