# 脚本编辑器语义高亮重构方案（对齐 RoslynPad 新版单一分类系统）

> 创建日期：2026-08-21 09:50:48
> 所属模块：T-SCRIPT（脚本工具）
> 涉及项目：SunEyeVision_V2-script / CommonControl / SunEyeVision.Tool.Script

## 背景与痛点

脚本编辑器当前存在**语义高亮跳变**问题：滚动、文本变化、初始打开调试窗口时，同一标识符会在"语法配色"和"语义配色"之间切换，产生可见跳变。

### 根因：两套高亮 + 两套色板

编辑器同时挂载两层高亮，色值不统一：

| 图层 | 机制 | 能识别的 token | 色板 |
|------|------|---------------|------|
| Layer 1 xshd 语法高亮 | 正则词法规则 | 关键字/注释/字符串/数字/类型名 | `CSharpLight.xshd`（旧配色，如 Method `#6F42C1` 紫） |
| Layer 2b 语义高亮 | Roslyn `Classifier` 分类 | 字段/局部变量/参数/属性/类型引用/方法等 | `ClassificationHighlightColors`（VS Dark/Light 语义色） |

同一 token（如方法名、数字）在 **xshd 层显示**和**语义层显示**之间切换时，色值不同 → 跳变。三个触发场景：

- **初始打开**：workspace 未就绪，行只有 xshd 色；就绪后语义色覆盖 → 跳变
- **滚动**：新行语义未缓存，先 xshd 色；异步 worker 算好后语义色 → 跳变
- **文本变化**：行失效重算，旧色平移 → 新语义色 → 跳变

### 关键盲区（用户指出）

xshd 是**词法**高亮，**认不出字段、局部变量、参数**（在它眼里只是普通标识符，落默认色）。这些"语法不可达"的 token 只能靠语义分类器识别。无论 xshd 怎么改色，只要行先经过语法层显示（落默认色）、再被语义层覆盖（浅蓝/深蓝），就会跳变——**统一 xshd 色板治不了这部分**。

## 参考方案：新版 RoslynPad（Morgania.Editor）

新版 RoslynPad 的编辑器重构为单一分类系统，从根上消除跳变。三个核心机制：

### 1. 无 xshd，单一分类器

RoslynPad 新版**完全没有 xshd**。语义高亮用 Roslyn 的 `Classifier`（`GetClassifiedSpansAsync`），它产出统一的**分类类型**（`ClassName`/`MethodName`/`FieldName`/`LocalName`/`ParameterName`/`Keyword`/`StringLiteral`/`Comment`/`NumericLiteral`）。语法分类与语义分类**合并进同一个分类器**，输出同一套分类类型。

### 2. 单一色板 + 分类继承链

颜色由单一 `ClassificationFormatMap` 统一管理（`src/Morgania.Editor/Classification/ClassificationFormatMap.cs`）：

```csharp
public TextFormattingRunProperties GetTextProperties(IClassificationType classificationType)
{
    if (_cache.TryGetValue(classificationType, out var cached)) return cached;  // 缓存
    var properties = MergeLineage(classificationType, []);   // 沿继承链合并祖先颜色
    properties = Merge(properties, _defaultTextProperties);  // 与默认文本属性合并
    _cache[classificationType] = properties;                 // 缓存
    return properties;
}
```

- **分类继承链（MergeLineage）**：`"record class name"` 继承 `"class name"` 色；`"parameter name"` → `"identifier"` → 默认文本色。**未在主题里着色的分类类型沿继承链 fallback 到祖先分类或默认前景**，而不是落到"另一套 xshd"。
- 同一个分类类型**永远一个色**，无论哪层产出。
- 色值由 **VS Code 主题**驱动（`ThemeClassificationFormats.cs` 读 `scopes-roslyn.json` + VS Code 主题 JSON）。

### 3. 语义分类器异步，xshd 不参与渲染

语义分类器基于 workspace 异步分类，但**编辑器不依赖 xshd 兜底**，未就绪时靠分类继承链 fallback 到默认前景，保证始终可读。

## 落地方案（对齐 RoslynPad）

我们的架构（AvalonEdit + `RoslynHighlightingColorizer`）不直接搬 RoslynPad 的 VS 分类系统，但核心思想对齐：

| RoslynPad 新版 | 我们落地 |
|---|---|
| 无 xshd，单一分类器 | **移除 xshd**，只用 `RoslynSemanticHighlighter`（Roslyn `Classifier`，内含语法+语义分类） |
| 分类继承 fallback | `ClassificationHighlightColors.GetBrush` 补全 `Identifier`（→ 基础色）等映射，未匹配分类 fallback 到主题默认前景 |
| 单一色板 | 色板就一套（VS Dark/Light 语义色），由 `IsDarkTheme` 切换 |
| 语义分类器 + 同步渲染可视行 | `DoHighlightLine` 语义模型就绪时**同步分类**（已实施），未就绪时 fallback 语法分类 |

### 改动清单

**1. 移除 xshd（语法高亮完全退出）**
- 删除工具层 `LoadCustomHighlighting`，`SetSyntaxHighlightingProvider` 不再调用
- `ScriptEditorCore.InitializeEditor` 不再加载 xshd，`CodeEditor.SyntaxHighlighting` 保持 null
- 删除 `CSharpLight.xshd` 加载逻辑 + csproj 复制配置
- 未就绪兜底不靠 xshd，靠语义分类器内部 fallback

**2. 语义分类器接管一切（`SemanticHighlighter.cs`）**
- `DoHighlightLine` 语义模型就绪 → 同步 `Classifier.GetClassifiedSpansAsync`（已实施）
- 语义模型未就绪（初始打开）→ **语法分类 fallback**：用 `CSharpSyntaxTree.ParseText` 解析代码 + C# 分类器（纯语法，不需要 workspace），**同一色板**着色 → 打开第一帧就有色，workspace 就绪后同色覆盖无跳变

**3. 色板补全（`ClassificationHighlightColors`）**
- 补 `Identifier` → 基础色（主题默认，暗 `#D4D4D4`/浅 `#000000`）
- 补 `PreprocessorKeyword` → 预处理色
- 已有 7 类（Keyword/Type/Method/Field/Local/Param/Constant/String/Comment/Number）不变

**4. 构建 + 验证**
- 构建 CommonControl + 工具 csproj + slnx 0 错误
- 启动主程序，暗色/浅色主题分别验证：滚动、输入文字、打开工具时不再有颜色跳变

## 关键收益

- 单一分类器 + 单一色板，从第一帧到滚动/打字/打开**都是同一套颜色**，跳变根除
- 不再有"xshd 认不出字段/局部变量"的盲区（语义分类器全认得）
- 对齐 RoslynPad 新版的成熟架构，后续全局脚本编辑器复用同一内核
