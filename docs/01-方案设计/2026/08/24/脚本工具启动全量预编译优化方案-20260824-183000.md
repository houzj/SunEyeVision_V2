# 脚本工具启动全量预编译优化方案

- 日期：2026-08-24
- 类型：方案设计（脚本工具性能优化）
- 状态：已确认，待实施

## 一、问题定义

**现象**：脚本工具首次执行 `Compile: 142ms`，后续执行 `Compile: 0-6ms`。

**目标**：任何节点（含从未编辑过）首次执行也命中缓存，首次与后续执行时间一致（`Compile: 0ms` 级）。

**根因（已确认）**：
- 编译发生在执行路径上：`ScriptLifecycleManager.Execute` → `ScriptCompiler.Compile`（ScriptLifecycleManager.cs:91-96）
- 142ms 构成：Emit 113ms（Roslyn 对真实代码的 IL 生成）+ 引用 27ms（33 个固定引用）+ 语法树/创建 ≈ 0ms
- 与 halcondotnetxl 等 SDK DLL **无关**（日志确认：未勾选 halcondotnetxl 时仍 142ms）
- C# 无主流解释器（编译型语言），编译成本不可消除，只能**提前编译 + 复用**

## 二、核心设计：编译与执行解耦

```
┌─────────────────────────────────────────────┐
│ 启动/方案加载 ──► 并行预编译所有脚本节点       │  ← 编译提前到启动，一次性
│   （Parallel.ForEach，半核，SplashScreen）     │
└───────────────────┬─────────────────────────┘
                    ▼
┌─────────────────────────────────────────────┐
│ ScriptCompiler._compileCache（static SSOT）   │  ← 进程级共享，工具/工作流共用
│   缓存键 = SHA256(generatedCode+userCode)     │
│           | 宿主指纹 | 引用指纹               │
└───────────────────┬─────────────────────────┘
                    ▼
┌─────────────────────────────────────────────┐
│ 执行路径（工具调试 / 工作流）                 │
│   Execute ──► Compile()：命中→0ms；未命中→兜底 │  ← 时间一致
└─────────────────────────────────────────────┘
```

### 缓存键分析（已确认）

- 缓存键 = `SHA256(combinedCode) | 宿主指纹 | 引用指纹`（ScriptCompiler.cs:152-159）
- `combinedCode = generatedCode + "\n" + userCode`
- `generatedCode` = Inputs/Outputs 字段声明（`public IVisionImage input1;` 等，ScriptParameters.cs:211-219）
- `GenerateFieldCode()` 只含 Name + 类型，不含 GUID/绑定源（ScriptInputConfig.cs:79）

**两个什么都不动的新建节点 → 缓存键相同 → 第二个命中缓存**。契约不同 → 程序集不同 → 缓存键必须不同（否则错误命中），这是正确性要求。

## 三、预编译入口（工具层新增）

### 1. `ScriptLifecycleManager.CompileOnly()`（ScriptLifecycleManager.cs:230 后）

```csharp
public List<string> CompileOnly(
    string generatedCode, string userCode, string? assemblyRefDir,
    IReadOnlyList<string>? assemblyNames = null)
{
    if (string.IsNullOrWhiteSpace(generatedCode) && string.IsNullOrWhiteSpace(userCode))
        return ["脚本代码为空"];
    var assemblyName = $"ScriptPreCompile_{Guid.NewGuid():N}";
    var result = _compiler.Compile(
        [generatedCode, userCode], assemblyName, assemblyRefDir, assemblyNames);
    return result.Success ? [] : result.Diagnostics;
}
```

只调 `Compile`（命中缓存跳过，未命中编译入缓存），**不建沙箱/实例**。

### 2. `ScriptTool.PreCompile(ScriptParameters)`（ScriptTool.cs）

```csharp
public static void PreCompile(ScriptParameters parameters)
{
    if (parameters == null || string.IsNullOrWhiteSpace(parameters.ScriptCode)) return;
    try
    {
        using var lm = new ScriptLifecycleManager();
        var errors = lm.CompileOnly(parameters.GeneratedCode, parameters.ScriptCode,
            parameters.AssemblyReferenceFullPath, parameters.AssemblyReferences);
        if (errors.Count > 0)
            PluginLogger.Warning($"[ScriptTool] 预编译发现错误: {string.Join("; ", errors)}", nameof(ScriptTool));
    }
    catch (Exception ex)
    {
        PluginLogger.Warning($"[ScriptTool] 预编译异常: {ex.Message}", nameof(ScriptTool));
    }
}
```

## 四、挂载点：方案加载后全量并行预编译

**`LoadSolutionToWorkflowTabs`（MainWindowViewModel.cs:1813）末尾**，Tab 创建后、主窗口 Show 前。方案已反序列化完成，所有 `ScriptParameters` 完整，覆盖主工作流 + 子程序工作流。

```csharp
var scriptNodes = solution.Workflows
    .SelectMany(w => w.Nodes)
    .Where(n => n.Parameters is ScriptParameters)
    .ToList();

if (scriptNodes.Count > 0)
{
    LogInfo($"开始并行预编译 {scriptNodes.Count} 个脚本节点...");
    var sw = Stopwatch.StartNew();

    var options = new ParallelOptions
    {
        MaxDegreeOfParallelism = Math.Max(1, Environment.ProcessorCount / 2)  // 半核，不抢启动其他任务
    };

    Parallel.ForEach(scriptNodes, options, node =>
    {
        try
        {
            ScriptTool.PreCompile((ScriptParameters)node.Parameters);
        }
        catch (Exception ex)
        {
            LogWarning($"脚本预编译失败: {node.Name}, {ex.Message}");
        }
    });

    sw.Stop();
    LogSuccess($"脚本预编译完成: {scriptNodes.Count} 个节点, 耗时 {sw.ElapsedMilliseconds}ms");
}
```

**线程安全（已确认）**：
- `_compileCache` ConcurrentDictionary（ScriptCompiler.cs:105）
- `ComputeHostFingerprint`/`ComputeRefListFingerprint` 纯函数（ScriptCompiler.cs:347-383）
- `ResolveAssemblyPath` 纯函数 + `EnsureLoaded` 有锁（MetadataReferenceProvider.cs:105,252）
- Roslyn `CSharpCompilation` 独立实例（ScriptCompiler.cs:225）

→ **并行安全**。

## 八、防御机制

1. **编译失败不阻塞**：`PreCompile` 内部 try-catch + `CompileOnly` 返回诊断，仅日志告警
2. **空代码跳过**：`PreCompile` 对空 ScriptCode 直接返回
3. **并行安全**：已验证全部共享状态线程安全
4. **执行兜底**：`Execute` 内缓存未命中时用最新代码编译，保证正确性
5. **同契约节点并行重复编译一次**：无害（缓存键相同，后者覆盖，无正确性问题）

## 九、风险评估

- **风险 1**：`LoadSolutionToWorkflowTabs` 是同步方法，预编译同步阻塞加载链路。缓解：有启动页（SplashScreen 显示"预编译中"），N 节点并行（半核）耗时 ≈ 单次编译 ≈ 150ms 级。
- **风险 2**：代码变化节流频繁触发预编译。缓解：复用现有诊断节流机制。
- **回退**：改动集中在新方法 + 加载末尾追加，git 单提交回退。
