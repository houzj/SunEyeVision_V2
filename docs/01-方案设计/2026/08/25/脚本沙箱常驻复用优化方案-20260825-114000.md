# 脚本沙箱常驻复用优化方案（每次执行时间一致）

- 日期：2026-08-25
- 类型：方案设计（脚本工具性能优化）
- 状态：已确认，待实施

## 一、问题定义

**现象**（日志 `SunEyeVision_113703.txt` 确认）：
- 脚本预编译已解决编译问题（两次执行都 `Compile: 0ms` 命中缓存）
- **但首次执行 74ms vs 后续 2ms，差 72ms**——脚本工具执行时间不一致

**根因拆解**：
| 层 | 首次 | 后续 | 可否消除 |
|----|:----:|:----:|:-------:|
| 框架路径 JIT（ToolExecutor/沙箱/反射） | 冷启动 | 热 | ✅ 预热一次 |
| 沙箱 ALC 创建 + 程序集加载 | 首次 | **每次重建** | ✅ 常驻复用 |
| 脚本用户代码 JIT | 首次 | **每次重新**（新 ALC 不共享 JIT） | ✅ 常驻复用 |
| 反射设输入/读输出 | 每次 | 每次 | ⚠️ 不可避免（本身 ~1ms） |

**目标**：脚本工具**每次执行时间一致**（差异从 72ms → ~2ms）。

## 二、核心架构：沙箱常驻复用

### 设计原则

- **沙箱（ALC）= 运行时隔离单元**，按"编译缓存键"分组（缓存键 = `codeHash|宿主指纹|引用指纹`，唯一标识程序集+引用）
- **程序集常驻**（不每次卸载），**实例每次新建**（状态干净，同现状）
- **代码变化**：缓存键变化 → 新沙箱（旧 ALC 卸载）
- **宿主 DLL** 仍走默认 ALC fallback（类型一致，不变）

### 架构图

```
┌──────────────────────────────────────────────────────────┐
│ ScriptSandboxPool（新增，静态 ConcurrentDictionary）       │
│   key = 编译缓存键（codeHash|宿主|引用）                   │
│   value = 常驻 ScriptSandbox（不 Dispose）                │
│                                                            │
│   GetOrAdd(key, () => new ScriptSandbox(key, refDir))      │
│   LRU 治理：上限 N（如 16），超限淘汰最久未用（旧 ALC 卸载） │
└───────────────────────┬──────────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────────┐
│ ScriptLifecycleManager.Execute（改造）                     │
│  1. 编译（命中缓存）→ AssemblyBytes + EntryClassName       │
│  2. sandbox = Pool.GetOrAdd(cacheKey)   ← 复用常驻沙箱     │
│  3. sandbox.LoadAssembly(bytes)         ← 幂等（同程序集）  │
│  4. 每次执行：CreateScriptInstance()    ← 新实例，状态干净  │
│  5. 注入 Context + 反射设输入                              │
│  6. Init/Process/Release                                  │
│  7. 反射读输出                                            │
│  （不 Dispose 沙箱，返回池继续复用）                        │
└──────────────────────────────────────────────────────────┘
```

## 四、关键实现细节

### 4.1 沙箱池（ScriptSandboxPool）

```csharp
internal static class ScriptSandboxPool
{
    private const int MaxResident = 16;   // 常驻上限（LRU 淘汰）
    private static readonly ConcurrentDictionary<string, SandboxSlot> _pool = new();

    public static ScriptSandbox GetOrCreate(string cacheKey, string? refDir)
    {
        var slot = _pool.GetOrAdd(cacheKey, k => new SandboxSlot(new ScriptSandbox(k, refDir)));
        slot.LastUsed = DateTime.UtcNow;
        EvictIfNeeded();
        return slot.Sandbox;
    }

    public static void Invalidate(string cacheKey)   // 代码变化时调用
    {
        if (_pool.TryRemove(cacheKey, out var slot))
            slot.Sandbox.Dispose();   // 卸载旧 ALC
    }

    private static void EvictIfNeeded()
    {
        if (_pool.Count <= MaxResident) return;
        var victim = _pool.OrderBy(kv => kv.Value.LastUsed).First();
        if (_pool.TryRemove(victim.Key, out var slot)) slot.Sandbox.Dispose();
    }
}
```

### 4.2 ScriptLifecycleManager.Execute 改造

```csharp
// 改造（常驻复用）：
var cacheKey = ScriptCompiler.ComputeCacheKey(generatedCode, userCode, assemblyNames);  // 新增
var sandbox = ScriptSandboxPool.GetOrCreate(cacheKey, assemblyRefDir);
sandbox.LoadAssembly(compileResult.AssemblyBytes!, compileResult.SymbolBytes);  // 幂等
var instance = sandbox.CreateScriptInstance(compileResult.EntryClassName);      // 每次新实例
// ... 注入 Context + 反射设输入 + Init/Process/Release + 反射读输出 ...
// 不 Dispose，归还池（GetOrCreate 已更新 LastUsed）
```

### 4.3 代码热更新

代码变化 → 缓存键变化 → `GetOrCreate(新key)` 建新沙箱；旧沙箱留池等 LRU 淘汰。**无需显式 Invalidate**。

### 4.4 并发安全

- 池：`ConcurrentDictionary.GetOrAdd` 线程安全
- 沙箱 LoadAssembly：同 key = 同程序集，幂等无害；不同 key = 不同沙箱，无冲突
- 实例：每次 `CreateScriptInstance` 新建，实例隔离 → **并发执行安全**

## 五、验收标准

| # | 验收项 | 方法 |
|---|--------|------|
| 1 | 首次执行脚本 ≈ 后续执行（差异 ≤ 5ms） | 执行工作流两次对比 |
| 2 | 脚本用户代码 JIT 只发生一次 | 日志/性能 |
| 3 | 代码变化后执行正确（新代码生效） | 改代码执行 |
| 4 | 多节点（不同引用/代码）各自独立沙箱 | 多脚本节点 |
| 5 | 连续执行不泄漏内存（沙箱上限 16） | 长时间运行观察 |
| 6 | 并发执行同一节点正确 | 并行执行 |
| 7 | 构建零错误 | 构建 |

## 六、防御机制

1. **LRU 淘汰防泄漏**：沙箱池上限 16，超限卸载最久未用 ALC
2. **实例每次新建**：无状态残留（同现状语义）
3. **代码变化隔离**：缓存键区分新旧程序集，不混用
4. **宿主 DLL fallback 不变**：类型一致（Script 基类校验不受影响）
5. **失败不阻塞**：沙箱获取/加载异常时回退临时沙箱

## 七、风险评估

- **风险 1**：常驻 ALC 内存占用（16 沙箱 × 程序集）。缓解：LRU 上限 + 宿主共享默认 ALC
- **风险 2**：代码频繁变化沙箱频繁重建（编译+加载慢）。缓解：缓存键隔离 + LRU 淘汰
- **风险 3**：改造 `ScriptLifecycleManager` 影响面（工具调试/工作流/连续执行共用）。缓解：封装在 Execute 内，对外行为不变
- **回退**：改动集中工具层（4 文件），git 单提交回退
