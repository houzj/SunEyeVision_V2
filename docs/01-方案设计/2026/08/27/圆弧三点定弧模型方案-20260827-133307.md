# 圆弧三点定弧模型方案

> 整合完整对话上下文：两点+半径模型多轮反馈（端点带动圆心、P3 不同步、半径交互反着）→ 三点定弧收敛
> 日期: 2026-08-27

---

## 一、改前 / 改后 / 依据（用户视角）

### 核心问题：当前"两点+半径"模型的 P3 不同步

| | 当前（两点+半径）| 改后（三点定弧）|
|---|-------------------|---------------------|
| **参数** | P1 + P2 + 半径（P3 是派生的弧中点）| **P1 + P2 + P3**（三个独立弧上点）|
| **拖 P1** | P1 被**投影到当前圆**（圆心/半径不变，沿圆滑）❌ | P1=鼠标，P2/P3 不动，**圆心/弧长派生变** ✅ |
| **拖 P2** | 同 P1 问题 ❌ | P2=鼠标，P1/P3 不动，圆心/弧长变 ✅ |
| **拖 P3** | P3 是派生点，圆心一变就乱跳，**不同步** ❌ | P3=鼠标，P1/P2 不动，**半径变**，圆心/弧长变 ✅ |
| **手柄跟随** | P3 是派生点，圆心变导致不同步 | 手柄=弧上的参数点，**天然跟随鼠标** ✅ |

**依据**：用户多轮反馈的核心矛盾——当前实现把 P3 当作"派生的弧中点"，导致拖 P3 时圆心一变它就不跟随鼠标。三点定弧模型让 P1/P2/P3 都是**独立参数点**，天然同步。

---

## 二、问题分析（含来源标注）

**当前实现缺陷**：

1. **P3 不同步** [来源] `MeasureEditorControl.CreateArcHandles` — 半径手柄 = 派生的弧中点，圆心随半径滑动 → 手柄不跟随鼠标
2. **端点带动圆心/弧长** [来源] `MeasureInteractionModel.UpdateArcEndpoint` — 端点被投影到当前圆（圆心/半径不变），但用户期望端点移动时圆心/弧长派生变
3. **半径交互反着** [来源] `MeasureEditorControl.HandleShapeEdit` — 用"到圆心距离/投影"算半径，与手柄位置脱节

**三点定弧模型**：`Arc2d.FromThreePoints(p1,p2,p3)` 由三个独立点确定外接圆，圆心/半径/起止角全部派生。该方法曾在代码中存在但被两点模型改造时删除（当前 [来源] `Arc2d.cs` 仅有 `FromEndpointsAndRadius`/`FromTwoPointsDefault`）。

---

## 三、Bug 模式分析

**当前 bug**：P3 不同步、端点不带动圆心、半径交互错乱。

**真因分类**：**设计缺陷**——"两点+半径"模型把中间点(P3)做成派生的弧中点，而非独立参数点。

**同类潜伏点**：
- [来源] `MeasureEditorControl.CreateArcHandles` — 半径手柄位置 = 派生弧中点
- [来源] `MeasureInteractionModel.UpdateArcEndpoint` — 端点投影到圆（不带动圆心）

**治本点**：改为**三点定弧**——P1/P2/P3 都是独立参数点，`FromThreePoints` 派生圆心/半径/起止角。

## 五、方案对比

| 维度 | **A（推荐）** 三点定弧 | B：保留两点+半径 | C：中心+半径+角度 |
|------|------|------|------|
| 手柄跟随鼠标 | ✅ P1/P2/P3 都是点 | ❌ P3 派生不同步 | ❌ |
| 端点带动圆心/弧长 | ✅ 派生变 | ❌ 投影固定 | ❌ |
| 绘制流程 | ✅ P1/P2 与现状一致 + P3 默认 | ✅ | ⚠️ 三步 |
| 复杂度 | 中 | 低（但 bug 多）| 低 |
| 长期 ROI | **高**（治本）| 低 | 低 |

**推荐 A**：三点定弧，一次解决所有交互问题。
