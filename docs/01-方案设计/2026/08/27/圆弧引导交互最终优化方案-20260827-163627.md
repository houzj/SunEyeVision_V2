# 圆弧引导交互最终优化方案（三点定弧 + P3 弧中点手柄）

> 整合完整对话上下文：三点定弧方向翻转问题 → 两端点+半径+方向模型讨论 → VM 行为确认 → P3 弧中点手柄收敛
> 日期: 2026-08-27

---

## 一、改前 / 改后 / 依据（用户视角）

| | 改前 | 改后 |
|---|------|------|
| **拖 P1/P2** | 三点定圆，P3 独立点不动，半径会变 | **半径/方向不变**，弧重算，P3 手柄在弧中点跟随 |
| **拖 P3** | P3 独立参数点，拖到任意位置，可能不在弧上 | **P3 手柄始终在弧中点**；拖 P3 时用三点定圆保证**弧过鼠标**，提取新半径/方向 |
| **P3 过弦** | 方向判断有 bug（`FromThreePoints` line 151-160），弧可能不经过 P3 | **方向自动翻转**（三点定圆自然行为），弧总经过 P3（VM 行为）|
| **拖 P1 到 P3 右边** | 可能方向翻转错误 | 拖 P1/P2 用两端点+半径法，方向锁定，永不翻转 |

**依据**：VM 实测（用户提供截图：P3 过弦弧翻转到另一侧）；用户明确确认"P3 参与方向判定，P3 过弦方向自动翻转"、"P3 手柄始终在弧中点，拖 P3 保证弧过鼠标"。

---

## 二、问题分析（含来源标注）

**当前实现缺陷**：

| 缺陷 | 证据 |
|------|------|
| `FromThreePoints` 方向判断 bug：`pos <= span` 分支直接用 `a2m`（原始 atan2 角度），未处理弧跨越 0° 边界 → 弧可能不经过 P3 | [来源] `Arc2d.cs:145-160` |
| P3 是独立参数点（`ArcPoint3`），拖 P1/P2 时 P3 不动 | [来源] `MeasureInteractionModel.cs:51-58` |
| `CreateArcHandles` P3 手柄 = `_model.ArcPoint3`（独立参数点），不保证在弧中点 | [来源] `MeasureEditorControl.xaml.cs:760-780` |

**正确模型**（用户确认）：
- **存储**：`ArcPoint1`(P1) + `ArcPoint2`(P2) + `ArcRadius`(R) + `ArcClockwise`(方向)
- **P3 手柄** = 派生弧中点（`arc.GetPointOnArc(StartAngle + AngularSpan/2)`），不独立存储
- **拖 P1/P2**：`FromEndpointsAndRadius`（R/方向不变）
- **拖 P3**：`FromThreePoints(P1, P2, 鼠标)` 提取新 R + 方向 → 弧过鼠标

---

## 三、Bug 模式分析

**当前 bug**：P3 过弦时弧方向翻转错误（弧不经过 P3）。

**真因分类**：**实现偏差**——`FromThreePoints` 方向判断未处理角度跨越边界，且 P3 作为独立参数点导致"弧中点"语义丢失。

**同类潜伏点**：
- [来源] `Arc2d.cs:151-160` — `FromThreePoints` 方向判断
- [来源] `MeasureInteractionModel.cs:215-220` — `UpdateArcPoint3` 三点定圆（依赖 FromThreePoints）
- [来源] `MeasureEditorControl.xaml.cs:760-780` — P3 手柄位置

**治本点**：修复 `FromThreePoints` 方向判断（保证弧经过 P3 + 过弦自动翻转）；P3 改为派生弧中点手柄；拖 P1/P2 用两端点+半径法。

## 五、方案对比（≥3 候选）

| 维度 | **A（推荐）** 两端点+半径+方向，P3 弧中点 | B：纯三点法（当前）| C：纯两端点+半径 |
|------|------|------|------|
| 拖 P1/P2 方向稳定 | ✅ 永不翻转 | ❌ 可能翻转 | ✅ |
| 拖 P3 弧过鼠标 | ✅ 三点定圆 | ✅ | ❌ P3 只能沿径向 |
| P3 过弦自动翻转 | ✅ | ✅（但 bug）| ❌ 方向锁定 |
| P3 手柄在弧中点 | ✅ | ❌ 独立点 | ✅ |
| 复杂度 | 中 | 低 | 低 |
| 长期 ROI | **高**（交互正确）| 低（bug）| 中 |

**推荐 A**：两端点+半径+方向模型，P3 弧中点手柄，拖 P3 三点定圆提取半径。
