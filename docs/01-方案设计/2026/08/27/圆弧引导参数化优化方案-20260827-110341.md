# 圆弧引导参数化优化方案

> 基于完整对话上下文：区域编辑器交互分析 + VM 参数面板实测推算 + 多轮交互设计讨论
> 日期: 2026-08-27
> 决策: 参数模型直接替换（A 方案，零兼容，旧流程反序列化报错）

---

## 一、改前 / 改后 / 依据（用户视角）

| | 改前 | 改后 |
|---|------|------|
| **画圆弧** | 按下点当圆心，弧总从 0° 开始，拖不出来"任意角度"的弧 | **按下=起点，拖动=终点**，自动生成 60° 弧（半径=弦长）|
| **圆弧参数** | 圆心+半径+起止角（`GuideCircle+StartAngle+EndAngle`），不直观 | **起点+终点+半径+方向**，与 VisionMaster 一致，参数面板所见即所得 |
| **圆心** | 绘制时用户指定 | **计算得出**（起点+终点+半径+方向唯一确定）|
| **编辑手柄** | 起止角+半径手柄（圆心固定）| **起点手柄+终点手柄+半径手柄**，拖任意一个，圆心/半径实时重算 |
| **绘制过程** | 卡尺跟随鼠标乱动 | 只显示引导几何，松开后显示测量带 |

**依据**：VM 实测两次独立数据（弦长 510.50 / 57.31）均验证 **默认半径 = 弦长，默认张角 60°**；`Arc2d` 当前是 (Center,Radius,StartAngle,EndAngle) 模型 [来源] `Arc2d.cs:11-35`。

---

## 二、问题分析（含来源标注）

**当前圆弧参数化缺陷**：

| 问题 | 证据 |
|------|------|
| Arc 用 `GuideCircle + StartAngle + EndAngle`（圆心/半径/角度）| [来源] `EdgeDetectParameters.cs:69-92,110-111,190-201` |
| 绘制交互：按下=圆心，起始角固定 0° | [来源] `MeasureEditorControl.xaml.cs`（重写前 `UpdateDrawPreview` Arc 分支）|
| 编辑：圆心固定，只改角度/半径 | [来源] `MeasureInteractionModel.UpdateArcAngle/UpdateCircleRadius` |
| 手柄语义：起止角+半径（非三点/两点）| [来源] `MeasureEditorControl.CreateArcHandles` |

**根本问题**：圆弧的**参数化模型**（圆心+角度）与工业标准（VM 的起点+终点+半径）不一致。

---

## 三、Bug 模式分析

**当前 bug 模式**：圆弧交互不自然（圆心难定位、弧总从 0° 起）。

**真因分类**：**设计缺陷**——参数化模型选错（圆心+角度 vs 起点+终点+半径）。

**同类潜伏点**：
- [来源] `Arc2d.cs` — 结构固定为 (Center, Radius, StartAngle, EndAngle)，无"端点+半径"构造
- [来源] `EdgeDetectParameters.cs` — Arc 用 Circle+角度，模型混乱

**治本点**：`Arc2d` 新增 `FromEndpointsAndRadius` 工厂方法；`MeasureInteractionModel` 的 Arc 改用 (StartPoint, EndPoint, Radius, Direction) 存储；绘制/编辑/参数面板全链路对齐"两点+半径"模型。

## 五、方案对比（≥3 候选）

| 维度 | **方案 A（推荐）** 全链路改"两点+半径" | 方案 B：仅改交互层 | 方案 C：改参数模型不动 UI |
|------|------|------|------|
| 参数化 | Arc 用 (起点,终点,半径,方向)，圆心计算 | 交互改两点，参数仍存圆心角度 | 参数改两点，交互保持 |
| 架构一致性 | ✅ 对齐 VM 工业标准 | ⚠️ 交互与参数脱节 | ⚠️ UI 与参数脱节 |
| 复杂度 | 中（5 文件）| 低（2 文件）| 中（2 文件）|
| 维护成本 | 低（模型唯一）| 中（两套语义）| 中 |
| 长期 ROI | **高**（几何测量工具链全受益）| 低 | 中 |

**推荐 A**：参数模型 + 交互 + UI 全链路统一为"起点+终点+半径+方向"，一次治本。
