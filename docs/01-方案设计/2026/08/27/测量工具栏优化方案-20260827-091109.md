## 一、改前 / 改后 / 依据（用户视角）

| | 现在 | 改后 |
|---|------|------|
| **工具栏** | 只有 3 个几何类型按钮（直线/圆/圆弧），点了 Arc 显示"待完善" | 保持 3 个选择按钮（已验证的薄选择器模式），Arc 可绘制 |
| **卡尺可视化** | 画完引导线只能看到一条线 + 一排无差别的蓝色小方块 | **主卡尺高亮**（其余半透明）+ **方向箭头**，一眼看清卡尺在哪、多宽、朝哪测 |
| **调参数** | 只能去 Tab2 手输数字，改完图像不变 | 在图像上**拖手柄**直接改宽度/长度，图像实时刷新 |
| **引导几何编辑** | 画错只能重画 | 可**移动/旋转/缩放**（复用 RoI 手柄系统） |
| **架构** | 边缘检测工具自己手写鼠标交互（每个工具抄一遍） | 交互抽象到 **SDK 通用控件**，未来几何测量工具一行 XAML 复用 |

**依据**：`ShapeToolBar` 薄选择器 + `RoiEditorControl` 承载状态机、被 6 个工具复用的模式已被验证 [来源] `tools/SunEyeVision.Tool.Threshold/Views/ThresholdToolDebugControl.xaml:48`；Halcon 卡尺参数语义（MeasureLength1/2、NumMeasures）业界标准。

## 二、问题分析（含来源标注）

### 1. 工具栏功能单一
`MeasureToolBar` 是 `ShapeToolBar` 的复制品 [来源] `src/Plugin.SDK/UI/Controls/Measure/Views/MeasureToolBar.xaml.cs:16`，只做几何类型选择，不承载任何测量操作。

### 2. 卡尺参数交互脱节
- 宽度/长度/间距是 Tab2 裸 TextBox [来源] `tools/SunEyeVision.Tool.EdgeDetect/Views/EdgeDetectToolDebugControl.xaml:51-67`
- 改参数**不实时刷新**渲染：`RenderGuideOverlay` 只在绘制完成/切换类型时调用 [来源] `EdgeDetectToolDebugControl.xaml.cs:319-335`
- 数量写死 `10` [来源] `EdgeDetectToolDebugControl.xaml.cs:220`；`MeasureDistance` 注释"与数量互斥"但 `NumMeasures` 参数根本不存在 [来源] `tools/SunEyeVision.Tool.EdgeDetect/EdgeDetectParameters.cs:133-139`

### 3. 引导几何零编辑能力
绘制完成后仅存参数 + 渲染，无移动/旋转/缩放手柄 [来源] `EdgeDetectToolDebugControl.xaml.cs:233-262`

### 4. 无检测方向可视化
`MeasureBandOverlay` 只画矩形带，无方向箭头 [来源] `src/Plugin.SDK/UI/Controls/Measure/Rendering/MeasureBandOverlay.cs:37-71`

### 5. Arc 纯占位
`OnGuideMouseDown` 只处理 Line/Circle [来源] `EdgeDetectToolDebugControl.xaml.cs:188-206`；`UpdateGuidePanel` 对 Arc 显示"待完善" [来源] `EdgeDetectToolDebugControl.xaml.cs:310`

### 6. 渲染层是"孤岛"
`MeasureBandOverlay` 自绘 Polygon [来源] `MeasureBandOverlay.cs:159-170`，**绕过了** RoI 的手柄系统（`RoiHitTester`）、命中测试，卡尺无法承载交互。

## 三、Bug 模式分析

**当前 bug（症状）**：卡尺交互缺失、参数与渲染脱节。

**真因分类**：**设计缺陷**——交互逻辑错放在工具层（`EdgeDetectToolDebugControl` 手写鼠标事件），而项目已有一套成熟的 SDK 通用交互控件模式（`RoiEditorManagerControl`）。

**同类潜伏点**：
- [来源] `tools/SunEyeVision.Tool.EdgeDetect/Views/EdgeDetectToolDebugControl.xaml.cs:151-179` — `SetMainImageControl` 手写订阅/退订鼠标事件
- [来源] `src/Plugin.SDK/UI/Controls/Measure/Rendering/MeasureBandOverlay.cs:22-32` — 直接操作 Canvas.Children，无命中测试

**治本点**：把引导几何 + 卡尺的完整交互**抽象为 SDK 层通用控件**（对齐 `RoiEditorManagerControl`），工具只做组装。消灭"每个工具抄一份交互"的重复模式。

## 五、方案对比（3 候选）

| 维度 | **方案 A（推荐）** SDK 通用交互控件 | 方案 B：工具栏扩展操作台 | 方案 C：最小改动 |
|------|------|------|------|
| 实现方式 | 新增 `MeasureEditorControl`（对齐 `RoiEditorControl`），承载绘制/编辑/方向 + 卡尺手柄；`MeasureToolBar` 保持薄选择器；`MeasureBandOverlay` 升级主卡尺渲染 | `MeasureToolBar` 加分区（几何/操作/参数），宿主仍手写交互 | 只给 `MeasureBandOverlay` 加主卡尺高亮 + `NumMeasures` |
| 架构一致性 | ✅ 完全对齐现有 `RoiEditorManagerControl` 模式 | ⚠️ 工具栏职责膨胀，与 ShapeToolBar 模式背离 | ✅ 无架构破坏 |
| 复杂度 | 中（新增 1 控件 + 升级渲染器） | 高（工具栏分组 + 两组选中态） | 低 |
| 维护成本 | **低**——交互只写一次，多工具复用 | 中——工具栏与宿主交互逻辑分离 | 低但不解决交互缺失 |
| 扩展性 | ✅ 几何测量工具直接复用 | 中 | ❌ 卡尺仍不可交互 |
| 长期 ROI | **高**（1 年：边缘/位置/几何测量全受益） | 中 | 低 |
| 问题覆盖 | ✅ 解决痛点 1-6 全部 | ✅ 解决 1、4，部分 2 | ❌ 只解决 2 |

**推荐理由**：方案 A 一次性根治"交互下沉到工具"的坏味道，把卡尺交互沉淀为 SDK 资产（对齐 rule-004 复用优先）；方案 C 只是"打补丁"（违反 rule-008 治本原则）；方案 B 破坏已验证的薄选择器模式。
