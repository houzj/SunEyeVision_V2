# 测量引导直线参数化与交互完善优化方案

> 整合完整对话上下文：VM 直线卡尺实测（起点+终点）+ 直线点向式长度丢失 bug + 之前定位的交互问题
> 日期: 2026-08-27
> 决策: 直线参数模型直接替换（A 方案，零兼容，rule-015 报错优先）

---

## 一、改前 / 改后 / 依据（用户视角）

### 核心问题：直线引导只有 1 像素长（最严重）

| | 改前 | 改后 |
|---|------|------|
| 绘制直线卡尺后执行 | Halcon 测量带从起点到"起点+1像素"——**引导线实际只有 1 像素长**，测量结果错误 | 用**真实两端点**，测量带覆盖整条引导线 |

**根因** [来源] `EdgeDetectTool.cs:89`：`GetPointAt(1.0)` = `Point + Direction*1.0`（Direction 是单位向量），所以终点=起点+1像素。

### 问题 2：直线参数模型（对齐 VM）

| | 改前 | 改后 |
|---|------|------|
| 直线参数 | `GuideLine`（点向式：点+方向，**丢长度**）| `LineStartPoint` + `LineEndPoint`（两端点，对齐 VM 起点/终点）|
| 参数面板 | 显示圆心/方向（隐晦）| 显示起点 X/Y、终点 X/Y（对齐 VM 截图）|
| 参数回填 | 用固定 200px 近似长度 | 用真实两端点回填 |

### 问题 3：拖端点影响半径（圆弧）

| | 改前 | 改后 |
|---|------|------|
| 拖圆弧起点/终点手柄 | 半径和圆心被带动 | 半径/圆心不变，端点沿圆滑动 |

### 问题 4：光标悬停无反馈

| | 改前 | 改后 |
|---|------|------|
| 鼠标移到手柄/引导线/卡尺 | 始终箭头 | 手柄=手（编辑）、引导线=十字（移动）、卡尺=十字（移动）|

## 二、问题分析（含来源标注）

### 问题 1（最严重）：`GetPointAt(1.0)` 导致直线 1 像素
[来源] `EdgeDetectTool.cs:88-89`：
```csharp
var startP = parameters.GuideLine!.Value.Point;
var endP = parameters.GuideLine.Value.GetPointAt(1.0);  // = Point + Direction*1（单位向量）
```
`Line2d.Direction` 是单位向量 [来源] `Line2d.cs:33`（`direction.Normalize()`），`GetPointAt(1.0)` = 起点 + 1 像素。测量带从起点到起点+1px。

### 问题 2：`GuideLine` 点向式丢长度
[来源] `Line2d.cs:30-35` 构造归一化方向，不存长度；`EdgeDetectParameters.GuideLine` 是 `Line2d` [来源] `EdgeDetectParameters.cs:83-87`。

### 问题 3：`UpdateArcEndpoint` 影响半径
[来源] `MeasureInteractionModel.cs:184-192` 用鼠标位置当端点 + `FromEndpointsAndRadius` 重算 → 圆心滑动。

### 问题 4：无光标悬停反馈
[来源] `MeasureEditorControl.xaml.cs:273` `OnGuideMouseMove` 无悬停光标切换。

---

## 三、Bug 模式分析

**当前 bug**：直线引导 1 像素 + 直线长度丢失 + 圆弧端点编辑影响半径 + 无光标反馈。

**真因分类**：
- 问题 1/2：**设计缺陷**——`Line2d` 点向式（点+单位方向）不携带线段长度，渲染/执行都用 `GetPointAt(1.0)` 误当终点。
- 问题 3：**实现偏差**——`UpdateArcEndpoint` 用"重算整条弧"而非"端点沿圆滑动"。
- 问题 4：**功能缺失**——无悬停命中 → 光标切换。

**同类潜伏点**：
- [来源] `EdgeDetectTool.cs:89` — `GetPointAt(1.0)` 误用（直线执行）
- [来源] `MeasureEditorControl.cs` 旧代码 `_lineEnd = line.Point + line.Direction * 200.0`（回填固定长度近似）
- [来源] `Arc2d.GetSamplePoints` 之前不包含终点（已修）

**治本点**：统一"点参数化"——直线用两端点、圆弧用两点+半径，`Line2d`/`Arc2d` 执行层用真实几何而非 `GetPointAt(1.0)`。

## 五、方案对比（≥3 候选）

### 直线参数化
| 维度 | **A（推荐）** 参数层改两端点 | B：仅修执行层 GetPointAt | C：仅改交互层 |
|------|------|------|------|
| 参数存储 | `LineStartPoint`+`LineEndPoint` | 保持 GuideLine | 保持 |
| 执行正确性 | ✅ 真终点 | ✅ 修 GetPointAt | ❌ 执行仍错 |
| 长度持久化 | ✅ 序列化保留 | ❌ 丢 | ❌ 丢 |
| 面板对齐 VM | ✅ 起点/终点 | ❌ 点向式 | ❌ |
| 复杂度 | 中（3 文件）| 低（1 文件）| 低 |
| 长期 ROI | **高**（治本）| 低（打补丁）| 低 |

**推荐 A**：参数层+执行层+面板全链路"两点参数化"（与圆弧改造范式统一）。
