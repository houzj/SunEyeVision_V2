# 方案报告：几何交互策略化解耦

> 本方案遵循 rule-004（全局视角/复用优先）与 rule-008（YAGNI/KISS/零兼容/报错优先）。
> 历史代码已全部提交 git，可放手重构（用户确认）。

---

## 0. 用户功能性视角（必读）

### 改前：你看到的问题
- 每个几何（矩形/圆/多边形/直线/圆/圆弧）的绘制、编辑、命中、渲染逻辑**散落在两个巨型编辑器文件里**：
  - `RoiEditorControl.xaml.cs`（**3000 行**，23+ 个几何相关方法）
  - `MeasureEditorControl.xaml.cs`（**860 行**，3 个几何用 switch 分发）
- 想给"边缘检测"加一种新几何（如椭圆、圆环）：要改 `switch` 的 **4 个方法**（绘制 + 编辑 + 命中 + 渲染）
- 改圆的手柄逻辑可能碰坏弧的 → 几何之间通过 `switch` 耦合
- 加新几何类型 = 编辑巨型文件 + 改多个 switch

### 改后：你将看到什么
- 每种几何的完整行为（绘制/编辑/命中/手柄/渲染）封装在**一个策略对象**里
- 编辑器只做"状态机编排 + 策略分发"（几十行），不再 contain 几何算法
- 加新几何 = 新增一个策略类 + 注册，**不再碰编辑器核心**
- 改圆的手柄逻辑 = 只改圆的策略文件，**不影响弧**

## 2. Bug 模式分析

**当前问题**：加新几何需改多个 switch；几何之间通过巨型文件耦合；编辑冲突风险随几何数量增长。

**真因分类**：设计缺陷（架构层面注定——switch 分发 + 巨型类违反单一职责）。

**同类潜伏点**：
- `RoiEditorControl` 23+ 几何方法集中在单类 `[来源] Roi:1229-2257`
- `MeasureEditorControl` 4 处 switch 分发 `[来源] Measure:567-757`
- 未来任何新几何都会重复此模式

**治本点**：用**策略模式**把"几何行为"从"交互编排"中剥离——编辑器保持状态机，几何行为下沉到策略对象。

## 4. 方案对比（3 候选）

| 维度 | 方案 A：策略接口+各自策略化（推荐） | 方案 B：统一几何基类 | 方案 C：仅提取工具类 |
|------|---------------------------------|--------------------|--------------------|
| 实现方式 | Roi/Measure 各定义 `IGeometryInteraction` 策略接口，每几何一个策略类，编辑器改为策略路由 | 抽象 `GeometryBase`，所有几何继承 | 继续把算法抽静态工具类（GeometryToolkit 扩展） |
| 与架构一致性 | ✅ 对齐 Halcon IDrawingStrategy | ⚠️ 强行统一差异大的几何 | ⚠️ 治标，行为仍在编辑器 |
| 解耦程度 | ✅ 几何行为完全脱离编辑器 | ⚠️ 部分（基类仍耦合） | ❌ 行为仍在巨型文件 |
| 加新几何成本 | 低（新增策略类+注册） | 中 | 高（仍改编辑器） |
| 改动量 | 中（Roi 大，Measure 小） | 大 | 小 |
| 风险 | 中（Roi 3000 行改造） | 高 | 低 |
| 6个月/1年/3年 ROI | 高/高/高 | 中/中/中 | 低/低/低 |

### 推荐：方案 A（策略接口 + 各自策略化）
- **理由**：
  1. 治本：几何行为从编辑器剥离，switch 分发消失
  2. 对齐 Halcon 已验证的 IDrawingStrategy 模式
  3. 与项目已有 `IRoiRenderer`/`GeometryToolkit` 风格一致
  4. **不强行统一 Roi/Measure**（几何差异大，统一基类=过度设计）→ 各自定义策略接口
  5. 分阶段：先 Measure（小，验证模式），再 Roi（大）

## 6. 防御机制

### 防御机制 #1：策略契约测试
- `GuideInteractionContractTests`：每种引导策略的 `UpdatePreview`/`Complete`/`HitTest`/`EditHandle` 正确性（防退化、命中容差、大小弧）
- `ShapeInteractionContractTests`：每种形状策略的绘制/编辑/命中正确性
- **验收**：unit test 全绿

### 防御机制 #2：端到端冒烟（手动）
- 区域编辑器：7 种形状绘制/编辑/旋转/多边形流式
- 边缘检测：3 种卡尺引导 + P1/P2/P3 手柄 + 大小弧
- **验收**：行为与重构前一致

### 防御机制 #3：Fail-Forward
- 策略工厂遇到未注册类型 → 直接 throw（rule-015 报错优先），不静默回退
- 编辑器策略路由时策略为 null → 抛 InvalidOperationException（明确可见）

## 10. 风险评估

- **影响范围**：`MeasureEditorControl`（860 行）+ `RoiEditorControl`（3000 行）——后者是核心交互控件
- **回退策略**：历史已提交 git，每阶段独立提交
- **兼容性**：编辑器公开 API（StartDraw/SetGuide/SetCaliberParams 等）不变，宿主零改动
- **范围收敛**：不强行统一 Roi/Measure 策略接口（各自几何差异大）；策略化只解耦"行为"，不改变交互状态机
