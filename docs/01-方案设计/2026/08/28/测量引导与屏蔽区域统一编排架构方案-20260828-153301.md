# 方案报告：测量引导与屏蔽区域统一编排架构（MeasurementEditorManagerControl）

> 本方案遵循 rule-004（全局视角/复用优先）与 rule-008（YAGNI/KISS/零兼容/报错优先）。
> 历史代码已全部提交 git；当前工具宿主仅为验证空壳，可放手重构。

---

## 0. 用户功能性视角（必读）

### 改前：你面对的问题
- 测量工具（如边缘检测）需要**两类交互几何**：测量卡尺引导（`MeasureEditorControl`）+ 屏蔽区域（`RoiEditorControl`），但**没有编排它们的管理器**。
- 两者共用同一图像控件，却各自订阅鼠标事件 → **事件冲突**（都响应鼠标）。
- `MeasureEditorControl`（单对象）与 `RoiEditorControl`（多对象）生命周期管理**两套**（你质疑的"设计灾难"）。
- 测量渲染生命周期缺陷：手柄残留、解绑不清理、销毁无清理。

### 改后：你将看到什么
- 新增 **`MeasurementEditorManagerControl`**（SDK 层），统一编排"测量卡尺 + 屏蔽区域"。
- 抽 **`EditorInteractionManagerBase`**（生命周期骨架），Roi/Measure 两个 Manager **共用一套**生命周期管理。
- `MeasureEditorControl` 改造为"无头模式"（对齐 `RoiEditorControl`），由 Manager 统一路由鼠标 → **事件冲突根治**。
- 屏蔽区域直接复用 `RoiEditorControl`（多 ROI 能力）→ **零重复**。
- 生命周期缺陷一并修复（统一清理入口）。

## 1. 问题分析（来源标注）

### 1.1 现有架构证据
- `RoiEditorControl` **已是"无头编辑器"**：`SetMainImageControl`/`ClearMainOverlay` 已 `[Obsolete]` 空实现 `[来源] RoiEditorControl.xaml.cs:424-437`；由 Manager 路由 `ProcessMouseDown/Move` `[来源] :804,872`；`OverlayCanvas` 由 Manager 设置 `[来源] :96`
- `RoiEditorManagerControl` 已有成熟生命周期：`SetMainImageControl`/`ClearMainOverlay`/`OnViewTransformed`/`OnEditorRenderRequested`（节流）/工具互斥 `[来源] RoiEditorManagerControl.xaml.cs:130-228,458-505`
- `MeasureEditorControl` **仍自订阅事件**：`SubscribeEvents` 订阅 `CanvasMouseLeftButtonDown`/`ImageMouseMove`/`ViewTransformed` `[来源] MeasureEditorControl.xaml.cs:620-634`
- EdgeDetect 工具当前无屏蔽区域概念（搜索 0 结果）

### 1.2 核心矛盾
两个编辑器共用 ImageControl，一个自订阅（Measure）、一个由 Manager 路由（Roi）→ **事件路由不一致 + 潜在冲突**。

## 2. Bug 模式分析

**当前 bug**：测量工具缺屏蔽区域 + 两编辑器事件路由不一致 + 测量渲染生命周期缺陷（手柄残留/解绑残留/销毁无清理）。

**真因分类**：设计缺陷（无统一管理器编排 + 生命周期两套）。

**同类潜伏点**：
- `MeasureEditorControl` 自订阅事件 `[来源] Measure:620-634` vs `RoiEditorControl` 由 Manager 路由 `[来源] Roi:804`
- 测量渲染手柄残留 `[来源] Measure:580-583`
- 解绑不清理 `[来源] Measure:101-105`
- 销毁无清理（无 OnUnloaded/Dispose）`[来源] MeasureEditorControl` 类

**治本点**：统一管理器（`EditorInteractionManagerBase`）+ 编辑器无头化 + 统一清理入口。

## 3. 方案对比（3 候选）

| 维度 | 方案 A：统一管理器+基类（推荐） | 方案 B：互斥开关（过渡） | 方案 C：仅修复生命周期 |
|------|------------------------------|----------------------|---------------------|
| 事件冲突根治 | ✅ Manager 统一路由 | ⚠️ 靠开关易漏 | ❌ 不解决 |
| 生命周期一套实现 | ✅ 基类 | ❌ 两套 | ❌ 只补测量 |
| Measure 对齐 Roi | ✅ 无头化 | ❌ 不一致 | ❌ |
| 屏蔽区域复用 | ✅ RoiEditorControl | ✅ | ❌ 无 |
| 改动量 | 大（宿主可破坏）| 小 | 中 |
| 长期 ROI | 高 | 中 | 低 |

### 推荐：方案 A（统一管理器 + 生命周期基类 + 无头化）
- **理由**：宿主是验证空壳可破坏；治本（消除两套生命周期 + 事件冲突）；对齐既有 `RoiEditorControl` 无头模式。

## 4. 最终架构设计

```
┌──────────────────────────────────────────────────────────────┐
│  EditorInteractionManagerBase（SDK 层，新增）                   │

└─────────────────────────┬────────────────────────────────────┘

        ┌─────────────────┴──────────────────┐
        ▼                                    ▼

│ RoiEditorManagerControl│         │ MeasurementEditorManagerControl│
```

## 6. 防御机制

### 防御机制 #1：生命周期契约测试
- `EditorManagerContractTests`：绑定/解绑/缩放同步/节流合并/互斥切换/统一清理。
- 覆盖：绑定后事件路由到正确编辑器、解绑后画布清空、缩放同步到所有子编辑器、互斥时只有一个编辑器激活。

### 防御机制 #2：端到端冒烟（手动）
- 测量工具：画卡尺引导 + 画屏蔽区域，两者共存无冲突。
- 切换：画引导时屏蔽不响应，反之亦然。
- 删除/解绑/关闭：画布无残留、光标正常。

### 防御机制 #3：Fail-Forward
- 未绑定 ImageControl 时安全跳过；`GetEditors()` 返回空时 RenderAll 空操作。
