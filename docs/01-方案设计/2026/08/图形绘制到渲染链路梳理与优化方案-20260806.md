## 🔄 改前 → 改后 → 依据（写在最前面）

### 改前（用户视角）

在区域编辑器里拖动一个区域、拖动手柄、或连续移动鼠标时：

- **日志面板疯狂刷屏**（每帧几十条），真有问题时反而被淹没
- **拖动跟手度下降、CPU 占用偏高**
- 区域一多（上百个）、图一大（5000×4000），编辑器明显卡顿
- 同一张图上"结果叠加层"很流畅，但"区域编辑器"很卡——**同项目两套画法，慢的那套恰恰是你天天在用的**

### 改后（用户视角）

- 拖动区域 / 手柄时不再每帧全量重画，只更新正在动的那一块
- 日志从"每帧几十条"降到"操作级一条"级别，真有问题能一眼找到
- 上百个区域也能跟手，不再卡顿
- 区域编辑器与结果叠加层统一成同一种高性能画法，性能对齐

### 依据（业界参考）

- WPF 高性能叠加层标准做法：`DrawingVisual` + `DrawingContext` + 单次 `OnRender`，几何合并成 `StreamGeometry`，画刷/几何缓存并 `Freeze`，视口裁剪，LOD 降采样——本项目 `ResultRenderLayer.cs` 已是教科书级实现
- 控件级（`Shape`/`Ellipse`）逐个更新触发布局（`Measure`/`Arrange`），是 WPF 渲染慢的根源，业界统一用 `DrawingVisual` 规避
- 鼠标热路径应节流（读像素、更新状态栏文本），避免每帧做重活

### 接口/类型定义

- `IRoiRenderer.RenderTarget` 为 `ImageSource`，设计上"渲染到位图"，实际实现操作 Canvas 控件集合——**接口契约与实际实现背离**
- `IRoiRenderer.UpdateRegion`（增量）已定义，但全量路径 `RenderAll` 未使用

### 调用链

- 鼠标移动 → `ImageControl` 每帧 `CopyPixels` 读像素 + 更新状态栏 → 触发 `ImageMouseMoveEvent`
- → `RoiEditorManagerControl` 收到事件 → 每帧 `RenderAll()` 全量重画所有区域 + 所有手柄
- → `WpfShapeRenderer` 逐区域更新 Shape 控件（每帧 `new SolidColorBrush` + `label.Measure` + 改布局属性）
- → `HandleRenderer` 每帧销毁重建 8-10 个 `Ellipse` 手柄
- → 结果叠加层 `ResultRenderLayer.OnRender` 一次性绘制（相对健康）

### 配置/数据格式

- 无特殊数据格式问题，均为 WPF 控件/绘制上下文

### 现有模式参考

- `ResultRenderLayer.cs`：高性能绘制的标杆（`DrawingContext` + 合并几何 + 缓存 Freeze + 裁剪 + LOD）
- `NodeUIPool.cs` / `NodeRenderScheduler.cs`：对象池 + 异步批量渲染调度（工作流画布健康路径）

## 问题分析（Phase 0）

### 需求拆解

- **表面需求**：区域编辑器和渲染日志太多，感觉影响渲染性能
- **根本问题**：渲染热路径上挂着大量无条件日志 + 控件级逐帧全量重画，导致 UI 线程开销大、掉帧、日志刷屏
- **问题分类**：架构冗余（两套画法并存）/ 实现有误（降频 bug）/ 设计浪费（增量接口闲置）

### 架构分配检查

- 最自然的归属层：`RoiEditor` 渲染管线（`WpfShapeRenderer` + `HandleRenderer` + `RoiEditorControl`）——本层职责就是"把区域画出来"
- 已有类似机制：`ResultRenderLayer`（高性能 DrawingContext 画法）可作为迁移参照——有
- 不改是否可覆盖：不可，控件级画法在大量图形下必有瓶颈
- 是否改变分层边界：不改变，仍是"区域编辑 → 渲染层"职责划分

### 方法对比（≥ 3 候选）

| 维度 | 方案 A（推荐）DrawingVisual 改造 | 方案 B 仅日志降频 | 方案 C 全量移植 DrawingContext |
|------|--------------|--------------|--------------|
| 实现方式 | 区域编辑器从 Shape 控件改为 `DrawingVisual` + 单次 `OnRender`，配合缓存/裁剪/增量 | 只降频/删除热路径日志 | 编辑器完全复用 ResultRenderLayer 画法重写 |
| 架构一致性 | 与结果层统一高性能画法 | 只治标，画法仍慢 | 最高一致性，但改动最大 |
| 复杂度 | 中等（改动 RoiEditor 渲染 3 个文件） | 低（2 个文件） | 高（编辑器重构） |
| 维护成本 | 中 | 低但治标 | 低（彻底统一） |
| 长期 ROI | 6月内见效 | 立即但不彻底 | 最优但需较长时间 |

**推荐方案 A**：分阶段——先做日志降频（B，立即止血），再做 DrawingVisual 改造（根治大量绘制瓶颈）。这也是"快速见效 + 长期治本"的合理路径。

## Bug 模式分析（Phase 0.5）

**当前问题**：

1. **降频形同虚设**：`CORRECTION_LOG_INTERVAL = 1`（`RoiEditorControl.cs:67`），`_correctionStatusCount++ % 1 != 0` 恒 false → `LogCorrectionStatus`（内容超长，矩阵+全部区域摘要）**每次必打**
2. **降频 bug**：`WpfShapeRenderer` 的 `_logCounter` 只在 `CreatePolygon` 里 `++`，其他 4 个 `Create*` 方法检查 `%10==0` 时计数恒 0 → 降频从未生效，每次都打

**真因分类**：实现偏差（降频逻辑放错位置 / 参数设错）

**同类潜伏点**：

- `ParameterSource.cs:113`：`NodeOutputSource.GetValue` 每次获取打 Info+Success——同属"取值热路径刷日志"
- `RoiEditorControl.cs:2108 / 2164`：手柄绘制入口无条件 Info——同属"每帧热路径刷日志"

**治本点**：修复降频逻辑位置与参数，并在渲染热路径移除/大幅降频日志，而非逐个删日志点。

## 解决方案

### 方案概述

分三阶段落地，先止血再治本：

1. **阶段一（立即止血）：日志降频** —— 修复 2 个降频 bug + 删除/降频渲染热路径日志
2. **阶段二（根治瓶颈）：区域编辑器渲染管线改造** —— 从 Shape 控件改为 DrawingVisual + 单次重绘，配合画刷/几何缓存 + 视口裁剪 + 增量渲染
3. **阶段三（配套清理）**：事件节流 + 死代码清理 + 参数日志降频

### 技术方案

**阶段一：日志降频（改动 2 个文件：`WpfShapeRenderer.cs` + `RoiEditorControl.xaml.cs`）**

1. `UpdateShapeFromContext`（WpfShapeRenderer:334）：删除无条件日志（或降到每 500 次）
2. `LogCorrectionStatus`（RoiEditorControl:151）：从 `CreateRenderContextInternal` 移除调用点，`CORRECTION_LOG_INTERVAL` 从 1 改为 100
3. `DrawEditHandles` / `CreateHandlesForShape`（2108 / 2164）：删除入口日志
4. `HitTestRegion`（2333）：删除每次 Info，仅保留"命中时"一条 Success（有诊断价值）
5. `ProcessMouseDown`（870）：降到每 20 次打一条
6. `ProcessMouseMove`：保持每 100 次（已是降频）
7. 修复 `_logCounter` 降频 bug：提升到 `CreateShapeFromContext` 统一递增
8. `RemoveInvisibleRegions`（219）：精简掉 GUID 全列表拼接

**阶段二：区域编辑器渲染管线改造（核心）**

1. `WpfShapeRenderer` 改为基于 `DrawingVisual` 绘制，`RenderTarget` 真正用起来（对齐 `IRoiRenderer` 契约）
2. 画刷/几何/文字缓存并 `Freeze`，避免每帧 `new SolidColorBrush` / `new FormattedText`
3. 接入视口裁剪 + LOD 降采样（参照 `ResultRenderLayer`）
4. 手柄、橡皮筋、标签全部纳入单次 `OnRender`，不再每帧创建/销毁控件
5. 增量渲染：拖动单区域只更新该区域 visual，不再 `RenderAll` 全量（接上已定义的 `UpdateRegion` 接口）

**阶段三：配套清理**

1. `ImageControl` 鼠标移动像素读取 + 状态栏文本更新降频（30ms 节流）
2. `NodeOutputSource.GetValue`（ParameterSource:113）去掉 Info+Success
3. 清理死代码：`CanvasRenderer` / `GeometryOptimizer` / `SpatialIndex`（或先审计 `SpatialIndex` 是否可复用到区域裁剪）

### 实施步骤

1. **阶段一**：日志降频（修复 bug + 降频/删除热路径日志），改动 `WpfShapeRenderer.cs` + `RoiEditorControl.xaml.cs`
2. **阶段二**：区域编辑器渲染管线 DrawingVisual 改造，增量渲染接线
3. **阶段三**：事件节流 + 死代码清理 + 参数日志降频
