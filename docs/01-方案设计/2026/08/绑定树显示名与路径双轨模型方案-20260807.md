# 绑定树显示名与路径双轨模型方案

> 主题：绑定树"显示名 ↔ 路径"双轨模型统一 + RoI 数组绑定全链路修复
> 日期：2026-08-07

## 一、改前 → 改后 → 依据

### 改前（你现在遇到的问题）

1. **绑定"圆"分组后，显示名是错的**：实际显示 `圆.InspectionGeometries[圆]`，而不是 `Blob分析2.圆[]`——根节点取成了"圆"（因为子节点 Parent 链断了），叶子名拼成了"属性名+[圆]"（而不是"短名+[]"）。
2. **分组带数量**：树里显示 `圆 (2项)`，不想要。
3. **想指定索引没门路**：手动把显示名 `圆[]` 改成 `圆[2]`，后台绑定路径会**静默丢掉类型过滤**——变成取"检测区域数组第 2 个元素"（可能取到矩形），比报错更危险。
4. **后台解析路径不稳定**：显示项/输出项解析用 `Split('.')` 只取第一段，嵌套路径（`[0].Geometry.X`）会被截断。

### 改后（你要的效果）

| 操作 | 显示名（人看） | 绑定路径（机器用） | 后台行为 |
|------|--------------|-------------------|---------|
| 点"圆"分组 | `Blob分析2.圆[]` | `Node1.检测区域[Type=Circle]` | 过滤出所有圆 → 遍历逐个画 |
| 手动改 `圆[2]` | `Blob分析2.圆[2]` | `Node1.检测区域[Type=Circle][2]` | 过滤圆 → 取第 2 个 → 画一个 |
| 点"整体" | `Blob分析2.检测区域[]` | `Node1.检测区域[]` | 全部图形 → 遍历逐个画 |
| 点"[0]" | `Blob分析2.检测区域[0]` | `Node1.检测区域[0]` | 取第 0 个 → 画一个 |
| 普通数组（宽度） | `图像载入1.宽度[]` | `Node1.宽度[]` | 不变 ✅ |

- 绑定树保持现状（容器 → 整体 + 类型分组 + 单元素），分组**不显示数量**；
- 显示名与路径**双轨分离**：显示名只负责"人看得懂"，路径只负责"机器取得到"；
- 用户改显示名 `[]→[n]` → 绑定路径**自动同步且保留类型过滤**。

### 依据（业界参考）

- **VisionMaster / 基恩士**数据源绑定：下拉显示名用中文友好文本，内部存节点 ID + 属性路径，两轨分离是标配；
- **本仓既有设计**：`AvailableDataSource` 早已分"身份层 + 展示层 + 状态层"，`GetBindingPath()`（机器）与 `GetDisplayText()`/`DropdownDisplayText`（人看）本就是两个方法——本次只是把这条原则贯彻到 RoI 合成节点上。

## 二、问题清单（对话中发现的全部缺陷）

| # | 问题 | 现象 | 根因位置 | 影响 |
|---|------|------|---------|------|
| P1 | RoI 子节点 `Parent` 链断裂 | 显示名根节点取成"圆" | `ParamBindingBase.ApplyArrayDisplay` 创建子节点未设 `Parent` | 显示名错误 |
| P2 | RoI 分组叶子名拼错 | `InspectionGeometries[圆]` 而非 `圆[]` | `ParamBinding.GetDisplayLeafName` 走 `PropertyName+翻译后缀` | 显示名不统一 |
| P3 | 分组显示数量 | `圆 (2项)` | `ArrayTreeFormatter.BuildRoiBindingChildren` | 界面不简洁 |
| P4 | 改显示名索引丢类型后缀 | `圆[2]` → 路径变成 `检测区域[2]` | `ParamBinding.OnBindingDisplayTextChanged` 重建路径时丢弃 typeFilter | **静默取错元素**（违反 rule-015） |
| P5 | 解析器不支持"类型+索引"组合 | `[Type=Circle][2]` 中 `[2]` 被忽略 | `PropertyPathParser.ParsePropertyPart` 只解析第一对括号 | P4 修复的前提缺失 |
| P6 | 嵌套路径被 `Split('.')` 截断 | `[0].Geometry.X` 只剩 `[0]` | `SubroutineTool` 输出项/显示项/循环边界 + `GenerateBindingDisplayText` | 属性穿透绑定失效 |
| P7 | 整体绑定 `[]` 被剥离 | `检测区域[]` 被剥成 `检测区域`，长度1时退化为单值 | `SubroutineTool` 三处 `parts[1].EndsWith("[]")` 剥离 | 契约语义退化 |

## 三、修复方案（按层分四组）

### 组 A：绑定树生产层（P1、P3）

| 文件 | 改动 |
|------|------|
| `ParamBindingBase.ApplyArrayDisplay` | 给 RoI 子节点（整体/分组/单元素）统一补 `Parent = leafNode` |
| `ArrayTreeFormatter.BuildRoiBindingChildren` | 分组节点 `Text` 去掉 `(N项)` → 统一 `圆`（与设计期 `BuildRoiDesignTimeGroups` 一致） |

### 组 B：显示名生成层（P2）

| 文件 | 改动 |
|------|------|
| `ParamBinding.GetDisplayLeafName` | RoI 分组分支改为 `$"{node.Text}[]"`（即 `圆[]`），不再拼 `PropertyName`；单元素分支保持 `PropertyName[i]`；整体走数组分支 `DisplayName[]` |

### 组 C：路径解析层（P5）

| 文件 | 改动 |
|------|------|
| `PropertyPathParser.ParsePropertyPart` | 支持双括号：`[Type=X]` 解析完后继续看 `[n]`，返回 `(propName, index, typeFilter)` 三要素同时有值 |
| `OutputVariableResolver.Resolve` | 第一段先 `FilterByShapeType`（有 typeFilter）再 `GetArrayElement`（有 index ≥ 0）；`[]` 保留数组语义不变 |

### 组 D：编辑联动 + 消费层（P4、P6、P7）

| 文件 | 改动 |
|------|------|
| `ParamBinding.OnBindingDisplayTextChanged` | 重建 `BindingSource` 时**保留 typeFilter**：`[Type=X][n]` / `[n]` / `[]` 三态正确重建 |
| `SubroutineTool` 输出项/显示项/循环边界 3 处 | 统一改为：`Source != null ? Source.GetBindingPath() : BindingSource`，再 `IndexOf('.')` 只切第一个点（不 `Split('.')`、不剥离 `[]`） |
| `ParamBinding.GenerateBindingDisplayText` | 同样改用 `IndexOf('.')` 切第一个点，防嵌套截断 |

### 防御机制

1. **契约测试**（组 A/B/C/D 全覆盖）：显示名 ↔ 路径映射表钉死 + 双括号解析 + 编辑联动保留类型后缀；
2. **回归测试**：现有 `RoiDesignTimeGroupsContractTests` / `RoiBindingContractTests` 数量与路径断言同步更新。
