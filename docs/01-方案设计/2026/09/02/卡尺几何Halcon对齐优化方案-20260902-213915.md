## 三、Bug 模式分析

**真因分类**：**设计缺陷**（跨层语义混用 + 无单一事实源），不是单个实现笔误。

**同类潜伏点**：
- [来源] `ArcGuideInteraction.cs:91` — 与 P2 同 pattern（角度折叠破坏连续扫掠），**仍存在**
- [来源] `Annulus2d.cs:216-223` — **项目内已有正确模式**：`NormalizeAngle(angle, reference)` 规范到 `[reference, reference+2π)`，**保持相对差不变**（应复用，而非新写）
- [来源] `Arc2d.cs:211-225` — `AngularSpan` 的 `(-π,π]` 折叠是**模型层唯一合法折叠**，禁止复制到几何层

**治本点**：修复「缺少 WPF↔Halcon 单一适配出口」+「卡尺几何没有真值基准」，而非逐个调公式。

**方法论纠正**：此前两次公式调整（中心对齐 → 半格）均基于目测反馈推测，**无 Halcon 真值支撑**，属方法错误。本方案规定：卡尺分布参数必须由 Halcon 回读值定标，定标前不再改动公式。

## 八、防御机制

1. **契约测试**：`HalconArcAdapter` 不变量——输出 ∈ `[0,2π]`；`(end−start) mod 2π` 沿 `point_order` == `|AngularSpan|`；整圆恒 `(0, 2π, positive)`
2. **真值回归**：定标判据 `max|P_halcon − P_wpf| < 0.5 px`，写入单测成为"Halcon 契约用例"
3. **Fail-Forward**：适配层输入非法（NaN / Radius≤0 / \|span\|>2π+ε）直接抛错，禁止静默兜底（rule-015）
4. **跨层保护**：几何层禁止出现任何 `(-π,π]` 折叠（code review 检查项）
