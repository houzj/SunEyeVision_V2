# 双渲染层幂律缩放治理方案

> 背景：结果层（`ResultRenderLayer`）与交互覆盖层（`InteractionOverlayCanvas`）共用一个图像缩放变换，但各装饰元素的缩放规则分散实现、参数不一，导致"同一语义元素两层视觉不一致""结果层三角偏大"等问题。
> 本文整合完整调研上下文，给出治本方案与**幂律管控列表**。

- 方案类型：显示层缩放规则治理（优化/重构）
- 关联文件：`ImageControl` / `ResultRenderLayer` / `MeasureBandOverlay` / `HandleRenderer` / `RotatedRectangleHelper` / `WpfShapeRenderer`
- 日期：2026-09-03
- 状态：待用户确认后移交方案实施

---

## 1. 改前 / 改后（用户视角大白话）

**改前**：结果层和交互层虽然共用一个缩放变换，但每个"装饰元素"的缩放规则是各画各的——有的贴图放大、有的屏幕大小不变，公式和常数散落在 4+ 个类里，参数还各不相同。表现就是：同一个卡尺方向标记，结果层画得大、交互层画得小；圆/弧结果层"三角"随图像放大后显得刺眼；线宽、手柄、箭头各自为政。

**改后**：全工程只有一套"装饰缩放公式库"（一个静态类）。任何装饰元素（箭头、三角、十字、手柄、文字、虚线）要多大、要不要随缩放变化，去查**幂律管控表**，公式统一、参数统一，结果层与交互层视觉永远一致。

**依据**：单一事实来源（single source of truth）+ 最小改动（YAGNI/KISS，rule-008），不改渲染架构，只归口公式。

### 2.3 已识别的不一致

- **同一语义元素公式不同步**：极性方向标记在结果层（`BuildMeasureGuideItems`，[来源] `src/Plugin.SDK/Execution/Parameters/RoiParameters.cs:96`）与交互层（`MeasureBandOverlay.cs:84-86`）系数未对齐。
- **同 p 不同实现**：同是"线宽"，结果层 `rawWidth/scale` 与交互层 `2.0/zoom` 语义一致但字面量不统一，存在笔误风险面且无测试。
- **盲区**：Polygon 批量合批绘制（`ResultRenderLayer.RenderPolygons` 435-472、`MeasureBandOverlay.AddPolygon` 398-410）的三角无法单独反除——混在整批几何里贴图放大。这是"结果层三角偏大"的根源之一。

## 3. Bug 模式分析

**当前 bug**：结果层与交互层装饰元素缩放视觉不一致、"结果层三角偏大"。

**真因分类**：设计缺陷 —— 架构上没有"装饰缩放"的唯一归口，导致每个开发者按直觉写公式。

**同类潜伏点**：
- [来源] `HandleRenderer.cs:96-134` — 三套幂律公式与 `ResultRenderLayer:148-149` 各自为政
- [来源] `MeasureBandOverlay.cs:477-482` 与 `ResultRenderLayer:213` 的线宽反除实现不一致
- [来源] `RotatedRectangleHelper.cs:146-217` — 又一套内联 `1/scale`
- [来源] `ResultRenderLayer.cs:847-864` 与 `MeasureBandOverlay.cs:467` — 同是"方向箭头"，翼长一处幂律、一处半贴图

**治本点**：建立**装饰元素缩放管控**（公式唯一源 + 幂律管控表），而非逐个调系数。

## 6. 幂律管控列表（核心交付）

> 统一模型：`Screen = Base / zoom^p`；WPF 逻辑尺寸 = `Screen / zoom`（被 `ImageScaleTransform` 乘回）。
> 语义红线：**锚点/朝向贴图，尺寸幂律**；几何数值类（圆心、半径、顶点、bandWidth）永远 p=0。

### 6.1 元素分类与规则

| 类别 | 典型元素 | p | 说明 |
|---|---|---|---|
| 几何数据 | 多边形顶点、圆心/半径、矩形角点、测量带边界、引导线端点 | 0（贴图） | 承载测量语义，WYSIWYG |
| 边界线宽 | 多边形/带/引导线描边 | 1 | 屏幕恒定（2px 起） |
| 强几何随附标记 | 卡尺极性三角（顶/底边小箭头） | 0（贴图） | 尺寸语义与带成比例，缩放必须保比例 |
| 方向箭头头部 | 结果层 Arrow 翼长 / 交互层方向箭头 | 1 | 锚点贴图 + 翼长幂律 |
| 十字/点标记 | 点、Cross | 0.7 | 缓和反除，避免高倍 zoom 丢失 |
| 操作手柄 | ROI/Measure 缩放手柄方块 | 0.15，clamp 10~12px | 交互恒定，可点中 |
| 文本标签 | 结果文字 | 0.15，clamp 9~12px | 可读性 |
| 虚线间隔 | 旋转连线虚线 | 0.15 | 视觉精细 |
| 坐标轴 | CoordinateSystem 轴长 | 0（贴图，几何值） | 轴长是数据 |

### 6.2 逐元素管控表（现状 → 目标）

| # | 元素 | 层 | 现状 | 目标 | 动作 |
|---|---|---|---|---|---|
| 1 | 引导线/带线宽 | 交互 | `2/zoom` | p=1, Base=2 | 归口调用 |

## 9. 防御机制

1. **契约测试**：`ViewportScaling` 公式单测 —— zoom=1 时 Screen=Base；反除互逆 `(Base/zoom^p)*zoom^p ≈ Base`；clamp 边界
2. **端到端冒烟**：`ImageControl.xaml.cs:830` 缩放链路回归 —— 改 zoom 后结果层与交互层线宽/字号同步更新
3. **Fail-Forward**：`zoom≤0` 一律取 `Math.Max(zoom, 0.01)`，沿用现有保护，不允许除零分支
4. **管控表对应回归**：极性三角（表 #9）在 3 个 zoom（0.3/1.0/4.0）下必须与带成比例（贴图），用截图对比
