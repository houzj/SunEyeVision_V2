## 0. 用户功能性视角（改前/改后）

**改前**：`SunEyeVision.Plugin.SDK` 自称"纯契约层"（csproj Description），实际引用 `halcondotnetxl` + `OpenCvSharp4`，SDK 内 8 个文件调 Halcon 算子、7 个文件用 OpenCV 类型。结果是**框架层被算法库绑死**——想换算法库、想独立发 SDK 包、想不装 Halcon 反序列化 recipe，全都做不到。

**改后**：
- **框架层**（SDK/UI/Workflow/Core/Plugin.Infrastructure）引擎无关：只认 `IVisionImage/IVisionRegion/IMonitorable` 接口 + 纯契约（RoI/几何/矩阵/绑定/序列化/词汇表）；
- **算法库层平级独立**：Halcon（第三方直接用 `HOperatorSet`）‖ CvEngine（自研纯算法库，仅依赖 OpenCvSharp；`CvImage`/`CvRegion`/`CvContour` 为纯数据载体，**不实现 SDK 接口**）；
- **适配层两个薄桥、分开独立**：`HalAdapter`（引 SDK+halcon）‖ `CvAdapter`（引 SDK+CvEngine），各自把算法库产物桥成 SDK 契约；**后期可按需加载**，宿主/工具只用哪个引哪个；
- **工具层自由选型**：ShapeMatch 引 Halcon、某工具引 CvEngine、某工具纯 C#——只改工具 csproj，不碰框架。

> **架构决策记录（2026-09-04 用户确认）**：CvEngine 必须与 halcon 完全对称——
> ① CvEngine 是算法库层，不属于适配层；② CvImage/CvRegion 迁入 CvEngine 后只保留纯算法载体（Mat + 算子），去掉 `IVisionImage/IMonitorable/ToBitmapSource` 等 SDK 职责；③ SDK 接口的 Cv 侧实现由独立的 `CvAdapter` 提供；④ `HalAdapter` 与 `CvAdapter` 分开两个程序集，按需加载。

## 1. 现状问题分析（全量盘点 · 带来源）

| 层 | 文件 | 依赖 | 性质 |
|---|---|---|---|

| `VisionAdapters/HalRegion.cs` | Halcon | Halcon 实现（实现 SDK 接口）| → HalAdapter |
| `VisionAdapters/HalconHelpers.cs` | Halcon+OpenCV | `GetHalconImage` 扩展 + Cv→Hal | → HalAdapter（Cv→Hal 桥经 CvAdapter 注册契约，避免适配器互引）|

> 已核实：SDK 内 `using HalconDotNet` 8 文件、`using OpenCvSharp` 7 文件；`UI/` 层零引擎依赖；77 个外部 `.cs` `using SunEyeVision.Plugin.SDK.VisionAdapters`；23 csproj 引用 SDK；11 个工具 csproj 直接引 halcondotnetxl。

### 1.2 三个结构性难点

**难点 A：`VisionImage` 静态门面横跨双侧**（FromFile→HalImage、FromMat→CvImage）
**难点 B：Cv↔Hal 交叉转换**（HalconHelpers 内 Cv→Hal；CvToolHelpers 内 Hal→Cv）
**难点 C：`SdkTypeVocabulary` 用 `typeof(Mat)` 映射**（契约层渗入引擎类型）

### 1.3 关键有利先例（复用）

SDK **已有**"接口 + 静态定位器注入"的成熟模式：
`IVisionImageDisplayBridge` + `VisionImageConverterLocator.Current`（UI 启动注入）——这正是适配器层该用的机制，`VisionImage` 门面、`Mat` 词汇注册都可复用此模式。

## 2. Bug 模式分析

**当前 bug**：契约层携带引擎依赖（框架腐化）。
**真因**：分层边界未执行到 csproj 级——接口/实现/桥接/门面全部同居一个程序集。
**同类潜伏**：SdkTypeVocabulary 的 Mat、VisionImage 门面、RegionConverter 直接 new HRegion。
**治本点**：按"框架(接口+契约) / 算法库(平级实现) / 适配器(纯中转)"三层物理分程序集，csproj 依赖单向。

## 3. 业界对标

| 框架 | 做法 | 借鉴 |
|---|---|---|

## 5. 目标架构

```
┌──────────────────────────────────────────────────────────────────┐
│ SDK 框架层（契约/UI/Workflow/Core/Infrastructure）— 零引擎依赖    │
│  IVisionImage/IVisionRegion/IVisionContour/IMonitorable(接口)    │
│  RoI(ShapeParameters)/几何/AffineMatrix/绑定/词汇表/序列化        │
│  VisionImageConverterLocator / VisionImageFactoryLocator(注册点) │
└───────────▲─────────────────────────────▲────────────────────────┘
     适配(薄)│                        适配(薄)│
┌───────────┴─────────────┐   ┌──────────┴──────────────────────┐
│ HalAdapter（适配层·独立） │   │ CvAdapter（适配层·独立）          │
│ HalImage→IVisionImage     │   │ CvVisionImageAdapter→IVisionImage│
│ HalRegion→IVisionRegion   │   │ CvVisionRegionAdapter→IVisionRegion
│ RegionConverter/ToolRegionHelper  │ CvToolHelpers(GetCvImage)     │
│ 引 SDK + halcondotnetxl   │   │ 引 SDK + CvEngine               │
└───────────▲─────────────┘   └──────────▲──────────────────────┘
            │ 引第三方库                   │ 引自研纯算法库
┌───────────┴─────────────┐   ┌──────────┴──────────────────────┐
│ Halcon（第三方算法库）    │   │ CvEngine（自研纯算法库）          │
│ HImage/HRegion/HOperatorSet  │ CvImage/CvRegion/CvContour      │
│                           │   │ CvOp.* ≈ HOperatorSet          │
│                           │   │ 仅依赖 OpenCvSharp，不引 SDK    │
└──────────────────────────┘   └─────────────────────────────────┘
       工具层：引 SDK + 所选算法库(Halcon‖CvEngine) + 对应适配器(HalAdapter‖CvAdapter) → 按需加载
```

**依赖方向（对称）**：`适配器 → SDK + 算法库`（单向）；`算法库（CvEngine）→ OpenCvSharp`（不引 SDK）；`工具 → SDK + 所选算法库 + 对应适配器`；`主程序装配注入`。SDK 永不反向依赖引擎；两个适配器互相独立、不互引，Cv↔Hal 交叉转换经 SDK 注册契约分发。

## 6.5 SDK 视觉抽象层命名治理（2026-09-04 用户确认）

适配器迁出 SDK 后，原 `VisionAdapters/` 目录只余**契约接口 + 注册点/门面**，按设计职责更名为：

```
src/Plugin.SDK/Vision/Contracts/   → SunEyeVision.Plugin.SDK.Vision.Contracts
     IVisionImage.cs  IVisionRegion.cs  IVisionContour.cs  IMonitorable.cs   ← 纯接口契约
src/Plugin.SDK/Vision/Hosting/     → SunEyeVision.Plugin.SDK.Vision.Hosting
     IVisionImageFactory.cs（+VisionImageFactoryLocator）     ← 引擎接入注册点
     IVisionImageDisplayBridge.cs（+VisionImageConverterLocator）
     VisionBackendExtractorLocator.cs（Cv↔Hal 跨后端提取注册点）
     VisionImage.cs（门面）  VisionFileLoader.cs（内部辅助）
```

- `Contracts` = 框架消费的视觉数据接口（工具/适配器引用它）；
- `Hosting` = "宿主如何接引擎"的注册点/定位器/门面（装配侧注入实现，SDK 保持零引擎）；
- 目录名 `VisionAdapters` 退役（"适配器"语义已随 HalAdapter/CvAdapter 迁出 SDK，避免误导）。

## 12. 决策建议

按 S1→S5 分阶段实施，每阶段构建验证 + 对应 AC。**架构定位（2026-09-04 用户最终确认）**：
- CvEngine = 纯算法库（算法层，不实现/不依赖 SDK 接口），与 halcon 完全对称；
- CvAdapter 新建、HalAdapter 复活，**两个适配器分开独立**，按需加载；
- Cv↔Hal 交叉转换经 SDK 注册契约分发，两适配器互不引用；
- S1 已实施完成并提交（SDK 解耦接缝），后续从 S2 开始。
