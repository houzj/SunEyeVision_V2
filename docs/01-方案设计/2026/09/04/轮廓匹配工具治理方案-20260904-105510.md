# 轮廓匹配工具治理方案

> 目标工具：`tools/SunEyeVision.Tool.ShapeMatch/`（Version 2.0.0，displayName "轮廓匹配"）
> 方案类型：架构治理（正确性 + 性能 + 参数可信度）
> 日期：2026-09-04

---

## 1. 改前 / 改后 / 依据（用户视角）

**改前**：轮廓匹配工具能用，但有几个"看不见的坑"：
- 每跑一次都要往磁盘写临时文件再读模型，图多模板多时明显卡（`ShapeMatchTool.cs:311-327`）；
- 参数面板里一堆"拟合参数"（角度步长、缩放步长、最小对比度、极性模式、并行度、每模板覆盖）**调了根本不生效**——要么只影响建模板、要么压根没接线；
- 轮廓旋转方向、角度文本方向、角度线方向**谁对谁错没有实测证据**：渲染走"手拼的 WPF 矩阵"（`+Angle`），角度文本/指示线走 `-Angle`（`ShapeMatchTool.cs:407-413` vs `:423`），两处符号相反，坐标系约定不统一；
- 匹配数量不足判 NG 时，已画出的框仍显示绿色 OK（单个匹配项 `JudgmentPassed` 从未被赋值，`ShapeMatchResults.cs:222` + `ShapeMatchTool.cs:489-524`）。

**改后**：
- 模板句柄只在首次加载/变更时构建，之后每帧直接复用，跑图不再做磁盘 IO；
- 矩阵计算全部收敛到 **Halcon 官方链**（`vector_angle_to_rigid` + `hom_mat2d_scale` → `affine_trans_contour_xld`），**WPF 只负责画已经算好的像素坐标轮廓，不参与几何计算**；
- 坐标系方向用一次已知旋转实测定案，矩阵与角度显示统一同一符号约定；
- 无效参数从面板移除或接线；NG 时框变红；缺模板/零匹配路径判定口径统一。

**依据（业界/官方）**：Halcon 官方 `find_scaled_shape_model` Example 的**权威做法**就是用矩阵算子链而非手拼：

```hdevelop
vector_angle_to_rigid (0, 0, 0, Row, Column, Angle, HomMat2DTmp)
hom_mat2d_scale (HomMat2DTmp, Scale, Scale, Row, Column, HomMat2DObject)
affine_trans_pixel  (HomMat2DObject, 0, 0, RowObject, ColObject)
```
[来源] 本机 `find_scaled_shape_model.html:1361-1377`（官方 Example 段落）

| 项 | 内容 |

## 8. 防御机制

1. **方向一致性契约测试**（核心）：构造已知旋转(如 +30°)模板图，断言"渲染轮廓旋转方向 == Angle 字段符号 == 角度线方向"，三向一致才通过。
2. **句柄缓存幂等测试**：同一 ModelData 连续 Run N 次，断言只构建一次模型、结果一致。
3. **Fail-Forward**：模型反序列化失败升级为 Error 并指明模板名，不再静默返回空。
4. **死参数静态防线**：实施后全库搜"XAML 绑定 ParamValue 但 Run 未引用"，输出残留清单。

## 11. 风险评估

- **R1（关键前置确认）**：`AngleStep/ScaleStep/MinContrast/Metric/Optimization` 若编辑器数据源来自 `Parameters` 同名属性则不能删属性只能隐藏 UI。初步判断 `ShapeMatchTemplateEditorDialog` 用对话框本地控件（如 `cmbMetricMode`）而非 `Parameters.MetricMode`，可删，但需二次确认（`ShapeMatchTemplateEditorDialog.xaml.cs:215-231`）。
- **R2 回退策略**：按阶段提交（P0→P1→P2），任一阶段构建失败可单独 revert。
- **R3 行为变化**：默认 SortMode 变更、NMS 引入会改变既有流程结果数量——存量 Recipe 需复查匹配数判定窗口。

## 12. 结论

一次"分组治理"同时解决架构边界（计算归 Halcon）、性能（句柄缓存）、判定正确性、参数可信度四类问题，与仓库刚完成的 Line/Circle 治理纪律一致。按 P0→P1→P2→P3 分阶段实施，每阶段构建验证。
