# 轮廓匹配工具治理方案（更新版）

> 目标工具：`tools/SunEyeVision.Tool.ShapeMatch/`（V2.0.0，displayName "轮廓匹配"）
> 方案类型：架构治理（正确性 + 性能 + 参数可信度）
> 日期：2026-09-04
> 版本说明：本版按"框架流通通用类型 + 独立适配器"范式重构矩阵链路表述，修正上一版（105510）"Halcon→WPF 转换"的错误叫法。

---

## 1. 改前 / 改后 / 依据（用户视角）

**改前**：轮廓匹配工具有几个"看不见的坑"：
- 每跑一次都写磁盘临时文件再读模型，多模板时卡（`ShapeMatchTool.cs:311-327`）；
- 参数面板多个"拟合参数"调了无效（角度步长/缩放步长/最小对比度/极性/并行度/每模板覆盖）；
- 旋转方向无实测：渲染用 `+Angle` 手拼矩阵、角度线/文本用 `-Angle`，两处符号相反（`ShapeMatchTool.cs:409-413` vs `:423`）；
- NG 时框仍绿（`item.JudgmentPassed` 从未赋值）；
- **矩阵数值来源是开发者手拼，非算法权威**——框架内明明流通统一的 `AffineMatrix` 通用类型，工具却在边界自算坐标系。

**改后**：
- 句柄缓存，跑图零磁盘 IO；
- 矩阵 = 框架通用类型 `AffineMatrix` **唯一事实源**，由独立构造工厂从算法权威姿态产出（仿 `HalconArcAdapter` 范式），WPF/Halcon/下游只消费它的适配方法；
- 坐标系约定写死在类型注释（仿 `Circle2d.cs:105`），方向实测定案后全链路统一；
- 无效参数移除；NG 变红；零匹配路径判定口径统一。

**依据（业界/官方）**：
- Halcon 官方 `find_scaled_shape_model` Example 用 `vector_angle_to_rigid + hom_mat2d_scale` 链（本机 `find_scaled_shape_model.html:1370-1374`）；
- 本仓库范式：[来源] `HalconArcAdapter.cs:5-22` "WPF ↔ HALCON 唯一转换出口，只在传给 HALCON 这一刻做一次性转换"；[来源] `Circle2d.cs:105` 通用类型自带坐标系注释。

## 8. 防御机制

1. **方向契约测试**：+30° 已知旋转模板，断言渲染轮廓方向 == Angle 字段 == 角度线方向三向一致；断言 `FromPose` 输出矩阵 `atan2(M21,M11) == +30°`（WPF 约定下）。
2. **句柄幂等测试**：同一 ModelData 连续 Run N 次只构建一次。
3. **工厂唯一出口静态检查**：`new AffineMatrix` 在 ShapeMatch 内仅工厂出现（code review）。
4. **Fail-Forward**：模型反序列化失败升 Error 指名模板。
5. **死参数防线**：全库搜 XAML 绑定但 Run 未引用。

## 12. 结论

更新版方案把矩阵链路从"手拼 + 单向转换叫法"修正为**"算法权威姿态 → 独立工厂构造框架通用 `AffineMatrix` → 边界适配消费"**，完全对齐本仓库 Geometry 层既有范式（`HalconArcAdapter`），同时保留性能/判定/参数三组治理。建议按 P0→P1→P2→P3 分阶段实施，每阶段构建验证。
