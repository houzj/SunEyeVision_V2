## 0. 改前 / 改后（用户视角）

**改前**：拖节点时连线是否跟得上、箭头是否同步，需要拖拽代码反复"救火"——先修线不动（Transform 不触发重绘）、再修箭头不动（两套状态各跑各）。每次修补都往 Node_MouseMove 里加逻辑。

**改后**：
- 节点一挪，线与箭头自动跟着更新（单节点/多选/程序改位置全走同一条自动路径）
- 拖一堆节点：组内线整体平移不卡、跨组线自动重算
- 线体与箭头永远同步（同一份"渲染产出"生成，不再出现"线动箭头不动"）

## 1. 问题分析（三次修补揭示的真因）

| 轮次 | 现象 | 修补 | 暴露的根因 |
|---|---|---|---|
| 1 | 线不随动 | 缓存几何挂 Transform | 渲染链走 ToString→SVG，Transform 不体现在串里 → 触发模型错 |
| 2 | 线仍不随动 | 坐标级平移克隆 | 必须换坐标让串变化 |
| 3 | 箭头不动 | Move 同步 ArrowPosition | 线体与箭头是两个派生源，各自更新路径 |

**根因三层**：
1. 渲染模型：线体 = 缓存 PathGeometry 快照 + 手动 dirty；箭头 = connection.ArrowPosition 模型属性 → 同一视觉对象两条更新路径（状态分裂）
2. 触发模型：线的刷新由 Node_MouseMove 手挑（遍历/分类/调度）→ 拖拽代码承担了本应由"端点派生"自动完成的职责
3. Bug 模式：状态分裂，每次修补只对齐其中一个分支

**业界对照**（调研报告 §3-§4）：Nodify = Source/Target DP 绑定 Anchor，节点动→线自动重算；React Flow = store 派生 edge path；mxGraph = 只 reroute 受影响边；Figma = 组整体变换。结论：线是端点的派生数据；箭头是线的附着产物，二者同一次派生。

## 2. 方案对比

| 维度 | A. 收敛"渲染产出" + 端点驱动刷新（推荐） | B. 单 Path 合并箭头 | C. 完整组变换容器（远期） |
|---|---|---|---|
| 核心 | 线+箭头一次派生同产出；连接层订阅端点自动失效；拖组会话加速 | 箭头并入线体 PathGeometry Figure | 选中节点+组内线入局部坐标容器 |
| 消除分裂 | ✅ 单一产出 | ✅ 物理消除 | ✅ 整体变换 |
| 性能模型 | 拖组会话平移零重算 + 跨组 reroute | 同左 | O(1) 父变换 |
| 改动面 | 中 | 中-大 | 大 |
| 风险 | 中 | 中 | 高 |
| ROI | 高 | 高 | 最高但晚投入 |

**推荐 A**：改动内聚到"连接刷新服务"，散在 MouseMove 的线逻辑收走；箭头同步经"单一渲染产出"根治；组会话平移保留为已验证加速。

## 3. 修改清单（A 方案）

### 3.1 新增 ConnectivityRefreshService（关注点分离核心）
- 职责：接收"被移动节点集合 + 位移"，内部决策并执行连线刷新（画布 MouseMove 不再直接碰 Cache/Connection）
- API：
  - BeginDrag(IEnumerable<WorkflowNode> group)：组内/跨组线分类；Cache.BeginGroupTranslation(inner)
  - OnDrag(Point offset)：组内线 UpdateGroupTranslation + Invalidate；跨组线 5px 节流 + 批量 reroute
  - EndDrag()：组内线一次性真实重算落账；EndGroupTranslation
  - Reset()
- 单测友好：纯逻辑不依赖画布

### 3.2 WorkflowCanvasControl：线逻辑全部移交
- Node_MouseMove/Up 删除组内/跨组分类、ScheduleUpdate、InvalidatePath、平移会话、ResetDragGroup → 只保留写 Position + 调 _connectivityRefresh.OnDrag/EndDrag
- Down 调 _connectivityRefresh.BeginDrag(group)

### 3.3 ConnectionPathCache：会话能力"通用化 + 单一产出"
- 保留 Begin/Update/EndGroupTranslation（坐标级平移克隆已验证）
- 新增"渲染产出"保证：GetPath 平移克隆分支与真实重算分支（CalculatePath）都写 connection.ArrowPosition —— 两侧一致，消除分裂

### 3.4 端点驱动（阶段 2 可选）
- WorkflowConnection 订阅两端节点 Position → 自动入队刷新（幂等防重订阅）
- 拖组时 Position 用 BeginSuppressNotifications 抑制，仍由会话显式刷新
- 单节点/程序移动走订阅自动刷新

### 3.5 箭头：短期收敛、长期可选合并
- 短期：与线体同一次产出写入（3.3 落地即根治）
- 长期可选：单 Path 合并箭头（方案 B）

## 5. 防御机制

1. 单一产出契约：线几何与箭头同一锁/同一分支写入（结构约束 + 评审）
2. 服务单测：ConnectivityRefreshService（分类/只 reroute 跨组/落账清理）；Cache.TranslateGeometry 各段类型平移
3. 端到端冒烟：单节点拖、多选拖、松手保存重开、（可选）程序改位置
4. 回退：Service 异常 Reset 清理状态

## 6. 验收标准

|---|---|---|---|

| 2 | 单节点拖动：相连线与箭头同步刷新 | manual | 冒烟 |
