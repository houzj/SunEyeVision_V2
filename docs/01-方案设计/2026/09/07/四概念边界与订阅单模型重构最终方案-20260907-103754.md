## 一、改前 / 改后（用户视角）

**改前**：`RoI`(词目)↔`ShapeParameters`(类)名实脱节；"区域/图形/几何/订阅"词义纠缠；订阅三件套（`FixedRoi/ComputedRoi/ParameterSource`）是 tools 层零使用的死代码却占据模型主体；执行域反向依赖 UI 层；词目 `Arc` 半死（无中文名、无过滤消费）。

**改后**：
- **四个词职责唯一**：`ROI`=几何输入/图形定义（词目+`RoiInput` 类）；`Geometry`=纯几何值（SDK）；`Region`=算法像素区域（永不进契约）；`ShapeType`=形状类型标签。
- 一个几何输入单模型 `RoiInput`（本地 `RoiShape` + 可空订阅绑定），替代 `RoiData/ShapeParameters/FixedRoi/ComputedRoi` 四类。
- 订阅统一 `ParamSetting` 契约路径（SSOT `OutputVariableResolver` 解析），整对象/按图形参数只是路径深度差异。
- 执行域不再依赖 UI 层（依赖倒挂消除）。

## 二、为什么推翻初版（盘点纠偏，全库只读 2026-09-07）

| 历史裁决 | 当前代码实际 | 影响 |
|---|---|---|
| `07-16`："RoI 彻底移出契约" | 词表 `RoI` 与 6 几何词目**并存**且 RoI 是 9 文件依赖主力（`SdkTypeVocabulary.cs:36-43`） | 初版"RoI 退契约"前提错误 |
| `07-16` E1："InspectionGeometries 输出裸 SDK 几何" | `ToolResults.cs:322,329` 类型仍 `ShapeParameters[]`，下游四级绑定依赖容器形态 | 契约外发必须保留容器语义 |
| 裸几何词目=通用契约值 | 仅 CircleDetect/LineDetect/EdgeDetect 三工具真实裸输出；RotatedRect/Polygon/Annulus 零裸输出、100% 内嵌容器 | 裸几何只覆盖"算法拟合结果" |
| `FixedRoi/ComputedRoi` 成熟可用 | tools 层 **0 使用**，仅 SDK UI + HalAdapter 内部演示 | 推翻零风险 |

**结论**：治理方向 = 保留容器契约语义 + 统一 Roi 词根命名 + 清除订阅死代码 + 修复依赖倒挂与半死词目，而非"RoI 退契约/外发裸几何"。

## 三、四概念定稿（各归其位）

| 概念 | 唯一职责 | 载体 | 进契约 | 词目 |
|---|---|---|---|---|
| **Roi / ROI** | 几何输入/图形定义（可绘制、可订阅、含值+样式） | `RoiInput`/`RoiShape`/`RoiInputCollection` | ✅ | `ROI` |
| **Geometry** | 纯几何值（算法拟合产物、几何运算载荷） | `Models/Geometry/*` | ✅ | `Circle/Line/Arc/RotatedRect/Polygon/Annulus/Point` |
| **Region** | 算法像素区域（iconic、掩码/连通域、引擎态） | `IVisionRegion` + `HalRegion`/`CvVisionRegionAdapter` | ❌ 永不 | 无 |
| **ShapeType** | 形状类型标签（绘制/序列化/绑定 `[Type=X]`） | `ShapeType` 枚举 | 绑定路径标签 | 非词目 |

> 一句话：**Roi = 输入项/图形，Geometry = 值，Region = 像素，ShapeType = 标签。**

## 四、目标架构

```
┌──────────────────────────────────────────────────────┐
│ SDK 框架层（Execution 域）— 引擎无关、被 UI 依赖        │
│  RoiInput（本地 RoiShape? + Binding: ParamSetting?）   │
│  RoiShape（SDK 几何值 + 样式 + 编辑桥 + ShapeType）     │
│  RoiInputCollection（角色集合）                        │
│  RoiParameters（工具参数基座，保留）                   │
│  ParamSetting + OutputVariableResolver（订阅 SSOT）    │
└──────────────────────────────────────────────────────┘
  依赖 ↓ 单向                        依赖 ↓ 单向
┌──────────────────────┐  ┌──────────────────────────┐
│ UI 层（Controls.Roi） │  │ HalAdapter / CvAdapter   │
│ RoiEditor/ParamBinding│  │ RoiShape→Region/CvRegion │
│ 绘制交互/绑定树        │  │ 引擎栅格化/桥接           │
└──────────────────────┘  └──────────────────────────┘
```

### RoiInput 单模型

```csharp
// Execution/Parameters/RoiInput.cs（吸收 RoiData 的几何输入职责）
public class RoiInput
{
    Guid Id; string Name;
    bool IsEnabled / IsVisible / IsEditable;
    RoiShape? LocalGeometry;      // 本地绘制几何（null=无本地）
    ParamSetting? Binding;        // 订阅（null=本地）
}
```

- 绘制 = `LocalGeometry` 非空；订阅整对象 = `Binding.SourceProperty="输出名"`；订阅图形参数 = 同 `Binding` 指向字段级契约路径（`输出[Type=X].Geometry.Radius`）。
- 点卡尺（仅订阅）：`LocalGeometry` 恒 null，只配 `Binding`。

## 六、序列化迁移（一次性，rule-015）

`RoiInput` 自定义读取按旧 `RoiData` 结构分流：

| 旧结构（RoiData.Parameters $type） | 迁移目标 |
|---|---|
| `$type:"Shape"` | `LocalGeometry = RoiShape(...)`，`Binding=null` |
| `$type:"Fixed"` | `LocalGeometry=null`，`Binding = ParamSetting.CreateBinding(输出路径)` |
| `$type:"Computed"` | 逐参数字典折叠为字段级绑定路径；不可折叠**显式抛错** |
| 词目 `RoI` | 迁移到 `ROI`（词目规范化） |

- 不双写旧类型；`$geom` 几何序列化沿用 `GeometryJsonConverter`。
- tools 无 Fixed/Computed 存量数据；ShapeMatch 的 ShapeParameters 方案 JSON 需样本回归。
