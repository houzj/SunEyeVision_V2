# 订阅链路单模型重构方案（GeometryInput）

> 日期：2026-09-07
> 类型：方案设计（架构重构）
> 状态：评审稿（待用户确认后移交「方案实施」）
> 关联 plan：平台订阅链路打通与几何测量工具集（本方案为 P1 前置重构）

## 〇、执行摘要

废弃历史遗留的"ROI 词根三叉戟"模型（`ShapeParameters` / `FixedRoi` / `ComputedRoi`）与重复绑定模型（`ParameterSource` 三件套），重构为 **`GeometryInput` 单模型**：每个几何输入（检测区/屏蔽区/测量工具双卡尺几何）= 本地几何定义 + 可空订阅绑定，语义与既有 `ParamValue<T>` 同构，订阅统一走 `ParamSetting` 契约路径，由 `OutputVariableResolver` SSOT 解析。

全量迁移含旧方案 JSON（提供迁移器无损转换），执行域不再 `using` UI 层（修复依赖倒挂）。

---

## 一、改前 / 改后 / 依据（用户视角，大白话）

### 改前

1. **一个"几何输入"要记住三种完全不同的东西**：用户亲手画的（`ShapeParameters`）、整块订阅上游某个输出的（`FixedRoi`）、逐个参数绑上游数值拼出来的（`ComputedRoi`）。
2. 订阅读起来混乱：`FixedRoi` 名字像"固定区域"，其实是"订阅上游"；`ComputedRoi` 名字像"自动计算"，其实是"每个参数单独绑定"。
3. 平台有两套重复的"绑定"实现：主流参数用的 `ParamSetting`，和区域订阅单独造的 `ParameterSource`（几乎一样的东西）。
4. 这些类型埋在"UI 控件"目录里，却被算法适配层、执行解析器反过来引用，分层颠倒。
5. 订阅面板里硬编码的类型词目 `"Region"` 在官方词表里根本不存在，绑定树按它过滤必然显示不出候选源。

### 改后

1. 工具的每个几何输入统一是一个 **`GeometryInput`**：要么本地放着一段几何（绘制/几何定义 `GeometryDefinition`），要么绑定一个上游来源（`Binding`），两者可空其一。和工具参数 `ParamValue<T>` 的"常量/绑定"双态是同一个思路，概念一致。
2. 订阅整对象 vs 订阅图形参数，**不再是两种类型**，只是绑定路径写多深：绑 `节点.输出` 是整对象；绑 `节点.输出[Type=Circle].Geometry.Radius` 就是图形参数。
3. 全平台只剩一套绑定实现：`ParamSetting` + `OutputVariableResolver`（与 Condition/Script 同一寻址器）。
4. 执行域干净：适配层/解析器引用的是 Execution 域的模型，不再反向依赖 UI 控件目录。
5. 旧方案文件（含已存的 `Shape/Fixed/Computed` 记录）由迁移器自动转成新模型，用户无感。

### 依据

- Microsoft .NET `System.Text.Json` 多态序列化的迁移惯例：自定义 discriminator 可读旧 `$type`、按版本迁移。
  - [MSDN · Polymorphism in System.Text.Json](https://learn.microsoft.com/zh-cn/dotnet/standard/serialization/system-text-json/polymorphism)
  - [MSDN · JsonPolymorphicAttribute.TypeDiscriminatorPropertyName](https://learn.microsoft.com/zh-cn/dotnet/api/system.text.json.serialization.jsonpolymorphicattribute.typediscriminatorpropertyname)
- HALCON：Iconic 数据（Region/Image）是算法引擎态，不进入流程语义契约 —— 与本平台词表注释一致，重构不破坏该原则。
- Cognex VisionPro：可绘制/可订阅的工具输入几何统一为 ICogShape 形状族，非"三分类型"。
- VisionMaster：工具输入=数据源/上游直连，区域为输入槽，无"绘制/固定/计算"三种继承类型。

## 二、问题分析（调研取证）

### 2.1 历史遗留模型全貌

`RoiData`（容器）持有 `RoiDefinition`（抽象，`$type` 多态）三种实现：

```csharp

[JsonDerivedType(typeof(ShapeParameters), "Shape")]
[JsonDerivedType(typeof(FixedRoi), "Fixed")]
[JsonDerivedType(typeof(ComputedRoi), "Computed")]
public abstract class RoiDefinition : ObservableObject
```

| 类 | 实际职责 | 命名误导点 |
|---|---|---|
| `ShapeParameters` | 用户绘制几何（`Geometry` 属性 + 样式 + 扁平编辑桥） | 叫 "Parameters" 与工具参数混淆 |
| `FixedRoi` | 订阅上游**整对象输出**（`SourceNodeId/OutputName/RegionIndex`） | "Fixed" 不表达订阅；"Roi" 不表达任意对象 |
| `ComputedRoi` | 按参数名逐项绑定的字典（`ParameterBindings`） | "Computed" 不表达逐参数绑定 |

来源：`RoiDefinition.cs:52,571,604`

### 2.2 两套绑定模型重复（同一语义双实现）

- Execution 域正统：`ParamSetting`（`ParamSetting.cs:32`）—— `ParameterName/BindingType/ConstantValue/SourceNodeId/SourceProperty/...`
- UI 层重复：`ParameterSource` 抽象 + `ConstantSource`/`NodeOutputSource`（`ParameterSource.cs:15,41,75`）——字段 `NodeId/OutputName/Index/PropertyPath` 与 `ParamSetting` 同构。

`OutputVariableResolver`（SSOT 契约寻址，rule-015）已是平台解析口径，`NodeOutputSource.GetValue()` 的反射实现被其取代。

### 2.3 依赖倒挂（执行域反向依赖 UI 层）

`UI.Controls.Roi.Models` 命名空间内模型被执行层消费：

即 `Execution` 与 `HalAdapter` 依赖 `UI.Controls.Roi`。订阅/几何模型应属执行域，UI 只做消费。

### 2.4 词目污染

`"Region"` 非词表词目（`SdkTypeVocabulary.cs:87-109` 无 Region；仅保留 `"RoI"=typeof(ShapeParameters[])`）。词表注释明示 Region 属引擎态禁止进契约（`SdkTypeVocabulary.cs:19-20`）。

## 三、Bug 模式分析（真因 / 同类潜伏 / 治本点）

**当前问题**：命名与模型不承载真实语义，且分层倒挂，导致订阅链路无法被工具真实使用（tools 层 Fixed/Computed 零使用）。

**真因分类**：设计缺陷 —— 早期"区域编辑器"阶段把**执行域订阅**建模成 **UI 区域类型的子类**，且 UI 控件库先于执行域成熟，执行域被迫反向依赖。

**同类潜伏点**：
- `RoiCollectionParameter` 自持一套 `BindingConfig` 与集合常量值（`RoiCollectionParameter.cs:103`），与 `RoiData` 内逐元素订阅又叠一层（两层订阅语义并存）。
- `ShapeParameters` 三重身份（UI 绘制/契约 RoI 词目/[Type=X] 过滤载体），`SdkTypeVocabulary.cs:36,95` 与 `OutputVariableResolver.cs:159-175` 均以具体类名耦合。

**治本点**：重构"值 + 来源"单模型并归位 Execution 域，而不是继续给旧类型改名。

## 六、目标架构与命名映射

### 6.1 概念模型

```
GeometryInput（几何输入项，原 RoiData 的几何角色）
 ├─ Id / Name / IsEnabled / IsVisible / IsEditable / Tag
 ├─ LocalGeometry: GeometryDefinition?     本地几何（绘制或几何定义；可为 null）
 ├─ Binding: ParamSetting?                 订阅来源（null=本地）
 └─ ShapeType（声明类型，Binding 模式下表达期望图形类型；绘制模式由几何推导）

GeometryDefinition（本地几何定义，原 ShapeParameters 的值+样式部分）
 ├─ Geometry: object?（Circle2d/Line2d/Arc2d/Polygon2d/Rect/...）
 ├─ FillColorArgb / StrokeColorArgb / StrokeThickness / Opacity
 ├─ ShapeType（推导）
 └─ 扁平编辑桥（CenterX/Y/R/W/Rect/StartX/Y/EndX/Y/Angle/Points）与 GetMonitorFields

GeometryInputCollection（原 RoiCollectionParameter）
 ├─ Mode（InspectionRegion / MaskRegion，即"检测区/屏蔽区"角色）
 └─ Items: ObservableCollection<GeometryInput>
```

命名对齐 `ParamValue<T>`：值（`Value` ↔ `LocalGeometry`）+ 来源（`BindingConfig` ↔ `Binding`）分离。

### 6.2 旧→新映射总表

| 旧 | 新 | 处置 |
|---|---|---|
| `RoiData`（容器） | `GeometryInput` | 重构并迁 `Execution/Parameters` |
| `ShapeParameters` | `GeometryDefinition` | 剥离 UI 样式属性并入，保留 `IMonitorable` 能力 |
| `FixedRoi` | —（删除） | 语义并入 `GeometryInput.Binding`（`SourceProperty="输出名"`） |
| `ComputedRoi` | —（删除） | 语义并入同一 `Binding`（字段级路径），无独立类型 |
| `RoiDefinition`（抽象基类） | —（删除） | 多态继承树拆除 |
| `ParameterSource` 三件套 | —（删除） | 统一复用 `ParamSetting` |
| `RoiCollectionParameter` | `GeometryInputCollection` | 角色由 Mode 保留 |
| `RoiType`（Inspection/Mask） | 角色概念由 `GeometryInputCollection.Mode` 表达 | 收敛 |
| `RoiSourceMode`/`RoiSubscribeSubMode` | 仅 UI 交互态，不落模型 | UI 层概念 |
| `IParameterContext` | 保留（好抽象） | 迁 Execution 域 |
| `NodeResultsParameterContext` | 保留（名准确） | 注释去掉 Fixed/Computed 挂靠 |
| `RoiResolver` | 演进为几何解析器 | 迁 Execution 域 |
| `ResolvedRegion` | 演进为几何值载体 | 见 §6.3 |

### 6.3 引擎无关几何载体

`RoiResolver`/`ResolvedRegion` 保留"引擎无关解析"价值，迁入 `Execution/Geometry/`。解析结果按需：
- 构建为引擎像素区域（HalAdapter/CvAdapter 对等实现，各自消费 `GeometryDefinition.Geometry` 的 SDK 几何值）
- 供测量工具纯几何测量直接使用 SDK 几何类型，零引擎依赖。

> 与既有决策一致：`ToolRegionHelper`（Halcon）与 `CvAdapter` 对等提供"几何→区域"转换；SDK 不碰任何引擎类型。

## 七、契约词目决策（评审点 D1）

### 7.1 现状

词目 `"RoI" = typeof(ShapeParameters[])`，中文"图形定义"（`SdkTypeVocabulary.cs:36,95,118`）。

### 7.2 视觉软件对标结论

- VisionPro：工具可绘制/可订阅输入几何 = **Shape 形状族**（ICogShape），ROI 为绘制交互概念。
- Halcon：ROI 为交互绘制概念；Iconic Region 属引擎数据。
- 结论：本平台 `ShapeParameters[]` 的契约语义是"**一组可绘制/可订阅的图形（形状）定义**"，非"引擎区域"。

### 7.3 推荐词目

| 词目 | 映射 CLR 类型 | 中文名 | 理由 |
|---|---|---|---|
| `Shape`（推荐） | `GeometryDefinition[]` | 图形 | 与既有 `ShapeType`、绑定语法 `[Type=Circle]` 词根一致；对齐 VisionPro Shape 族语义；避免 "Region"（引擎态）/ "Geometry"（过于泛数学） |
| 备选 A：`Geometry` | 同上 | 几何 | 简洁但偏数学，与"检测区/屏蔽区"操作语义稍远 |
| 备选 B：保留 `RoI` | 同上 | 图形定义 | 零迁移，但与视觉业界拼写/语义不一致（用户已否决） |

> 词目 `[Type=Circle]` 路径与 `ShapeType` 枚举不变；词目迁移仅影响词表映射 + 历史 JSON 中 VariableType 字段的迁移器转换。

## 八、序列化迁移设计（评审点 D2）

### 8.1 新序列化形态

- `GeometryInput`：`LocalGeometry`（内嵌 `GeometryDefinition` 扁平 JSON，几何仍走既有 `GeometryJsonConverter`）+ `Binding`（`ParamSetting` 既有序列化，无需多态）。
- 移除 `RoiDefinition` 的 `$type` 多态（Shape/Fixed/Computed 全部不再存在）。

### 8.2 迁移器（加载路径）

`JsonConverter<GeometryInput>`（自定义 Read）按旧 JSON 结构分流：

| 旧结构（RoiData.Parameters） | 迁移目标 |
|---|---|
| `$type:"Shape"` | `LocalGeometry = GeometryDefinition(...)`，`Binding=null` |
| `$type:"Fixed"` | `LocalGeometry=null`，`Binding = ParamSetting.CreateBinding(outputName路径)` |
| `$type:"Computed"` | 逐参数字典折叠为字段级绑定路径（同名参数无法折叠为单一路径时按 rule-015 **显式报错**，不静默丢参数） |

- 旧词目 `"RoI"` → `"Shape"`（VariableType 字段）。
- 新旧结构并存期：仅自定义反序列化器按旧结构识别，**不保留**旧类型（一次性迁移，不双写）。
- 规则：迁移器对未知 `$type` / 无法映射绑定一律抛 `NotSupportedException`（rule-015 零静默回退）。

### 8.3 范围确认

- `RoiData`/`RoiCollectionParameter` 在 SDK 与工具的序列化路径统一走迁移器。
- tools 层现无 `FixedRoi/ComputedRoi` 数据（已证 0 使用），存量 JSON 影响极小；ShapeMatch 使用 ShapeParameters 的数据需迁移（Shape→GeometryDefinition）。
- 需要一份**历史 JSON 样本回归清单**（单元测试覆盖：构造三种旧 $type JSON → 新模型 → 回写 JSON → 再读一致）。
