## 0. 用户功能性视角（必读）

### 改前用户看到什么
- 检测区"绘制模式"画好的区域，切到"订阅模式"运行后，**结果层同时显示绘制区 + 绑定区**（双画）；
- 订阅配置好，**关掉调试窗再打开就丢/空白**；
- 切回绘制时本地几何**时有时无**，行为不稳定；
- 表现上分不清是"显示残留"还是"数据被清了"，因为**同一区域对象上同时挂"本地几何"和"订阅引用"两套真相**；
- ROI（检测区域）的**下钻字段**在参数绑定时看不到——比如下游一个 `double` 参数（宽度/中心X）想绑到上游检测区域的 `[0].Geometry.Width`，下拉里根本看不到检测区域。

### 改后用户看到什么
- 检测区/屏蔽区**一组区域只有一个来源**：要么整组"我自己画的"，要么整组"订阅上游的"；
- 订阅模式下运行，结果层**只显示订阅源解析出的区域**；切回绘制，只显示本地区域——两个方向干净、可预期；
- 关窗重开、直接跑流程、切换模式，三种路径行为一致（来源是参数，不再靠 UI 临时状态猜）；
- 绑定任意标量参数时，能看到上游 ROI 按**形状类型分组 → 字段**两级下钻，选中的字段类型与参数匹配才可绑。

### 解决了哪些功能性问题
1. 订阅模式下结果层不再混显本地几何（根治双画）
2. 本地几何与订阅引用不再共存 → 还原/回退/修正矩阵错位全部消除
3. 模式状态持久化 → 关闭重开不丢、运行/显示/交互三层语义一致
4. ROI 复合数据源可达字段过滤 → 下钻字段设计期可见、类型可校验、错误挡在设计阶段
5. 为后续工具（ShapeMatch/Threshold…）提供同一套可复用的区域来源模型

### 依据（参考了什么成熟做法/文档）
| 决策 | 依据 | 引用 |
|------|------|------|
| 区域的"来源"应作为工具参数的一级选项（本地 vs 继承/链接上游） | 海康 VisionMaster：Blob 分析的 ROI 可"继承 / 按矩形区域 / 区域链接（上游匹配框）"，来源是独立参数项 | https://blog.csdn.net/qq_44082700/article/details/141362615 |
| 每个工具用一个 Region Tab 声明输入区域形态与来源 | Cognex VisionPro：工具均有 Region 页，`None=Use entire image` 或由数据流提供 | https://docs.cognex.com/vpromx_1000 → region-tab |
| 区域数据对象与"从哪来"分离：数据流决定来源，参数只声明本地值或引用 | MVTec HALCON/HDevelop：Region 是纯数据对象，流程中由数据流连线决定取值 | https://www.cnblogs.com/ksjqsj/p/17333205.html |
| 拒绝"同一对象双真相"：本地几何与引用互斥存储 | 一般参数建模原则（Option 类型 / SourceMode），避免 if-else 二义 | 见 §3 业界对标 |

## 1. 问题分析

### 1.1 "双画 / 还原错乱 / 丢状态" 同源：区域来源与几何身份耦合

| 现象 | 机制 | 证据 |
|------|------|------|
| 同区域对象上，本地几何与数据来源共存 | `Roi` 同时承载 `LocalGeometry`、`Binding`、`ParameterBindings` 三个互斥真相 | [来源] `src/Plugin.SDK/Execution/Parameters/RoiInput.cs:26-33`（三个私有字段并存）；三态由非空推导 [来源] `RoiInput.cs:127-137` |
| 运行时裁决靠 if 优先级 | `ResolveRuntime` 一串 if 决定取哪个 | [来源] `RoiInput.cs:220-248` |
| 为"切回绘制可还原"刻意保留双真相 | 订阅/拼装写入时**不清空 LocalGeometry** | [来源] `src/Plugin.SDK/UI/Controls/Roi/ViewModels/RoiEditorViewModel.cs:563-565` |
| 结果层/算法层识别不了"组处于订阅态" | 遍历全部 enabled Roi，各自解析各自画 | [来源] `src/UI/Services/Workflow/NodeResultManager.cs:422-453`；`src/SunEyeVision.HalAdapter/ToolRegionHelper.cs:47-100, 462-481`；`src/SunEyeVision.HalAdapter/HalconRegionPipeline.cs:77-98` |
| 结果层每次运行整体替换 | 不会残留旧列表，双画来自"多颗 Roi 并存" | [来源] `NodeResultManager.cs:152-157`（`SetRegionItems` 整体替换） |
| 模式是 UI 内存态，参数无对应字段 | `CurrentMode` 仅 ViewModel 属性；反向猜模式 | [来源] `RoiEditorViewModel.cs:116-138`（CurrentMode）、`:498-518`（`RestoreEditorModeFromRois` 反向推导）、`:143-168`（`RevertSubscribedRoisToLocal` 逐颗清） |

### 1.2 "ROI 下钻属性绑定不可见"：单词汇数据源 vs 复合 ROI 容器

| 机制 | 证据 |
|------|------|
| 每个数据源只有一个类型标签 | [来源] `src/Plugin.SDK/Execution/Parameters/AvailableDataSource.cs:88-94`（单词汇 `PropertyType`/`VariableType`） |
| ROI 注册为单一词目 "ROI" | [来源] `src/Plugin.SDK/Models/SdkTypeVocabulary.cs:38`（`RoiShape[]` → "ROI"） |
| 过滤按**容器词汇**裁决，不按"内部叶子词汇" | [来源] `src/Plugin.SDK/UI/Controls/ParamBindingBase.cs:243-286` |
| 规则 3.5 只在目标为几何词目时放行 ROI 容器 | [来源] `ParamBindingBase.cs:280`：`if (dsVarType=="ROI" && GeometryVocabularies.Contains(targetVarType))` —— 目标 double/int 时 ROI 容器被滤掉，下钻不可达 |
| 字段叶子只能由运行值反射物化 | [来源] `src/Plugin.SDK/Execution/Parameters/ArrayTreeFormatter.cs:198-224`（`BuildRoiBindingChildren` 需真实 `RoiShape[]`）、`:275-336`（`BuildGeometryAttributeLeaves` 用反射 + 真实几何取值） |
| 设计期只有"整体 + [Type=X] 分组"，无字段叶子 | [来源] `ArrayTreeFormatter.cs:236-267`（`BuildRoiDesignTimeGroups`） |

**矛盾本质**：ROI 容器内部叶子**横跨多种词汇**（`double` 数值字段、`Circle` 整体、`Point`…），而过滤模型用"容器单词汇是否等于目标词汇"来裁决——把复合容器当叶子过滤，必然整棵砍掉或整棵放行，表达不了"盒子里有什么"。

### 1.3 绑定存在两级、语义错位

## 2. Bug 模式分析

### 当前 bug（症状）
1. 订阅模式运行 → 结果层同时显示本地绘制区域与订阅绑定区域；
2. 模式切换后还原/回退错乱、状态不持久；
3. ROI 下钻字段在标量（double）参数绑定时不可见。

### 真因分类
**设计缺陷**（架构上注定），非契约漏洞、非实现偏差、非"规则参数没调对"。

### 同类潜伏点
| # | 位置 | 描述 | 修复优先级 |
|---|------|------|:---------:|
| 1 | `NodeResultManager.cs:422-453` | 结果层遍历全量 Roi、无来源过滤 → 双画 | P0 |
| 2 | `ToolRegionHelper.cs:47-100, 462-481` | 算法层同 pattern → 处理区错 | P0 |
| 3 | `RoiEditorViewModel.cs:143/498` | Revert/Restore 靠推导补模式 → 状态易失 | P1 |
| 4 | `ParameterPanelViewModel.cs:161` | `LoadFromRoi` 按 Roi 三态回显 → 面板错乱 | P1 |
| 5 | `RoiInput.cs:220` | `ResolveRuntime` if 三态裁决 → 每个新消费方复制优先级 | P2（本次重构消除） |
| 6 | `ParamBindingBase.cs:280` | ROI 容器按"单词汇是否等于目标"裁决 → 下钻字段不可达 | P0 |
| 7 | `ArrayTreeFormatter.cs:236-267` | 设计期无声明式字段 Schema → 下钻叶子依赖运行值 | P1 |

### 治本点
修复 **"区域来源与几何身份耦合 + 模式无单一事实源 + 数据源单词汇表达不了复合 ROI"** 三个设计缺陷，而非"结果层加过滤 / 规则加特例"。

### 证据缺失警告
无；7 个潜伏点均有真实代码定位。

## 4. 方案对比

| 维度 | A 现状修补 | B（推荐）组级来源 + 复合数据源 | C 激进（ROI 仅运行时数据） |
|------|-----------|------------------------------|--------------------------|
| 实现方式 | 在结果层/执行层对订阅组过滤掉本地 Roi | `InspectionRois`/`MaskRois` 组带 `SourceMode(Local/Subscribe/Compose)` + 唯一 payload；Roi 仅存几何；模式落参数字段；数据源支持复合可达词汇+声明式字段 Schema | 区域仅作为执行期数据对象，由流程连线决定来源 |
| 与架构一致性 | 否（继续复制裁决） | 是（参数即声明、单一出口，符合现有 ParamValue 体系） | 否（推翻参数树输入模型） |
| 复杂度 | 小 | 中 | 大 |
| 维护成本 | 高（每消费方记住过滤） | 低（只有一组概念） | 低但 UI 重做 |
| 扩展性 | 弱 | 强 | 过拟合 |
| 6 个月 ROI | 低 | 高 | 中 |
| 1 年 ROI | 低 | 高 | 中 |
| 3 年 ROI | 低 | 高 | 中 |

### 推荐方案与理由
- **推荐**：方案 B（组级来源 + 复合数据源），Blob 试点、不做向后兼容
- **理由**：
  - 消除"本地+订阅共存"、"模式无字段"、"单词汇表达不了复合 ROI"三个根因；
  - 改动集中在 SDK 参数/数据源模型 + Blob 调试窗 + 统一解析出口，范围可控；
  - 用户已确认不需要向后兼容 → 可干净删除 `Revert/Restore/Roi.Binding` 逐颗补丁；
  - 与业界（VisionMaster 区域链接、VisionPro Region Tab/静态 Schema）一致。

## 6. 防御机制

### #1 契约测试
- 目的：`ResolveGroup` 本地/订阅/空源三态结果确定；`RoiFieldSchema` 覆盖全部 `ShapeType`；"UI 放行 ⇔ 运行期可解析"一致性（UI 放行的运行期必能解析，不放行的运行期必抛错）
- 落地：SDK 纯函数单元测试（`RoiFieldSchema`、`ResolveGroup`、过滤可达性）
- 验收：切换 Mode 后 `ResolveGroup` 结果只含对应来源几何

### #2 端到端冒烟（Blob 全链路）
- 目的：覆盖"启动→配参→运行→切模式→重开→无源"完整路径
- 落地：手动验收清单（见 §7）
- 验收：订阅运行只显绑定区；切绘制只显本地；关窗重开一致

### #3 Fail-Forward（订阅无上游结果时）
- 目的：绑定源上游未执行时不崩 UI、不让旧画面误导
- 落地：解析失败 → 结果层该组显示空并打 Warning（不保留上一次结果）
- 验收：无上游运行时订阅组区域为空，不显示残留

### #4 选中即校验（下钻叶子）
- 目的：过滤放行后不给人选错的机会
- 落地：叶子选中时校验声明词汇与目标词汇（数值互通才可绑），不匹配禁止选择；运行期类型真不匹配仍抛错（rule-015，无静默回退）
- 验收：非法绑定在设计期被禁止、运行期报错可见

## 9. 风险评估

- **影响范围**：SDK `Roi/RoiCollection/RoiParameters/AvailableDataSource/ParamBindingBase/ArrayTreeFormatter` + Blob + 结果层；因模型在 SDK，波及所有区域工具编译面
- **回退策略**：Git 分支实施；若 Blob 冒烟不过则回退合并
- **兼容性**：不向后兼容（用户已确认）；旧 JSON 中 `Roi.Binding` 反序列化默认丢弃 + Warning
- **同类 pattern 风险**：`RoiEditorManagerControl` 检测/屏蔽两组同时改造，防止只改一组导致不对称；数据源复合改造（#5/#6/#7）与区域模型改造（#2/#3/#4）相互独立，可分批落地

### 遗留确认点
1. 下钻字段 UI 采用"形状类型分组 → 字段"两段式（非逐元素 `[0]` 下钻，因运行前元素个数未知）；
2. 旧 JSON `Roi.Binding` 反序列化默认丢弃 + Warning（不迁移）。
