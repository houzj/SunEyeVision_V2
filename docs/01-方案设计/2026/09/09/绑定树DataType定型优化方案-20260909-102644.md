# 绑定源树 DataType 定型优化方案

> 类型：方案/设计
> 关联模块：Plugin.SDK 参数绑定系统（ParamBinding / Roi 订阅面板）
> 状态：方案已确认，待实施

---

## 0. 用户功能性视角

### 改前用户看到什么

订阅面板绑定下拉（整对象订阅"区域源"/几何参数"中心X"等）的树中，存在**既能展开、点了又直接绑定**的节点：单击"旋转矩形"即绑定整组 `[Type=RotatedRect]`，无法点开下钻字段；同时树里混入大量当前类型下不可绑定的节点（字段灰行 / ROI 整组叶），视觉噪音大。

### 改后用户看到什么

树只保留两种节点，行为一眼可辨：

| 节点 | 形态 | 单击行为 |
|------|------|---------|
| 容器（带 ▸/▾ 箭头） | 有子节点的类型分组 | 只展开/收起，**永不写入绑定** |
| 叶子（无箭头、缩进） | 唯一可绑定的目标 | 单击立即绑定并关闭弹窗 |

**树形由参数 DataType 决定**（词目一次性定型），同一节点在不同目标下只承担一种角色：

```
DataType=RoiShape[]（词目 ROI）         DataType=double（词目 Double）
  检测区图形[]  （容器）                  检测区图形[]  （容器）
   ├─ 整体       （叶·绑全部 []）         └─ ▸ 圆       （容器·展开）
   ├─ 圆         （叶·绑 [Type=Circle]）       ├─ 圆心X  （叶）
   ├─ 旋转矩形   （叶·绑 [Type=RotatedRect]）   ├─ 圆心Y  （叶）
   └─ …                                      └─ 半径   （叶）
```

- 想绑"所有旋转矩形"→ ROI 目标下点"旋转矩形"叶子；
- 想绑"旋转矩形的角度"→ double 目标下展开"旋转矩形"点"角度"叶子；
- 不会再有"点一下莫名绑了整组/展开不了"。

### 依据

| 决策 | 依据 | 引用 |
|------|------|------|
| 容器节点不可选中（Focusable=false）、仅导航 | WPF TreeView 选中模型：`TreeViewItem.IsSelected` 与导航态分离 | https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/controls/treeview |
| 绑定目标 = 有值的数据源叶子 | WPF 数据绑定 Source+Path 须落到可取值成员 | https://learn.microsoft.com/zh-cn/dotnet/framework/wpf/data/data-binding-overview |
| 词目不匹配不进入候选树 | rule-015 报错优先 | src/Plugin.SDK/Models/SdkTypeVocabulary.cs:38-43 |

## 1. 问题分析（含来源）

### 1.1 交互触发链

1. TreeView 单击任一行 → `ParamBinding.OnBindingTreeViewPreviewMouseLeftButtonDown`，若 `IsSelectable && DataSource != null` → `ApplyDataSourceBinding` + 关 Popup + `e.Handled=true`。
   [来源] src/Plugin.SDK/UI/Controls/ParamBinding.cs:493-550
2. 展开/收起仅由行首 ToggleButton 触发，单击文本不展开。
   [来源] src/Plugin.SDK/UI/Themes/Generic.xaml:1621-1684
3. 模板对 `IsSelectable=false` 节点置 `Focusable=false/IsSelected=false`，即"容器"不可选中，但不阻止其被标记可绑。
   [来源] src/Plugin.SDK/UI/Themes/Generic.xaml:1719-1723

### 1.2 节点角色冲突（根源）

树构建允许同一节点"有 children 可展开 + 自身可绑"：

- 设计期类型分组：`IsSelectable=true`（绑整组 `[Type=X]`）且 children 挂字段叶。
  [来源] src/Plugin.SDK/Execution/Parameters/ArrayTreeFormatter.cs:260-306
- 运行期 `[i]` 元素节点：`IsSelectable=true`（绑单元素）且 children 挂几何属性叶。
  [来源] src/Plugin.SDK/Execution/Parameters/ArrayTreeFormatter.cs:213-224

### 1.3 数据未按 DataType 裁形（设计缺陷之二）

`FilterDataSourcesByType` 仅过滤**顶层数据源**；Roi 子树 children 构建后不按控件 `DataType` 决定可见/可绑，导致整对象订阅树混入 double 字段叶、double 参数树混入 ROI 整组叶。

[来源] src/Plugin.SDK/UI/Controls/ParamBindingBase.cs:243-292（仅顶层过滤）、:168-200（children 一次性构建，无 DataType 参与）

### 1.4 字段来源双轨（设计缺陷之三）

| 时机 | 字段叶来源 | 绑定路径 |
|------|-----------|---------|
| 设计期 | `RoiFieldSchema.GetFields(type)` 静态声明 | `[Type=X][0].Geometry.…` |
| 运行期 | 反射元素真实 `Geometry` 字段（`BuildGeometryAttributeLeaves`） | `[i].Geometry.…` |

同一批字段两处描述且路径不一致 → 设计期/运行期树形不一致。

[来源] src/Plugin.SDK/Execution/Parameters/ArrayTreeFormatter.cs:317-356（反射枚举）、:273-303（schema 声明）

## 2. Bug 模式分析

- **当前 bug**：单击"旋转矩形"欲展开却直接绑定整组。
- **真因分类**：设计缺陷（节点同时承载"容器"与"绑定终点"两种互斥角色）。
- **同类潜伏点**：

| # | 位置 | 描述 | 优先级 |
|---|------|------|:---:|
| 1 | ArrayTreeFormatter.cs:260-306 | 设计期类型分组"可绑整组+挂字段 children" | P0 |
| 2 | ArrayTreeFormatter.cs:213-224 | 运行期 `[i]` 元素"可绑单元素+挂几何字段 children" | P0 |
| 3 | ArrayTreeFormatter.cs:187-194 | 运行期类型分组与设计期形态不一致 | P1 |

- **治本点**：树节点角色模型（容器绝不绑、绑定全在叶子）+ 按 DataType 词目定型。

## 4. 方案对比

| 维度 | A：交互层打补丁 | B：角色分离 + DataType 定型（推荐） | C：双击/按钮确认绑定 |
|------|------|------|------|
| 实现方式 | 点文本=展开 + 保留灰叶 | 树构建统一容器/叶子，按 DataType 词目裁形 | 单击高亮、双击/按钮确认 |
| 与架构一致性 | 否（绕开本因） | 是 | 部分 |
| 复杂度 | 小 | 中 | 大 |

**推荐 B**：把"歧义"从架构消灭（有 children 的节点一律不可绑），并顺带根治两模式树型混杂与字段双源。

## 5. 最终设计

### 5.1 规则

1. **容器永不绑定，绑定全在叶子。**
2. **树形 = f(DataType)**：同一节点（如"圆"）由构建后词目剪枝一次性定型为集合叶（ROI）或字段容器（数值），同刻只承担一种角色。
3. 类型枚举：声明式全枚举（`ShapeType` 跳过 None），设计期/运行期结构一致，不因跑图增删层级。
4. 删除逐元素 `[i]` 层级与 `BuildGeometryAttributeLeaves` 反射枚举；字段叶路径统一 `[Type=X][0].Geometry.{schema.Path}`，运行期无该类型即报错（rule-015）。

### 5.2 RoiFieldSchema 定位

**保留并收编为几何可绑字段的唯一事实源**，删除与之重复的运行期反射枚举。精确绑定第 N 个元素走文本手动路径（不在树中铺 `[i]`）。

### 5.3 修改清单

| # | 类型 | 文件 | 核心变更 |
|---|------|------|---------|
| 1 | 修改 | `src/Plugin.SDK/Execution/Parameters/ArrayTreeFormatter.cs` | `BuildRoiDesignTimeGroups` 重构为"双态类型节点+字段叶"声明树；新增词目定型裁剪；删除 `BuildRoiBindingChildren` 的 `[i]` 层与 `BuildGeometryAttributeLeaves`/`AddLeaf` 反射枚举 |
| 2 | 修改 | `src/Plugin.SDK/UI/Controls/ParamBindingBase.cs` | `ApplyArrayDisplay` Roi 分支统一走声明式树；新增 `TrimTreeByTarget(roots, dataType)`：词目裁剪 + 递归强制"有可绑 children → `IsSelectable=false`"；调用链加 DataType 参数 |
| 3 | 修改 | `src/Plugin.SDK/UI/Controls/ParamBinding.cs` | `PreviewMouseLeftButtonDown`/`SelectedItemChanged`：容器（`!IsSelectable && HasChildren`）单击→toggle `IsExpanded` 不绑；叶子才 `ApplyDataSourceBinding`；绑定前防御 guard |
| 4 | 清理 | ArrayTreeFormatter.cs / RoiSubscribePanel.xaml.cs | 移除"默认全展开""字段灰显"hack 注释/逻辑残留 |
| 5 | 不动 | 工具结果类 | 无需改（继承 `ToolResults` 已带 `InspectionGeometries`/`MaskGeometries`） |

### 5.4 防御机制

- **D1 词目定型自检**：裁剪后 Debug.Assert 树中不存在 `IsSelectable && Children.Count>0` 的节点；`DataType` 为 null 仅容器化不裁剪，绝不放行脏树。
- **D2 端到端冒烟**：ROI 模式无字段叶、double 模式无集合叶、容器单击不写 `BindingSource`。
- **D3 Fail-Forward**：重开窗口回显若绑定节点被裁剪（历史错绑），按既有 `BackfillDisplayTextFromSource` 回退原文不空白。

### 5.5 验收标准

| # | 验收项 | 方法 |
|---|-------|------|
| 1 | ROI 模式树 = 整体 + 类型集合叶，无字段/`[i]`，类型叶单击即绑 `[Type=X]` | manual |
| 2 | double 模式树 = 类型容器(展开)→字段叶，字段叶可绑，无集合叶 | manual |
| 3 | 点容器整行只展开/收起，`BindingSource` 不变 | manual |
| 4 | 树内不存在"可绑+可展开"双角色节点 | code review / Debug.Assert |
| 5 | 设计期与运行后树结构一致（不因跑图增删层级） | manual |
| 6 | 全量构建 0 error | 构建验证 |

### 5.6 测试方法

构建验证（slnx 全量）→ 代码合规审查（rule-015 词目、无 hack 残留）→ 端到端手动冒烟（两种订阅模式 + 重开窗口 + 切绘制/订阅回归）→ 其余工具（Blob/ShapeMatch 等 ParamBinding 树）点验回归。

### 5.7 风险评估

- **影响范围**：所有走 `ParamBinding` 的绑定 UI；`DataType=null` 场景仅容器化不裁剪，行为近似现状。
- **兼容性**：删除 `[i]` 树层后既有"绑第 N 个元素"配置路径文本仍受支持，仅树不再引导。
- **回退**：改动集中 3 个 SDK 文件可单独回滚；工具结果类零改动。
