## 1. 审计结论

原主题方向包含正确组件，但装配规则互相矛盾，因此整体设计不合理：

1. SDK `Themes/Generic.xaml` 已合并 `DefaultTheme.xaml`，宿主 `AppResources.xaml` 又显式合并一次 DefaultTheme。
2. ROI、测量和公共工具栏共 7 个 UserControl 在元素级再次合并 Generic；元素资源优先于 Application 资源，导致暗色主题被亮色兜底覆盖。
3. 工具设计器在 `OnInitialized` 才补入 Generic，但部分 UserControl 使用跨字典 `StaticResource`，XAML 解析阶段可能先报资源缺失。
4. 分隔线 Color/Brush 分别使用 `ThemeDividerBrush` 与 `ThemeDividerBrushBrush`，名称不能表达资源类型，工具还直接使用裸字符串。
5. 代码注释同时存在“Generic 内含 DefaultTheme”和“DefaultTheme 已从 Generic 拆出”两种相反说明。

## 2. 最终主题分层

```text
Plugin.SDK
├─ SdkThemeKeys.cs             共享语义 Key 契约
├─ UI/Themes/DefaultTheme.xaml 无宿主/设计器的亮色兜底值
└─ Themes/Generic.xaml         SDK 样式、模板、图标，并合并 DefaultTheme

主程序 Application.Resources
├─ AppResources.xaml
│  └─ 只合并一次 SDK Generic.xaml
└─ ThemeManager
   └─ 将 LightTheme 或 DarkTheme 追加到 MergedDictionaries 末尾

工具与 SDK UserControl
├─ 使用 DynamicResource + SdkThemeKeys/ThemeKeys
├─ 只定义自身转换器和局部样式
└─ 禁止元素级合并 SDK Generic.xaml
```

资源优先级：

```text
Application 末尾 Light/Dark
        ↓ 覆盖
Application 中 SDK Generic → DefaultTheme
        ↓ 提供兜底
SDK 控件 DynamicResource
```

## 3. 设计时策略

1. SDK 程序集通过 `ThemeInfo(ResourceDictionaryLocation.SourceAssembly)` 注册约定路径 `themes/generic.xaml`。
2. Generic 自带 DefaultTheme，Visual Studio 设计器或独立工具开发环境无需主程序即可获得样式和兜底颜色。
3. 每个工具调试根在 XAML 中显式合并 `DesignTimeThemeResourceDictionary`。该字典仅在 Visual Studio/Blend/无 Application 的独立设计宿主中加载 Generic，正常运行时保持为空。这让设计器在解析 XAML 资源时直接获得完整 DefaultTheme，不再依赖基类构造时机或设计器的 `Application.Current`。
4. `DesignTimeThemeLoader` 继续为可被单独打开的 SDK ROI、测量和工具栏控件提供构造期与 `Initialized` 后的兜底装配。
5. 控件根的 Generic 只在设计模式下注入，使整个工具可视树固定使用 SDK DefaultTheme；运行时不会建立该局部作用域，仍由宿主 Light/Dark 主题覆盖。禁止直接在工具 XAML 或运行时 `OnInitialized` 中合入 Generic。
6. `ToolDebugControlBase` 用 DynamicResource 为工具根设置面板背景和主文字色，保证根区域与内部 SDK 控件解析同一套资源，避免外层暗色、内部亮色的拼接界面。
7. UserControl 对 Generic 中的共享样式使用 `DynamicResource`，避免 XAML 解析阶段依赖尚未装配的跨字典 `StaticResource`。
8. 同一 Generic 字典内部允许 `StaticResource` 组合样式，因为定义顺序明确且在同一解析作用域。

## 4. 运行时策略

1. `AppResources.xaml` 只合并 Generic，不重复合并 DefaultTheme。
2. `ThemeManager` 删除旧主题字典后，将新 Light/Dark 字典追加到 Application 合并字典末尾。
3. 所有主题化属性使用 DynamicResource，切换主题时现有控件立即重新解析。
4. ROI 的检测蓝和屏蔽橙属于业务语义色，可保持稳定；面板背景、边框、文字和按钮必须跟随主题。
5. 控件不得在局部资源中引入 DefaultTheme 或 Generic，否则会破坏 Application 主题优先级。

## 5. Key 命名规则

共享 Key 必须表达资源类型：

| 类型 | 规则 | 示例 |
|---|---|---|
| Color | `*Color` | `ThemeDividerColor` |
| SolidColorBrush/Brush | `*Brush` | `ThemeDividerBrush` |
| Style | `*Style` | `SegmentedToggleStyle` |
| Geometry | `*Path` 或 `*Geometry` | `LinkIconPath` |

本轮已将：

- `ThemeDividerBrush`（旧 Color）改为 `ThemeDividerColor`。
- `ThemeDividerBrushBrush`（旧 Brush）改为 `ThemeDividerBrush`。
- SDK、Light、Dark、主 UI 和四个算法工具全部同步更新。

本轮不保留旧 Key 兼容别名，防止新旧名称继续并存。

## 9. 架构守卫

后续提交必须满足：

- 工具和 SDK 控件 XAML 不得直接合并 SDK Generic；工具根只允许声明运行时为空的 `DesignTimeThemeResourceDictionary`，SDK 独立控件由 `DesignTimeThemeLoader` 在设计模式下注入。
- `tools/**/*.xaml` 与 SDK 共享控件不得为 Background、Foreground、BorderBrush、Fill、Stroke 写死 UI 颜色；业务叠加色必须显式使用业务常量或配置模型。
- 工具和 SDK 控件后台代码不得自行识别 DarkTheme，也不得直接向普通 UI 的 Background/Foreground/BorderBrush 写固定 Brush。
- 工具不得直接写共享主题字符串，应使用 `SdkThemeKeys`。
- DefaultTheme、LightTheme、DarkTheme 必须覆盖全部 `SdkThemeKeys`。
- 新增共享 Style 时，使用方优先使用 DynamicResource。
- Color 与 Brush 不得共用同一 Key，也不得使用 `BrushBrush` 命名。
