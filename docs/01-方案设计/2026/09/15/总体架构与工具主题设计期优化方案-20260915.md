## 1. 目标

在不推倒现有视觉算法、工具参数和主界面的前提下，建立稳定的运行边界与插件边界：一次运行拥有独立状态；工具只依赖稳定契约；工具界面在设计器中完整可见；主题在宿主、独立调试和设计器中一致生效。

## 2. 目标分层

```text
UI
  └─ Workflow.Application、Plugin.Infrastructure
       ├─ Workflow 运行计划与调度
       ├─ Plugin.Runtime 执行服务
       ├─ Plugin.SDK 稳定契约
       ├─ Plugin.Wpf 工具控件与主题
       └─ Vision Adapter / DeviceDriver 实现
```

依赖只允许向下。SDK、工具算法不得引用 UI 或 Workflow 内部实现；不得通过反射寻找宿主对象。

## 3. 运行与工作流

### 3.1 单次运行会话

`WorkflowExecutionEngine` 不再在实例字段中保存本次运行状态。每次启动建立 `WorkflowRunSession`：

```text
RunId、ParentRunId、取消与暂停控制、WorkflowContext、变量视图、节点结果、资源作用域、运行状态
```

子程序建立子会话，并链接父会话取消令牌。停止、暂停、UI 状态和异步回调都按 `RunId` 定位。

### 3.2 定义、计划、会话、结果分离

```text
WorkflowDefinition → WorkflowExecutionPlan → WorkflowRunSession → WorkflowRunResult
```

- Definition：用户编辑和持久化的方案。
- Plan：校验后的节点、连接、配置快照和依赖关系。
- Session：本次运行中变化的状态。
- Result：运行结束后可查看的输出与诊断。

### 3.3 唯一执行链

所有入口（工作流、单节点调试、连续运行、子程序）采用同一链路：

```text
配置快照 → 绑定与输入解析 → 位置修正/公共输入准备 → 校验 → 工具执行 → 结果发布与资源交接
```

`AlgorithmNode` 与 `ToolExecutor` 不得重复解析绑定。执行状态与业务判定分离：尺寸超差是 `Success + NG`，取消是 `Cancelled`，不是 `Failed`。

## 4. 工具接口与参数

### 4.1 执行接口

建议工具算法接口：

```csharp
public interface ITool<TParameters, TResult>
    where TParameters : ToolParameters
    where TResult : ToolResults
{
    ValueTask<TResult> ExecuteAsync(
        TParameters parameters,
        ToolExecutionContext context);
}
```

`ToolExecutionContext` 提供 `RunId`、`NodeId`、日志、取消令牌、变量读取器和受控输入读取器。普通工具不直接获得整个上游结果字典。

### 4.2 参数与运行数据分离

`ToolParameters` 只保存用户配置、绑定描述、版本和验证规则。以下运行数据迁出：

- `Context`
- `NodeResults`
- `ResolvedInputImage`
- 子程序执行委托
- 已解析的运行期值

执行前创建配置快照。UI 编辑原始配置，不影响正在运行的快照。

### 4.3 工具描述和展示接口

注册时生成不可变 `ToolDescriptor`：工具标识、参数/结果类型、输入输出契约、能力、执行策略、编辑器工厂和契约版本。

算法接口不再返回或创建 WPF 窗口。编辑和结果展示放在 `Plugin.Wpf`：

```csharp
public interface IToolEditorFactory
{
    FrameworkElement CreateEditor(ToolEditorContext context);
}
```

宿主负责窗口生命周期、节点绑定、调试执行和结果展示。

## 5. SDK、Runtime 与 WPF

### Plugin.SDK

只保留工具、参数、结果、绑定描述、视觉/几何接口、日志/变量接口、控制流接口和状态模型。

### Plugin.Runtime

承载 `ToolExecutor`、参数绑定、输入解析、校验、超时/取消、结果发布和执行资源作用域。

### Plugin.Wpf

承载 `ToolDebugControlBase`、ROI/测量编辑器、参数控件、图像控件、主题和转换器。工具算法不直接依赖这层。

移除 SDK 内通过反射读取 UI 方案和全局变量的路径，改由宿主显式注入变量读取接口。

## 6. 主题与设计期可见性

### 6.1 当前已定位的问题

`MeasureElementsEditorControl` 的构造函数在设计期直接返回，且发生在 `InitializeComponent()` 前。其内部 XAML、工具栏和编辑器因此不会创建，导致点线工具的测量元素区域在设计器中空白。

修正原则：始终先执行 `InitializeComponent()`；设计期仅跳过主图像交互、事件订阅、运行服务和原生资源。

```csharp
InitializeComponent();
if (DesignMode.IsActive(this))
{
    ApplyDesignTimePreview();
    return;
}
InitializeRuntimeBehavior();
```

对同类测量、ROI、脚本和图像交互控件执行同样检查。

### 6.2 三种宿主状态

| 状态 | XAML | 演示数据 | 主图像/工作流服务 |
| --- | --- | --- | --- |
| VS 设计器 | 加载 | 加载 | 不连接 |
| 独立调试 | 加载 | 可选 | 显式注入 |
| 主程序运行 | 加载 | 不使用 | 显式注入 |

布局结构不得依赖 `SetMainImageControl()`、`SetParameters()` 或 `Loaded` 后才形成。

### 6.3 测量工具声明式 Profile

点线工具当前在 `SetMainImageControl()` 后才隐藏元素 1、限制元素 2 为直线。应改为 `MeasureElementsEditorControl` 的依赖属性或 `MeasureElementProfile`。

```xaml
<measure:MeasureElementsEditorControl
    Element1Visible="False"
    Element2AllowedGeometry="Line" />
```

点线、点圆、线线、线圆、圆圆工具因此在设计期和运行期共享同一布局约束。

### 6.4 主题 Token

工具统一通过 `SdkThemeKeys` 使用动态资源：

```xaml
Background="{DynamicResource {x:Static themes:SdkThemeKeys.PanelBackgroundBrush}}"
BorderBrush="{DynamicResource {x:Static themes:SdkThemeKeys.BorderBrush}}"
Foreground="{DynamicResource {x:Static themes:SdkThemeKeys.TextPrimaryBrush}}"
```

禁止工具直接写固定颜色或新增裸字符串主题 Key。主题结构为：

```text
SdkThemeKeys：唯一 Token 声明
DefaultTheme.xaml：设计器/无宿主时的亮色兜底
LightTheme.xaml、DarkTheme.xaml：主程序覆盖同一 Token
Generic.xaml：控件模板，只引用 Token
```

补充布局 Token：面板内边距、分组间距、圆角、输入宽高和标题字体，逐步消除工具中的重复硬编码。

## 7. 视觉、设备与资源

- 输入图像由运行会话拥有；工具仅借用，不释放。
- 工具临时图像由工具释放。
- 成功输出图像交由结果存储管理；替换、关闭方案和运行结束时由结果存储统一释放。
- HALCON/OpenCV 转换必须经明确适配入口，记录复制成本。
- 纯几何工具不强制要求图像；图像仅作为可选显示或标定输入。
- 相机接口补充取消令牌、结构化结果、状态机和有界帧队列；预览与检测使用不同队列策略。

## 8. 插件加载与交付

加载流程：

```text
发现主程序集 → 契约校验 → 建立 LoadContext → 注册 ToolDescriptor/工厂 → 发布工具目录
```

`ToolRegistry` 逐步迁移为宿主持有的 `ToolCatalog`，避免静态全局状态污染测试与独立调试。

采用两目录模型：

```text
tools/<Tool>/bin/：设计器和独立开发的完整输出
dev/Debug/plugins/<Tool>/：运行时最小部署产物
```

部署目录包含工具主程序集、deps.json、调试符号、私有托管/原生依赖和资源；宿主平台依赖由宿主提供。

### 8.1 当前两目录设计障碍（2026-09-15 实测）

`Directory.Build.targets` 为保证 WPF 设计器能按 `TargetPath` 找到工具程序集，将工具项目的
`OutDir/OutputPath/TargetPath` 全部直接指向 `dev/Debug/plugins/<Tool>/`。因此方案中的
“工具完整设计期输出”和“运行期最小部署目录”目前并未物理分离。Script 目录仍可见
`SunEyeVision.Plugin.SDK.dll`、`SunEyeVision.Core.dll`、`System.Text.Json.dll` 等宿主副本；
加载策略会回落宿主，避免类型身份分裂，但这些文件增加体积并掩盖依赖归属。

已加入 `PluginDeploymentInspector`，在插件加载前报告缺失的主程序集/deps 文件和不会被使用的
宿主程序集副本。下一步构建改造应保留一个设计器可解析的完整 `TargetPath`，再由独立部署目标将
经过裁剪的文件复制到 `plugins/<Tool>/`，运行期只扫描后者。

## 9. 迁移顺序

1. 运行正确性：运行会话、父子取消、配置快照、唯一执行链。
2. 设计期与主题：修复设计期控件初始化、测量 Profile、统一 Token。
3. 工具接口：`ToolExecutionContext`、输入读取器、编辑器接口迁移。
4. SDK 边界：拆出 Runtime/Wpf，删除宿主反射。
5. 插件交付：ToolCatalog、两目录构建、仓库外开发包验证。
6. 资源和性能：图像生命周期、缓存、设备队列、UI 职责收敛。

首批试点工具：ImageFilter、PointLineMeasure、Script、Subroutine。它们分别覆盖图像、测量设计期、动态输出和嵌套执行。

## 10. 验收标准

1. 一次运行、子程序和调试运行互不覆盖状态。
2. 运行期间编辑参数只影响下一次执行。
3. 调试与正式运行使用同一执行链，结果一致。
4. 工具算法可在无 UI 的测试宿主中执行。
5. Blob、点线及其他测量工具在设计器中显示完整界面和默认主题。
6. Light/Dark/独立设计器均使用同一套语义 Token。
7. 外部工具可在没有完整主仓库源码的环境中构建、设计期预览和部署。
