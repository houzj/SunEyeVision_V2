# 算法工具结果页数据驱动最终优化方案

- 日期：2026-09-15
- 工作区：`D:\MyWork\SunEyeVision_V2`
- 状态：代码实施完成，待设计时与运行时截图验收
- 范围：算法工具的结果判断、图形显示、文本显示，以及对应的设计期可见性、运行期判断和主题

## 1. 最终结论

所有算法工具按自身能力选择结果页模块；工具一旦声明某个模块，该模块必须统一采用数据驱动：

```text
工具构造 ResultPresentationConfig
        ↓
工具在 XAML 中直接组合 SDK/Plugin.Wpf 的三个模块控件
        ↓
工具使用稳定 Key 解析结果、执行判断和生成显示对象
```

不要求每个算法工具都具备“结果判断、图形显示、文本显示”三个模块。统一的是已声明模块的数据契约、编辑控件、布局规则和主题。每个工具继续决定：

- 有哪些判断、图形和文本项；
- 项目的名称、稳定 Key、分组、顺序、单位和默认值；
- 判断值如何从算法结果取得；
- 整体判断、逐对象判断及其业务联动；
- 实际图形和文字如何绘制到主界面的共享图像空间。

SDK 不出现 `BlobCount`、`FootPoint`、`FitLine2` 等工具业务字段，不通过反射猜测属性，也不拥有算法结果值。

输出图像是工具结果的图像输出，由主界面共享图像空间选择和显示，不属于“图形显示”模块；图形显示专指 ROI、轮廓、点、线、圆等可单独控制样式的叠加对象。

## 2. 当前问题

### 2.1 同一结果页存在多套组织方式

- Blob 使用专用 `BlobAnalysisResultConfig` 和大段静态 XAML。
- 六个几何测量工具使用 `ObservableCollection<MeasureThreshold>`，但图形和文本仍逐项写在各自 XAML 中。
- LineDetect、CircleDetect、ShapeMatch、Threshold、Morphology、ImageFilter、ImageThreshold 等工具各自维护结果页结构。
- 六个几何测量工具此前接入的临时 `MeasureJudgmentEditorControl` 只解决重复判断模板；实施阶段 A 已将其提升为通用 `JudgmentEditorControl`。

### 2.2 静态 XAML 造成重复修改

新增一个 Blob 判断项需要同时修改参数、XAML、Clone、校验和算法。图形与文本项也存在“属性已经声明，但页面忘记增加控件”的风险。

### 2.3 数据驱动页面可能在设计器中变成空壳

设计器不执行主程序的 `SetParameters`、插件加载、图像注入或工作流初始化。集合在运行时才建立，或者参数在 `InitializeComponent` 后才出现时，ItemsControl 只能显示空白。

## 3. 分层与职责

| 层 | 职责 | 禁止事项 |
| --- | --- | --- |
| Plugin.SDK 契约层 | 结果页数据模型、稳定 Key、判断类型、作用域、判断结果模型 | WPF 控件、工具业务字段、反射读取 UI |
| Plugin.Wpf 表现层 | 三个独立模块控件、主题、设计时示例 | 执行算法、解释 Blob/测量业务 |
| 工具参数层 | 构造本工具的判断、图形、文本配置并持久化用户设置 | 等待宿主注入后才创建集合 |
| 工具算法层 | 按 Key 提供值，执行工具专用解析和逐对象遍历 | 依赖 WPF 控件 |
| Plugin.Runtime | 调用通用判断器、聚合结果、发布运行状态 | 修改持久化参数实例 |
| 主 UI | 承载工具编辑器和共享图像空间 | 为每个工具创建独立图像区域 |

当前仓库尚未物理拆出 Plugin.Wpf，公共 WPF 控件可暂放 `src/Plugin.SDK/UI`，物理分层时原样迁移，不改变工具数据契约。

## 4. 数据模型

### 4.1 结果页根模型

```csharp
public sealed class ResultPresentationConfig
{
    public ObservableCollection<JudgmentConfigItem> Judgments { get; } = [];
    public ObservableCollection<GraphicsDisplayItem> Graphics { get; } = [];
    public ObservableCollection<TextDisplayItem> Texts { get; } = [];
}
```

三个集合始终非 null。工具通过在结果 Tab 中直接放置对应公共控件选择模块，并把该控件绑定到对应集合。集合负责数据，XAML 负责明确表达模块组合，不再维护一份重复的 `Modules` 标志。

### 4.2 判断项

```csharp
public sealed class JudgmentConfigItem
{
    public string Key { get; init; } = "";
    public string Name { get; init; } = "";
    public string Group { get; init; } = "";
    public int Order { get; init; }
    public JudgmentRuleKind RuleKind { get; init; }
    public JudgmentScope Scope { get; init; }

    public bool Enabled { get; set; }
    public double Min { get; set; }
    public double Max { get; set; }
    public string Unit { get; init; } = "";
    public int DecimalPlaces { get; init; }
    public double AllowedMinimum { get; init; }
    public double AllowedMaximum { get; init; }
    public bool AffectsItemDisplayState { get; init; }
}
```

```csharp
public enum JudgmentRuleKind
{
    Range,
    Empty,
    Boolean
}

public enum JudgmentScope
{
    Overall,
    PerItem
}
```

`Key` 是序列化、迁移、结果匹配和日志定位的唯一稳定标识；`Name` 只用于显示，可以修改或本地化。

### 4.3 图形与文本项

```csharp
public sealed class GraphicsDisplayItem
{
    public string Key { get; init; } = "";
    public string Name { get; init; } = "";
    public string Group { get; init; } = "";
    public int Order { get; init; }
    public GraphicsStyle Style { get; set; } = new();
}

public sealed class TextDisplayItem
{
    public string Key { get; init; } = "";
    public string Name { get; init; } = "";
    public string Group { get; init; } = "";
    public int Order { get; init; }
    public TextStyle Style { get; set; } = new();
}
```

图形和文本配置只描述用户可编辑的显示状态。实际叠加对象仍由工具结果生成，并绘制到主界面共享图像空间。

### 4.4 运行结果模型

配置与运行结果分离：

```csharp
public sealed record JudgmentOutcome(
    string Key,
    JudgmentScope Scope,
    int? ItemIndex,
    object? ActualValue,
    bool IsPass,
    string Message);
```

`JudgmentOutcome` 属于单次运行结果，禁止写回 `ResultPresentationConfig`。

## 5. 工具如何组织数据

工具在参数构造时建立完整配置。构造过程必须是纯托管、无宿主依赖的同步过程。

### 5.1 PointLine 示例

```csharp
ResultPresentation.Judgments.AddRange(
[
    Range("distance", "距离", "测量判断", 0, 1000, "px", enabled: true),
    Range("foot.x", "垂足X", "测量判断", -100000, 100000, "px"),
    Range("foot.y", "垂足Y", "测量判断", -100000, 100000, "px")
]);

ResultPresentation.Graphics.AddRange(
[
    Graphic("point1", "点1", Point1Style),
    Graphic("guide.line2", "引导线2", GuideLine2Style),
    Graphic("fit.line2", "拟合结果2", FitLine2Style),
    Graphic("foot", "垂足", FootPointStyle)
]);
```

### 5.2 Blob 示例

```csharp
ResultPresentation.Judgments.AddRange(
[
    Empty("output.empty", "输出为空判断", "整体判断"),
    Range("blob.count", "Blob数量", "整体判断", 1, 9999, "个"),
    Range("blob.totalArea", "总面积", "整体判断", 0, 10000000, "px²"),
    Range("blob.area", "每个Blob面积", "逐Blob判断", 0, 10000000, "px²",
        scope: JudgmentScope.PerItem, affectsItemDisplayState: true)
]);
```

Blob 与测量工具使用同一数据结构，但组织不同的项目、分组和作用域。

## 6. SDK/Plugin.Wpf 编辑器

最终提供三个可独立使用的公共控件：

```text
JudgmentEditorControl
GraphicsDisplayEditorControl
TextDisplayEditorControl
```

### 6.1 JudgmentEditorControl

- 按 `Group`、`Order` 显示项目；
- 每项统一显示名称与启用开关；
- `Range` 显示上下限、单位和精度；
- `Empty`、`Boolean` 只显示适用的编辑器；
- `PerItem` 只改变分组提示，不在 SDK 中解释具体对象；
- 运行时关闭的条件编辑器可以折叠，设计时用 `d:Visibility="Visible"` 强制可见。

### 6.2 GraphicsDisplayEditorControl

遍历 `GraphicsDisplayItem`，复用 `DispItemColorControl`。工具决定项目和顺序，SDK 统一行高、标签宽度、开关、颜色、线宽和主题。

### 6.3 TextDisplayEditorControl

遍历 `TextDisplayItem`，复用 `DispTextColorControl`。工具决定文本项目，SDK 统一字体、颜色、位置、格式和数据源入口。

### 6.4 工具直接组合

- 每个公共控件自己包含对应的标准 Expander 和数据驱动内容。
- 工具在结果 Tab 中直接放置实际需要的一个、两个或三个公共控件。
- XAML 打开即可看出工具选择了哪些模块，不经过总控件和可见性转换器二次解释。
- 公共控件不包含图像控件，也不负责执行或绘制结果。

## 7. 运行期判断

### 7.1 禁止反射猜值

工具显式按稳定 Key 提供结果值：

```csharp
double? ResolveOverallValue(string key, PointLineMeasureResults result) => key switch
{
    "distance" => result.Distance,
    "foot.x" => result.FootPoint?.X,
    "foot.y" => result.FootPoint?.Y,
    _ => null
};
```

未知 Key、缺失值或不支持的规则必须返回明确诊断，不能静默跳过。

### 7.2 通用执行器与工具责任

- SDK/Runtime 通用执行器负责 Range、Empty、Boolean 的比较和整体聚合。
- 工具负责把算法结果映射到 Key。
- Blob 负责提供逐 Blob 对象序列；执行器逐项产生带 `ItemIndex` 的结果。
- `AffectsItemDisplayState` 只声明显示联动，Blob 根据逐项 Outcome 决定 OK/NG 颜色。
- 业务 NG 是执行成功后的判断结果，不得转成执行失败。

## 8. 设计时可见性保障

数据驱动必须同时满足以下条件：

1. 参数构造时创建非空集合和默认项目，禁止等到 `Loaded`、`SetParameters` 或图像注入。
2. 参数构造不访问 Halcon 图像、设备、文件、插件管理器、工作流上下文或服务容器。
3. 工具根 XAML 声明可创建的设计时数据：

   ```xml
   d:DataContext="{d:DesignInstance Type=local:ToolParameters,
                                    IsDesignTimeCreatable=True}"
   ```

4. 工具控件在 `InitializeComponent()` 前准备默认 Parameters，避免首次普通绑定得到 null。
5. 所有设计模式提前返回都发生在 `InitializeComponent()` 之后。
6. 条件编辑器增加 `d:Visibility="Visible"`，使关闭状态下的范围控件仍能在设计器检查。
7. 三个公共编辑器提供 SDK 示例 `d:ItemsSource`，确保单独打开公共控件也能检查模板。
8. 公共控件合并 SDK DefaultTheme；工具设计器不依赖主程序主题注入。

设计时只验收参数与结果配置控件。输入图像、ROI、测量引导和结果叠加在运行时使用主界面共享图像空间验收。

## 9. 序列化与配置切换

### 9.1 新格式

只保存用户可编辑状态和稳定 Key。显示名称可以保存，但加载后以当前工具定义为准，避免改名后出现重复项目。

### 9.2 旧配置处理

- 本轮明确不提供旧结果配置的向后兼容与自动迁移。
- 删除工具私有的 `*ResultConfig`、旧属性和双轨执行路径，只保留 `ResultPresentationConfig`。
- 旧工程加载后由用户按新结构重新设置结果判断、图形和文本显示参数并保存。
- 算法输入和几何参数不属于本节删除范围。

### 阶段 E：清理和物理分层

1. 删除所有工具中的三组重复 DataTemplate 和逐项显示 XAML。
2. 删除名称驱动、反射驱动和旧双轨执行路径。

## 11. 自动化验收

### 11.1 结构检查

- 14 个目标工具的结果页只使用三个独立公共模块控件，并且 XAML 直接表达模块组合。
- 工具 XAML 中不存在直接绑定 `Judgments` 的 ItemsControl。
- 工具 XAML 中不存在逐项堆叠的 `DispItemColorControl`、`DispTextColorControl`。
- SDK 契约模型不引用 `System.Windows`。
- SDK 不包含具体工具业务 Key。

### 11.2 模型和序列化

- 所有 Key 在单个工具内唯一且非空。
- 集合构造后非 null。
- Clone/快照为深复制。
- 新格式序列化后稳定 Key、集合内容和用户可编辑值不丢失。
- 运行时 Outcome 不写回参数。

### 11.3 UI 与设计器

- 公共控件独立设计器显示三类示例。
- 每个工具设计器显示真实项目、分组、顺序、单位和默认值。
- 关闭的条件项在设计器仍能检查完整编辑器。
- Light、Dark 和 DefaultTheme 无资源错误。
- 设计器无需主程序、工作流、图像或 `SetParameters`。

### 11.4 运行时

- Blob 的整体和逐项判断结果与迁移前一致。
- 六个测量工具的 OK/NG 与迁移前一致。
- 图形和文本开关、颜色、线宽、字体、位置设置生效。
- 所有叠加只进入主界面共享图像空间。
- 切换工具、主题、缩放和平移后无重复、漂移和残留。
