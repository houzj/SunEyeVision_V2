# 工作流引擎实施计划

日期：2026-09-16  
依据：[全量重构设计](./工作流运行引擎全量重构设计-20260916.md)  
状态：实施中

## 目标

在不改变已验证业务结果的前提下，逐步建立可取消、可复现、可并行且不污染方案设计数据的工作流执行链。

## 里程碑与验收

| 里程碑 | 内容 | 验收标准 | 状态 |
|---|---|---|---|
| M1 | 统一运行请求、会话、取消链路与输入快照 | 停止连续运行可取消当前工具；切图不改写方案节点参数；本轮参数稳定 | 已实施，待人工回归 |
| M2 | 编译完整依赖图 | 普通连线、参数绑定、全局变量绑定均形成依赖；缺失源与环在运行前报错 | 进行中：流程内图已接入；解决方案级全局变量边已接入，待 UI 输入来源接线 |
| M3 | 受控并发调度器 | 默认串行；资源、旧插件和上限约束生效；仅审计工具可并行 | 进行中：全局就绪队列已接入；等待/超时策略待实施 |
| M4 | 工具审计、预热与性能观测 | 首轮预热耗时、节点执行耗时、资源等待可见；纯计算工具逐步放开 | 进行中：执行快照 UI 已接入；预热和等待/超时观测待实施 |
| M5 | 全局变量数据总线与 UI | 单生产者、多订阅者；跨流程自动推导依赖；模块结果与变量管理均可绑定 | 进行中：数据模型、跨流程依赖图、RunAll 运行快照及双入口绑定 UI 已接入；待人工回归与解绑入口 |

## M1 已实施内容

1. 新增 `WorkflowRunRequest`，复制运行参数、全局变量、上下文变量和节点参数覆盖。
2. `WorkflowRunSession` 接受外部取消令牌并建立链接；执行管理器的连续运行停止信号会传到真实执行会话。
3. 图像载入节点的 `FilePath` 改为本轮覆盖值，应用于深拷贝后的执行参数；执行过程不再修改方案节点 `Parameters.FilePath`。
4. 运行参数注入 `WorkflowContext`，供参数绑定解析使用。

## M2 已实施内容

1. 新增 `WorkflowExecutionDependencyGraph`；普通连接和 `ParamSettings` 的动态绑定均会编译为前驱边。
2. 缺失节点、自依赖、不完整动态绑定和依赖环会在实际执行前失败，避免按节点集合偶然顺序运行。
3. 现有串行调度已经改用该依赖图划分拓扑层、检查失败前驱和准备数据源；并发度仍是 1。
4. 执行参数绑定配置改为深拷贝，不再与设计器节点共享 `ParamSettingContainer`。
5. 解决方案级依赖图以 `工作流 ID/节点 ID` 作为作用域节点标识；全局变量的唯一生产者与多个消费者会生成跨流程边。旧方案缺少工作流 ID 时仅在节点 ID 全局唯一时兼容，歧义时拒绝执行。

## M3 已实施内容与已知限制

1. 工具可通过 `IToolExecutionProfileProvider` 在代码中声明 `ParallelSafe`、`ResourceExclusive` 或默认 `WorkflowExclusive`。
2. 调度器会检查资源租约和并发上限；未声明的旧工具保持工作流独占。
3. 调度器使用全局就绪队列：节点只在所有依赖完成且资源租约可得时派发；不会因同一拓扑层的无关等待节点而设置层屏障。等待原因与超时策略尚未纳入节点状态。

## M4 已实施内容

1. 每个工作流持有一个长期 UI 执行快照；切换工作流标签时，主界面状态栏切换到该工作流的快照。
2. 运行开始时清空并激活该快照；执行引擎逐节点发布状态和完成结果，UI 实时更新节点状态及耗时，不参与调度。
3. 状态栏显示当前工作流的运行状态/耗时，点击可打开“执行快照”窗口，查看节点名称、状态、模块耗时和算法耗时。
4. 子程序内部节点通过“子程序节点 / 内部节点”的名称路径列入父工作流快照；本阶段不绘制依赖图或展示原始参数/全局变量。

## M5 已实施内容与已知限制

1. `GlobalVariable` 支持可持久化的 `ProducerBinding`（唯一输入来源）与 `ConsumerBindings`（多个目标参数）；消费者记录已保存 `WorkflowId`。
2. `RunSolutionAsync` 从解决方案初值建立本批次变量快照，生产节点结果写回该快照，后续消费者流程读取更新后的快照；不回写 `Solution.GlobalVariables.Value`，避免污染设计期初值。
3. 主界面“全部流程运行”已改为调用真实 `RunSolutionAsync`，不再使用模拟延时。
4. 全局变量管理器的“输入来源”列只读显示生产者；唯一绑定入口位于模块结果表的真实结果字段，点击“变量管理”链接后选择目标全局变量并写入 `ProducerBinding`。
5. 目标参数管理器已使用 `ThemeKeys` 动态资源；树用于浏览流程/节点/参数，三级复选框管理目标绑定；父节点采用二态整组操作，不显示半选状态。
6. 旧方案只使用变量初值/消费者绑定时保持兼容；消费者比较和节点参数写回优先使用 `WorkflowId + NodeId + ParameterName`，旧方案缺少工作流 ID 时仅在节点 ID 全局唯一时兼容。
7. 模块结果绑定采用 `IsBindable` 与 `ResultBindingInfo`，不再以“是否可展开”决定绑定按钮。ROI 形状类型节点保存 `[Type=ShapeType]` 完整路径与 `ShapeTypeVocabulary` 词汇，图形字段保存同源字段路径；纯目录没有绑定描述，不显示入口。

8. B5 第一批已完成：目标输出差异计算、目标树选中状态、改绑写回和解绑清理均使用带工作流作用域的消费者键；重复节点 ID 的跨工作流绑定不会再被误合并。子程序多次调用的实例路径仍需在后续批次加入稳定键。

## 后续实施约束

1. M2 在只读诊断模式先运行，输出依赖图和错误，不切换调度器。
2. M3 上线时并发上限保持 `1`；只有显式声明 `ParallelSafe` 且资源租约可得的工具才逐步放开。
3. 全局变量 UI 不新增 RunAll 编排面板；输入来源和目标参数的既有流程信息就是编排来源。
4. 每个里程碑必须完成单元测试、UI 编译和对应人工回归后才进入下一里程碑。

## 2026-09-18 参数与绑定方案实施计划

当前按以下顺序实施，前一阶段未通过编译和回归不得进入下一阶段：

1. **B2 目标树生成逻辑**：以工具参数契约全集生成树，`ParamSettings` 只表示已选状态；补充空配置/已有配置集合一致性测试。
2. **B5 绑定一致性**：统一消费者唯一键，处理改绑、删除变量、节点复制和子程序路径，确保输入来源与目标输出只反映同一事实。第一批已完成工作流作用域键；子程序实例路径仍待补齐。
3. **D1-D3 SDK 参数契约**：已增加输入槽位、运行参数描述和校验器；最终契约只接受算法参数的纯 CLR 值，不把 `ParamValue<T>` 作为运行时模型。当前代码中的 `ParamValue<T>` 解包仅是迁移施工痕迹，必须在参数模型迁移阶段删除，不能作为长期兼容能力。
4. **D4-D5 工具契约迁移**：按工具逐个登记契约，收口 UI 自判据和旧排除法；每批做结果树快照对比。Blob 分析、图像二值化、图像滤波和形态学处理已登记输入槽位及主要运行参数；下一步先完成这些工具的纯值参数迁移，再继续其他工具。
5. **C1 参数模型 ADR**：冻结来源表、运行快照和方案格式版本，明确直接迁移边界，不设计旧工具兼容层。
6. **C2/C3 参数模型迁移**：直接拆除 `ParamValue<T>` 在算法参数中的职责；绑定定义、编辑器状态和运行时解析结果分别建模，算法只接收纯值参数。方案格式按当前版本一次性迁移，不增加旧工具兼容层。
7. **N 工具分层**：先拆 `Plugin/Algorithm/ViewModel/Results`，最后评估类型重命名；不新增旧工具兼容适配层。
