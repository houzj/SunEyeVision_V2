# 大批量结果渲染架构基线

日期：2026-09-19  
适用范围：Blob、轮廓、旋转矩形、质心、文本及其他大批量结果图形  
基线状态：作为后续渲染架构优化的唯一设计基线

## 1. 当前问题

当前结果层以单个 WPF `FrameworkElement` 和 `OnRender` 为核心。缩放或平移时，视口变化会触发结果层重新遍历并提交大量轮廓路径。即使已经加入批量 `StreamGeometry`、Tile 查询、视口裁剪、文本缓存和 `BitmapCache`，轮廓显示状态下仍会出现明显卡顿。

根本原因不是单个绘制 API 的效率，而是结果数据、场景编译和视口渲染仍然耦合在同一个结果层重绘路径中。

## 2. 设计原则

1. 保持图像层、结果层、交互层三层分离。
2. 算法工具不依赖 WPF 控件，不负责视口和绘制调度。
3. 完整保留算法结果、`HRegion`、OK/NG 数据和参数绑定。
4. 轮廓、旋转矩形、质心和文本必须支持独立颜色、可见性和清除。
5. 视口变化不重新编译完整结果，只更新变换或查询可见 Tile。
6. 只选中的对象进入交互命中测试，不为每个 Blob 创建 WPF 控件。
7. 输出开关决定是否编译对应结果数据；图形样式只负责绘制样式。

## 3. 目标架构

```text
算法工具
  ↓
+-----------------------------+
| Immutable Algorithm Results  |
| Blob / HRegion / OK / NG     |
+-----------------------------+
  ↓
ResultRenderCompiler（后台）
  ↓
RenderScene
  ├── TileScene(0,0)
  ├── TileScene(0,1)
  ├── TileScene(1,0)
  └── ...
  ↓
ResultTileHost
  ├── TileVisual
  ├── TileVisual
  └── ...
  ↓
WPF 图像显示容器
```

## 4. 各层职责

### 4.1 算法结果层

工具只产生不可变结果数据：

- `BlobResult[]`
- 完整 `BlobRegions`
- `OkBlobRegions` / `NgBlobRegions`
- 旋转矩形数据
- 可选轮廓数据
- 结果状态和统计数据

工具不创建 `DrawingVisual`、`FormattedText` 或 WPF 控件。

### 4.2 渲染编译层

`ResultRenderCompiler` 将结果编译为按图像坐标分区的 `RenderScene`。每个 Tile 按 OK/NG、几何类型和样式分组，并在后台生成冻结几何。

编译过程可取消，旧结果不能回写新场景。

### 4.3 WPF Tile 宿主

`ResultTileHost` 管理可见 Tile：

- 平移：只修改宿主变换矩阵；
- 缩放：查询当前可见 Tile；
- Tile 进入视口：异步加载；
- Tile 离开视口：卸载或保留缓存；
- 样式变化：只刷新受影响 Tile。

不再由单个 `ResultRenderLayer.OnRender()` 全量遍历所有结果。

### 4.4 交互层

交互层仅维护当前选中对象、ROI、卡尺和命中测试。命中流程为：

```text
鼠标位置 → 空间索引 → 当前 Tile 候选 → 精确命中测试
```

## 5. 缩放和平移策略

### 平移

- 不重新生成几何；
- 不重新排版文本；
- 不重新遍历全部轮廓；
- 只改变 `RenderTransform`；
- 视口稳定后再刷新可见 Tile。

### 缩放

根据缩放级别使用不同细节：

- 低倍率：旋转矩形或简化轮廓；
- 正常倍率：完整轮廓；
- 高倍率：当前视口内的完整轮廓和文本。

文本始终保持可见，只绘制当前视口内文本，不使用“交互时隐藏文本”作为优化手段。

## 6. 输出和可见性规则

输出参数决定是否生成结果数据：

- Blob 图像输出；
- 二值化图像输出；
- 轮廓输出。

图形样式只决定：

- 颜色；
- 线宽；
- 透明度；
- 线型；
- 可见性。

矩形或质心隐藏时，几何仍然存在，重新显示只改变样式，不需要重新执行算法。

## 7. 后端演进

第一阶段直接使用 WPF `DrawingVisual` Tile 后端作为唯一结果渲染路径。完成迁移后删除单体 `ResultRenderLayer` 运行时路径。后续如需支持百万级轮廓，再抽象：

```text
IRenderBackend
  ├── WpfDrawingVisualBackend
  └── Direct2DBackend（后续）
```

不更换 Halcon 控件，不把结果合成为单张 Overlay 图作为主显示方案。

## 8. 迁移阶段

### M1：结果数据和样式解耦

- 工具只输出算法结果和输出开关对应的数据；
- 样式可见性由结果层统一判断；
- 禁止“隐藏时不创建图元”。

### M2：RenderScene 和 TileScene

- 定义不可变渲染数据契约；
- 实现后台编译和取消；
- 完成 OK/NG、矩形、轮廓、质心、文本分组。

### M3：ResultTileHost（唯一运行时结果宿主）

- 用多个 `DrawingVisual` Tile 替换并删除单体全量 `OnRender`；
- 平移只更新 Transform；
- 缩放只查询可见 Tile。

### M4：交互空间索引

- Tile 内对象索引；
- 选中对象精确命中；
- 只为选中对象生成交互图形。

### M5：性能和后端评估

- 71905 区域基准；
- 3000、10000、100000 区域基准；
- 连续缩放、平移帧率和响应延迟；
- 评估是否引入 Direct2D 后端。

## 9. 验收标准

1. 71905 区域执行不阻塞 UI。
2. 轮廓显示和隐藏可独立切换。
3. 轮廓、旋转矩形、质心、文本可独立控制。
4. 平移过程中不重新编译完整场景。
5. 缩放过程中只处理可见 Tile。
6. 文本始终可见，且不因交互被隐藏。
7. OK/NG 颜色和清除操作互不影响。
8. 关闭、重开、切换工作流不残留旧 Tile 或旧结果。
9. 算法结果、区域绑定和显示结果保持一致。

## 10. 当前实现与目标架构的关系

当前代码已经具备：

- 批量轮廓；
- OK/NG 分组；
- 后台几何构建；
- 分块和 Tile 查询；
- 视口过滤；
- 文本缓存；
- 可取消构建；
- 输出开关。

这些属于迁移前的现有能力。下一步直接实施 `RenderScene + ResultTileHost` 的唯一运行时路径，并在切换完成后删除单体 `ResultRenderLayer.OnRender()` 全量重绘代码。禁止保留“双路径自动回退”或继续增加新的全量重绘分支。
