# 大规模区域批量渲染优化方案

日期：2026-09-19

## 1. 问题

阈值结果可能包含数万甚至十万级连通区域，例如：

```text
threshold(Image, Region, 128, 255)
区域数量：71905
```

当前结果显示链路把每个区域展开成独立轮廓、矩形、十字和文本，再交给 WPF `DrawingContext`。这会造成轮廓转换、托管对象数量和 UI 绘制时间同时爆炸，最终阻塞界面。

算法结果完整性和结果显示性能必须分离：算法保留完整区域，显示层使用批量渲染。

## 2. 目标

1. 保持现有三层结构：图像层、结果层、交互层。
2. 不更换 Halcon 控件，不把原图和结果合成为不可拆分的图片。
3. 保留全部 `HRegion`、Blob 数值和每个 Blob 的 OK/NG 判定。
4. OK 和 NG 支持独立颜色、线宽、可见性、填充和清除。
5. 结果层不再创建一个区域对应一个 WPF 图形对象。
6. 选中区域、ROI、卡尺和手柄继续由 WPF 交互层绘制。
7. 新结果到达、切换节点或缩放时不能阻塞 UI 线程。

## 3. 最终架构

```text
算法结果层
  完整 HRegion + BlobResult + JudgmentPassed
          │
          ▼
区域显示命令层
  OK RegionBatch / NG RegionBatch
  样式、可见性、显示模式、版本号
          │
          ▼
批量区域渲染器
  按状态、样式和图像 Tile 构造批量 StreamGeometry
  后台线程构造，Freeze 后切换到 UI
          │
          ▼
WPF 结果层
  少量批量几何对象
          │
          ▼
WPF 交互层
  选中区域、ROI、卡尺、手柄和高亮
```

## 4. 区域数据与显示数据分离

算法结果继续保存：

```text
FilteredBlobs     全部 Blob 的数值和判定状态
BlobRegions       全部区域本体
```

结果显示层建立批次：

```text
OK RegionBatch
NG RegionBatch
```

每个批次只保存区域引用和显示样式，不复制成大量 WPF `Point[]`。

颜色修改、隐藏、显示和清除只作用于显示命令，不重新执行算法，也不修改算法结果。

## 5. 批量渲染规则

禁止在 `OnRender` 中逐区域调用 `GenContourRegionXld`，也禁止为每个区域创建 `ContourGeometry`。

新增批量转换器，按批次将区域轮廓直接写入一个或多个 `StreamGeometry`：

```text
OK 区域集合 → OK 批量几何
NG 区域集合 → NG 批量几何
```

每个批量几何可以包含多个闭合轮廓，但不创建每个区域的托管几何对象。

## 6. Tile 与异步更新

结果按图像坐标划分为 Tile。每个 Tile 按 `状态 + 样式` 生成批量几何。

轮廓转换在后台线程执行，完成后冻结几何并回到 UI 线程一次性替换结果层。每次结果带有渲染版本号；旧版本任务完成后不得覆盖新结果。

```text
Run 42 → RenderVersion 42
Run 43 → RenderVersion 43
```

只更新当前视口或当前变化的 Tile，避免每次缩放和平移重建整张结果。

## 7. 精度和交互

缩放级别只影响显示轮廓精度，不影响算法结果：

```text
缩小：轮廓简化
正常：标准轮廓
放大：高精度轮廓
```

交互层建立 Blob 空间索引。鼠标点击先按 BoundingBox 找候选，再只将当前选中的区域转换为 WPF 轮廓进行高亮。

## 8. 实施阶段

### M1：冻结显示契约

- 增加区域批量显示模型和 OK/NG 显示命令。
- 明确算法结果不得因显示预算被截断。

### M2：批量轮廓转换

- 在 HalAdapter 增加批量轮廓构造器。
- 结果层按批次创建 `StreamGeometry`。
- 移除 Blob 结果构建阶段逐区域生成 WPF 轮廓的路径。

### M3：异步与版本控制

- 后台生成批量几何。
- 增加取消令牌和渲染版本校验。
- UI 线程只做结果层替换。

### M4：Tile 和样式刷新

- 按图像 Tile 缓存批量几何。
- OK/NG 颜色和可见性变化只刷新样式，不重跑算法。

### M5：交互和验证

- 增加空间索引和选中区域单独高亮。
- 验证 71905 区域、OK/NG 混合判定、清除/改色、缩放、节点切换和重复运行。

## 9. 验收标准

1. 71905 个区域完整保留在算法结果中。
2. OK/NG 区域全部可见，颜色独立可改。
3. 清除结果显示不会清除算法结果。
4. 结果显示不创建 71905 个 WPF 图形对象。
5. 执行完成和切换节点时 UI 不冻结。
6. 选中任意 Blob 可在交互层高亮。
7. 运行工作流不会因为结果显示失败而失败。

## 10. UI 显示预算

Blob 参数页提供“最大显示 Blob 数”设置，默认值为 5000，允许范围为 100~100000。该参数只控制当前阶段的轻量 WPF 图形展开数量，不影响算法结果、完整 `BlobRegions`、OK/NG 判定或下游绑定。

正式批量区域渲染器启用后，该设置继续作为交互层和高亮几何的预算；完整区域显示由批量区域渲染器负责。
