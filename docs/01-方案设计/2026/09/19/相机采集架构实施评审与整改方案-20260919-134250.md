## 1. 用户视角结论

**改前的现象：** 相机模块是占位实现，设备管理界面能打开但连不上真设备，工作流里没有相机采集节点。

**Codex 这轮之后用户看到的：** 相机管理器、添加相机、设备详情、实时预览四个界面都做出来了，能自动发现海康（MVS）与模拟相机，能读到参数并按类型渲染编辑控件，两个窗口已经跟随亮/暗主题。

**但离"能用"还差得远，用户实际会遇到：**

1. 点「连接」**不会真的连上任何相机** —— 管理器里的"已连接"是自己写上去的标签，不是设备状态
2. 添加完相机**关窗再打开就没了** —— 列表不落盘，"刷新"等于清空
3. 详情页「描述 / 延迟 / 帧率」**永远是空的或 0** —— 这些字段没人赋值
4. 切一下设备，**刚连上的相机被悄悄断开**，界面却还显示"已连接"，而且**再也点不上连接**
5. 相机管理界面**右半边（设备详情）在暗色主题下是白底黑字** —— 那一整片没有主题适配
6. 「添加相机」**点"取消"会被当成"添加成功"**；勾选三台设备**只会加进去一台**
7. 表单里有**用户名 / 密码 / 554 端口**（这是网络摄像机的概念，工业相机没有），而且密码框**根本没接线**，输入直接被丢弃

**依据：** 上述判据全部来自本次代码走查的可追溯锚点（文件 + 行号），见第 4～6 章；验收对照见第 7 章。

### 4.4 主题适配

#### 4.4.1 根因：平台级控件主题样式几乎是空的

`src/UI/Resources` + `src/UI/Themes` 中**真正全局生效的隐式样式只有 3 个**（无 `x:Key` 的 `TargetType` 样式）：

```
src/UI/Resources/Styles/CommonStyleResources.xaml:179   <Style TargetType="ScrollBar">
src/UI/Resources/Styles/MenuStyleResources.xaml:71      <Style TargetType="MenuItem">
src/UI/Resources/Styles/MenuStyleResources.xaml:87      <Style TargetType="ContextMenu">
```

`ToolTipStyleResources.xaml:35` 的 `TextBlock` 样式嵌在 ToolTip 模板的 `ContentPresenter.Resources` 内，**不是全局**。

## 9. 总体结论

**架构方向正确，落地完成度偏低。**

- 分层（SDK 契约 / 驱动契约 / 适配器 / 运行时 / UI）、命名、能力模型、Schema 驱动 UI 与方案高度吻合，`src/Plugin.SDK/Devices/Camera/` 与 `src/DeviceDriver/Cameras/Contracts/` 的落位与方案 §3.1 基本一致
- 但**"能编译、能开窗口"与"能用"之间有实质差距**：管理器操作不接设备、采集每帧重连、并发可开双句柄、列表不落盘、详情大面积空数据、出错无日志无错误码
- 方案 §12 的 17 项 UI 要求中，仅 3 项完全达成；§14 的 M3/M6 尚未开始；§15 的迁移策略被整体提前执行
- 规则层面有 5 条硬性规则被违反（rule-001 / rule-003 / rule-008 / rule-015 / rule-016）
- 前置环境问题（游离 HEAD、落后主仓库、`dev/Debug` 与 `solutions/` 目录隔离、缺 Halcon native）**必须先解决**，否则每次构建启动都会重复踩坑

**建议执行顺序：** 先处理第 8 章未决事项 2、3（基线与环境），再按第 7 章梯队一 → 二 → 三推进；每完成一个梯队跑一次 `dotnet build SunEyeVision.slnx -c Debug` + `dotnet test`，并按 rule-021 §5 更新 `docs/collaboration/CURRENT_TASK.md`。
