## 0. 一句话结论

**结果图形之所以不显示，是因为把"取景框（视口）"当成了"能不能画"的开关，而它还会被"清空结果"顺手清掉。**
修正方向：**视口降级为"省力优化输入"**；能否显示只由**"有无内容 + 内容是否属于当前图像"**决定。

---

## 1. 问题定性

### 1.1 现象

工作流执行完成、选中 Blob 分析节点后，**图像正常显示，但结果图形（Blob 轮廓/矩形/质心/文本）一个都不显示**；缩放或拖动图像一次后，图形立刻全部出现。

### 1.2 证据时间线（工作区 `-comm` 的 `logs/2026/09/21/SunEyeVision_151632.txt`）

| 时间 | 日志 | 含义 |
|---|---|---|
| 15:16:57.770 | `Refresh skip: reason=viewport-change, viewport=True` | 视口正常 |
| 15:17:02.325 | `BlobAnalysisResults | Blob数量=3000 | 总面积=1419758` | 算法正常 |
| 15:17:02.376 | `SetDisplayCollector: items=4, allItems=4, buildVersion=1` | **结果已提交** |
| 15:17:02.378 | `Batch geometry build begin: version=1, batches=4, contours=6000` | 图形已入批 |
| 15:17:15.895 | `RoiEditorControl 控件已卸载（Tab切换）` | 触发清理 |
| 15:17:15.896 | `Refresh skip: reason=highlight-clear, viewport=False` | ⚠ **视口被作废** |
| 15:17:16.262 | `GPU batch scene ready: imageIdentity=3, renderGeneration=5, backend=wpf-batch, batchCount=4, vertexCount=725242, drawRanges=6000` | 批几何就绪 |
| 15:17:16.262 | `Refresh skip: reason=batch-scene-ready, viewport=False` | ⚠ **就绪却不渲染** |

**结论**：算法、结果提交、批几何编译**三者都正常**；唯一异常是 `viewport=False`，且渲染被**静默跳过**（`[ERROR]/[WARN]` 计数为 0）。

### 1.3 根因四条（设计层）

| # | 缺陷 | 说明 |
|---|---|---|
| **D1** | **状态归属错位** | 视口属于"图像视图（相机）"，却存放在"结果层宿主（投影仪）"中，并随内容一起被清 |
| **D2** | **单向依赖、无回程** | 只有"图像视图 → 结果层"的推送；结果层**从不主动索取**视口，也不在缺失时降级渲染 |
| **D3** | **失败模式静默** | "画不出来"只写 INFO 日志，不报错、不提示 |
| **D4** | **清理语义不分层** | `Clear()` 被"切 Tab／切节点／清高亮／关调试窗"多场景共用，并把"清内容"与"作废视口"绑定 |

### 1.4 代码落点

| 落点 | 位置 | 对应缺陷 |
|---|---|---|
| 清空时连带作废视口 | `src/Plugin.SDK/UI/Controls/ImageControl/ResultTileHost.cs:83-86`（`Clear()` 内 `_hasViewport = false`） | D1 / D4 |
| 无视口即静默跳过 | `ResultTileHost.cs:99-113`（清 Visual 后 `return`，仅 INFO） | D2 / D3 |
| 视口唯一提交点 | `src/Plugin.SDK/UI/Controls/ImageControl/ImageControl.xaml.cs:837-841`（仅在图像变换更新时提交） | D2 |
| 传播路径 | `ResultRenderLayer.Clear()` 末尾 `base.Clear()`；`ResultRenderLayer.SetViewport(...)`（`:509-518`） | D1 |

### 1.5 为什么定性为"设计问题"而非"代码写错"

只改 `_hasViewport = false` 那一行，当前现象会消失，但**同类问题会换入口复发**：

| 复发现场 | 复发原因 |
|---|---|
| 关闭调试窗口后"自动恢复工作流结果"（决策 7.3） | 恢复过程同样先清结果 ⇒ 视口又被清 |
| 切换选中另一节点再切回 | 同一 `Clear()` 路径 |
| 重新载入图像 / 图像尺寸变化 | 视口未重推 ⇒ 空白或错位 |
| 窗口 / 画布尺寸变化 | 同上（是否重推视口尚未核实，见 §4.6） |

⇒ 只要"视口"仍住在结果层里、仍与内容同生共死，修一个入口就会出现下一个入口。

## 2. 目标语义（方案的"宪法"）

### 2.1 依赖分级：正确性 vs 优化

| 依赖 | 性质 | 缺失时应当 |
|---|---|---|
| `ImageIdentity` | **正确性**（画到别的图上=错） | **拒绝渲染**（保留现状） |
| `RenderGeneration` | **正确性**（过期回写=错） | **丢弃过期结果**（保留现状） |
| **视口矩形** | **性能 / 体验** | **照常渲染**（全量或按最后已知范围）← 现状相反 |
| 缩放倍率 | 体验（线宽/字号/LOD） | 默认 `1.0` 兜底 |
| "界面已有可绘制表面（尺寸>0）" | 前提 | 无表面 ⇒ 不画（**唯一合理的不画**） |

### 2.2 三条不变式（验收基线）

| 不变式 | 内容 | 违反后果 |
|---|---|---|
| **I1** | 有内容 **且** 图像匹配 ⇒ **必须显示**（不得因视口/时机/清空而拒绝） | 黑屏（本次故障） |
| **I2** | 图像不匹配 **或** 代次过期 ⇒ **必须不显示**并丢弃 | 画错图 / 陈旧结果覆盖 |
| **I3** | 内容过多 ⇒ **降级显示**（LOD 采样 / 合并批次）；**绝不允许降级为"不显示"** | 静默丢结果（最危险） |

### 2.3 视口语义：由 push 事件改为 pull 状态

| 现状 | 修正后 |
|---|---|
| 视口是**间歇推送**，用完作废 | 视口是**持续有效的状态**；谁要画谁来取（pull） |
| 取不到 ⇒ **不画** | 取不到 ⇒ **全量画** + **主动索取一次** |
| 清内容 ⇒ **连带作废**视口 | 清内容**不动**视口；作废只由图像视图在**换图/卸载**时显式执行 |

**一句话**：把"时机问题"转化为"状态问题"——状态一旦设定即持续有效，"何时选节点"便不再重要。

### 显示时序（"什么时候"显示）

```
1. 结果提交（选中节点 / 执行完成）
2. 后台编译（批几何 + 场景；7 万区域为百毫秒~秒级）
3. 编译完成回调 → 【强制提交绘制一次】← 关键：必须在此主动重绘
4. 显示
```
⇒ "选节点后百毫秒内出现"是正常且可接受的；**"必须缩放一下才出现"不可接受**。

## 4. 修改清单

### M1 · 依赖分级：删除"无视口不渲染"硬门槛【核心·必须】
- **文件**：`src/Plugin.SDK/UI/Controls/ImageControl/ResultTileHost.cs`（`:99-113`）
- **改动**：`!_hasViewport` 不再"清空 Visual + return"，改为**按最后已知视口或全量渲染**（降级渲染而非拒绝渲染）。
- **验收**：场景 1 / 5 ⇒ 日志出现 `renders=N`，无 `viewport=False` 跳过。

### M2 · 视口状态归位：清内容不作废视口【核心·必须】
- **文件**：`ResultTileHost.cs:83-86`（`Clear()`）、`ResultRenderLayer` 的 `Clear()`
- **改动**：① `Clear()` 只清 `_scene` 与 Visual，**保留 `_hasViewport` / `_viewport`**；② 新增 **`ClearViewport()`**，仅由 `ImageControl` 在**图像卸载/关闭图像**时调用。
- **验收**：场景 2 / 3 / 4 ⇒ 不再需要缩放平移即可显示。

### M3 · 补闭环：编译完成强制重绘 + 缺失时主动索取【必须】
- **文件**：`ResultRenderLayer`（批几何/场景编译完成回调）、`ResultTileHost`
- **改动**：① 编译完成回调**无条件提交一次绘制**；② 提交绘制时若"界面有表面但视口未知" ⇒ **主动向图像视图索取一次当前取景框**（同步 pull）；索取失败 ⇒ 全量渲染。
- **验收**：场景 1 / 12 ⇒ 选节点后自动出现，无需任何用户操作。

### M4 · 可观测性：失效必须自曝【必须】
- **文件**：`ResultTileHost`（日志分级与统计）
- **改动**：① "因无视口而跳过/降级"由 INFO 升为 **WARNING**；② 连续 N 次未恢复 ⇒ **ERROR** + `scene/backend/viewport/trace` 上下文；③ 统计项并入 `ResultTileHostStats`（跳过次数、降级次数、最后原因）。
- **验收**：人为制造视口缺失 ⇒ 日志明确 WARNING/ERROR，不再静默。

### M5 · 职责归一（架构项，建议单列）
- **文件**：`ImageControl.xaml.cs`（视口提交）、`ResultTileHost`
- **改动**：① 视口提交收敛为**单一入口**，在**换图 / 缩放 / 平移 / 画布尺寸变化 / Loaded** 任一变化时**无条件**提交（现仅覆盖图像变换更新）；② 按审核 §3.3 **方案 A**：`ResultTileHost` 退化为"少量 Visual + 空间查询宿主"，Tile 仅做**空间索引 / 命中候选 / 局部范围管理**（与上位 GPU Batch 方案一致）。
- **验收**：窗口尺寸变化后图形位置正确；Tile 不再作为绘制单元。

### 4.6 施工前待核实项
- **画布/窗口尺寸变化时是否重推视口**？现仅见 `ImageControl.xaml.cs:837-841` 一处提交点，需核实是否覆盖 `SizeChanged`；据此决定 M5 是否补第 4 个触发点。

## 10. 附录 A：大白话说明

- **视口 = 相机取景框**：由"当前缩放倍率 + 平移量 + 画布尺寸"决定，"现在看到的是图像哪一块"。
- **结果层 = 投影仪**：要出画需要两样：**胶片（要画的图形）** 和 **幕布位置（画在哪一块）**。
- 本次故障：**胶片早就备好了（6000 条轮廓 / 72 万顶点已编译），但"幕布位置"被清掉了**，投影仪于是不投、也不报警。
- 为什么"缩放一下就好了"：缩放会让相机重新报一次取景框 ⇒ 投影仪又知道往哪投了。
- **正确期望**："我选节点，就该显示结果图形" —— 修正后成立：选节点 ⇒ 用当前取景框直接画 ⇒ **无需缩放**。
