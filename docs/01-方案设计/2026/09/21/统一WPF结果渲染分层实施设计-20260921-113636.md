## 1. 目标接口（一次定义到位，后续阶段不再改公共面）

```csharp
// ── 状态语义（上位方案 §5）——几何类型不进公共面，但渲染内部保持强类型 ──
public enum DisplayState { Pass, Fail, Neutral }

public enum RenderGeometryKind { Contour, Rectangle, Circle, Line, Point, Arc, Polygon, Text }

public interface IRenderGeometry
{
    RenderGeometryKind Kind { get; }
    Rect Bounds { get; }                       // 图像坐标包围盒（索引与裁剪均用它）
}

public sealed class ContourRenderGeometry  : IRenderGeometry { /* 点集 / 是否闭合 / 可选变换 */ }
public sealed class RectangleRenderGeometry: IRenderGeometry { /* 旋转矩形 */ }
public sealed class CircleRenderGeometry   : IRenderGeometry { }
public sealed class LineRenderGeometry     : IRenderGeometry { }
public sealed class PointRenderGeometry    : IRenderGeometry { }
public sealed class ArcRenderGeometry      : IRenderGeometry { }
public sealed class PolygonRenderGeometry  : IRenderGeometry { }
public sealed class TextRenderGeometry     : IRenderGeometry { /* 文本内容 / 锚点 / 字号 / 粗体 */ }

public sealed class RenderItem
{
    public DisplayState State { get; }         // Pass / Fail / Neutral（无判定语义的辅助结果）
    public IRenderGeometry Geometry { get; }   // 强类型，禁止 object
    public GraphicsStyle Style { get; }        // 颜色/线宽/可见性仍由样式驱动
}

public sealed class RenderSnapshot
{
    public IReadOnlyList<RenderItem> Items { get; }
    public long ImageIdentity { get; }         // 图像切换失效用
    public long RenderGeneration { get; }      // 过期回写丢弃用
}

// ── 统一提交单元（审核 §2.1 方案 B：DebugPreview 进正式接口）──
public sealed class RenderFrame
{
    public RenderSnapshot? WorkflowResult { get; init; }   // 工作流执行结果
    public RenderSnapshot? DebugPreview   { get; init; }   // 调试窗口立即执行结果
    public RenderSnapshot? Regions        { get; init; }   // 检测区/屏蔽区
    public RenderSnapshot? Highlight      { get; init; }   // 数据分析高亮
}

// ── 宿主提交入口（一次提交；替代 SetDisplayCollector + SetRegionItems 两次调用）──
public void SetRenderFrame(RenderFrame frame);

// ── 事务形式（供多次写入场景）──
public void BeginRenderUpdate();   // 期间只累积
public void EndRenderUpdate();     // 只触发一次编译 + 一次 Visual 提交

// ── 分层清理（上位方案 §3/§4）——禁止再用无语义 Clear() ──
public void ClearWorkflowResult();
public void ClearDebugPreview();
public void ClearInteraction();
public void ClearHighlight();

// ── SDK ↔ UI 宿主的清理契约（审核 §2.3：SDK 只依赖接口，不依赖 UI 实现）──
// 定义位置：src/Plugin.SDK/UI/Controls/IDebugPreviewHost.cs
public interface IDebugPreviewHost
{
    void ClearDebugPreview(string nodeId);
    void ClearInteraction(string nodeId);
    void ClearHighlight(string nodeId);
}

// ── 独立调试结果上下文（业主 2026-09-21 决策②：调试结果不进生产 WorkflowContext）──
// 定义位置：src/Plugin.SDK/UI/Controls/IDebugResultContext.cs（SDK 只定义接口，UI 实现）
public interface IDebugResultContext
{
    void SetDebugResult(string nodeId, ToolResults result);        // 按节点仅保留最近一次
    bool TryGetDebugResult(string nodeId, out ToolResults? result);
    void ClearDebugResult(string nodeId);
}
```

## 2. M1a：结果来源与生命周期分离（**必须先做**）

审核 §2.2 的阻断项：不区分来源时，"调试执行"会通过普通工作流结果入口覆盖工作流结果。

| 动作 | 文件 | 具体 |
|---|---|---|

| 独立调试结果上下文 | 新增 `src/Plugin.SDK/UI/Controls/IDebugResultContext.cs` + UI 侧实现 | `SetDebugResult` / `TryGetDebugResult` / `ClearDebugResult`。用途：调试数据与显示解耦，供调试窗口重开与数据分析控件消费；**不参与工作流执行链**。清理时机：切换节点时清该节点旧值；关窗只清显示层（见 §3） |
| 调用点按来源分流 | `MainWindowViewModel.cs:4424`（工作流完成）→ `UpdateWorkflowResult`；`:4004`（调试完成）→ `UpdateDebugPreview` | — |

## 4. M2：RenderFrame 一次性提交

审核 §2.4 的阻断项：**不得把两个编译器的职责强行合并**。目标改为"收敛为一个提交入口"，而非"删掉一个编译器"。

```text
一次 RenderFrame 提交
├── RenderBatchCompiler     → 绘制批次（顶点/范围表/可冻结 WPF Geometry 数据）
└── RenderSceneCompiler     → 空间索引（Tile 归属 / 视口查询 / 命中候选）
```

| 动作 | 文件 | 具体 |
|---|---|---|
| 一次提交取代两次调用 | `NodeResultManager.cs:104-135` | 组装 `RenderFrame{ WorkflowResult, Regions, Highlight }` → 一次 `SetRenderFrame` |
| 消除重复构建 | `ResultRenderLayer.cs:83-115` | `SetDisplayCollector`/`SetRegionItems` 各自触发的整套编译合并为：**batch 编译 1 次 + scene 编译 1 次**；三条 `Task.Run`（`:184`/`:265`/`:565`）中两套重复的几何构建合并，保留"绘制批次"与"空间索引"两个**职责明确**的阶段 |
| 版本与取消统一 | `ResultRenderLayer.cs` | 单一 `RenderGeneration` + 单次取消源（消除现有三套 CTS/版本号） |

**测试**：`RenderSubmissionCountTests`：一次 `SetRenderFrame` ⇒ `batchCompileCount == 1`、`sceneCompileCount == 1`、`visualCommitCount == 1`（用诊断计数钩子断言）。

## 6. M4：少量 WPF Visual（收敛边界已明确）

审核 §3.3：`ResultTileHost` 不能只删 `CompositeVisibleTileThreshold` 分支就算迁移完成。

**采用审核推荐的方案 A**：`ResultTileHost` **保留** `FrameworkElement` 与 `VisualCollection`，但**只维护少量 Visual**，不再按 Tile 创建 `DrawingVisual`。

| 动作 | 说明 |
|---|---|
| Visual 结构 | `ResultVisual`（Pass/Fail/Neutral 几何）+ `TextVisual` + `InteractionVisual`，共 3 个，由 `ResultRenderLayer`（继承 `ResultTileHost`）持有 |
| Tile 职责回收 | 删除"每可见 Tile 一个 `DrawingVisual`"与 composite 分支（`ResultTileHost.cs:95-188`）；`RenderScene.Query` 仅用于**空间查询/视口裁剪/命中候选** |
| 缩放/平移 | 只改 `ImageScaleTransform`（已由 `ImageContainer` 共享）+ 重新提交，**不重建几何** |
| 样式变化 | 只重提交对应样式批次（`ApplyLiveResultPresentationStyles` 路径） |
| 命中接入 | `ResultHit`（现零订阅者，`ImageControl.xaml.cs:399-408`）→ 只对选中项生成 `InteractionVisual` 图形 |

**"Visual ≤ 3"的统计范围（按审核 §3.3 明确）**：

| 计入 | 说明 |
|---|---|
| ✅ 计入 | `ResultRenderLayer`（`ResultTileHost`）**自身直接托管的 Visual 子级** |
| ❌ 不计入 | `ImageControl` 的图像层（`DisplayImage`）、棋盘层（`ChessboardLayer`）等其它层 |
| ❌ 不计入 | 交互层 `InteractionOverlayCanvas`（独立 `Canvas` 层，承载 RoI/卡尺/手柄） |
| ❌ 不计入 | 高亮层若由 `InteractionVisual` 承载，则**不单独计数**（并入上述 3 个之一） |

**测试**：`RenderVisualCountContractTests`：在"大量 Blob（≥10000 图元）"下，`ResultRenderLayer` 直接 Visual 子级 **≤ 3**；扩 `RenderHitTestingContractTests` 覆盖"只高亮选中项"。

## 7. M5：收敛与基准

- 后台冻结几何 + `RenderGeneration` 取消过期回写（单提交后天然统一）；
- `RenderSceneCompiler` 的索引构建可**惰性化**（首次视口查询时构建）以压低首帧成本；
- 诊断计数：`submitMs` / `batchCompileMs` / `sceneCompileMs` / `geometryCount` / `batchCount` / `visualCount`（沿用现有 `RenderAnalysis` 埋点风格）；
- **基准**：沿用 `RenderScenePerformanceTests`（3000 / 10000 / 71905 / 100000）并补**真实轮廓场景 + UI 平移/缩放帧率与内存**。

## 9. 施工顺序（按审核 §4 细化）

## 10. 风险与回滚

| 风险 | 处置 |

## 12. 对审核意见的回填（8 问逐条）

| # | 审核提问 | 回填结论 | 落点 |
|---|---|---|---|
| 1 | `RenderFrame` 是否包含 `DebugPreview`？ | **包含**。采用审核 §2.1 **方案 B**：`RenderFrame{ WorkflowResult, DebugPreview, Regions, Highlight }`，统一走 `SetRenderFrame(RenderFrame)` | §1 |
| 2 | 工作流结果与调试结果的独立写入入口？ | **`UpdateWorkflowResult(node, result)`**（写 `WorkflowContext` + WorkflowResult 层）与 **`UpdateDebugPreview(node, result)`**（只写 DebugPreview 层）。原 `UpdateNodeResult` 收敛为私有或删除 | §2 |
| 3 | SDK 与 UI 宿主之间通过什么接口清理调试预览？ | **`IDebugPreviewHost`**（SDK 只定义接口，UI 实现并在创建调试控件时注入）；`ToolDebugControlBase` 仅持有接口引用。备选方案（`DebugWindowClosed(nodeId)` 事件由 VM 清理）在不便注入时使用 | §1、§3 |
| 4 | 两个编译器的职责边界？ | `RenderBatchCompiler` = **绘制批次**（顶点/范围表/可冻结 Geometry 数据）；`RenderSceneCompiler` = **空间索引**（Tile 归属/视口查询/命中候选）。**两者都保留**；消除的是重复提交与重复构建，不是删除编译器 | §4 |
| 5 | 是否移除 `object Geometry`？ | **移除**。改用 `IRenderGeometry{ Kind, Bounds }` + 强类型几何类（Contour/Rectangle/Circle/Line/Point/Arc/Polygon/Text） | §1 |
| 6 | `ResultTileHost` 保留为少量 Visual 宿主，还是拆分为空间查询组件？ | **保留为少量 Visual 宿主（方案 A）**：保留 `FrameworkElement`/`VisualCollection`，只维护 3 个 Visual；空间查询继续复用其内部 `RenderScene` | §6 |
| 7 | 批次测试是否改为"兼容状态/样式合并"断言？ | **是**。断言"同一状态 + 同一兼容样式 + 同一绘制语义 ⇒ 合并为 1 批"，并校验三态颜色/显示状态；**不再断言固定批次数** | §5 |
| 8 | "Visual ≤ 3"的统计范围？ | **仅统计 `ResultRenderLayer` 直接托管的 Visual 子级**；不含 `ImageControl` 图像/棋盘层、不含 `InteractionOverlayCanvas`、高亮并入 3 个 Visual 之一不单独计数 | §6 |
