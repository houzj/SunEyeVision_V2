## 0. 本批要解决的问题（大白话）

| # | 问题 | 一句话 |
|---|---|---|
| P1 | **文字最亏** | 看不见的文字也参与排版；每行都重新"量一次尺寸"（最贵的一步）；找"谁和谁在同一位置"是挨个问，文字一多慢得不成比例 |
| P2 | **画笔越堆越多** | 缩放时线宽变一点点就造一支新画笔，造了不扔；缓存无上限、永不清空 |
| P3 | **轮廓一块块地交** | 整图视角下把轮廓按 512px 方块一块块提交给渲染管线（几十上百次），本可打包成一次 |
| P4 | **没有尺子** | 只有总耗时，不知道时间花在"块多"还是"顶点多"，无法定向优化 |

## 1. 改前 / 改后 / 依据（用户视角）

| 场景 | 现在 | 改后 |
|---|---|---|
| 面积文本几千条的图 | 卡；视口外的文字也在算，每行重新量尺寸，找同位置是平方级 | 顺；看不见的不算，量过的存起来，找同位置按格子查 |
| 连续缩放几十次 / 切多个工具 | 越跑越肿（画笔只增不减） | 稳定（画笔按档位造 + 设上限） |
| 整图视角看 6000 条轮廓 | 几十上百次提交 | 大范围打包成一次提交（局部仍分块） |
| 想定位瓶颈 | 只能猜 | 日志给出：提交次数 / 轮廓块数 / 顶点量 / 耗时 |

**依据**：① WPF 性能指南（冻结几何、减少每帧提交、`GeometryGroup` 组合子几何）；② Direct2D `Geometry Realization`（大范围用整块、小范围用细分）；③ WPF 文本渲染成本模型（`FormattedText` 构造含字形布局，必须缓存复用）；④ CAD 类软件交互期位图快照的通用做法（第三梯队，需裁示）。

## 3. 问题分析（代码事实 + 来源）

| 结论 | 来源 |
|---|---|
| 文本收集**完全不做视口剔除**：视口外文字也进入排版 | `ResultRenderLayer.RenderTextsGrouped`（收集循环 `foreach (var item in items)` → `for (int i = 0; i < texts.Length; i++)`） |
| 每行文本都 `new FormattedText + new Typeface + new SolidColorBrush`，**无缓存** | 同文件 `CreateFormattedText`（`new Typeface(...)`、`new FormattedText(...)`、`new SolidColorBrush(color)`） |
| 同锚点分组为**双层循环**（O(n²)） | 同文件 `groups` 构建段（`foreach (var line in lines)` 内层 `foreach (var group in groups)`） |
| `TextLine` 对象每帧重新 new | 同文件文本行收集段 |
| Pen 缓存 key 含 `线宽×100`，线宽随缩放连续变化 ⇒ 每个缩放档位一条 Pen；`_penCache` **无上限、无清理**（注释明确"跨渲染复用、不再清空"） | 同文件 `GetPen`、私有字段声明区与 `OnRender` 注释 |
| Brush 缓存受颜色数限制（有限），Pen 缓存受线宽连续值影响（可无限增长） | 同文件 `GetBrush` / `GetPen` |
| 非批量路径每帧重建几何：`new StreamGeometry + Freeze` | 同文件 `DrawPolygon` / `DrawPolyline` / `DrawMultipleFigures` |
| 轮廓批量几何按 1000 条/块 + 512px tile 归档并冻结（已有缓存） | 同文件 `ScheduleBatchGeometryBuild` / `BuildBatchGeometries` 与常量 `BatchGeometryChunkSize=1000`、`GeometryTileSize=512` |
| 有视口时按 tile 取块后**逐块 `DrawGeometry`** ⇒ 提交次数 = 相交 tile 数 | 同文件 `RenderContours` 批量分支 |
| 无视口时该批次**全部块都画**（不去重按 tile，改为全量 HashSet） | 同文件 `RenderContours` 批量分支 `if (!_hasViewport)` |
| 诊断仅有 items/contours/crosses/texts，**无提交次数/块数/顶点量** | 同文件 `WriteRenderDiagnostics` |

## 4. Bug 模式分析（治本依据）

**当前问题**：这不是"某个函数写错了"，而是一组**同类模式**在消耗性能。

| 项 | 内容 |
|---|---|
| **真因分类** | ① **每帧重复劳动**：可复用的中间结果（文本布局、非批量几何）没有缓存；② **缓存无界**：缓存只增不减且键含连续量（线宽）；③ **提交粒度过细**：可合并的块级绘制被逐个提交；④ **度量缺失**：无提交量/块数指标，优化无从定向 |
| **同类潜伏点** | ① `DrawPolygon` / `DrawPolyline` / `DrawMultipleFigures` 与非批量轮廓分支同属"每帧重建"族；② `CreateFormattedText` 与 `TextLine` 同属"每帧重建"族；③ `_brushCache` 虽受颜色数限制，但与 `_penCache` 共用"只增不减"策略⇒同一处治理；④ 文本分组 O(n²) 与"锚点容差判定"耦合，属算法级 |
| **治本点** | **"算过一次就存起来、看不见就不算、能合并就合并、不确定就先量"** —— 四句话对应 P1~P4 四个方向，而不是逐个函数打补丁 |

## 6. 方案对比（≥3 候选 + 长期 ROI）

| 维度 | **A（推荐）分阶段治理：尺子 → 文本 → 缓存 → 提交** | B 只做轮廓整组提交 | C 全路径化 + 单盒 | D 直接上交互期位图快照 |
|---|---|---|---|---|
| 内容 | 阶段 1~5 依次落地，每阶段独立可验证 | 仅阶段 5 | 所有图形统一转路径，按 OK/NG 两盒绘制 | 交互期用位图，停手重绘 |
| 与现有架构一致性 | ✅ 不动分层与数据契约 | ✅ | ❌ 破坏"按类型渲染"专属处理（十字屏幕恒定、轮廓分块、线宽幂律） | ⚠ 需处理位图与矢量切换观感 |
| 复杂度 | 低→中（逐阶段） | 低 | 高 | 中高 |
| 风险 | 低（每阶段独立回退） | 低 | 高（渲染语义全面改写） | 中（放大期间会糊） |
| 收益覆盖 | 文本、内存、提交次数、度量四项 | 仅提交次数 | 提交次数（类型合并） | 交互手感 |
| **长期 ROI** | 6 月 **高**｜1 年 **高** | 6 月 中｜1 年 中 | 6 月 低（改造期）｜1 年 中 | 6 月 中｜1 年 中 |
| 结论 | ✅ 采用 | 作为 A 的子集 | ❌ 不采用 | 待数据，列为可选阶段 7 |

**推荐 A 的理由**：① 每阶段独立可验证、可回退（rule-008 KISS/YAGNI）；② 文本与缓存两项是"纯赚"（不改任何观感）；③ 提交次数优化（阶段 5）先有度量再动手，避免盲目改造；④ C/D 属于观感或架构重写，必须用户裁示。

## 9. 防御机制（≥2）

| # | 机制 | 内容 |
|---|---|---|
| 1 | **契约测试** | ① 提交量恒等：给定 N 条轮廓/十字/文本（视口覆盖全图），实际提交量 == N（优化不得减少） ② 缓存正确性：缓存命中与未命中两种路径产出的绘制内容一致 ③ 分桶分组与线性分组结果一致（同锚点判定等价） |
| 2 | **可观测性（防静默）** | 阶段 1 起 `[RenderDiag]` 含 `drawCalls/blocks/vertexEstimate/renderMs`；单帧超阈值升 Warning（1 秒节流）；优化前后数字可对照 |
| 3 | **Fail-Forward** | 缓存构建/分桶/两级切换任何一步异常 ⇒ **退回"逐项现算 + 分块提交"**（宁可慢，不可少画、不可不画）；禁止"缺缓存就不画" |
| 4 | **端到端冒烟** | 同一张图（`C:\Users\houzhongjie\Desktop\OK\103821989.png`）三组对照：优化前 / 优化后 / 关闭优化开关；逐项目视 + 截图比对，确认显示内容不减少 |

## 12. 风险评估与回退

| 风险 | 程度 | 应对 / 回退 |
|---|---|---|
| 文本缓存占用内存（内容×字号组合多） | 中 | 缓存条目上限 + LRU；字号量化后再入键 |
| 分桶分组与线性分组判定不等价（同锚点判定差异） | 中 | 契约测试断言"分组结果集合一致"；不等价则退回线性（带上限告警） |
| Pen 量化后线宽出现"跳档"观感 | 低 | 档位取足够细（0.25px）；肉眼确认后再定档 |
| 两级切换导致抖动（同一视口反复切换） | 中 | 覆盖率滞回（0.4~0.6 保持上次）+ 55 万顶点护栏 |
| 非批量几何缓存失效不及时（显示旧几何） | 中 | 沿用批量缓存的版本号机制；切换结果/清空时整体失效 |
| 阶段 6/7 涉及"少画"或观感取舍 | — | **必须用户裁示后才实施** |

**回退**：每阶段独立提交，可单独 revert；第一批量语义改动在 `feature/render-quantity`（`1a8c261f`）可整体切回。
