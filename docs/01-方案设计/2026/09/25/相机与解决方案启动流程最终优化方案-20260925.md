# 相机与解决方案启动流程最终优化方案

## 一、总体目标

解决以下问题：

- 启动页、解决方案管理器、主界面职责混乱；
- 加载解决方案时界面卡住或直接退出；
- 相机连接阻塞主线程，导致主界面无法显示；
- 相机连接状态与参数界面耦合；
- 关闭或重新打开设备管理器影响相机连接；
- 添加、重命名、保存、重启后设备状态不一致；
- 用户等待相机连接时没有明确提示。

最终原则：

> 解决方案加载和相机连接失败，都不能阻止主界面显示。

## 二、界面职责

### 1. 启动页

启动页只负责应用基础初始化：

```text
启动应用 → 加载插件 → 初始化服务 → 初始化解决方案仓库 → 显示解决方案管理器
```

解决方案管理器显示完成后，启动页正常退出，不负责等待具体方案中的相机连接。

### 2. 解决方案管理器

负责新建、打开、删除、重命名和选择解决方案。用户双击方案后进入方案加载流程。

### 3. 主界面方案加载遮罩

双击方案并完成当前方案设置后，立即显示主界面；主界面上覆盖模态加载遮罩，不重新显示启动页，也不新增独立加载窗口：

```text
正在加载解决方案

当前阶段：正在恢复相机连接
相机连接进度：1 / 1
已连接：0
失败：0
剩余等待时间：10 秒
```

加载阶段依次显示：读取方案、解析工作流、设置当前方案、恢复相机连接、准备主界面。

## 三、最终启动流程

```text
应用启动
  ↓
显示启动页
  ↓
加载插件和基础服务
  ↓
显示解决方案管理器
  ↓
启动页退出
  ↓ 用户双击解决方案
设置当前方案后显示主界面加载遮罩
  ↓
读取解决方案
  ↓
设置当前解决方案
  ↓
根据设备列表恢复相机连接
  ↓
等待连接成功、失败或超时
  ↓
显示主界面
  ↓
关闭加载遮罩
```

连接流程必须使用异步调用，禁止在 UI 线程使用 `.Result` 或 `.GetAwaiter().GetResult()`。

## 四、相机连接生命周期

相机连接由应用级 `CameraConnectionManager` 持有，设备管理器窗口只负责显示和操作：

```text
应用启动 → 创建连接管理器 → 加载设备列表 → 恢复连接 → 应用退出时统一释放
```

关闭设备管理器窗口不能断开相机，也不能释放 `CameraAdapter`。只有用户点击 ToggleButton、应用退出、明确的重新连接流程或删除设备时才允许断开。

设备连接必须按唯一 `DeviceId` 管理，例如：

```text
hikvision-mvs:DA5892282
```

避免添加、搜索、打开设备管理器和加载方案时重复注册同一设备。

## 五、连接状态与超时

设备状态统一为：

```text
未连接、连接中、已连接、连接失败、连接超时、设备不存在、被其他程序占用
```

ToggleButton 的语义为：

```text
开启 = 连接相机
关闭 = 断开相机
```

方案加载后最多等待 10 秒：

- 10 秒内完成：统计连接成功和失败数量后进入主界面；
- 超时：标记未完成设备为“连接超时”，进入主界面；
- 超时任务可在后台继续观察，最终结果更新设备状态；
- 加载遮罩持续显示当前阶段、设备进度和剩余时间。

超时提示：

```text
相机连接恢复超时，软件将继续启动，可在设备列表中重新连接。
```

## 六、主界面显示策略

无论连接结果如何都显示主界面：

| 连接结果 | 主界面行为 |
| --- | --- |
| 全部成功 | 正常进入，设备显示已连接 |
| 部分成功 | 正常进入，失败设备显示故障 |
| 全部失败 | 正常进入，显示失败原因 |
| 超时 | 正常进入，显示连接超时 |
| 设备不存在 | 正常进入，显示设备不可用 |

连接结果通过底部状态栏或通知区域提示，不阻塞用户使用主界面。

## 七、设备列表界面

设备列表采用新版通信设备列表的紧凑卡片样式：

```text
设备列表                         [+]

1   Hikrobot-MV-CU120-10GM-001
    Hikrobot · GigE Vision · 已连接       ●  [预览] [ToggleButton]
```

设备卡片显示：名称、厂商、型号或接口、连接状态、状态圆点、预览按钮和连接/断开 ToggleButton。

设备管理器不再保留大面积基本信息或常用属性面板。窗口宽度降低约 30%，高度增加约 20%，保持紧凑布局。

## 八、预览与参数管理

预览按钮直接整合到设备卡片，不增加独立预览选项卡。点击后打开当前已有的相机设置/预览窗口，现有预览窗口实现保持不变。

相机参数与连接状态解耦：

- 设备列表只显示必要设备信息和连接状态；
- 参数在预览窗口中读取和调试；
- 参数读取失败只在预览窗口提示；
- 参数失败不影响设备列表和主界面显示；
- 关闭预览窗口不能改变打开前的连接状态。

打开前已连接，关闭后必须仍然连接；打开前未连接，关闭后仍保持未连接。

## 九、设备持久化

本地只保存设备配置，不保存运行时连接对象、SDK 句柄、线程、预览窗口或临时缓存。

建议保存：

```json
{
  "DeviceId": "hikvision-mvs:DA5892282",
  "Name": "相机1",
  "Vendor": "Hikrobot",
  "Model": "MV-CU120-10GM",
  "IpAddress": "11.245.254.169",
  "InterfaceType": "GigE",
  "IsAutoConnect": true
}
```

应用重启后重新创建 `CameraAdapter`，按 `DeviceId` 查找设备并恢复连接。

名称重命名后立即更新内存对象并保存；重命名输入框获得编辑焦点时自动全选；添加相机窗口的名称与当前设备数据同步。

## 十、错误处理与日志

连接失败必须保留真实原因，例如设备未发现、设备被占用、SDK 初始化失败、网络失败或超时，不能只显示“故障”。

启动链路日志至少覆盖：

```text
应用启动
启动页显示
插件加载完成
解决方案管理器显示
用户双击方案
开始读取方案
方案读取完成
设置当前方案
开始恢复相机连接
单个设备连接开始
单个设备连接成功/失败
连接等待超时
显示主界面前
主界面 Show
主界面 Loaded
加载流程结束
```

每条日志包含时间、阶段、线程 ID、方案路径、设备 ID、进度、耗时和异常信息。

## 十一、验收标准

- 启动页完成基础初始化后关闭；
- 解决方案管理器正常显示；
- 双击方案后出现加载遮罩；
- 加载期间界面不会卡死；
- 用户能看到 10 秒连接等待进度；
- 连接成功、失败或超时后都能进入主界面；
- 设备不会重复发现或重复注册；
- 关闭设备管理器不影响相机连接；
- 关闭预览窗口不改变连接状态；
- 重启软件后设备列表和名称保持一致；
- 方案加载根据设备列表恢复相机连接；
- 连接失败显示真实原因并支持后续重试；
- 相机参数全部在现有预览窗口中调试。

## 十二、实施顺序

1. 收口应用级相机连接生命周期；
2. 完成方案加载异步链路，移除 UI 线程同步等待；
3. 在主界面增加方案加载遮罩和阶段提示；
4. 增加 10 秒超时、后台观察和失败状态更新；
5. 将主界面显示与相机连接结果解耦；
6. 收口设备唯一标识和持久化恢复；
7. 完成设备列表卡片、预览按钮和 ToggleButton 交互；
8. 修复重命名全选和添加窗口名称同步；
9. 补齐启动、方案加载、连接恢复和主界面显示日志；
10. 使用真实相机完成统一构建和回归测试。
