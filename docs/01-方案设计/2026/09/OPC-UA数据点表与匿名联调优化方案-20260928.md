# OPC UA 数据点表与匿名联调优化方案

日期：2026-09-28  
状态：沟通与验收基线；核心代码已实施，**真实 KEPServerEX 界面联调、WPF 运行时布局和 VS 设计时尚待人工验收**。实际完成度以代码、构建及协作记录为准。

## 1. 已确认的产品决策

- 软件作为 **OPC UA 客户端**，KEPServerEX 作为服务器。新建和详情页均与其他网络通讯协议一样，分别填写**服务器地址**与**服务器端口**；默认 `127.0.0.1`、`49320`。协议 `opc.tcp://` 固定，由程序组合只读端点预览 `opc.tcp://127.0.0.1:49320`，用户不直接编辑整条 URL。已有设备的显式端点不得被默认值覆盖。加载解决方案时依设备列表建立连接，不另设“打开方案时连接”开关。
- 第一阶段只使用 **Anonymous 身份 + None 安全模式**。不提供用户名、密码、安全模式选择、服务器证书信任/导入/撤销等产品入口。OPC UA SDK 内部为客户端应用初始化证书的要求与“用户用证书登录”不同，不能误删必需的内部初始化。None 不加密，限本机或隔离测试网络联调。
- 不做完整节点树，也不再以 `i=85` 的浏览/读写/订阅调试区作为主要界面。通过“添加数据点”弹窗配置明确的字符串 NodeId，在表格中监视及修改 Value。
- 数据点表**不设置 NodeId 列**；表格上方设置一个公共的只读 NodeId 显示区，仅显示当前选中数据点的完整 NodeId。
- 添加弹窗的必填输入仅为两个文本框：**命名空间索引**和**标签名称**。例如索引 `2`、标签名称 `通道 1.设备 1.test1`，预览为 `ns=2;s=通道 1.设备 1.test1`。标签名称必须填写完整字符串标识，不是仅填 `test1`。
- 修改 Value 必须由用户显式确认，不因键入、失焦或订阅通知而自动写入。

表格列宽随窗口伸缩；空间不足时横向滚动，不截断至无法辨认。名称默认取标签名称最后一段；表格不重复铺开长 NodeId，完整 NodeId 只在公共区域显示。该区域使用可选中文本的只读控件，长内容可横向滚动或复制，不能在此直接修改节点标识。`Type`、权限、质量、当前值和更新时间均为服务器运行数据。没有数据点时显示空态提示：“尚未添加数据点，点击［+ 添加数据点］”。连接状态是设备级，错误信息尽量定位到具体行。

### 2.1 新建 OPC UA 设备弹窗（同其他网络协议的地址/端口布局）

```text
┌─ 添加通讯设备 ───────────────────────────────────────┐
│ 协议类型      [ OPC UA 客户端                ▾ ]    │
│ 设备名称      [ OPC UA 设备 1                 ]    │
│ 服务器地址    [ 127.0.0.1                     ]    │
│ 服务器端口    [ 49320                         ]    │
│ 请求超时(ms)  [ 3000                          ]    │
│ 端点预览      opc.tcp://127.0.0.1:49320（只读）   │
│ 自动重连      [开]                               │
│ 连接方式      匿名 · None（本阶段固定）           │
│                                  [取消] [添加]     │
└─────────────────────────────────────────────────────┘
```

“服务器地址”允许 IP 或主机名，不要求用户输入 `opc.tcp://` 或端口；端口使用 SDK NumericUpDown，范围 `1..65535`。请求超时使用数字控件，有效范围 `250..120000 ms`。IPv6 等合法主机形式由统一端点构造逻辑处理，不用字符串直接拼接出错。详情页与新建弹窗保持相同字段和默认值；新建 OPC UA 设备默认启用自动重连，旧设备保留已有策略。

## 3. 添加数据点弹窗目标 UI（ASCII）

```text
┌─ 添加 OPC UA 数据点 ───────────────────────────────────────────┐
│                                                                 │
│ 命名空间索引   [ 2                                     ]        │
│ 标签名称       [ 通道 1.设备 1.test1                   ]        │
│                                                                 │
│ NodeId 预览：ns=2;s=通道 1.设备 1.test1                          │
│ 显示名称：test1（自动从标签名称提取）                             │
│                                                                 │
│ 提示：填写服务器提供的完整字符串标识；中文、空格、点号            │
│       以及大小写须与服务器保持一致。                              │
│                                                                 │
│                                           [取消]  [添加]          │
└─────────────────────────────────────────────────────────────────┘
```

弹窗不增加第三个必填框，不要求用户手动拼 `ns=...;s=...`。预览为只读，随两个输入实时更新。命名空间索引须在 OPC UA NamespaceIndex 范围内（`0..65535`）；标签名称非空，且保留内部及边界字符的原貌，不静默清理可能有意义的空格。若首尾空格疑似误输入，可警告并让用户确认；预览与实际发送的 NodeId 必须一致。以命名空间索引和完整标签名称组合判断重复；重复时提示并定位既有行。

## 4. 交互与状态逻辑

### 4.1 连接、加载和保存

1. 应用加载方案后按通讯设备列表建立会话；OPC UA 数据点的监视属于设备运行时，不依赖管理窗口是否打开。关闭窗口不停止连接或订阅；设备禁用、方案切换、应用退出时按既有生命周期取消订阅并释放会话。
2. 新建设备显示默认服务器地址 `127.0.0.1` 和端口 `49320`；二者或超时有修改时，实时更新只读端点预览。界面区分“编辑中的端点预览”与“当前实际连接端点”；保存/应用配置后再安全重建连接，不得在用户键入地址或端口的过程中反复重连。地址不能为空；端口范围 `1..65535`，无效配置不得应用。
3. 添加、删除等配置变更先进入编辑状态并显示“未保存”。点击“保存”持久化；保存失败必须保留未保存标记并显示错误。带未保存变更关闭时提供“保存 / 不保存 / 取消”。
4. **旧方案迁移**：现有 OPC UA 配置保存的是 `endpointUrl`，而现有新建流程还可能写入其他协议通用的 `host/port` 默认值；因此迁移旧设备时必须以其有效的 `endpointUrl` 为准解析地址和端口，不能直接信任旧 `host/port`。新格式应有明确的配置版本/迁移标志，使迁移后地址、端口成为唯一可编辑来源，驱动运行时统一生成端点，避免两组字段相互覆盖。读取旧方案不应破坏旧值；若旧 URL 含非根路径，需保留该路径并在只读端点预览中展示，不能拆分时静默丢失。无法安全解析的旧 URL 应保留原文并提示修正，不自动替换为默认地址。

### 4.2 添加和删除

1. 离线时允许添加；行显示“等待连接”，保存后在下次连接时自动校验并监视。
2. 在线时添加后，后台读取节点元数据和当前值，确认节点类型及访问权限，再订阅。节点不存在、服务器拒绝访问或不支持当前监视时，保留配置行并显示可操作错误，不影响其他行。成功添加后自动选中新行，公共 NodeId 区随之更新。
3. 删除仅移除本软件配置的数据点，并撤销其订阅；**绝不删除 KEPServerEX 中的标签**。已删除行的迟到通知必须被忽略。确认提示说明影响范围，保存前仍可取消整个未保存编辑。删除当前选中行后清空选择与公共 NodeId，不得继续显示已删除节点。

### 4.2.1 表格选择与公共 NodeId

1. 单击一行后，高亮该行，公共区显示该行完整 NodeId；选中另一行立即切换。无选中行、空表或切换到其他设备时显示“未选择数据点”，不沿用前一设备的 NodeId。
2. 名称允许因末段相同而重复显示，实际选择和所有读写/删除命令必须绑定数据点稳定 ID 或完整 NodeId，不能按名称定位。排序、实时值更新或表格刷新不应无故改变选中项。
3. 公共 NodeId 是查看/复制区域，不是编辑入口；修改节点标识应作为独立的配置编辑行为处理，不通过改写此框触发重订阅。添加弹窗里的 NodeId 预览仍保留，用于添加前核对。

### 4.3 监视与刷新

1. 连接成功后对每个已配置点先读取一次，再建立或恢复监视；后续以服务器数据变更通知为主要更新来源。“刷新一次”只执行读取，不创建第二套周期性轮询。
2. 行状态至少区分“等待连接 / 正在读取 / 监视中 / 只读 / 节点无效 / 质量异常 / 已断线”。Value、质量和更新时间从同一数据事件更新；质量非 Good 时不把数值显示成可信实时值。
3. 断线可保留最后值供参考，但显式标注“已断线/非实时”；重连后重新校验、读取和订阅。以会话代次或等效机制丢弃旧连接迟到事件，不能把过期通知写回新会话。
4. 底层通知必须携带设备 ID 与精确 NodeId 或数据点 ID，以及值、类型、质量和时间；不能从现有格式化日志字符串反向解析表格数据。UI 接收通知后在 UI 线程合并/节流刷新，不逐条重建整表。

### 4.4 修改 Value

1. 仅服务器标记为可写的节点启用“修改”；只读、无效、断线或类型未知时禁用并解释原因。
2. Boolean 使用 True/False 选择；数字依服务器实际 OPC UA 类型校验范围和格式；字符串用文本输入。第一阶段支持常见标量；数组、结构等复杂类型只监视并标记“暂不支持在此编辑”。不可用笼统的 `Int64/Double` 猜测代替精确类型，否则 KEPServerEX 标签可能返回 `BadTypeMismatch`。
3. 用户按“确认写入”或 Enter 才发送；Esc/“取消”丢弃编辑。发送时防重复提交，明确显示进行中。成功后由写入结果及读取/订阅回传确认服务器实际值；失败则保留原监视值并显示服务器状态码。编辑时到达的新通知不能覆盖未提交的编辑缓冲。

## 5. 分层、持久化与兼容性

- `Workflow/Communication`：新格式保存 OPC UA 服务器地址、端口、必要的旧端点路径兼容信息、配置版本、超时和数据点配置（稳定 ID、命名空间索引、完整字符串标识及必要的显示配置）；连接用端点统一派生，不能让 `host/port` 与 `endpointUrl` 成为互相冲突的双重真源。旧 `endpointUrl` 按上述迁移规则读取；旧方案缺少数据点列表时按空列表加载。克隆、保存、重开及方案切换须同步兼容。Value、质量、更新时间和在线状态**不**进入方案序列化。
- `DeviceDriver/Communications/OpcUa`：负责真实连接、按点读取元数据和值、订阅与取消、精确类型写入、错误状态及重连恢复。应用级运行时持有设备会话；不要由 WPF 窗口独占或释放方案级连接。
- `UI/Features/CommunicationManager`：负责弹窗输入、表格绑定、编辑缓冲、状态说明及用户命令；不承担通信调度或从文本日志解析数据。跨层事件/DTO 只暴露实际消费者需要的稳定字段，不因单个 UI 页面预先扩张 Plugin.SDK。
- 当前单节点 `i=85` 浏览/读取/订阅/写入调试区由数据点表取代；迁移时避免影响已有非 OPC UA 协议页面。已有方案中旧的安全设置字典键不再参与第一阶段连接，读取旧方案不能因其存在而失败。

## 6. 首轮联调与验收

1. 新建 OPC UA 设备时输入地址 `127.0.0.1`、端口 `49320`，预览 `opc.tcp://127.0.0.1:49320`；与 KEPServerEX 建立匿名 None 连接。验证主机名、IPv6、空地址和非法端口的显示与校验。
2. 添加索引 `2`、标签名称 `通道 1.设备 1.test1`；表中出现 `test1` 行，选中后公共区域显示完整 `ns=2;s=通道 1.设备 1.test1`，读到 `False`、`Boolean`、读写权限与 Good 质量。
3. 在服务器侧改变 `test1`，表格自动变化；在本软件明确写入 `True`，服务器侧可读到 `True`。失败时不得伪造成功。
4. 验证离线添加、重复点、中文和空格、无效点、只读点、断线重连、旧事件丢弃、删除不影响服务器标签，以及保存后重开恢复配置。另用已有 `endpointUrl` 方案验证迁移，尤其检查旧 `host/port` 为无关默认值时仍以原端点连接、端点非根路径不丢失。
5. 验证行选中切换、同名数据点、排序和实时更新时选中项不漂移；无选择、删除选中行、切换设备时公共 NodeId 正确清空。
6. 监视持续运行期间，窗口点击、编辑、滚动和关闭保持响应。按用户此前要求，实施后先做 Debug 构建和相关自动化测试；KEPServerEX 真机联调、WPF 运行时布局及 VS 设计时分别记录人工验收结果。
