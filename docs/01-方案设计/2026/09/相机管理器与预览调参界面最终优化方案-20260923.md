# 相机管理器与预览调参界面最终优化方案

日期：2026-09-23  
状态：完整方案已确认；界面整合第一阶段已实现，显式采集控制与参数分层待继续实施

## 1. 目标与原则

让用户在同一个相机设置窗口完成：**选择设备 → 自动连接 → 调整参数 → 应用到相机 → 开始采集 → 在图像控件中确认实际画面**。

本软件面向多品牌、多接口相机。MVS Demo 只作为操作流程和 SDK 行为的参考，不照搬海康的参数清单、UI 或参数假设。通用界面依赖统一相机能力契约；每个品牌/接口适配器负责映射自己的 SDK 能力。

设计原则：

- 用户常用功能简单、明确；设备 SDK 能提供的完整参数仍保留在高级属性中。
- 参数能力、枚举选项、读写权限、可用状态和值以当前设备/SDK 为准，不由 UI 猜测或伪造。
- 参数编辑后自动写入相机；开始/停止取流、触发一次是独立操作；图像预览控件只显示实际收到的帧。
- 不改变用户熟悉的相机管理器整体布局，仅收敛详情区域并提供单一设置入口。

## 2. 相机管理器布局

- 沿用现有设备列表和详情区域。
- 详情区域只保留“基本信息”Tab；参数设置移至独立相机设置窗口。
- 基本信息展示名称、厂商、型号、IP 和连接状态。
- “预览”按钮继续放在基本信息中，不移到设备列表。
- 点击“预览”自动连接相机，成功后打开相机设置窗口；连接失败显示明确错误，不打开空白窗口；已连接时复用现有会话。
- 不在详情区域放置独立的连接、断开或重复编辑按钮。
- 移除参数 Tab 后可适当收窄管理器；具体尺寸以设备列表和基本信息不被截断为准。

```text
┌────────────── 相机管理器（沿用当前布局）──────────────┐
│ 设备列表                       │ 基本信息             │
│                                │                      │
│ 相机 A                         │ 名称：相机 A         │
│ 相机 B                         │ 厂商：海康           │
│                                │ 型号：MV-xxxx        │
│                                │ IP：192.168.1.10     │
│                                │ 状态：未连接         │
│                                │              [预览]  │
└────────────────────────────────┴──────────────────────┘
```

## 3. 相机设置窗口布局

一个独立窗口同时放图像预览、采集操作和参数面板，三者使用同一相机会话。参数区支持常用参数和高级属性；图像区使用 SDK 图像显示控件。

```text
┌──────────── 相机设置：相机 A ──────────────────────────────┐
│ 已连接 · 采集状态 · AcquisitionMode / TriggerMode / Source │
│ [开始采集] [停止采集] [触发一次]                           │
├──────────────────────────────┬────────────────────────────┤
│                              │ 参数设置                   │
│                              │ [搜索参数……]               │
│         实时图像预览         │ ▾ 常用参数                  │
│                              │   曝光 / 增益 / 自动控制    │
│                              │   帧率 / 触发 / 图像格式    │
│                              │ ▸ 高级属性                 │
├──────────────────────────────┴────────────────────────────┤
│ 参数应用结果 / SDK 回读值 / 取流状态 / 最新帧状态          │
└───────────────────────────────────────────────────────────┘
```

打开窗口时自动连接并读取设备参数，但不暗中启动采集。若选中设备阶段因被其他相机软件占用而导致参数树读取失败，预览连接成功后必须用当前已连接会话重试读取；不得要求用户删除并重新添加设备。用户通过明确的开始操作启动取流；关闭窗口时停止该窗口的取流并释放会话。

## 4. 多品牌参数接入与呈现

### 4.1 常用参数：标准功能视图

常用参数按跨品牌的标准相机功能组织，例如曝光、增益、自动控制、采集/触发配置、帧率、图像尺寸和像素格式。适配器只在相机实际支持某项功能时提供该项；不支持就不显示，不填默认值冒充支持。

通用功能应有稳定的标准标识，适配器负责将标准功能映射到各自 SDK 节点。例如多个品牌都支持“曝光时间”，但底层节点名、单位、约束、枚举值或写入时机可以不同。

### 4.2 高级属性：完整设备属性

完整读取并保留适配器从设备 SDK 获取的属性，不等于默认全部平铺给用户。高级区按类别分组并可搜索，提供设备级/厂商专属/专业调试属性。未知厂商节点保留 SDK 原名，不误译、不静默丢弃。

只读属性以只读形式显示；仅当节点可用、已实现且 SDK 确认可写时才提供编辑控件。枚举下拉项必须来自相机 SDK 返回的有效选项。未实现或当前不可用的节点不放进常用视图。

### 4.3 参数描述契约

统一参数描述至少应能表达：

- 标准功能标识（若能映射）与原始 SDK 节点名；
- 品牌/适配器来源、类别路径、显示名称和可见级别；
- 参数类型、当前值、范围/步进/单位及 SDK 枚举项；
- 已实现、当前可用、可读、可写状态；
- 动态依赖/Selector 关系；
- 修改时机策略：允许实时写入、需要停止取流后写入，或需要重新连接/初始化。

通用功能优先进入常用视图；其他节点进入高级属性。SDK 节点全集留在适配器/schema 中，不能因为 UI 默认隐藏就从接入层删掉。

## 5. 应用参数与采集控制

MVS C# WPF BasicDemo 的参考流程是：读取/设置常用参数；开始和停止 SDK 取流；按相机触发配置选择连续或触发行为；软触发命令只有在取流已启动且软件触发有效时才执行。该操作关系可复用，海康参数本身不可直接作为所有品牌的软件规范。

### 参数即时生效

- 常规可写参数编辑后自动写入相机；控件连续变化时做短暂合并（约 350 ms），避免 NumericUpDown 每个中间值都产生一次 SDK 调用。
- 写入后优先只回读变更节点并更新当前值；Selector、采集模式、图像尺寸/格式等可能改变其他节点权限或范围的参数，才重新读取完整 Schema。单独切换 TriggerMode/TriggerSource 只需读回新值并刷新预览状态，不重扫整棵参数树。
- 参数是否需要停流由适配器按设备能力判定。MVS BasicDemo 在取流线程运行时直接写 TriggerMode/TriggerSource，故 MVS 这两个节点按在线写入处理；采集模式和 ROI/像素格式仍按停流处理。普通节点写入不应等待图像 SDK 的取帧超时。
- MVS 将帧缓冲区读取与设备参数操作分开串行：只保证同一时刻一个取帧调用，但不让阻塞中的 `GetImageBuffer` 持有参数写入锁；以 BasicDemo 的取流线程与 UI 线程并行操作作为适用依据。其他厂商适配器可根据其 SDK 线程安全约束采用不同策略。
- 需要停止取流的参数自动暂停、写入、回读并恢复；不要求停流的参数不重启取流。
- “开始采集”仍作为保险，会先提交尚未完成自动写入的编辑；但日常修改参数不需要再找单独的“应用参数”按钮。
- 写入/回读结果与自动曝光、自动增益覆盖提示显示在状态区；“参数即时生效”表示 SDK 已应用到设备，图像变化需等设备输出下一帧（软件触发则需再触发一次，硬触发则等外部触发）。

### 开始/停止取流

- “开始采集”调用当前相机适配器的启动取流能力，取得的真实帧转换后提交到图像控件。
- 点击开始时若仍有待应用参数，先应用并确认成功；失败则不启动。
- “停止采集”停止 SDK 取流，图像控件保留最后一帧。
- 预览工具栏将“连续采集/停止采集”合并为一个随取流状态切换的按钮；另提供“单次采集”。单次采集按当前真实相机配置执行：连续模式取下一帧后自动停止；软件触发模式发送一次软件触发并在收到帧后自动停止；硬件触发模式等待一次外部触发后自动停止。单次采集中不提供取消：禁用“单次采集”避免重复排队，连续采集按钮显示“连续采集”并禁用；完成后恢复可用。它不临时改写相机的 AcquisitionMode/TriggerMode/TriggerSource。独立“触发一次”保留给需要连续处于触发取流状态、逐次手动调试的场景。
- 停止请求期间，MVS `GetImageBuffer` 若因 SDK 等待超时返回无数据，应作为取消后的正常退出处理，并完成 UI 采集状态复位；不得把停止过程中的超时当成采集故障而遗留“停止采集”状态。
- “连续/触发”状态从实际参数回读；不在工具栏另建一套与参数树冲突的模式状态。

### 触发与单帧语义

- 触发关闭且 `AcquisitionMode` 为连续时，开始取流后连续接收帧。
- 触发开启、软件触发源时，取流已启动并等待触发；“触发一次”才调用设备的软件触发命令，每次成功触发后由图像控件显示收到的新帧。
- 触发开启、硬件触发源时，取流等待外部信号；不能误切换成连续或软触发。
- “触发一次”不是通用“单帧采集”。`AcquisitionMode=SingleFrame` 是设备参数模式；仅在适配器确认设备支持且定义清楚时，才提供相应单帧模式行为。
- 预览控件只显示帧，不独立启动取流、不修改触发配置，也不调度工作流。

## 6. 统一架构边界

```text
相机设置窗口
  ├─ 常用参数 / 高级属性
  ├─ 开始 / 停止 / 触发一次（参数编辑自动写入）
  └─ 图像控件（只显示帧）
          │
统一相机会话与采集接口
          │
各品牌/接口适配器（MVS、其他厂商、GenICam 等）
          │
设备 SDK：节点发现与读写、取流、触发、取帧
```

UI 负责交互和状态展示；适配器负责设备差异及 SDK 调用细节；相机会话负责同一设备的连接和采集资源生命周期。不能由 UI 为单一品牌硬编码参数行为，也不能让预览控件和参数面板分别创建/管理相机连接。

## 7. 日志与诊断

使用统一 camera id 和 correlation/trace id 串联：用户操作、待提交值、SDK 写入及返回码、设备回读值、开始/停止取流、触发命令及返回码、帧获取/超时、帧尺寸与像素格式、图像转换和控件提交结果。高频取帧日志需限频采样，错误和状态转变不能丢失。

## 8. 验收标准

1. 相机管理器沿用当前设备列表/详情结构，基本信息中的“预览”是唯一设置入口；连接失败有明确错误。
2. 设置窗口共享一个相机会话，展示图像、采集控制和参数；进入窗口后不会无提示地开始取流。
3. 常用参数只显示设备支持的标准功能；高级属性仍可找到完整 SDK 节点；未实现/不可用参数不会伪装成可编辑。
4. 参数应用有真实 SDK 返回和读回值；更改曝光/增益后可从后续帧与日志确认写入是否生效。若自动控制或图像内容影响观察，应能识别该原因。
5. 开始/停止真实控制取流；停止后保留最后一帧；软/硬触发遵循设备配置；触发一次只在能力允许时可用。
6. 至少覆盖模拟相机和两种真实品牌/接口适配器，验证标准功能映射、专属参数保留、权限状态和不同修改时机。
7. 关闭设置窗口后取流与会话按既定策略释放，不遗留后台线程或 SDK 句柄。

## 10. 最终参数树与相机设置界面方案（2026-09-24）

### 10.1 设计原则

相机原生 GenICam 属性树是参数结构的权威来源。适配器通过 SDK 获取相机 XML 节点的分类、顺序、类型、权限、范围、枚举项和依赖关系；UI 不再把节点打散后按中文名称排序。原生属性树必须尽量保持厂商相机软件的分类、层级和顺序，多品牌差异由适配器隔离。

“常用属性”是跨品牌标准功能的快捷视图，不替代原生属性树；ROI、AOI、LUT、事件批量配置和用户集等复杂能力使用专用编辑器或操作视图。

### 10.2 最终界面结构（ASCII）

```text
相机设置
├─ 顶部采集栏：[连续采集/停止] [单次采集] [触发一次]
│              采集模式：实际值  触发模式：实际值  触发源：实际值
├─ 原生属性树
│  ├─ 收藏属性
│  ├─ 设备控制
│  ├─ 图像格式控制
│  ├─ 采集控制
│  ├─ 模拟控制
│  ├─ 用户查找表控制
│  ├─ 数字IO控制
│  ├─ 计数器和定时器控制
│  ├─ 文件访问控制
│  ├─ 事件控制
│  ├─ 数据块控制
│  ├─ 传输层控制
│  └─ 用户集控制
├─ 常用属性
│  ├─ 基本属性
│  ├─ ISP
│  └─ 传输层控制
├─ 触发
│  ├─ IO输入

├─ 高级功能
│  ├─ ROI

├─ 图像预览区：只显示真实帧，不覆盖相机触发配置
└─ 状态栏：连接、采集、触发、帧号、回读值、错误和耗时
```

### 10.3 参数获取和显示链路

```text
相机内部 GenICam XML
        ↓
MVS/厂商 SDK 解析
        ↓
GetRootNode / GetChildren
        ↓
读取节点类型、权限、分类、顺序
        ↓
按 Integer/Float/Boolean/String/Enum/Command 读取真实值
        ↓
CameraParameterDescriptor（保留 XmlOrder 和 CategoryPath）
        ↓
原生属性树：严格按 XML 顺序
常用属性：按 StandardFeature 映射
高级功能：专用编辑器
        ↓
NumericUpDown / ComboBox / ToggleSwitch / 只读显示 / 命令按钮
```

AM_NI 和 AM_NA 节点保留在适配器诊断数据中，但普通参数树不显示；AM_RO 节点保留并只读显示；只有 SDK 确认可写且当前可用的节点才显示编辑控件。

### 10.4 关键功能边界

- ROI 是输出图像区域，修改通常需要停流并重建帧格式；AOI 是自动曝光/自动增益等算法的参考区域，通常不改变输出尺寸。
- LUT 使用曲线编辑器，不展开成数百或数千个普通节点；保存、导入、导出和清除都按命令节点处理。
- 事件控制信息是 `EventSelector`/`EventNotification` 的批量视图；复选框表示是否启用通知，不代表事件已经发生，真实事件需要独立 SDK 回调链路。
- Chunk/数据块模式会改变帧附加元数据，适配器必须分离主图像和 Chunk 信息，并将帧号、时间戳、实际曝光/增益写入诊断状态。
- 用户集加载后必须重新读取完整 Schema、参数值、采集模式和触发配置，不能只更新当前用户集文本。
- GEV 传输层参数只在设备支持 GigE Vision 时显示；网络流参数修改按适配器能力决定是否停流和重建连接。

### 10.5 验收重点

1. 原生属性树分类和参数顺序与相机 XML/厂商软件一致。
2. 常用属性只作为快捷视图，修改后能定位回原生节点。
3. Selector、自动控制、ROI、像素格式和用户集切换后，权限、范围、枚举项和当前值正确刷新。
4. 只读节点不再显示为可编辑 NumericUpDown、ComboBox 或 ToggleSwitch。
5. 参数写入必须有 SDK 返回码和设备回读值；预览使用后续真实帧验证效果。
6. 连续、单次、软件触发和硬件触发完全遵循实际相机配置。
7. 不支持某类接口能力的相机不显示对应厂商专属参数；适配器不得把海康 GEV 参数硬编码到通用 UI。

### 10.6 与当前实现的结构对齐

当前代码已将“高级属性”调整为“高级功能”：完整有效 SDK 参数只在“属性树”中展示；高级功能视图按参数名称和 XML 分类识别 ROI、AOI、查找表、事件控制信息、Chunk 数据和用户集操作节点。该阶段仍使用统一参数表承载这些节点，后续再替换为 ROI/AOI/LUT 等专用编辑器；未匹配到高级功能的厂商参数不会丢失，仍保留在原生属性树中。Debug 构建已验证通过（0 错误、744 警告，输出 `dev\\Debug`），未构建 Release，未做真实相机验收。
