# 相机管理器最终重构方案

> 日期：2026-09-24  
> 状态：最终设计方案，待分阶段实施  
> 重要约束：现有预览窗口保持实现，不重做预览界面和采集交互

## 1. 总体结论

当前相机管理器将设备列表、设备持久化、设备发现、连接会话、参数读写、预览采集和窗口生命周期耦合在一起，导致以下问题：

- 关闭管理器窗口影响相机连接；
- 参数读取和预览可能重复创建连接；
- 同一设备出现 `already in use`；
- 连接故障时参数区域被清空；
- 参数状态、连接状态和采集状态互相覆盖；
- 设备配置、运行时会话和 UI 对象边界不清晰。

最终原则：

> 设备管理器管理设备，现有预览窗口调试相机，连接管理器管理会话，参数服务管理参数，当前方案负责持久化。

## 2. UI 目标

### 2.1 设备管理器

设备管理器只负责设备列表和设备操作，不再显示相机参数。

设备卡片包含：

- 逻辑名称；
- 厂商、型号、接口和连接状态；
- 状态指示灯；
- 连接/断开 ToggleButton；
- 预览/调试按钮；
- 右键重命名和删除。

设备管理器移除：

- 常用属性面板；
- 参数平铺列表；
- 参数分类树；
- 参数读取按钮；
- 参数写入逻辑。

### 2.2 现有预览窗口

现有 `CameraPreviewWindow` 保持当前实现，不重做界面和采集交互，继续承载：

- 实时图像；
- 连续采集；
- 单次采集；
- 触发操作；
- 常用参数；
- 高级参数；
- 参数搜索、读取和写入。

设备卡片的“预览/调试”按钮直接打开现有预览窗口。

## 3. 运行时架构

```text
当前方案 / 应用
└─ CameraRuntimeComposition
   ├─ CameraBindingStore
   ├─ CameraDiscoveryService
   ├─ CameraConnectionManager
   ├─ CameraParameterService
   └─ CameraAcquisitionService
       ├─ CameraManagerView
       └─ CameraPreviewDebugView
```

### 3.1 设备配置层

持久化对象保存逻辑设备信息：

```text
CameraBinding
├─ 逻辑名称
├─ DeviceId
├─ 序列号
├─ MAC
├─ 厂商
├─ 型号
├─ 接口
├─ 最近 IP
├─ 是否启用
├─ 是否自动连接
└─ 参数覆盖配置
```

不保存 SDK 句柄、`CameraSession`、预览窗口、采集线程和实时连接状态。

### 3.2 发现层

负责搜索设备、更新设备信息并注册到运行时。

设备身份匹配优先级：

1. 厂商 + 序列号；
2. 厂商 + MAC；
3. 稳定 `DeviceId`；
4. IP 仅作为辅助匹配条件。

刷新发现结果时不能清空已保存设备。设备离线时保留设备记录并显示“离线”。

### 3.3 连接层

所有连接操作必须经过统一的 `CameraConnectionManager`：

```text
Acquire(deviceId)
Release(deviceId, owner)
Disconnect(deviceId)
TryGetSession(deviceId)
```

同一台设备只能有一个底层 SDK 会话。设备管理器、预览窗口和参数服务只能复用该会话，不能分别调用底层 `OpenAsync` 创建第二个连接。

## 4. 生命周期规则

### 4.1 打开预览

```text
设备未连接
    ↓
连接管理器建立连接
    ↓
打开现有预览窗口
```

```text
设备已连接
    ↓
复用已有连接
    ↓
打开现有预览窗口
```

### 4.2 关闭预览

```text
关闭预览
    ↓
停止采集
    ↓
释放采集引用
    ↓
保持设备连接
```

关闭预览不能自动断开设备。

### 4.3 关闭设备管理器

关闭设备管理器只释放窗口和 UI 对象，不释放方案级相机运行时和连接会话。

再次打开管理器时，读取共享运行时中的真实设备状态，不能重新创建第二个会话。

### 4.4 方案切换和应用退出

切换方案或退出应用时统一：

- 停止采集；
- 释放参数访问；
- 断开设备；
- 释放 SDK 资源；
- 释放运行时对象。

## 5. 参数管理

参数继续放在现有预览窗口中，但参数状态必须与连接状态分离。

```text
ParameterSchemaState
    参数定义是否存在

ParameterValueState
    当前值是否已读取、是否过期

ConnectionState
    设备当前是否连接

AcquisitionState
    当前是否正在采集
```

合法状态示例：

```text
设备：未连接
参数结构：已加载
参数值：上次读取值，已过期
采集：未运行
```

设备断开时：

- 不清空参数列表；
- 保留参数分类；
- 保留上次读取值；
- 参数控件变为只读；
- 显示“设备未连接，当前显示缓存参数”。

设备重新连接后复用已有 Schema，读取当前值并更新状态。

参数读取失败只标记参数读取失败，不应把整个设备或参数文档清空。

## 6. 参数修改规则

### 6.1 在线修改

```text
修改参数
    ↓
进入写入队列
    ↓
写入设备
    ↓
读回确认
    ↓
更新 UI 状态
    ↓
保存参数覆盖配置
```

### 6.2 离线修改

```text
修改参数
    ↓
保存为本地草稿
    ↓
显示“待设备连接后应用”
    ↓
设备连接成功
    ↓
统一应用待提交参数
```

需要停止采集的参数按以下流程处理：

```text
停止采集 → 写入参数 → 刷新依赖节点 → 恢复采集
```

## 7. 持久化

设备配置跟随当前本地方案保存到 `Solution.Devices`。

保存内容：

- 逻辑名称；
- `DeviceId`；
- 序列号；
- MAC；
- 厂商和型号；
- 接口；
- 最近 IP；
- 是否启用；
- 是否自动连接；
- 参数覆盖值。

保存时机：

- 添加设备；
- 删除设备；
- 重命名确认；
- 修改启用状态；
- 修改自动连接设置；
- 修改参数覆盖值；
- 保存方案；
- 关闭方案前。

重新打开方案时重新发现设备，按稳定身份匹配。连接状态不写入方案文件，而是在运行时重新建立。

## 8. 代码职责

```text
CameraManagerViewModel
    设备列表、增删改、连接命令、打开预览

CameraConnectionManager
    连接会话、会话复用、断开

CameraParameterService
    参数 Schema、参数读取、参数写入、参数缓存

CameraAcquisitionService
    连续采集、单次采集、触发、停止采集

CameraPreviewWindow
    保持现有界面和交互，仅改为使用统一服务
```

`CameraPreviewWindow` 不重新设计，重点调整其底层连接和参数访问来源。

## 9. 实施顺序

### 第一阶段：统一连接会话

- 统一连接和断开入口；
- 增加会话复用；
- 解决 `already in use`；
- 管理器关闭不再释放连接；
- 预览关闭只停止采集。

### 第二阶段：调整设备管理器

- 删除管理器右侧参数区域；
- 在设备卡片增加“预览/调试”按钮；
- 按钮打开现有预览窗口；
- 管理器只保留设备管理和连接控制。

### 第三阶段：参数状态解耦

- 参数 Schema 独立缓存；
- 断开后保留参数界面；
- 参数值支持过期状态；
- 支持离线参数草稿；
- 连接后应用待提交参数。

### 第四阶段：完善方案持久化

- 保存设备绑定；
- 保存自动连接配置；
- 支持设备离线恢复；
- 方案切换时释放旧设备；
- 应用退出时统一释放资源。

## 10. 验收标准

- 关闭设备管理器不会断开相机；
- 再次打开管理器能显示真实连接状态；
- 点击预览不会创建第二个连接；
- 不再出现 `Camera is already in use`；
- 预览窗口继续使用当前实现；
- 关闭预览只停止采集，不影响连接；
- 管理器不再承担参数显示和参数读取；
- 参数全部在现有预览窗口中调试；
- 设备断开后参数不会被清空；
- 设备重连后可以刷新参数；
- 故障状态下 ToggleButton 可以重试；
- 相机配置能随方案保存和恢复；
- 设备离线时仍保留在设备列表；
- 方案切换和应用退出时正确释放连接。
