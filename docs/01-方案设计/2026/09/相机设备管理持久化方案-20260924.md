# 相机设备管理持久化方案

> 日期：2026-09-24  
> 范围：相机设备管理器的设备列表、设备身份、用户配置和本地方案保存  
> 状态：设计方案，尚未实施代码

## 1. 目标

解决相机设备管理器关闭、重新打开或重启软件后设备列表丢失的问题，并保证用户重命名、启用状态和设备配置能够跟随当前方案保存到本地。

本方案只描述持久化设计，不改变当前连接、预览和采集会话的运行时生命周期。

## 2. 保存位置

设备配置保存到当前方案的本地文件中，不能只保存在内存，也不建议作为全局用户配置保存。

```text
当前方案目录/
├─ Solution.json
├─ Devices/
│  └─ Cameras.json
└─ Workflows/
```

推荐由方案统一管理设备配置；`Devices/Cameras.json` 可以作为物理文件，也可以在方案序列化时内嵌到 `Solution.json`，最终以现有方案存储架构为准。对 UI 来说必须只有一个读写入口，不能同时维护两份来源。

这样可以保证不同方案拥有各自的相机列表，方案复制、迁移和备份时设备配置能够一起携带。

## 3. 持久化模型

运行时的 `CameraDevice` 不直接作为序列化模型。应增加独立的 `CameraBinding` 配置模型：

```csharp
public sealed class CameraBinding
{
    public string Id { get; set; } = string.Empty;
    public string DisplayName { get; set; } = string.Empty;
    public string DeviceId { get; set; } = string.Empty;
    public string SerialNumber { get; set; } = string.Empty;
    public string MacAddress { get; set; } = string.Empty;
    public string Manufacturer { get; set; } = string.Empty;
    public string Model { get; set; } = string.Empty;
    public string Transport { get; set; } = string.Empty;
    public string IpAddress { get; set; } = string.Empty;
    public bool IsEnabled { get; set; } = true;
    public bool AutoConnect { get; set; } = true;
    public DateTime AddedTime { get; set; }
    public Dictionary<string, object?> ParameterOverrides { get; set; } = new();
}
```

### 保存内容

- 用户显示名称，包括重命名结果；
- `DeviceId`、序列号、MAC、厂商、型号和接口；
- 最近一次发现到的 IP 地址；
- 是否启用；
- 是否自动连接；
- 添加时间；
- 用户修改过的常用参数覆盖值。

### 不保存内容

- `IsConnected`、`CameraState` 等实时状态；
- `CameraSession`、SDK 句柄和 WPF 控件；
- 预览窗口、采集线程和后台任务；
- 仅用于本次运行的错误信息。

连接状态必须在程序启动或方案打开后重新建立，不能尝试恢复旧句柄。

## 4. 设备身份匹配

设备重新发现后，不能只用 IP 地址匹配。建议按以下顺序匹配：

1. 厂商 + 序列号；
2. 厂商 + MAC 地址；
3. 稳定的 `DeviceId`；
4. IP 地址仅作为最后的辅助匹配条件。

匹配成功时保留本地的逻辑名称和用户配置，并用本次发现结果更新在线状态、IP 和能力信息。匹配失败时不能删除配置，应保留设备并显示“离线”。

## 5. 加载流程

```text
打开本地方案
    ↓
读取 CameraBinding 列表
    ↓
恢复设备列表和用户名称
    ↓
重新发现物理设备
    ↓
按稳定身份匹配
    ├─ 匹配成功：显示在线，可按 AutoConnect 自动连接
    └─ 匹配失败：保留记录，显示离线
```

刷新设备发现时只能更新在线信息，不能清空已保存的设备列表。

## 6. 保存时机

以下操作完成后应标记方案为已修改，并由统一的方案保存服务持久化：

- 添加设备确认；
- 删除设备；
- 重命名确认；
- 修改启用状态；
- 修改自动连接设置；
- 修改常用属性；
- 方案保存和方案关闭前的最终保存。

建议使用“脏标记 + 防抖保存”机制，避免参数编辑时每一次输入事件都直接写文件。重命名回车确认、失焦确认或取消时要明确区分是否产生变更。

取消添加不能写入设备配置，也不能留下运行时会话。

## 7. 自动连接规则

添加后的自动连接和方案重新打开后的自动连接要分开处理：

- 添加设备后：按当前产品交互规则默认立即连接；
- 方案重新打开后：只对 `AutoConnect = true` 的设备发起连接；
- 连接失败：保留设备配置，显示“连接失败”，不能删除设备；
- 预览关闭：不能改变预览打开前的设备连接状态；
- 程序退出：释放所有运行时会话，但不把连接状态写入配置。

## 8. 兼容和迁移

配置文件应带版本号：

```json
{
  "schemaVersion": 1,
  "cameras": []
}
```

加载时支持：

- 文件不存在：创建空设备列表；
- 旧版本缺少字段：使用默认值；
- JSON 损坏：保留原文件备份并提示用户，不能静默清空设备；
- 重复设备：按稳定身份合并，优先保留用户名称和最新修改时间较新的配置。

## 9. 实施拆分

### 第一阶段：设备列表持久化

1. 增加 `CameraBinding` 和方案设备集合。
2. 实现当前方案的读取和保存入口。
3. 添加、删除、重命名、启用状态接入持久化。
4. 关闭并重新打开方案后恢复设备列表。
5. 离线设备保留并显示离线状态。

### 第二阶段：连接策略

1. 增加 `AutoConnect` 配置。
2. 方案加载后按配置自动连接。
3. 区分“用户主动连接”和“自动连接失败”。
4. 验证预览关闭不改变原始连接状态。

### 第三阶段：参数持久化

1. 只保存用户修改过的参数覆盖值。
2. 设备连接成功后按能力和权限应用参数。
3. 对设备不支持或不可写的参数给出提示，不阻止设备列表加载。

## 10. 验收标准

- 添加相机后关闭管理器，再次打开仍能看到设备。
- 重命名后关闭软件，重新打开名称不丢失。
- 保存方案、关闭软件、重新启动后设备配置仍存在。
- 修改 IP 后重新发现，仍能匹配到原逻辑设备。
- 设备离线时配置保留，不被刷新操作删除。
- 取消添加不产生配置变化。
- 预览前已连接的设备，关闭预览后仍保持连接。
- 预览前未连接的设备，预览关闭后恢复未连接。
- 不同方案之间的相机列表互不污染。
