# 相机采集架构整改实施计划

**制定日期：** 2026-09-19  
**状态：** 实施基线  
**依据：**

- `相机采集架构与设备管理最终方案-20260918.md`
- `相机采集架构实施评审与整改方案-20260919-134250.md`

## 1. 总体目标

将当前相机模块从“架构骨架和界面可用”推进到“真实设备可连接、可采集、可持久化、可进入工作流”的正式实现。

最终链路：

```text
自动发现
  ↓
设备绑定与持久化
  ↓
CameraRuntimeManager 注册设备
  ↓
打开唯一会话
  ↓
连接 / 参数 / 单帧 / 连续采集
  ↓
预览与状态同步
  ↓
工作流相机采集工具
  ↓
CameraFrame → IVisionImage → 工作流输入
```

本计划明确：

- 不恢复 `ICameraService`、`CameraPoolManager` 等旧契约；
- 不新增旧契约兼容 Facade；
- 旧实现由 Git 历史保留；
- 新架构以 SDK 相机无关契约、`CameraRuntimeManager` 和厂商适配器为唯一正式入口。

## 2. 实施原则

1. 先修复真实运行链路，再扩展工作流契约和高级体验。
2. UI 不伪造设备状态，所有连接状态来自 Runtime/Session。
3. 每个设备同一时间只能存在一个有效访问会话，访问冲突返回明确错误码。
4. 设备发现信息与用户绑定配置分离保存。
5. 运行时使用快照，不直接读取执行期间变化的 UI 参数。
6. 每个阶段完成后进行构建、测试和必要的人工验收。

## 3. 阶段一：运行时核心整改

### 3.1 `CameraRuntimeManager`

- 增加设备级异步锁，将“检查—创建适配器—连接—登记会话”纳入串行区。
- 同一设备已有会话时返回 `DeviceBusy`，不再只抛普通异常。
- 连接失败时完整释放适配器和临时会话。
- 按 `Diagnostic`、`Preview`、`Capture`、`Exclusive` 管理访问模式。
- 所有连接、断开、采集、参数操作记录 `DeviceId`、操作名、访问模式、耗时和错误码。

### 3.2 采集会话生命周期

- `CaptureAsync` 优先复用已有可用会话。
- 没有会话时创建临时会话，采集完成后释放。
- 连续采集和预览持有稳定会话，禁止每帧重新连接设备。

### 3.3 阶段验收

- 两路并发打开同一设备时只有一路成功。
- 连接、详情、预览看到同一个真实状态。
- 断开后没有残留会话或 SDK 句柄。
- 连续采集 10 帧只连接一次。
- 关闭预览后设备会话被正确释放。

## 4. 阶段二：设备绑定与管理流程

### 4.1 配置模型

将设备发现信息和用户绑定配置分离：

```text
CameraDescriptor
  DeviceId / 序列号 / 厂商 / 型号 / 接口 / IP / 能力

CameraBinding
  用户名称 / 是否启用 / 默认参数 / 自动连接 / 绑定时间
```

绑定配置保存到当前 `Solution.Devices`，确保不同解决方案可以拥有不同的设备配置，并为未来用户管理和权限控制保留扩展空间。

### 4.2 自动发现

统一由 `CameraDiscoveryCoordinator` 管理：

- MVS GigE；
- MVS USB3；
- Simulation；
- 后续可扩展 GenTL 和其他厂商适配器。

发现结果必须包含设备身份、接口、在线状态、是否已绑定和能力摘要。发现失败必须返回来源和错误信息，不能静默显示“0 台设备”。

### 4.3 添加流程

第一版采用单设备添加：

```text
选择一台设备
  ↓
设置显示名称
  ↓
查看身份与能力
  ↓
测试连接
  ↓
测试单帧
  ↓
确认添加
```

添加前按 `DeviceId` 或序列号检查重复绑定。取消操作不得写入配置，也不得返回成功结果。

### 4.4 阶段验收

- 添加设备后关闭并重新打开管理器，设备仍然存在。
- 刷新重新发现设备，不清空已有绑定。
- 同一设备不能重复绑定。
- 取消添加不产生任何配置变化。
- 设备离线时保留绑定记录并显示离线状态。

## 5. 阶段三：管理器与详情页

### 5.1 命令整理

保留并接通：

- 添加；
- 删除；
- 刷新发现；
- 连接；
- 断开；
- 启用；
- 禁用；
- 保存。

没有实现的导出、全局设置等命令暂时删除或隐藏，不保留死命令。

### 5.2 选择模型

明确区分：

- `SelectedCamera`：当前查看详情的设备；
- `IsEnabled`：设备是否允许被工作流使用；
- `IsCheckedForBatch`：批量操作选择状态。

如果第一版不需要批量操作，则取消批量选择模型。启用列必须绑定 `IsEnabled`，不得绑定 `IsSelected`。

### 5.3 详情数据

详情页只显示有真实来源的数据：

- 名称、厂商、型号、序列号；
- 接口、IP、在线状态、连接状态；
- 当前访问模式；
- 当前帧率、最近采集延迟；
- 最近一次错误。

没有数据的字段隐藏，不显示恒定空值或固定 0。

### 5.4 会话与详情切换

- 切换设备不得关闭用户主动建立的连接。
- 参数页优先复用已有会话。
- 只有临时诊断会话才在完成参数读取后释放。
- 删除设备前确认并释放其会话。

## 6. 阶段四：海康 MVS 适配器

### 6.1 真机测试矩阵

必须人工验证：

- GigE 和 USB3 自动发现；
- 连接、断开和句柄释放；
- 单帧采集和连续采集；
- 曝光、增益、触发参数读写；
- 设备被其他程序占用；
- 两窗口同时连接；
- 拔网线、重新连接和恢复采集。

### 6.2 触发模式

- `Software`：配置软件触发并调用厂商软触发命令；
- `Hardware`：配置硬触发并等待外部触发，超时返回 `TriggerTimeout`；
- `Continuous`：启动连续采集流；
- 不支持的模式返回 `ParameterUnsupported`，不得静默降级。

### 6.3 断线重连

采用有限退避：

```text
1s → 2s → 5s → 10s → 30s
```

重连流程：停止旧采集、进入 `Reconnecting`、释放旧适配器、重新连接、重放参数快照、恢复预览或连续采集，失败后保留明确错误状态。

## 7. 阶段五：工作流接入

新增 `src/Workflow/Camera/`，至少包含：

- `CameraWorkflowBinding`；
- `CameraRunSnapshot`；
- `CameraFrameConverter`。

工作流链路：

```text
相机采集工具
  ↓
ICameraCaptureService
  ↓
CameraFrame
  ↓
IVisionImage
  ↓
WorkflowRunRequest
  ↓
图像工具节点
```

`CameraFrame` 增加可空的：

- `RunId`；
- `WorkflowId`；
- `NodeId`；
- `TriggerId`。

SDK 契约可以保存这些关联信息，但不得反向依赖 Workflow 程序集。

工作流启动时冻结设备引用、采集参数、触发模式、图像格式、超时和参数快照，执行期间不直接读取 UI 当前值。

## 8. 阶段六：完整主题适配

重点处理：

- `CameraDetailPanel.xaml`；
- `CameraManagerDialog.xaml`；
- `AddCameraDialog.xaml`；
- `CameraDataGridStyle`。

清除硬编码颜色，包括 `White`、`#999999`、`#F5F5F5`、`#4CAF50`、`#333333`、`#777777` 等，统一使用动态主题资源：

- `TextPrimaryBrush`；
- `TextSecondaryBrush`；
- `TextDisabledBrush`；
- `PanelBackgroundBrush`；
- `InputBackgroundBrush`；
- `InputBorderBrush`；
- `TableRowBackgroundBrush`；
- `TableRowSelectedBackgroundBrush`；
- `SuccessBrush`；
- `WarningBrush`；
- `ErrorBrush`。

完成亮色、暗色和运行时切换主题验收。设备状态统一使用“图标 + 文字 + 颜色”，逐步替换不可随主题变化的 Emoji 图标。

## 9. 执行顺序

```text
1. RuntimeManager 会话与真实连接
2. 管理器连接/断开/状态同步
3. 添加、删除、刷新、持久化
4. 详情页会话生命周期和真实数据
5. MVS 触发、采集、错误码和重连
6. 完整主题适配
7. 工作流 Camera 输入节点
8. 真机测试、Debug/Release 构建和验收文档
```

每批完成后必须执行：

```text
代码修改 → 单元测试 → Debug 构建 → 必要的人工验证 → 更新 CURRENT_TASK.md
```

## 10. 最终验收标准

- 相机可以自动发现并显示明确身份；
- 相机可以真实连接和断开；
- UI 状态与 Runtime 状态一致；
- 设备绑定可以保存并恢复；
- 预览不会每帧重复连接；
- 参数读写有效并有错误提示；
- 断线有明确状态并支持重连；
- 工作流可以使用相机图像；
- 亮色和暗色主题没有系统白底黑字残留；
- 关闭窗口和退出程序没有设备句柄泄漏；
- Debug 和 Release 构建通过，测试和真机验收结果有记录。
