# 通讯接收来源与目标绑定最终方案

日期：2026-09-30  
状态：方案基线；按阶段实施，未接通的运行时能力不得显示为已生效

## 1. 关键修正

“是否显示绑定地址”不由“是否寄存器类协议”决定，而由**接收事件是否必须定位设备内的具体数据目标**决定。目标可能是寄存器地址块、PLC 内存区域、CIP 对象属性或 OPC UA 变量节点；“地址”不是所有协议通用的界面名称。原始 TCP／UDP／串口通常只需绑定设备（若未来要区分 TCP 服务端的客户端，可另设客户端筛选条件，不冒充内存地址）。

设备管理维护可复用的目标定义；接收事件保存设备 ID 与目标的稳定身份，并显示可读名称和协议位置。删除目标后绑定应明确失效，不按同名目标自动重绑。

## 2. 协议能力与界面映射

| 来源 | 第二绑定项 | 当前目标定义 | 运行时交付给事件的数据 | 合适的规则 |
| --- | --- | --- | --- | --- |
| TCP／UDP／普通串口 | 无 | 原始连接 | 完整业务报文的字节；按设置解码 UTF-8 | 文本解析／比对、原始字节匹配 |
| Modbus | 绑定地址 | 已配置的地址块 ID | 读回寄存器的数据字节或按配置解释后的值，**不含完整 Modbus 帧头** | 字节区间解析／比对；有明确类型时可做数值比较 |
| S7 | 绑定内存地址 | 尚无持久化目标目录，当前仅手动读写参数 | 指定区域读回的数据 | 按区域、起始位置、长度解析；目标目录建成前不宣称事件已接入 |
| EtherNet/IP CIP | 绑定属性 | 尚无持久化目标目录，当前仅手动 Class／Instance／Attribute 参数 | 指定属性的返回值 | 按属性实际数据类型或字节规则 |
| OPC UA | 绑定数据点 | 已配置数据点的稳定 ID；接收事件下拉只展示名称，NodeId 在设备管理查看 | 原生类型值、状态码及时间戳 | 按实际类型比较；仅 String／ByteString 按需开放文本／字节规则 |

协议能力提供目标种类、候选目标、展示名称、可选处理方式及运行时载荷种类；UI 不再用 `IsModbus || IsS7` 当作“需要地址”的通用判断。绑定面板的第二行仅在目标种类不为 `None` 时出现。

## 3. 绑定契约

建议独立于解析字段的 `FieldId` 定义接收来源引用：

```text
DeviceId          稳定设备 ID
TargetKind        None / ModbusAddress / S7Memory / CipAttribute / OpcUaDataPoint
TargetId          已配置目标的稳定 ID；目标目录尚未建立的协议暂不提供“已绑定”承诺
TargetPathSnapshot 仅用于诊断显示，例如 0..19、DB1.DBW0、Class/Instance/Attribute、NodeId
```

目标定位与字段解析是两层不同的绑定：`DeviceId + TargetId` 决定**哪一次设备数据**进入事件；`FieldId` 决定**解析出的哪一个字段**供组装、触发和下游使用。运行时必须先按设备和目标筛选，再处理载荷，不能只按设备 ID 将一次轮询结果广播给所有事件。

设备更换、目标删除或目标类型不匹配时清除／标记失效绑定；目标重命名只刷新显示快照，不改变稳定身份。S7/CIP 应先建设可持久化的目标定义，当前自由文本或手动测试参数不能冒充稳定目标 ID。OPC UA 下拉只显示数据点名称，保持简洁；完整 NodeId 在设备管理的数据点详情查看，持久化仍引用数据点 ID。

## 4. 数据到达与解析边界

底层接收先更新共享的当前连接数据，再分别供接收事件判断和接收数据工具读取。工具不依赖事件存在、规则通过或触发工作流；手动执行与事件驱动执行使用同一读取语义。TCP／UDP／串口按节点接收当前会话未消费报文，不新增第二个 socket 读取者；已有未消费报文可立即接收，已消费报文不得跨轮复用，也不主动生成设备请求。Modbus／OPC UA 的主动读取和变量当前值读取保持各自协议语义。

事件结果是解析显示，不是接收工具的数据源。未配置事件或事件条件为 NG，不应阻止工具读取有效的当前载荷。以下流程描述事件分支，不是工具读取必须经过的前置链。

2026-10-14 已修复设备名称、描述变化误清空接收记录的问题。展示名称更新保留同一连接的数据身份；实质配置变化、断线或方案切换仍使当前记录失效，不回退到上一次连接的数据。本批只收敛设备名称／描述及来源显示元数据的比较，其他目标配置仍按当前保守失效规则处理。

TCP／UDP／串口按[被动报文逐次消费优化方案](../10/被动报文逐次消费优化方案-20261014.md)处理：同一节点每次成功接收一条未消费报文，无新报文则保持执行中，停止可取消。各节点独立游标，不清空其他节点的数据，事件判断不推进工具消费进度。断线、来源删除、方案重置或数据配置变化终止旧等待，旧会话数据不带入新会话。保留现有等待隔离，不新增超时或有效期。逐次消费核心已于2026-10-14实施并部署；读取进度按节点及稳定调用作用域隔离，首次订阅与容量边界见链接方案。用户真实方案验收待反馈。

```text
协议驱动取得数据 → 按 DeviceId + TargetId 选择事件 → 检查完整性／质量
→ 按载荷种类选择文本、字节或原生类型规则 → 原子发布 Value／Result／Status／历史
→ 由执行层消费成功事件并决定触发／回复
```

- TCP 原始数据是字节；文本模式严格 UTF-8 解码后先校验**整条字符长度**，再分隔。按当前用户验收口径，分隔结果保持 `string`，不把 `"4"` 隐式转为 `int`；类型不匹配时结果为空、状态 `NG`。字节模式则按字节长度与区间处理。
- VM 4.4 的 Modbus 示例绑定地址并轮询两个保持寄存器，对读回的 `00 5C 41 44` 四个**数据字节**按 `0..1`、`2..3` 做字节匹配，得到 `92` 与 `AD`。这证明 Modbus 的字节匹配可用，但匹配对象不是完整 RTU／TCP 帧。当前本项目地址轮询用 FC03；VM 文档限定保持寄存器和主机模式，不应据此推断它所有写入路径只用 FC03。
- 本项目接收事件的 Modbus `int` 解析按用户确认的数值口径：将 FC03 每个寄存器依次展开为高、低两个数据字节；按规则的闭区间截取 1～4 字节和规则内的字节顺序重排；拼接为十六进制字符串，再转十进制 `int` 用于数据结果与比较。例如 `00 5C` → `0x005C` → `92`，`41 44` → `0x4144` → `16708`。四字节遵循 `Int32` 补码语义，短字节序列按非负数解释；无效区间、未支持的类型或顺序清空结果并记 `NG`。这与 VM 示例把 `41 44` 解释成 ASCII `AD` 属于不同类型口径，不应混同。
- OPC UA 数据变化通知交付原生类型值及状态、时间戳；先检查质量，再按数值、布尔、文本、数组等实际类型开放规则。不要先转成 UTF-8 字符串或丢弃类型再做通用字节匹配。
- 解析失败、长度错误、质量不佳或失效绑定不更新部分字段，不沿用上次值；`Result` 清空，状态 `NG` 并留原因。成功解析后“不比较”才是 `OK`。历史保留原始来源、目标、时间和失败阶段；十六进制只是字节载荷的展示方式。
- UI 不调度工作流；事件发布与触发在执行层，以运行开始时的输入、参数和全局变量快照消费。

## 5. 分阶段实施与验收

### 比较规则（2026-09-30 修订）

| 字段与处理方式 | 下拉规则 | 参数与状态 |
| --- | --- | --- |
| `string`（文本解析或文本比对） | 不比较、等于、不等于 | 使用文本框；按原始字符串做严格相等／不等，失败为 `NG` |
| `Boolean`（OPC UA 原生数据点） | 不比较、等于、不等于 | 使用 `True`／`False` 比较；不将 TCP 文本 `"False"` 强制转为布尔值 |
| 数值字段（文本解析或文本比对） | 不比较、范围内、范围外 | 使用闭区间最小／最大值；文本 UTF-8 分割结果仍是 `string`，不会为范围规则强制转换，只有实际类型化的二进制输入可按数值比较 |
| 数值字段（字节匹配－协议比对） | 不比较、等于、范围内、范围外、上升沿、下降沿 | 等于使用单值文本框；范围内／外使用闭区间；沿按已解析整数的零态变化，首次样本仅建立基线、不会触发 |

“不比较”表示**解析成功后**规则通过，不表示忽略解析错误。比较规则不满足时保留本次数据结果、状态为 `NG`；解析错误则清空数据结果并 `NG`。字节规则当前仅 Modbus FC03 的 `int` 已接入运行时，其他类型和协议须显式失败。

1. **目标能力与 UI**：按协议显示目标行；Modbus 从地址块选择、OPC UA 从数据点选择，使用稳定 ID。S7/CIP 在缺目标目录时明确标注尚不可用于事件，避免自由文本看似可运行。保存／重载及设备切换后绑定正确。
2. **字节比对运行时**：Modbus FC03 的已绑定地址块可路由至接收事件，当前先支持 `int` 规则：展开数据字节、校验长度与区间、按规则顺序解释、比较并组装。`float`／`string`、ASCII 转换及其他协议仍需单独实现和验收；普通原始字节协议通过自己的报文路径，不复用 Modbus 帧头。
3. **类型化来源**：OPC UA 订阅按设备和数据点 ID 路由，保留原生类型、质量与时间戳。非 `String` 标量数据点对应一条解析规则，`Boolean` 可用“不比较／等于／不等于”；原生 `String` 在文本模式下按接收事件的分隔符从左到右分配到已配置字段，不做数值强制转换。尾部分隔符产生的空字段保留，超出已配置字段的片段不自动生成输出行；字符长度比较先于分割执行。质量或类型不符清空旧结果并标 `NG`。S7/CIP 建设可持久化目标目录后再接入对应读取／通知路径。
4. **事件消费**：成功事件发布到触发／回复执行层，失败不触发；测试目标删除、设备切换、不同协议同名目标、断线重连、重复轮询与历史。

每阶段以 Debug 构建和针对性自动测试验收，UI 还需分别核对设计时、运行时与用户实际设备验收。当前已接入 Modbus FC03 地址块的 `int` 字节规则，以及 OPC UA 已绑定数据点的原生标量接收、`String` 文本分割与 `Boolean` 比较；OPC UA 数组／结构体、其他字节规则及 S7/CIP 接收事件尚未接入，事件触发／回复执行链仍未接通。
