# 通讯管理器 Modbus 地址空间与调试最终优化方案

## 1. 方案目标

通讯管理器同时支持两类场景：

- 地址空间：用于长期保存寄存器地址、轮询、数据采集、变量关联和地址级记录。
- 手动调试：用于现场验证 Modbus 连接、功能码和寄存器读写。

两类场景共存，但职责分开。当前先聚焦寄存器功能，线圈读写暂不纳入本阶段，后续需要时再扩展。

## 2. Modbus 通讯参数

### 2.1 Modbus TCP

显示：

- 通信方式：TCP Client
- 目标 IP
- 目标端口
- 站号
- 轮询间隔
- 自动重连

### 2.2 Modbus RTU

显示：

- 通信方式：串口
- 串口号
- 波特率
- 数据位
- 停止位
- 校验位
- 超时时间
- 站号
- 轮询间隔
- 自动重连

串口号和波特率使用 ComboBox，创建、切换设备和重新打开方案后必须保留原配置。

## 3. 当前阶段支持的手动操作

手动操作区保留当前操作下拉框，但只显示寄存器相关操作：

- 读取离散输入
- 读取保持寄存器
- 读取输入寄存器
- 写单个寄存器
- 写多个寄存器

暂时移除：

- 读取线圈
- 写单线圈
- 写多个线圈

手动操作区用于临时输入起始地址、数量和写入值，验证设备和协议是否正常。

## 4. 地址空间业务

地址空间采用 VM 的地址块模式，优先管理寄存器地址点。

每个地址块包含：

- 地址名称，例如 `1 Address`
- 起始寄存器地址
- 寄存器数量
- 数据类型
- 数据位数
- 字节顺序
- 读写属性
- 轮询是否启用
- 轮询周期
- 变量关联
- 当前值
- 接收记录

连接参数属于设备级配置，地址块只保存寄存器业务配置，不重复保存 IP、端口、串口号等连接参数。

## 5. 地址空间表格

表格以 VM 已完成的 Modbus 界面为最终参考，不采用地址块卡片堆叠作为正式界面。设备创建完成后，在同一页面直接显示“寄存器地址”和“地址空间”区域。

### 5.1 VM 基线布局

寄存器地址区域包含：

- 首地址：默认 `0`。
- 寄存器个数：默认按设备配置生成，例如 `50`。

地址空间区域包含：

- 顶部地址偏移列 `0` 至 `9`。
- 左侧十位地址行 `0`、`10`、`20`、`30`……。
- 右侧垂直滚动条，用于浏览更大的寄存器空间。
- “最大化”：扩大地址空间区域。
- “隐藏空白行”：隐藏没有配置内容的地址行。
- “清空”：清空当前设备的地址块配置，执行前需要二次确认。

表格底部包含：

- 创建总数。
- 轮询状态图例。
- 读/写状态图例。
- 关联状态图例。
- “数据同步”。
- “发送测试”。

表格采用 VM 的地址空间显示方式：

- 顶部显示地址偏移：0、1、2、3……
- 左侧显示十位地址：0、10、20、30……
- 每个单元格对应一个实际寄存器地址。
- 已配置地址块使用统一颜色显示。
- 地址块第一位上方显示归属名称，例如 `1 Address`。
- 归属条横跨该地址块占用的全部单元格。

用户可以直接看出哪些单元格属于 Address 1、Address 2，以及每个地址块的起止范围。

### 5.2 地址块归属显示

地址块创建后直接绘制在统一地址空间表格中：

- 地址块覆盖的每个寄存器单元格保持连续可见。
- 地址块第一位上方显示归属名称，例如 `1 Address`。
- 归属条横跨地址块占用的全部单元格。
- 不同地址块使用稳定、可区分的颜色。
- 单元格中显示当前寄存器值或默认空值。
- 地址块之间不能重叠；发生重叠时阻止保存并提示冲突范围。

用户不需要通过额外的地址块列表判断归属，表格本身必须能够回答“哪些单元格属于地址 1、哪些属于地址 2”。

### 5.3 新增地址

点击空白单元格，打开地址配置窗口。

默认填入：

- 起始地址：当前点击的寄存器地址
- 数量：默认值
- 地址名称：自动生成，例如 `1 Address`

点击确定后，表格生成归属条，并将地址块加入设备配置。

### 5.4 编辑地址

点击已配置地址块中的任意单元格，打开该地址块配置窗口，可以修改名称、起始地址、数量、数据类型、字节顺序、读写属性、轮询和变量关联。

### 5.5 删除地址

地址块最后一位归属条的末端作为删除入口：

- 鼠标悬停时显示 `×`。
- 点击 `×` 删除整个地址块。
- 同时删除所有占用单元格、地址配置、轮询配置、变量关联和该地址的接收记录。
- 删除后重新计算并刷新其他地址块的位置。

不能只删除地址块中的单个单元格，避免产生不完整配置。

## 6. 地址接收记录

点击已配置地址块中的任意单元格，打开该地址的接收记录窗口。

记录包括：

- 接收时间
- 地址名称
- 寄存器起始地址
- 原始寄存器值
- 解析后的数据值
- 十六进制值
- 读写方向
- 请求状态
- 错误信息

每个地址块拥有独立记录，不与整个设备的普通通信日志混合显示。

## 7. 发送测试

“发送测试”使用已经配置好的地址块。

点击后显示：

- 地址选择
- 发送数据类型
- 发送数据内容
- 清空
- 发送

地址选择只显示已配置的地址块，例如 `1 Address`、`2 Address`。

发送时根据地址块配置自动确定起始地址、数量、数据类型、字节顺序以及单寄存器或多寄存器写入方式。

地址块“寄存器个数”是可写容量上限，不要求每次写满：发送内容少于容量时只写实际占用的寄存器，其余保持原值；超过容量时只发送前面能完整容纳的值并提示截取数量。32bit 的 int/float 每值占两个寄存器，不写半个值；string 使用 UTF-8 且截取时不拆分多字节字符。超过单次 FC16 上限时按顺序分批写入。

发送测试窗口不要求用户重新输入功能码和起始地址。

## 8. 轮询和数据同步

地址块启用轮询后：

1. 根据地址块配置生成读取请求。
2. 按轮询周期访问寄存器。
3. 更新对应表格单元格。
4. 更新该地址的接收记录。
5. 更新关联变量。
6. 更新地址块状态。

状态颜色：

- 绿色：读取成功
- 黄色：轮询中
- 红色：读取失败
- 灰色：未启用轮询

“数据同步”用于主动读取当前设备所有已配置且可读的地址块，与“轮询使能”无关；“轮询使能”只控制自动定时读取。两者共用设备连接和寄存器结果回写，但手动同步不因轮询关闭而拒绝数据。

## 9. 数据模型边界

设备级：

```text
Communication
├─ TCP/RTU 连接参数
├─ Modbus 基础参数
└─ Modbus 地址块集合
```

地址块级：

```text
ModbusAddressPoint
├─ 名称
├─ 起始地址
├─ 数量
├─ 数据类型
├─ 字节顺序
├─ 读写属性
├─ 轮询配置
└─ 变量关联
```

运行时级：

```text
AddressRuntimeState
├─ 当前值
├─ 最后读取时间
├─ 当前状态
└─ 接收记录
```

设计配置和运行时数据分开，运行过程不能覆盖设计期配置。

## 10. 最终界面结构

```text
左侧：通讯设备列表

右侧：
├─ 通讯参数
│  ├─ Modbus TCP：通信方式、目标 IP、目标端口、站号、轮询间隔、自动重连
│  └─ Modbus RTU：串口、波特率、数据位、停止位、校验位、超时、站号、轮询间隔、自动重连
├─ 寄存器地址
│  ├─ 首地址
│  └─ 寄存器个数
├─ 地址空间
│  ├─ 地址表格
│  ├─ 0–9 偏移列
│  ├─ 0/10/20… 地址行
│  ├─ Address 1 / Address 2 归属条
│  ├─ 最大化 / 隐藏空白行 / 清空
│  ├─ 单元格当前值
│  └─ 地址块删除 ×
├─ 地址操作
│  ├─ 数据同步
│  └─ 发送测试
├─ 手动 Modbus 操作
│  ├─ 寄存器操作
│  ├─ 地址
│  ├─ 数量
│  ├─ 写入值
│  └─ 执行
└─ 接收记录 / 发送记录
```

## 11. 实施顺序

1. 手动操作下拉改为寄存器操作集合，移除线圈操作。
2. 增加地址块配置模型。
3. 按 VM 基线实现统一 0–9 地址空间表格、十位地址行和滚动浏览。
4. 实现首地址、寄存器个数对表格范围的控制。
5. 实现点击空白单元格新增地址。
6. 实现点击地址查看记录和编辑配置。
7. 实现地址块末端悬停删除。
8. 实现最大化、隐藏空白行、清空和冲突校验。
9. 实现发送测试。
10. 实现地址级轮询和数据同步。
11. 接入变量关联和工作流数据绑定。

最终目标是：保留当前寄存器手动调试能力，增加 VM 风格的寄存器地址空间管理，让每个地址块可以识别、配置、轮询、测试、查看记录和整体删除。
