# 通讯管理器 Modbus 地址空间最终优化方案

**日期：** 2026-09-26  
**范围：** Modbus 地址空间、地址块配置、地址块交互和寄存器显示  
**视觉基准：** VM 地址空间界面截图

## 1. 目标

- 删除 Modbus 界面中的“手动读写”折叠区。
- 地址空间表使用一个独立的纵向滚动区域。
- 已分配地址显示连续的地址归属色条。
- 未分配寄存器保持普通表格样式，仅在悬停时显示 `＋`。
- 地址格和地址色条不再使用按钮视觉。
- 地址配置模型与 VM 的 `Int 位数 16bit/32bit` 对齐。

├────────┼────┬────┬────┬────┬────┬────┬────┬────┬────┬───────┤
│ 0      │0000│0000│0000│0000│0000│0000│0000│0000│0000│0000   │
├────────┼────┴────┴────┴────┴────┴────┴────┴────┴────┴───────┤
│        │ Address                                            │

地址空间表放入一个 `ScrollViewer`。表头随表格内容保持一致，底部统计、数据同步和发送测试区域固定显示。

左侧地址序号列需要纵向合并，覆盖同一地址行中的地址归属色条和寄存器值：

```text
┌──────┬──────────────────────────────────────────────┐
│      │ Address                                      │
│  0   ├──────┬──────┬──────┬──────┬──────┬──────┬─────┤
│      │ 0000 │ 0000 │ 0000 │ 0000 │ 0000 │ 0000 │ ... │
└──────┴──────┴──────┴──────┴──────┴──────┴──────┴─────┘
```

实现上，地址序号单元格使用 `Grid.RowSpan="2"`，色条和寄存器单元格位于右侧的两行中。地址 `0`、`10`、`20` 等序号始终与对应的色条和寄存器值整体对齐。

## 3. 地址归属色条

地址块按实际起始地址和寄存器数量显示为连续色条，不拆成独立按钮，也不固定铺满一整行。每行仅绘制地址块与该行十个寄存器范围的交集；例如起始地址 3、数量 4，只覆盖 3～6 列，起始地址 8、数量 5，分别覆盖首行 8～9 列和下一行 0～2 列。同一行可显示多个彼此独立的色条段，段外仍是未分配区域。

```text
默认：

━━━━━━━━━━━━ Address ━━━━━━━━━━━━━━━━━━━

悬停：

━━━━━━━━━━━━ Address ━━━━━━━━━━━━━━━ ×
```

规则：

- 高度建议为 8–10px。
- 使用主题色填充，默认使用警告色，轮询成功使用成功色，轮询失败使用错误色。
- 地址名称只在色条起始位置显示。
- 默认不显示删除符号。
- 鼠标悬停时，色条末端显示 `×`。
- 地址块跨越多个地址行时，每一行保持连续色条，不拆成按钮块。

## 4. 未分配寄存器交互

```text
默认：

┌──────┬──────┬──────┐
│      │      │      │
└──────┴──────┴──────┘

悬停：

┌──────┬──────┬──────┐
│  ＋  │      │      │
└──────┴──────┴──────┘
```

- 默认不显示 `＋`。
- 悬停时显示浅灰色 `＋` 和轻微背景变化。
- 不使用按钮边框、圆角或按下效果。
- 点击空白单元格打开地址配置窗口。
- 起始地址默认填入当前寄存器地址。

## 5. 交互逻辑

### 5.1 空白寄存器

```text
悬停空白单元格 → 显示 ＋
点击空白单元格 → 打开地址配置
保存 → 创建地址块并刷新连续色条
```

### 5.2 已配置寄存器

```text
点击寄存器值 → 查看当前地址的接收记录
右键寄存器值 → 编辑地址块 / 删除地址块 / 查看记录
```

### 5.3 地址归属色条

```text
左键点击 → 编辑整个地址块
右键点击 → 编辑 / 删除 / 查看记录
悬停色条末端 → 显示 ×
```

删除入口只在悬停或右键菜单中出现，避免默认状态增加视觉负担。

## 6. 地址配置字段

地址配置窗口与 VM 对齐：

```text
地址名称
Int位数       16bit / 32bit
发送顺序      ABCD 等
设备地址
寄存器地址
寄存器个数
超时时间
关联地址
轮询使能
```

当前 `UInt16`、`Int16`、`UInt32`、`Int32`、`Float32` 数据类型下拉不作为主配置项。

## 7. 16bit / 32bit 地址占用

16bit 时，每个值占用一个寄存器：

```text
寄存器 0 → 值 1
寄存器 1 → 值 2
寄存器 2 → 值 3
```

32bit 时，每个值占用两个寄存器：

```text
寄存器 0 + 1 → 值 1
寄存器 2 + 3 → 值 2
寄存器 4 + 5 → 值 3
```

地址空间表始终按原始寄存器显示，避免显示地址与实际设备寄存器不一致。

## 8. 字节顺序

32bit 数据使用四字节顺序：

```text
ABCD：A B C D
BADC：B A D C
CDAB：C D A B
DCBA：D C B A
```

16bit 数据只涉及两个字节，可按 `AB` 或 `BA` 处理。若界面保持 VM 的 `ABCD` 选项，则 16bit 模式只使用前两个字节规则。

## 9. 数据模型建议

地址块模型建议从 `DataType` 主导改为位数主导：

```csharp
string IntBits
string ByteOrder
int DeviceAddress
int StartAddress
int RegisterCount
```

旧数据迁移：

```text
UInt16 → 16bit
Int16  → 16bit
UInt32 → 32bit
Int32  → 32bit
Float32 → 暂不自动转换
```

如果后续需要支持浮点数，单独增加“数据格式”字段，不扩展 `Int位数` 选项。

## 10. WPF 控件结构

地址空间不再用 `Button` 作为地址格和色条：

```text
Grid
 ├─ TextBlock       地址行号
 ├─ Border          连续地址归属色条
 │   └─ TextBlock   地址名称
 └─ ItemsControl    寄存器格
     └─ Border      普通表格单元格
         ├─ TextBlock  数值
         └─ TextBlock  悬停时的 ＋
```

通过 `MouseLeftButtonUp`、`MouseRightButtonUp`、`MouseEnter` 和 `MouseLeave` 保留交互功能。

## 11. 实施状态

已完成第一批实现：轮询批量 UI 回写、地址表不重建、轻量 `Border` 地址格和地址条、空白格悬停 `＋`、地址序号纵向合并、`IntBits=16bit/32bit` 配置及旧 `DataType` 兼容读取。

仍需用户统一进行运行时视觉、点击、滚动、轮询刷新和真实设备通讯验收。

## 12. 验收标准

### 视觉

- 地址空间整体接近 VM 截图。
- 已分配地址显示连续色条。
- 未分配区域显示普通空白网格。
- 未分配单元格只有悬停时显示 `＋`。
- 默认状态没有按钮边框、圆角和常驻删除符号。
- 地址空间只有一个纵向滚动条。

### 交互

- 点击空白格可以创建地址块。
- 点击色条可以编辑地址块。
- 点击已配置寄存器可以查看接收记录。
- 色条悬停或右键可以删除地址块。
- 轮询成功后色条切换成功色。
- 轮询失败后色条切换错误色。
- 地址块跨多行时色条保持连续显示。
- 左侧地址序号纵向覆盖色条和寄存器值两行。

### 参数

- 配置项使用 `16bit / 32bit`。
- 寄存器数量按原始寄存器计算。
- 32bit 数据正确占用两个寄存器。
- 字节顺序只影响数据解析和发送，不改变地址表布局。
- 旧 `DataType` 数据能够平滑迁移。
