# 通讯管理器与通讯工具完整设计方案

> 日期：2026-09-21  
> 状态：设计基线，当前实施范围已收敛，待评审后实施  
> 适用范围：解决方案通讯配置、运行时连接管理、通讯协议适配、工作流通讯工具及通讯管理 UI

## 1. 结论与现状审计

当前通讯功能只能作为配置占位，不能作为生产运行能力使用：

1. `src/Workflow/Communication.cs` 仅提供 `CommunicationType`、名称、启用状态以及两个弱类型字典；协议参数没有类型契约、默认值、版本和敏感字段语义。
2. `CommunicationManagerViewModel.TestConnection()` 使用 `Thread.Sleep(500)`，无论目标是否存在都会记录成功；UI 直接改写 `Solution.Communications`，没有保存前校验、运行时生命周期和连接状态。
3. 现有模型未区分“通讯配置”“连接实例”“请求/响应”“通讯结果”，不能处理连接复用、断线重连、并发请求、取消、超时或半包。
4. 工作流执行层没有通讯输入/输出快照边界，工具无法安全地访问通讯连接；若直接让工具访问 WPF 或 `Solution`，会破坏执行层与 UI 的架构边界。

本方案的目标是把通讯能力建设为独立的运行时子系统：配置是纯数据，管理器拥有连接生命周期，协议驱动只实现协议，通讯工具通过 SDK 契约调用管理器，工作流只传递不可变运行时快照。

### 2.0 当前实施定位（本轮讨论确认）

当前实施以 VisionMaster 通讯管理器的交互形态为参考，先确定页面结构和产品定位，不在本阶段实现通用通讯平台。

当前“设备管理”导航中的设备列表，定位为：

> 管理用于连接海康光源控制器的通讯设备连接配置，并提供连接调试入口。

当前阶段只需要确认以下内容：

- 通讯管理器窗口的导航和页面布局。
- 通讯设备列表及其新增、选择、删除、启用/禁用交互。
- 点击设备列表旁的“+”后打开“设备管理”对话框。
- 在对话框中选择协议类型、填写通讯参数、创建设备连接配置。
- 选中设备后查看通讯参数，并预留连接调试区。
- 连接状态、连接/断开/测试按钮和基本错误提示的交互位置。

当前阶段明确不设计、不实现：

- 海康光源控制器的具体协议字段、命令帧、数据帧和业务映射。
- TCP、UDP、串口、Modbus、OPC UA 等通用协议的完整适配器。
- 接收事件、发送事件、触发配置、响应配置和心跳管理的完整业务设计。
- 工作流通讯工具、通讯结果绑定和全局变量集成。
- 相机、光源设备驱动本身的发现、控制和采集逻辑。

因此，本阶段的“协议类型”和“通讯参数”先作为可扩展的 UI 配置区域，不提前固化海康光源控制器的协议语义。后续拿到光控协议资料并确认实际连接方式后，再单独补充协议适配和运行时实现方案。

## 2. 设计原则与边界

### 2.1 原则

- 配置、运行时状态、一次请求和工具结果四类对象分离。
- 所有 I/O 异步化，支持取消、超时、重试和关闭；禁止 UI 线程阻塞。
- 协议实现可插拔，核心管理器不依赖具体 Modbus、OPC UA 或厂商 SDK。
- 一个逻辑通讯配置对应一个受控连接会话；并发策略由管理器统一执行。
- 工作流开始时冻结通讯引用和参数；执行期间不得读取 UI 控件或直接读取可变 `Solution`。
- 默认安全：密码、Token、证书私钥不明文写入方案文件，日志不输出敏感数据。
- 所有外部数据先做长度、编码、类型和边界校验，再映射到工具结果或全局变量。

### 2.2 模块边界

```text
UI 通讯管理器
    └─ CommunicationConfigurationService（编辑、校验、保存）
              ↓ 只读配置快照
CommunicationRuntimeManager（连接池、状态机、重连、指标）
    └─ ICommunicationTransport / IProtocolAdapter
              ├─ TCP / UDP / Serial
              ├─ HTTP
              ├─ Modbus TCP / RTU
              └─ OPC UA（后续独立适配器）
              ↓ ICommunicationClient
Workflow Communication Tools（读、写、请求、订阅）
              ↓ ToolResult / OutputVariable / 全局变量快照
WorkflowExecutionEngine
```

`SunEyeVision.Plugin.SDK` 只放稳定的通讯契约和 DTO，不引用 WPF、`SolutionManager` 或具体协议库。运行时实现放在 `src/Workflow` 或独立的 `src/Communication` 基础设施项目；UI 只依赖应用层服务。

## 3. 领域模型

### 3.1 通讯配置

保留现有 `Communication` 作为持久化入口，但逐步把弱类型字段迁移为版本化配置：

```csharp
public sealed class CommunicationDefinition
{
    public string Id { get; init; } = Guid.NewGuid().ToString("N");
    public string Name { get; set; } = "";
    public bool IsEnabled { get; set; } = true;
    public CommunicationProtocol Protocol { get; set; }
    public int SchemaVersion { get; set; } = 1;
    public EndpointDefinition Endpoint { get; set; } = new();
    public CommunicationOptions Options { get; set; } = new();
    public List<CommunicationMapping> Mappings { get; set; } = new();
    public DateTime ModifiedTime { get; set; } = DateTime.UtcNow;
}
```

协议参数采用可序列化的强类型子模型。旧 `Settings` 保留一个版本周期作为迁移输入，不再作为新代码的运行时 API：

- `TcpEndpoint`：Host、Port、连接/发送/接收超时、KeepAlive、最大帧长度。
- `UdpEndpoint`：LocalHost、LocalPort、RemoteHost、RemotePort、广播开关。
- `SerialEndpoint`：PortName、BaudRate、DataBits、Parity、StopBits、Handshake、ReadTimeout。
- `HttpEndpoint`：BaseUri、Method、Path、Headers、ContentType、TLS 校验策略。
- `ModbusOptions`：UnitId、字节序、寄存器地址基准、功能码允许列表。
- `OpcUaOptions`：EndpointUri、SecurityPolicy、认证方式、证书引用、订阅队列上限。

敏感值使用 `SecretReference`（本机凭据存储键、环境变量键或受保护文件引用）表示。方案文件只保存引用和脱敏摘要。

### 3.2 运行时状态

```csharp
public enum CommunicationConnectionState
{
    Disabled, Disconnected, Connecting, Connected,
    Reconnecting, Degraded, Faulted, Closing
}

public sealed record CommunicationRuntimeSnapshot(
    string CommunicationId,
    CommunicationConnectionState State,
    DateTimeOffset? ConnectedAt,
    DateTimeOffset? LastActivityAt,
    int ConsecutiveFailures,
    string? LastErrorCode,
    string? LastErrorMessage,
    long SentCount,
    long ReceivedCount,
    long TimeoutCount);
```

状态由管理器单向发布；工具和 UI 只能订阅快照，不得自行修改连接状态。状态转换必须经过状态机，禁止 `Connected = true` 式的旁路赋值。

### 3.3 请求、响应和错误

```csharp
public sealed record CommunicationRequest(
    string CommunicationId,
    ReadOnlyMemory<byte> Payload,
    CommunicationRequestOptions Options);

public sealed record CommunicationResponse(
    ReadOnlyMemory<byte> Payload,
    DateTimeOffset ReceivedAt,
    TimeSpan RoundTripTime,
    IReadOnlyDictionary<string, object?> Metadata);

public enum CommunicationErrorCode
{
    InvalidConfiguration, Disabled, NotFound, NotConnected,
    ConnectTimeout, RequestTimeout, Cancelled, ProtocolError,
    TransportError, BufferOverflow, AuthenticationFailed,
    RateLimited, ReconnectExhausted, InternalError
}
```

所有公共调用返回 `CommunicationResult<T>`，包含 `IsSuccess`、错误码、可诊断消息、重试建议和关联 ID；异常只用于编程错误或未捕获的基础设施故障，不把网络断开直接暴露给工具层。

## 4. 通讯管理器设计

### 4.1 核心接口

```csharp
public interface ICommunicationRuntimeManager : IAsyncDisposable
{
    IReadOnlyCollection<CommunicationRuntimeSnapshot> GetSnapshots();
    Task<CommunicationResult> ConnectAsync(string id, CancellationToken ct = default);
    Task<CommunicationResult> DisconnectAsync(string id, CancellationToken ct = default);
    Task<CommunicationResult<CommunicationResponse>> SendAsync(
        CommunicationRequest request, CancellationToken ct = default);
    Task<CommunicationResult> TestAsync(
        string id, CommunicationTestRequest request, CancellationToken ct = default);
    IDisposable Subscribe(string id, Action<CommunicationRuntimeSnapshot> handler);
}
```

应用层另设 `ICommunicationConfigurationService`，负责增删改、协议 schema 校验、迁移和保存；运行时管理器不直接操作 `Solution`。执行开始时由 `CommunicationRuntimeSnapshotFactory` 从方案配置生成只读快照。

### 4.2 连接池与并发模型

- 以 `CommunicationId` 为键维护 `CommunicationSession`，懒连接，连接成功后复用。
- 每个会话一个串行发送队列，默认保证请求顺序；纯 UDP 可通过显式选项启用并发。
- `ConnectAsync`、`DisconnectAsync`、`SendAsync` 均经过同一会话锁，避免连接/关闭与发送交叉。
- 队列具有容量上限、请求超时和取消；超限返回 `RateLimited`，不无限积压内存。
- 运行工作流期间，管理器持有运行批次引用；批次结束释放引用，但不强制关闭可复用连接，应用退出或配置变更时统一关闭。

### 4.3 连接状态机与重连

状态路径：`Disabled → Disconnected → Connecting → Connected`；异常后进入 `Reconnecting`，超过策略次数进入 `Faulted`。手动断开直接进入 `Disconnected`，取消重连不会被后台任务重新拉起。

默认重连策略：指数退避 200ms、500ms、1s、2s、5s，最多 5 次；每次连接尝试都受连接超时和取消令牌约束。只有幂等请求或明确允许重试的请求才自动重发；串口/PLC 写操作默认不自动重发，避免重复写入。

### 4.4 配置变更

配置编辑不直接修改活动会话。保存时执行：校验 → 生成新版本 → 关闭旧会话 → 创建新会话 → 按“自动连接”策略启动。连接配置变化必须记录 `ConfigurationVersion`，旧请求只能使用创建时的版本，避免半途切换。

### 4.5 诊断与指标

每次请求生成 `CorrelationId`，记录协议、通讯 ID、耗时、结果码、载荷长度、重试次数和状态变化；默认不记录原始载荷，调试模式只记录截断后的十六进制并做敏感字段遮罩。

管理器至少提供：连接成功率、平均/最大 RTT、超时数、收发字节、重连次数、队列深度、最近错误。日志应能按 `CommunicationId` 和工作流运行 ID 关联。

## 5. 传输层与协议适配器

### 5.1 传输契约

```csharp
public interface ICommunicationTransport : IAsyncDisposable
{
    CommunicationTransportKind Kind { get; }
    Task OpenAsync(EndpointDefinition endpoint, CancellationToken ct);
    Task CloseAsync(CancellationToken ct);
    Task<int> WriteAsync(ReadOnlyMemory<byte> data, CancellationToken ct);
    Task<int> ReadAsync(Memory<byte> buffer, CancellationToken ct);
    ValueTask FlushAsync(CancellationToken ct = default);
}

public interface IProtocolAdapter
{
    CommunicationProtocol Protocol { get; }
    CommunicationValidationResult Validate(CommunicationDefinition definition);
    Task<ProtocolRequest> BuildRequestAsync(CommunicationOperation operation, CancellationToken ct);
    Task<ProtocolResponse> ParseResponseAsync(ReadOnlyMemory<byte> payload, CancellationToken ct);
}
```

传输层只负责字节流/数据报，不解析 Modbus、HTTP 或 OPC UA。协议适配器负责帧构造、长度、校验、响应匹配和协议错误；这样既能复用 TCP/串口，也能避免管理器出现协议分支地狱。

### 5.2 第一阶段协议范围

1. TCP 客户端：长度帧、分隔符帧、固定长度帧三种 framing；支持 ASCII/UTF-8/HEX。
2. UDP：单次请求响应、广播发送、来源地址校验。
3. Serial：标准串口参数、帧间隔、分隔符/固定长度/校验帧。
4. Modbus TCP/RTU：读线圈、读离散输入、读保持寄存器、读输入寄存器、写单/多寄存器；验证 CRC、异常码、地址边界和字节序。
5. HTTP：GET/POST/PUT、模板化 URL/Headers/Body、状态码和 JSON/文本响应映射。

OPC UA 作为独立后续适配器：先完成连接、读写节点和订阅契约，再引入证书管理与安全策略；不在第一阶段把 OPC UA SDK 强行加入核心工程。

### 5.3 插件化

协议驱动以 `ICommunicationAdapterFactory` 注册，插件元数据包含协议 ID、schema 版本、能力（读、写、订阅、测试）、依赖和最低 SDK 版本。插件不得引用 UI 宿主程序集；所有第三方依赖由插件发布规则部署到插件目录，并通过现有插件加载策略隔离。

## 6. 通讯工具设计

通讯工具是工作流节点，不是连接管理器的替代品。工具只接收 SDK 的 `ICommunicationClient` 和执行快照，不能直接 `new TcpClient`、访问 WPF 或读取 `SolutionManager`。

### 6.1 工具基类与统一执行

```csharp
public interface ICommunicationClient
{
    Task<CommunicationResult<CommunicationResponse>> SendAsync(
        CommunicationRequest request, CancellationToken ct = default);
    Task<CommunicationRuntimeSnapshot> GetStatusAsync(CancellationToken ct = default);
}

public interface ICommunicationTool : IToolPlugin
{
    CommunicationToolKind Kind { get; }
    CommunicationOperationDefinition Operation { get; }
}
```

工作流运行时把 `CommunicationExecutionContext` 注入工具：通讯配置快照、客户端、运行 ID、节点 ID、取消令牌、超时策略和变量读取/写入边界。工具不得保存跨运行的可变请求状态。

### 6.2 第一批工具

| 工具 | 输入 | 输出 | 典型用途 |
| --- | --- | --- | --- |
| 通讯连接 | 通讯 ID、连接策略 | 状态、耗时、错误码 | 预连接或流程中显式连接 |
| 通讯断开 | 通讯 ID | 状态 | 流程收尾、释放独占设备 |
| 通讯发送 | 字节/文本/模板、超时 | 发送字节数、状态 | 自定义 TCP/UDP/串口协议 |
| 通讯请求响应 | 请求模板、响应 framing | 原始响应、文本、JSON | 通用设备交互 |
| Modbus 读 | 地址、数量、数据类型、字节序 | 标量/数组、原始寄存器 | 采集 PLC 数据 |
| Modbus 写 | 地址、值、写入类型 | 写入确认、异常码 | 下发控制量 |
| HTTP 请求 | 方法、路径、Headers、Body | 状态码、Headers、Body/JSON | 设备 REST 接口 |
| 通讯订阅 | 通讯 ID、订阅参数 | 事件流/最新值 | OPC UA 或持续数据 |

工具配置中的通讯引用使用稳定 `CommunicationId`，不嵌入连接对象。工具结果采用统一 `OutputVariable` 路径，例如 `Response.StatusCode`、`Response.Text`、`Modbus.Registers[0]`、`Diagnostics.RoundTripMs`，可绑定到后续节点和全局变量。

### 6.3 工具安全与语义

- 写操作必须显式选择“允许写入”，默认不允许由设计期测试误写现场设备。
- 调试窗口的“测试”使用独立 `TestExecutionContext`，有单独日志标识、超时和权限确认，不污染工作流结果。
- 工具执行失败由 `RunResult` 返回结构化错误；是否终止工作流由节点的 `FailurePolicy` 决定（终止、跳过、使用默认值、重试）。
- 变量模板只允许引用当前运行快照中的已授权数据源，禁止任意脚本执行和字符串拼接绕过类型校验。

## 7. 工作流与全局变量集成

工作流启动时执行以下步骤：

1. 从 `Solution` 创建通讯定义快照，校验启用配置、协议 schema、敏感引用和节点引用。
2. 为本次运行创建 `CommunicationExecutionScope`，记录配置版本、连接策略和资源租约。
3. 节点执行请求携带 `CommunicationExecutionContext`；工具只通过客户端发送请求。
4. 结果转成 `OutputVariable` 和 `ExecutionResult`，按既有数据源路径发布。
5. 绑定到全局变量时写入运行批次变量快照；生产者结果不可直接改写设计期配置。
6. 运行结束按租约释放订阅、请求队列和连接引用；异常退出也必须通过 `finally` 清理。

通讯输入不应在节点执行中直接读取 UI 或动态配置。通讯输出默认只在当前运行批次可见；若需要跨批次保留，必须通过显式的全局变量写入策略并带版本号，避免多个流程并发覆盖。

## 8. 配置管理器 UI

### 8.1 页面结构

- 左侧：通讯列表、协议图标、启用状态、连接状态、最近错误。
- 右侧“基本信息”：名称、描述、启用、协议、自动连接、连接池策略。
- 右侧“端点”：根据协议动态显示强类型字段；端口、地址、编码、超时均有范围校验。
- 右侧“协议”：Modbus 地址/字节序/功能码，或 framing/校验/HTTP 模板等。
- “映射”：把响应字段映射为命名输出，显示类型、默认值和转换失败策略。
- 底部诊断：连接、断开、测试请求、清空统计、查看最近日志；测试结果必须来自真实 I/O。

### 8.2 编辑事务

UI 编辑副本，不直接修改 `Solution.Communications`。点击保存时执行验证并提交一个不可变配置版本；失败时保留编辑内容并显示字段级错误。删除前检查工作流节点引用，默认阻止删除或提供“迁移引用后删除”。

现有 `DataGrid` 只展示字典键值的做法应移除；协议字段用独立 ViewModel 和 DataTemplate 呈现。`TestConnectionCommand` 改为异步命令，禁止 `Thread.Sleep`，按钮绑定 `IsBusy` 并支持取消。

### 8.3 UI 信息架构

通讯管理器采用“列表 + 编辑器 + 诊断抽屉”的三栏结构，窗口建议初始尺寸 1280×760，最小尺寸 1024×640。窗口不承担通讯执行逻辑，只调用应用层配置服务和运行时管理器。

### 8.5 顶部工具栏

```text
+--------------------------------------------------------------------------------+
| [+ 新建] [复制] [删除] | [连接] [断开] [测试连接] | [导入] [导出] | [诊断] [保存] |
+--------------------------------------------------------------------------------+
```

- 新建：打开协议选择菜单，不直接创建含有虚假地址的 Modbus 配置。
- 复制：复制为新的 ID，敏感值默认不复制，要求重新确认凭据。
- 删除：有引用时进入“引用处理”对话框。
- 连接/断开：异步执行，按钮显示进度并允许取消。
- 测试连接：执行真实连接或协议握手；TCP/串口至少完成打开和关闭，Modbus/HTTP 可配置探测请求；不使用固定延时伪造成功。
- 保存：保存编辑副本，只有验证通过才提交；有未保存改动时显示圆点标记。

### 8.6 新建通讯流程

新建采用两步向导，避免生成空配置后直接进入“已成功”状态。

```text
+---------------- 新建通讯 ----------------+
| 1 选择协议  >  2 配置端点  >  3 完成      |
|------------------------------------------|
| 请选择通讯协议                           |
|                                          |
| [🔗 TCP/IP]  [📡 UDP]  [🔌 串口]         |
| [▣ HTTP]     [▤ Modbus TCP] [▤ Modbus RTU]|
| [⚙ OPC UA]  [其他/插件...]               |
```

### 8.16 UI 验收检查表

- 深色、浅色主题下文字、状态图标、选中行、错误提示均可读。
- 1024×640 窗口不出现关键控件被裁切；键盘 Tab 顺序与鼠标顺序一致。
- 新建、复制、编辑、取消、保存、重开方案后数据一致。
- 无效 IP、端口、串口、URI、超时、Modbus 地址均显示字段级错误。
- 无服务端时测试连接真实失败；成功必须有真实响应证据和 RTT。
- 连接中、重连中、取消、超时、故障状态均有明确文案和可用操作。
- 被工作流引用的通讯不能静默删除，替换后引用全部指向新 ID。
- 敏感值不出现在列表、日志、导出诊断包和普通错误消息中。
- 用户手动验证 Visual Studio 设计时显示、运行时布局、主题切换、滚动和窗口关闭行为，并记录结果。

### 8.17 基于现有参考界面的 UI 收敛方案

本节根据用户提供的通讯管理参考界面进行收敛。参考界面不是简单的“通讯配置表”，而是一个以设备、事件、触发、响应和心跳为核心的通讯编排工作台。因此最终 UI 采用“左侧功能导航 + 中部对象列表 + 右侧参数编辑”的一级结构，并在此基础上增加真实连接状态、版本、校验和诊断能力。

参考界面中已经体现的产品语义应保留：

- “设备管理”负责通讯设备连接配置的创建、编辑、删除和调试。
- “接收事件”负责定义接收帧、事件解析和接收后的处理方式。
- “发送事件”负责定义发送帧、变量模板和发送条件。
- “触发配置”负责定义何时发送或接收，以及触发源和防抖策略。
- “响应配置”负责定义收到响应后的协议解析和结果输出。
- “心跳管理”负责连接保活、周期探测、掉线检测和重连策略。

当前阶段不实现控制器业务逻辑，但保留参考 VM 中的控制器列表区域和页面导航，用于保持通讯管理器整体布局：

```text
通讯设备（CommunicationDevice）
  └─ 物理或逻辑连接：TCP 客户端、TCP 服务端、UDP、串口、HTTP、Modbus、OPC UA
       └─ 协议适配器（当前只注册常用协议，厂商协议后续按需扩展）
```

这样可以避免把“TCP 客户端”与“VC2000/VC2100 控制器”混在同一个协议下拉框中：前者是传输层，后者是业务协议/设备驱动。控制器创建时必须选择一个通讯设备引用，不能再复制一份 IP、端口和串口参数。

## 9. 持久化、迁移与兼容

方案 JSON 增加：`CommunicationSchemaVersion`、`Protocol`、`Endpoint`、`Options`、`Mappings`、`SecretReference`。加载旧方案时：

1. 根据 `ConnectionType` 和 `Settings` 识别协议。
2. 把 `ipAddress/host/port/serialPort` 等旧键转换为强类型端点。
3. 对无法识别或不完整的参数生成迁移警告，不伪造“连接成功”。
4. 首次保存时写入新结构；保留只读兼容读取，不再写回旧字典。

配置校验至少覆盖：名称和 ID 唯一、协议端点合法、端口 1–65535、超时为正、串口枚举值合法、Modbus 地址/数量边界、HTTP URI 合法、订阅队列有限、引用的映射字段存在。

## 10. 异常、可靠性与安全

- 所有 I/O 均有连接、请求和关闭三个层级的超时。
- 取消优先级高于重试；关闭应用时先停止新请求，再等待有限时间完成当前请求，最后强制关闭传输。
- TCP 半包、粘包、远端静默、RST、DNS 失败、串口拔出、Modbus CRC/异常码、HTTP 非 2xx 都有独立错误码。
- 重试按操作幂等性分类；写 PLC、触发动作、HTTP 非幂等 POST 默认不重试。
- 限制最大帧、最大响应体、每连接队列和订阅缓存，防止异常设备造成内存增长。
- 凭据由 Windows Credential Manager/DPAPI 保护；日志默认遮罩密码、Token、Authorization 和证书私钥。
- 允许配置 IP/域名白名单、TLS 证书校验、HTTP 重定向策略和写操作权限。

## 11. 实施分期与验收

### M0：契约冻结与迁移工具

新增 SDK 通讯 DTO、结果码、`ICommunicationClient`、配置 schema 和旧 `Settings` 转换器；补充 JSON round-trip、配置校验和迁移测试。此阶段不接真实 I/O。

### M1：真实传输与管理器

实现 TCP、UDP、Serial transport；实现会话状态机、队列、超时、取消、重连、诊断指标和真实连接测试。用 loopback TCP、虚拟串口或测试服务器完成自动化验证。

### M2：Modbus/HTTP 协议与基础工具

实现 Modbus TCP/RTU、HTTP 适配器及连接、断开、请求响应、Modbus 读写工具；接入工作流执行快照和结构化结果。

### M3：UI 重构与运行联调

把字典 DataGrid 改为协议表单，加入字段校验、状态显示、异步测试、配置版本和引用检查；验证保存、重开方案、断线重连、运行中取消和并行流程。

### M4：订阅、OPC UA 与生产增强

加入 OPC UA 读写/订阅、证书管理、通讯权限、性能指标面板、故障诊断导出和插件化协议包。

验收门槛：

- 真实无服务端时测试连接必须失败并显示明确错误，不能出现固定成功。
- 1000 次顺序请求无句柄泄漏；并发请求不发生响应串线。
- 断线后按策略重连，取消后不再重试；应用退出无后台 I/O 线程。
- Modbus CRC/异常码、TCP 半包、串口拔出、HTTP 超时均有自动化测试。
- 工作流运行只使用启动时快照；修改 UI 配置不影响当前运行。
- 方案保存/加载后配置、引用、敏感值引用和映射保持一致。
- UI、Workflow、Plugin.SDK 和全量 Release 构建通过；工具插件场景按项目规则执行 Release 程序验证。
