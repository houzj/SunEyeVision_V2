# 通讯管理器运行时架构与协议扩展最终设计方案

日期：2026-09-23  
状态：设计基线，待按阶段实施与设备验收  
范围：通讯设备管理、运行时连接、工业协议扩展、调试 UI、工作流调用边界

实施范围补充（2026-09-23）：当前 OPC UA 服务端未配置账号凭据，本阶段客户端身份固定为匿名；用户名/密码与用户证书身份、凭据库界面及运行时支持均延期，待用户明确需要后再单独实施。下文身份方式表格和相关 ASCII 界面表示未来可扩展设计，不代表当前版本已交付。

## 1. 决策摘要与范围

本方案将“通信配置 UI”与“真实协议运行时”明确区分。现有设备管理器能够承载协议差异化配置，但这不等于底层驱动已经真实连接设备；运行时必须由独立、可测试的协议实现承接。不得用 UI 假状态、延时或本地回显冒充连接成功。

当前纳入的协议/角色：

| 协议 | 角色/方式 | 范围 |
|---|---|---|
| TCP | 客户端、服务端 | 原始字节流收发；服务端可管理多个远端会话 |
| UDP | 本地绑定并可配置默认远端 | 数据报收发 |
| 串口 | 本机串口 | 串口参数、超时、字节收发 |
| Modbus | TCP Client、串口 | 作为应用协议驱动；串口是承载方式，不另建“Modbus RTU协议设备”重复概念 |
| EtherNet/IP CIP | TCP Client | CIP 显式消息/目标设备通信；扫描、隐式 I/O 等能力另立范围 |
| Siemens S7 | TCP Client | S7 通信；具体读写地址与 PLC 型号能力由驱动定义 |
| OPC UA | **仅客户端** | Endpoint、会话、安全策略、身份认证、节点浏览/读写/订阅；不实现 OPC UA Server |

本期不纳入 HTTP。OPC UA Server、协议网关、自动网络扫描、CIP 隐式 I/O、通用 PLC 编程和厂商私有协议均不属于本方案承诺。左侧原有功能导航可保留作为产品页面入口；设备管理页不显示控制器列表，设备列表标题旁保留新增按钮。

### 1.1 术语边界

- **传输承载（Transport）**：TCP、UDP、串口等字节传输机制。
- **工业协议（Protocol）**：Modbus、CIP、S7、OPC UA 等规定应用报文、寻址与语义的协议。
- **角色/连接方式（Mode）**：例如 TCP Client / TCP Server；并非所有协议都需要客户端/服务端两个设备类型。
- **通信设备配置（CommunicationDeviceConfig）**：持久化、版本化的连接参数，不包含运行时 Socket、会话或 UI 控件。这里采用自动化软件中直观的“配置/Config”命名，不使用偏领域建模术语的 Definition。
- **连接会话（Session）**：运行时对象，由管理器创建、取消、监控和释放。

TCP 被分为 Client / Server，是因为 TCP 本身具有主动连接方与监听方两种角色。UDP 没有连接握手的 Client/Server 角色，但通常有本地绑定端点和默认远端。OPC UA 本产品只作为客户端，因此 UI 不提供 Server 选项。

### 2.1 OPC UA 客户端参数设计

设备创建页按“连接与安全 / 会话行为”分组。推荐字段如下：

| 分组 | 参数 | 交互/约束 |
|---|---|---|
| 端点 | Endpoint URL | 必填，如 `opc.tcp://host:4840`；支持手工输入和“发现端点” |
| 端点 | 应用名称 / Application URI | 应用名称可编辑；Application URI 由本应用证书身份生成并展示，不允许与证书不一致 |
| 端点 | 安全模式 | None、Sign、SignAndEncrypt；最终选项以服务器发现结果与本机证书能力交集为准 |
| 端点 | 安全策略 | 从发现到的 Endpoint 选择，不提供未经服务器确认的自由组合；过时/弱策略明确警告，遵从项目安全策略拒绝或显式允许 |
| 身份 | 匿名 / 用户名密码 / 用户证书 | 按选项显示对应字段；密码、私钥不明文落入普通配置文件 |
| 信任 | 服务器证书 | 首次连接展示主题、指纹、有效期；用户明确“信任一次/始终信任”后记录信任决策；禁止静默接受未知证书 |
| 会话 | 连接/建链超时 | 毫秒数值，设合理上下限并说明单位 |
| 会话 | Session timeout / KeepAlive | 以服务器协商能力为准，界面显示请求值与协商值；断线后按自动重连策略恢复 |
| 会话 | 自动重连 | SDK ToggleSwitch；退避重试并可取消，达到上限后进入 Faulted |

OPC UA 节点 NodeId、读写类型、采样间隔、队列大小、死区和订阅项属于**操作/订阅配置**，不是连接端点的全局参数。设备管理只保存服务端端点与身份/安全配置；浏览节点后由具体通讯操作或工作流节点引用 NodeId。用户名密码和证书私钥应存 OS Credential Vault/证书库，配置只保存受保护凭据引用。

### 3.1 责任与禁止依赖

1. **UI** 负责编辑、校验提示、调用应用服务和呈现事件；不得持有 `TcpClient`、`SerialPort`、OPC UA Session 等运行对象，也不承担重连循环或工作流调度。
2. **Configuration Service** 负责协议 schema 校验、默认值、版本迁移、保存和凭据引用解析；输出不可变快照。
3. **Protocol Registry** 根据稳定 `ProtocolId` 解析 descriptor/factory，不在 ViewModel 或管理器里写大型协议 `switch`。
4. **Runtime Manager** 以 DeviceId 管理会话生命周期、重复连接策略、取消、释放、健康状态和事件路由；配置变化只影响新快照，不悄悄修改正在运行的对象。
5. **Driver** 实现单一协议/角色，负责协议语义与错误映射；可依赖传输接口或官方/成熟协议 SDK，但不可依赖 UI 宿主。
6. **Workflow** 在执行启动时取得配置/输入快照，通过通讯工具契约调用运行服务；执行层不直接访问 WPF 控件。
7. **SDK/插件部署**：若驱动以插件交付，协议依赖必须由构建/发布规则随插件部署，不能靠开发机全局程序集“碰巧可用”。

### 3.2 建议核心契约（概念签名）

```csharp
public sealed record CommunicationDeviceConfig(
    Guid Id, string Name, string ProtocolId, int SchemaVersion,
    JsonElement Settings, CommonCommunicationOptions Common);

public interface ICommunicationProtocolDescriptor
{
    string ProtocolId { get; }
    int CurrentSchemaVersion { get; }
    ProtocolCapabilities Capabilities { get; }
    ValueTask<ValidationResult> ValidateAsync(
        CommunicationDeviceConfig config, CancellationToken ct);
    ICommunicationSession CreateSession(CommunicationDeviceSnapshot snapshot);
}

public interface ICommunicationSession : IAsyncDisposable
{
    CommunicationSessionState State { get; }
    event EventHandler<CommunicationDataEventArgs>? DataReceived;
    Task ConnectAsync(CancellationToken ct);
    Task TestAsync(CancellationToken ct);
    Task DisconnectAsync(CancellationToken ct);
}
```

工业协议的操作面需在基础会话上提供类型化 API（例如 Modbus ReadHoldingRegisters、OPC UA Read/Write/Subscribe），不能把所有协议功能压成一个含糊的 `Send(byte[])`。原始字节收发仍可由 TCP/UDP/串口会话提供。事件载荷带 DeviceId、时间戳、方向、原始字节/解码值、协议状态和关联请求 ID；队列有界，拥塞有明确丢弃/背压策略。

## 4. 配置与运行模型

持久化结构建议采用稳定 ID + schema 版本 + 协议专属设置，协议字段不得全部塞进一个 UI ViewModel：

```json
{
  "schemaVersion": 1,
  "id": "<device-guid>",
  "name": "PLC-UA",
  "protocolId": "opcua.client",
  "protocolSchemaVersion": 1,
  "settings": {
    "endpointUrl": "opc.tcp://127.0.0.1:4840",
    "securityMode": "SignAndEncrypt",
    "securityPolicyUri": "<discovered-policy-uri>",
    "identity": { "kind": "UsernamePassword", "credentialRef": "<vault-reference>" },
    "timeouts": { "connectMs": 10000, "sessionMs": 60000 },
    "reconnect": { "enabled": false, "maxAttempts": 0 }
  }
}
```

上述只是结构示例，不表示默认值或安全策略已由用户/服务器确认。迁移必须按 `protocolId + protocolSchemaVersion` 执行；未知字段可保留或拒绝并给出诊断，禁止静默丢失。保存编辑中的配置不自动改写现有活动会话快照。

### 4.1 生命周期与状态

```text
Disconnected → Validating → Connecting → Connected
      ▲             │           │           │
      │             └─ Invalid  └─ Faulted  ├─ Disconnecting → Disconnected
      │                                     └─ Lost → Reconnecting → Connected
      └──────────────────── cancelled / disposed ───────────────────────┘
```

所有异步操作接受 `CancellationToken`；每设备同一时刻只允许一个状态迁移；关闭应用先停止新请求，再取消/释放会话。自动重连采用有上限的指数退避、随机抖动和可取消等待，不在 UI Dispatcher 睡眠。连接测试必须触发真实驱动连接/握手并返回阶段、耗时和诊断信息。

### 5.4 按协议区分调试操作

原始 TCP/UDP/串口使用发送文本/字节模式、ASCII/HEX 切换、发送和收包窗口；Modbus 提供功能码、站号、地址、数量及响应视图；CIP/S7 提供受驱动支持的类型化读写操作；OPC UA 提供 Browse、Read、Write、Subscribe 操作面板。不能让 OPC UA 用户把 NodeId 当作任意原始 TCP 文本发送。接收结束符仅用于原始字节流的分帧/展示选项；协议驱动已定义消息边界的场景不显示此选项。

## 6. 协议扩展机制

### 6.1 新增协议的固定步骤

1. 分配不可变 ID（例 `vendorx.foo.client`），显示名称可本地化，禁止以显示文字作为持久化键。
2. 定义强类型设置 DTO、SchemaVersion、默认值、字段单位、范围、必填规则与迁移器。
3. 声明能力（客户端/服务端、原始收发、读写、订阅、数据上传、自动重连、结束符适用性）。
4. 实现 descriptor、validator、session factory 和协议操作接口；只通过抽象服务访问凭据、时钟、日志、证书和传输。
5. 实现该协议 editor 与主题资源；以能力决定控件而不是协议名散落判断。
6. 提供单元测试、协议模拟器/录制报文测试、取消/重连/并发/释放测试及真实设备验收清单。
7. 声明依赖版本、许可、平台支持和部署文件；通过插件 SDK 兼容性门禁加载。
8. 注册协议并跑配置迁移测试，既有未知/旧配置不得被破坏。

### 6.2 扩展边界

```text
ProtocolDescriptor
  ├─ Config schema + migration
  ├─ Editor provider (UI assembly only)
  ├─ Session factory (core contract)
  ├─ Typed operations (protocol-specific)
  ├─ Capabilities + diagnostics
  └─ Tests + package/deployment manifest
```

插件不得引用 UI 宿主程序集；UI editor 通过 UI 扩展点独立加载，运行时 driver 依赖 SDK/core 契约。未知插件或版本不兼容时显示“协议驱动不可用”及原因，仍允许导出/删除配置；不得因一个插件缺失导致整个管理器崩溃。

## 7. 安全、可靠性与可观测性

- 明确区分用户输入错误、DNS/网络失败、超时、协议拒绝、证书不信任、身份认证失败、驱动缺失及取消；错误携带阶段和可操作建议。
- 日志采用结构化字段，敏感数据脱敏；原始报文捕获默认关闭或有明确授权/保留策略。
- 设置连接/读取/写入/队列上限；防止 UI 因高速接收阻塞；使用有界 Channel 或等效背压机制。
- 重连策略不适用于所有协议：仅 descriptor 声明支持且协议语义安全时开放；OPC UA 重连后需重建 Session/Subscription 并报告恢复状态。
- Server 端 TCP 会话逐客户端隔离，不能用单个全局接收缓冲区混合数据。
- 对证书失效、过期、Endpoint 与 Application URI 不匹配、策略不支持提供显式诊断；默认安全优先。

## 8. 实施阶段与验收门槛

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| A：契约与配置 | DTO/schema、注册表、迁移、状态/错误模型、密钥引用接口 | 配置往返、旧配置迁移、未知协议降级测试通过 |
| B：运行时基础 | 生命周期管理、取消/释放、日志/事件、有界队列、真实 TCP/UDP/串口 | 本机回环/虚拟串口测试证明确实收发；UI 关闭可释放资源 |
| C：工业驱动 | Modbus TCP/RTU、CIP TCP、S7 TCP 类型化操作 | 模拟器测试 + 至少一类真实设备验证；地址/类型边界清楚 |
| D：OPC UA Client | endpoint discovery、证书/身份、安全连接、browse/read/write/subscribe | 安全模式与身份测试、未知证书拒绝、重连后订阅恢复、真实服务器验收 |
| E：产品 UI/工作流 | 协议表单、调试面板、工作流工具快照接入、主题一致性 | 无选中设备空态正确；协议字段隔离；界面人工验收；工作流取消/并发正确 |
| F：发布 | 驱动依赖打包、插件兼容性、升级/卸载诊断 | 干净环境 Release 安装验证，无依赖缺失或开发机路径依赖 |

每个协议最少验收：有效/无效配置校验；连接成功/拒绝/超时；操作成功/异常响应；取消；断线及重连；并发访问；应用关闭清理；协议字段主题与缩放；日志脱敏。具体构建命令依项目协作约束执行，任何需要构建的验证需遵循当轮审批要求。

## 9. 需要实施前冻结的事项

1. **Modbus 串口表单细节**：用户尚未给出串口模式截图，站号、超时、串口复用策略等以截图/需求确认后冻结；本文件的字段列表是推荐设计。
2. **CIP/S7/OPC UA 驱动与许可**：选用 SDK 前核对商业许可、目标框架、原生依赖、打包与安全维护；协议 UI 方案不等于已选定第三方库。
3. **设备能力验证**：确定测试 PLC、OPC UA Server、串口设备/模拟器及其可访问窗口；对没有真实硬件的功能注明模拟器覆盖边界。
4. **当前代码真实程度**：既有通讯 UI/参数编辑能力不代表真实驱动接入完成。实施时逐个以真实握手/协议操作验收，不把配置创建、进程存在或 UI“已连接”当作成功。
