# 通讯解析字段与统一绑定模型实施计划

基线方案：[通讯解析字段与统一绑定模型最终优化方案-20260929.md](./通讯解析字段与统一绑定模型最终优化方案-20260929.md)

## 1. 实施目标

在不破坏现有工作流配置和已完成通信管理器 UI 的前提下，逐步落地以下能力：

1. 通讯解析项拥有创建后不变的稳定字段 ID。
2. 显示名称可以修改，已有组装绑定和下游引用不会因名称变化失效。
3. 新增字段即使复用显示名称，也不会继承已删除字段的绑定。
4. 组装配置只显示当前事件允许的数据源，不默认追加全局变量。
5. 解析、组装、脚本、子程序后续使用一致的字段/绑定语义。
6. 脚本继续保持所见即所得：正常情况下脚本变量名与显示名称一致。

## 2. 当前基线和边界

### 2.1 已有实现，不重复设计

通信管理器已经完成较多界面级调整，包括：

- 接收事件列表、重命名、删除和空状态。
- 协议解析/协议比对详情页及输入配置、组装配置页签。
- DataGrid 独立滚动、解析消息区域固定在底部、`＋` 不被遮挡。
- `string` 使用文本输入，数值使用范围控件。
- 绑定设备下拉显示名称、导航高亮和主题化样式。
- 组装“内容”使用 SDK `ParamBinding`，并已关闭通信管理器的全局变量数据源。

### 2.2 当前缺口

- 协议解析/比对字段仍需要从临时 VM 模型收敛为可持久化的稳定字段模型。
- 组装绑定仍需要从名称/路径兼容方式迁移到稳定字段 ID。
- 接收解析的运行时 `Value / Result / Status` 需要接入真实执行链。
- 旧配置需要迁移、失效绑定需要可见提示。
- 脚本和子程序暂不在第一阶段改造，但必须预留统一绑定契约。

### 2.3 本轮不做的内容

- 不重写通讯设备驱动和底层连接协议。
- 不一次性改造所有普通工具的参数面板。
- 不立即删除全局变量能力；先改为显式数据源提供，保留兼容开关。
- 不把 GUID 直接显示给用户。

## 3. 分阶段实施顺序

### 阶段 0：建立模型和影响面基线

目标：先确认现有数据结构和持久化边界，避免在 XAML 层继续堆补丁。

重点检查：

- `src/UI/Features/CommunicationManager/CommunicationEventViewModels.cs`
- `src/UI/Features/CommunicationManager/CommunicationManagerViewModel.cs`
- `src/UI/Features/CommunicationManager/CommunicationManagerDialog.xaml`
- `src/Plugin.SDK/UI/Controls/ParamBinding.cs`
- 通讯事件序列化、快照和工作流保存入口。

产出：

- 通讯解析字段、组装项、输入/输出项的现状映射表。
- 字段创建、删除、重命名、保存、加载、运行时解析的调用链。
- 当前名称绑定路径的兼容清单。

验收：不修改业务行为，能够明确每个字段从配置到运行时的生命周期。

### 阶段 1：落地通讯字段身份模型

目标：先让协议解析/比对输入项和解析输出项具备稳定身份。

新增或统一字段概念：

```text
FieldId      Guid，创建时生成，永不复用
Name         显示名称，允许修改
TypeName     int/float/string 等
Value        运行时解析值
Result       展示值或结果文本
Status       未接收/匹配通过/匹配失败等
```

规则：

- 新增 item 生成新的 GUID。
- 删除后允许复用 `in2` 等显示名称，但不能复用旧 GUID。
- 序号只用于显示，不参与绑定。
- `Name` 在同一字段集合内必须唯一。
- 脚本相关字段另行保留脚本命名校验，不在本阶段混入通信 UI。

验收：保存、重新加载、删除后新增字段时，GUID 和显示名称行为符合规则。

### 阶段 2：改造组装绑定和数据源目录

目标：让组装配置绑定解析字段，而不是绑定名称字符串。

绑定记录统一保存：

```text
SourceNodeId
SourceFieldId
SourceNameSnapshot
BindingDisplayText
```

实现内容：

- 通讯组装页只注入当前事件解析列表字段。
- `ParamBinding` 不再自行追加全局变量。
- 解析字段改名时，按 `SourceNodeId + SourceFieldId` 更新显示快照。
- 删除字段时，将引用标记为“字段已删除”，不自动改绑。
- 新增同名字段不能恢复旧绑定。
- 绑定源显示名称与内部身份分离。

兼容策略：

- 旧版只有名称/路径的绑定，加载时按旧路径尝试一次迁移。
- 能唯一匹配时补齐 `SourceFieldId`。
- 无法唯一匹配时保留失效绑定并提示，不静默指向其他字段。

验收：重命名、删除、同名新增、保存重载四类场景均不出现错误串绑。

### 阶段 3：接入真实解析执行和持久化

目标：让界面配置真正驱动解析运行时。

2026-09-29 本批落地：文本长度改为分隔前整报文校验；字段数／类型统一验证后再更新字段；失败清除旧值并记录原因；比较状态为 `OK/NG`；组装结果仅在整体通过后更新，配置 `Content` 不再被运行时覆盖；TCP 客户端、TCP 服务端（各客户端独立）及串口按可选结束符组帧。通信相关 Debug 测试 34/34 通过，全量 Debug 构建通过（0 错误）。尚未完成真实界面／设备人工验收；无结束符的 TCP 仍按底层读取块交付，不能保证一次读取恰好是一条业务报文。

实现内容：

- 解析结果写入对应字段的 `Value`。
- 设备先按结束符／协议边界形成完整报文；文本长度使能时先校验**整报文字符数**（分隔符计入），再按分隔符拆字段，禁止按长度切片。
- 按列表顺序读取已配置字段并验证类型；报文多出的分隔段不要求有对应 item。文本模式分隔后保持 `string`，不隐式转为 `int/float`；缺少必需字段或类型不匹配时本轮整体失败：清空字段结果并置 `NG`，不发布部分成功字段，不触发依赖成功事件的流程。
- `Result` 保存用于界面显示的文本或转换结果。
- `Status` 表示最后一次接收数据的状态和匹配结果：成功解析后“不比较”为 `OK`；数值范围（含端点）或字符串等于／不等于按规则给 `OK/NG`；未接收和解析失败不能显示 `OK`。
- 解析历史同时记录时间、设备、原始字节、成功／失败及原因；十六进制是同一原始数据的展示方式。
- `string` 字段使用文本比较值。
- 数值字段使用 NumericUpDown/范围配置。
- 输入配置、组装配置和事件类型正确序列化。
- 解析异常、连接失败、字段缺失不可复用上一轮成功状态；运行时发布须保证同一报文的字段结果一致。

验收：真实接收一条消息后，字段值、结果、状态和组装输出可追踪；重启后配置仍可恢复。

### 阶段 3.5：协议目标绑定与类型化来源

依据 [通讯接收来源与目标绑定最终方案](./通讯接收来源与目标绑定最终方案-20260930.md) 实施，不能用 `IsModbus || IsS7` 代替目标能力判断。

1. 定义协议提供的目标种类与候选：无目标、Modbus 地址块、S7 内存区域、CIP 对象属性、OPC UA 数据点。UI 按目标种类显示准确标签；Modbus／OPC UA 优先使用现有稳定目标 ID。S7／CIP 先建设可持久化目标目录，当前手动测试参数不得视为已绑定事件。
2. Modbus FC03 轮询结果携带设备和地址块 ID，先把寄存器数据展开为确定顺序的字节，再按绑定目标送入字节规则；不把 Modbus 帧头或所有地址块混进同一事件。目标失效或规则失败时清空结果、状态 `NG`。
3. OPC UA 数据点变化携带设备、点 ID／NodeId、原生值、质量与时间戳。先验质量，再按真实类型比较；不要一律 UTF-8 解码或数值强转。S7／CIP 待目标目录后按同一契约接入。
4. 成功事件交给执行层触发／回复；WPF 不直接调度流程。保存重载、目标删除／重命名、同名不同目标、设备切换、断线重连与多地址轮询必须回归。

当前字节匹配和 Modbus/S7 目标页仅具备 UI／配置持久化，运行时尚未接通；OPC UA 目标 UI 与运行时也未完成。每批先跑相关 Debug 测试及 UI Debug 构建，再做真机验收。

### 阶段 4：脚本适配统一字段契约

目标：保持脚本所见即所得，同时让外部绑定使用稳定 ID。

模型：

```text
FieldId       稳定绑定身份
DisplayName   界面显示名称
ScriptName    生成的 C# 字段名，正常情况下等于 DisplayName
Value         运行时值
```

实现内容：

- 脚本输入/输出配置补齐稳定 ID。
- 自动生成的 C# 声明继续使用显示名称。
- 保存时校验名称为合法且唯一的 C# 标识符。
- 修改名称时执行安全重命名，同步脚本声明和脚本引用。
- 更新输出契约及下游绑定的显示快照，绑定仍按 FieldId 识别。
- 旧脚本配置加载时补齐 ID，并保留旧名称兼容迁移。

注意：不采用“脚本显示名称是温度、真实字段永远是 input_001、靠隐藏转换”的默认方案，因为这会损害所见即所得和编译错误定位。

验收：新增、重命名、删除脚本输入输出后，脚本编辑、编译、执行和下游绑定均保持一致。

### 阶段 5：子程序及其他数据源适配

目标：将统一字段语义推广到其他需要参数绑定的模块。

- 子程序输入使用稳定 `BindingKey`。
- 子程序输出增加稳定 `OutputId`。
- 普通工具、ROI 等页面按需显式注入数据源。
- 需要全局变量的页面显式启用全局变量提供器。
- 不需要全局变量的页面不创建、不展示全局变量节点。

验收：数据源树只显示调用方声明的数据源，已有全局变量使用场景保持兼容。

### 阶段 6：清理过渡兼容逻辑

目标：在完成迁移和验证后，收敛旧名称绑定和隐式数据源逻辑。

- 统计仍使用旧名称绑定的配置。
- 对无法迁移的配置提供明确修复入口。
- 默认关闭隐式全局变量追加。
- 保留必要的读取兼容，避免旧工程无法打开。
- 删除重复的名称遍历、字符串猜测和 UI 隐藏逻辑。

## 4. 测试和验收矩阵

### 通讯管理器

- 无事件时不显示详情。
- 新增字段自动生成 GUID。
- 删除 `in2` 后新增字段可以显示 `in2`，但 GUID 不同。
- 重命名字段后组装绑定仍指向原字段。
- 删除有引用字段时出现确认或失效绑定提示。
- 同名字段不能导致旧绑定恢复或串联。
- `string` 显示文本输入，数值显示范围控件。
- 解析结果状态反映最后一次接收数据。
- 长度使能时 `ABC,2` 按完整文本长度 5 校验后仍分出两个字符串段；若某输出配置为数值类型，则本项目文本模式按类型不匹配报 `NG`，不暗中转换。长度不符不产出字段、不触发流程；关闭长度校验时也不能把逗号当字段。
- 只配置一个 `string` 字段时，`4,3,4,5,6,7` 应得到 `"4"/OK`；字符长度比较关闭时不因多余分段失败，开启并设置 11 时按整条报文校验，设置 1 时长度失败。同报文若首字段配置 `int`，结果应为空且状态 `NG`。
- `int/float` 的“不比较／范围”和 `string` 的“不比较／等于／不等于”分别验收；范围外为 `NG`，解析失败不是 `OK`。
- 原始接收、解析成功和解析失败均有可辨认的历史，切换十六进制显示不改变解析结果。
- DataGrid、消息面板和 `＋` 在不同窗口高度下不互相遮挡。

### 脚本

- 自动生成变量与界面显示名称一致。
- 名称非法或重复时阻止保存并给出原因。
- 安全重命名会同步修改脚本引用。
- 编译失败时错误位置仍可定位。
- 旧脚本配置可以加载并补齐稳定 ID。

### 兼容性

- 旧配置名称绑定迁移成功。
- 无法迁移的绑定不会静默改指向。
- 需要全局变量的现有页面继续可用。
- 通讯管理器不会看到不属于当前事件的全局变量。

## 6. 风险和回滚策略

- 任何阶段先增加兼容读取，再切换新写入格式。
- 不直接删除旧字段或旧绑定属性，至少保留一个迁移周期。
- 每个阶段保持可独立构建和运行。
- 发现旧配置无法迁移时，停止清理阶段，保留兼容路径。
- 脚本重命名必须可撤销；重命名失败时不保存半更新状态。
- UI 布局调整与数据模型改造分开提交，便于定位回归。
