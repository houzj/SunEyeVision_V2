# 通讯解析字段与统一绑定模型最终优化方案

日期：2026-09-29
状态：沟通基线，待分阶段实施

## 1. 目标

统一通讯解析、脚本、子程序和普通工具参数的输入输出模型，解决以下问题：

- 解析列表名称修改后已有组装绑定失效。
- `ParamBinding` 自动追加不属于当前场景的全局变量。
- 新增、删除、重命名字段后绑定身份不稳定。
- 脚本、子程序、通讯解析各自维护不同的输入输出规则。
- 解析出的运行时值没有明确归属。

## 2. 核心原则

绑定身份与显示名称必须分离：

```text
FieldId：稳定 GUID，创建后永远不变，不复用
Name：显示名称，可修改、可复用
Value：运行时实际值
```

不建议通过运行时修改普通 C# 类型来增加属性。动态字段应由字段定义集合承载，运行时值写入对应字段对象的 `Value`。

脚本是特殊场景：脚本编辑器可以根据配置生成 C# 字段声明并重新编译。为了保证脚本内所见即所得，正常情况下生成的 C# 字段名应与界面显示名称一致；稳定字段 ID 只用于绑定和识别，不直接显示在脚本中。

## 3. 统一字段模型

建议抽象为：

```csharp
public sealed class DynamicField
{
    public Guid FieldId { get; set; } = Guid.NewGuid();
    public string Name { get; set; } = string.Empty;
    public string TypeName { get; set; } = string.Empty;
    public object? Value { get; set; }
}
```

通讯比对字段可扩展：

```text
FieldId
Name
TypeName
CompareRule
Minimum / Maximum 或 CompareValue
Value / Result / Status
```

组装字段保存对解析字段的引用，不复制解析值。

## 4. 绑定引用与快照

绑定不再以名称作为身份，保存以下信息：

```text
SourceNodeId
SourceFieldId
SourceNameSnapshot
BindingDisplayText
```

示例：

```text
SourceNodeId：ReceiveEventInputs
SourceFieldId：7f4d6b2e-...
SourceNameSnapshot：in1
BindingDisplayText：解析列表.in1
```

实际绑定路径使用稳定 ID，显示文本使用当前名称：

```text
绑定身份：ReceiveEventInputs.{FieldId}
界面显示：解析列表.in1
```

名称从 `in1` 改为 `温度` 时，只更新快照和显示文本，`FieldId` 与绑定身份不变。

## 5. 重命名处理

字段重命名发布统一变更事件：

```text
SourceNodeId
FieldId
PreviousName
CurrentName
```

绑定消费者根据 `SourceNodeId + FieldId` 更新：

- `SourceNameSnapshot`
- `BindingDisplayText`
- 数据源树中的显示名称
- 结果树和调试面板显示

禁止通过遍历字符串或显示文本猜测绑定对象。

## 6. 新增与删除字段

### 新增

- 每次新增生成新的 GUID。
- 显示名称可以使用 `in1`、`in2` 等可读编号。
- 删除后可以复用显示名称空洞，但不能复用 GUID。
- 新字段不能继承旧字段的绑定。

示例：

```text
旧字段：FieldId=A，Name=in1
删除后新增：FieldId=B，Name=in1
```

虽然名称相同，但 A、B 是两个完全不同的字段。

### 删除

- 删除前检查是否存在绑定引用。
- 有引用时提示用户确认。
- 确认后移除字段，并将相关绑定标记为“字段已删除”。
- 不自动改绑到其他字段。
- 序号可以重新排列，但序号不参与绑定。

## 7. 数据源提供方式

`ParamBinding` 只展示调用方提供的数据源，不主动追加业务数据源。

建议后续移除内部硬编码的全局变量节点，改为数据源提供器或数据源目录：

```text
LocalFieldDataSourceProvider
NodeOutputDataSourceProvider
GlobalVariableDataSourceProvider
SubroutineInputDataSourceProvider
```

每个页面只注入需要的数据源：

```text
通讯组装配置：解析列表字段
普通工具参数：节点输出 + 全局变量
ROI：ROI 数据源 + 全局变量
子程序：子程序输入 + 上游节点输出
```

当前 `AllowGlobalVariableBinding` 仅作为过渡能力配置，最终应收敛为显式数据源注入，而不是“先生成再隐藏”。

## 8. 通讯管理器模型

### 解析配置

解析列表由字段定义组成：

```text
解析字段
├── FieldId
├── Name
├── TypeName
├── CompareRule
├── 范围或字符串比较值
├── Value
├── Result
└── Status
```

解析完成后：

```csharp
field.Value = parsedValue;
field.Result = parsedValue?.ToString();
field.Status = match ? "匹配通过" : "匹配失败";
```

### 组装配置

组装内容使用参数绑定控件，数据源仅来自当前事件的解析字段集合。

组装项保存 `SourceFieldId`，运行时读取对应解析字段的 `Value`。

组装配置不显示全局变量，也不使用普通文本框替代参数绑定。

## 9. 脚本模型对齐

当前脚本会根据 `Inputs` 和 `Outputs` 生成 C# 字段并编译执行。后续需要区分稳定身份和脚本可见名称：

```text
FieldId：绑定身份
DisplayName：界面显示名，也是正常情况下生成的 C# 字段名
ScriptName：生成层最终使用的 C# 字段名；正常情况下等于 DisplayName
```

脚本必须保持所见即所得：用户在脚本中看到并使用的变量，应与输入输出配置中显示的名称一致。

字段名称需要满足以下规则：

- `DisplayName` 必须是合法且唯一的 C# 标识符；不满足时保存配置应提示用户修改。
- 正常情况下 `ScriptName = DisplayName`，不引入用户看不见的隐藏变量名。
- 修改显示名称时执行安全重命名，将脚本中的旧变量引用同步替换为新变量名。
- 同步更新输出契约及下游绑定的显示快照，但绑定身份仍使用 `FieldId`。
- 如果未来必须支持不符合 C# 标识符的显示名称，只能通过明确的别名映射实现，且必须保证脚本编辑、编译错误和调试信息可追踪；不作为当前默认方案。

脚本运行时仍可使用输入值字典和输出值字典，生成字段是脚本代码的访问适配层；字段对象的 `FieldId` 和 `Value` 负责运行时归属，脚本变量负责可见访问。

## 10. 子程序模型对齐

子程序输入继续使用稳定的 `BindingKey`，`Name` 作为显示名称。

子程序输出增加稳定 `OutputId`，不要只用输出名称作为身份。

输出重命名时：

- 更新结果树。
- 更新图像输出列表。
- 更新输出契约。
- 根据稳定 ID 更新下游绑定。

旧版本仅有名称的配置，加载时按旧名称迁移一次；无法匹配时显示失效绑定，不静默指向其他输出。

## 11. 通讯管理器界面要求

保留并统一前期确认的交互规则：

- 导航只由 `ActivePage` 控制高亮。
- 导航文字水平、垂直居中，并适配主题。
- 事件列表支持右键重命名和删除。
- 没有事件时不显示详情区域。
- DataGrid 使用独立滚动条。
- 解析结果区域固定在底部，不遮挡 DataGrid、滚动条和 `＋`。
- `＋` 始终可点击，展开消息时至少保留 4～5 个列表项可见。
- `string` 使用 TextBox，数值使用 NumericUpDown 或范围控件。
- 分隔符使用 ComboBox。
- 组装配置中只有启用“回复给设备”时才显示分隔符。
- 序号和状态文本居中。
- DataGrid 空区域使用主题背景，不显示白色空条。

## 12. 旧数据迁移

兼容旧绑定路径：

```text
ReceiveEventInputs.in1
```

加载时按以下顺序处理：

1. 优先读取稳定 `SourceFieldId`。
2. 旧配置没有 ID 时，使用旧名称匹配一次。
3. 匹配成功后写回稳定 ID。
4. 匹配失败时标记“数据源已删除”。
5. 禁止自动改绑到其他同类型字段。

## 13. 实施顺序

1. 增加通讯字段 `FieldId` 和绑定引用模型。
2. 将解析结果写入字段 `Value`。
3. 将组装内容绑定改为 `SourceFieldId`。
4. 实现字段新增、删除、重命名事件。
5. 实现绑定引用自动刷新和失效提示。
6. 移除 `ParamBinding` 内部默认全局变量追加逻辑。
7. 改造普通工具、ROI、脚本和子程序的显式数据源提供。
8. 增加旧配置迁移。
9. 完成通讯接收、协议解析、协议比对和协议组装运行时接入。
10. 进行 UI、运行时、保存加载和重命名回归测试。

## 14. 验收标准

- 新增字段生成新的 GUID。
- 删除后重新新增同名字段不会继承旧绑定。
- 修改显示名称不会改变绑定身份。
- 组装配置只显示解析字段，不显示全局变量。
- 解析值能写入对应字段并被组装读取。
- 删除被引用字段后显示失效绑定，不误绑其他字段。
- 脚本和子程序输出改名后，结果树及下游绑定保持一致。
- 旧配置能够迁移，无法迁移的引用明确提示。
- SDK Debug、UI Debug、UI Release 构建通过，并完成运行时人工验收。
