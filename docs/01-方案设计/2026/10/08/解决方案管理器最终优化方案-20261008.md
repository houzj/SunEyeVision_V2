# 解决方案管理器最终优化方案

- 更新日期：2026-10-08
- 状态：代码实施及自动验证完成，2.0.0.7_alpha 最终安装包已生成；安装现场验收待人工确认
- 适用项目：SunEyeVision V2
- 代码基线：main，d703960764e0f1cdd287c8398def759ad638251d
- 决策边界：以本方案覆盖此前沟通中不一致的目录、资源打包及配置备份设计；历史文档保留，不代表当前目标已经实现。

保留现有解决方案管理架构，修复操作一致性，分离软件配置和方案目录，支持任意路径载入与资源重新配置。暂不增加资源打包、自动收集或复杂备份管理。

用户只需管理自己的方案和资源；软件配置由软件在用户指定的数据根目录内维护。失效路径不能阻止用户清理引用。

## 一 目录与配置归属

安装目录只放程序和依赖。首次使用时选择数据根目录，优先建议非系统盘，但不硬编码 D 盘，也不在用户未确认时随意选择磁盘。

例如选择 `D:\SunEyeVisionData`：

| 路径 | 用途 |
|---|---|
| `Config\user-settings.json` | 软件配置：最近记录、默认方案、主题、启动偏好 |
| `Solutions\` | 默认方案保存位置，不限制其他保存位置 |
| `Logs\` | 软件日志，限制保留时间和大小 |

明确规则：

- 软件配置不放桌面，不放方案目录，也不依赖安装路径。
- `Solutions` 只是默认位置，用户可以把方案保存在任意可写位置。
- 不建立独立的 `Backups\Config` 目录。
- 数据根目录必须存在或可创建，并且实际运行程序的普通用户可写；不通过强制管理员运行规避权限问题。
- 数据根目录不可用时明确提示，不静默创建空配置替代原配置。
- 升级和卸载默认保留数据。
- 支持查看和更改数据位置；迁移遵循先复制、验证、切换的规则。

Windows 用户目录只保存可重建的数据位置记录，不作为重要配置的唯一存储位置。系统重装后，重新选择原数据根目录即可恢复。

非系统盘能够降低系统重装误删风险；同一硬盘的其他分区并不是独立备份。

## 二 方案文件必须能独立传递

`.solution` 保存完整业务配置：

- 方案 ID、名称、描述。
- 工作流、节点参数、全局变量。
- 相机、通讯和执行配置。
- 资源引用及方案格式版本。

软件配置只保存本机管理信息，不成为方案运行的必要附件。

用户之间传递方案时，不需要一起传递 `user-settings.json`，也不会覆盖接收方的主题、默认方案或最近记录。管理器中的名称、描述和统计信息是缓存，方案文件是这些信息的来源。

### 任意路径载入

支持从任意可读位置添加和打开方案，不自动复制到默认方案目录。

- 可读但不可写：允许载入，保存修改时提示另存。
- 文件失效：保留管理记录，提供重新定位或移除记录。
- 不支持的方案格式、缺少插件：明确提示，不静默丢弃配置。
- 同一文件重复添加：更新原记录，不生成重复条目。
- 不同路径存在相同 ID：提示替换记录或创建独立副本，不能自动混为一条记录。

手动传递原方案保留 ID；“创建副本”生成新 ID。路径比较、文件身份识别和记录更新由管理层统一处理。

## 三 资源文件单独传递和重新配置

不增加方案包、自动资源收集或强制资源目录。图片、模型、标定文件等资源可以单独传递，接收方重新选择路径。

处理规则：

- 资源引用使用明确的路径基准，不依赖进程当前目录或安装目录。
- 数据根目录内的管理路径以数据根目录为基准；方案内部相对资源路径以方案所在目录为基准。外部绝对路径不承诺跨电脑自动有效。
- 资源丢失不阻止载入方案。
- 对应配置位置显示“文件失效”，提供重新选择、移除和清空。
- 执行到确实依赖缺失资源的节点时，报告具体节点和文件，不使用过期缓存冒充有效资源。
- 重新配置后，将新引用保存到接收方方案，不改动发送方文件。

相机和通讯设备只传递配置，不保证接收方具有相同硬件。不能把“方案载入成功”当作“所有设备均可连接”。

## 四 图像预览器允许清理失效文件

用户反馈“文件丢失后无法清空”是专项检查和修复项，代码根因尚待核查，不能将该现象写成已定位或已修复。

最终行为：

| 操作 | 应有行为 |
|---|---|
| 移除选中项 | 不检查文件是否存在，直接移除引用 |
| 移除失效项 | 只移除失效引用，保留有效项 |
| 清空 | 清除全部列表、选中项、当前路径和预览缓存 |
| 重新选择 | 替换失效引用，刷新预览和配置 |
| 打开失效文件 | 显示失效状态，不重复弹错或阻塞其他操作 |

“清空”判断依据是列表、配置或缓存中是否有内容，而不是文件是否存在。

还需要保证：

- 移除引用不等于删除磁盘文件。
- 清空后的状态真正写回方案，重新打开不恢复旧列表。
- 文件加载采用取消或请求版本校验，旧异步结果不能在清空后重新填回预览。
- 显示预览的清理与工作流执行快照分离，不直接修改正在执行的一轮输入。
- 原文件不存在时，重新配置、移除和清空仍然可用。

## 五 管理器界面与操作语义

保留“最近打开＋全部方案”，增加明确的选中项详情和打开按钮。

顶部保留“新建方案”“添加已有方案”和搜索。选中项操作区或右键菜单提供打开、重命名及修改描述、创建副本、另存为、设为启动默认、打开所在目录、移除记录和删除文件。

详情显示名称、描述、完整路径、修改时间，以及当前打开、启动默认和文件失效等明确状态。

| 操作 | 行为 |
|---|---|
| 新建 | 创建并选中新方案，不隐式关闭当前方案 |
| 添加已有 | 加入管理列表，不复制、不切换当前方案 |
| 打开 | 完成切换保护后加载 |
| 创建副本 | 新 ID，原方案不变，默认不切换 |
| 另存为 | 针对当前方案创建新 ID，成功后切换 |
| 重命名 | 保持 ID；文件名同步变化时检测冲突 |
| 移除记录 | 保留方案文件 |
| 删除文件 | 单独确认，显示完整目标路径 |

“创建副本”对当前方案使用最新编辑状态，对未打开方案使用磁盘内容。不能让用户以为复制了当前修改，实际却复制旧磁盘版本。

补齐空列表、搜索无结果和文件失效提示，以及键盘选中、Enter 打开。双击只是快捷方式，另有明确的“打开选中方案”主按钮。

选中、悬停、失焦和禁用状态全部适配亮暗主题；小窗口下布局不挤压，大列表使用虚拟化。

## 六 优先修复已确认的功能问题

以下问题必须先于界面美化：

1. 另存身份不同步：当前对象、方案 ID、路径、管理记录和界面状态同步切换。
2. 复制参数错位：目标目录不能传入描述参数，改用命名参数并验证结果。
3. 同名覆盖缺少保护：新建、复制、另存检测目标冲突，禁止无提示覆盖和覆盖源文件自身。
4. 切换保护不足：未保存修改提供“保存／不保存／取消”；运行中先由执行层停止并等待完成。
5. 窗口事件未释放：关闭时注销订阅，避免重复回调和窗口滞留。

另存、复制或切换失败时，原方案和当前工作区必须保持可用。文件写入成功与当前状态切换之间发生异常时，返回明确结果并保留可恢复状态。

最近打开时间只在成功打开后更新，修改描述、刷新列表和设为默认不得改变它。

## 七 保存与恢复机制保持简单

配置和方案均采用“校验、写临时文件、验证、原子替换、更新管理状态”的顺序。

具体要求：

- 临时文件位于目标文件所在目录，避免跨盘替换问题。
- 配置保存失败不把脏标记清掉，退出或关闭时明确提示。
- 不做日常配置多版本归档；只在格式升级或迁移前保留内部恢复副本。
- 不增加独立配置备份目录或配置备份管理窗口。
- 方案保留一份上一成功保存版本，作为简单故障恢复，不增加复杂历史版本管理。
- 恢复文件使用软件内部数据位置管理，不在桌面长期散落 `.bak`。
- 外部方案跨盘保存时，备份复制与目标原子替换分别处理，不能假设跨盘操作是原子的。
- 保存失败不能静默宣称保存或备份成功，管理状态只在对应操作成功后提交。

恢复文件的维护不影响用户正常传递 `.solution`。删除引用和清空列表不得删除这些引用对应的磁盘资源。

## 八 启动方式与文件图标

将“启动时跳过”改为明确选项：

- 每次选择方案。
- 打开上次方案。
- 打开指定默认方案。

自动打开失败时返回管理器，显示失败原因和处理入口。

文件关联优化：

- 正常发布渠道均注册 `.solution` 文件类型、图标和打开命令。
- 关联指向已安装版本，不指向旧 Debug 或 Release 开发路径。
- 调试运行不默认覆盖安装版关联。
- 尊重 Windows 已有用户默认选择，提供正规修复入口。
- 双击文件可以从任意路径进入同一套载入和切换流程。

方案格式版本与软件版本分开，不因复制方案而重置格式版本。

## 九 旧数据迁移

首次启用新结构时，采用“先备份、复制、验证，再切换”。

1. 用户确认新的数据根目录。
2. 读取桌面旧 `solution_settings.json`。
3. 按旧目录解析相对路径，再转换到新的路径基准。
4. 保留最近记录、默认方案和用户偏好。
5. 将旧配置中的名称、描述补入对应方案文件，修改前保留恢复副本。
6. 处理已有 `.bak`，保留恢复能力。
7. 验证配置、方案及文件引用，并生成迁移结果。
8. 验证成功后切换到新配置位置。

不强制搬走用户桌面的方案，保留原位置也可以载入。迁移支持重复执行和失败回退；失效文件、重复 ID 或已有新配置冲突应提示确认，不猜测、不覆盖。

不直接删除桌面文件。迁移成功后，旧内部配置和备份的清理由用户单独确认。

## 十 架构边界与实施顺序

### 架构边界

- 用户配置位置、数据根目录和默认方案保存目录独立，不再通过同一个 `SolutionsDirectory` 推导所有位置。
- 管理器 UI 负责选择、展示和发起操作，不承担工作流调度。
- 运行中的方案切换协调由应用执行层负责，停止完成后才能替换当前方案。
- 执行开始时使用输入和参数快照，预览器清理不修改当前执行快照。
- 文件读写、路径比较、记录身份和失败恢复由管理及存储层统一处理。
- 插件依赖和发布依赖仍通过构建规则部署，不让工具插件依赖 UI 宿主。
- 配置和文件关联变更需评估启动页、主题初始化、相机及通讯会话恢复的跨模块影响。

## 十一 验收标准

- 新建和添加方案不再往桌面生成内部配置。
- 普通用户运行不依赖安装目录写入权限。
- 任意路径、只读路径和跨盘方案能够正确处理。
- 单独传递方案后，名称、描述和业务配置完整，接收方软件偏好不被覆盖。
- 同文件重复添加和不同路径同 ID 有明确处理。
- 资源丢失仍可移除、清空和重新选择；清空后不会被旧加载结果恢复。
- 清空并保存后，重新打开不恢复旧资源列表；原磁盘文件不被删除。
- 另存后再次保存，内存与文件 ID 一致。
- 新建、复制、另存的同名冲突及同路径目标有保护。
- 保存失败、停止失败和同名冲突不破坏旧方案。
- 恢复配置时保留最近记录、默认方案和用户偏好。
- 重装后重新定位数据根目录能恢复管理配置。
- 数据目录不可写、暂时离线或配置损坏时明确提示，不静默覆盖。
- 迁移可重复执行并可回退，桌面原文件不自动删除。
- 文件图标及双击打开指向安装版，并正确处理旧关联。
- 亮暗主题、失焦、键盘操作、最小窗口和大列表正常。
- 全量 Release 构建、自动测试、真实运行、安装及 Visual Studio 设计时验收通过。

涉及发布或插件依赖规则时，按项目要求执行全量 Release 构建并运行 Release 程序验证。测试应使用独立夹具，不依赖个人桌面文件或真实设备。

## 十七 2026-10-09 图像预览器最终交互优化

此节仅覆盖图像预览器，不取消解决方案管理器对失效方案的定位/移除功能。

- 图片添加及配置恢复时跳过不存在的路径；恢复选中状态按原图片路径映射，不能沿用过滤前的数字索引。全部失效时为空列表、索引 -1，仍可重新添加图片；正常保存持久化有效列表，不因打开方案自动覆盖原文件。
- 删除预览器“移除失效”和“定位”操作。图片需要重新配置时直接添加文件或文件夹；右键只提供“移除图片引用”，单张移除及清空均不删除磁盘文件。
- 左键点击/明确键盘导航按运行模式执行所选图，并停留该图；未勾选图片在运行选择模式下不执行。右键、绑定、恢复等普通选中变化不触发工作流。勾选框/按钮的键盘操作不混入选图执行。
- 手动请求明确关闭本次自动推进；执行按钮及连续运行保留原策略，开启自动切换后成功才推进，失败/取消不推进。运行中拒绝新执行请求，既有输入快照不变。
- 保留选中索引/运行模式/自动切换的双向绑定；移除图片使用输入源已经修正的索引，避免再次扣减；全部重复或无效路径添加不改变选中项。
