## 2. 当前分析与待验证原因

2026-10-15已锁定“工作流执行正确，打开圆查找窗口、不改参数、点击工具执行就错位”的直接代码原因：`ImageSourceReference.MatchDataSource`恢复出的`AvailableDataSource`只有路径，不携带`CurrentValue`。圆查找窗口初始化会恢复此绑定；原CircleDetect算法只读该空值，将启用的修正静默当作无修正。工作流入口则在执行前主动填充此值，因此产生不同结果；交互层实时查询矩阵，使蓝色卡尺仍显示正确。此前以CircleCircleMeasure为主的修改未覆盖CircleDetect，不能作为本场景已修复的依据。

修复执行契约：绑定对象只表示引用，工具从本次NodeResults解析矩阵；预览值不作执行权威数据。CircleDetect算法、卡尺相位及屏蔽过滤使用同一捕获矩阵，缺源或无效时明确停止。调试入口复制节点参数，公共请求从查询服务采集当前源结果并以同一快照解析图像。`DataSourceQueryService.GetPropertyValue`实际直接读取WorkflowContext，无独立值缓存；此前缓存假设及“必须先引入完整工作流运行包”的推断不作为本次修复依据。

以下为前期检查的历史代码链路，圆圆相关部分已在后续批次修改：

- AlgorithmNode.ResolveAvailableDataSources执行前从本轮上游结果填充AvailableDataSource.CurrentValue。
- PositionCorrectionResolver.ResolveFirstMatrix只读取CurrentValue，空值返回null；绑定路径存在不等于运行矩阵有效。
- AvailableDataSourceConverter从字符串恢复时仅构造节点和字段引用，不填运行值。ToolDebugControlBase存在延迟绑定恢复，可能覆盖已带运行值的来源对象。
- CircleCircleMeasureToolDebugControl.UpdatePositionCorrectionMatrix直接读取参数绑定对象；OnExternalResultArrived重新调用同一方法，不保证重新查询上游值；位置修正开关与绑定变化缺少统一刷新生命周期。
- CircleCircleMeasureTool及FillDisplay分别从各自参数读取矩阵；交互图形则来自当前窗口参数，缺少共同图像／轮次／参考版本校验。

这些是已识别的代码缺口。截图具体由空矩阵、旧矩阵、图像不匹配、首次绑定坐标解释或多因素引起，仍需诊断和复现锁定，不能先宣布唯一根因。

蓝色交互引导与本次结果引导／卡尺带应一致；拟合圆相对引导圆的中心、半径差异可能是正常测量结果，不要求所有颜色图形无条件重合。

## 3. 坐标契约

| 对象 | 归属与转换 |
| --- | --- |
| 未启用位置修正的ROI | 按原参数直接显示和使用；关闭修正不转换数值 |
| 已建立修正关系的ROI | 保存参考坐标和参考关系身份 |
| 算法使用的区域／引导 | 参考几何经本轮有效矩阵转换到当前图像 |
| 交互图形、卡尺、手柄及命中 | 使用同一上下文及形状规则显示与交互 |
| 鼠标编辑写回 | 当前图像坐标逆变换为参考坐标 |
| 拟合结果、测点 | 已属当前图像坐标，禁止再次位置修正 |
| 视口缩放和平移 | 独立显示变换，不写入ROI参数 |

完整位置矩阵方向统一为参考到当前图像。绑定引用、参考几何和运行矩阵分离；首次绑定将已有数值作为参考坐标解释，不转换数值。同一来源每轮更新矩阵不改写参考ROI。

三个不变量：绑定不改ROI位置参数；打开窗口、刷新和切图不改ROI位置参数；只有用户实际编辑图形才通过逆变换更新参考参数。这里的位置参数包括中心、角度、尺寸及相关几何数据，不仅是X／Y。

圆等无向几何的中心定位、手柄方向与卡尺阵列相位分别按现有统一形状语义处理，不能直接把无向手柄的剥旋转矩阵用于整个算法。执行、显示、命中和逆编辑使用公共几何策略，避免各层重新解释。

工具须声明支持的变换类型。圆在非等比缩放、剪切下不再保持圆形；本批优先明确拒绝不支持变换，不用单一ScaleFactor静默近似。若未来支持几何升级为椭圆等，应独立设计输出、交互和算法契约。

## 4. 绘制与首次绑定顺序

### 4.1 先绑定再绘制

有效矩阵下在当前图像绘制，按相应几何逆转换保存为参考坐标，显示时正向转换，画面位置不跳动。矩阵无效、不可逆或图像身份不匹配时，禁止依赖逆变换的编辑，并提示原因，不按单位矩阵静默保存。

### 4.2 先绘制再绑定

首次绑定保留已有ROI全部位置参数，将这些数值作为参考坐标，按当前有效矩阵更新显示。图形可能平移、旋转或按支持规则缩放，这是预期行为；不弹出“保持当前画面位置”的转换选择，也不自动逆转换已有参数。

用户可以在非注册图像上先绘制。绑定后若图形不在目标位置，直接移动、调整更新后的图形；编辑器按当前图像对应的矩阵逆变换，保存新的参考参数。以后切换图像，使用新矩阵与这份参考参数计算显示位置。

例如当前矩阵水平平移100，已有X=500：首次绑定参数仍为500，显示X=600；用户拖动显示图形到X=550，保存参考X=450；下一张图像平移200时显示X=650。

矩阵未就绪时可保留绑定和原参数，但不得用旧矩阵或单位矩阵伪装有效显示／提交修正编辑。只有取得当前图像的有效矩阵后才恢复修正交互。

检测区、屏蔽区及多个关联引导的实际编辑按事务整体提交；失败或取消全不变，支持一次撤销／重做。逆转换只作用于当前节点拥有的本地几何，不能改写订阅的上游共享ROI；订阅／组合ROI的坐标来源和消费者转换关系须纳入统一解析契约。

## 5. 操作语义

| 操作 | 行为 |
| --- | --- |
| 同一参考来源更新本轮矩阵 | 更新运行上下文，不迁移参数 |
| 更换修正来源 | 明确变更来源并更新显示，保留位置参数；如注册基准不同，提示重新核对ROI，不自动迁移 |
| 临时关闭修正 | 保留参考ROI，显示未修正参考位置，开启后恢复 |
| 解除绑定 | 保留位置参数，不自动固化当前显示坐标；启用状态下提示未绑定 |
| 打开关闭窗口、刷新候选或重画 | 不迁移坐标、不写参数 |
| 匹配失败、空数组、无矩阵、来源失效 | 明确不可用，不静默沿用旧值或单位矩阵 |

绑定配置事务、图形编辑事务与显示刷新分开。绑定和换源可以改变来源身份，但不改ROI位置参数；只有实际图形编辑才逆变换写回。更换注册图像或重建模板基准不是普通切图，必须明确提示重新核对参考关系，不静默沿用或重算坐标。

## 6. 统一修正上下文

提供无WPF依赖的公共解析契约，至少包含启用状态、来源稳定身份、选中矩阵／索引、有效性与不可用原因、可逆性、支持变换类型，以及图像、运行轮次和参考关系版本。

状态至少区分未启用、有效、等待来源、空匹配、失效、不可逆和不支持变换。矩阵数组沿用已明确的选取策略，不在不同层各自选目标；多目标实例须使用明确作用域，不隐式展开。

执行使用本轮冻结上下文。结果保存实际使用的上下文与几何快照，不在重画历史结果时重新读取最新参数或最新矩阵。交互与结果必须能核对同图像、同轮次、同参考版本。上下文只保存必要身份与数据，不额外长期持有整幅图像造成泄漏。

当前编辑或图像已变化时，明确标记与历史结果不一致，默认不混合不匹配图层。历史重放使用历史上下文，不移动历史结果伪装重合。

一次拖动固定图像、矩阵和参考版本；拖动中切图或参考基准改变时取消尚未提交的编辑并刷新，不能在按下与松开时使用不同矩阵。矩阵必须来自对应图像的成功匹配，不能只取最近一次矩阵。暂时等待／空匹配不等于类型不适配，不能因此自动解绑；确定的来源删除或契约不适配仍遵循既有绑定适配规则。

## 7. 窗口生命周期与刷新

统一刷新入口覆盖所有初始化注入完成、修正开关／绑定变化、对应上游结果更新、显示图像或轮次切换：

1. 从稳定引用重新解析实际运行数据，不只重读旧AvailableDataSource。
2. 校验上下文及图像身份，忽略过期异步刷新。
3. 一次更新引导、卡尺、手柄、标签和命中上下文。
4. 不迁移坐标、不写设计参数。

关闭窗口解除订阅，避免重复事件及悬挂引用；按真实依赖通知已打开窗口，不以任意结果触发全量重算。UI只展示与编辑，工作流不访问控件，插件不依赖宿主程序集。

## 8. 旧方案兼容

旧方案缺少坐标归属时保留原始数值和已有执行行为，标记为旧版关系；不能根据坐标值猜来源，不能打开窗口或普通保存就自动逆变换。

统一采用绑定保留参数、图形随矩阵更新的规则，不提供本轮已取消的首次绑定逆转换选择。旧方案缺少参考身份时不得伪造图像／基准对应关系；必要时提示核对来源，允许用户在有效修正下重新调整图形，无须强制重画。参考身份和版本的补充不得改变原几何数值。具体持久化字段及兼容接口须在实施前对照当前模型明确。

## 15. 可信图像谱系与已知错帧门禁

SDK通过弱关联保存图像帧标识和结果实际输入帧，不以时间戳或对象地址猜测帧关系。ToolExecutor的同步及异步路径在调用工具前捕获输入身份，工具返回后记录结果身份。元数据只包含标识，不序列化、不增加可绑定输出、不额外持有图像。它是帧谱系，不是工作流运行轮次或模板版本。

传播必须由工具显式声明。图像源每次产出新帧，即使复用同一图像对象也更新身份；本批核对图像滤波、两类阈值工具、形态学和轮廓匹配保持图像坐标，故其显示图像输出继承输入帧。裁剪、缩放、变形等改变坐标的输出不得声明保持坐标；未接入插件不自动推断谱系。

圆圆使用的位置修正解析器支持两条路径：调试查询从来源结果和当前图像读取，正式执行从本次NodeResults及ResolvedInputImage读取。双方身份已知且不一致时返回ImageFrameMismatch，禁止修正编辑和算法执行，提示对当前图像重新匹配；已知矩阵来源但当前图像缺失则等待。来源结果在查询中替换也等待，不接受跨代值。重新匹配同一当前帧后自动恢复，ROI参数不变。

兼容边界明确区分：未知来源仍可使用，但FramePairingVerified为false，显示图像帧关系未验证；只有可信身份相等才标记已验证。不因旧插件未接入就清绑定或全面拒绝执行。

回归覆盖同步／异步入口、同对象新帧、前处理派生图像、旧匹配保持旧输入身份、错帧拒绝、重新匹配恢复、查询中来源替换、未知旧插件兼容，以及真实圆圆窗口禁用／恢复且参数不变。最终SDK76项、圆圆15项、UI172项通过；全量Release0错误1089警告、UI0错误1064警告；实际Release安全探针退出0、SDK测试发布哈希一致。证据artifacts/validation/roi-frame-20261014。

## 16. 实际预览位图帧桥接

2026-10-15补齐上一节所述主预览桥接缺口。统一IVisionImage到BitmapSource转换器把转换时的可信帧身份存入SDK UI弱元数据，位图只关联标识，不持有源图像。转换前后源身份变化时返回无图，避免发布不确定帧；源对象以后再次产出新帧，旧位图仍保留旧身份。未知源不猜测身份，复用元数据登记接口也允许清除旧标识。

位置修正快照携带CorrectionFrameId，ForPreview只接受帧标识和有无图像状态，不让执行层读取WPF控件。共享双元素编辑器在实际SourceImage变化时先取消／回滚未完成交互，再通知圆圆窗口重新校验。即使参数图像来源没变，实际预览切到另一已知帧也会禁用修正编辑；切回对应帧恢复，空预览暂停。未知预览保留兼容但显示未验证，不能标为已验证。该校验不阻止使用正确输入图像的后台算法，仅约束当前预览上的编辑；算法继续使用输入帧校验。

验证包括统一转换器的帧快照保持、转换中换帧不发布、未知兼容，以及真实窗口切换错误预览时回滚宿主参数、恢复正确预览、空图暂停。最终圆圆15项、SDK76项、UI联合174项通过；全量Release0错误1041警告，UI0错误1064警告。实际Release安全探针退出0，SDK测试发布哈希一致。证据artifacts/validation/roi-preview-frame-20261015。
