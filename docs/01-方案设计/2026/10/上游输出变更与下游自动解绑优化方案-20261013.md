# 上游输出变更与下游自动解绑优化方案

更新日期：2026-10-14。状态：核心解绑、B1和B2统一关系描述已实施；B3独立配置事务核心已加入，宿主整体接入、增量索引和全入口人工验收仍待完成。

本方案以一份正式配置为依据，统一生成绑定关系、适配检查和执行依赖。节点、参数、连接、全局变量关系及撤销重做都进入同一个变更提交流程。先准确处理变化影响，再通过引用索引加速；不依靠控件刷新决定绑定是否合法。首批实现作为基础保留，不能扩展成彼此独立的清理入口。

## 旧方案回归修复优先级

新增执行回归定位：设计节点转为AlgorithmNode时，构造器把ToolType写成类别“Algorithm”，工厂没有保留真实工具ID。冻结计划的新预检随后按此字段读注册表，使静态图像等来源误报“契约暂不可用”。工厂已补真实toolId；不跳过契约校验、不清除原引用，也不要求重建旧方案。新增用例覆盖实际工厂转换及冻结图像／数值契约；部署和用户复测状态以协作记录为准。

2026-10-14按用户要求先修复位置修正、窗口关闭和候选范围，再继续B3节点配置提交服务接入。AvailableDataSource原有TypeConverter支持非空路径，并非完全缺少类型适配；本批补空文本与null映射，并让ParamBinding选源和恢复时保留WPF双向绑定，避免仅消除红框却未写回新来源。不修改旧方案格式或要求重建方案。

执行／确认仍严格校验。标准和自定义窗口关闭失败时提供继续编辑或明确关闭、放弃未提交控件编辑的选择；选择放弃后取消控件待编辑状态，并抑制关闭／卸载再次持久化。当前仍是实时写入架构，已写入参数的内容不会回滚，退出提示必须说明此边界，不能把它称作完整草稿取消。

普通工具默认仅列连线上游；已有合法无连线来源单独保留在“当前绑定来源（无连线）”，不隐藏或删除真实引用。解析、组装、发送编辑器显式启用同流程其他合法来源，树按“上游节点／其他可绑定节点”区分，上游优先，自身及下游仍排除。类型过滤后才生成节点树，无适配字段不生成节点；字段自身的执行信息等分组保留，导航分组不写进绑定路径、显示名或持久化身份。

专项验证与真实旧方案验收分开记录；不把单元测试或启动探针视为用户方案已执行。B3窗口生命周期、各执行入口和统一撤销历史在本批回归验收之后继续，不与修复同时切换。

## 最终规则

绑定跟随稳定的输出字段身份，不跟随名称、序号或当前值。上游发生不适配变化时，直接解除该输出所有受影响的下游输入绑定，用户需要重新选择来源。只清除受影响输入，不清空下游节点的其他有效绑定；不按同名字段自动重连。

本规则取代对话中“保留失效引用并要求修复”的建议。解绑后的历史来源只用于日志或变更记录，不再作为可执行绑定保留。候选列表尚未刷新、上游暂未执行、设备暂时断线不是输出字段删除，不能据此自动解绑。

## 当前实现与优化缺口

当前OutputBindingChangeService保存旧输出契约，正式提交时扫描当前方案的模型引用，形成临时消费者解绑计划。它不是依据执行快照，也尚未建立统一、带版本的消费者引用索引。旧契约只包含输出定义，不包含本次运行数据。

B1已在正式节点提交时补双向检查：发送类型改变复查已有来源；解析保留的旧引用在输入解释签名变化时要求重新绑定，同次选择的新来源则按新要求验证。合法常量使用实际发送解析或无运行上下文的纯解析探针检查；普通参数沿既有常量解析器校验。需要重配的输入不能靠非空文字或控件选择绕过运行预检，正式提交验证成功后才解除状态。

B1已取消宿主及图像选择器的自动换源。自动图像绑定保存连线归属，连线删除或替换只清除其建立的默认来源并标记需重配；显式来源保留。图像、解析和组装的显式输入补入局部执行依赖，因此不依靠保留画布连线维持数据顺序。节点提交可复用宿主正式静态元数据验证图像重配，但不是完整静态契约统一。

B2以BindingInputCatalog和BindingRelationCatalog统一现有存储的模型描述，候选、适配和依赖读取相同来源。节点按工作流作用域寻址，动态输入／输出和变量生产端保存稳定身份；正式静态契约直接读取工具注册表，不依赖打开窗口或先执行上游。声明类型、集合形状、固定数量及复合成员路径进入三态检查，未声明完整的多态或嵌套集合保留引用、标记待校验并阻止执行。

节点编辑、保存／加载、变量输入／目标、删除以及撤销重做后的复查已接入；冻结执行计划进行只读预检，核心层不访问WPF。消费者事务仍不回滚已经写入的上游编辑；撤销后的复查不等于恢复整个解绑事务。候选草稿、整体原子发布和结果版本属于B3，引用增量索引属于B4，用户实际入口、设计器和高DPI验收属于B5。

### B3配置事务核心与接入边界

BindingConfigurationStore已提供独立的工作流／全局绑定配置草稿。参数、输入设置、节点与连线以及变量生产／消费关系深拷贝并保留稳定身份；运行结果不进入配置历史。适配校验和依赖编译使用候选副本，失败不改变旧正式代，也不抹去用户草稿；成功才共同发布新配置和依赖版本。过期或其他发布器的草稿不能覆盖当前代。

核心撤销／重做恢复整个已接受配置，包括上游修改、下游解绑及重配标记、节点删除、连线和变量关系，不再仅恢复画布。恢复生成递增的新版本，旧版本不重新成为当前版本。参数变化、全局初值变化和连线变化按旧／新依赖传播结果失效范围；删除连线只清其拥有的自动图像来源，包括持久化引用，不替换合法显式绑定。

## 统一身份与绑定描述

来源采用工作流ID、节点ID、输出字段ID及属性／元素路径；目标采用工作流ID、节点ID和输入参数／输入行ID。显示名、序号和控件文字不参与身份判定，节点改名、字段重排不换身份；删除重建产生新身份。

普通参数、解析、组装、接收、发送、全局变量和图像输入通过适配器提供统一描述，包含来源、目标、输入要求及绑定建立方式。连接自动生成的绑定还记录关联连接身份。可以分阶段保留现有存储，但候选展示、适配服务、引用查询和依赖图必须读取同一描述；不得各自按字符串包含或名称猜测关系。多来源表达式必须提供结构化引用列表，不以单一首段匹配代替完整分析。

## 实施前问题

ReceiveData设备模式使用参数中的FieldId，变量模式每行使用另一个FieldId。切换模式后，即使输出都叫out0，也可能替换为另一输出身份。下游原表达式仍引用旧字段，ParamBinding查找失败时回显内部GUID路径；协议解析找不到声明时又可能显示字符串／HEX设置，不能据此认定绑定已经适配。

首批实施前已有稳定字段、动态输出契约和绑定解析基础，但缺少统一的契约差异比较、消费者查询及自动解绑事务。本问题与此前已修复的表格编辑提交不同。既有测试成功不能作为新自动解绑能力已交付的证据。

## 变化分类

| 正式变化 | 检查与处理 |
| --- | --- |
| 当前值或报文内容变化 | 保留绑定；下次执行取新值，本次快照不变。长度不足属于数据校验失败，不自动解绑 |
| 节点名、字段名变化或字段重排 | 保留字段身份和绑定，刷新显示 |
| 同一逻辑输出换来源且消费规则仍适配 | 保留绑定，刷新类型及来源信息 |
| 类型、形状、数组元素路径或表示方式变化后不适配 | 解除所有受影响输入绑定，并要求重新绑定 |
| 字段删除、身份被替换或节点删除 | 解除对该旧身份的全部绑定 |
| 删除后新增同名字段 | 新身份，不自动恢复旧绑定 |
| 下游发送类型、解析模式或输入形状要求改变 | 对称检查该输入当前来源，不仅检查本节点消费者；不适配清除该输入绑定 |
| 连接新增、删除或替换 | 检查拓扑与来源可用性，按连接语义处理，不直接换源或机械解绑 |
| 节点禁用或分支跳过 | 更新本次执行输出有效性，不当作字段删除，不自动解绑 |

是否适配由候选配置的正式输出契约和下游输入要求共同判断，不能只看类型下拉候选，也不能由显示名猜测。检查节点／字段存在性、合法作用域、允许类型、标量／集合形状、元素路径、数据解释和输入规定的拓扑约束；不隐式转换、拼接、截断或修改解析模式。

判定统一为三态：已确认适配则保留；已确认不适配则解绑并要求重配；契约缺失或信息不足、暂不能确认则保留引用并标记待校验，阻止相关输入执行。待校验不是可执行兜底，也不是永久保留已确认失效的引用；不能以候选空列表判定字段删除。

本例中Binary和String都可能被协议解析接受，但字节输入与HEX文本／字符文本不是相同解释。只有现有配置明确适配新输入时才保留；不能默默把Binary改成HEX文本输入。实际内容非法时按运行错误处理，不因为某次报文解析失败就删除工程绑定。

协议解析首批Binary与String类型变化要求重绑的保守规则保留，后续只有证明具体解释配置适配才允许保留。协议组装仅保留其明确支持的类型变化；发送按显式发送类型检查，不由目标名称推断类型。AllowsTypeChange布尔开关只能作为首批策略，不能代替最终输入要求与解释规则的适配判定。

## 连接与数据绑定

显式数据绑定本身建立数据执行依赖；画布连接另行表达其规定的执行关系，二者汇入同一依赖图。A输出绑定B输入时必须包含A到B的依赖，不能只依赖画布连线。

删除画布连线不自动删除仍合法的显式绑定，绑定依赖仍然存在。某输入明确规定只能使用连接上游时，应检查变更后是否还有合法路径；连接自动产生的绑定失去合法来源时清除并要求重配，不选取剩余第一个来源。新增或替换连接不能覆盖用户的合法显式绑定。

新连接或绑定造成循环、自依赖或非法作用域时，拒绝候选变更，保持旧正式配置；不能删除其他合法绑定来消除循环。候选列表、适配检查与执行依赖共用相同来源规则，既有绑定是否合法不能仅由候选是否显示决定。

## 引用索引与执行依赖

引用索引从正式配置生成，是带配置版本的派生查询结果，不是第二套需要独立保存维护的绑定配置，也不是执行快照。支持输出字段到全部消费者、输入到当前来源、节点到关联连接与变量关系的查询。全局变量经稳定变量身份连接生产者与消费者，不按可修改的变量名作为最终权威身份。

上游定义变化检查相关消费者，下游要求变化检查该输入来源，连接变化检查受影响拓扑。沿统一依赖关系传播结果失效，但只有契约适配确实破坏时才继续解绑后续输入。改名、拖动节点及运行值变化不触发全方案适配扫描。

加载、导入及配置恢复时完整重建关系与索引；正常提交增量更新。执行前检查配置／索引／计划版本及有效性，版本不一致时重建校验，不能依据过期索引解绑或执行。索引仅定位影响，适配必须使用新配置的正式定义。局部和方案依赖图从统一关系编译，不再让各工具分别解析一套表达式。

## 接收输出身份优化

接收节点统一维护逻辑输出行，字段身份、名称与来源映射分离。对已有逻辑输出行切换设备／变量来源时保留FieldId，不再以模式选择两套out0。变量模式新增其他输出生成新ID；删除后重新新增使用新ID。字段名重复不能作为对应关系。

此结构优化减少不必要的身份变化，但不能掩盖真实不适配变化。已经失效的旧工程引用不会按out0名称自动迁移；开发期使用当前契约重新确认绑定，不恢复旧版本兼容分支。

## 变更处理流程

1. 在编辑草稿中完成修改，生成候选配置，不先破坏旧正式配置。中间输入状态不触发批量解绑。
2. 对比输入要求、输出定义、绑定和拓扑变化，以稳定作用域身份查询受影响输入；包含关闭窗口和跨流程合法引用。
3. 检查适配并生成保留、解绑、待校验、结果失效及依赖更新计划。只处理受影响输入，不清空无关配置。
4. 校验字段、路径、作用域、完整性和循环等约束。应拒绝的非法变更不通过清除其他合法绑定强行修复。
5. 成功后原子发布新配置、绑定关系、索引和依赖版本，并对相关结果版本失效；失败保留旧正式配置，不能留下部分上游编辑或解绑。
6. 发布一次可读通知，刷新打开编辑器、候选与结果展示，不把GUID作为说明。撤销重做恢复完整配置变更，再校验派生关系，不能只恢复画布节点或连线。

节点添加／删除、参数提交、连接增删／替换、变量绑定、批量导入和撤销重做统一进入配置变更服务。控件负责编辑与展示，服务负责适配与正式提交，工作流负责执行。执行入口只提交相关打开编辑器的待编辑内容，再取得正式配置；不遍历全部节点从控件重新抄写参数。通信触发等无编辑上下文入口直接使用正式配置。

索引必须涵盖ParamSettings、解析InputText、组装Parts、发送Rows中的表达式，以及变量输入来源／目标输出等现有传递入口。先评估各入口的真实存储和执行范围，不根据字符串包含关系批量替换。一个输入中有多来源表达式时，只按该输入适配规则解除受影响表达式，不能误删其他输入。

解绑范围是所有引用被破坏输出的消费者输入，不机械清空整个后继图。若消费者自己的输出契约也被删除或变得不适配，再按新契约继续检查。依赖于失效配置的后续结果不可继续当新配置的有效数据使用。

## 解绑后的配置和界面

清除真实来源引用、数组路径及可执行表达式，同时清除显示文本和相关缓存；保留输入行身份、名称、其他合法配置。输入显示“请选择”，通过主题状态、Tip及一次通知说明“上游输出变化，需重新绑定”。不增加常驻说明段落。

被自动解绑的输入显式记录需要重新配置的状态，保存重开后仍有效。运行预检不能把空表达式、原显示文字、保存初值或历史结果当常量补位。重新选择并验证合法来源，或用户明确提交新的合法常量后解除该状态；仅输入非空文字不代表配置合法，不能由自动解绑替用户决定常量。

变量生产来源被破坏时，需要同步处理对应生产关系，不能清除生产者后让消费者静默读设计初值。相关消费者按变量契约及来源有效性重新检查；不旁路唯一生产者规则。

## 与执行快照的关系

所有运行入口消费同一正式配置及绑定校验规则。UI提交服务负责完成编辑，共用配置服务负责契约比较和解绑，不让WPF承担调度；工作流层不访问控件。

已启动运行保留其配置、依赖和结果快照，不被本次设计变更中途改写；下一次运行使用新配置。新配置解绑后，相关输入预检明确失败，不能补跑上游或使用旧结果。候选、结果和依赖缓存以同一配置版本失效，避免旧表达式重新出现。

每个正式配置版本对应一致的契约、引用索引与依赖关系，执行开始从同一版本生成参数及关系快照。设计结果展示与运行中的结果空间分开管理；发布新配置使相关设计结果和后续依赖结果失效，不清除正在运行的结果空间。普通参数继续按运行边界冻结；接收工具按既定显式当前读取语义工作，配置版本一致不意味着锁定旧设备报文或恢复样本时效机制。
