协议解析工具把输入文本或字节按配置规则转换为多个类型化输出，不连接设备、不等待报文、不触发流程、不发送数据。本轮包含文本解析和字节解析；用户明确暂不实现脚本解析，因为尚无通信脚本基础能力，不使用全局脚本替代。

统一输出原则：只输出用户配置的字段，按配置类型、区间和顺序解析，不自动增加字段或猜测类型。文本片段多于配置时仅消费配置项所需片段，不新增输出；片段不足、配置类型转换失败或字节区间越界则整体失败。字节模式只读取配置区间，未引用字节不自动生成字段。具体整数宽度、编码和索引基准仍按明确配置及已定稿规则处理，不能由本原则推定。

配套基线：[接收数据工具](./接收数据工具方案与沟通基线-20261010.md)、[发送数据工具](./发送数据工具方案与沟通基线-20261010.md)。通信项目开发通信工具链，主程序项目开发标定工具链；共享 SDK 和执行契约变化需评估双方影响。

## 当前优化目标

2026-10-12最新开发顺序：优先接收服务和真实接收插件，同批接入本工具String／Binary与组装String／Integer／Double的类型过滤，以实际报文联合验证接收→解析→组装→模块结果。约260宽等UI细节后置，不作为接收入口的前置。原始接收Binary先按协议解析为标量，再进入文本组装；全局触发out不是该链的必经来源。文本编码目标保留，协议必要适配可同批处理，不能用界面调整替代生产取数服务。

2026-10-12最终输入方案以[统一优化基线](./通信接收与协议解析优化基线-20261012.md)为准。接收节点执行时取得当前来源，解析消费该次成功输出，不重新读设备、不默认取事件out。输入接受String／Binary单项，候选联合筛选且执行再次校验；数值、图像、几何和未选一项的多项列表不自动ToString或拼接。直接变量绑定仍按解析参数快照，实时变量取数通过接收变量模式完成。

| 绑定输入 | 文本模式 | 字节模式 |
| --- | --- | --- |
| String | 直接按分隔符拆分 | 明确HEX文本或字符文本后转换为字节 |
| Binary | 按字符编码严格解码，再拆分 | 直接按配置区间读取原字节 |

文本Binary解码目标支持UTF-8／ASCII，默认UTF-8；编码置于条件显示的高级设置，String文本输入隐藏编码。字节ASCII按字符解释字段，不等于输入格式或HEX显示。Binary载荷41 42 43 2C 32可文本解析为ABC和2；00 5C 41 44可字节解析为92和AD。两种模式保留同一来源绑定，不要求接收额外输出String。

保留520×600窗口，解析内容左对齐，初始目标约260个WPF逻辑单位，不铺满整行。长路径省略显示并通过Tip查看，保存的表达式不截断；说明继续放Tip／帮助，配置页不展示运行值。当前算法支持两种载荷，候选已过滤String／Binary；文本Binary固定UTF-8、控件仍填满剩余空间；联合筛选已接通，文本编码选项和控件收窄仍待实施。重排序号与首末按钮修复已部署，文本移动改变片段映射，字节移动保留字段区间，身份和绑定键不变。

### 输入与分隔

- 解析内容允许字符串常量、前序结果绑定及宿主支持的变量绑定。
- Byte[] 输入建议严格 UTF-8 解码，非法编码失败。数值、布尔、图像不隐式转换成文本；原生数值可直接用于下游。
- 分隔符复用统一目录和自定义值，不建立独立硬编码数据源。
- 多字符分隔符按完整字符串匹配，不按其中每个字符分割。
- 连续、首部和尾部分隔符产生的空字段保留。
- 无分隔符表示整段输入为一项，不自动按空白分割。

### 字段与类型

按输出列表顺序对应分割片段：

```text
输入：12,3.5,ABC
第1段 -> out0 : int    -> 12
第2段 -> out1 : float  -> 3.5
第3段 -> out2 : string -> "ABC"
```

| 类型 | 项目建议 |
| --- | --- |
| int | Int32，严格检查范围，不截断小数 |
| float | Float32，固定文化格式，拒绝非有限值 |
| string | 保留原字段，不自动去空白 |

数值转换可允许首尾空白，字符串不随之 Trim。小数点、科学计数法等接受格式固定，不随电脑区域设置改变；具体格式在实施前定稿。

按配置字段数量生成输出。文本从左至右为各配置项取片段，多余片段不消费也不新增字段；所需片段不足则整体失败。例如配置3项、输入4段，只按规则输出前3项；第4段可计入诊断中的输入数量，不成为业务输出。此为本项目确认口径，不认定为VM内部行为，也不自动修改既有事件规则。空字符串可以是string的有效值，不能作为int或float的成功值。

### 输入格式归一化

核心输入是字节序列，不能猜测字符串代表什么。

- 绑定 Byte[] 原样使用。
- 自定义 HEX 明确标识格式，严格转换；空格等可接受字符统一定义。
- 普通字符串不自动猜测为 HEX 或文本。
- ASCII 字符模式接受字符串时严格编码 ASCII，不支持的字符报错，不替换为问号。
- HEX 结果显示文本不等于原始字节。

```text
HEX 输入 "31 32" -> 字节 0x31 0x32
ASCII 输入 "12"  -> 字节 0x31 0x32
相同字节也必须通过明确输入格式形成，不能隐式猜测。
```

建议输入格式作为解析内容的编辑属性：常量明确选择，绑定按实际类型开放能力。该属性的具体交互尚待定稿，不能把显示内容或解释方式替代输入格式判断。

### 起止位置

建议 0 起始、闭区间：

```text
字节：00 5C 3F 80 00 00
索引： 0  1  2  3  4  5
[0,1] -> 00 5C
[2,5] -> 3F 80 00 00

0 <= 起始 <= 结束 < 输入字节数
长度 = 结束 - 起始 + 1
```

越界失败，不裁剪区间。建议允许不同字段区间重叠，以便对同一数据进行不同解释；这是读取规则，不是写入冲突。位置单位始终为字节，不是 HEX 字符或 Unicode 字符。

### 顺序

| 四字节配置 | A B C D 重排结果 |
| --- | --- |
| ABCD | A B C D |
| BADC | B A D C |
| CDAB | C D A B |
| DCBA | D C B A |

建议按长度限制可选项：1 字节仅原顺序；2 字节仅原顺序和两字节交换；4 字节四项；3 字节首版仅原顺序。实际标签可附原顺序或交换说明，不能将四字节规则未经定义延伸至任意长度。

ASCII 字符模式和字符串字段建议隐藏顺序编辑，按原顺序处理，避免字符交换。字符串可能为任意长度，其顺序候选处理以此限制为准，不套用数值宽度规则。该设计仍待确认。

## 4 字节解释与输出类型

### 二进制数值

| 类型 | 首版建议 |
| --- | --- |
| int | 1 至 4 字节，短于4字节按非负值解释，4字节按 Int32 补码解释 |
| float | 4 字节，按 IEEE 754 Float32 解释，拒绝非有限结果 |
| string | 截取区间严格 UTF-8 解码，不输出 HEX 展示字符串 |

短字节整数建议与项目已有口径保持一致，但不等于有符号 Int16。负数 Int16、UInt32、Double 等如果需要，必须显式增加类型，不能根据数据内容猜测。具体开放类型仍待确认。

```text
00 5C       -> int    92
3F 80 00 00 -> float  1.0
41 44       -> string "AD"
```

UTF-8 字符串规则是项目扩展，须与协议组装编码一致。Byte[] 来自 Modbus 时解析对象是寄存器数据区，不包含 TCP 或 RTU 帧头；工具本身不增加协议头剥离逻辑。

### ASCII 字符

建议截取字节后严格 ASCII 解码，再按字段类型转换：

```text
31 32    -> "12"  -> int 12
33 2E 35 -> "3.5" -> float 3.5
41 44    -> "AD"  -> string "AD"

同样的字节 31 32：
二进制整数 -> 0x3132 -> 12594
ASCII 整数 -> "12"   -> 12
```

非 ASCII 字节、空数值、非法数字和越界均失败。尾部 00 填充、尾部空格等协议习惯需要单独规则；首版不偷偷清除字节，数值字符转换的首尾空白处理与文本规则统一。

## 5 输出身份与窗口操作

- 添加生成唯一 out0、out1 等名称，名称非空、同工具内唯一。
- 字段维护稳定身份；改名不破坏下游绑定，删除或改类型检查引用并提示。具体绑定实现遵循统一工具输出契约。
- 切换解析方式建议保留各模式草稿，仅当前模式运行。
- 区间、类型和顺序不兼容时就地提示，不自动改变含义来取得成功。
- 分隔符、主题和水平垂直居中复用项目公共设计。
- 不显示脚本方式，不添加脚本路径或占位入口。

| 按钮 | 建议行为 |
| --- | --- |
| 执行 | 用当前编辑配置和可取得输入快照单次解析，发布到本节点模块结果，不保存方案 |
| 确定 | 校验并提交节点配置，保存解决方案时统一持久化 |

绑定输入不可用时在模块结果记录失败，不自动运行上游或重新从设备接收。单步结果通过宿主统一结果通道显示，并标识对应执行；不能注入另一个正在运行的上下文。变量发布仅遵循已显式配置的宿主生产者规则，不因打开或刷新结果表而赋值，不新增触发行为。关闭草稿规则沿用工具宿主。

## 6 执行与失败边界

```text
配置及输入快照
       |
       v
输入格式校验
       |
       +-- 文本：解码 -> 分割 -> 按字段转换
       |
       +-- 字节：截取 -> 重排／解码 -> 按类型解释
       |
       v
全部字段成功
       |
       v
一次性发布类型化输出
```

任一字段失败则整条失败，不发布部分业务输出，不沿用上次成功值。临时成功值仅可用于诊断，不能作为下游有效结果。错误包含字段名、区间和原因，例如 out1 需要4字节而区间长度为2。

不提供忽略错误数据开关，避免协议结构被破坏。输入与配置均使用快照，不在运行中读取控件；取消沿用执行层契约，不发布半完成结果。

现有 [CommunicationReceiveProcessor](../../../../src/UI/Features/CommunicationManager/CommunicationReceiveProcessor.cs) 位于 UI 层，包含事件比较、状态及历史逻辑，插件不能直接依赖。实施时可评估提取纯算法，但不得顺带改变接收事件已确认行为。解析工具不添加事件比较、回复或触发职责。

## 7 工具链衔接与验收

```text
接收数据 -> 协议解析 -> 检测／计算 -> 协议组装 -> 发送数据
              |
              +-> 多个类型化字段供下游绑定
```

输入不限于接收工具，也可来自其他工具的字符串或字节结果。OPC UA 原生数值或布尔不需要绕道解析。数据队列列表批量解析需要另定契约，首版不隐式展开。

实施后覆盖文本空字段、多字符分隔符、数量不匹配、固定数值格式、溢出和非有限值、UTF-8 或 ASCII 非法输入、HEX 明确转换、字节越界、各顺序和宽度、整数符号、字符串填充、失败清空、原子输出、稳定绑定、执行测试隔离及取消。设计时、运行时、明暗主题和高 DPI 分别验收。

## 8 模块结果与绑定

共用[通信工具链模块结果与数据分析统一约定](./通信工具链模块结果与数据分析统一约定-20261010.md)。模块结果发布配置的类型化字段；主界面数据分析展示每字段的来源片段、文本序号或字节区间、类型、顺序和转换原因。局部解析值只可用于诊断，整体失败时不得作为有效模块业务字段或下游输入。分析数据与模块结果来自同一次ToolResults，不重新解析设备最新值，也不回填调试窗口。

```text
+------------------------------------------------------------------+
| [图像]  [模块结果]                                                |
+--------------------------+----------------------+----------------+
| 结果名称                 | 当前值               | 变量管理       |
| v 协议解析1              |                      |                |
|   耗时(ms)               | 0.8                  | [绑定]         |
|   模块状态               | OK                   | [绑定]         |
|   out0                   | 92                   | [绑定]         |
|   out1                   | 1.0                  | [绑定]         |
+--------------------------+----------------------+----------------+
```

示例值不代表 VM 默认值，状态展示沿用项目宿主契约，不擅自增加 SDK 状态枚举。每个配置输出对应模块结果的稳定字段；变量管理入口按类型绑定到变量，遵循唯一生产者。失败清除有效业务值并更新状态，错误原因进入宿主诊断或扩展结果信息，不保留上次成功值冒充本次值。

## 9 待确认事项

| 事项 | 当前建议 |
| --- | --- |
| 文本字段数量 | 已确认按配置项输出，多余片段不新增输出，所需片段不足失败 |
| 字节索引 | 建议从0开始，闭区间 |
| 整数类型 | 明确宽度和符号，是否首版增加 Int16、UInt16 等待确认 |
| ASCII 解释 | 建议先解码字符再转数值，不认定为 VM 精确内部语义 |
| 二进制字符串 | UTF-8、填充处理及顺序限制待确认 |
| 输入格式编辑 | 明确 Byte[]、HEX 文本和字符文本，不猜测；具体控件交互待定 |
| 结果显示位置 | 已确认：统一模块结果，配置窗口不显示执行结果；具体诊断字段待定 |

本轮仅同步方案，不新增代码、SDK、运行时或用户方案数据修改。用户已授权按计划实施并启动P0，独立待定行为仍需明确；不把项目建议写成VM已确认事实。通信脚本基础能力具备后另行设计脚本解析，不混用全局脚本。
