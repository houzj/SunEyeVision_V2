发送数据工具在工作流执行到该节点时，把绑定数据写入指定目标。协议组装负责生成内容，发送数据负责实际提交；发送事件提供可复用的格式与目标定义。本轮输出目标为数据队列、通信设备、变量管理、发送事件，视觉控制器和相机 IO 通信暂不实现。

统一输出原则：按配置目标和绑定数据校验、编码并提交，不推断新的字段、不把字节展示文本当成原始数据，不把字符串强制改为目标原生数值。实际提交事实、状态和分析数据使用同一次执行结果。框架类型适配由实施者负责，目标容量、权限及类型不兼容仍须明确报错。

## 2026年10月13日显式发送类型

用户定稿为所有发送行显式选择发送类型，而不是由输入内容或目标类型推断。选择包括String、Integer、Int16、Int32、Int64、UInt16、UInt32、Float、Double、Boolean、Binary。绑定候选只接受对应工作流类型，执行时再次严格检查；整数位宽使用范围校验，Float及Double拒绝非有限或超范围值。工作流整数仍以Integer承载，不新增数值词汇或旧版本兼容分支。

手填常量按发送类型解析，Binary手填使用HEX字节；HEX格式与值类型独立。String加HEX表示将文本作为HEX编码，Binary表示完整载荷，不追加分隔符或结束符。绑定值不会隐式把String改成数值，Binary也不会转换成展示文本发送。TCP等文本发送可显式格式化数值及Boolean。

OPC UA在预检时刷新真实数据点元数据，发送类型必须与目标声明类型一致；例如Int32类型的点可按Int32解析手填1111，Double则报目标要求Int32。事件行与参数声明比较，变量行与变量类型比较。int／Int32、bool／Boolean、float／Float32为同义名称，不把Integer与Int32或Float与Double当同一发送类型。选择事件时可用目标声明初始化类型，刷新不能覆盖用户所选类型。

Modbus当前地址配置只有IntBits和容量，不具有唯一标量类型，不能伪造“16bit即Int16”的目标声明。发送仍由已有编码器校验：当前直发支持Integer／Int32、Float、String，其他显式类型明确拒绝；不静默改成可写类型或截断。事件原生输出继续由共用发送核心检查最终值、容量和权限。

全部预检完成才提交；忽略错误时全部无效的日志保留逐项原因，不再只报“没有有效发送单元”。成功／失败回执规则不变。34项专项通过，本机OPC UA模拟验证手填1111成功以及Double不匹配时目标不被写入，TCP字节闭环和Modbus模拟通过。深浅主题实际编辑器截图已核验，窗口保持520×600。部署证据见[显式类型交接](../../../collaboration/HANDOFF_SEND_TYPES_20261013.md)。本节取代前文历史记录中的直接输入类型和精确绑定筛选待处理状态，队列及其他P4边界仍待完成。

## 2026年10月13日发送事件选择修复

通信管理器的默认事件名称原先只用于列表显示，发送数据候选却读取空的Name，导致已有事件显示为空白。两处现在共用名称规则：空名称按模式显示“文本-直接输出”或“文本-组装输出”，不改写保存的名称。

发送数据候选显示“事件名称 · 设备名称”；仍重复时追加稳定EventId短码，短码冲突时显示完整ID。未绑定和失效设备有明确标签。选择与执行始终按EventId寻址，参数按FieldId对应，同名、改名和列表重排不会改变绑定。删除事件不自动绑定另一个同名事件，执行时拒绝失效引用。

未选择事件时不显示虚构的data行。选择后加载事件声明参数，不复制管理器测试值；刷新更新匹配字段的名称与类型，保留已有输入表达式。完整事件名称可通过Tip查看。

- 建议把 VM 的 16 进制发送开关改为发送格式下拉，选项为文本或 HEX。
- 文本按现有 UTF-8 契约发送，各项按列表顺序串联，开启分隔符时在项之间插入一次。

- HEX 隐藏文本分隔符，按字节拼接。HEX 是否允许结束符仍需确认；若允许，只按明确字节追加，不二次文本编码。
- 结束符仅在最终报文末尾追加一次，候选复用现有结束符目录。
- 分隔符复用统一目录与自定义值机制，不为该工具再建一套硬编码选项。
- 发送数据可用常量或绑定，常量校验及格式化遵循同一契约。

| 协议组装原始字节 | 不再次解释或重排，校验寄存器对齐与容量后写入 |

原始字节是新增设计，是否首批开放尚待确认。该路径不得包含 Modbus 帧头，不把协议组装结果误当作完整请求帧直接发送。

寄存器模式不显示文本分隔符或结束符。奇数字节、超容量、类型不匹配不静默补齐、截断或强制转换。重复或重叠地址在执行前报告，不用列表顺序暗示可以覆盖。目标删除标记失效，改名只刷新显示。

## 7 忽略错误数据建议规则

建议默认关闭，开启时仅跳过独立提交单元的预检错误，不代表忽略通信故障、取消或破坏报文结构。通信失败后的继续或终止策略需要明确，不由此开关隐式决定。

| 模式 | 可跳过边界建议 |
| --- | --- |
| Modbus 或 OPC UA | 一个独立目标行 |
| 变量管理 | 一个独立变量映射 |
| 数据队列 | 取决于记录完整性契约，不能擅自提交缺列记录 |
| 普通设备组合报文 | 整条报文是一个单元，不跳过内部字段 |
| 单个发送事件 | 参数缺失导致事件整体失败，不跳过参数破坏格式 |

```text
约定格式：结果,位置X,位置Y
位置X 出错，不能自动变成：结果,位置Y
```

结果显示成功、跳过、失败数量。出现跳过保留警告与明细，不显示为完全成功；全部跳过判失败。现有宿主ExecutionStatus包含PartialSuccess，可复用表示部分成功，不新增SDK枚举；具体状态条件遵循独立单元规则。

## 8 执行流程与副作用

```text
取得配置及参数快照
        |
        v
解析所有绑定 -> 类型／权限／容量校验
        |
        v
生成独立发送计划
        |
        v
通过共享运行时按序提交
        |
        v
发布本次状态、明细与已发送内容
```

UI 不发送、不调度，工具插件不得依赖 UI 宿主程序集。当前 [CommunicationSendEventService](../../../../src/UI/Services/Communication/CommunicationSendEventService.cs) 位于 UI 项目，引用 UI 编码组件；插件不能直接依赖该服务。实施前规划发送契约及可复用核心的位置，评估共享 SDK、执行层和主项目标定工具链影响。

关闭忽略错误时，任一预检失败都不开始提交。多目标实际写入不是事务：前一目标成功、后一目标失败不宣称回滚。取消停止后续提交，已经发送的数据不能撤回；不默认重试可能产生重复副作用的发送。

TCP 完成仅代表本地发送操作完成，不等于对端业务处理完成。Modbus 和 OPC UA 按协议返回判断写入结果，超时可能不能证明对端未执行，应在明细中明确，不能无条件重发。

工作流执行和管理器发送测试调用同一无控件发送核心，不直接复用界面发送测试命令。配置与绑定数据在执行时形成快照，不在执行过程中重新读取窗口值。

## 10 与通信工具链衔接

```text
接收数据 -> 协议解析 -> 检测／计算 -> 协议组装 -> 发送数据
                                      |
                                      +-> 发送事件参数绑定
```

直接通信设备路径由协议组装生成最终文本或字节，发送工具提交；发送事件路径由发送工具提供业务参数，事件格式化后提交。不能在协议组装、发送工具和发送事件重复添加分隔符或结束符。

建议区分最终报文和待格式化字段两种输入契约。已经组装的报文不再按字段二次组装；字节输出与文本 HEX 展示严格区分。具体工具输出类型、稳定字段身份、图像所有权与队列列表契约，在协议解析和协议组装方案完成后统一。
