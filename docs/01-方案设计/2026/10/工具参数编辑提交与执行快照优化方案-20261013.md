# 工具参数编辑提交与执行快照优化方案

日期：2026-10-13。适用通信开发工作区，共用工具编辑器及UI运行入口。

## 已确认问题

真实WPF发送编辑器测试复现：选中test2及Double后，表格仍处于编辑事务，参数对象的TargetId为空、DataType为String。执行入口此前直接复制参数，因而可能发送旧配置；不是手填1111始终作为String，也不是已证实的ParamSettings覆盖。用户保存方案中的该节点ParamSettings为空，不能据此假定绑定快照覆盖。

修复后同一编辑操作不关闭窗口，执行命令先提交待编辑值，请求携带正确目标、Double声明及1111d。冻结参数副本后再修改设计参数，副本仍保持Double。此证据确认了本次编辑事务缺口，不排除其他历史方案存在独立的失效目标或配置问题。

## 配置和运行边界

控件绑定已经更新的有效值保存在参数模型；BindingExpression及BindingGroup中的未提交值仍属于编辑状态。提交沿现有绑定进行，不从显示文字重新拼装参数，不覆盖隐藏字段、稳定ID和绑定表达式，不创建第二套列表初值。

UI层负责验证和完成绑定、单元格及整行事务，随后沿现有执行参数复制链冻结快照。工作流核心不访问WPF。运行中再编辑只影响后续快照，不改本次已复制的参数。方案级配置关系编译和全局变量一致性仍按后置U1至U3处理，本次不宣称完整跨流程原子冻结重构已交付。

## 已实施入口

| 入口 | 提交方式 |
| --- | --- |
| ToolDebugControlBase节点执行命令 | 提交本编辑器，保存绑定定义，再调用工具执行；连续命令每轮同样经过此入口 |
| 默认窗口确定及关闭 | 使用同一提交服务；失败提示并保留编辑，关闭被取消，不再静默CancelEdit |
| UI工作流、主界面和预览驱动 | WorkflowExecutionManager在获取输入和构造运行前切到UI线程，提交当前流程及子流程范围内登记的打开编辑器 |
| UI方案执行 | 在依赖计划编译前预验证并提交登记的编辑器，不从所有节点控件取值 |
| 通信触发 | 既有通信操作上下文跳过UI提交；单模块触发路径不操作控件，消费已有配置快照 |

作用域确定可以读取工作流节点身份和子流程关系，但并不逐节点回收参数。只登记已加载ToolDebugControlBase，卸载后注销；即使Unloaded延迟，已脱离呈现源的编辑器也不参与。提交时只更新脏绑定和脏组，已有模型值不重复从界面采集。

## 校验和失败规则

先验证相关编辑器的待编辑绑定，再进行提交。转换或表格验证失败时阻止本次执行，保留输入；纠正后可再次提交。提交后仍有验证错误也不能执行。发送原生目标为空时明确提示“请选择发送目标”，与真实目标失效区分。

预验证阻止已知无效编辑引发其他编辑器先发布；这不等于对任意自定义属性setter副作用提供数据库式回滚。自定义独立窗口已有自己的确认入口，不被伪装成默认编辑器；后续新增工具应接入同一提交服务。

## 验证和剩余验收

50项接收、发送、事件选择、分析主题和编辑提交专项通过。新增真实WPF窗口测试验证空TargetId／String的提交前状态、正确发送请求、无需关窗、快照隔离；显式文本提交、无效输入保留及纠正重试、登记作用域、多编辑器预验证和关闭注销通过。实际加载窗口测试使用独立非并行集合，避免与其他WPF渲染测试共享静态事件并发。

UI运行入口接线已核查，但主界面／图像预览／相机／通信触发的用户真实联合操作、VS设计器和高DPI仍待验收，专项测试不等同全部入口端到端验收。标准构建和常用Release部署结果见[提交实施交接](../../../collaboration/HANDOFF_EDITOR_COMMIT_20261013.md)。用户方案和设备不作测试写入。
