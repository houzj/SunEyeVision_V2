# 工具箱分类排序与图标基线

日期：2026-10-12。状态：用户确认后已实施，通信项目Release已更新；主窗口人工验收待完成。

工具按使用流程分类，分类和分类内顺序均显式声明，不以目录扫描、插件注册或中文名称排序决定位置。分类只显示实际注册工具，不创建空的识别分类或未实现工具占位。现有工具ID、参数、算法与用户节点名称不变。

## 分类与工具顺序

| 顺序 | 分类 | 当前工具显示顺序 | 分类图标 |
| --- | --- | --- | --- |
| 1 | 图像采集 | 图像源 | 相机轮廓 |
| 2 | 图像预处理 | 图像滤波 → 图像阈值化 → 图像二值化 → 形态学处理 | 调节滑杆 |
| 3 | 特征定位 | 轮廓匹配 → 直线查找 → 圆查找 | 定位框与中心线 |
| 4 | 区域分析 | Blob分析 | 不规则区域轮廓 |
| 5 | 几何测量 | 点-点 → 点-线 → 点-圆 → 线-线 → 线-圆 → 圆-圆测量 | 刻度尺 |
| 6 | 坐标标定 | N点标定 → N点标定验证 | 坐标轴 |
| 7 | 通信工具 | 协议解析 → 协议组装 | 双向数据箭头 |
| 8 | 流程控制 | 条件分支 → 子程序 | 分支节点 |
| 9 | 脚本工具 | Script | 代码括号 |

轮廓匹配是之前讨论中的形状匹配工具（ShapeMatch），本次保留现有显示名。Threshold与ImageThreshold是当前两个独立插件，保留图像阈值化与图像二值化，不借分类调整删除或合并算法。

通信的完整编排为接收数据 → 协议解析 → 协议组装 → 发送数据。接收和发送尚未实施，所以Release只显示中间两项。以后增加OCR、条码等真实识别工具时再扩展识别分类。

## 图标和显示入口

全部使用SDK共用的24单位矢量线框图标，按显示区域缩放，不依赖Emoji字体、不以颜色区分不同功能。分类、工具、画布和标准配置窗口标题都从同一元数据取语义图标键，由同一控件渲染。

| 工具 | 图标语义 |
| --- | --- |
| 图像源 | 图像边框、山形与亮点 |
| 图像滤波 | 三组调节滑杆 |
| 图像阈值化／图像二值化 | 半圆分区／分格黑白图样，两者可区分 |
| 形态学处理 | 方形与三角形组合 |
| 轮廓匹配 | 定位框内轮廓 |
| 直线查找／圆查找 | 带端点标记的直线／带中心标记的圆 |
| Blob分析 | 多个独立区域 |
| 六种几何测量 | 按点、线、圆配对，加入距离箭头，不共用一个尺子图标 |
| N点标定／验证 | 坐标轴／带勾的验证轮廓 |
| 接收／发送 | 箭头进入／离开边界，仅预备图形，不增加未实现插件 |
| 协议解析／组装 | 单线分支／双支合并 |
| 条件分支／子程序 | 分支圆点／嵌套流程方框 |
| Script | 代码括号 |

工具箱紧凑模式移除红色数量圆点，悬停显示分类名称和工具数量；展开模式保留文字数量。画布保留原有运行状态背景／前景色，子程序仍可点击打开参数设置。未知图标键显示中性通用几何图形，不显示问号；扩展工具应显式声明已注册图标键。

## 实现约定

SDK Core/ToolCategories.cs保存分类名称、顺序和分类图标键。插件ToolAttribute保存Category、Order和Icon，ToolMetadata.Order从属性读取，不维护第二份工具排序表。已编排工具Order在分类内递增；未声明顺序的扩展工具默认1000，同序工具以稳定ID打破并列。

SDK UI/Controls/Icons/ToolIcon.cs保存共享图形和渲染器。工具箱的两种模式、画布和DefaultDebugWindow标题复用它。分类适配器同步到当前分类名称，仅调整展示，不改变调度、相机、标定或通信算法。产品版本不变，SDK及全部工具继续使用当前开发契约2.1；共享SDK和插件须一起构建部署。
