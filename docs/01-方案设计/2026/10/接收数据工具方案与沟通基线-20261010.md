# 接收数据工具方案与沟通基线

日期：2026-10-10  
状态：输出与同次样本原则已确认，本工具及无UI接收服务为下一批最高优先级；生产功能尚未接通，队列等独立契约仍待落实。  
适用项目：SunEyeVision_V2-comm；统一开发基线 a0f92a8732f31a2ffe20e10fcc6feb7c792a093f。

接收数据工具把指定来源的数据引入当前工作流，生成供后续工具绑定的输出，不负责协议解析，也不负责触发工作流。本轮通信工具链包括接收数据、发送数据、协议解析、协议组装，暂不包含相机 IO 通信；主程序项目继续开发标定工具链。

本方案保留三种来源的完整 UI 与交互约定，区分 VM 已确认行为、本项目建议和待确认执行语义。用户已授权按实施计划推进，不等于确认全部细节或允许无评估改动共享契约。

统一输出原则：接收工具按配置的来源和目标获取数据，保留实际载荷语义与类型，不自动解析或猜测字段。字节来源保留字节，原生数据点保留原生值；框架承载和绑定适配由实施者负责，不要求用户选择SDK词目。此原则不替代取数时机、样本时效和队列消费契约。

2026-10-12最终输出约定：TCP／UDP／串口业务报文及Modbus寄存器数据区的out统一为BinaryPayload／Binary，不自动追加String副本。TCP传字节，可以承载文本或二进制；HEX只是展示。Modbus保留寄存器顺序、高字节在前的数据区，不含帧头。业务报文完整性复用分帧规则，不能把TCP一次读取块当作报文。OPC UA及变量／队列保留实际类型，原生数值可直接绑定兼容下游，不强制转String或经过解析。

2026-10-12优先级确认：接收无UI服务和真实生产插件为下一批最高优先级；不再先完成输入框宽度等微调。插件必须有真实来源、输出声明、当前样本、模块结果、分析、绑定、方案保存及Release部署，不能只注册空壳。同批完成解析String／Binary和组装String／Integer／Double兼容筛选，首先验证设备→接收→解析→组装→模块结果；原始Binary需先解析为标量才进入文本组装。现有常量／变量测试不能替代设备链，优先级提升不代表本插件已经实现。发送、队列和完整收发仍属后续阶段。

协议解析接收String／Binary两种输入；文本模式必须能看到并订阅接收节点的完整Binary out，执行时按编码解码，再按分隔符拆分；字节模式直接按位置读取。绑定一个Binary载荷是取得完整报文，不是取一个字节；多项载荷需选择其中一项，不能自动拼接。输出身份、实际值、接收时间和后续解析对应同次快照。接收生产服务与插件仍未接通，本段是定稿目标而非完成记录，详见[最终优化基线](./通信接收与协议解析优化基线-20261012.md)。

2026-10-10 用户确认：接收工具的执行值、耗时、状态统一输出到宿主模块结果；配置或调试窗口只负责选择来源、定义输出和校验配置，不新增预览、结果表或历史框。

## 5 公共交互与配置保存

1. 切换模式只显示对应配置。建议各模式保留编辑草稿，只有当前模式参与执行。
2. 输出名称非空、同工具内唯一，默认从 out0 递增。建议用稳定输出 ID 维护下游绑定，改名不破坏引用；具体实现须符合统一工具结果契约。
3. 更换来源后重新校验绑定，不静默改绑同名设备、地址、变量或队列列。
4. 来源类型变化时刷新输出类型并提示不兼容的下游绑定，不做隐式强制转换。
5. 复用项目主题和局部表格样式，名称、数据与操作内容水平和垂直居中。
6. 确定提交到工具节点配置并标记方案变更；保存解决方案时统一持久化，不设独立保存配置入口。
7. 测试使用工具宿主统一单步运行入口，不另建收发调试区。队列测试若消耗数据，必须按配套队列契约明确提示。

确定和关闭是否采用草稿提交，服从现有工具配置窗口的统一交互；不能为通信工具另起一套保存行为。删除输出的确认和下游引用处理也应复用工具宿主规则。

## 6 执行与数据一致性

### 通信执行快照建议

统一基线已有 [CommunicationUploadSnapshot](../../../../src/Workflow/CommunicationUploadSnapshot.cs)，包含会话、设备、目标、时间、类型、质量、值与可选原始字节。现有模型不等于接收工具接口已接通，也不等于其 SessionId 已能单独标识每一条样本。

```text
设备接收／轮询／订阅
          |
          v
应用级通讯运行时
          |
          v
形成本次工作流执行的来源快照
          |
          v
接收数据工具按 DeviceId + TargetId 取数据
          |
          v
校验来源、质量和类型 -> 原子发布 out0
```

建议首版不让接收工具再次读取随时变化的共享最新值。通讯触发的执行使用触发该次运行的样本，不能被下一条报文替换；该样本能否覆盖工具选择的其他设备或目标，需要按执行输入契约明确校验，不能按相同设备名称替代。

用户确认所见即所得：触发运行锁定触发那条报文；手动执行使用执行开始时已收到的有效样本，不等待下一条或主动额外读取。接收、解析、下游与模块结果同属一次执行快照，新报文不覆盖本次输入。没有有效样本则失败、清空输出；实际来源和接收时间在模块结果／数据分析显示，不放在配置页运行预览。有效期数值、会话切换和跨目标校验在R3补齐，不能把旧会话值当作有效数据。此处为已确认规则，生产服务及接收工具仍未实施。

### 队列原子出队建议

按选定列和行数统一校验取数，任一列不足则整次失败，不消耗部分列。成功后消费本次数据，多个工作流不能重复取到同一份待消费数据。本工具不承担队列触发调度，调度由执行服务负责。

行对齐、多个读取者竞争、工具成功但下游失败后是否返还，以及取消发生时的消费边界，属于配套队列方案待定契约，不能仅依据 VM 界面决定。

### 失败与取消

来源失效、没有样本、质量错误、队列不足、变量不存在或类型不支持时，工具返回失败和原因，本次输出清空，不沿用上次成功结果。多输出模式全部成功后统一发布，避免半成功数据流入下游。

日志包含工具、来源和目标路径，不重复堆积无意义日志。取消沿用执行层令牌及统一状态规则；工具不得为等待数据而阻塞 UI，不持有窗口控件用于执行。

## 7 工具输出与功能边界

### 模块结果字段与分析数据

共用[通信工具链模块结果与数据分析统一约定](./通信工具链模块结果与数据分析统一约定-20261010.md)。配置输出out0等为模块结果业务字段，通信设备只一项；保留实际类型，字节当前值可HEX展示。来源路径、样本时间、质量与实际取得数量作为接收分析数据，主界面数据分析与模块结果读取同一次结果快照，不再次读设备。原始数据仅在来源提供时记录，不对图像或原生数值伪造字节；失败和无样本更新状态，清除无效业务值，分析保留原因。

| 输出或结果信息 | 用途 |
| --- | --- |
| out0、out1 等 | 配置的业务输出，保留相应类型 |
| 状态、耗时、错误原因 | 工具宿主统一执行信息 |
| 来源时间、设备与目标、样本身份、质量 | 结果详情诊断信息，样本身份须使用已建立的契约 |
| HEX 展示 | 仅字节输出提供，不改变实际类型 |

不设置对所有来源通用的 16 进制组装结果。队列图像、全局数值、OPC UA 布尔不应为了接收工具而转为 HEX。

| 功能 | 职责 |
| --- | --- |
| 通讯管理器 | 设备连接、目标配置、轮询和订阅、运行时收发 |
| 接收事件 | 后台解析或比较设备数据，产生事件结果 |
| 触发配置 | 根据事件或数据条件提交工作流执行 |
| 接收数据工具 | 在工作流中引入所选来源数据 |
| 协议解析工具 | 将引入的文本或字节按规则解析为字段 |

接收工具不要求先配置接收事件。工作流如果由通信条件触发，触发依据与工具读取数据应关联到同一次样本，避免触发依据是上一条、工具读到下一条。

工具插件不得依赖 UI 宿主程序集。来源解析通过执行层提供的服务或快照契约，不直接依赖通讯管理器 ViewModel。新增共享契约前须评估主程序标定工具链的影响，不能在通信分支擅自改动共享执行或 SDK 边界。

## 8 实施范围与验收建议

建议首批接入通信设备、已有变量快照、动态输出、下游绑定与方案保存；队列模式在配套服务具备后接入。如果要求三种来源一起交付，必须把队列基础设施纳入同一实施范围。工具链已进入P0，本工具运行路径尚未接通，本轮仅同步文档。

验收覆盖三种模式显示和切换、输出名称与下游引用、设备和目标删除或改名、类型变化、质量不良、无样本、会话切换、连续报文期间样本一致性、变量快照、原子发布及取消；队列实施后增加不足、并发取数和消费失败边界。UI 需验证设计时、运行时、明暗主题和高 DPI。实际设备测试必须独立记录，不以模拟测试冒充人工设备验收。

## 9 待确认事项

| 事项 | 当前建议或边界 |
| --- | --- |
| 手动运行的数据读取时机 | 取有效执行快照或等待新数据，需要用户确认；首版建议不隐式等待、不主动追加读取 |
| 数据队列交付范围 | 是否纳入本轮完整实施；当前尚无完整可复用队列服务 |
| TCP 服务端多客户端 | 是否选择具体客户端及如何隔离来源 |
| 数据时效与跨目标快照 | 明确有效期、会话隔离，以及触发样本不含所选目标时的失败策略 |
| 队列消费边界 | 明确行对齐、取消、下游失败返还和并发读取契约 |
| 参数绑定及窗口提交 | 获取行数链形按钮的绑定能力、关闭是否丢弃草稿，按现有宿主契约定稿 |

后续以本文件追加修订，不把待确认项改写成 VM 已确认事实，不把已保存方案描述为已实施。其他通信工具逐项收集 UI 与官方依据后建立各自方案，再统一工具链输入输出契约。
