# 被动报文逐次消费优化方案

日期：2026-10-14  
状态：逐次消费核心已实施并部署Release；自动回归通过，用户原方案、设计器及高DPI人工验收待完成。

## 1. 目标与适用范围

纠正TCP／UDP／串口跨轮复用最新报文的设计。对于同一接收节点，一条完整报文只能成功接收一次；下一次执行没有未消费报文就等待。Modbus／OPC UA主动读值及全局变量读取不改为报文消费。

本方案取代既有“当前连接最新报文可重复读取”的规则。保留已实现的异步等待、停止取消及无关分支隔离，不新增报文年龄参数、隐藏超时、第二个socket读取者或自动请求。

## 2. 各来源的执行契约

| 来源 | 每次执行 | 无新数据或异常 |
| --- | --- | --- |
| TCP／UDP／串口 | 顺序接收本节点尚未消费的完整报文 | 无未消费报文则保持执行中；来源失效明确失败 |
| Modbus／OPC UA主动读取 | 复用连接实际读一次当前值；相同值仍有效 | 按现有协议取消、超时、质量及错误规则处理 |
| 无生产者全局变量 | 读取节点执行时当前值 | 校验存在性与类型 |
| 有生产者全局变量 | 获取生产者本轮成功结果 | 遵守真实依赖，不回退上轮值或设计初值 |

报文是否为新数据依据会话与递增序号，而非载荷内容。连续发送两次7是两条报文，可以分别满足两次接收。

## 3. 缓冲与消费身份

底层沿用设备分帧，完整业务报文进入有界缓冲，记录设备／目标身份、连接会话、递增序号、到达时间、质量与载荷。一次socket读取不直接等于一条业务报文。

接收节点独立维护消费进度，身份使用稳定工作流ID、节点ID及设备／目标ID；子程序须包括稳定定义／调用作用域以避免同ID串读，本批采用根工作流ID加稳定调用节点路径及子流程ID构成作用域，跨轮不使用RunId；窗口／工作流请求共享相同节点进度。不得使用显示名称、临时冻结工作流ID或每轮运行ID作为持久跨轮消费身份。同一消费者不得并发重复领取一条报文。

每次执行取下一条未消费报文，无数据则可取消异步等待。执行前已到达、仍在缓冲且未消费的报文可直接接收；不能要求所有数据都必须在点击执行后到达。提前到达多条时按序处理，不只保留最新一条。

各节点是独立订阅关系：一个节点消费不推进其他节点游标，不清空其他节点待接收的数据。一个接收节点的多个下游共用其本轮固定输出。跨节点竞争消费不属于本方案，不与后置P5通用数据队列混为一谈。

## 4. 消费提交与失败边界

接收节点校验完成、成功发布本次输出与推进游标必须有统一提交边界。本批ConsumeAsync接口在来源锁下执行短时内存输出提交回调并推进游标，同一消费者Busy状态拒绝并发领取；异常／提交前取消释放Busy且不推进。提交完成后到达的取消不撤销消费。此提交指接收工具本次内存结果，不是外部业务事务。

- 等待或提交前取消：不消费，释放预留。
- 质量、类型或输出发布失败：不推进游标，记录原因；坏报文可能再次阻挡该消费者，不能静默跳过。显式丢弃／调试处理入口若需增加，应独立设计。
- 接收成功后解析、组装或发送失败：不自动回滚消费，不重放旧报文，避免重复业务副作用。
- 历史重放必须是明确调试操作，不默认回退。

这不是端到端业务恰好一次保证；对端重发、进程崩溃及外部设备副作用的事务一致性不在本批承诺范围。

## 5. 会话与生命周期

断线、来源删除、设备切换、实质配置变化或方案重置终止旧等待，清理对应旧会话报文与预留；新会话数据不得完成旧会话请求。设备或节点改名不重置消费进度。停止工作流仅取消当前等待／未提交领取，不使已消费报文变新。

程序重启或方案重载不恢复旧运行报文作为新数据；消费状态属于运行时，不写回用户设计参数。节点删除、复制、改来源及消费者首次注册须明确生命周期：新身份不得继承其他节点进度；允许提前到达的数据仅限当前来源缓冲中仍可合法交付的记录，不承诺恢复缓冲窗口之前的数据。

缓冲必须按条数或字节数有界。本批每来源最多256条且4 MiB，消费者最多4096个。首次消费者从当前会话序号1开始；若早期报文已被容量淘汰，明确报告缺口，不静默改成从最新记录开始。断线、来源实质变化及方案重置清理相应缓冲与消费者；删除节点后的逐个自动回收未接入，不使用LRU丢弃进度，达到消费者上限明确要求重载方案。溢出恢复当前通过重载方案重新建立接收会话，未增加自动跳过或丢弃按钮。溢出造成缺口必须明确报告丢失范围，不得静默跳到最新值后仍宣称逐条交付；慢消费者不能造成无限内存增长。

## 6. 事件和执行调度

底层报文分别进入接收缓冲及事件判断。事件负责判断、触发和响应，不能消费工具游标；无事件或条件NG不阻止手动接收。保持事件与工具解耦，不通过第二套网络读取争抢数据。

保留ExternalDataWait边界：被动接收等待不占普通计算名额，不阻挡无关独占节点；真实绑定与连线依赖仍等待本轮生产结果。主动读取、未知来源及其他工具不自动放宽互斥。

同一工作流上一轮仍在等待时，再次执行仍拒绝，不排队、不叠加。重新开始须先停止并等待退出再启动。普通完成后的再次执行沿用稳定消费进度，不能重置成第一次接收。

参数、图与变量配置仍来自执行快照；报文领取通过无UI运行时服务完成，插件不依赖宿主程序集，UI不承担调度。

## 9. 验收场景

| 场景 | 必须结果 |
| --- | --- |
| 第一轮发送7并接收，第二轮不发 | 第二轮等待，不能复用第一轮 |
| 第二轮再次发送同样的7 | 识别为新报文并继续 |
| 执行前提前到达两条报文 | 后续两次按顺序分别取得 |
| 两节点或两工作流读取同一来源 | 各自独立进度，不互抢，不跨轮重复 |
| 同一接收节点多个下游 | 使用本轮同一份输出 |
| 等待中停止／提交前取消 | 及时退出，未提交报文不被消费 |
| 接收成功后下游失败 | 下一轮不自动重放已消费报文 |
| 断线重连、方案切换 | 旧等待结束，旧报文不进入新会话 |
| 多个接收同时等待 | 不占满计算名额，无关22及已就绪21→23继续；真实24／25等待 |
| 缓冲溢出或坏报文 | 明确缺口或失败，不静默丢弃／跳过 |
| 节点改名、复制、子程序作用域 | 身份保持或隔离符合定义，不串消费进度 |
| 寄存器／OPC UA重复读取相同值 | 每次实际读取可成功，不被判作旧报文 |
| 全局变量及生产者依赖 | 保留当前值／本轮生产结果规则 |

此前3项扩展自动化失败仍为未解决事项，不能用本方案保存或未来专项通过替代完整链验收。
