# 通信工具链模块结果与数据分析统一约定

日期：2026-10-10  
状态：解析／组装共用结果与分析已接通，接收执行期当前值与变量多行已实施；发送、队列及完整来源未完成。

适用接收数据、发送数据、协议解析、协议组装。配置窗口仅编辑参数、绑定和配置校验，不展示运行值。各节点执行输出进入宿主模块结果；详细数据分析使用主界面既有数据分析区域，不放回调试窗口，也不独立维护第二套结果。

### 已确认的输出口径

2026-10-12组装来源及优先级确认：组装列表每行主要订阅本次已成功上游节点的字段，也可取变量执行快照或常量；不固定取全局触发out、不隐式订阅接收事件out。文本组装项仅支持String／Integer／Double，原始Binary先经解析，不任意ToString。组装固定String与对应UTF-8 Binary输出；两类展示及下游读取同次结果。下一批接收服务／插件优先，解析和组装的候选过滤同批补齐，以设备→接收→解析→组装→模块结果验证类型、样本和稳定键一致，UI微调后置。接收首版服务路径、两处筛选已实现，不把已有纯算法测试计为设备验收。

2026-10-12最终输入输出确认：TCP／UDP／串口报文与Modbus寄存器数据区由接收节点保留为Binary，不自动复制String；OPC UA及变量／队列保留实际类型。协议解析输入兼容String／Binary，输出按配置产生int／float／string。文本Binary先解码，字节Binary直接读取；String字节输入必须明确格式，HEX展示不代表载荷转换。绑定控件仅显示来源关系，完整接收值及接收时间在模块结果／主界面数据分析查看；原生数值可以绕过解析直接绑定下游。文本字段重排改变片段对应关系，字节重排不改变区间值，两者都保留稳定字段身份。联合候选筛选与接收首版已实现，文本编码设置和剩余来源仍待完成，不由结果约定自动获得运行能力。

2026-10-12当前取数已实施：接收执行期获取当前来源，模块结果、分析与下游固定使用这次输出，不再读取设备。普通变量当前集合、多行原子结果及生产者运行值已接通；时序由工程保证，原生类型和Binary／HEX展示不变。

事件out与节点out独立，不自动复制；事件显式输入／运行参数赋值仍是独立路径。执行期取数及新UI已接通，证据见[当前值交接](../../../collaboration/HANDOFF_RECEIVE_CURRENT_VALUE_IMPLEMENTATION_20261012.md)。

- 接收数据按所选来源和目标取得实际载荷，不擅自解析。
- 协议解析按配置字段、类型、区间和顺序输出，文本多余片段不产生新字段；所需数据不足、转换失败或越界整体失败。
- 协议组装按配置内容、顺序和分隔符形成结果，不增加隐式类型猜测。
- 发送数据按配置目标和绑定数据校验、编码并提交，不能把显示内容当作实际载荷。
- 模块结果、主界面数据分析及下游绑定关联同一次执行，失败不沿用上次有效值。

原始字节保持原始载荷语义，HEX仅用于显示。统一SDK现有Integer／Double和tuple规则沿用，协议int/float限制与框架数值承载分层处理。本轮已实施不可变BinaryPayload及Binary独立词目：一个对象承载一段完整字节报文，多个对象可组成tuple；旧Byte标量和直接byte[]词目不恢复。变量保存按Base64存储载荷，显示为HEX，绑定仍为BinaryPayload。开发期宿主及全部插件统一当前SDK契约2.1，旧契约不兼容、不增加迁移或回退；框架适配由实施者负责，不能把词汇规范化误认为设备编码改变。

共享基础已实现CommunicationToolResults及CommunicationDataAnalysisControl，后者直接接收前者并用于主界面分析。ProtocolParse及ProtocolAssemble工厂已复用该控件，宿主执行、固定／动态输出、下游绑定、参数保存和失败空值已有插件专项回归。接收首版宿主通信接线已完成，发送及完整来源未完成，因此本轮不是整条工具链的最终交付；实际主窗口视觉与人工交互验收仍待完成。

## 1 结果发布和展示关系

```text
工具执行的配置与输入快照
             |
             v
       同一份 ToolResults
             |
             +-> 模块结果：业务字段／状态／耗时／变量绑定
             |
             +-> 主界面数据分析：来源、片段、转换和提交明细
             |
             +-> 下游订阅与显式变量生产者发布
```

现有 [ToolResults](../../../../src/Plugin.SDK/Execution/Results/ToolResults.cs) 提供状态和结果元数据机制；[IToolControlDataAnalysis](../../../../src/Plugin.SDK/UI/Controls/IToolControlDataAnalysis.cs) 接收执行结果用于主界面数据分析区域。插件不引用 UI 宿主结果管理器，宿主负责把结果分发到显示与分析控件。动态输出字段与可绑定字节／列表的适配仍须实现前评估，现有基础接口不代表四工具已经接通。

业务结果与诊断数据区分：业务字段用于下游或变量绑定；分析行用来解释本次执行，不把格式化诊断字符串当作实际业务值。两个展示入口必须关联同一节点、同一次执行，不可各自读设备最新值或重复执行算法。

## 2 公共模块结果

```text
+--------------------------------------------------------------------+
| [图像] [模块结果]                                                  |
+--------------------------+------------------------+----------------+
| 结果名称                 | 当前值                 | 变量管理       |
| v 当前通信工具           |                        |                |
|   耗时(ms)               | 本次执行耗时           | 按元数据能力   |
|   模块状态               | 宿主状态               | 按元数据能力   |
|   业务输出字段           | 保留实际类型           | [绑定]         |
+--------------------------+------------------------+----------------+
```

公共诊断含执行时间戳、错误原因和执行身份，来源会话身份按运行时实际契约记录；这些是否显示为可绑定模块字段由元数据决定，不默认全部开放变量链接。

宿主已有 NotExecuted、Running、Success、Failed、Timeout、Cancelled、PartialSuccess，不另建通信专用状态枚举，不把 VM 的0/1状态数值直接替代 SDK。发送部分成功映射可以复用 PartialSuccess；具体条件仍由发送工具已定义的独立单元策略决定。

当前值只读。HEX只是字节展示；变量绑定使用实际字节、字符串、标量或列表类型并遵循唯一生产者。查看和刷新不触发额外设备操作或赋值。执行失败清除无效业务值，但保留本次错误诊断；发送已成功提交部分不能被清空成未提交事实。

## 3 四工具结果字段清单

### 接收数据

| 字段 | 类型与用途 |
| --- | --- |
| out0、out1等配置输出 | 每项保留来源类型；通信设备模式一项；队列按已定稿行数契约返回列表 |
| 原始数据 | 字节来源可选 Byte[]诊断，不对原生节点或图像伪造字节 |
| 来源信息 | 来源类别、设备和目标或变量和队列列路径，诊断 |
| 样本时间与质量 | 运行时可提供时记录，不能虚构精度或状态 |

来源不存在、质量不良或快照不可用时，业务字段无有效值。分析数据必须说明取到了哪份样本，而不是展示随时变化的设备缓存。

### 发送数据

| 字段 | 类型与用途 |
| --- | --- |
| 发送数据 | 字节型目标返回实际提交字节；原生目标用对应提交值，不统一伪造HEX |
| 成功数量、跳过数量、失败数量 | 非负整数，按独立提交单元计数 |
| 提交明细 | 结构化诊断列表，不默认允许绑定到任意变量 |
| 目标及协议响应 | 每单元的稳定目标、提交状态和错误，不等同对端业务完成 |

一行发送对应一个独立目标计划时，明细保留其序号和目标。预检失败没有实际发送数据；超时等不确定结果标识提交不确定，不能宣称对端未执行。

### 协议解析

| 字段 | 类型与用途 |
| --- | --- |
| out0、out1等配置输出 | 按规则实际输出 int、float、string等已开放类型 |
| 输入信息 | 实际输入格式、文本或字节长度，诊断 |
| 解析明细 | 每字段原始片段、区间或文本序号、转换类型和校验结果 |

仅全部成功才发布业务输出。失败明细中局部解析值属于诊断，不是可用业务字段。

### 协议组装

| 字段 | 类型与用途 |
| --- | --- |
| 组装结果 | string，完整组装文本 |
| 16进制组装结果 | 建议Byte[]，文本编码后的字节；编码和首版开放仍待确认 |
| 组装明细 | 每项来源、原生类型、格式化片段、插入分隔符位置 |

组装列表项只产生一个最终报文，不为每项新增误导性的业务输出。字节结果不是寄存器数值编码。

## 4 数据分析界面建议

四工具复用主界面数据分析宿主，每种工具显示相应列，不新增配置窗口页签或独立调试窗口。以下明细为项目建议，未认定为VM原样界面。

```text
+------------------------------------------------------------------------+
| 主界面数据分析：当前选中的通信工具                                     |
| 节点：协议解析1   执行：本次快照   状态：失败                           |
|------------------------------------------------------------------------|
| 序号 字段   来源片段       类型    规则                  校验说明      |
| 1    out0   00 5C          int     [0,1] / ABCD         诊断值92      |
| 2    out1   3F 80          float   [2,3] / ABCD         需要4字节     |
|------------------------------------------------------------------------|
| 诊断：整体失败，业务输出均无有效值；局部诊断不供下游订阅。             |
+------------------------------------------------------------------------+
```

| 工具 | 分析明细主要列 |
| --- | --- |
| 接收数据 | 输出名、来源路径、来源类型、样本时间、质量、取得数量、原因 |
| 发送数据 | 序号、目标路径、提交值或字节、实际长度、预检／提交状态、原因 |
| 协议解析 | 字段、原始片段、起止字节或文本片段序号、类型、顺序、转换诊断 |
| 协议组装 | 序号、常量或绑定来源、原生类型、格式化片段、分隔符、输出位置 |

输入、字节区间和提交明细按本次结果快照生成。原生类型不强制HEX；长文本与大字节数组可只读展开，显示截断不截断实际输出。日志历史不混入当前结果，切换节点或执行身份时不串行错显。

## 5 结果有效性与绑定

- 字段显示名和稳定身份分离，改名或排序不破坏订阅；删除和类型变化明确标记失效。
- 单步与正式执行使用同一结果契约，发布不同执行上下文，不污染正在运行的其他流程。
- 未执行、无样本、失败和取消与合法空字符串、合法零值区分，不用空格或0冒充有效数据。
- 模块结果、数据分析、下游订阅共享本次有效性；局部成功诊断不得绕过原子发布。
- 变量管理仅配置显式生产者绑定，数据分析没有直接修改变量或重试设备的入口。
- 通信工具不输出图像时不伪造图像结果；图像数据队列如后续支持，则遵循宿主图像和所有权契约。

## 6 实施和验收边界

本轮仅同步方案。后续实现需覆盖声明式结果字段、动态配置输出、类型化绑定、四种分析数据模型、宿主结果发布和分析更新、失败有效性、单步上下文、节点切换与大数据只读展示。结果与分析适配依赖SDK现有能力，必要扩展先评估主程序标定工具链，不在文档更新时修改SDK。

具体诊断字段、列表绑定能力、提交状态及组装字节编码继续按四份工具方案确认。本约定确定统一入口与数据关系，不扩大到脚本、视觉控制器、相机IO或自动重试能力。
