## 全局变量统一传递最终方案

一个全局变量系统共用一套生产者、消费者、运行值和依赖规则。直接订阅与接收／发送是不同配置入口，不是两套机制；不增加“普通全局参数”等用户分类。本节是通信工具链完成后的目标，不改变当前交付顺序：先完成现有工具链，再依据完成时的代码复核并执行U1关系编译、U2快照／取值、U3范围／等待优化。

### 两种入口与同一生产关系

| 入口 | 系统登记 |
| --- | --- |
| X输入来源绑定A结果 | A是X生产者 |
| X目标输出绑定B参数 | B是X消费者 |
| 接收R选择X | R是X消费者 |
| 发送S写入X | S是X生产者，其输入绑定仍形成上游到S依赖 |
| B直接绑定A输出 | A到B直接依赖 |

一个变量只有一个明确生产来源，可以有多个消费者。发送选择目标时同步登记输入来源；已有其他生产者时提示冲突，不静默覆盖、不建立任意赋值旁路。删除或修改绑定同步更新关系。复用既有绑定和变量选择窗口，说明放Tip／帮助，用户不配置调度图。

```text
直接入口：A结果 → 变量X → B参数
节点入口：A结果 → 发送S写X → 接收R读X → B参数
```

编译器必须识别发送到接收的中间依赖，不能只识别A到发送、接收到B。仅选择同一设备不表示依赖，请求应答关联由工程协议明确配置。

### 执行快照与依赖图

快照确定本次执行配置和已提供输入，图确定谁等谁，结果集保存随后产生的输出。冻结配置与输入 → 编译依赖、输入取值规则和资源要求 → 校验 → 调度 → 发布成功结果 → 解锁消费者 → 更新模块结果。

配置包括节点、参数、连线、绑定、变量身份／类型／生产来源、运行覆盖和输入生命周期。图与执行必须使用同一份配置，执行中编辑只影响下一次。设备当前数据仍在接收节点执行时读取，不提前冻结。图像、数组等须明确复制或生命周期，字典浅复制不代表完整深复制。界面最近执行记录仅展示，不作为调度或下一轮输入。

编译器扫描连线、直接绑定、变量生产／消费和发送映射，按工作流ID加节点ID寻址。变量桥接解析到真实生产节点，不作为额外可执行节点。重复依赖合并但保留原因；检查缺失引用、类型、重复生产者、自身依赖、循环、执行范围和调度粒度。

### 统一取值与等待

| 来源 | 定稿规则 |
| --- | --- |
| 常量、无节点生产来源的变量直接用于算法参数 | 使用本次运行边界取得的值 |
| 直接节点输出 | 使用本次成功结果 |
| 有生产来源的变量，无论直接绑定还是接收读取 | 等待对应生产者，解析本次成功结果，不以设计初值或其他轮次结果补位 |
| 接收读取无生产来源的变量 | 执行时一次取当前集合，整项校验后原子输出 |
| 设备来源 | 保留既有当前值契约，不改变触发规则 |

直接参数的稳定设置值与接收的显式当前读取有不同用途，但节点生产变量共用来源和结果解析。类型跟随来源，不一律转字符串；运行结果不写回设计初值，失败清空业务输出。

等待在调度器派发前发生，不在消费者内部轮询。前驱未完成则待执行；所有前驱成功且所需输出可用后进入就绪队列，再申请资源。前驱失败、禁用或分支跳过则跳过依赖消费者。不按画布层或序号排序，不等无关节点整层结束；并行仍受资源和工具声明限制。

分别记录等待节点、工作流、资源和设备读取。循环执行前拒绝，设备操作支持超时和取消；没有运行任务却无法推进时明确报错。等待前驱不占用设备或计算资源。

### 各传递场景

| 场景 | 定稿行为 |
| --- | --- |
| 同流程直接／经变量绑定 | 自动推导生产者依赖，读本次结果，同层或无连线不改变规则 |
| 发送写X、接收读X | 自动建立发送到接收依赖 |
| 多消费者或条件分支 | 共用生产来源；分支未执行不回退其他轮次结果 |
| 整体方案跨流程 | 当前阶段按整流程排序，上游整体成功发布后启动下游；失败跳过依赖流程 |
| 单独运行／单步，上游不在本次范围 | 提示缺少上游，不自动补跑、不无限等待、不复用界面最近结果 |
| 独立事件或各流程独立连续运行 | 本阶段不保证跨运行配对；当前共享值契约另行确认，不混入同批规则 |
| 同产品／同轮对应 | 方案批次或工程时序保证，不由变量名推断 |
| 父子流程 | 优先显式输入／输出，保留调用作用域；嵌套变量寻址专项验收 |
| A前半段到B再回A后半段 | 整流程调度不自动交错，需拆分或明确调用，编译时提示粒度不支持 |

每次方案运行独立结果集合，不新增跨运行历史回退、报文年龄或触发样本锁定。节点图无环但归纳到流程后成环时也须提示。

## 2 两条路径与输出关系

```text
通信设备／地址
      |
      +--> 通信管理接收事件：解析／比较／组装
      |             |
      |          事件 out
      |             |
      |      触发条件、流程输入／运行参数赋值
      |
      +--> 工作流接收数据工具：获取来源载荷
                    |
              本次节点接收输出
                    |
              协议解析工具
                    |
              类型化节点输出
```

事件out属于EventId／FieldId，节点输出属于NodeId／稳定字段键；同名out1不表示同一字段，不进行隐式复制。触发时若使用事件参数，值通过执行快照交付，不让执行层读取管理器控件。

事件与工具复用通信连接和解析核心，不建立第二套连接。事件只决定工作流启动；工具按所选来源在节点执行时取数，期间值变化由工程保证。主动读与后台轮询通过同一通信服务协调；下游只消费接收节点本次成功输出。

## 3 来源适配和架构

| 来源 | 接收工具目标输出 | 边界 |
| --- | --- | --- |
| TCP客户端／服务端、UDP、串口 | 一份完整业务报文BinaryPayload | HEX只是展示；复用现有分帧，不能把TCP读取分块直接保证为完整业务报文 |
| Modbus地址块 | 寄存器数据区BinaryPayload | 不含协议帧头，保留寄存器原始数据顺序，不提前按int／float解码 |
| S7／CIP目标 | 由目标读取能力决定 | 不假定全部转字节；工具链未适配前不宣称可用 |
| OPC UA数据点 | 原生类型值及对应有效性 | 原生数值直接用于下游；字符串需要拆分时进入文本解析，不伪造报文 |
| 变量、队列 | 来源实际类型 | 队列仍属计划，未完成前不能提供可运行占位 |

共用解析核心应是无WPF、无设备副作用的算法层，统一HEX输入、严格字符转换、区间、顺序、数值规则和错误。通信事件负责比较、状态、历史和触发；工具负责本次执行结果。插件不能引用UI宿主或直接调用CommunicationReceiveProcessor。

共享改动覆盖SDK、执行服务、设备样本和事件解析，编码前需评估主项目影响。本工作区不开发标定、不自行同步主项目，不恢复SDK旧契约兼容。

### 接收输出与下游类型

TCP本身传输字节，不保证内容是字符串；UTF-8等编码把字节解释成文字，HEX只是另一种显示。接收工具对TCP／UDP／串口业务报文和Modbus寄存器数据区统一输出BinaryPayload，SDK词目为Binary，不自动追加String副本，也不提前拆字段。Modbus寄存器按原顺序保留，高字节在前，不夹带协议帧头；例如寄存器92的数据区为00 5C。此处为工具输出约定，不声称所有驱动底层都直接返回BinaryPayload。

OPC UA及变量／队列保留实际类型。原生Integer／Double等可以直接绑定兼容的下游参数，不必先转成String／Binary，也不必经过协议解析。接收设备首版已实现，S7／CIP、队列等未接通路径不能称为可用。

### 解析输入和绑定过滤

解析内容不是固定String输入，而是兼容String和Binary的单项载荷输入；输出字段的int／float／string不决定输入过滤。文本与字节两种模式都必须能看到上游接收节点的Binary out，也能看到String来源。

- 绑定候选只允许String／Binary兼容来源，复用现有树形路径、稳定输出键与索引选择，增加最小范围的多类型筛选能力。
- 不以空DataType或object放行所有候选，不把全局ParamBinding改成任意类型互通；不能只配置DataType=String而隐藏Binary。
- 来源声明用于候选过滤与条件UI，实际执行仍校验值类型、来源有效性和单项输入。手工填写不兼容路径必须报错，不能靠ToString把数值、图像或几何对象伪装为报文。
- 一份BinaryPayload包含完整报文；选择其中一个载荷不是选择一个字节。遵循现有单项tuple取值，多个载荷或多项String列表需显式选择一项，不自动拼接。
- 切换模式保留兼容的来源绑定，由解析方式改变解释过程，不更换设备来源、绑定键或底层载荷类型。

| 实际输入 | 文本解析 | 字节解析 |
| --- | --- | --- |
| String | 直接按分隔符拆分，不做字符解码 | 按明确的HEX文本或字符文本规则转换为字节，再解析 |
| BinaryPayload | 按所选字符编码严格解码，再按分隔符拆分 | 直接读取原始字节，不需要输入格式选择 |
| Integer／Double／Boolean／图像／几何等 | 不支持，过滤并在执行时拒绝 | 不支持，过滤并在执行时拒绝 |

### 文本与字节的转换规则

```text
文本解析
String ----------------------------------+
                                         +--> 按分隔符拆分 --> 配置字段转换
Binary --> 按字符编码严格解码为文字 ------+

字节解析
Binary ----------------------------------+
                                         +--> 按闭区间、类型与顺序解析
String --> 明确HEX文本或字符文本转字节 ---+
```

例如Binary载荷41 42 43 2C 32表示ABC,2：文本解析用逗号和string／int字段得到ABC及2，不需要接收节点额外输出String。字节模式直接读取原始位置；例如00 5C 41 44，int区间0～1得到92，string区间2～3得到AD。

文本Binary输入的编码目标为UTF-8／ASCII，默认UTF-8，放在高级设置；String输入已经是文字，不显示无效编码项。当前文本Binary解码固定UTF-8，条件编码选项与执行适配尚未实施。HEX展示字符串不自动还原为字节：String进入文本解析仍按文字拆分，进入字节解析才由输入格式决定转换。

字节模式ASCII数据表示字段按ASCII字符解释。例如39 32可按字符转换为整数92；二进制整数00 5C则关闭ASCII数据。它不等于HEX显示，也不等于输入格式。ASCII字符解释不使用数值字节重排。非法HEX、编码错误、所需片段不足、区间越界、类型转换失败及取消不发布部分业务值，不复用历史成功结果。

### 文本模式

```text
+----------------------------------------------------------+
| 协议解析                                             ×   |
+----------------------------------------------------------+
|  解析方式                                                |
|  方式选择    [文本解析                           v]       |
|  解析内容    [适中宽度的绑定控件____][绑定]                |

|                                                          |

|  序号  名称                 类型              操作       |

|                    [连续执行]   [执行]   [确定]          |

```

文本按列表顺序解析，只产生配置字段。多余片段不生成输出；缺项、转换失败、越界及取消不发布部分业务值。模块结果、主界面分析和下游绑定来自同次结果，配置页不增加运行预览。

上下移动不改变名称、FieldId或绑定键。文本模式会改变字段对应第几个片段，因而可能改变结果或导致类型转换失败；字节模式仍按各字段原区间读取，只改变排列。序号和首末行按钮按实际item位置更新，不使用交替行索引；该重排修复已部署到常用Release。

### 高级设置及条件显示

文本模式仅在Binary输入需要解码时显示高级设置的字符编码：

```text
|  v 高级设置                                              |
|  字符编码    [UTF-8                   v]                 |
```

字节模式按条件显示以下项目，而不是无条件全部展开：

```text
|  v 高级设置                                              |
|  输入格式    [HEX文本                           v]       |
|  字符编码    [UTF-8                             v]       |
|  当前字段    [out0                              v]       |
|  数值解释    [按统一规则                         v]       |
```

- 输入格式仅在字符串进入字节解析时显示；真实BinaryPayload不需要识别格式，不猜字符串含义。
- 字节编号固定从0开始，起止均包含，不再展示0／1选择框。这是本项目约定，不断言VM全部实现。
- 字符编码在文本Binary解码、字节字符文本编码或字节string字段解码时显示；String进入文本解析无需编码。字节ASCII解释使用ASCII规则，该设置不参与时隐藏。声明类型无法确定时不能默默猜格式，执行仍按实际值严格校验。
- 数值解释仅对当前二进制int字段显示，当前行切换同步该字段。选项为按统一规则、有符号、无符号，已按字段持久化；字段重排保留设置与身份。
- 默认统一规则为1～3字节非负、4字节有符号，允许显式覆盖。无符号值仍须落入协议int32范围，不因此放宽SDK承载范围。
- float仍为有限32位浮点、4字节；string按配置编码解释。输入格式、编码和符号是项目扩展，不伪称VM主界面已有对应参数。

已完成BinaryPayload、模块结果基础、两协议插件、R1／R2／R4首批，以及本轮R3接收首版和同批筛选；不是四工具完整交付。原始载荷已可经ReceiveData节点进入工作流，事件out仍不会自动变成节点输出。

## 6 接收运行时契约

接收节点执行时取当前值：Modbus读所选地址块，OPC UA读所选点，全局变量读当前变量集合；主动读取不要求轮询开启，不用缓存补位。TCP／UDP／串口取当前连接最近完整报文，不清空、不隐式发请求、不等待下一条；没新报文可重复读到同一内容，这不保证远端实时值。查询应答工程须明确配置设备协议，不由接收工具猜测。

取消报文年龄参数和隐藏时间限制；断线、通信配置或方案变化使旧连接数据失效。读取完成后，本次结果固定供模块结果、分析和下游使用。失败清空，不回退上次输出。触发事件与接收工具可取得不同值，不默认桥接事件out。详情和当前ASCII图见[接收数据定稿](./接收数据工具方案与沟通基线-20261010.md)。这些执行时机是项目契约；VM官方仅确认来源／布局、轮询及数据同步，不明确接收节点内部读取时机。

## 7 协议组装来源与联合验证

组装列表每行是一个独立文本片段，主要订阅本次已有成功结果的上游节点字段，不限于紧邻上一节点；也可绑定全局变量快照或直接填写字符串常量。不是从设备再次读取，不固定接收全局触发out，也不默认复制接收事件out。

当前文本组装支持String／Integer／Double单项值，数值按固定文化明确格式化。Binary、Boolean、图像、几何等不自动转文字；多项集合需明确选取一项。组装绑定候选已限制为String／Integer／Double，实际运行仍校验类型，不能仅依赖下拉过滤。

```text
设备业务报文／寄存器数据区
          |
     接收数据 out：Binary
          |
     协议解析 out：String／Integer／Double
          |
     组装列表：上游字段 + 变量快照 + 字符串常量
          |
     组装结果：String + 对应UTF-8 Binary
          |
     宿主模块结果／主界面数据分析
```

原始Binary接收out不能直接进入当前文本组装项，必须先取得解析后的标量；原生数值或String来源可直接绑定兼容组装项。全局触发只有明确映射到流程输入或模块参数且执行接线具备后才可能参与，仍属独立路径，不是第一批联合验证的前置。

首批实例：TCP对端发ABC,2，接收out保持41 42 43 2C 32，文本解析得到ABC和2，组装常量RESULT与两字段得到RESULT,ABC,2。Modbus数据区00 5C 41 44经字节解析得到92和AD，组装为RESULT,92,AD。两例均从本次上游结果取值，检查下一报文到达不覆盖当前执行、无数据与失败清空、会话及设备隔离、重排／改名／保存重载后的绑定身份。

第一批终点为模块结果，不发送回设备；发送插件、队列及完整收发验收仍按后续计划实施。详见[组装来源方案](./协议组装工具方案与沟通基线-20261010.md)及[实施计划](./通信工具链实施计划-20261010.md)。
