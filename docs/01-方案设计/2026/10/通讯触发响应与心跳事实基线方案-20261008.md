# 通讯触发响应与心跳事实基线方案

更新日期：2026-10-08

本方案是触发配置、响应配置和心跳管理后续沟通的基线，整合本机 VisionMaster 帮助、用户实际截图和已确认的项目约定。心跳首批状态见第 8 节；用户后续确认忙时跳过并警告、Modbus 响应严格拆分编码，触发与响应已进入接入阶段，最新实施范围见第 9 节。历史待确认项不自动成为已确认需求。

事实状态：

- **已确认**：用户明确要求、实际截图或帮助正文支持。
- **暂缓**：用户明确要求暂不实现。
- **待确认**：尚未展示的布局或未明确的运行语义，不能作为定稿需求。

后续截图或用户说明改变本方案时，更新对应章节和待确认清单，不沿用旧建议冒充 VM 事实。

## 1 共同约定

~~~text
+----------------+--------------------------------------------------+
| 设备管理       |                                                  |
| 接收事件       |           当前导航对应的配置区域                 |
| 发送事件       |                                                  |
| 触发配置       |                                                  |
|----------------|                                                  |
| 响应配置       |                                                  |
| 心跳管理       |                                                  |
+----------------+--------------------------------------------------+
~~~

1. 保留现有导航，不新建另一套配置管理窗口。
2. 配置实时同步到解决方案共享对象，保存解决方案时统一落盘，不增加独立“保存配置”按钮。
3. 内部按稳定 ID 引用，编号、名称和回填路径只负责显示。
4. 分隔符共用目录、普通 ComboBox 样式和模板，不新增专用控件，各配置的值独立。
5. DataGrid 内容水平、垂直居中，编辑控件保持铺满宽度；全部适配主题。
6. 打开或切换页面不自动执行流程或发送测试数据。
7. 状态、计数和历史不持久化。现有收发历史保留 200 条并自动滚动；新增导航是否提供记录面板仍待确认，不能标为 VM 截图已有控件。
8. 本轮不支持通信脚本。

四类命令已由截图确认。“执行流程”布局已确认；其他三种命令的配置需求有帮助依据，但上述排列仅表达字段关系，具体 UI 待截图确认。

### 2.3 触发字符弹出和回填

~~~text
未绑定：[触发字符 绑定]
                   +----------+
                   | 无       |
                   | out1     |
                   | out2     |
                   +----------+

已绑定：[out1     绑定]
~~~

链条按钮在行附近弹出字段列表，不是独立窗口。选择 out1 后回填名称，按钮保留用于重选。这是事件字段订阅，不是输入匹配文本。内部保存 FieldId。

| 事件 | 帮助示例中的字段 |
| --- | --- |
| 文本协议解析 | 输出列表 outX |
| 文本或字节协议比对 | 组装列表 outX |
| 无组装输出的边沿事件 | 可以不绑定触发字符 |

触发字符不是统一必填项。IO 上升沿示例不配置组装输出、也不订阅触发字符，仍可执行流程。不能因无组装输出一概禁止事件触发。

触发字符值在执行流程内部如何使用尚未完整确认，不能等同于字符串匹配、运行参数映射或工作流输入映射。

### 2.4 暂缓的内容查看

完整用户截图列名为“参数设置”和“设置输入”；部分帮助图片使用“目标输出”，实现依据以用户确认范围为准。

~~~text
+---------------------------------------------------------------+
| 内容查看                                                  [×] |
+---------------------------------------------------------------+
| 序号 | 名称 | 类型   | 参数设置              | 设置输入       |
|------|------|--------|-----------------------|----------------|
|  1   | out1 | string | [运行参数绑定]        | [输入参数绑定] |
~~~

- 两条映射和目标选择窗口均暂缓，不成为首版流程触发前置条件。

帮助示例视频确认“内容查看 → out2 目标输出 → 流程1 → 直线查找1 → 边缘阈值 → 确认回填”，仅作为后续功能参考。

### 2.5 字符串触发

~~~text
+-----------------------------------------------------------------------+
| 事件触发  [字符串触发]                                                |
+-----------------------------------------------------------------------+
| 序号 | 触发字符 | 匹配模式       | 触发命令类型 | 触发配置    | 操作 |
|------|----------|----------------|--------------|-------------|------|
|  1   | [START ] | [完全匹配 v]  | [执行流程 v] | [流程1 v]   | [×]  |
+-----------------------------------------------------------------------+
| [+]                                                                   |
+-----------------------------------------------------------------------+

匹配模式
+--------------+
| 完全匹配     |
| 部分匹配     |
| 不匹配       |
+--------------+
~~~

触发字符是输入框；没有接收事件选择、内容查看按钮或右侧事件字段订阅。截图无设备选择列，不擅自添加设备筛选。

- 完全匹配：整条字符串相同。
- 部分匹配：收到的字符串包含配置内容。
- 不匹配：不做匹配判断，收到就触发；不是“不等于”。

VM 要求字符串触发使用的数据开启“数据上传”，接收事件不受该开关影响。改名“任意收到”属于项目变更，须另行确认。

### 3.3 条件字段

~~~text

~~~

PLC 必须定位地址并配置 int、float、string 类型；普通设备无需 PLC 数据类型。字符串相关输出有自定义结束符及 CR、LF、CRLF 选择的帮助依据。

### 3.4 运行语义

| 分组 | 条件 | 内容 |
| --- | --- | --- |
| 方案加载 | 加载成功 | 配置内容，按延迟发送 |
| 流程控制 | 忙碌或空闲状态变化 | 对应内容 + 分隔符 + 流程 ID |
| 相机响应 | 连接或掉线 | 对应内容 + 分隔符 + 相机 ID |

“通信超时时间(s)”在本章节中表示加载后的发送延迟，不是底层读写超时。截图示例出现忙碌／空闲文字混用，以正文语义为准，不复制错误文案。

VM 流程 ID 采用显示编号减 9999，相机 ID来自相机管理编号。项目需确认稳定引用 ID 与对外协议标识，不照搬换算。

数值寄存器、OPC UA 数值目标如何携带对象标识仍待确认，不能将拼接文本隐式转为数值；原生数值写入没有文本结束符含义。

选项名称及两种模式的输入布局均已由截图确认：

~~~text

心跳类型 [多数据 v]   发送内容 [0          ] - [1          ]
~~~

多数据在同一“发送内容”单元格内并排两个独立输入框，中间显示短横线；不是新增两列、弹出编辑窗口或输入一个分隔字符串。短横线是 UI 分隔，不表示数值范围、减法或实际发送分隔符。截图的两份示例内容为 0、1，不据此认定默认值或数据类型。

用户明确确认：单数据每隔一个周期发送配置内容；多数据每隔一个周期轮流发送两份内容，不是一个周期内同时发送两份。

~~~text
单数据：内容A → 间隔T → 内容A → 间隔T → 内容A …
多数据：内容A → 间隔T → 内容B → 间隔T → 内容A …
~~~

时间间隔仍由同一数值框控制。以上描述发送之间的间隔，不确定启用后首次发送是否立即发生。切换回单数据时第二份内容是否保留、再次切换是否恢复仍待确认。

### 4.4 运行语义和待确认

帮助已确认的运行语义：

1. 建立通信后周期发送，支持多个设备。
2. 普通设备不能重复配置；PLC 选具体地址，同设备不同地址可分别配置。
3. 单数据一组内容；多数据两组内容循环交替。
4. 默认间隔 1000ms，有启用／关闭。
5. 单／多数据模式与 int／float／string 数据类型不是同一个概念。

待确认：普通设备和 PLC 目标下的内容编码／类型来源、同 PLC 多地址候选、新增及删除确认行为、模式切换时第二份内容是否保留、启用后是否可编辑、间隔上下限、首次发送时机、断线恢复和失败后的交替位置。不增加未经确认的“发送一次”入口。

## 5 执行关系和架构边界

~~~text
实际设备数据
  → 接收事件解析和比较
  → 触发配置
  → 工作流执行

方案、流程、相机状态变化
  → 响应配置
  → 指定设备和目标写入

周期计时
  → 心跳配置
  → 指定设备和目标写入
~~~

响应、心跳自行配置目标和内容，不强制引用发送事件；与发送测试和流程发送工具共用底层发送能力。

应用级连接、轮询、订阅已有；接收解析仍依赖通讯管理器视图模型。正式自动触发前须迁到后台，关闭窗口不停止自动功能，切换或关闭方案须取消旧任务。缓存重算不能作为新数据触发。

UI 不调度流程，驱动不调度工作流。执行开始时传递输入、参数、全局变量快照，不直接改 WPF 控件。未来工具插件通过 SDK 服务契约接入，不依赖 UI 宿主。

Modbus 按绑定地址类型化写入；OPC UA 按节点原生类型和权限写入。请求返回成功不等于读回值一致，诊断和 UI 不应混同。

VM 接收数据工具从设备／地址、变量或队列读取，再由后续协议解析模块解析，并非选择通讯接收事件。项目若新增接收事件数据源，须标明是项目扩展。

普通文本设备只使用 string，不额外显示类型选择。Modbus 提供 int、float、string，并复用绑定地址的位宽、字节顺序、容量和访问权限。OPC UA 支持现有发送服务的标量类型，包括 Boolean、Double；选中数据点时可用已读取的原生类型作为默认值，每次写入仍检查实时类型、质量和权限，不进行隐式强制转换。数组和结构体不支持。S7、CIP 尚无本项目统一发送实现，不作为本批心跳候选。

新增行默认关闭、间隔 1000ms、内容为空。树形选择回填设备与目标路径，以稳定 ID 保存；已占用目标从候选中排除，不同地址可独立配置。单数据一个内容输入，多数据两个输入；切回单数据保留第二份内容。删除前确认，删除或关闭行取消后台发送。修改配置立即同步解决方案对象，不单独落盘、不触发 OPC UA 设备保存提示；保存解决方案时统一持久化。

以下是本项目首批实现的运行策略，不是 VM 的已核实行为：

- 首次发送等待完整间隔；每次发送结束后再计下一个间隔，慢设备不积压周期请求。
- 多数据成功写入后才切换 A/B；断线、无接收端或失败保持当前位置，恢复连接不补发错过的周期。
- 运行中编辑生成新快照，取消旧任务并等待在途发送结束，再从 A 开始；不把可变 UI 集合交给后台线程。
- 心跳由应用级通讯服务运行，关闭通讯管理器不停止；关闭或切换方案停止旧心跳后再释放连接。
- 无效行单独报告错误，不阻断其他有效行。错误可从设备/开关提示及应用日志查看，不新增未经确认的历史面板。
- 发送成功表示驱动写入成功，不保证外部设备后续读回值仍保持一致。

## 9 触发与响应接入

### 9.1 最新确认规则

用户确认：触发目标忙碌时跳过，不排队，并记录 Warning 日志。Modbus 响应内容可自行定义，按分隔符拆分并按选定数据类型正常编码；不符合类型、越界、地址容量不足或只读目标均报错，整条不写入。

“空闲时触发”“忙碌时触发”输入的是发送内容，不是接收条件。绑定 Modbus 地址后，状态变化响应实际写入该寄存器地址；普通文本设备发送报文，OPC UA 写绑定数据点。VM 帮助没有说明数值型状态与 ID 的具体编码，以下 Modbus 逐项编码规则是项目实现，不冒充 VM 实测事实。

### 9.4 Modbus 编码和对外编号

~~~text
配置内容 + 分隔符 + 流程/相机编号
  -> 数值模式按分隔符拆分
  -> 全部分段严格解析为同一选定类型
  -> 按绑定地址块的位宽与字节顺序编码
  -> 校验访问权限和总容量
  -> 一次 FC16 写入绑定起始地址

例：绑定地址 40，16bit int，容量至少 3 个寄存器
    忙碌内容 30,40，分隔符 ","，流程编号 1
    写入：R40=30，R41=40，R42=1
~~~

int 不接受 abc 或小数，不隐式转换。float 使用浮点编码，不把数值字符当 UTF-8 写入；每个值占多少寄存器由地址块位宽决定。string 保留完整文本，并将结束符纳入字符串编码，不按数值列表拆分。任何校验失败不执行部分写入；超出 FC16 单次容量也拒绝。

数值响应附带编号时必须配置非空分隔符，不能把 10 和 1 拼成 101。方案加载没有附加编号，其数值内容也可按分隔符拆成列表。

项目流程/相机对外编号从 1 起按各自类别分配，以对象稳定 ID 为键保存到方案的响应配置中。改名、重排和删除其他对象不改变已有编号，删除编号不复用；新增对象分配后续编号。不是把 GUID 强转为整数，也不照搬 VM 的显示编号减 9999；流程触发目标选项可显示已分配编号。

OPC UA string 节点可承载完整文本；单个原生数值/Boolean 节点只能写一个同类型标量。因此，带编号的多项状态响应会明确报错、不发送，不能隐式丢掉编号或把多项塞进一个节点。单项方案加载响应可按节点原生类型写入。多数据点状态/编号映射尚未实现。

### 9.5 生命周期和验收边界

自动接收解析使用脱离控件的独立状态，复用现有解析和比较实现；真实 TCP/UDP/串口样本、当前 Modbus 轮询批次和 OPC UA 原生通知进入后台。缓存重算不派发触发；未变更的接收规则在编辑其他配置后保留边沿状态。UI 保留自己的显示解析，不成为自动执行的必要条件。

通讯命令与手动/连续运行共用非等待运行租约；存在活动流程或另一个通讯执行操作时，跳过新触发并记录规则 ID、目标 ID 和忙碌原因。关闭通讯窗口不停止自动功能；关闭/切换方案取消旧任务并等待清理，再释放连接；退出先释放通讯自动执行，再释放相机。
