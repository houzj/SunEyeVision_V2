性能与 VM 对标硬指标

CodeBuddy 重设计的动因是控件较多时窗口打开慢、Tab 切换慢，以及当前界面与 VM 存在差异。最终源码树评审必须覆盖打开链、切换链和对标链：窗口创建/模型构造/模板与资源加载/绑定/首帧；Tab 复用、销毁、状态保存和重复绑定；VM 与当前实现的布局、分组、动态显隐、状态和释放差异。无 VM 证据的缓存、异步或延迟加载只能列为 CodeBuddy 候选。

结合新旧方案后的最终目标架构

最终采用“旧方案的职责闭包 + 新方案的性能与产品边界”。旧方案保留已形成的 VM 调用链、配置模型、模板分派、调试会话和生命周期证据；新方案负责统一命名、删除旧双轨、拆开 UI/执行/持久化、降低工具窗口首次打开和 Tab 切换成本。以下是当前可冻结的目标结构，SDK 的具体公开类型仍以 VM 真实证据为准。

工具调试窗口与性能硬约束：VM 原厂没有运行时主题切换，SunEyeVision 不保留主题切换功能，只保留固定主题资源。窗口首次打开、Tab 切换、换节点关闭和释放必须按 VM 原厂组装链逐项对比；缓存、异步、虚拟化、延迟加载只有取得 VM 证据后才能采用。现有实现中的性能优化不能绕开原厂行为。
性能影响：节点 UI 打开时先创建轻量配置会话和必要模型，模板/资源按 VM 的真实装配链加载；Tab 切换复用同一节点会话和已确认的视图状态，关闭或换节点才执行完整释放。缓存、延迟加载、异步和虚拟化只有取得 VM 证据后才能加入，不把它们当作默认推断。
