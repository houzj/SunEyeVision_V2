CodeBuddy 重构与 VM 工具窗口链路对齐审计

冲突项

级别CodeBuddy 当前方向VM 链路对照立即调整
高第一批优先整体退出旧 Plugin.SDK，随后迁移工具。VM 窗口语义闭包仍需沿入口→AlgorithmTabRoot→ParamsTab→DataTemplate/GroupLinkItem→绑定→回调→释放迁移；旧消费者逐类型映射尚未完成。暂停不可逆删除和公共接口切换；先生成旧 SDK 类型/消费者/窗口链映射，按完整链迁移后再退场。
高“四层一一对应 VM”主要依据参考项目 Source 与当前工程引用。参考项目工程树不能代替 VM 原厂程序集、模板和运行链证据。把 VM 原件证据与 CodeBuddy 候选分栏；没有 VM 证据的分层只作为候选，不放行删除。
高新 Plugin.Contracts/Runtime/Wpf 与工具 Runtime/Wpf 已作为目标边界推进。目标边界尚未包含 VM 的 AlgorithmTabRoot、GroupLinkItem、202 类 DataTemplate 分发、外部槽和动态显隐闭包。先补公共参数模型、模板目录、父链、绑定/触发器和窗口宿主合同，再继续工具迁移。
中当前代码已出现 ThemeManager、PreviewBitmapCache、EnhancedBatchUpdateManager、CachedNodeConverters 等优化/平台设施。VM 是否有对应运行机制尚未确认；这些只能是我方候选实现。保留代码但禁止以 VM 行为名义验收；逐项加入证据开关和性能对照，未证实机制不得扩展。
中工作区包含大量文档删除、工程调整和源码改动，提交基线不再等于当前内容。VM 对照必须能回到明确源码/资源/提交。CodeBuddy 固定当前临时提交和改动清单；后续每批只允许一条完整功能链，中文提交并记录构建/回归。

需要立即调整的方案

  1. 将当前 R1“旧 SDK 退场”改为“旧 SDK 消费者闭包盘点与语义迁移”，删除动作延后到逐类型、逐模板、逐消费者验收通过。
  2. 把工具窗口重构入口固定为 VM 组装链：IToolPresentationFactory → ModuleParam/AlgorithmTabRoot → ParamsConfigControlBase → ParamsTabUserControl → ParamListView/ParamUserControl → UserTempConverter/DataTemplate → GroupLinkItem/Tab/底部命令/外部槽。
  3. 为每个当前窗口和模型记录创建、复用、切换、绑定、回调和释放所有者；没有同版本 VM 运行证据的复用、缓存、异步、虚拟化不写成事实。
  4. CodeBuddy 当前已修改源码先做只读映射：目标路径、现路径、消费者、依赖方向、证据等级、迁移/重构/删除动作；完成映射前不继续扩大公共 API。
  5. 验收顺序固定为：静态 VM 链核对→当前实现逐段映射→同节点 Tab/跨节点/关闭释放场景→构建→Release 宿主验证→再决定删除旧实现。
