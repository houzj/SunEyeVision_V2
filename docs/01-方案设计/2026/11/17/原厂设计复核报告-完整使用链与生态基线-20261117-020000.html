原厂设计复核报告：完整使用链与生态基线

日期：2026-11-17　参照：VisionMaster 4.4.0 Build20250516@1555331（28 个托管程序集约 39 万行 + 原生模块）
目的：早期迁移依赖语义逆向，结论未必准确。本批用反编译与运行时取证能力，复核自研是否存在框架层的严重偏离与设计错误，并回答“能否直接批量实现其余工具”。
判定口径：双轴——轴一与原厂对照（一致/结构偏离/语义偏离/原厂不合理/静态无法确认），轴二架构正确性（十判据）。原厂只作参照，不作为正确性标准。
边界：只做复核、不改产品代码；全局变量、相机、通信不在范围；验证用本地图像驱动。
证据：docs/collaboration/evidence/原厂设计复核-*.json（材料可信度、启动与方案、工具箱与节点、显示与状态栏、执行与工具栏、生态基线就绪度）。

一、结论摘要

必须修（阻断新工具）：执行引擎是纯 DAG“前驱全成功”模型，没有控制流语义，分支/条件类工具无法实现；组/嵌套类同样缺嵌套执行路径。
建议修（不阻断，影响体验/吞吐）：连续执行的轮次循环在 UI 层（原厂在原生 Server 内）；工具箱无热插拔；工具箱分类一次性构建；图像区状态栏缺“模块/算法耗时 + 缩放档位”。
保持（自研更正确，与原厂不同）：两阶段打开、托管序列化 + 原子写 + 目标身份校验、画布作为文档投影、声明式结果投影（RequiredOutputs 回传）、图编辑与配置编辑分历史、工具窗口用调试会话对象而非容器路由、像素信息与状态栏按职责拆分。
数据工具可直接批量做：图像处理/测量类工具的七项基线能力（契约、参数、结果声明、UI、执行、保存、准入）齐备，建议先做一次“非 Blob 类工具”端到端试点再全面铺开。

六、生态基线就绪度（能否批量做工具）

工具类结论缺口
图像处理/测量类可直接批量实现无（七项基线能力齐备）
分支/条件类阻断控制流语义（领域模型 + 引擎 + 端口 + 取消）
组/嵌套类阻断嵌套执行路径；Group 与子流程语义未定
脚本类部分就绪缺脚本工具 Runtime 与执行宿主、隔离策略
通信类范围外底座存在（Domain + Plugin.Editing.Wpf 通信服务），未核验
批量前建议：先用一个“非 Blob 类工具”（例如直线查找或阈值类）走一次端到端试点，验证契约是否真的够用。只用 Blob 一个样本不能证明基线完整。
