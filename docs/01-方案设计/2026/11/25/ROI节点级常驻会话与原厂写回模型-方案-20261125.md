# 方案报告：ROI 节点级常驻会话与原厂写回模型

> 遵循 rule-004（全局视角/复用优先）、rule-008（纯净/零兼容/报错优先）。
> 本方案已按用户 `question_answer` 明确的两个决策定范围：① 完整改造为节点级常驻 ROI 会话；② 参数写回改为原厂即时写、无草稿。

## 0. 用户功能性视角（必读）

### 改前用户看到什么
- 打开调试窗口时 ROI 在 viewbox 上可编辑；关闭后 ROI 层消失（投影被拆、`ROIList` 被置 null）。
- 不同工具节点的 ROI 输出逻辑表面不一致（工具各自产出过 `ResultRoiSnapshot`，已清理）。
- ROI 改动走"草稿→提交"，与用户从原厂看到的"拖动即生效"不同。

### 改后用户看到什么
- `ROIList` 从选中节点起就常驻绑在 viewbox 上；打开/关闭调试窗口只切 ROI 可见性，对象不销毁、不重建。
- 拖动/增删 ROI **立即**写入节点配置并进撤销历史；关闭窗口不再回滚已做的 ROI 改动。
- 所有工具节点走同一条系统层 ROI 链，工具只声明字段名与组元数据。

### 解决了哪些功能性问题
1. ROI 显示/生命周期由工具会话驱动 → 改为节点级常驻，与原厂对象模型一致。
2. 参数写回时机与本方草稿模型耦合 → 改为原厂即时写参数对象。
3. 结果层/交互层 ROI 曾混成一处 → 声明层统一，工具不再各自输出 ROI 快照。

### 依据
| 决策 | 依据 | 引用 |
|------|------|------|
| 常驻 ROIList | 原厂参数树 ROISelecter 常驻，结果视图绑定其 ROIList | `ModuleDisplayDecorator.cs:512`、`ModuleResultView.xaml:126/153` |
| 关窗只切可见性 | 原厂 Closed 回调只清引用与 `IsOpenParams`，再统一 `SetRoiVisible` | `ProcedureConfigControl.xaml.cs:830-843`、`ModuleResultView.xaml.cs:2250-2273` |
| 即时写参数 | 原厂 ROI 编辑经 `DataChangedCommand=RoiParamChange` 后 `SetValue()` | `ROISelecter.cs:2481/2483` |
| 工具只声明不改显示 | 原厂所有工具 ROI 都由 `ROISelecters` 汇出，无工具分支 | `ModuleDisplayDecorator.cs:512` |

## 1. 问题分析

- 本方 viewbox 的 `ROIList` 由 `NativeResultViewport.SetRoiRows` 写入、`RetireRoi` 清空，且 `NativeRoiSession.Dispose` 会 `Detach()` 所有投影。[来源-本方] `src/Plugin.Wpf/Presenters/Display/NativeResultViewport.RoiEditing.cs:67-92`、`src/Plugin.Wpf/Adapters/Regions/NativeRoiSession.cs:553-558`
- 会话由 `NativeRoiEditHost.AcquireFrame` 在参数页控件可见时才创建，随窗口关闭而 `RetireFrame()`。[来源-本方] `src/Plugin.Wpf/Presenters/Regions/NativeRoiEditHost.cs:103-155/372-391`、`src/Plugin.Wpf/Presenters/Parameters/NativeStandardBasicPage.cs:80-81`
- `RoiDocumentStore` 构造依赖 `DeclaredInputFieldsView`（WPF 控件），无法脱离参数页构造。[来源-本方] `src/Plugin.Wpf/Adapters/Regions/RoiDocumentStore.cs:30-62`
- 本方 `ToolConfiguration.Fields` 提供免开窗的字段读取入口。[来源-本方] `src/Plugin.Contracts/FieldSettings.cs:34-40`、`src/Domain/Workflows/WorkflowDefinition.cs:38`

## 2. Bug 模式分析

### 当前 bug
ROI 对象的生命周期绑在"参数窗口这张 UI"上，而不是"节点配置这个数据"上——窗口关了对象就没了，与原厂对象模型相反。

### 真因分类
设计缺陷（架构层：会话/投影与 UI 控件生命周期强耦合）。

### 同类潜伏点
| # | 位置 | 描述 | 优先级 |
|---|------|------|:------:|
| 1 | `NativeResultViewport.RoiEditing.cs:81-92` | 换帧/关窗都 `RetireRoi` 清 ROIList 并拆投影 | P0 |
| 2 | `NativeRoiSession.cs:553-558` | Dispose 强制 Detach 所有投影，投影不可跨会话 | P0 |
| 3 | `NativeRoiEditHost.cs:105/193` | 建会话门禁是参数页控件的 IsLoaded/IsVisible | P0 |
| 4 | `RoiDocumentStore.cs:30-62` | 文档读写依赖 WPF 控件，宿主无法常驻构造 | P1 |

### 治本点
把 ROI 文档与投影的**所有权**从 UI 会话移到节点级服务；窗口只借用/归还，不创建/销毁。

### 证据缺失警告
无（同类潜伏点已列出）。

## 3. 逆向原厂取证与阻碍判定

### 3.1 双链路证据
| 链路 | 证据 | 结论 |
|------|------|------|
| A 静态 | `ModuleDisplayDecorator.cs:512`、`ModuleResultView.xaml:126/153` | ROIList 从 ROISelecters 常驻汇出 |
| A 静态 | `ModuleResultView.xaml.cs:2250-2273`、`ProcedureConfigControl.xaml.cs:830-843` | 关窗只切 ROIVisible，不销毁对象 |
| A 静态 | `ROISelecter.cs:2481/2483` | 编辑即 SetValue 写参数 |
| B 实机 | 用户提供开/关调试窗口对比截图；agent-desktop CLI 不可用，实施后由用户人工验收 | 缺工具链路，UI 对齐以用户验收为准 |

### 3.2 阻碍/成本/接缝
| 项 | 判定 | 依据 | 处理 |
|---|---|---|---|
| **常驻会话的帧源（实施中新发现）** | **接缝（比预估大）** | `NativeRoiSession` 构造强制需要 `IReadOnlyImage`（[来源-本方] `src/Plugin.Wpf/Adapters/Regions/NativeRoiSession.cs:99-107`）；`NativeRoiEditHost` 借帧还依赖参数页控件 `IsLoaded/IsVisible`（`:105`）与 `IsLocalDrawing`（`:119`）。原厂 ROISelecter 常驻对象不依赖图像帧 | 本方不能"无帧常驻 ROI 会话"；需宿主在选中节点时借结果帧并长期持有，或为常驻投影提供不依赖会话的只读几何通道。此接缝在批次 3 暴露，需回方案设计细化后再实施 |
| 节点级常驻文档 | 同构可行（已完成批次 1） | 字段读取 API 齐备 | `IRoiInputAccess` + `NodeRoiDocumentAccess` 已落地 |
| 投影跨会话 | 接口缺失（接缝） | `NativeRoiProjection.Detach` 无重绑入口 | 契约扩展，明确为宿主接缝 |
| 即时写参数 | 接缝 | 本方草稿/撤销合同 | 新增"ROI 字段直写"通道，保留其它参数草稿 |
| 关窗不回滚 | 接缝 | 本方 Closed→Discard | 改为 ROI 常驻上下文，关窗只退役 UI |

### 3.3 决策沉淀
- 常驻 ROIList/只切可见性：同构迁移（原厂证据充分）。
- 投影跨会话与免开窗文档：必要接缝（本方无原厂参数树对象模型，需新契约承载）。
- 即时写 ROI 字段：同构语义 + 本方撤销栈适配（原厂 SetValue 语义，落到本方 DocumentSession）。

## 4. 方案对比

| 维度 | A 节点级常驻（推荐） | B 会话驱动+视觉一致 | C 结果层只读通道 |
|------|---------------------|---------------------|------------------|
| 实现 | 文档/投影/会话归属节点，窗口只借用 | 保持会话驱动，仅统一显隐 | 结果视图另绘只读 ROI |

## 5. 修改清单（分批）

### 批次 1：节点级 ROI 文档（脱离参数页控件）
- `src/Plugin.Wpf/Adapters/Regions/INativeRoiEditDocument.cs` — 无需改契约；新增纯数据实现 `NodeRoiDocument`。
- `src/UI/Services/Editing/NodeRoiDocument.cs`（新增）— 按 `RoiEditDeclaration` + `NodeDefinition.Configuration.Fields.Read` 实现文档读写，写经 `DocumentSession` 即时提交+撤销。
- `src/Plugin.Contracts/RuntimeEntry.cs:16-20` — `IToolDefinition.RoiEdit` 已声明；宿主按 ToolType 取声明。

### 批次 2：投影跨会话
- `src/Plugin.Wpf/Adapters/Regions/NativeRoiProjection.cs:15/86-89` — 增加 `AttachScope`/`DetachScope` 重绑入口；`Detach()` 只清 pending，不清 `PropertyChanged`（由节点级生命周期负责）。
- `src/Plugin.Wpf/Adapters/Regions/NativeRoiSession.cs:553-558` — `Dispose` 不 `Detach` 投影，只解除会话订阅；投影由节点级服务回收。

### 批次 3：宿主常驻
- `src/UI/Services/Editing/NodeRoiEditingService.cs`（新增）— 选中节点建立 `NodeRoiDocument` + 投影集合，绑 `ROIList`；节点切换/流程切换时退役。
- `src/Plugin.Wpf/Presenters/Display/NativeResultViewport.RoiEditing.cs:81-92` — `RetireRoi` 只切 `ROIVisible=false`，不清 `ROIList`、不拆投影。
- `src/Plugin.Wpf/Presenters/Regions/NativeRoiEditHost.cs:103-155/372-391` — 会话从节点级服务借出，窗口关闭只归还。

### 批次 4：即时写参数（修正：复用本方 draft 提交链）
- **修正说明**：原方案写"不经 `NodeConfigurationEditDraft`"与本方架构冲突——`NodeDefinition.Configuration` 是 Domain internal set（[来源-本方] `src/Domain/Workflows/WorkflowDefinition.cs:38`），UI 无法绕过 draft 直写；且撤销历史由 `DocumentSession` 的审批链产生。原厂 `SetValue()` 即时写在语义上等价于本方"每次 ROI 编辑立即触发一次 draft→proposal→commit"，不是绕过提交链。
- `src/UI/Services/Editing/NodeRoiDocument.cs` — ROI 写入时：`NodeConfigurationEditHost.BeginEdit(workflowId,nodeId)` → `draft.ApplyFields({roiFieldId:ConstantSetting(document)})` → `DocumentEditProposal.Prepare` → `session.ValidateEdit/CommitEdit`（同 `MainWindowRootWorkspace.cs:52-55`），立即生效且进撤销。
- `src/UI/Shell/Windows/MainWindowRuntimeEditing.cs:246` — ROI 已提交部分不随 `context.Discard()` 回滚；草稿仅承载未提交的非 ROI 参数。
- ROI 字段由 `NodeRoiDocument` 独占写入，参数页 draft 不得接管同一字段（避免双写）。

## 7. 防御机制
1. **契约测试**：`NodeRoiDocument` 读写 RoundTrip + 与 `FieldSettings.Read` 一致；ROI 身份（group,id）唯一。
2. **生命周期测试**：开窗→编辑→关窗→再开窗，投影实例保持同一引用；节点切换后旧投影被回收。
3. **Fail-Forward**：文档字段缺失/类型不符直接报错，不静默回退空 ROI。
4. **端到端冒烟**：用户打开 Blob/ContourMatch 调试窗口拖动 ROI → 关窗 → 立即看到配置已变 → 撤销恢复。

## 10. 风险评估
- **高风险**：改 `NativeRoiSession.Dispose` 与草稿提交链，可能波及所有 ROI 编辑与参数页。
  - 回退：按批次提交，每批独立构建+测试；批次 2 失败可回退到"会话驱动"基线。
- **中风险**：常驻文档与参数页草稿同时存在导致写冲突。
  - 规避：ROI 字段由 `NodeRoiDocument` 独占写入，草稿不接管 ROI 字段（显式字段归属）。
- **未确认**：原厂实机未被 agent-desktop 驱动，最终 UI 对齐以用户验收为准。
