# 端到端链路对照：节点 ROI → 执行 → 结果 → viewbox

> 基线：`1716fe79f` + 当前未提交改动。原厂证据为反编译静态源码（`docs/07-工具逆向/decompiled`）与配置清单；agent-desktop CLI 在本机不可用，**实机链路缺失**，原厂呈现结论以用户实机观察为准，文中凡只靠静态证据的结论都标注了证据级别。
> 本文按要求以**完整链路**为主线组织，不做局部模块罗列。

---

## 0. 结论先行

这条链在本方**是通的**，但"同一语义有三套并行实现 + 失败即整帧放弃"这两个结构性问题，导致所有可见差异：

1. **轮廓点有三条互不兼容的通道**：Blob 走全局 `CONTOURPOINTS`（`x/y/score/blob-index`），BlobLabels 走行内 `contour`，ContourMatch 走行内 `outline`（`x/y/match-index`），而 ContourMatch 另有全局 `output.outline-points` **格式与显示契约不匹配、无消费者**。
2. **失败策略是"整帧放弃"**：预算超限、帧/坐标不一致、形状校验失败，任一处抛错都会让**整帧图形（含检测区域）全部不画**；原厂是逐对象/逐缓冲扩容或降级。
3. **结果层触发模型是"发布快照驱动"**：调试快照优先、同身份短路、陈旧保持，三者在原厂不存在；原厂是"数据变化即 `UpdateModuleViewResultShow` 重建图像+形状"。

## 2. 分段对照

### S1 参数数据基座：ROI 存在哪里

**原厂设计**
- ROI 是参数树节点上的**活对象集合**：`ROISelecter.ROIList => NormalizeROIList`（`ROISelecter.cs:264`），注册于参数页 `Tab.cs:243-245`，节点生命周期内常驻。
- 结果视图直接绑定这份集合：`ModuleDisplayDecorator.ROIList => AlgorithmItems.ROISelecters.Select(p => p.ROIList)`（`ModuleDisplayDecorator.cs:512`）→ `ModuleResultView.xaml:126/142/153` 的 `imageView.ROIList`。
- 编辑即写参数：每个 ROI 挂 `DataChangedCommand = RoiParamChange`（`ROISelecter.cs:2481`），编辑后 `SetValue()`（`:2483`）。

**本方实现**
- ROI 是节点配置里的**不可变值**：`ToolConfiguration.Fields` 的 `ConstantSetting(RecordValue)`，声明在 `input.roi.local` 等字段。
- 工具声明编辑契约：`RoiEditDeclaration(DocumentFieldId, ImageFieldId, Groups, Inheritance, MaskInheritance, ItemNames)`（`src/Plugin.Contracts/Results/Presentation/RoiEditDeclaration.cs:40-65`），三工具均实现 `IToolDefinition.RoiEdit`（`ContourMatchTool.cs:18`、`BlobTool.cs:18`、`BlobLabelsTool.cs:17`）。
- 统一读写：`RoiDocumentStore.From(declaration, IRoiInputAccess)`（`RoiDocumentStore.cs:30-44`）；`Read` 只读文档字段、类型不符直接抛（`:126-137`）；`Write` 写回字段（`:68-69`）；提案落地含撤销栈（`:139-204`）。

**差异**
- **D-01（结构）**：原厂"同一对象被两处共享"，本方"同一份值被两处各自读取"。值相同则显示一致，但**对象身份、生命周期、变更通知**都没有对齐；这直接决定了后面"常驻但不可见"的补丁式实现。
- **D-02（写回粒度）**：原厂 `SetValue` 写参数对象；本方 `NodeRoiDocumentAccess.Write` 走 `BeginEdit → ApplyFields → DocumentEditProposal.Prepare → ValidateEdit → CommitEdit`（`src/UI/Services/Editing/NodeRoiDocument.cs:40-55`）。**语义对齐（即时生效 + 进撤销），但每次编辑都是一次完整文档提交**，比原厂重。
- **D-03（空值语义）**：原厂 `ROIList` 可为空集合且仍绑定；本方 `Read` 遇 `UnsetSetting` 返回 `Empty`（`RoiDocumentStore.cs:131`），但常驻服务在无声明/无继承时**整体 `Retire`**（`NodeRoiEditingService.cs:45-51`），即"没有 ROI 就完全不绑定"。

**影响面**：S2（编辑）、S3（窗口生命周期）、S7（ROI 层渲染）全部建立在这一段之上。
**依赖**：`IRoiInputAccess` 是 S1 唯一接缝（`src/Plugin.Wpf/Adapters/Regions/IRoiInputAccess.cs`），参数页与节点级服务都实现它。

### S2 参数 ROI 编辑入口（参数页）

**原厂设计**
- 参数页宿主 `ParamsConfigWithResultViewControl` 自带一个结果视图（`ParamsConfigWithResultViewControl.xaml.cs:155`），`Loaded` 时 `IsOpenParams=true; SetRoiVisible()`（`:238-241`），`Unloaded` 时置 false（`:244-247`）。
- 编辑会话即参数对象本身，无"会话"概念。

**本方实现**
- `NativeRoiEditHost` 建会话（`src/Plugin.Wpf/Presenters/Regions/NativeRoiEditHost.cs:103-155`）：**前置门禁是参数页控件的 `IsLoaded && IsVisible`**（`:105`），借帧 `_source.Borrow(...)`（`:111`），每组一个 `NativeRoiSession`（`:116-121`）。
- `NativeRoiSession` 构造**强制需要 `IReadOnlyImage`**（`NativeRoiSession.cs:99-107`），即没有图像就没有会话。
- 会话产出投影 `NativeRoiProjection`（`_scope` 指向会话），写入 `NativeRoiAttachment.OnChanged → SetRoiRows → viewport.ROIList`（`RoiEditing.cs:86-91`）。

**差异**
- **D-04（依赖倒置）**：原厂"数据常驻、图像只是背景"；本方"会话必须借到帧才存在"。这是 S3 所有补丁的根源。
- **D-05（门禁）**：本方编辑能力挂在**控件可见性**上；原厂挂在 `IsOpenParams` 这个数据状态上。

**影响面**：S3、S7；并解释"为什么必须造一个 `NodeRoiEditingService`"。
**依赖**：`NativeRoiFrameLease` / `BorrowRoiFrame`（`ResultWorkspacePresenter.RoiEditing.cs:13`）。

### S3 调试窗口生命周期与 ROI 可见性

**原厂设计（已逐行复核）**
- 打开：`ProcedureConfigControl.xaml.cs:739-767` → `IsOpenParams=true` + `moduleResultView.SetRoiVisible()`。
- `SetRoiVisible`（`ModuleResultView.xaml.cs:2250-2273`）：`IsOpenParams=true` → `ROIVisible = IsCanDrawROI`（当前显示图必须是模块输入图）；`else` → `imageView.ROIVisible=false; imageViewIn.ROIVisible=false`。
- 关闭：`ProcedureConfigControl.xaml.cs:830-843` → 清 `curTabControlBase`、`ROIPartUI.Tag=null`、`IsOpenParams=false`、`SetRoiVisible(false)`（`:849-858` 分发）。
- **ROI 数据不销毁**，`ROIList` 仍绑定；只是 `ROIVisible=false`。
- `ROIHitTestVisible` 默认 true（`ImageViewBox.xaml.cs:62`），`RoiEnableExecute(b) => ROIHitTestVisible=b`（`:2442-2445`），右键锁定/解锁只切命中测试（`ImageViewBox.xaml:51-56`）。

**本方实现**
- 关窗：`NativeRoiAttachment.Dispose`（`NativeRoiAttachment.cs:380-398`）→ `ReleaseFrame`（`SetRoiRows(空)` `:377`、`SetRoiShapes(空)` `:378`）→ `ROIHitTestVisible=false`（`:396`）→ `DetachRoi`（`:397`）。
- `DetachRoi → RetireRoi`（`RoiEditing.cs:98-111`）：清 attachment/layer → `RestoreResidentRoi(); ROIVisible=false; ROIHitTestVisible=false`（`:108-109`）。
- 常驻层：`NodeRoiEditingService.Sync` 建 `CreateResident` 投影并 `SetResidentRoiRows`（`NodeRoiEditingService.cs:70-80`）；`SetResidentRoiRows` **只绑 `ROIList`，不动 `ROIVisible`**（`RoiEditing.cs:64-69`）；构造时 `ROIVisible=false`（`NativeResultViewport.cs:66-70`）；**唯一置 true 的地方是 `BeginRoiEditing`**（`RoiEditing.cs:46-48`）。

**差异**
- **D-06（可见性语义已对齐，但常驻层是"死绑定"）**：`ROIVisible=false` 与原厂一致，但常驻投影永远等不到"开窗才可见"的原厂时机——它绑上就不可见，只有真开窗时被交互会话顶替。结论：**常驻层当前对用户不可见，等于没有生效**。
- **D-07（ROIList 清空时机）**：本方帧退役时 `ROIList = null`（`NativeResultViewport.cs:241`），原厂换图不清 `ROIList`。
- **D-08（可编辑性）**：常驻投影 `_scope == null`（`NativeRoiProjection.cs:41-46`），`DataChangedCommand.CanExecute == false`（`:131-136`），只读。原厂关窗后不可见，因此该差异**不可观测**；但若将来要让常驻层可见，这里必须先解决。

**影响面**：用户"关窗后 ROI 消失"的观感——**这是原厂行为**，非缺陷。
**依赖**：S2 的会话；`ROIVisible` 是唯一开关。

### S4 执行与输出契约

**原厂设计**：模块执行产生结果对象，结果对象同时承载算法输出与显示所需形状（`ShapeList` 由模块结果填充，`ModuleResultView.xaml.cs:1644-1651`、`:1754-1772`）。

**本方实现**
- 执行入口 `WorkflowExecutionEngine.cs:163` → 工具 `ExecuteAsync`。
- 输出契约分离：`IToolResultGeometryOutput.ResultGeometry`（`ResultGeometrySnapshot.cs:4-7`）、`IToolResultRecordOutput`、文本。
- 几何契约：`ResultGeometryRole` 只有 `Inspection/Mask/Annulus/ReferencePoint/RunPoint`（`ResultGeometrySnapshot.cs:8`）——**没有 Match/匹配框角色**；`Coverage` 为 `None/FullDomain/Explicit/Unavailable`（`:9`）；非 `Explicit` 不允许带名义形状（`:18`）；有形状必须 `ImageFrame`（`:58`）。
- ContourMatch 只产 **1 个 Inspection 光栅组 + 基准/运行点**（`ContourMatchResultGeometry.cs:17-27`）；`OutlineOnly=true`（`:68`）；预算 `MaximumContours=128`（`:13`）、`MaximumVertices=400_000`（`:14`）；超限 → **整组 `Unavailable`**（`:34-41/52/60/71-72`），不截断、不降采样。
- Blob：Inspection/Annulus/Mask 四分支（像素/全屏/位姿/名义，`BlobAlgorithm.cs:789-831`），光栅组 `outlineOnly:true`（`:972`）。
- BlobLabels：Inspection/Annulus/Mask 一律 `region ∩ domain` 光栅化（`BlobLabelsResultGeometry.cs:17-38/43/81`）。

**差异**
- **D-09（角色集缺失）**：匹配框不走几何组，走行值 `Descriptor.Rectangle`（`ContourMatchResultDisplay.cs:41` + `Display.cs:234-244`）。语义可达，但**几何契约无法表达"匹配框"**，导致 Blob 类工具若要画结果框只能借行值。
- **D-10（预算即失败）**：`MaximumVertices=400_000` 触发整组 `Unavailable`——**这是"检测区域不显示"的最高概率根因**：区域一复杂，整组直接消失，且只有一条汇总日志。
- **D-11（三工具粒度不一致）**：ContourMatch 只有 Inspection；Blob 有 Inspector/Annulus/Mask；BlobLabels 同 Blob 但几何全光栅。同一"检测区域"在不同工具走不同产出路径。

**影响面**：S6、S7、S8。
**依赖**：`ResultGeometrySnapshot` 的校验比原厂严格（见 S8）。

### S5 结果发布与触发

**原厂设计**：`UpdateModuleViewResultShow()`（`ModuleResultView.xaml.cs:1342-1373`）一次性 `ExternShapes.Clear()` + `ShapeList.Clear()` + `UpdateShapesWithCallBackData()` + `UpdateImageView()`；非运行态也调用（`:490-494`），换图/改选项即刷新（`:2216`）。**没有"调试快照 vs 正式结果"两套数据源**。

**本方实现**
- 捕获：`DocumentSession.RuntimeCapture.cs:137-138` → `RuntimeVariableAcceptance.cs:12/48/60/67` → `PostResultAvailable`（`:113`）→ `RuntimePublications.cs:32/38` → 事件 `RuntimeResultAvailable`（`:29`）。
- UI：`MainWindowDocumentHistory.cs:126-136` → 选中节点匹配才 `RefreshFormalPublishedResult()`（`:130`）。
- 发布对象：`ToolResultViews.FromSnapshot`（`ToolResultViews.cs:32`），`!snapshot.IsComplete` **直接抛**（`:36`），`ResultViewState` 由 `ExecutionStatus` 映射（`:40-46`）。
- 渲染触发：`RefreshFormalPublishedResult`（`MainWindowResultPublication.cs:138-169`）：
  - `:144` **调试快照优先** → `PresentSnapshot(debug)`；
  - `:145` retained 调试快照次之；
  - `:154-155` **同身份短路**（不 retire 不重建）；
  - `:160` 正式快照呈现实保留租约；
  - `:165` reader 为空时**保持陈旧结果不动**。

**差异**
- **D-12（两套数据源）**：原厂只有模块结果一条源；本方有"正式发布 / 调试快照 / retained 快照"三条优先级。调试窗口开合会改变显示数据源，这是**"打开和关闭调试窗口对比结果不一致"的结构性原因**（用户最初的现象）。
- **D-13（同身份短路）**：原厂按数据变化重建；本方按 `Identity` 相等直接 return（`:154-155`），**同一身份下的几何/显示配置变化不会触发重画**——除非另有路径显式 `QueueResultDisplay`。
- **D-14（陈旧保持）**：`:165` 执行域被编辑退役后 reader 为空，本方保持上一轮结果；原厂由 `SetRoiVisible`/`UpdateROI` 语义表达，不靠"保持"。

**影响面**：S6 的所有时序问题；也解释"运行后要重新选一下才刷新"。
**依赖**：`ResultDisplayState`/`CaptureCurrentResultDisplay`（`MainWindowResultDisplay.cs:12/87`）。

### S7 视口落地与渲染

**原厂设计**
- `shapeList` 为 `ObservableCollection<object>`（`RenderControlBase.xaml.cs:64/234`），从 `shapeStore` 合并（`:1029-1094`），`IMultiPoint` 合并为单个 `MultiPoint`（`:1087`），`GetDisplayList → DrawShapesInShapeBuffer`（`:1134-1163`）。
- `ShapeItemsPage` 监听集合变化重画（`ShapeItemsPage.cs:162-172`），`IMultiPoint → MultiPointShape`（`:174-197`），受 `ShapeRenderingMaxNumber` 限制（`:176`）。
- 点位缓冲按 100000 递增扩容（`MultiPointShape.cs:86-88/482-505`），**不抛错**。

**本方实现**
- `ShapeList` 唯一写入点：`NativeResultViewport.Shapes.cs:136`，前置 `ClearExternShapes()`（`:135`），清空在 `RetireShapes`（`:161`）。
- 形状生成：`NativeShapeProjection.Geometry`（`NativeShapeProjection.cs:50-94`）要求 `Image/Pixel` 且 `SourceFrame==receipt.Frame && Geometry.Frame==receipt.Coordinates`（`:54-63`）；`Outlines`（`Outlines.cs:12-39`）写每点 16 字节 `x,y,Passed?0f:2f,ResultIndex`（`:29-34`）；`MergePointBatches`（`:43`）。
- 预算：`ShapeBudget = min(10000, ShapeRenderingMaxNumber)`、`MaximumPolygonVertices = 1_000_000`（`Shapes.cs:21/36`）；超限 **抛**（`Outlines.cs:15/24`、`NativeShapeProjection.cs:56/91/98`）。
- ROI 层：`ROIList`（`SetRoiRows`）+ `ROIVisible` + `ROIHitTestVisible`；常驻/会话单槽仲裁（`RoiEditing.cs:64-111`）。

**差异**
- **D-18（预算策略）**：原厂扩容/逐对象限制；本方**抛异常 → 整帧不画**（`Shapes.cs:42`、`Outlines.cs:15/24`）。这是"某些图整帧没有图形"的直接原因。

## 5.5 轮廓点的系统类型同构（原厂生态链 vs 本方）

### 原厂生态链（5 层，工具不参与显示）

| 层 | 原厂实现 | 证据 |
|---|---|---|
| ① 数据 | 工具输出 chunk：`ContourInfo/ContourNum`、`MatchOutline/MatchOutlineNum` | `BlobFindResult.cs:152/157`、`FastFeatureMatchResult.cs:67/72` |
| ② 接口声明 | 每个实现 `IOutlinePoint/IMicroPoint/IRectangle`，渲染控件用 `[ShapeDisplayForInterfaceType(typeof(IMultiPoint))]` | `MultiPointShape.cs:18` |
| ③ 显示对象 | 系统类型 `outlinepoint`：`"outlinepoint" => new Outlinepoint()`，写 `OutLineInfo` 与 ok/ng 颜色 | `ObjectBase.cs:599`、`Object.cs:714-719`、`Object.cs:944-948` |
| ④ 统一适配 | `DrawShapeHelper.DrawShapes` 按接口类型分派，**不按工具名分支** | `DrawShapeHelper.cs:33-109` |
| ⑤ 统一渲染 | `IMultiPoint → MultiPointShape`；逐点 score 0/1/2 → 绿/黄/红；缓冲 100000 递增 | `ShapeItemsPage.cs:174-196`、`MultiPointShape.cs:374-376`、`:86-88` |

**工具层职责**：只输出 chunk 数据；`OutLineEnable` / `BolbOutLineEnable` 只是透传给 C++ 模块的参数，C# 侧无读取点（`FastFeatureMatchParam.cs:398-410`、`BlobFindParam.cs:632-644`）。**是否出形状由系统显示项 `IsDisplay` 决定**（`ModuleResultView.xaml.cs:953`、`ObjectBase.cs:234-253`）。

### 本方旧实现的问题

`ResultDisplayDescriptor.GlobalOutline(ResultOutlinePayload{IndexField, ScoreField})` 让**工具声明数据形态**；Blob/ContourMatch 走全局通道，BlobLabels/MarkFind 走行内通道 —— 同一语义四套声明，违背“系统类型 + 工具只消费”。

### 本方同构后（已实施）

| 层 | 本方实现 |
|---|---|
| ① 系统类型 | `ResultOutlineSet`：`SourceFrame + Points + ResultIndices + Scores`，统一校验/预算（`src/Plugin.Contracts/Results/Presentation/ResultOutlineSet.cs`） |
| ② 工具定义声明 | `IToolResultOutlineDeclaration.OutlinePortId`（对应原厂 IO 名映射）；四个工具各自声明端口 |
| ③ 工具输出数据 | `IToolResultOutlineOutput.ResultOutline`；四个工具从自身 measurements 构建同一点集 |
| ④ 宿主统一请求 | `ExecutionNodeSnapshot` 按声明请求该输出端口，不再由 Descriptor 声明 |
| ⑤ 统一装配 | `ResultDisplayState.Outline` → `ResultWorkspacePresenter.GroupOutline` 按结果序号分组 → `NativeOutlineOverlay.Scores` |
| ⑥ 统一渲染 | `NativeShapeProjection.Outlines` 逐点写 0/1/2 标记，交由原生多点图形三色渲染 |

**显示合同回归纯净**：`ResultDisplayDescriptor` 移除 `Outline` / `GlobalOutline` / `RequiredOutputs`，不再承载任何轮廓点通道信息；`ResultDisplayAppearance.Outline` 只保留显示项语义（可见性 + OK/NG 颜色），等价原厂 `outlinepoint` 的 `IsDisplay/okcolor/ngcolor`。

### 剩余差异

- 逐点中间态（score=1 → 黄色）通道已就绪，但 Blob/ContourMatch/BlobLabels/MarkFind 的算法侧目前只有整条/整目标判定，统一写 0/2；**不伪造 1**。
- 原厂 `outlinepoint` 的 `OutLineInfo` 走 C++ chunk，本方走托管 `ResultOutlineSet`；这是宿主接缝，不是语义差异。
