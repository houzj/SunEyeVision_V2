## 一、T-AN6 平台扩展点：`ToolPanelOverride` 的合法范围

### 1.1 原厂事实

**模板合并机制**（`XmlUi/Apps.XmlUI/ParamUserControl.xaml.cs:59-72`）：
- 触发：`Content` 变化且非空（`:62-63`）；
- 取字典：`Content.GetType().Assembly`（`:64`），白名单跳过 `Apps.XmlParser`、`WindowsBase` 与已登记程序集；
- 每程序集**进程内只合并一次且永不撤销**（`:67`）；
- 加载路径固定无配置：`/{assemblyName};component/DataTemplate/ParamUserControlDataTemplate.xaml`（`:68`）；
- 挂到静态基字典的 `MergedDictionaries`（`:69`）。

**查找顺序的关键事实**（`UserTempConverter.cs:35`）：
```csharp
return (!ResourceDictionary.Contains(key)) ? ResourceDictionary["Default"] as DataTemplate : ResourceDictionary[key] as DataTemplate;
```
WPF 语义是“字典自身条目优先于 MergedDictionaries”，而平台 202 个内置模板就在自身条目里 —— **原厂机制下工具其实覆盖不了平台内置 key，只能新增**。

**可替换粒度**：

| 粒度 | 可否 | 证据 |
|---|---|---|
| 单个参数控件（一行） | 可，且是唯一正式开放粒度 | `FormatModuleControl/datatemplate/paramusercontroldatatemplate.xaml:3-5`；行外壳仍归平台（`globalresources.xaml:21-24/76-80`、`LeftRightControl.xaml:11-15`） |
| 一个 Category | 不可（无钩子） | Category 只是 `GroupName` 分组（`ParamListView.xaml:15-17`） |
| 一个 Tab | 可，但只能走平台自带 `TabType=Panal` | `Tab.cs:26/54`、`ParamsTabUserControl.xaml:19-23/58-60` |
| 整页 | 不可（面板内）；只能另开窗口 | `TabWinBase.cs:12/64`、`ParamsTabControl4Format.xaml.cs:14` |

**9 类复合控件全部是行级替换**（`progress.md:205-221`）：`c-threshold`/`c-imgsrc`/`c-rangecfg`/`c-timecfg`/`c-model`/`c-filecfg`/`c-color` 七个族覆盖 9 个类型，无一改变页面骨架。

**8 个“XML 无控件声明”的工具**（`progress.md:137`）：`calculatormodule`、`imvscolorimagegenerationmodu`、`dataassemblemodule`、`globaltriggermodule`、`globalvariablemodule`、`lightcontrol`、`localvariablemodule`、`procedurecomm`。其中 `ParamsConfigControlBase.xaml.cs:434-452` 只负责加载 `*Control.dll`，**不创建界面**；这 8 个的界面全在自带窗口/UserControl 里，没有一个靠平台 `ParamsTabUserControl` 出界面 —— 反证平台对页结构的所有权。

### 1.2 判定（定稿）

`ToolPanelOverride` 的合法范围：

| 项 | 定稿 |
|---|---|
| **允许** | **行级**：一个 `DisplayType key` → 一个模板；保留行外壳（左标签、`Enable`、`CustomVisible`、`GroupName`）与值通道 |
| **允许（需登记）** | 页级仅两种形态：① 等价 `TabType=Panal` 的单页签（页签栏/底栏仍归平台）；② 工具独立窗口（等价 `TabWinBase`） |
| **禁止** | 替换参数面板骨架（页签结构/分类/行容器/值读写通道） |
| **覆盖优先级** | **不得模仿**原厂“合并字典”（WPF 自身条目优先，实际覆盖不了内置 key）。若需覆盖，必须我方实现**显式 override 表**并单独测试 |

## 二、T-AN1 节点 IO 树与动态输出：`ToolInputSet` 的定稿与缺口

### 2.1 原厂事实

**IO 是运行时动态图，不是静态声明**：
- 树结构 = 组合节点（`TypeName` 取 `Combination.Style`，17 种）+ 叶节点；判定分派在 `DynamicIOContainer.cs:248-269`，组合递归在 `Combination.cs:96-117`；
- 组合声明 `<Combination Style=IMAGE/ROIBOX/POINT>` + `<Filter Name/ValueType/IsForce/CanSubscribe/...>`（`FilterBase.cs:21-67`，共 15 个标志位）；
- **动态端口由操作创建**：`SetResultIOToModuleOperation.cs:200-217` 在用户选中来源时 `new DynamicVmIO` 并 `Outputs.Add`，新建即 `Visible=false / VisibleInResultTree=false / CustomVisibleA=false`（`:207-210`）；订阅端只认 `CanSubscribeA && Visible && !IsPrivate`（`VmModuleExtern.cs:1069-1071`）；
- 端口身份 = `(Root.ID, Name)` + 模块路径；**改名会全方案扫描重写订阅串**（`DynamicIO.cs:680-733`）；
- 端口类型变化会**重建子树**（`DynamicIO.cs:143-176/497-510/584-591`）；
- 上限：600 个 IO、32 字符名（`DynamicIO.cs:23-25/352-362`）。

**边 ≠ 订阅**：
- 图边 `ModuleCommonConnect` 只含 `<Front Index><Following Index>`，**不含端口信息**（`VM方案格式…html:106/120`）；
- 端口级数据订阅另存 `ModuleSubscribe`（同上 `:107-110`）。

**自动连线规则无法证明**：`AutoLinkData` 实现体在未入库的 `VM.Core.dll`（`decompiled/README.md:158`）。可确证的只有：先加 `NextModules` 再自动订阅；目标是流程时不自动订阅；可显式关闭（`VmModuleBaseDecorator.cs:1104-1118`、`DecoratorBase.cs:169-172/252-255`）。

### 2.2 本方现状

| 概念 | 本方 | 判断 |
|---|---|---|
| 端口 | `Port(Id, Type, Required, Nullable, Storage, EditModes, DefaultPresence, Choices)`（`Values.cs:6-7`）**扁平** | 无父子/路径寻址 |
| 组合模板 | `ToolSchema` 有 `RoiGroups`/`AssistGroups`/`ExternalInputs`（`Values.cs:15-28`） | 部分对应 |
| 控制流输出 | `ControlOutput(Id, DisplayName)` + `ToolOutcome.SelectedBranches`（`Values.cs:8-12`） | 对应原厂分支，**不是数据端口** |
| 动态参数端口 | **已有** `IToolDynamicSettings.ExpandSettings/ExpandDefaults`（`ToolSettingsFields.cs:26-32`），4 处使用（`SolutionDocumentReader.cs:80-92`、`DocumentSession.NodeCreation.cs:35-47`、`AdmittedToolConfiguration.cs:142-170/228-233`） | 对应原厂 `IDynamicChild` ✓ |
| 动态**输出**端口 | **无** | ✗ 缺口 |
| 连线 | `ConnectionDefinition`（节点级 + 端口字符串）+ `ExecutionConnectionPolicy`（有向唯一/防环） | 图边对应，端口语义弱 |
| 自动连线 | 无证据 | ✗ 缺口（规则未知，暂不追） |

### 2.3 判定（定稿）

1. **`ToolInputSet` 保留但降级为“组合模板标识”**，不再假装能穷举所有输入形态：
   ```csharp
   // 组合模板：编译器按模板展开为标准端口集
   public enum ToolInputTemplate { Image, ImageRoi, ImageRoiFixture, ImageRoiMask, None }
   ```
   端口展开由 `ManifestCompiler` 负责，manifest 不手写端口。

2. **必须新增动态输出契约**（对应原厂 `DynamicVmIO`）：
   ```csharp
   public interface IToolDynamicOutputs
   {
       /// 按当前配置展开输出端口；无变化返回 null。
       IReadOnlyList<Port>? ExpandOutputs(FieldSettings current);
       /// 新增端口的默认值。
       IReadOnlyDictionary<string, ParameterSetting> ExpandOutputDefaults(IReadOnlyList<Port> expanded, FieldSettings current);
   }
   ```
   **理由**：原厂动态端口是输出侧的（`Outputs.Add`），而我方 `IToolDynamicSettings` 只展开 `SettingsSchema`。若不补，"输出端口数随参数变化"的工具（如多模板匹配、可变分支输出）无法表达。

3. **端口身份需支持“实例改名不破引用”**：原厂靠 `IOInfo SrcName→DstName` 迁移表（`html:163-179`）。本方若后续允许端口改名，必须在持久化层留映射，不能只靠 Id 稳定。

4. **自动连线不纳入本期**：规则无源码证据，强行实现会造“看起来像但不是原厂”的行为。登记为未知项。

## 三、T-AN2 节点参数订阅：参数声明需携带“可绑定档位”

### 3.1 原厂事实

**五档绑定**（`AlgorithmTabRoot.cs:1442-1548`）：

| 档 | 判定 | 调用 |
|---|---|---|
| 空/清空 | `value` 空（`:1452-1455`） | `DelModuleParamBinding` |
| ① 常量 | `IsNumber/IsConst` 且非 `TRIGGER_STRING[[]]`（`:1469-1472`） | `SUBSCRIBE_VAR_CONSTANT` |
| ② 全局（外部通讯） | `text == ExternIO.Name` 或 `+[]`（`:1473-1476`） | `SUBSCRIBE_VAR_GLOBAL` |
| ③ 变量 + 常量索引 | `[n]` 后是数字（`:1533-1536`） | `…INDEX_CONSTANT` |
| ④ 变量 + 变量索引 | `[n]` 内是带 `.` 的路径（`:1523-1532`） | `…INDEX_VARIABLE` |
| ⑤ 变量 + 全量 | 其它（`:1537-1541`） | `…INDEX_ALL` |

**订阅与绑定是两条独立通道**：
- 结果数据订阅（端口→端口）走 `VmIO.RelateIO`（`SetResultIOToModuleOperation.cs:253-260`）；
- 参数取值（参数←上游/全局/常量）走 `ParamSubManager.SetModuleParamBinding`，**不进 IO 图**；
- 两者互不自动生成对方（`B08前驱连线与订阅关系来源-20261031.md:13-15`）。

**绑定与显隐共享同一 Trigger→Setter 管线**，顺序由 XML 声明顺序决定，**没有全局固定次序**（`Trigger.cs:44-55/77-112`、`DynamicIO.cs:264-268`）。加载期顺序：先 Initer 回填绑定，再按值触发显隐（`ParamsConfigControlBase.xaml.cs:251`、`Tab.cs:235-256`、`NameValueItem.cs:650-656`）。

### 3.2 本方现状

- `BindingSelection`：`All` / `AtConstant(index)` / `AtField(reference)` / `AtVariable(reference)`（`BindingPlans.cs:3-31`）；
- `OutputReference`（节点 + 端口 + 成员路径 + 选择）、`VariableReference`（SolutionId + VariableId + 选择）；
- `BindingPlan`（编译后指令 + `BindingCompatibility` + 依赖集）；
- **未见“外部通讯全局量”作为参数来源的等价档位**（原厂 ② `SUBSCRIBE_VAR_GLOBAL`）。

### 3.3 判定（定稿）

`ToolParameterDeclaration` 必须增加**可绑定档位声明**，而不是让所有参数默认可绑所有来源：

```csharp
[Flags]
public enum ParameterBindingKinds
{
    None = 0,
    Constant = 1,          // 常量
    NodeOutput = 2,        // 上游节点输出（原厂 VARIABLE + INDEX_*）
    Variable = 4,          // 方案变量
    ExternalGlobal = 8,    // 外部通讯全局量（原厂 SUBSCRIBE_VAR_GLOBAL）
    DisplayExpression = 16 // 显示表达式（仅显示字段）
}

public sealed record ToolParameterDeclaration(
    ..., ParameterBindingKinds Bindable = ParameterBindingKinds.Constant);
```

**理由**：原厂由 XML `CanSubscribe`/`AccessMode` 逐参数控制可订阅性；manifest 若不表达，编译器只能全部放开或全部禁止，两者都不对。

**顺序约束进编译器**：`VisibleWhen` 的求值必须发生在绑定回填**之后**（原厂 Initer 先于 Trigger 显隐），这条要写成 `ManifestCompiler` 的固定顺序并有测试。
