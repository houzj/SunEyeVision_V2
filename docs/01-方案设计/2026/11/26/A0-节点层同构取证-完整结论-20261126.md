> 覆盖 T-AN1..T-AN10 全部十项。性质：只读取证 + 设计定稿，**未改任何代码**。

## 0. 十项判定总表

| ID | 主题 | 核心判定 | 改动 manifest？ | 新发现的实现缺口 |
|---|---|---|---|---|
| AN1 | 节点 IO 树与动态输出 | 原厂 IO 是运行时动态图；静态声明只承担模板 | **是**（`ToolInputTemplate` + `IToolDynamicOutputs`） | 输出侧无动态端口契约 |
| AN2 | 节点参数订阅 | 五档绑定、订阅与绑定两条独立通道、绑定与显隐共享 Setter 管线 | **是**（`ParameterBindingKinds` + 固定求值顺序） | 无 `ExternalGlobal` 等价档位 |
| AN3 | 节点身份与生命周期 | 原厂无统一序号字段；撤销是整方案 Import 重放 | **否** | 无（本方模型更细） |
| AN4 | 节点状态机 | 原厂无节点状态机类型，只有三通道 | **否** | **`ResultViewState` 缺 `Skipped`，映射会抛异常** |
| AN5 | 节点显示选择/叠加 | 显示项 = 工具声明默认 + 节点实例值；导航单独存节点 | **否**（已分家） | 无 |
| AN6 | 平台扩展点 | 只有行级替换；页级只能 Panal 页签/独立窗口 | **是**（`ToolPanelOverride` 行级） | 无模板覆盖优先级机制 |
| AN7 | 子流程/分支节点 | 原厂无 `SubroutineId`；分支靠结果字段 | **否** | **新 Execution 引擎不感知 Subroutine（最大断层）** |
| AN8 | 画布装饰器 | 装饰器全通用 + 平台类型名特例；工具只给 2 张 png | **否**（已有 IconKey/NodeDisplayType） | 7 项能力缺失（连接点/自动连线/参数剪贴板等） |
| AN9 | 诊断与错误码 | 码表是平台资源，工具只返码 | **否** | 无统一码表；两套诊断类型未统一 |
| AN10 | 方案版本迁移 | 迁移由平台独立工具做；工具只给字段改名对+默认值 | **否** | 版本只用于硬拒绝；无字段改名表 |

**结论**：manifest 只需吸收 **AN1 / AN2 / AN6** 三项；其余七项属于节点层与平台层职责，不进 manifest，但暴露了 5 处真实实现缺口（AN4/AN7/AN8/AN9/AN10）。

## 1. T-AN1 节点 IO 树与动态输出

### 原厂（A 级）
- IO 树 = 组合节点（17 种 `Combination.Style`）+ 叶节点，判定分派 `DynamicIOContainer.cs:248-269`；组合可递归 `Combination.cs:96-117`。
- 动态端口由操作创建：`SetResultIOToModuleOperation.cs:200-217`，新建即 `Visible=false/VisibleInResultTree=false/CustomVisibleA=false`（`:207-210`）；订阅端只认 `CanSubscribeA && Visible && !IsPrivate`（`VmModuleExtern.cs:1069-1071`）。
- 端口身份 = `(Root.ID, Name)`；改名全方案重写订阅串（`DynamicIO.cs:680-733`）；类型变化重建子树（`:143-176/497-510/584-591`）；上限 600 IO / 32 字符（`:23-25/352-362`）。
- **图边 ≠ 订阅**：`ModuleCommonConnect` 只含 `<Front Index><Following Index>`（`VM方案格式…html:106/120`）。

### 本方
- `Port` 扁平（`Values.cs:6-7`），无父子/路径；
- `ControlOutput` 只表达控制流分支（`:8-12`），非数据端口；
- **已有** `IToolDynamicSettings`（对应 `IDynamicChild`）但只展开**设置**端口（`ToolSettingsFields.cs:26-32`）。

### 判定
1. `ToolInputTemplate`（组合模板，编译器展开端口）；
2. **新增 `IToolDynamicOutputs`** 补输出侧；
3. 端口改名需持久化映射表（原厂 `IOInfo SrcName→DstName`，`html:163-179`）；
4. 自动连线规则不可证（`VM.Core`），**不纳入本期**。

## 4. T-AN4 节点状态机

### 原厂（A 级）
- **没有节点状态机类型**，只有三通道互不聚合：
  - (a) 参数项态 `ItemState`（`GetParamErro` 黄 / `SetParamErro` 红，`ItemCheckConverter.cs:16-20`）；
  - (b) 节点可用态 `IsForbidden`/`IsLoadFailed`/`ConfigAvailable`（`VmModuleDecorator.cs:350-359`、`diagramitemtemplate.xaml:836-1042`）；
  - (c) 运行结果态 `(ModuStatus)` IO，取值 `RenderSatus`：`NG=0/OK=1/ALL=2`（`RenderControlBase.xaml.cs:2360-2371`）。
- 超时不在状态枚举内，只有错误码常量（`NameValueItem.cs:87-89`，`IMVS_E_MODU_OVERTIME=0xE0000E08`）。
- 结果到达靠事件 `AsyncModuleResultCallBackArrived`（`ModuleDisplayDecorator.cs:1197-1201`）。
- **无"工具声明前置条件"契约**；门禁由宿主强制（`CheckRunning` `DecoratorBase.cs:68-76`）。

### 本方（A 级）
- `ExecutionStatus` 8 值（`ExecutionStatus.cs:3-45`）；
- `ResultViewState` 8 值但**缺 `Skipped`**（`ResultPublication.cs:7-10`）；
- 唯一映射点 `ToolResultViews.cs:40-46` 的 switch **未含 `Skipped`**，落到 `_ => throw new ArgumentOutOfRangeException`；
- 而 `DocumentCanvasProjection.cs:196-197` 明确处理了 `Status == Skipped` 的快照。

### 判定
1. **发现 P0 缺陷**：`Skipped` 快照进入 `FromSnapshot` 会抛异常。需在映射前过滤或补齐 `ResultViewState.Skipped`。
2. 工具**不需要**声明可执行前置条件（原厂由宿主强制）；本方已有 `HasUnconfiguredRequiredInputs`/`CheckWorkflowReadiness` 等价物。
3. 本方 8 值状态是原厂的扩展，属合理增强，不要求回退。

## 7. T-AN7 子流程/分支节点

### 原厂（B 级）
- **没有 `SubroutineId` 等价字段**。子流程表达 = 模块类型 + 模块目录/文件（`ModuleDir`/`ModuleFilePath`/`.prcx`）+ 容器 `Children`（`VmModuleExtern.cs:855-876/903-916`，`DecoratorBase.cs:365-437`）。
- `IVmProcedure` 本身也是 `IVmModule`（`VmProcedureDecorator.cs:69/99/165`）；流程顶层"上游集"为空（`ModuleDisplayDecorator.cs:1346-1356`）。
- 分支：**无源码级证据**。`ifbranchmodule` 材料自述 inventory-only、8/9 步 inferred；可确证旁证是"边不含端口语义，分支由源工具自己的决定解析"（本方注释 `ExecutionWorkflowSnapshot.cs:115-118` 亦同）。

### 本方（A 级）
- `WorkflowDefinition.IsSubroutine` + `NodeDefinition.SubroutineId`（`WorkflowDefinition.cs:22/69`）；唯一写入点 `AddGroupNodeCommand.cs:13-23`（强校验独占流程，同时写节点与参数）；
- 执行入口 `ISubWorkflowExecutor`（`ISubWorkflowExecutor.cs:10-14`），实现 `SubroutineParameters.cs:15/77-81`，委托 `[JsonIgnore]` 不持久化；
- **`src/Execution` 内 "Subroutine" 零命中**；`ExecutionPlan.GetWorkflow` 只接受 `!IsSubroutine` 的流程（`ExecutionPlan.cs:29-31`）。

### 判定
1. **最大同构缺口**：子流程展开仍由旧链（宿主注入委托）完成，新 Execution 引擎不感知。新旧引擎并存会导致"同一方案在两条链上行为不一致"。
2. manifest **不需要**声明子流程能力（`Subroutine` 是平台内置工具类型，不是普通工具）。
3. 分支能力：`ControlOutput` + `SelectedBranches` 是自建，原厂无源码证据；**保持现状，不宣称同构**。

## 9. T-AN9 诊断与错误码

### 原厂（A/B 级）
- 反编译产物中 `IMVS_E_MODU_*` 常量仅 2 个（`NameValueItem.cs:87/89`）；**码表本体不在 decompiled**；文案表是平台本地化资源（`zh-cn.xaml:9745`，按 `符号名:英文` 做 key）。

- 判定：错误码是**平台契约**，工具只返回 code，不持有文案。

### 本方（A 级）
- `Diagnostic(Code, Message, FieldId)` + `NativeErrorCode`（`ToolContracts.cs:29-33`）；
- **无统一码表**：码值就地 kebab-case 字符串，分域前缀有事实约定但无注册处；

- `tests/` 有 76 个文件触及 `Diagnostic`，但 **`*Architecture*.cs` 0 命中**（无架构守卫）。

### 判定

- 建议（非现状）：把 `Diagnostic.Code` 前缀/形态纳入契约测试，或 manifest 声明"诊断码命名空间"；统一两套诊断类型。

## 10. T-AN10 方案版本迁移

### 原厂（A 级）
- `SoftVersion` 是**产品版本字符串**（`<Version CurrentVersion="V4.4.0"/>`），不是整数 schema 号（`VM方案格式…html:47/115`）。
- 迁移链：`FrontendUI Upgrade → DynamicIO Upgrade → GlobalVar Upgrade → CustomizedHandleModule Upgrade → SaveAs`（`:143-147`），**另存新文件、原文件保留**（`:141/148`），缺模块只计数继续（`:142`）。
- 迁移由**独立可执行件** `CompatibleTool.exe` 做（`:151`），不在主程序内。
- 工具义务仅两项：① 在 `CompatibleTool.xml` 贡献字段改名对（`IOInfo SrcName→DstName`，`:163-179`）；② 新参数必须带默认值供补齐。

### 本方（A 级）
- `SolutionFormatPolicy.cs:9-26`：`Current=5`，`ReadVersion` 只返回 `Current`（**不解析真实版本**），`ValidateReadable` 版本≠5 **直接抛** —— **无任何迁移分支**；
- 未知字段：`ignoreUnknown` 只为动态子项放行（`SolutionDocumentReader.cs:78/89`）；根级 `AdditionalData` 原样保留作前向兼容口袋；
- 新增参数补默认值：`SolutionDocumentReader.cs:93-97` + `FrozenToolDeclarations.cs:18-24`（仅 `UseDeclaredDefault` 可恢复）+ `IToolDynamicSettings`。

### 判定
- manifest **不需要**携带版本/迁移信息；迁移责任方 = **平台**；

- 工具唯一义务：新增参数必须声明 `default` 且 `DefaultPresence=UseDeclaredDefault`（否则旧方案加载即缺字段）。
