# 原厂参数声明六项取证（字段改名 / 显隐 / 成对 / 提示 / 分类 / ROI 组）

> 目的：在把 PixelCount 迁移到 ToolManifest 之前，先看清原厂 XML 里这 6 项到底怎么写、谁读、影响什么。
> 性质：只读取证，未改代码。
> 主件：`docs/evidence/original-release-units/BlobAnalysis/IMVSBlobFindModuAlgorithmTab.xml`、`.../ImageSource/ImageSourceModuleAlgorithmTab.xml`、`docs/07-工具逆向/decompiled/Groups/Group.xml`。

## 1. 字段改名（参数身份）

### 原厂写法

```xml
<Integer Name="LowThreshold">
  <DisplayName>Low Threshold</DisplayName>
  <AlgorithmIndex>0x0603</AlgorithmIndex>
  <MinValue>0x0</MinValue><MaxValue>0xff</MaxValue><IncValue>0x1</IncValue>
  <CustomVisible>False</CustomVisible>
</Integer>
```

### 三个概念必须分开

| 概念 | 原厂载体 | 用途 |
|---|---|---|
| 存储/算法键 | `Name`（`NameValueItem.cs:49-50`） | 写方案、下发给算法都用它（`userStringData[ComName]`、`ParamsDictionary[ComName]`） |
| 界面文案 | `DisplayName`（`:239-257`） | 先当本地化 key 查表，查不到按原文显示；同一份 XML 里 key 与英文混用 |
| 可绑定类型 | `ComType`（`ValueBase.cs:90/100-105`） | 只用于筛选"能绑哪些变量"，**不参与存储** |

### C# 字段名与 XML 名不一致

`BlobFindParam.cs:1955-1970`：

```csharp
inputImage       = new InputItem(this, ..., new[]{"InImage","InImageWidth","InImageHeight","InImagePixelFormat"});
ModuRoiManager   = new BlobFindRoiManager(this, "RoiType", ...);
lowThreshold     = new ParamItem(this, "LowThreshold", 255.0);
```

- 字段名 `lowThreshold`，参数键 `"LowThreshold"`；
- 字段名 `ModuRoiManager`，参数键 `"RoiType"`；
- 字段名 `inputImage`，参数键 `"InImage"`（另有 3 个派生键）。

**映射完全靠构造函数里的字符串字面量**，不靠命名约定、不靠反射。

### manifest 结论

参数声明必须同时有：`ParamKey`（存储/算法键）、`PropertyName`（C# 属性名）、`DisplayName`（文案或 key）、`AlgorithmIndex`（可选，原生算法索引用）。当前 manifest 只有 `Id` + `PropertyName`，缺 `ParamKey` 与文案 key 的区分。

## 2. 条件显隐

### 原厂写法（Blob `ThresholdType` 六支）

```xml
<Triggers>
  <Trigger><Property>CurValue</Property><Value>0x2</Value><Setters>
    <Setter><TargetName>Polarity</TargetName><OperationName>VisibleOperation</OperationName></Setter>
    <Setter><TargetName>LowThreshold</TargetName><OperationName>VisibleOperation</OperationName></Setter>
  </Setters></Trigger>
  ...
</Triggers>
```

配套：被控目标默认写 `<CustomVisible>False</CustomVisible>` —— **默认隐藏，由 trigger 打开**。

### 机制

| 环节 | 证据 |
|---|---|
| Setter 结构（目标名 + 操作名） | `Setter.cs:9-17` |
| 目标解析：先本 Category 按 `Name` 找，再全局 `FindBaseNodeByName` | `Setter.cs:119-138` |
| `VisibleOperation` → `CustomVisibleA = true` | `VisibleOperation.cs:24-40` |
| `HiddenOperation` → `CustomVisibleA = false` | `HiddenOperation.cs:28-44` |
| 多值匹配 `"0x1\|0x3"` | `Trigger.cs:106-145` |
| 多条件（and/or、支持 `Node.Property`） | `MultiTrigger.cs:11-15/102-167` |
| 加载期顺序：`DoIniter`（只跑 Initers）→ `NotifyTrigger`（按默认值跑一次）→ 读真实值 | `AlgorithmTabRoot.cs:821-829`、`NameValueItem.cs:650-657/706-723` |
| 交互期两轮：先 `ReOnTrigger` 撤销、再 `OnTrigger` 应用 | `NameValueItem.cs:659-691` |

### 关键语义：隐藏 ≠ 不生效

- `CustomVisible` 只控制**控件可见性**，参数仍在、仍参与运行（`ValueBase.cs:165-196`）。
- **但隐藏会清掉该参数的变量订阅**（`ValueBase.cs:187-193`）。
- 真正的"不生效"另有三个口子：`IsAbandon="True"`、`AccessMode` 不含 `w`（写值直接返回 -2，`NameValueItem.cs:906-910`）、`Enable` 字段。

### manifest 结论

需要 `VisibleWhen` 能表达"源参数取哪些值 → 显示哪些目标参数"，并显式标注：①作用于可见性而非可用性；②隐藏会撤销订阅；③初始显隐 = 默认值 + 首轮触发，不只是 `<CustomVisible>`。

## 3. 成对编辑（上下限）

### 原厂有专门容器：`IntegerBettween`（原厂拼写，双 t）

```xml
<IntegerBettween Name="ThresholdRangArea">
  <AlgorithmIndex>0x0000</AlgorithmIndex>
  <DefaultValue>10000</DefaultValue><MinValue>0</MinValue><MaxValue>255</MaxValue>
  <CustomVisible>False</CustomVisible>
  <Integers>
    <Integer Name="LowSoftThreshold"><AlgorithmIndex>0x060C</AlgorithmIndex><CurValue>0x64</CurValue>...</Integer>
    <Integer Name="HightSoftThreshold"><AlgorithmIndex>0x060D</AlgorithmIndex><CurValue>0x96</CurValue>...</Integer>
  </Integers>
</IntegerBettween>
```

- 一个控件（`SliderArrange SliderType="between"`，`paramusercontroldatatemplate.xaml:577`）承载两个参数；
- 父节点 `AlgorithmIndex=0x0000`、`DefaultValue=10000` 超出自身 `MaxValue=255` —— **父节点不参与运行，只是容器元数据**；
- 存储仍是两个独立键：`ValueBettween.cs:76-96/127-135` 对两个子项各调一次 `SetParamUnit`。

### 交叉校验规则（`Integer.cs:134-180`）

```
我 = 右值(end)：我的下界被左兄弟的当前值抬高（left <= me）
我 = 左值(start)：我的上界被右兄弟的当前值压低（me <= right）
越界 → RangeChecker 抛 "参数越界 (min,max)"
```

### manifest 结论

`PairGroup { ContainerKey, MinKey, MaxKey, Constraint="min<=max", Slider=true, ExtremumFromDeclaration=true }`，容器键必须标记为非算法参数（不参与下发）。

## 4. 布尔开关提示文案

### 原厂类型叫 `BooleanTips`（继承普通 `Boolean`）

```xml
<BooleanTips Name="SolSaveImageData">
  <CurValue>False</CurValue>
  <DisplayName>RunParam_Save Image</DisplayName>
  <SelecetedTips>最大保存120张图片</SelecetedTips>
</BooleanTips>
```

- 类定义：`BooleanTips.cs:7-49`，多两个字段 `SelecetedTips` / `UnSelecetedTips`（原厂拼写少一个 t）；
- 切换时机：`CurValueA` 变化 → `MessageTips = CurValue ? SelecetedTips : UnSelecetedTips`（`:41-47`）；
- 渲染：开关右侧常驻小字（`MaxWidth=150`，超长省略）+ 同内容悬停（`booleantipsdatatemplate.xaml:21/34`）；
- 普通 `<Boolean>` 没有 tips，悬停文案来自 `Description`（`paramusercontroldatatemplate.xaml:109`）——**两回事，不要合并**。

### manifest 结论

布尔参数加 `TipsOn` / `TipsOff` 两个可选字段；`Description` 保持独立。

## 5. 分类（页签 / 分组）

### 原厂层级

```xml
<Tabs>
  <Tab Name="Tab_ROI Area">
    <Categorys>
      <Category Name="Tab_ROI Area" CanTriggerRun="TRUE">
        <Items>
          <GroupLinkItem Name="RoiSelectGroup"><LinkName>RoiSelectGroup</LinkName></GroupLinkItem>
          <ROISelecter Name="RoiType">...</ROISelecter>
        </Items>
      </Category>
    </Categorys>
  </Tab>
</Tabs>
```

### 关键事实

| 事实 | 证据 |
|---|---|
| 参数**没有**分类属性，归属由 XML 层级决定 | `NameValueItem.cs:326`（`GroupName => GetParentNode()` 返回父 Category 对象） |
| 渲染按"父 Category 对象"分组，不是按字符串 | `ParamsTabUserControl.xaml:11-17`（`PropertyGroupDescription PropertyName="GroupName"`） |
| 页签/分组显示名 = `Name` 查语言表 | `ParamsTabUserControl.xaml:51`、`globalresources.xaml:50`、`zh-cn.xaml:1298/1306/1310` |
| Category 级还有 `CustomVisible`（整组可隐）、`CanTriggerRun`、`SubscribeVisible`、`CategoryNoHead`（无标题分组） | `globalresources.xaml:65-70`、`Category.cs:58-72` |
| **`vmCategory` 不是原厂属性** | 原厂只有 `Category/@Name`；`vmCategory` 是我方清单加的对齐字段 |
| 我方 `vmCategory` 目前只做溯源校验，UI 不读 | `DeclaredParameterSchema.cs:351`、`BlobParameters.cs:397`；`src/Plugin.Wpf` 全无引用 |

### manifest 结论

group 只需 `Page` + `Section`（渲染依据）+ `VmCategory`（与原厂 `Category/@Name` 逐字对齐校验）。要与原厂分组行为等价，还需补三个可选字段：`NoHeader`、`GroupVisibleWhen`、`CanTriggerRun`。

## 6. ROI 组

### 原厂只有一个 ROI 参数

```xml
<ROISelecter Name="RoiType">
  <FullScreenEnable>True</FullScreenEnable>
  <SelectType>Mul</SelectType>
  <ROISelection>Box SectorRing Polygon Sector</ROISelection>
  <RoiMaxNum>16</RoiMaxNum>
</ROISelecter>
```

- 形状集合写在一个空格串里，不是每形状一个参数（`ROISelecter.cs:74-106` 的 17 个布尔图标位）；
- `InitMap` 把 `SelectType` 与 `ROISelection` 按空格一一配对，个数不等直接弹错（`:1076-1099`）；
- 值本体是二进制协议：逐 ROI `[类型字节][版本][结构体]`，多边形 `uint 点数 + 点数*8`（`:2586-2663`）；键仍是 `ComName`。

### "绘制/继承"由共享组驱动

`Group.xml:42-109` 的 `RoiSelectGroup` 里 `RadioSelecter Name="RoiSelect"`（0=绘制，1=继承），用 `MultiTrigger` **按名字跨组**控制：

- `CurValue=0 且可见` → 显示 `RoiType`
- `CurValue=1 且可见` → 显示 `InheritWay`

### 掩膜分三处，都不是 `RoiType` 的子项

| 项 | 载体 |
|---|---|
| 输入掩膜 | `InputMaskImageGroup`：`RadioSelecterEx2 Name="ROIAreaType"` + `EnumerationG Name="MaskImage"`（`Group.xml:2621-2704`） |
| 输出掩膜 | 单个布尔 `OutputMaskImage`（`Group.xml:2605-2617`） |
| 屏蔽区 | 独立 `ROISelecter_Extern Name="ExternRoiType"`，`SelectType="Avoid"`、`ROISelection="Polygon"`（`Group.xml:2560-2569`） |

### 我方缺口

`RoiGroupDeclaration.cs:19-37` 只认 `rectangle` / `annulus` 两种 `kind`（`:81-82`），缺：

1. `SelectType` / `ROISelection` / `RoiMaxNum` / `FullScreenEnable` 四个声明字段；
2. 屏蔽区（`SelectType=Avoid`）的独立声明位（现只用 `maskSourceField`/`maskInheritedField` 近似）。

### manifest 结论

ROI 组要补上述 4 个字段 + 屏蔽区独立声明位；形状集合用"名字串"而非枚举列表（与原厂一致）。

## 7. 汇总：manifest 需要补的字段

| # | 补充项 | 目的 |
|---|---|---|
| 1 | `ParamKey`（与 `PropertyName` 分开）、`DisplayNameKey`、`AlgorithmIndex` | 对齐原厂"存储键 ≠ 字段名 ≠ 文案" |
| 2 | `VisibleWhen { SourceKey, Values[], Targets[] }` + `HidesSubscription` 标注 | 对齐原厂 Triggers 与"隐藏撤销订阅" |
| 3 | `PairGroup { ContainerKey, MinKey, MaxKey, Constraint }` + 容器不参与下发 | 对齐 `IntegerBettween` |
| 4 | `TipsOn` / `TipsOff` | 对齐 `BooleanTips` |
| 5 | Group 级 `NoHeader` / `GroupVisibleWhen` / `CanTriggerRun` | 对齐 Category 级行为 |
| 6 | RoiGroup 补 `SelectType` / `ROISelection` / `RoiMaxNum` / `FullScreenEnable` + 屏蔽区声明位 | 对齐 `ROISelecter` 全量 |
