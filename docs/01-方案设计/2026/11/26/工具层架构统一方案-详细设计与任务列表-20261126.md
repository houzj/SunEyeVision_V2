## 1. 范围与目标

### 1.1 做

| 目标 | 量化基线 | 目标值 |
|---|---|---|
| 声明样板（52%） | ~16,850 行 | ≤ 3,000 行 |
| 编辑器手工装配（33%） | ~10,740 行 | ≤ 2,000 行 |
| 工具项目数 | 18 | ≤ 10（同族合并后） |
| 平台装配器复用率 | `ToolEditorCommit` 0/18 | ≥ 16/18 |
| 同一语义的写法数量 | Schema 3 种、结果声明 3 种、目录 3 种 | 各 1 种 |

### 1.2 不做（明确排除）

- **算法统一**：Blob 的 HALCON 阈值内核、ContourMatch 的模板训练窗、各工具的匹配算法，一律不动；
- **执行契约变更**：`IToolSession`/`IToolOutput`/`ToolOutcome` 保持现状；
- **持久化格式变更**：`ToolConfiguration.Fields` 结构不变，已有方案文件继续可读；
- **UI 视觉改版**：参数页视觉沿用现有原厂迁移控件，只改“谁来装配”。

## 2. 目标架构

### 2.1 四层与职责

```
┌─ L0 契约层（src/Plugin.Contracts）─────────────────────────┐
│  ToolManifest（声明模型）                                  │
│  ManifestCompiler（manifest → Schema/Descriptor/Appearance）│
│  ToolDefinition<TSettings,TOutput>（工具基类，默认实现）    │
│  ResultOutlineSet / RoiEditDeclaration 等系统类型           │
└───────────────────────────────────────────────────────────┘
┌─ L1 工具层（tools/*）──────────────────────────────────────┐
│  唯一文件：<Tool>Manifest.cs（声明） + <Tool>Session.cs（算法）│
│  可选：<Tool>Panel.cs（仅无公共模板的复合控件，需登记）      │
└───────────────────────────────────────────────────────────┘
┌─ L2 平台装配层（src/Plugin.Wpf、src/UI）──────────────────┐
│  ToolPageComposer（参数页唯一装配入口）                     │
│  ToolEditorCommit / ProductionEditorContext（提交与撤销）  │
│  RoiDocumentStore / RoiDocumentRasterizer（ROI 全链）      │
│  GeometryCapture（几何快照基座）                            │
│  DisplayFieldBuilder（显示字段基座）                        │
│  ResultWorkspacePresenter（结果显示）                       │
└───────────────────────────────────────────────────────────┘
┌─ L3 宿主层（src/UI/Shell）─────────────────────────────────┐
│  节点选择、结果发布、调试窗口生命周期、结果工作区           │
└───────────────────────────────────────────────────────────┘
```

### 2.2 边界（硬约束，进架构测试）

| 能力 | 归属 | 工具层禁止 |
|---|---|---|
| 参数页页签/分组/行/控件选择 | L2 `ToolPageComposer` | 禁止 `*ParameterEditor`（例外需登记） |
| Schema（Settings/Result/Display） | L0 `ManifestCompiler` | 禁止手写 `new Port(...)` |
| 显示合同（Descriptor/Appearance） | L0 `ManifestCompiler` | 禁止手写 `ResultDisplayDescriptor` |
| ROI 声明与交互 | L0+L2 | 禁止手写 `RoiEditDeclaration` |
| 几何快照（检测区域/光栅/预算） | L2 `GeometryCapture` | 禁止手写 `*ResultGeometry.cs` |
| 结果行冻结（Freeze/FreezeBox） | L2 `DisplayFieldBuilder` | 禁止各写 `Freeze*` |
| 提交/撤销/发布 | L2 `ToolEditorCommit` | 禁止直接调 `DocumentEditProposal` |
| 算法 | L1 | — |

### 2.3 数据流（改后）

```
tool.manifest（唯一声明）
   │ ManifestCompiler（编译期纯函数）
   ├→ SettingsSchema ──→ 参数页（ToolPageComposer）
   ├→ ResultSchema   ──→ 结果树/结果表
   ├→ DisplaySchema  ──→ 显示项（Appearance）
   ├→ Descriptor     ──→ 结果工作区
   └→ RoiEditDeclaration ──→ ROI 会话（RoiDocumentStore）
```

## 3. 核心契约设计

### 3.1 ToolManifest（声明模型）

```csharp
public sealed record ToolManifest(
    string Id, string Name, string Description, string Icon, string Category, int Order,
    IReadOnlyList<ToolParameterDeclaration> Parameters,
    ToolResultDeclaration Result,
    ToolDisplayDeclaration Display,
    ToolInputSet Inputs = ToolInputSet.ImageRoiFixture,
    ToolRoiDeclaration? Roi = null,
    ToolCapabilityFlags Capabilities = ToolCapabilityFlags.None);
```

**输入用组合模板**（消灭逐工具重复的端口声明）：

```csharp
/// 组合模板：编译器按模板展开为标准端口集，manifest 不手写端口。
/// A0/T-AN1 定稿：原厂 IO 是运行时动态图，静态声明只承担"模板 + 默认标志"。
public enum ToolInputTemplate { Image, ImageRoi, ImageRoiFixture, ImageRoiMask, None }
```

> ✅ **A0 已定稿三项**（见 `A0-节点层同构取证-AN1-AN2-AN6-20261126.md`）：
> - `ToolInputTemplate`（T-AN1）：组合模板语义，端口由编译器展开；
> - `ParameterBindingKinds`（T-AN2）：参数级可绑定档位；
> - `ToolPanelOverride`（T-AN6）：**行级**为唯一默认粒度，页级仅 Panal 页签/独立窗口且需登记。

**参数声明**（含原厂 XML 的等价信息 + 可绑定档位）：

**动态输出契约**（A0/T-AN1 新增，对应原厂 `DynamicVmIO`）：


### 3.2 ManifestCompiler（编译期纯函数）

```csharp
public static class ManifestCompiler
{
    public static ToolSchema SettingsSchema(ToolManifest manifest);
    public static ToolSchema ResultSchema(ToolManifest manifest);
    public static ToolSchema DisplaySchema(ToolManifest manifest);
    public static ResultDisplayDescriptor Descriptor(ToolManifest manifest);
    public static ResultDisplayAppearance Appearance(ToolManifest manifest, FieldSettings fields);
    public static RoiEditDeclaration? RoiEdit(ToolManifest manifest);
}
```

**关键约束**：无副作用、无 IO、可重复调用；同 manifest 必须产出字节级相同结果（快照测试据此）。

### 3.3 ToolDefinition 基类

```csharp
public abstract class ToolDefinition<TSettings, TOutput> :
    IToolDefinition<TSettings, TOutput>, IToolSettingsFields,
    IToolCatalogProvider, IToolResultPresentationProvider, IToolResultDisplayProvider
    where TSettings : IToolSettings<TSettings>, new()
    where TOutput : class, IToolOutput
{
    protected abstract ToolManifest Manifest { get; }
    public abstract IToolSession<TSettings, TOutput> CreateSession();

    // 以下全部默认实现，工具不得 override（架构测试校验）
    public ToolSchema SettingsSchema => ManifestCompiler.SettingsSchema(Manifest);
    public ToolSchema ResultSchema => ManifestCompiler.ResultSchema(Manifest);
    public ToolSchema DisplaySettingsSchema => ManifestCompiler.DisplaySchema(Manifest);
    public ResultDisplayDescriptor ResultDisplay => ManifestCompiler.Descriptor(Manifest);
    public ResultDisplayAppearance CaptureResultDisplay(FieldSettings f) => ManifestCompiler.Appearance(Manifest, f);
    public ToolCatalogDescriptor Catalog => new(Manifest.Name, Manifest.Description, Manifest.Icon, Manifest.Category, Manifest.Order);
    public InputValues ReadSettings(object settings) => /* 基类反射/manifest 驱动 */;
    public object MaterializeSettings(InputValues values) => /* 同上 */;
}
```

**读取/物化**的两种实现路线（任务 T04 决策）：
- 路线 A：反射按 manifest 字段读 `TSettings` 属性（零工具代码，但需约定属性名 = 字段 Id）；
- 路线 B：工具实现 `ReadSettings/MaterializeSettings`（灵活，但保留少量样板）。

建议 **路线 A + 显式映射表**（manifest 里每个参数给 `PropertyName`，默认等于 Id）。
