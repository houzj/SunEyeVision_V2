一、目标与「完成」的定义

以 图像源 + Blob 分析 两个工具为样板，打通「工具箱 → 画布节点 → 参数 → 调试 → 执行 → 结果 → 保存重开」，并按四个维度分别给出可验证的完成标准。

维度完成标准（可验证）证据基准能否承诺
算法 原件每个参数都映射到明确算子与调用点；执行结果在给定测试图上与基准一致 BlobFindModuParams.cs（1758 行 / 95 属性）、BlobFindResult.cs 可承诺逐项对照
参数 原件 95 个属性逐条有处置结论：已实现 / 已合并（写明并入哪项）/ 不适用（写明原因），无未解释缺口 同上 可承诺当前 41 vs 95，差集需清零
显示 结果字段逐项对应；图形样式（轮廓/十字/文本/图例）与原件一致 BlobFindResult.cs、CBlobInfo.cs、CMultiCategoryBlobFindResult.cs 可承诺逐字段对照
UI 每个参数按类型映射到控件（原件控件优先），布局遵循原件参数面板规格 无 Blob 专属 UI 原件：只能依据 ConfigurationShell + 原件控件 + 类型映射表 不承诺像素级一致
必须说清的一条：反编译产物里没有 Blob 模块的 WPF 程序集（只有 iMVS_6000PlatformSDKCS.ObjectPlatformSDKCS 的 SDK 定义，即参数与结果，不含界面）。因此 UI 只能做到「按参数类型映射 + 原件控件规格」的一致性，无法做到「与原件逐像素相同」。若需要 UI 也有原件依据，需补充 BlobModule*.dll 的 WPF 反编译产物。

五、不承诺项（明确写在前面）

  1. UI 逐像素一致：无 Blob 模块 WPF 反编译产物，只能按类型映射保证控件与分组，布局细节属推断。
  2. 算法数值完全等效：能保证参数语义与算子调用方式一致，但 HALCON 版本差异可能导致边界结果不同，需用固定测试图比对后结论。
  3. ROI 继承 / 位置修正：原件是否具备尚未确认；若原件不具备，则删除现有占位文案而非实现臆想功能。
