# 主界面产品级重构实施总结

## 一句话结论

主界面从"一个超长布局 + 一个管所有的上帝类"重构为"六个独立区域 + 六个就近管理类"，三套打架的蓝色统一为唯一主色 #0066CC，布局对标专业视觉软件（VisionMaster），并清理了假 CPU/FPS 等死 UI。全量构建 0 错误。

## 你得到什么（用户视角）

### 1. 颜色终于统一了
- 之前软件里三套蓝色打架（工具箱、图像控件、主界面各用一个蓝 #1890FF/#667EEA/#0066CC），看起来不专业、且改颜色要到处找。
- 现在全部收敛成**唯一主色 #0066CC**，SDK 控件、工具箱、图像区、插件全走同一套规则。改颜色只需改 `ColorConstants.cs` 一处，全软件同步。

### 2. 主界面从"巨石"变成"拼图"
- 原来主界面是 1187 行的超长 XAML + 220KB 的"上帝" ViewModel，改一处容易牵连崩一片。
- 现在拆成六个独立区域：顶部栏 / 工具箱 / 工作区 / 图像区 / 日志 / 状态栏。每个区域有自己的 View 和专属 ViewModel，互不干扰，好定位好维护。

### 3. 布局对标专业视觉软件（VisionMaster）
- **一体化标题栏**：菜单 + 工具栏两行合一，紧凑专业。
- **可折叠分栏面板**：右侧面板一键折叠/展开（自研 `CollapsibleSplitterBox`，不引第三方 Dock 依赖）。
- **三段式状态栏**：真实状态 / 耗时 / 消息。
- **右下角小地图**、**流程管理条**：方便看全局结构与流程。
- **深色右侧面板 + 机器视觉术语结果表**：高密度专业风格。

### 4. 去掉了假数据
- 状态栏之前显示的 CPU/FPS 是写死的假数据，已全部清理，只显示真实运行状态。

### 5. 修复：最大化不再遮挡底部任务栏
- 无边框窗口最大化时会按整块屏幕撑满、盖住任务栏。通过在 `MainWindow` 拦截 Win32 `WM_GETMINMAXINFO` 消息，把最大尺寸限制在任务栏以上的可用区，任何方式最大化都生效（含高 DPI 屏）。

## 技术要点（附录）

### 阶段一：SDK 主题收敛
- `Generic.xaml` 顶部 merge `Colors.xaml`，删除与 Colors 同名的硬编码 Key（PrimaryBrush/PrimaryHoverBrush/BorderBrush/BackgroundBrush）。
- 独有 Key（PanelBackgroundBrush/PanelHoverBrush/LabelBrush/LabelSecondaryBrush）改经 `x:Static` 引用 `ColorConstants`。
- 新增 `PrimarySelectedBrush`（主色 + 19% 透明度）承载选中高亮。
- 全仓清除 `#1890FF` / `#667EEA` 残留。

### 阶段二：拆 XAML + VM 就近化
- `MainWindow.xaml` 缩成骨架，拆出 `ShellTopBarControl` / `ToolboxControl` / `ShellWorkspaceControl` / `ImageResultControl` / `LogPanelControl` / `StatusBarControl` 六个 UserControl。
- 拆出各域 ViewModel：`ShellTopBarViewModel` / `WorkspaceViewModel` / `ImageResultViewModel` / `StatusBarViewModel` / `ToolboxViewModel` / `LogPanelViewModel`。
- `MainWindowViewModel` 变编排根 VM，各域子 VM 构造注入根 VM 引用共享基础设施（日志、StatusText、WorkflowTabViewModel、SetRuntimeParameter）。
- 假 CPU/FPS 模拟运行清理（rule-008 无死 UI）。

### 阶段三：可折叠分栏 + 布局落地
- 自研 `CollapsibleSplitterBox`（继承 GridSplitter）：四方向折叠（Left/Right/Top/Bottom）、双折叠档（收缩档 + 恢复原尺寸）、`IsCollapsed` 暴露供布局持久化。
- 布局持久化复用已有 `LayoutConfig`（保存右侧面板折叠状态 + 列宽）。
- 一体化标题栏、三段式状态栏、小地图、流程管理条就位。

## 说明与偏差记录

- 方案原计划"删除孤儿 AppResources.xaml"，实际核验发现它是**整个 UI 的资源入口**（被 App.xaml、MainWindow.xaml、HelpWindow.xaml、AboutWindow.xaml 共 4 处引用），删除会导致构建失败，故**保留**。其内部颜色值已与 ColorConstants 一致，不破坏主色统一。

## 文件改动概览（主要）

- `src/Plugin.SDK/UI/Themes/Generic.xaml`：merge Colors、删同名硬编码 Key、x:Static 引用 ColorConstants
- `src/Plugin.SDK/UI/Themes/Colors.xaml`：主色/语义色/中性色资源（x:Static 引用 ColorConstants）
- `src/UI/Shell/Windows/MainWindow.xaml(.cs)`：缩成骨架、拦截 WM_GETMINMAXINFO 修复最大化遮挡任务栏
- `src/UI/Shell/Windows/MainWindowViewModel.cs`：变编排根 VM，注入各域子 VM
- `src/UI/Shell/Controls/Shell/ShellTopBarControl.xaml(.cs)` + `ShellTopBarViewModel.cs`：一体化标题栏
- `src/UI/Shell/Controls/Shell/ShellWorkspaceControl.xaml(.cs)` + `WorkspaceViewModel.cs`：工作区 + 小地图
- `src/UI/Shell/Controls/Shell/ImageResultControl.xaml(.cs)` + `ImageResultViewModel.cs`：图像区 + 结果表
- `src/UI/Shell/Controls/Shell/StatusBarControl.xaml(.cs)` + `StatusBarViewModel.cs`：三段式状态栏
- `src/UI/Shell/Controls/Common/CollapsibleSplitterBox.xaml(.cs)`：可折叠分栏控件
- `src/UI/Shell/Controls/Toolbox/ToolboxControl.xaml` + `ToolboxViewModel.cs`：工具箱
- `src/UI/Shell/Controls/Panels/LogPanelControl.xaml` + `LogPanelViewModel.cs`：日志面板
