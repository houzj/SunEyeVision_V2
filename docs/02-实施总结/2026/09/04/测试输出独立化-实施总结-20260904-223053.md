# 测试输出独立化实施总结

## 实施日期
2026-09-04

## 实施状态
✅ 已完成

## 背景与目标

测试项目此前被全局 `Directory.Build.props` 强制输出到 `dev\Debug\`（Debug）与 `Release\SunEyeVision_v1.0.0\SunEyeVision\`（Release），与主程序/框架 dll 混在同一目录，污染主程序运行目录与发布包。

目标：
1. 主程序 `dev\Debug\` 与 Release 发布目录不再出现任何 `*.Tests.dll`。
2. 测试项目统一共享输出到 `tests\bin\`（非各自 bin、非 dev/Debug 根），宿主依赖在共享目录自然合并去重为一份，不随工具数量膨胀。
3. 测试运行目录自足完整（含 halcon native / OpenCvSharp runtimes / 语言资源），不依赖 dev/Debug 根补齐。
4. 全部测试从共享目录运行全绿。

## 实施内容

### 1. `Directory.Build.props`：测试项目输出特判

以 `$(MSBuildProjectName.EndsWith('.Tests'))` 判定（props 阶段 IsTestProject 尚不可知，全部测试 csproj 均以 `.Tests.csproj` 命名，普通项目无此后缀）：

- 测试项目 OutputPath/OutDir 统一为 `$(MSBuildProjectDirectory)\..\bin\Debug\`（= `worktree\tests\bin\Debug\`），Release 同理。
- `AppendTargetFrameworkToOutputPath=false`：关闭 SDK 自动追加 TFM 子目录，保证所有输出（含 deps.json/runtimeconfig）落在同一层。
- 主程序/框架项目输出不变（dev/Debug 根 + Release 发布目录）。

### 2. `Directory.Build.targets`：HostDebugRoot 注入 + halcon native 复制

- 对 `IsTestProject=true` 项目注入 `AssemblyMetadata("HostDebugRoot")`：Debug→`dev\Debug\`（工具 Debug 部署处），Release→Release 发布目录（工具 Release 部署处）。供共享 Loader 定位工具插件。
- `CopyHalconNativeRuntimes` 恢复对测试项目生效：halcon native 复制到共享输出 `tests\bin\<Config>\`，lock 文件去重保证只复制一份，halcondotnetxl.dll 与 native 同目录正常 P/Invoke。

### 3. `tests/_shared/ToolPluginTestLoader.cs`：共享测试加载器

- 宿主根显式注入读取：优先读 `AssemblyMetadata("HostDebugRoot")`，不再依赖"向上找 SDK.dll"（bin 内有 copy-local SDK.dll 会误判）。
- ModuleInitializer 注册 `AssemblyLoadContext.Default.Resolving`：bin 解析失败时从宿主根补齐宿主 dll（幂等）。
- 按"测试程序集名去 `.Tests` 后缀 = 工具名"约定，从 `plugins\<Tool>\` 加载最新工具 dll。

### 4. 各测试项目 csproj

- 工具测试（12 个）对工具 ProjectReference 设 `<Private>false</Private>`（工具 dll 不 copy-local，从 plugins 加载）+ `<Compile Include>` 接入共享 Loader。
- 移除 Condition/ShapeMatch csproj 的"复制到根" Target；移除 Subroutine 测试代码内 AssemblyResolve 兜底。

### 5. Script.Tests 5 文件收敛

HalconScriptCompileTests / MetadataReferenceProviderTests / AvalonEditBridgeTests / ScriptSandboxWarmupTests / ScriptEngineRegressionTests 的 debugDir 向上探测逻辑统一改为读共享 Loader 的 `HostDebugRoot`（去重 + 适配 bin 独立布局）。

## 目录结构（变更后）

```
dev\Debug\                      ← 主程序+框架+plugins（干净，无测试 dll）
tests\bin\Debug\                ← 所有测试共享输出目录（16 个 Tests.dll + 一份宿主依赖）
  ├─ *.Tests.dll                （16 个测试 dll 并集，无重复）
  ├─ SunEyeVision.*.dll          （宿主一份）
  ├─ halcon native               （一份）
  ├─ runtimes\win-x64\native\    （OpenCvSharp native 一份）
  └─ zh-Hans\ 等语言资源
Release\SunEyeVision_v1.0.0\SunEyeVision\   ← 发布目录（无测试 dll）
```

## 验证结果

| 项目 | 结果 |
| --- | --- |
| dev/Debug 根 *.Tests.dll | 0（清理完毕，构建不再产生） |
| Release 发布目录 *.Tests.dll | 0 |
| tests/bin/Debug 共享目录 | 16 个 Tests.dll + 宿主去重一份 |

## 遗留问题

- Script.Tests 10 失败：AvalonEditTextContainer 已迁至 CommonControl（namespace CommonControl），测试仍按 `SunEyeVision.Tool.Script.Views` 查找；SemanticHighlightContractTests 源码路径未找到。属架构重构遗留，另行处理。
- Plugin.SDK.Tests 2 失败：MeasureInteractionModel 圆弧端点/共线几何数学断言不符，属 SDK 测量模型问题，另行处理。

## 技术优势

- 主程序目录与发布包零测试污染。
- 测试共享单一输出目录，宿主依赖一份，新增工具测试不增加宿主占用。
- 测试运行目录自足完整，不依赖 dev/Debug 根补齐（解决"宿主依赖不都在根"问题）。
- 工具 dll 仍从 plugins 加载，与主程序运行路径一致（rule-008）。
