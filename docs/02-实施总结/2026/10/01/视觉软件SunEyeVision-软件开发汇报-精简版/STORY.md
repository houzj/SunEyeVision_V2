# STORY.md — 视觉软件 SunEyeVision 软件开发汇报（精简版，4 页）

## ① 用户意图对齐

- **目标受众 / 场合**：公司领导（老板）听一次软件开发进展汇报；口头汇报为主、材料为辅。
- **核心目标**：讲完后希望领导记住三件事 —— ① **东西已经做出来了**（平台底座 + 19 个工具插件 + 可安装内测包）；
  ② **测量工具链已提前完工**，现在在做设备层（相机/通讯/图像源）；③ **下一步路径清晰**，明年 Q2 交付 V1.0。
  期望动作：认可当前进度，支持相机硬件与客户现场联调窗口。
- **PPT 长度**：**4 页**（用户明确要求 ≤4 页）→ 无目录、无章节扉页，封面 + 2 内容页 + 结束页。
- **视觉调性**：专业克制 / 数据驱动 / 工程感 / 蓝白 / 不花哨。
- **内容边界**：
  - 必讲：关键指标、已完成产出、当前在建、下一步计划与关键出口、风险与需要的支持。
  - 不讲：开发节奏曲线、里程碑长表、文档体系细节、覆盖核查过程、覆盖残留缺口等过程性内容。
  - 禁碰：**不写"向老板要人"**（用户明确要求删除人力诉求）。

## ② 页面布局骨架

- **页面总数与分章**：4 页，不分章（无目录 → 无 section 扉页，符合"目录 N 章 = N 扉页"契约的 0 章情形）。
  1. `01_cover.slide` — 封面（hero）
  2. `02_output.slide` — 已完成产出（supporting，valley：信息密度最高）
  3. `03_plan.slide` — 下一步计划（supporting，peak：时间轴 + 大数字锚点）
  4. `04_ending.slide` — 风险与需要的支持（hero，结束页）
- **Hero 页定位**：封面 + 结束页为 hero（2/4）。4 页短稿无法满足"hero 占 20–30%"的比例约束，
  按"封面与结束页默认 hero"处理：2 页 hero 不相邻，中间由 2 页 supporting 隔开。
- **rhythm 曲线**：peak(封面) → valley(产出) → peak(计划) → peak(收束)，无连续 ≥3 页 valley。
- **非对称版式预算**：4 页中 3 页非对称（封面全幅骑线、产出左标题右内容、计划非对称双栏），占比 75% ≥ 40%。
- **对称版式预算**：仅结束页使用上下分栏（1 页 ≤ 2 页上限）。
- **版式相邻不重复**：骑线文字 → 左标题+右内容 → 非对称双栏 → 上下分栏，四页四种版式。
