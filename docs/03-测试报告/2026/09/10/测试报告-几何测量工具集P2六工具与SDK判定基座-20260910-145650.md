## 一、用户视角验收摘要

**改前用户看到什么**：工作流里只有图像处理类工具（阈值/滤波/形态学/Blob）和检测类工具（直线查找/圆查找/轮廓匹配），**没有任何"测量"类工具**。用户想做「两条线的夹角/平行距」「圆心距」「点到线的垂距」这类尺寸测量，只能靠人眼看结果图，没有判定、没有 OK/NG、也没有可复现的数值输出。

**改后用户看到什么**：工具箱新增 **6 个几何测量工具**——线-线、线-圆、圆-圆、点-线、点-圆、点-点。每个工具打开后是三 Tab 调试窗：

- **Tab1 元素编辑**：两个测量元素并排显示（线-线是两个卡尺带、线-圆是"卡尺带+圆环带"），点选哪个元素哪个高亮，两个元素互斥激活（不会同时抢鼠标）；每个元素的来源可选「绘制优先」或「订阅上游」。
- **Tab2 运行参数**：所有引导几何与卡尺参数都是 `ParamValue<T>`，既能填常量也能绑上游变量；判定上下限可增删条目。
- **Tab3 结果显示**：给出几何量（夹角/平行距/垂距/圆心距/点距/ΔX/ΔY）与判定结果树，启用项无实测值或超限即 **NG 标红**。

其中**点元素只有参数订阅入口（填 X/Y 或绑上游点图形），没有绘制入口**——因为"点"本身没有需要拟合的引导几何；点-点工具是纯几何直算，连图像和 halcon 都不需要。

**依据**：对齐 MVTec HALCON metrology 模型（"引导几何 + 卡尺参数 → measure 拟合 → 几何量 → 判定"的分层）与 VisionMaster 测量工具的"元素槽 + 卡尺带 + 判定规格"交互范式；判定基座与双卡尺容器沉到 `Plugin.SDK` 供 6 个工具共用，避免 6 份复制。

## 五、缺陷与观察记录

### P2-1【实现缺陷·低危】图像缺失守卫为不可达死代码

**位置**：`src/SunEyeVision.HalAdapter/HalconHelpers.cs:31` + 5 个工具的 `Run` 方法

**现象**：5 个基于 halcon 的工具（线-线 / 线-圆 / 圆-圆 / 点-线 / 点-圆）在 `Run` 中写了：

```csharp
var hImage = parameters.GetHalconImage();
if (hImage == null || !hImage.IsInitialized())
    throw new InvalidOperationException("输入图像为空或无效");
```

但 `GetHalconImage()` 内部在图像为 `null` 时**先抛英文异常** `"Input is not Halcon HImage, type: null"`，导致后两行中文守卫**永不可达**（死代码）。

**影响**：功能上仍 Fail-Fast（用户能看到报错、不会静默出结果），**不影响正确性**；但用户看到的是英文报错，且工具内的中文提示形同虚设。

**建议治本方向**（不在本次范围，待用户决策）：
- 方案 A：`GetHalconImage()` 的 `null` 分支改为抛中文可读异常（统一报错语言）；
- 方案 B：`GetHalconImage()` 在图像为 `null` 时返回 `null` 而非抛异常，由调用方守卫统一报错（校验顺序归口工具）；
- 无论哪种，需同步删除工具内不可达的重复守卫或调整其位置，避免死代码残留。

**测试处置**：3 个测试（点-线 / 点-圆 / 点-点）已按**实际行为**断言 `Assert.Contains("测量失败:", result.ErrorMessage)`，并在注释中显式记录 P2-1，避免测试与实现脱节。

### P2-2【测试注释瑕疵·极低危】点-点图像缺失用例注释与实现不符

**位置**：`tests/SunEyeVision.Tool.PointPointMeasure.Tests/PointPointMeasureContractTests.cs:253-254`

**现象**：该用例注释复用了 P2-1 的描述（提到 `GetHalconImage` 先抛英文异常），但点-点工具实际走 `parameters.ResolvedInputImage == null || IsEmpty` 分支（不经 `GetHalconImage`），其守卫**是可达的**。

**影响**：仅注释误导，断言本身正确。建议后续清理该注释为点-点专属描述。
