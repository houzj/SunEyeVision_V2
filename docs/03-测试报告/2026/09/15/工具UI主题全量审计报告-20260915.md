## 2. 根因与整改

1. `ToolDebugControlBase.OnInitialized` 曾将 Generic 合并到控件局部资源。局部资源优先级高于 Application，导致 ROI/测量管理器固定命中亮色兜底，而透明的工具外层显示设计器暗色。
2. 已删除 `OnInitialized` 中会进入运行时的控件局部 Generic 注入。设计时由 `DesignTimeThemeLoader` 在构造阶段同时向工具根与可用的 Application 装配 DefaultTheme；运行时仅由宿主 Application 的 Light/Dark 字典覆盖。
3. 后续设计器截图证明基于构造、`Initialized` 和 Application 的两级注入仍受 Visual Studio 设计宿主影响。最终改为全部 16 个工具调试根在 XAML 中显式声明 `DesignTimeThemeResourceDictionary`：设计器解析资源时直接加载 Generic，正常运行时字典为空，不参与 Light/Dark 覆盖顺序。
4. `ToolDebugControlBase` 根背景和前景改为 DynamicResource，工具页与内部共享控件现在使用同一资源作用域。
5. ShapeMatch 预览区的 `#333/#CCC`、Script 标题文字的固定白色已改为语义主题资源。
6. Script 监视值不再自行扫描 DarkTheme，也不再保存 Black/LightGray/Gray Brush；数据模型只保存 `HasValue`，XAML 用 DynamicResource 和触发器决定前景色。
7. Script 状态文字、编辑按钮、ShapeMatch 模板提取状态、ImageControl 全屏背景均改用语义主题键。
8. 新增 `ImageAreaBackgroundBrush` SDK 语义键，并确认 Default、Light、Dark 三套字典均有定义。

## 3. 保留的业务颜色

下列颜色表达图像内容，不属于界面皮肤，因此保持稳定：ROI 检测蓝/屏蔽橙、测量叠加线、结果叠加图形、选中高亮、颜色选择器色板和用户配置的显示颜色。

## 4. 自动守卫

SDK 测试现包含以下主题契约：

1. SDK 控件和工具 XAML 禁止局部合并 Generic/DefaultTheme。
2. Background、Foreground、BorderBrush、Fill、Stroke 禁止直接写普通 UI 颜色；透明色与显式业务常量除外。
3. XAML 后台代码禁止手工判断 DarkTheme，禁止直接为普通 UI 的背景、前景和边框创建固定 Brush。
4. 每个 `SdkThemeKeys` 键必须同时存在于 DefaultTheme、LightTheme、DarkTheme。
5. 所有工具根由 `ToolDebugControlBase` 使用动态背景和前景。

1. 彻底关闭并重启 Visual Studio 后，任取 Blob、PointCircle、ShapeMatch、Script：同一个设计器页面不得出现外暗内亮或外亮内暗。
2. 设计器统一使用 SDK DefaultTheme；源查找、ROI 管理器、测量管理器、结果模块与工具根背景一致。
