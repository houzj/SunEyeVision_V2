```powershell

```

两个目录分别串行构建，避免 WPF 临时 BAML 产物竞争：

## 3. 优化前后共同执行的黑盒场景

| 场景 | 操作 | 优化前预期 | 优化后验收 |
| --- | --- | --- | --- |
| 运行中编辑参数 | 启动含耗时节点的流程，运行中修改后续工具阈值 | 当前运行可能读到编辑后的对象 | 当前运行保持启动时快照；下一次运行才使用新值 |
| 连续双击运行 | 第一次未结束时再次点击运行 | 可能覆盖取消源或上下文 | 第二次被明确拒绝；第一次 RunId、结果和取消源不变 |
| 暂停/恢复 | 在两个执行组之间暂停，等待 3 秒再恢复 | 暂停可能只是 UI 状态 | 暂停期间不启动下一组；恢复后从边界继续 |
| 暂停后停止 | 暂停流程，再点击停止 | 可能卡在等待或记为失败 | 等待立即解除，最终状态为 `Cancelled`，错误列表不增加失败项 |
| 子程序停止 | 主流程进入子程序时停止 | 父子取消和结果可能互相覆盖 | 子作用域带 ParentRunId，共享根取消，父子均结束且没有孤儿任务 |
| Script 输入 | 全局变量与上游节点结果同时绑定后执行 | 运行数据写入参数对象 | 输出相同；运行数据只存在于请求上下文 |
| PointPoint 输入 | 使用请求图像执行 3-4-5 点距 | 依赖参数中的 ResolvedInputImage | 结果距离为 5，参数对象的图像字段保持为空 |

每个场景至少执行 20 次。记录错误次数、错误状态、平均耗时和最大耗时；正确性指标优先于耗时。

## 4. 设计器与主题 A/B

在两个 worktree 中分别用 Visual Studio 打开以下 XAML 设计器，窗口大小和缩放保持一致并截图：

检查项：

- 点线元素 1 是否隐藏，元素 2 是否只允许直线；其他测量工具的元素类型是否与声明 Profile 一致。
- 未连接主图像控件、参数服务和运行服务时，工具栏、参数区、ROI 区仍能形成完整布局。
- 工具自身不包含独立图像显示区域；真实图像与图形叠加只在运行时的主界面共享图像空间验收。
- Light、Dark、独立设计器三种环境下无资源缺失、黑底黑字或透明背景丢失。
- 六个 DataAnalysisControl 的序列色在暗色主题下可读，并随主题切换，而不是保持固定色。

设计期验收使用截图对比。自动测试只能锁住初始化顺序和资源完整性，不能替代 Visual Studio
设计器对 BAML、字体、尺寸和真实视觉层级的验证。

## 6. 源码结构差异

在两个 worktree 各执行一次：

```powershell
rg -n "Application\.Current|GetProperty\(|GetValue\(" src\Plugin.SDK
rg -n "System\.Windows|FrameworkElement|Window" src\Plugin.SDK\Core\IToolPlugin.cs
rg -n "\.Context|\.NodeResults|\.ResolvedInputImage" tools --glob "*.cs"
rg -n --glob "*DataAnalysisControl.xaml" "#(2196F3|4CAF50|FF9800|E91E63|9C27B0|607D8B)" tools
rg -n "InitializeComponent\(\)|DesignMode" src\Plugin.SDK tools --glob "*.xaml.cs"
```

优化后当前目标：

- SDK 不反射读取 UI 全局状态。
- `IToolPlugin` 不出现 WPF 类型。
- DataAnalysisControl 的目标固定色数量为 0。
- 设计模式判断不得出现在 `InitializeComponent()` 之前。
- 工具旧运行字段引用持续下降；在全部工具迁移前，该项记录数量，不要求立即为 0。

## 7. 判定方式

最终报告按三类结论填写：

- **已证明改善**：自动测试通过，且共同黑盒场景结果优于或等于基线。
- **结构已完成、待人工确认**：源码和测试通过，但需要 Visual Studio 设计器截图确认。
- **尚未完成**：当前两目录物理拆分、全部旧工具迁移、Plugin.Runtime/Plugin.Wpf 物理拆分、资源生命周期与设备队列。

不要用代码行数、文件数或单次耗时作为架构优化成功依据。核心指标是运行隔离、结果语义、设计期可见、主题一致和插件故障可诊断。
