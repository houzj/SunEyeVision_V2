过渡拦截的实际行为

命中判据 MaxAreaInnerRectNum != 0 || OverlapRatio != 0 || MaxOutPixelNumEnable || MaxOutPixelNum != 0， 在任何 HALCON 资源创建前抛出 BLOB_INNER_RECT_NOT_READY， 文本为「最大内接矩形数量、最小重叠率、最大超界像素尚未取得原厂产出链证据，本版本不执行该组参数。」。 默认（关 / 0）不触发，零回归；拿到证据后删除该拦截改为真实实现。

范围校验

四项闭包参数在 BlobSettings.Validate() 中复用 XML 上下限校验，越界统一报 BLOB_SETTINGS_INVALID， 并在进入算法前失败（顺序先于过渡拦截，保证越界优先报参数错误）。覆盖用例：Out_of_range_closure_values_are_settings_invalid。

算子语义出处

  • fill_up_shape：官方 24.05 文档 parameters 段——feature 取 "area"，min/max 决定孔洞特征需落入的区间；min 默认 1.0、值域 ≥0。
  • set_system 的 neighborhood/tsp_neighborhood（4/8，默认 8）作用于 Connection、FillUp、Contlength 等邻域算子。
  • 待证项：fill_up_shape 页面未明示孔洞判定的邻域类型；本批用例（孤立孔 / 贴边界开口）在两种连通下结论一致，对角仅相接场景未覆盖。

本批未做

验证执行情况

Release 环境实测（正式封签）：dotnet build SunEyeVision.slnx -c Release 0 错误； Blob 测试项目 45 / 45 通过（含本批 6 条用例 BlobParameterExecutionTests）； Release 封签清单 517 项与 HEAD 一致（commit 88a1e9b）。

顺序约束（踩过）：tests/_shared/ProductRuntimeTestHost.cs 会校验封签清单 SHA256，而dotnet test 自带的构建步骤会重建产品程序集、使清单立刻失效并抛 Product assembly SHA mismatch。 正确顺序是：先 dotnet build -c Release（构建末尾重封签），再 dotnet test --no-build。

另：dev\Debug 侧封签清单仍停留在 commit 83b83f1，需 PowerShell 7（Seal-ReleasePayload.ps1 使用 Core 专有 API）才能重封签；本批测试改走 Release 环境，Debug 侧未执行。
