# 图像源工具 UI 与执行设计方案

日期：2026-09-27  
状态：后续沟通与实施基线，已开始分阶段实施（见第 11 节）  
范围：工作流图像源工具、图像预览器本地输入、方案相机设备取帧、输出契约与验收

> 相机工作流的驱动、触发、预览互斥和超载规则已由同目录《相机图像源工作流驱动与采集调度方案-20260927.md》更新；本文相关“节点每轮主动取帧”描述仅记录旧阶段现状，不再作为后续相机调度实施基线。UI、本地图像预览器和未冲突的输出契约仍以本文为基线。

## 1. 已确认的产品决策

1. 相机管理器先停在当前阶段；后续通过“图像源”节点把方案设备列表中的相机接入工作流。
2. 图像来源在 UI 中明确显示为**“本地图像 / 相机”**，不显示“图像预览器 / 相机”。“从图像预览器获取”是本地图像模式的内部数据路径。
3. 本地图像由现有图像预览器载入、管理、选择与切换，包括现有的“添加文件”和“添加文件夹”。图像源工具只消费预览器提供的本地输入快照，不再做第二套文件/文件夹导入入口、列表或缩略图管理。
4. 相机由应用级相机运行时连接和采集。节点保存稳定 DeviceId，不保存 SDK 句柄，不直接访问 UI 或厂商 SDK。
5. 相机完整参数和预览调试继续使用当前相机设置窗口；图像源不复制参数树，也不因执行/关闭节点而改变原有设备连接状态。
6. 两种来源共用同一图像输出契约。来源切换时 UI **替换**来源专属字段，不用大量禁用字段占位；两种模式原有设置分别保留。
7. VM 界面用于交互参考，不代表所有 VM 开关都在首版交付。对未实施项不显示可操作但无效的开关。
8. 现有图像结果区分为上方**图像结果画布**和下方**本地图片预览器**。前者用于显示节点输出，两种来源都保留；后者只服务本地图像的载入、列表、选择与切换，其可见性必须跟随当前节点及来源模式。

## 2. 职责与数据流

```text
本地图像文件 → 图像预览器 → ImageInputSource/运行快照 ┐
                                                  ├→ 图像源节点 → OutputImage → 下游工具
方案设备列表 → 应用级相机运行时 → CameraFrame ───────────┘
```

图像预览器是本地图片交互入口；工作流只能读取从其状态生成的**运行快照**，不得跨层读取 WPF 预览控件或屏幕像素。相机管理器是设备配置和显式连接入口；相机运行时持有会话；图像源节点负责本次取图，不承担设备发现、厂商参数编辑或连接生命周期管理。

## 3. UI 基线

采用现有工具参数区域，不另造一套相机管理窗口。本地图像和相机模式按来源动态显示。

### 3.1 本地图像模式

```text
┌────────────────────── 图像源 ──────────────────────┐
│ 基本参数                                           │
│ 图像来源          [ 本地图像                 ▾ ]    │
│ 像素格式          [ 保持原图 / MONO8 / RGB24 ▾ ]    │
│ 显示图像名称      [开关]                            │
│                                                    │
│ 当前图像          part_003.png · 第 3 / 12 张       │
│                                                    │
│ 序列运行                                           │
│ 自动切换          [开关]                            │
│ 最后一张停止      [开关]                            │
│                                                    │
│ 高级选项                                           │
│ SN 初始值         [ 1 ]                            │
│                                                    │
│ 状态              就绪 · 1920×1080 · RGB24         │
└────────────────────────────────────────────────────┘
```

- 图像添加/删除、缩略图、当前选择、运行全部/运行选择继续沿用现有图像预览器与 `ImageInputSource`。
- 预览器的“添加文件夹”是一次性导入所选文件夹当时已有的图片（当前仅扫描顶层），不是持续监听新文件；本方案不要求图像源重复实现导入，也不把“订阅文件夹”列为当前待交付功能。
- 图像源配置区只显示当前图片及序列位置摘要，不提供“定位到图像预览器”按钮；文件导入、选择和切换都在主界面现有预览器完成。
- 自动切换仅在本轮成功产出图像后推进；失败不跳过。最后一张停止仅在连续运行且自动切换开启时生效，由工作流运行控制层执行，不由插件操作 WPF。
- 像素格式只作用于节点输出，不改源文件。

### 3.2 相机模式

```text
┌────────────────────── 图像源 ──────────────────────┐
│ 基本参数                                           │
│ 图像来源          [ 相机                     ▾ ]    │
│ 关联相机          [ Hikrobot-MV-CU120-10GM   ▾ ]    │
│ 设备状态          ● 已连接       [相机设置…]        │
│                                                    │
│ 采集设置                                           │
│ 每次执行          获取一帧                          │
│ 触发方式          跟随相机当前配置（只读）           │
│ 取帧超时          [ 3000 ] ms                       │
│ 输出 Mono8        [开关]                            │
│                                                    │
│ 高级选项                                           │
│ SN 初始值         [ 1 ]                            │
│                                                    │
│ 上次结果          帧 128 · 4024×3036 · Mono8       │
└────────────────────────────────────────────────────┘
```

- 关联相机下拉框只列出当前方案设备列表中的相机，显示名称/状态，保存稳定 DeviceId。离线设备仍可识别并提示，不自动改选其它设备。
- “相机设置…”打开现有设置/预览窗口。相机曝光、增益、像素格式和触发源由该窗口管理；图像源不在每轮运行时暗中覆盖设备参数。
- 输出 Mono8 只转换本次结果，不写回相机 PixelFormat。不能转换的原始格式必须报明确错误，不能仅凭字节长度误标为 Mono8/RGB24。
- 没有选相机、设备离线/删除、相机未连接、取帧超时、等待触发超时均显示针对性错误；不回退到本地图像，不发布上一帧。

### 3.3 共用字段与模式切换

- SN 初始值是**逻辑输出帧号**的起始值，不是设备硬件序列号，也不同于相机原生 FrameId。首次成功输出使用初始值，后续成功输出逐次加 1；失败不递增。重新开始工作流时重置。首版置于高级选项，默认 1。
- 本地图像模式不显示关联相机、相机状态和取帧超时；相机模式不显示本地序列自动切换、最后一张停止等字段。
- 切换来源不清空另一模式的配置；保存方案后重启仍能恢复选择和各自设置。

### 3.4 现有图像预览器的可见性与绑定（实施必需）

这里的“图像预览器”专指 `ImageResultControl` 下方的 `ImagePreviewControl`（本地文件列表），不是上方始终承担结果显示的 `ImageControl` 图像画布。工具参数面板不复制预览器的文件增删、缩略图和运行选择能力，也不提供额外的焦点跳转按钮；只读显示当前图片摘要。

| 当前选中/来源 | 下方本地图片预览器 | 绑定对象 |
|---|---|---|
| 选中本地图像模式的图像源节点 | 显示，即使列表尚为空 | 该节点的 `ImageInputSource` |
| 选中下游节点，且能确定其对应的上游本地图像源 | 显示 | 对应上游节点的同一 `ImageInputSource` |
| 选中相机模式的图像源节点或其对应下游节点 | 隐藏 | 解除 `ActiveInputSource`；本地列表仍保存在节点配置中 |
| 未选中节点、切换工作流标签、没有可确定的上游本地图像源 | 隐藏 | 解除 `ActiveInputSource` |

- 来源在**同一节点**由本地切到相机时立即隐藏、解绑；切回本地时立即重绑原输入源并恢复列表、索引和运行选择，不要求用户先点其他节点。工具参数面板的来源字段也同步替换专属内容。
- 现有逻辑仅凭 `IsImageLoadNode` 和逆向 BFS 判定显示，会让相机模式错误显示本地预览器。应先确定当前对应的图像源节点，再读取其 `SourceKind` 决定可见性；节点选择、连线增删、来源切换、标签切换及方案恢复后都应刷新。不能仅用 `_currentDisplayNodeId` 判断是否需要重绑：同 ID 的节点/输入源在恢复或模式切换后可能已换实例。
- 多个上游图像源时，优先使用节点显式选定的图像输入/显示来源；无法确定唯一来源时隐藏本地预览器并提示选择，不应沿用“按节点 ID 取第一个”而展示错误列表。子程序若沿用父级来源，只有父级当前来源确为本地图像且绑定仍有效时才保留预览器；否则隐藏，不保留过期状态。
- 上方图像结果画布不受 `ShowImagePreview` 控制；相机模式仍可显示实际采集帧，本地模式显示载入结果。隐藏下方预览器不意味着断开相机、清空节点本地配置或清空已正确归属的结果图像。

## 4. 执行语义

### 4.1 本地图像

工作流在本轮开始前从图像预览器维护的、**属于当前节点**的 `ImageInputSource` 中冻结当前选择，生成执行快照；图像源据此读取文件并输出。现有 `WorkflowExecutionManager` 已按当前 `InputSource` 生成 `FilePath` 覆盖快照，实施时复用、收口这一链路，不让工具直接读取 UI 控件或依赖预览器是否可见。没有选图、文件缺失或解码失败时本轮失败，不复用旧结果。预览器隐藏并不清空输入源；只有本地模式参与文件路径覆盖。

### 4.2 相机

工作流在本轮开始前冻结 DeviceId、超时和输出配置。图像源通过 `ICameraCaptureService` 异步请求一帧：连续模式取下一张有效帧；软件触发模式按相机真实配置触发一次并等待；硬件触发模式在超时内等待外部触发。取消、断线和超时均结束等待并返回明确结果。节点执行完毕不关闭已有应用级连接。

相机模式不从 `ImageInputSource` 注入 `FilePath`，也不因本地预览器隐藏/显示而切换设备连接。现有执行管理器对所有 `ImageLoad` 节点无条件覆盖 `FilePath`（无图时覆盖为空）的行为必须改为按 `SourceKind` 分流；相机分支仅使用冻结的设备引用和采集参数。两种分支共用输出图像契约。

设备列表的连接 ToggleButton 仍是显式连接入口；方案打开时继续按现有 AutoConnect 规则恢复。首版若节点运行时设备未连接，应提示用户连接或检查自动连接，不静默改变连接状态。

### 4.3 并发与帧所有权

同一设备的预览、工作流和多个图像源节点必须经应用级取帧协调器仲裁。一个 SDK 句柄不能由多个消费者各自并发调用取帧；应复用已有会话并统一分发帧，或在过渡阶段显式互斥并给出占用提示。CameraFrame 持有图像所有权，释放 Frame 会释放 Image；交给下游前必须深拷贝或完成明确的所有权转移，结果被替换/清除时释放旧图像。任何失败均不能把上一帧作为本轮成功输出。

| `WorkflowNode.InputSource.ConfigChanged` 通过 `ImageInputSource.ToConfig()` 整对象替换 `ImageSourceConfig` | 扩展配置后改为按字段合并本地列表/索引/运行选择，保留 `SourceKind`、DeviceId 和相机设置；恢复方案时不要让本地回调覆盖相机配置 |

| `Plugin.SDK` 已有 `IAsyncToolPlugin`、`ToolExecutionRequest` 与 `ICameraCaptureService` | 向本次工具执行请求注入应用级相机服务，插件只依赖 SDK 契约，不引用 UI/DeviceDriver |
| `CameraRuntimeManager.CaptureAsync` 每次独占 OpenAsync 再关闭 | 先改成复用已有应用级会话，解决设备列表已连接时的 `already in use`，并明确新建连接的所有权 |
| MVS 取帧部分按缓冲区长度推断通道数 | 基于实际 SDK 像素格式做映射/转换，避免 Bayer 或其他格式误标 |

工作流执行层不访问 WPF 控件；新增运行时服务依赖必须评估 `Plugin.SDK`、Workflow、UI 宿主和插件部署的跨模块影响。

## 6. 持久化与输出契约

方案保存来源类型、两种来源各自设置、稳定 DeviceId、本地文件路径列表及选择状态，不保存 SDK 对象、连接状态、图像缓存或采集帧。`ImageInputSource` 只代表本地输入状态；其变化只更新统一 `ImageSourceConfig` 的本地字段，不能重建整个配置导致相机字段丢失。旧 `ImageLoad` 方案缺少 `SourceKind` 时默认为本地图像，原图像列表和下游绑定保持有效。

保留旧输出：`OutputImage`、`GrayImage`、`Width`、`Height`、`Channels` 等；新增 `SourceKind`、`SourceDeviceId`、`Timestamp`、`SequenceNumber/SN`、相机原生 `FrameId` 和实际 `PixelFormat`。SN 与原生 FrameId 分开定义。输出图像的生命周期必须覆盖结果缓存替换、工作流停止和方案切换。

## 8. 分阶段实施

1. **配置与 UI**：扩展持久化配置并将本地状态回写改为字段合并；完成来源切换动态布局、下方预览器按节点/来源显示、即时绑定刷新及旧方案迁移，不改动上方结果画布的通用职责。
2. **执行契约**：图像源接入异步工具路径，注入应用级 `ICameraCaptureService`，保持插件不依赖 UI/厂商 SDK。
3. **相机运行时**：复用已有会话，解决预览/工作流争抢取帧，处理并发、取消、超时和断线。
4. **输出与内存**：按真实像素格式转换，明确帧/结果所有权，保留旧输出并增加来源元数据。
5. **验证与交付**：做单元/集成、UI 设计时和运行时、真实海康相机、Debug 与全量 Release 构建及运行验收。

## 9. 验收标准

- 旧本地图像方案无需手工修改即可打开、选择和运行；图像预览器管理的当前图像可准确进入工作流。
- 选中本地图像源或其明确对应的下游节点时，下方预览器显示并绑定同一列表（空列表也可添加）；相机源或其对应下游、无选中/无可确定来源时隐藏，图像结果画布仍可显示输出。
- 同一节点本地/相机来回切换立即更新可见性；切回后本地列表、当前索引、勾选与运行模式保持不变。多上游与子程序不展示错误或过期列表；切换工作流/恢复方案不留下旧输入源绑定。
- 预览器增删/切换图片后，相机 DeviceId、来源模式和相机设置不丢失；相机模式执行不读取残留本地 `FilePath`，本地模式执行不触发相机取帧。
- 本地自动切换只在成功运行后推进；最后一张停止规则明确，失败不跳图。
- 关联相机选择在保存/重启后仍指向同一稳定设备，离线时不悄悄改选。
- 设备列表已连接的相机可由图像源稳定取帧；预览与工作流并发不争抢 SDK；运行/关闭节点不意外断开原连接。
- 软件/硬件触发、超时、取消和断线有明确结果；失败不输出旧帧。
- 图像格式、SN、原生 FrameId 和时间戳正确；下游旧绑定仍可用；多轮执行和方案切换没有图像资源泄漏。
- 分别完成 Visual Studio 设计时、运行时及真实设备人工验收；未验收项不得标记为已完成。
