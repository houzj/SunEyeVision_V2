## 这里原来是什么

原 `10/21/` 目录直接存放整个《架构对照》专题站点的全部产物：能力对照页、工具详情页、审计页、优化方案页、历史归档页，以及 `公共资源/数据/` 下的页面数据脚本。共 544 个文件、约 84 MB，占全库 `docs` 体积的约 65%。

问题不在内容，而在位置：它被放在一个"一次性日期目录"里，但实际是长期迭代的站点，导致

- 打开 `04-工具设计` 看起来像"10 月 21 日的一批文档"，掩盖了它是活站点；
- 索引只登记 `.md`，这套 html 完全不可检索；
- 全库文档数、体积统计被这一个目录主导。

## 现在怎么放

| 位置 | 内容 |
|---|---|
| `10/21/index.html` | 唯一入口页，说明来源与去向，并链接归档站点 |
| `10/21/README.md` | 本文件 |
| `10/21/archive/架构站点-20261021/` | 原站点整树（544 个文件），内部相对链接保持不变 |
| `10/21/archive/`（原有） | 站点自身原有的 `archive` 子目录（1 个文件），保持原位 |

整树搬移而不是逐文件搬移，是因为站点内 `index.html`、`公共资源/数据/page-data-*.js`、`优化方案/references/*` 之间是相对路径引用，逐文件搬运会断链。搬移后目录层级与原来一致，直接用浏览器打开归档首页即可正常浏览。
