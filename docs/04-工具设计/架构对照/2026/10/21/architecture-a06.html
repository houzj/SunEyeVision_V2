本项选择与代价

借鉴VM结果/显示分层与轮次门；自研重做有界结果协议

ResultSnapshot不可变；以Project/Run/Scope/Frame/Schema寻址；先接纳Owner再发布；可靠业务与UI LatestOnly分流。

收益与成本

多消费者解耦和防旧轮；队列容量、保留窗口、错误与背压需定义。

为什么不选替代路线

统一无界事件简单却可能泄漏；业务可靠/UI最新分流增加背压和确认复杂度，换取可诊断的资源与交付保证。

拟议接口与数据字段

ResultAddress { ProjectId, RunId, ScopeId, NodeId, Iteration, FrameId, SchemaVersion }
ResultNotification { Address, Quality, Sequence, ProducedAt }
AcquireOutcome AcquireResult(ResultAddress address);
Subscribe(DeliveryPolicy { Reliable | LatestOnly, Capacity, Retention });
Subscription { Dispose(), DrainAsync(), DisposeAsync(), Ack(ResultAddress), Fail(ResultAddress, Reason) }

状态与生效时点

Owner先接纳不可变ResultSnapshot再发布地址；同Run/Scope的sequence单调，UI拒绝旧轮覆盖。可靠通道入队时为消费者固定结果使用权，确认或显式失败后退还。

Owner与释放责任

ResultStore拥有保留窗口和lease；订阅拥有队列及已固定使用权，UI仅持最近投影；DR三仓是VM局部机制，不能等同该目标。

失败、取消与幂等

Acquire可返回ResultExpired。Reliable满队列背压或拒绝并记录失败，不静默丢失；LatestOnly可合并并释放被替代项。订阅同步Dispose幂等，仅禁止新投递/启动handler并发起退订；DrainAsync或DisposeAsync等待已启动handler及队列处理结局。handler禁止同步等待自身Drain，检测后返回SelfDrainNotAllowed；ACK/显式失败归还队列所持结果权。

版本与兼容

事件携带协议版本、schema及身份；新增字段可忽略，质量枚举未知按Unknown处理；保留窗口和丢弃计数可查询。
