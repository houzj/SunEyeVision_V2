本项选择与代价

借鉴VM纯API/控件职责拆分；自研重做程序集边界

Tool.SDK纯运行；Controls.Wpf可选，Editor按ToolId关联；开发调试宿主调用同一Runtime，不让Tool.SDK依赖Runtime。

收益与成本

无UI运行和独立工具开发；Editor清单/版本/BAML兼容需额外发布验证。

为什么不选替代路线

一个WPF SDK便于分发但牵连所有客户；拆包增加发布矩阵和兼容成本，换取独立运行与工具开发。

拟议接口与数据字段

ToolManifest { ToolId, ToolContractVersion, Lifetime, ThreadSafety, InputSchema, OutputSchema }
EditorManifest { ToolId, EditorContractVersion, FactoryType, ResourceUris }

状态与生效时点

Tool.SDK运行合同独立于Runtime.SDK/Controls；调试宿主通过同Runtime准备输入。编辑器加载前匹配ToolId/版本/资源，关闭只退还控件使用权。

Owner与释放责任

Project拥有工具，Editor拥有自身订阅与视觉资源；Viewer不拥有Project，工厂不得调用内部宿主静态服务。

失败、取消与幂等

Editor缺失可保留无UI执行；合同不兼容拒绝加载并给具体清单。初始化失败清已加载资源，关闭幂等；UI线程调度由Controls适配层承担。

版本与兼容

纯API发行验传递依赖；旧SDK/BAML/pack URI兼容发行另测类型身份与资源URI。TypeForward只在签名/全名兼容时采用。
