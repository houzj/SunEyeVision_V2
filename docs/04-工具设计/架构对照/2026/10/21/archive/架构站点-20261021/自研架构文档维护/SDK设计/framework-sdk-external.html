从加载到退出：每个API必须说明返回意味着什么

首期建议.NET 9 Windows x64同进程，公开Capabilities明确MaxHosts/MaxProjects/MaxConcurrentRoots初期限制，不声称多租户、跨平台或.NET Framework兼容。应用级数据接口保持可扩展，现有静态注册表隔离未解决前拒绝第二项目。

操作拟议API（未实现）语义/失败边界责任与限制VM对照与现状证据
建立宿主RuntimeHost.Create(options) → Capabilities配置插件目录、日志、native搜索和自有许可provider；Create只校验配置/建立对象图，耗时初始化在Open等异步阶段完成。不弹自研窗口、不默认抢占设备。Runtime.SDK提供，内部composition实现；一进程首期一个运行宿主。VM官方API/控件依赖分开；自研engine构造目前需内部对象。doc-packages · engine · sdk
加载方案host.OpenProjectAsync(path, options, ct)绝对路径/版本/插件/权限/资源先检查候选；失败不发布半就绪项目，候选资源退役。加载期间多数操作拒绝ProjectNotReady。Open选项默认RestoreDevices=None，客户显式启用设备恢复才连接。ProjectSession唯一Owner；首期MaxProjects=1显式能力，不把静态注册表包装成已支持多项目。VM Load、加载事件与方案操作；内部实现不能只从API文档推断。sdk-doc-solution · doc-events
定位流程与schemaproject.Flows.Resolve(idOrName); flow.GetSchema()名称只用于初次解析；后续用稳定FlowId/FieldId及schema版本；缺少/重名/失配返回诊断。外部应用面向流程的公开输入输出，模块路径只保留专家接口。VM推荐流程输出降低模块耦合。sdk-doc-output · sdk-binding
修改持久参数BeginEditAsync(expectedRevision) → CommitAsync按项目修订号提交候选，校验全部绑定/类型/设备前置；默认运行中拒绝结构性编辑，成功只改设计态，保存另行调用。Runtime.SDK负责事务；不会让客户直接修改活跃ToolParameters对象。VM ModuParams有配置和临时输入；自研需明确分合同。sdk-doc-module · sdk-parameters
更新全局变量project.Globals.UpdateAsync(expectedRevision, values)更新全局设计值/修订，下一根运行冻结；当前Run及子Scope继续读旧快照。即时控制指令另走设备API，不伪装成变量。所有值校验类型与可变资源；不得提供未定义写回的共享可变字典。VM有全局模块入口；原SDK未据此证明自研所需快照语义。sdk-doc-globals · sdk-reader
准备当次输入flow.CreateRequest() → Inputs / ParameterOverrides只对本次Run有效，输入/ROI/覆盖参数不写入方案；数组/图像按明确copy/retain政策冻结，缺少必填输入拒绝。输入Owner在接纳前归调用者；Start接纳成功后运行持有必要lease。VM示例明确临时输入当次有效。sdk-doc-procedure · sdk-doc-module · sdk-request
开始执行flow.StartAsync(request, admissionToken) → RunHandle返回仅证明接纳，不证明执行结束；schema/定义/全局修订及身份冻结，忙则Busy，未获资源前可取消接纳。admissionToken只控制接纳；Run返回后取消运行用StopAsync，不把取消一次等待当停机。VM Run有bIsWait/执行计数；自研对外优先异步显式handle。doc-flow · session
等待运行run.Completion → RunOutcome包含约定的执行、在途观察和本轮收尾；Completed/Failed/Cancelled/Quarantined分开。等待者取消只结束等待。run.Completion.WaitAsync(waitToken)不自动停止硬件；业务取消后仍须StopAsync并观察结局。VM事件与等待参数不能代替自研终态保证。doc-flow · doc-events · engine
读取结果run.AcquireResultAsync() → ResultLease按Run/Scope/Frame和schema取得本轮只读快照；Read<T>/TryRead检查Quality及形状，失败不能回退旧成功。结果lease独立于显示；不让客户读取CurrentContext最后值猜轮次。VM每轮重新取得ModuResult，推荐流程输出。sdk-doc-output · sdk-doc-procedure · result
订阅结果project.SubscribeResults(filter, handler, options) → Subscription通知只带结果地址/版本/状态，不自动转移像素Owner；按Run/Flow/Scope过滤，业务记录与UIlatest-only分通道。回调不在执行/全局锁内运行；异常记录并隔离。Subscribe状态不决定运行是否保存结果。VM文档警示回调中耗时渲染阻塞下次运行；自研应隔离该负担。doc-events · sdk-doc-events · vm-queue
停止单次/连续run.StopAsync(deadline)；controller.StopAsync(deadline)请求停止新派发，取消并等待在途；连续控制器停止覆盖其所有iteration。超时返回隔离而非成功完成。不支持取消的native调用不得强制释放正在使用的资源；状态保留故障及恢复条件。VMContinuousRunEnable=false是官方调用方式，内部排空仍需逆向证据。sdk-doc-solution · sdk-doc-procedure · engine · feed
保存方案project.SaveAsync(expectedRevision, path?, ct)只保存已提交设计态，临时输入、当前结果、设备句柄不入文件。文件成功而索引失败分阶段反馈；另存资源复制政策明确。仅Ready/允许保存状态；未决编辑或过期revision拒绝，native副作用不当文件事务一部分。VM Save/SaveAs与配置操作分开。sdk-doc-solution
关闭项目/宿主project.CloseAsync(deadline) → CloseOutcome；DisposeAsync停准入→停连续/单次→等在途和回调→退订→等外部结果lease→释放项目实例；最后host释放应用设备/许可。重复调用共享同一退役任务；未排空保留隔离，Close/Dispose失败可观察，不悄悄回到Idle。VM例程CloseSolution/Dispose及退出前释放，避免析构函数调用。sdk-doc-solution · doc-wpf · feed

正常单次的外部程序示例

// 设计示例：以下RuntimeHost等API均未实现，非可直接编译的产品代码。
await using var host = RuntimeHost.Create(new HostOptions {
    PluginDirectories = new[] { pluginRoot }, LicenseProvider = ownLicenseProvider
}); // 不启动自研主窗；不默认连接全部设备
await using var project = await host.OpenProjectAsync(solutionPath, openOptions, ct);
var flow = project.Flows.Resolve(flowId); // 名称可先解析一次，保存稳定ID
var schema = flow.GetSchema();
using var subscription = project.SubscribeResults(
    new ResultFilter(flow.Id), n => uiQueue.Post(n.Address), LatestOnly);
using var input = host.Images.CopyFromPixels(bytes, width, height, stride, pixelFormat);
var request = flow.CreateRequest(schema.Revision)
    .WithInput(inputFieldId, input)
    .WithParameterOverride(thresholdFieldId, 128); // 只对当次Run有效，不写方案
await using var run = await flow.StartAsync(request, admissionToken);
// Start返回仅代表接纳；admissionToken不再用作运行停止信号。
var outcome = await run.Completion; // 等约定终态，不只等“命令已发送”
if (outcome.State != Completed) { ShowFailure(outcome); return; }
using var result = await run.AcquireResultAsync();
double score = result.Read<double>(scoreOutputId); // 检查Quality/type/schema
using var image = result.AcquireImage(imageOutputId); // 显式图像使用权
var pixelsForLater = image.CopyPixels(); // 需要脱离lease长期保存时复制
// 反向释放 image/result/run/input/subscription/project/host。
// 生产应用另用关闭协调器保留主异常并聚合收尾异常，参见故障与寿命合同。

修改方案与取消等待的独立示例

// 拟议：持久修改；同“当次参数覆盖”分开。
await using var edit = await project.BeginEditAsync(expectedRevision, ct);
edit.SetParameter(nodeId, parameterFieldId, newValue);
var commit = await edit.CommitAsync(ct); // 校验并采用候选，默认运行中拒绝结构修改
await project.SaveAsync(commit.Revision, destinationPath, ct);
// 拟议：取消等待不自动停运行。
try { await run.Completion.WaitAsync(waitToken); }
catch (OperationCanceledException) {
    var stop = await run.StopAsync(stopDeadline); // 独立控制操作
    if (!stop.Drained) ShowQuarantine(stop); // 不继续释放被native使用的资源
}

连续运行：StartContinuousAsync返回Controller；每轮具有独立Iteration/Frame身份和输入请求。InputProvider每轮提供数据，重复固定图像必须显式选择；StopAsync停止新轮并等待所有在途。结果通知不可代替controller.Completion；事件未订阅也要有运行结局与可查询结果。

避免完成与取结果循环等待：Completion等待执行任务、回调和本轮临时资源收尾，不等待未来才会获取的ResultLease。RunHandle活着时固定本轮结果版本；handle释放后禁止新Acquire，已取得的ResultLease继续持有自身资源引用。最终像素释放发生在结果Owner及所有使用权退出之后，不因Completion立即销毁。
