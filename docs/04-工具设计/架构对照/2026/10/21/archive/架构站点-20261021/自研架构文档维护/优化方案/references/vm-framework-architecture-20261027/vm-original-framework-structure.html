只读逆向VisionMaster 4.4.0静态/反编译证据

VisionMaster 原厂框架：层级分布与源码组织逆向

本报告重建 VM 原厂框架本身：程序集层次、职责边界、类型关系、关键源码文件和调用路径。反编译导出目录不等于厂商原始源码树。

当前确认的主干：VM.Core 持有方案/流程/模块对象模型与参数门面；VM.PlatformSDKCS 封装 native Platform SDK 调用与回调；VMControls.WPF 提供流程配置、通用参数页和结果呈现；Apps.XmlParser/Apps.XmlUI 解释参数/显示资源并生成通用参数 UI；具体工具包提供模块包装器、资源和算法组件。启动和保存分别有独立调用路径。下文按证据展开，未知项明确标记。

框架关系总图

实线边来自反编译源码/程序集引用；组件物理部署位置不用于推断进程隔离。native SDK 之后的内部实现尚未从托管调用链还原。

二、参数对象与通用配置页的数据流

VM.Core.ModuleParam 实现 IParamsConfig 等接口，是模块参数访问门面；它把字符串键读写转发到 SDK 的 GetParamValue/SetParamValue，二进制键走 GetBinaryData/SetBinaryData。参数 setter 记录 Undo/Redo 并通知 Parent.OnModuleParamChanged。XmlPath 指向参数 UI schema；Data 缓存解析出来的参数树。运行参数值仍由该对象访问 SDK；参数树/XML 属于 UI 声明与编辑呈现模型，不应误作算法输出对象。

四、框架内部边界：模块、参数配置与执行桥

反编译源码比单看目录名更具体地显示了框架分工。下面是目前已恢复的托管侧关系；SDK wrapper 下游的 native 调度和未追完的持久化细节仍需继续取证。

VmModule.CreateToModuleSet(...) 组装 IMVS_SYNC_ADD_ONE_MODULE_INFO 并进入 SyncAddOneModule；VmModule.Run() 读取 moduleInfo.nNodeID 后进入 ModuleManager.SelfRun。Blob 包装器调用的 SyncSelfRun(ID) 与这条通用机制相吻合。VM.Core 的 Save/SaveAs 入口和结果回调类型已见，但序列化器到 native 持久化的完整链还未闭合。

通用参数页不是“每工具一个必需 WPF Control”

ProcedureConfigControl.OpenParamsTabControl 检查模块目录中的 <type>.xml、<type>AlgorithmTab.xml、<type>Display.xml；再尝试装载可选的 <type>Control.dll 扩展并查找 TabWinBase 派生窗体。没找到扩展时构造通用 ParamsTabControlBase，将 vmModule.Params 赋给 ParamsConfig。通用窗体的 XAML 中由 paramstab 把数据交给 Apps.XmlUI 的参数控件；Apps.XmlParser.ParamTab.AlgorithmTabRoot 承载 AlgorithmTab 参数树/绑定相关数据，VmModuleExtern.GetParamRoot(ModuleParam) 从 param.Data 惰性创建根对象。

当前证据说明参数 UI 由 VMControls.WPF 的窗体调度、Apps.XmlParser 的参数树及 Apps.XmlUI 的控件协作。AlgorithmTab XML 的每类字段如何读写 VM.Core 参数、运行前怎样冻结/转换、显示 XML 与结果对象如何完整配对，仍应逐成员追踪，不能仅凭这些类名宣称全链已闭合。

执行、结果事件与保存调用

VmModule.Run() → ModuleManager.SelfRun(nodeID) → SDK native IMVS_SelfExecuteOneModule。同步 SyncSelfRun 按 node ID 重置等待状态、调用 native 执行接口并查询状态/等待完成标志。这支持“工具执行由 VM 执行框架调度”的结论；不证明 native 算法内部执行细节。

结果事件链：SDK ModuleManager 订阅 native module-result callback 并做 PreProData；VmSolution 按 module ID 更新 IO 树并把模块结果事件送入回调队列；RenderControlBase 弱订阅 IVmModule.AsyncModuleResultCallBackArrived；ModuleResultView 收到事件后从 RenderDataCenter 交换对应执行轮次的数据，再刷新图像/形状/结果树。QueryModuleOneResult 是另一个主动查询方法，不能与异步 UI 回调机制混为一谈。图形/文本/接管判断字段各自的资源映射仍需进一步按工具追踪。

保存调用：VmProcedure.ExportFile/SaveAs → CollectionManager.SyncExportProcess → native IMVS_ExportProcess；同步路径等待 export callback 并检查 error code。Solution 保存由独立 SolutionManager 路径处理。现有证据不支持“VM.Core 自己把整棵模块树序列化”，也不证明每次参数写入都同步落盘。

六、厂商原始源码目录能确认的范围

源码逻辑组织已恢复

厂商物理源码树未知

analysis/decompiled 的路径和导出 .csproj 是反编译/审计产物，不可直接视为厂商原工程目录。当前安装件扫描只找到少量示例/脚本工程，未观察到完整主程序/框架源码解决方案；因此不能声称恢复了原仓库的物理文件夹结构。

后续逆向缺口

所有模块加载分支、参数 Schema 到 native 参数的逐项映射、图形/文本/接管判定结果到消费者的数据流、Solution 序列化内部、native Platform SDK 及会话释放/错误分支尚未完全闭合。它们是尚待继续取得源码/二进制证据的问题，不以猜测补全。
