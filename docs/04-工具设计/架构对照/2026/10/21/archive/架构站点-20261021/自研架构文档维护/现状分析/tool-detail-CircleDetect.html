算法与输入前提

模型只供取点；拟合助手拒非有限/重复退化点，geotukey预拟合 → 按径向距离筛内点 → 必要时geometric精化 → RMSE。并非直接采用Metrology模型拟合圆。

核对项自研实际语义原版边界 / 差异与影响
圆/弧guide与卡尺模型用于取点，Mask过滤后自行拟合；圆弧角区间按guide合同，不借无序点native弧端点原FindMode/粗检/InitType声明不是同一实现
DistanceThreshold / 拟合独立点/非共线/归一化→geotukey→径向残差筛选→必要时geometric；至少3内点原FitFun/RejectNum不同可配置语义待证
Center/Radius/RMSE列→X、行→Y；RMSE是内点半径残差；不设置卡尺支持率门槛原score/逐点状态不能直接映射当前RMSE

参数生效条件与单位

引导圆/弧、测量带、数量/sigma/threshold、极性/选点、距离阈值；不能把固定拟合策略说成可选全部FitFun。

输出、排序与失败语义

Center、Circle或Arc、RMSE、内点及诊断测量带/排除点；没有克隆输出图像缓存，仍依赖输入图像/显示上下文。

已识别差异

当前有引导圆/弧，不是所有圆查找模式

问题与尚待核实的边界

当前是有引导几何的测量取点与固定拟合；原声明的粗检/初始化/拟合选项未覆盖。创建模型在主try外的异常应归统一失败边界。

这个工具界面实际做什么？

基本参数含圆/弧测量编辑器，运行参数含卡尺/极性/拟合阈值，结果显示配置；主图由宿主注入。

CircleDetectTool.Run → 修正guide → AddMetrologyObjectCircleMeasure/Apply → Capture测量点 → Mask过滤 → MeasuredCircleFitting.Fit → 圆/弧/诊断

参数里存什么

引导圆/弧、测量带、数量/sigma/threshold、极性/选点、距离阈值；不能把固定拟合策略说成可选全部FitFun。

实际算法/处理

模型只供取点；拟合助手拒非有限/重复退化点，geotukey预拟合 → 按径向距离筛内点 → 必要时geometric精化 → RMSE。并非直接采用Metrology模型拟合圆。

数据交给谁

Center、Circle或Arc、RMSE、内点及诊断测量带/排除点；没有克隆输出图像缓存，仍依赖输入图像/显示上下文。

缓存在哪里

HMetrologyModel每次新建using释放；未见跨轮模型缓存。

失败、取消与释放

模型局部using及助手XLD/tuple局部清理不证明输入转换/宿主结果全部释放；Run无内部取消点，不能承诺原生Apply立即停止。

具体缺点和VM差异

当前是有引导几何的测量取点与固定拟合；原声明的粗检/初始化/拟合选项未覆盖。创建模型在主try外的异常应归统一失败边界。

VM原始资源能证明什么？

原声明FindMode/CoarseDetectFlag/InitType/FitFun/RejectNum及逐点状态/卡尺输出；native拟合及粗定位数值基线缺失。
