算法与输入前提

ThresholdTool.Run：灰度转换→检测ROI减Mask→Restrict有效域→SelectBasic或SelectAdaptive→域内反转→Render输出图及0/255掩码→统计/质量判定。SelectBasic直接Threshold并按模式取当前domain补集；自适应在FullDomain算局部图，DynThreshold传-c后交有效域。

核对项自研实际语义原版边界 / 差异与影响
Type / MaxValue分割区域与渲染输出分开；Trunc/ToZero不是统一二值图原BinaryType/ROI外政策仅声明，未确立一一等价
UseAdaptive / AdaptiveOffset邻域图使用FullDomain；实际DynThreshold偏移=-C原局部公式与边界未闭合
WhitePixelRatio白区域像素 / 全图width*height ×100原输出比率分母未知，不能默认按ROI相同

参数生效条件与单位

Type保留Binary/BinaryInv/Trunc/ToZero/ToZeroInv模式；UseAdaptive仅允许Binary/BinaryInv；Threshold与MaxValue分别控制分割/输出值，BlockSize和AdaptiveOffset决定局部阈值，不是全图统一阈值。

输出、排序与失败语义

OutputImage按Type渲染，截断/置零模式不保证二值；BinaryMask固定0/255。GrayImage/ReducedImage另克隆。WhitePixelRatio分母为width*height整幅图，不是有效ROI面积；质心列→X、行→Y；执行成功与IsPass分开。

已识别差异

ROI面积缩小时白像素比例仍除以整幅面积；若读者按ROI占比理解会误判。局部ThresholdUsed=-AdaptiveOffset只是偏移的报告，不是单一分割阈值。不能按同名二值化工具声明其与VM公式等价。

编辑、确定、X与执行副作用

配置采用与设备/文件副作用分开。关闭不是“全部回滚”；以下是当前政策，不是完整生命周期验收。

图像阈值化 · 静态编辑政策已定位；产品关闭/重入/native寿命未验

编辑写到哪里

主窗把node.Parameters原对象交给控件，控件持typed引用；不是整窗草稿。部分控件仍有pending值，不等每按一键都写回。

确定

确定先TryCommit控件编辑，再校验参数；标准壳没有统一取消全部已生效修改。

X / 取消

X先TryClose：有效pending提交，无效可明确放弃尚未提交值；已经live写入参数的修改保留。

执行或编辑副作用

默认ExecuteToolAsync是Task.FromResult(ExecuteTool())，不自动后台运行；同步native计算不保证UI能及时关闭。

谁负责关闭

壳Closed停连续标志并退订事件，不等可等待执行会话或全部图像/native最后读者。

具体改法

先明确实时保存政策；若需整窗取消再引入逐工具草稿，不对全部native对象盲目深拷贝。外设/文件动作单独显示并确认。
