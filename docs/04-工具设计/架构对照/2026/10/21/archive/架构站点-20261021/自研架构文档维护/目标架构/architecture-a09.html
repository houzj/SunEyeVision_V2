本项选择与代价

借鉴VM公开方案/流程API；自研新建应用边界

Runtime.SDK公开Host/Project/Flow/Run，不暴露UI或内部Engine；后端接口经Contracts注入。

收益与成本

客户不拼内部对象；要承担公共API版本和错误语义维护。

为什么不选替代路线

直接公开Engine省包装但绑定内部装配；选择应用门面，承担公共API兼容、部署和错误语义维护。官方V4.4.2指南不直接承诺net9兼容。

拟议接口与数据字段

RuntimeHost Create(HostOptions options, IRuntimeBackendFactory backend);
Capabilities { Platforms, MaxProjects, MaxConcurrentRuns, DeviceAutoConnect, ContractVersions }
OpenOutcome OpenProjectAsync(ProjectSource source, OpenOptions options);
ProjectSession { Flows, BeginEdit, StartAsync, AcquireResult, CloseAsync }

状态与生效时点

Open构造隔离候选，校验插件/资源/版本后才发布Ready；默认不自动连设备。能力不足在接纳前拒绝，首期平台与多项目限制须如实返回。

Owner与释放责任

Host拥有后端与Project，Project拥有运行；客户拥有Session使用权并显式关闭；Controls只借用Session。

失败、取消与幂等

加载失败清候选、旧项目仍可用。重复Open按OperationId去重，路径相同不默认共用可变项目；重复Close按A08。许可和设备错误具有不同错误码。

版本与兼容

Runtime.SDK只依赖Contracts，通过工厂注入后端避免循环；API协商主版本，禁止暴露Engine实现类型和WPF类型。
