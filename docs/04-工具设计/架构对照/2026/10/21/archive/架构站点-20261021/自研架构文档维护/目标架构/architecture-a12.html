自研当前边界

自有授权策略、狗SDK和能力撤销尚无该批运行验收，不得因VM启动门就认定自研已具备。

VM · 已证与未知

VM已证 / 未知

原启动有授权/显示门，但许可协议与自有产品授权政策不能由恢复实现直接替代。

本项选择与代价

自研独立设计；不迁移VM狗体系

自有LicenseProvider在宿主能力门控制；许可、设备连接和文件加密职责分开；首期同进程，进程隔离为可选后续能力。

收益与成本

适配自身商业部署；需自有狗SDK和签发/失效政策，不能假称已具备。

为什么不选替代路线

复用VM授权体系不适合自有部署；独立设计有签发、失效和商业策略成本，但职责和产品控制更明确。

拟议接口与数据字段

ILicenseProvider.Evaluate(CapabilityRequest request) => CapabilityDecision;
CapabilityDecision { Allowed, ReasonCode, PolicyVersion, ExpiresAt }
LicenseChanged { Sequence, CapabilitySet, PolicyVersion };

状态与生效时点

Host在新运行/设备操作准入检查能力；运行中失效关闭新准入，已有任务安全收尾。许可、设备连接、文件加密各自有合同。

Owner与释放责任

Host拥有许可provider及订阅；Run保持已接纳资源Owner，许可变化不拥有native释放权。首期同进程，进程隔离仅后续设计。

失败、取消与幂等

无许可/过期/后端不可用分别诊断，默认拒绝新能力；检查无副作用可重试，重复事件按sequence去重。不在native执行中强制Dispose。

版本与兼容

PolicyVersion与SDK版本独立；离线宽限/撤销规则由产品明确后再实现，不从VM许可协议推断。
