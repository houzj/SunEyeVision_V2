管理器：改的是设计初值

数据结构

每个变量有Id、Name、Group、Type、Value和生产/消费绑定。分组主要组织显示，运行字典使用变量名，不能把分组当成独立名称空间。

实际链

主窗口ShowGlobalVariableManager → ViewModel/真实方案变量 → 名称/类型/Value编辑 → 保存方案

事实

管理器“当前值”列绑定GlobalVariable.Value；文本编辑失焦按Type写单元素long[]/double[]/bool[]/string[]。这列不能自动解释为本轮生产者输出。

VM

原GlobalVariableItem有名称校验、类型解析和显示/绑定字段；对话框通过VariableManager管理分组及导入导出。native实际写入/事务仍缺证据。

改法

将Value列明确标“设计初值”，本轮运行值另投影并带Run/来源/有效性；复用现有变量Id，勿从零再造。

验收

改初值不被误报为运行输出；同名规则跨新增/改名/导入一致；复杂值只读/编辑范围明确。

绑定：谁生产，谁消费

数据结构

ProducerBinding记录一个流程/节点/结果字段；ConsumerBinding稳定键含流程、节点和InputKey/参数名。变量Id、显示名和结果字段Id是不同身份。

实际链

输入来源/目标输出设置 → ProducerBinding/ConsumerBindings → ParamSettings/字段对账 → 方案依赖图

事实

普通ParamSettings改名有传播，App还通知活跃ConfigSetting；方案图同时识别__GlobalVars__名称表达式与__VariableId__引用。不能因此宣称所有离屏专用协议行/脚本表达式都已迁移。

VM

VM原对话框存在绑定模块结果/目标的独立模型；不能只从UI字段名判定全部原生作用域规则。

改法

优先复核已有Id路径的消费者，分普通参数/嵌套行/脚本/子程序核改名删除；批量变更先预检后原子采用，失败保留可读失效原因。

验收

跨流程同节点ID仍定位正确；改名/删字段/删变量不静默改成旧初值；未实例化控件的引用也能诊断。

开始运行：本轮到底拿到什么

数据结构

方案运行先把无生产者且没有失效标记的设计值放进runtimeGlobals；有生产者的变量不以初值冒充本轮结果。

实际链

RunSolutionAsync → 依赖图/顺序 → 设计值ToDictionary → 各流程执行 → 本轮上下文

事实

RunSolution排除生产者初值，但选中流程单次/连续入口直接把全部设计Value组成字典，调试查询也复制设计值。节点__GlobalVars__合成结果来自上下文快照；与接收工具的生产者结果读取不是同一路径。入口策略不同已见，具体错误表现仍需同流程/跨流程场景验证。另ToDictionary/Clone只拷容器或引用，ValueGate不保护数组原地修改。

VM

原DynamicOutput按nValueNum复制公开int/float/string输出数组。它只证明查询出口复制，不证明VM所有运行值天然深不可变。

改法

先统一普通全局绑定/接收变量及单次/方案/调试入口的值来源，生产者值必须来自当前Run成功结果；不拿设计Value兜底。再逐类型规定复制：普通数组可边界复制，图像/原生对象显式借用或租约，BinaryPayload复用已有封装。

验收

运行中改初值及原地改数组均有确定隔离政策；不能把只读字典当完整深快照；图像复制点与最后读者配套。

生产者完成：更新运行值，不污染文件

数据结构

方案级调度推导生产者到消费者的跨流程依赖。成功生产者值发布到本轮runtimeGlobals，未成功的变量先移除。

实际链

执行流程 → ApplyProducedGlobalValues → 按ProducerBinding读取成功节点结果 → runtimeGlobals → 下一个消费者流程

事实

ApplyProducedGlobalValues先Remove变量名，再检查失效标记/节点成功/工具成功，成功才写本轮字典；不写Solution.GlobalVariables.Value。失败流程中独立成功生产者仍可被取出。这是方案流程边界发布，不能据此保证同流程普通全局绑定已读取生产者新值。

VM

VM模块结果绑定存在；原生生产/消费调度和失败值清除不由GlobalVariableItem展示字段直接闭合。

改法

保留初值/运行值分域，补运行值身份和诊断投影；逐直接单流程、方案RunAll、通信触发、调试入口核快照来源差异。

验收

生产者失败/未执行时消费者不回退设计初值或上轮成功；跨流程顺序按实际依赖；本轮发布不改变保存文件的初值。

消费者读取：数组和单值不能混用

数据结构

通用参数、接收变量和协议输入不是一个相同的消费者。接收目录当前只公开String/Integer/Double/Boolean/Binary；不能把词汇表所有类型都算通信已支持。

实际链

RuntimeVariableReceiveService → 本轮成功节点或运行字典 → Normalize/类型检查；协议另经ProtocolBindingInput.RequireScalar

事实

有生产者时检查成功和当前流程；普通变量由宿主ReadCurrentVariables读设计值。协议只接受标量或长度1数组，多元素数组明确拒绝自动展开。

VM

DynamicOutput的int[]/float[]查询为32位元素；VM变量UI也有double解析分支，不能将整个变量系统概括为只支持float32。当前long[]/double[]不自动与其ABI等价。

改法

为每类消费接口列允许类型、数组基数和作用域，错误指到变量/字段；不要因同名Integer就不检查溢出或因源是数组就自动取首项。

验收

空/单/多元素数组、类型变化、失败源、跨流程生产者及缺值各有稳定错误；通信不支持的图像/矩阵入口明确限制。

保存 / 导入：当前有具体缺陷

数据结构

变量保存最终调用方案服务；导入不是简单把旧Id换成新Id就足够，名称和生产消费引用也有合同。

实际链

管理器Save → SolutionManager.SaveSolution → Repository；Import → JSON反序列化 → 新Id → 直接追加集合

事实

管理器Save忽略SaveSolution布尔返回，随后写成功日志；Import循环直接追加，未调用已有IsNameDuplicate检查。原有RunSolution按Name.ToDictionary，导入精确重名会导致构造失败。

VM

原对话框ImportGlobalVar/ExportGlobalVar调用VariableManager并检查返回状态；原生.gvar完整格式、导入冲突/回滚内部语义仍未知。

改法

必须检查保存结果后再报告成功；导入先形成候选，校验名称/类型/身份/引用与重复策略，全批通过才采用。失败不留半批变量。保持原文件并设计可读诊断。

验收

保存服务返回false不报成功；同批/与现有变量重名不部分追加；原生产消费引用在跨方案导入时有明确重映射或断开策略。

文件类型与复制：实际有边界

数据结构

基础类型读写合同是T[]，变换、图像、RoI另走分支，不能从词汇表存在推全部序列化对称。

实际链

GlobalVariableValueConverter.Read/Write → SdkTypeVocabulary → 类型分支；GlobalVariable.Clone → Value引用原样复制

事实

ParseAdaptive拒绝历史标量JSON；外层版本迁移是否覆盖仍待核。SerializeValue图像分支实际是Mat，不能据IVisionImage类型声明推HalImage全支持。Clone生成新变量Id，但Value保持同一引用。

VM

VM公开查询的tuple数组与自有JSON格式是两层；没有原.gvar内部结构，不能宣称文件兼容迁移完成。

改法

明确版本化迁移与各图像后端文件合同；按变量值类型列复制策略。保留原文件，先转换候选再提交，不要求用户打开失败的旧方案后自行重新保存。

验收

新/旧标量文件、数组、Mat/其他图像后端、Transform/RoI、未知类型分别验；克隆后修改数组不意外影响源方案。
