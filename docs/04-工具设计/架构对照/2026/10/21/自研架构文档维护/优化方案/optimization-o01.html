O01 入口、装配与编辑事务

VM → 我们 → 目标：设计来源与取舍

同一职责逐项对照。箭头表示比较和设计选择，不表示已贯通的原版调用或已实施。目标尚未改产品代码。

编辑 / 语义 / 编译的分工

① VM 已证设计

AvalonEdit 编辑；VM.CodeCompletion 包装 NRefactory 提供语义候选；CodeDOM 编译。

⇄
② 我们的现状

AvalonEdit 编辑；Roslyn 提供语义、诊断与编译。

→
③ 目标方案

保留现有组件，分清会话、语义服务、编译服务、运行Owner。

借鉴职责分层；保留整改组件

VM部分首次更快，但已测语义上下文与现代语法不等价；不机械换栈。

证据与适用范围

原版ShellCodeEditor / BaseScriptSupport；自研ScriptEditorCore / ScriptCompiler；同能力矩阵70单元

基础预热与窗口打开

① VM 已证设计

构造时有同步基础加载，也有后台引用准备；源码不能证明先显示再准备全文语义。

⇄
② 我们的现状

共享MEF与空Workspace预热；真实文档语义着色完成后才显示。

→
③ 目标方案

保留有收益的基础预热；正确文本先可编辑，首屏语义优先。

借鉴后台准备；自研显示时序

已测预热可提前部分成本；不能把未测目标写成VM已实现，更不能将等待全移到首次输入。

证据与适用范围

ShellCodeEditor153/270-330；ScriptEditorCore179/341；MainWindowViewModel3855；WPF预热9进程

自动补全的触发与任务

① VM 已证设计

自动输入与CtrlSpace分支不同；部分连续字母输入抑制；候选按文本排序。

⇄
② 我们的现状

按输入查询Roslyn并在窗口内过滤；部分查询未传取消令牌。

→
③ 目标方案

当前查询优先；取消过期计算，并以文档/引用/请求代次拒绝旧结果。

借鉴避免无效查询；自研版本准入

少触发不等于引擎算得快；触发协议与能力分开验收。

证据与适用范围

myLibs-GetCompletions.il / ShowCompletion.il；ScriptEditorCore706-727/923；独立触发协议8单元

编译触发、缓存与失败

① VM 已证设计

提交代码后后台编译，执行按dirty补编；内存与加载时磁盘产物可复用。所见缓存未含引用。

⇄
② 我们的现状

已有编译缓存，但多入口预编译；确认/执行部分路径同步等待。

→
③ 目标方案

同键共享任务，执行只取当前快照成功产物；源码/生成IO/引用内容/选项入键。

借鉴提前准备与产物复用；不采用弱失效

VM失败后清dirty等是静态风险，非复现；重做状态合同以保证速度不损害正确性。

证据与适用范围

ScriptCom259/676/720；BaseScriptSupport86-220；ScriptDebugControl289-315；ScriptCompiler.ComputeCacheKey

运行实例与资源释放

① VM 已证设计

成功加载后Init，Process复用实例；关编辑器主要解绑界面回调，不等运行实例Dispose。

⇄
② 我们的现状

池复用ALC/程序集，但每次新建用户实例并Init/Process/Release；异常可能跳过Release。

→
③ 目标方案

保留逐次实例语义，finally清理；会话/运行/池各自Owner，迟到任务拒绝。

不采用VM实例复用；保留整改并自研Owner

直接常驻用户实例会改变字段/初始化语义；宿主DestroyModule调用仍有未知，不照抄未知生命周期。

证据与适用范围

RemoteLoaderFactory209-327；ShellRun758-778；ScriptLifecycleManager138/204-206；ScriptSandboxPool

程序集引用管理：五项核心设计差异

进程加载的程序集、补全分析的元数据、编译引用、运行解析分别管理；不能只数 DLL。

默认能力范围

① VM 已证设计

源码默认五项：mscorlib/System/System.Core/Windows.Forms/Script.Methods；用户可增引用

⇄
② 我们的现状

RequiredAssemblyNames取当前存在的BCL白名单+脚本SDK，当前还原32项；许多设为必需

→
③ 目标方案

拆分编译基础必需、脚本公共API、按需业务API、用户增量；逐项验证依赖闭包，不靠删DLL追求数字少

借鉴分层；自研验证规则

较窄默认暴露面易解释；但.NET9有类型转发/程序集拆分，五项不能机械照搬

证据与适用范围

VM ShellRun542-583、ShellCodeEditor333-361、ScriptCom768-823；自研MetadataReferenceProvider192-224

引用清单的事实源

① VM 已证设计

UI JSON及类型编码通过ScriptRefrence提交，编辑器/编译器各自映射

⇄
② 我们的现状

ScriptParameters.AssemblyReferences是节点清单，BuildReferences与编译都按清单解析；空清单编译另有fallback

→
③ 目标方案

保留节点声明清单，解析后生成同一个不可变ReferenceSnapshot，所有消费者使用同一版本；错误明确，不静默扩大引用

保留整改；自研统一

避免两套事实源；增加快照/验证职责，但可追溯错误

证据与适用范围

ButtonSelecter_Shell232-267；自研ScriptDebugControl124-135、ScriptCompiler185-218

路径与依赖解析

① VM 已证设计

类型0简单名称，3模块根目录，4模块DLL目录；运行AssemblyResolve另查已加载FullName与模块目录

⇄
② 我们的现状

ResolveAssemblyPath依次解析BCL/宿主锚点/用户目录；运行沙箱有独立解析

→
③ 目标方案

解析到确定路径及实际程序集身份/内容SHA；补全、编译、运行统一准入和冲突规则，部署由构建规则保证

借鉴职责分层；自研身份合同

不能仅用文件名判同一版本；路径优先级易造成同名不同内容的错误复用

证据与适用范围

ScriptCom768-823；ComScriptSupport49-89；自研MetadataReferenceProvider258-283、ScriptSandbox

元数据准备

① VM 已证设计

修改引用会重建补全服务；部分引用后台Cecil加载，部分Assembly.LoadFrom同步

⇄
② 我们的现状

编辑器逐项Resolve创建MetadataReference，再加入Workspace；有共享基础缓存，但按节点路径不等对象共享

→
③ 目标方案

缓存不可变元数据对象与可取消共享准备任务；文档会话保留独立状态；前台查询优先，显示引用准备状态

借鉴异步准备；整改复用与Owner

不能以后台启动当准备完成；并行失控会争抢CPU，需合并与调度

证据与适用范围

ShellCodeEditor270-330；自研BuildReferences、RebuildWorkspace、ResolveAssemblyPath

引用更新与缓存失效

① VM 已证设计

所见Refrences分支不直接dirty，编译缓存source+property+moduleId不含引用

⇄
② 我们的现状

代码/宿主版本/引用名称指纹用于编译及池键，引用目录和用户DLL实际字节未完整覆盖

→
③ 目标方案

引用增删、同名替换、生成IO合同或选项变化均生成新键；旧代次语义/编译结果不得准入执行

不采用原版弱失效；自研重做

内容指纹有I/O成本，可按确定文件版本缓存；不能长期牺牲正确性换命中率

证据与适用范围

ScriptCom335-345；BaseScriptSupport112-114；自研ScriptCompiler.ComputeCacheKey与ScriptSandboxPool

引用管理的证据边界
  • 默认五项不是进程所有程序集；元数据文件大小不是内存或所有类型都已解析
  • 引用成本9进程测试只覆盖基础样本，不证明默认范围一定过重或毫无影响
  • 部署SDK含WPF职责已由工程证实，但这不等所有依赖都会进入脚本分析；API拆分应另核实际签名
  • VM实际加载补全副本及SDK间接目标仍保留未知，不拼成已运行链

最终推荐：采用 A，按三个批次重构集成

这是经过原版取证、共同能力与引用范围测试后的设计裁决；本轮没有修改产品代码。不是优化后性能已通过。

保留 Roslyn 的依据是能力、语法与维护代价的综合取舍；VM 部分首次查询及组件编译更快的事实不变。不能承诺改完即达到 VM 的肉眼体验。

为什么选 A，为什么这批不选 B / C？

先比较后选择：共同能力、现代语法、外部类型上下文与长文重复查询，不能用部分首次查询优势替代完整能力。A当前首次成本真实存在，整改收益须以后产品验收证明。

候选优势本批取舍与代价
B部分小脚本首次查询及组件编译更快本批不换为已测VM/NRefactory包装与CodeDOM栈；所测共同外部类型上下文缺候选；现代模式变量缺；当前Framework CodeDOM现代4语法失败、旧语法正控制成功。适配补洞、语言降级与维护成本没有证明优于A；不是所有轻量引擎的全局结论；未测试的新引擎另需同矩阵决策
C理论上可分别利用组件优势本批不采用NRefactory语义+Roslyn编译混合；保留语义理解与编译语法差异、双引用/诊断/版本适配及维护成本；无完整组合性能证据；未构建组合，不把独立组件耗时相加当总成绩

如果A完成上述集成改造后，合法能力通过但目标性能仍失败，按同样例同引用另测具体替代引擎；必须证明语言/引用/诊断一致和端到端净收益，不能只以首查询成绩替换。

新增测试改变了什么？

共同组 A 23/23、所测 B 包装 21/23；不是完整软件能力评分。第二轮恢复同一静态上下文后，B 的 new / 外部成员候选恢复，typeof 类型仍为空；不能单定 static 是根因。修订 /nostdlib 后，旧语法正控制两边编译成功，四现代语法 Roslyn 成功、当前 Framework CodeDOM 返回语法错误；不外推所有 VM 配置。

八项不可降低的目标合同
职责目标规则
session每编辑会话一个Owner和文档版本；共享不可变MEF/元数据，不共享可变编辑状态。关闭取消会话任务，迟到结果不得访问已关闭视图。
