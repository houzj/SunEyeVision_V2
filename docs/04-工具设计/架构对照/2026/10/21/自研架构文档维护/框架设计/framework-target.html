目标架构

目标架构：复用执行基础，补成统一数据平台

下图为待实现职责，名称是建议命名；现有Session/Scope、ToolResults和设备适配器被适配复用，不声称当前已经存在这些完整层。

① 入口与编辑层

主窗/工具窗/脚本/通信请求

提交运行意图和配置候选；不执行调度、不保存裸运行结果真相。

应用SDK门面（新增）

RuntimeHost / ProjectSession，独立客户程序入口

对外Open/SetInput/Start/Stop/ReadResult/Subscribe/Close；不要求创建主窗。工具SDK与WPF Viewer/Editor独立可选交付。

② 运行协调层

RunHandle + Session/Scope + ResourceCoordinator

冻结版本、校验绑定、资源准入、派发、取消与最终排空；设备副作用可诊断。

③ 工具适配层

现有ToolExecutor / 强类型参数和ToolResults

从只读输入视图读取；返回候选Outcome与资源声明；不直接更新WPF控件。

④ 公共数据与发布层

FieldCatalog + ValueStore + ResultPublisher

地址/稳定字段/质量/版本/Owner共同管理；批次提交后发通知，订阅者错误隔离。

⑤ 消费投影层

绑定读取 / 树 / 图像 / 分析 / 记录 / 通信

按同版本读取，UI由Dispatcher采用；latest-only与业务逐条通道分政策。

⑥ 贯穿各层的资源治理

Frame/Tool/Device/Control的Owner与Lease

所有使用者完成后最终释放；共享native最后读者未知时不得擅自释放。

五种贯穿场景必须同时满足

场景拟议端到端顺序正确性门槛
正常单次冻结定义/参数/全局→预检与资源准入→执行→构造Outcome→提交字段批次→通知投影→使用者退役同一批次树/图像/通信身份一致；返回成功不早于执行结局，显示可以异步。
生产者失败生产者失败→消费者按依赖跳过或明确容错→发布失败/缺失状态→撤销当前有效投影不回退旧成功或设计初值；日志保留失败节点及来源。
停止与超时StopRequested→停止新派发→取消在途→等待工具/回调→排空或隔离→最终释放超时未排空不得释放共享设备；父Completion覆盖子Scope与收尾。
两次调用同一子程序同一根Run创建两个Scope→分别读取同版全局快照→按Scope存结果→显示选定调用同NodeId不同调用不覆盖；循环迭代和历史有独立身份。
相机快、算法/显示慢采集准入→明确最新值或有界逐帧策略→执行批次→UI合并→历史按需Retain接收/替换/交付可解释，UI跳帧不改变算法执行计数；资源不被显示池误复用。

运行完成、结果已发布、UI已显示、文件已保存、资源已退役是不同确认点。它们应关联同一运行身份，但不能压成一个IsRunning或Success布尔值。
