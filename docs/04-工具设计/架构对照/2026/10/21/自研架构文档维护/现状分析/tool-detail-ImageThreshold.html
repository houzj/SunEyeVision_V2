算法与输入前提

Otsu用max_separability/dark；Triangle本地求阈值且明确byte限制；自适应SelectAdaptive；范围Threshold(min,max)。局部自适应记录的-C是偏移而非全图唯一阈值。

核对项自研实际语义原版边界 / 差异与影响
Method / Invert基础5模式、Otsu、Triangle、局部均值/高斯、InRange按不同分支执行；反转限有效域原BinaryType/CompareType等不能按枚举数直接等同
Otsu / TriangleOtsu调用max_separability/dark；Triangle读取byte域直方图，以峰到较长尾连线最大垂距选阈值原自动阈值公式/相等端点与样本基线未闭合
BlockSize / C局部均值或有限高斯邻域；ThresholdUsed=-C不是一张全局阈值图原Sauvola字段声明不等已有同算法
OutputImage / BinaryMask模式渲染图和0/255区域掩码不同；统计白像素比仍用整图像素分母原OutputMask/ROI外像素策略另需对应

参数生效条件与单位

固定基础方法、Otsu、Triangle、自适应均值/高斯及InRange；Threshold/MaxValue/BlockSize/C/范围与Invert分开。

输出、排序与失败语义

OutputImage按模式渲染，Trunc/ToZero不一定二值；BinaryMask始终独立0/255掩码，GrayImage另克隆。下游必须绑定正确输出。

这个工具界面实际做什么？

基本参数/运行参数/结果显示三页；结果显示是判定与绘制配置，不能画成运行数值表。主图由宿主注入。

统一执行器 → ImageThresholdTool.Run → 灰度/ROI/Mask → 按方法求区域 → 可选域内反色 → Render图像＋RegionToBin掩码

参数里存什么

固定基础方法、Otsu、Triangle、自适应均值/高斯及InRange；Threshold/MaxValue/BlockSize/C/范围与Invert分开。

实际算法/处理

Otsu用max_separability/dark；Triangle本地求阈值且明确byte限制；自适应SelectAdaptive；范围Threshold(min,max)。局部自适应记录的-C是偏移而非全图唯一阈值。

数据交给谁

OutputImage按模式渲染，Trunc/ToZero不一定二值；BinaryMask始终独立0/255掩码，GrayImage另克隆。下游必须绑定正确输出。

缓存在哪里

本轮结果持有多幅图像，GetDisplayImages提供引用，不复制；无跨轮算法缓存证据。

失败、取消与释放

binaryRegion、reducedImage和scope有局部清理；GetHalconImage仍在try前；输出图像进入宿主后的最后读者未闭合。

具体缺点和VM差异

若只写“阈值输出二值图”会误导Trunc/ToZero消费者；当前未见Sauvola完整合同，不能以方法数代替覆盖比较。

VM原始资源能证明什么？

原声明CompareType/ThresholdOffset/NonROIPrcType、Sauvola系数/窗口以及InputMask/OutputMask。声明不证明原公式和数值边界。
