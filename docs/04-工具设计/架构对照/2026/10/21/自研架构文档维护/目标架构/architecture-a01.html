本项选择与代价

借鉴VM的分层入口；自研重做统一运行服务

统一主窗/SDK/触发入口；共享执行管线但保留流程/工具调试的不同策略。

收益与成本

一致语义、可无窗；代价是迁移UI编排和建立上下文。

为什么不选替代路线

只包装现有UI manager成本低，但继续泄漏UI生命周期；统一服务需要迁移装配。以运行模式策略保留流程/调试差异，不强迫两者共用旧结果。

拟议接口与数据字段

ValueTask<StartOutcome> StartAsync(RunRequest request, CancellationToken admission);
RunRequest { ProjectId, ExpectedRevision, FlowId, Mode, InputSet, Overrides, RequestId }
StartOutcome = Rejected(Diagnostics) | Accepted(RunHandle);
RunHandle { RunId, ProjectRevision, PlanId, Completion, ResourceRetired, ResultRetired, Dispose }

状态与生效时点

接纳时校验能力、依赖、输入和版本并冻结；Accepted仅代表已接纳。Rejected→无任务；Accepted→Running→ExecutionFinished。调试缺值必须显式注入或拒绝。

Owner与释放责任

Project运行服务拥有在途任务；调用者拥有RunHandle使用权，handle固定结果版本。Dispose后禁止新Acquire；已有ResultLease独立存活。Completion不等待未来Acquire。输入按A04/A07取得使用权后才发布handle。

失败、取消与幂等

接纳取消在提交点前拒绝；提交点后返回同一handle，不能取消等待就遗失已启动运行。RequestId在项目保留窗口内去重，重复内容不一致返回Conflict；窗口过后明确RequestExpired。

版本与兼容

请求和结果携带ContractVersion；未知必填字段拒绝。RunId由服务生成，不能使用UI tab身份。
