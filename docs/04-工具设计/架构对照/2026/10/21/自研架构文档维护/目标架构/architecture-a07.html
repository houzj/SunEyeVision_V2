SUN EYE · 自研

自研当前边界

旧IVisionImage Clone/Dispose不等于Retain；相机借用、拷贝和池覆盖边界需要分别定义。

VM · 已证与未知

VM已证 / 未知

DI01/02/03/07/08/09证固定数组、映射、静态池等不同寿命；共享池可回绕复用，不能照搬成永久缓存。

本项选择与代价

借鉴VM区分copy/pointer/mapping；自研重做安全使用权

ImageDescriptor记录格式/stride/坐标域；默认复制安全边界，可零拷贝但必须持有Owner lease；池不得覆盖在用区。

收益与成本

减少不必要复制且安全；引用计数/池预算/过期策略增加成本。

为什么不选替代路线

默认复制安全但有带宽成本；允许持lease的零拷贝，承担引用管理和池预算，不照搬VM静态池回绕行为。

拟议接口与数据字段

ImageDescriptor { Width, Height, PixelFormat, Stride, ByteLength, CoordinateSpaceId }
ImageLease Retain(ImageLease active);
OwnedImage CopyPixels(ImageLease active);
BorrowedImage Borrow(ImageLease active, BorrowScope scope);

状态与生效时点

CopyPixels独立存储；Borrow只在作用域内且父lease有效时使用，不得异步逃逸；Retain原子增加Owner使用权。池租出区直到最后lease退还才可复用，预算不足背压/失败。

Owner与释放责任

BufferOwner负责内存/映射句柄和最终释放；lease只负责归还使用权。Viewer各持独立lease，绝不按IO列表清除推断native已释放。

失败、取消与幂等

Retain与最后归还须原子互斥，退役后返回ObjectRetired；同lease重复Dispose无额外释放。复制失败销毁候选；取消不撤销已交付lease。旧Clone适配为Copy，不能伪装共享Retain。

版本与兼容

PixelFormat/stride/长度溢出在边界验证；跨进程mapping需另定句柄及代次协议，首期不承诺跨进程零拷贝。

DI01 · source-confirmed · SDK ImageBaseData.ImageData / ImageDataPtr

ImageData setter保留传入数组引用并置SetByte；ImageDataPtr getter在SetByte时pin该数组并返回地址，随后置UnSet。反向getter在SetIntPtr时复制到新数组并置UnSet，但保留旧指针字段。两个表示不等于自动同步的不可变副本；不能据已有byte[]认定旧指针仍有效。

  • 未知/限制：原native借用指针生命周期、DataLen可信度/同步以及所有调用方KeepAlive/Dispose时机未完成运行核对。

DI07 · source-confirmed · chunk.FillData / GetData

FillData在对象锁内惰性填充，失败标志会阻止后续填充。非共享指针用默认内存池复制；GetData(out length)返回缓存指针，GetData()随后按Size新建数组并复制。GetData(bool)只在IsMemory路径调用共享读取，它和GetData()不是等价重载；传入bUseMemPool=true时共享读取会置byteData=null，该重载返回的数组可为null。不能把所有GetData调用都画成相同深拷贝。

  • 未知/限制：单对象锁不证明全局复制池并发安全；缓存pData被池回绕/扩容后是否仍在使用需沿消费者继续核对。
