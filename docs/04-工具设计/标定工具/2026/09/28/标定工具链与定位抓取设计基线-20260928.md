## 1. 目标与已确认原则

- 目标是建立从图像源、目标定位、标定、坐标转换到运动机构抓取的完整工具链，最终同时支持手动采集与自动采集标定样本。
- 产品层面对齐 VisionMaster（VM）4.4 帮助中的九个标定工具：保留独立名称、用途和用户可理解的操作边界；实现层遵守 SunEyeVision 架构并使用 HALCON，不复制 VM 专有算法、标定板规格或 XML 格式。
- 不把“N点标定”解释为手动版、“N图像标定”解释为自动版。VM 的 N点标定可通过触发获取或手动输入取点；N图像标定的区别在于借助专有标定板图像确定点位。我们使用经过验证的 HALCON 可识别标定板实现相同目的，但须明确支持清单。
- 不额外开发通用“坐标系”工作流工具作为当前前置条件；像素、物理、相机间坐标的方向和单位仍必须是底层标定契约的明确字段。
- 以固定相机、固定工作平面的 2D 定位抓取作为首条交付链，不把单相机数量写死为程序限制。眼在手上、不同物体高度、3D 手眼标定不是这条 2D 链的隐含能力。

## 2. VM 九工具与我们的目标能力

| 工具 | 用户看到的职责 | 我们的输入/输出边界 | 阶段 |
|---|---|---|---|
| N点标定 | 图像点与机构物理点配对，求像素→机构关系 | 上游特征点、手动/触发采点、机构点手输或回读；输出标定结果及误差 | 第一阶段 |
| N图像标定 | 标定板图像辅助取得图像点，求像素→机构关系 | 指定 HALCON 板型、图像和机构点；输出与 N点同类但带板型来源的结果 | 第二阶段 |
| 标定板标定 | 图像→板所在物理平面，用于平面测量 | 板特征点及其物理尺寸；输出板平面映射，不自动等于机构坐标 | 第二阶段 |
| 相机映射 | 对应点建立两个图像坐标系的映射 | 两个相机图像点集；输出有明确方向的相机 A→B 映射 | 第三阶段 |
| 映射标定 | 由板图像/板数据获取相机间对应点 | 两相机板图像；输出与相机映射同类的结果 | 第三阶段 |
| 平移旋转标定 | 联合求平移关系与旋转中心 | 平移/旋转配对样本；输出联合结果和分项误差 | 第二阶段 |
| 旋转标定 | 单独求机构旋转中心 | 不同机构角度的同一目标图像位置；输出中心与误差 | 第一阶段后半 |
| 畸变标定 | 产生畸变参数及校正文件 | 板图像、相机成像参数；输出校正数据。运行时另需畸变校正环节 | 按精度需求进入第二阶段 |
| 标定加载 | 加载并输出已有标定结果 | 方案内已发布结果 ID；输出结果及有效性，不重新求解 | 第一阶段 |

这九个是独立工具入口，采点、配对、求解、验证、持久化等服务可共用。现阶段不强制一个工作流只能存在一个图像源或标定工具；是否支持特定组合由每个工具的输入契约和现场验证决定。

## 3. 完整数据链与运行边界

```text
标定：图像源 → 特征定位 ─────────┐
                              ├→ N点标定 → 独立验证 → 发布结果
       机构物理点（手输/通讯回读）┘

生产：图像源 → 特征定位 ─────────────────┐
       N点标定结果或标定加载结果 ──────────┼→ 抓取坐标转换 → 通讯输出
       旋转标定结果（需要时）──────────────┘
```

- “抓取坐标转换”是生产运行工具，不替代 VM 九个标定工具，也不归入通用“坐标系”工具。输入定位点/角度、标定结果及必要的抓取基准与偏置；输出机构 X、Y、角度、有效标记及失败原因。抓取角度须根据变换方向与局部几何计算，不能无条件把图像角度直接加到机构角度上。
- VM 的 N点标定本身位于工作流中：图像源/定位工具与接收数据/协议解析分别向它提供图像点和物理点；它管理跨多轮运行的点表并产生结果，后面可直接接格式化/发送数据。标定加载是复用已有结果的可选入口，不是每条抓取流程的必经节点。
- 触发模式下，9 点平移和 3 点旋转意味着 12 组**有效点对**；并非工作流必定恰好运行 12 次。普通运行、采点失败或重复触发不计数；手动输入/导入完整点表可不运行 12 轮。
- 标定采集和求解只在用户显式操作时发生；生产连续运行只使用已发布结果，不每帧重新标定，不让标定工具控制工作流调度或相机连接。
- 图像点自动获取与机构真实坐标自动回读是两条独立能力。机构回读须关联相同样本/时间、检查超时与有效性；通讯事件链未实现前先支持人工录入，不称为全自动标定。
- 关闭调试窗口不改变设备原有连接状态。所有图像来自现有图像源与本轮工作流快照；不从标定窗口私自创建第二条相机会话。

## 4. 数据契约与持久化

在 `Plugin.SDK` 建立不依赖 HALCON/WPF 的最小标定 DTO：样本点对、变换类型及方向、标定结果元信息、误差与验证报告、状态/版本。计算和 HALCON 类型转换放在 `HalAdapter`；每个工具按现有独立插件项目方式提供参数、结果和调试编辑器。工作流执行层只消费本轮参数快照、上游结果和标定结果，不能直接操作 WPF。

标定结果至少包含：稳定 ID、模式/方法、源/目标坐标系和单位、相机或设备 ID、图像尺寸、工作平面、所用图像域（原图/畸变校正后）、点对及禁用点、变换参数、训练与独立验证误差、创建/发布时间、格式版本和校验信息。内部结果格式由我们版本化管理；不承诺直接读取 VM XML。

状态为“草稿 → 已求解 → 已验证 → 已发布 → 已失效”。只有已发布结果可供生产加载。发布前检查点对数量和几何分布、重投影或物理误差、留出验证点、最大误差及用户设定的工艺阈值。相机/镜头/分辨率/安装位置/工作平面/畸变校正链发生变化时需重新校验，不能静默沿用旧结果。方案加载时验证版本、文件完整性及绑定条件；不匹配则拒绝输出抓取坐标。

现有 `Plugin.SDK.Execution.Results.AffineMatrix` 的语义是“参考图像→测试图像”的位置修正，并按 WPF 坐标惯例定义；不可直接作为像素→机构毫米坐标的标定契约。两类变换必须独立命名、独立绑定和测试，HALCON row/column 与 UI x/y 的转换只在明确的适配边界进行。

## 5. HALCON 实现路线

- 第一阶段用图像/物理对应点拟合 2D 仿射关系，HALCON `vector_to_hom_mat2d` 可作为候选算子。其数学最低要求为三组对应点，但工程上必须采更多、覆盖工作区域并留出独立验证点；遇到尺度、透视或残差问题时按实际光学/几何条件选择模型，不以增加自由度掩盖错误采样。
- N图像、标定板与畸变能力采用经实测验证的 HALCON 标定板/标定数据模型链。VM 专有板不作默认兼容承诺。
- 双相机映射需先确认是仿射还是投影关系及适用平面；两个相机的同名像素点不天然对应同一物理点。
- 畸变标定与生产校正形成一对能力：用哪个图像域标定，就在同一图像域应用抓取映射；禁止“原图标定、校正图运行”的隐式混用。
- 如项目需要 3D 手眼标定，应另立数据模型和验收链，不从 2D 平面变换推断 3D 位姿。

官方算子参考：[vector_to_hom_mat2d](https://www.mvtec.com/doc/halcon/2311/en/vector_to_hom_mat2d.html)、[find_calib_object](https://www.mvtec.com/doc/halcon/2211/en/find_calib_object.html)、[calibrate_hand_eye](https://www.mvtec.com/doc/halcon/2311/en/calibrate_hand_eye.html)。本机 VM 原始用途参考 `D:/Program Files/VisionMaster4.4.0/Applications/Help/CH/index.html` 中的九个工具页。

## 6. 调试窗口与交互

沿用现有工具调试窗口的图像区/参数区/结果区风格，不新建应用级相机管理器：

```text
┌ 图像预览与点号/偏差显示 ───────┬ 标定设置 ──────────────────────┐
│ 可缩放，检查点号与配对关系    │ 点来源：上游点/图上取点        │
│ 当前图像与样本位置叠加        │ 机构点：手输/通讯回读          │
│ 异常点、验证点区别标色        │ 样本表：点号、坐标、来源、状态  │
│                              │ [采集一点] [重采] [求解]      │
├──────────────────────────────┴───────────────────────────────┤
│ RMS / 最大误差 / 独立验证误差 / 覆盖范围 / 失败原因            │
│ [保存草稿] [发布结果]        状态：草稿/已验证/已发布          │
└──────────────────────────────────────────────────────────────┘
```

样本记录图像来源、帧标识/时间、图像点、机构位置及其获取时间，允许停用异常样本但保留审计记录。界面不应在每帧刷新完整样本表，采集/求解放到后台并支持取消；发布时以明确的误差和适用范围提示用户。

## 7. 分阶段交付与验收

1. **契约与基础设施**：标定 DTO、结果仓储、版本/有效性、数据绑定、HALCON 适配与合成变换测试。验证坐标方向、单位、row/column、镜像、逆变换和持久化往返。
2. **第一条抓取链**：N点标定、标定加载、抓取坐标转换；先人工录入机构位置，用真实相机和已存在的定位工具走通图像点到机构坐标。使用独立验证点和现场定义的工艺容差验收，不把“生成矩阵”视为完成。
3. **采集自动化与旋转**：接通讯位置回读、样本配对/超时、旋转标定，检查断线、过时帧、取消、复开方案后加载与失败拒绝输出。
4. **板与畸变链**：N图像标定、标定板标定、平移旋转标定，以及有实际精度需求时的畸变标定+校正，完成板型与实物测试。
5. **多相机链**：相机映射、映射标定，明确相机身份、方向、共面条件和独立验证。

每阶段包括算法与工具契约测试、方案保存/加载回归、全量 Release 构建和 Release 程序验证；涉及 UI 时另核对 VS 设计时和运行时。真实相机、机构坐标与实际抓取精度必须由现场人工验收；模拟或合成测试不能代替现场验收。

## 8. 后续需由项目现场确定的问题

- 首个工位是否为固定相机俯视、物体与标定点同高的平面抓取？目标工艺容差是多少，单位是什么？
- 机构坐标从哪里取得（人工录入、Modbus/其他通讯、控制器直连），如何保证与图像帧为同一次采样？
- 需要哪一种 HALCON 可识别的标定板、相机镜头和图像分辨率？是否存在明显畸变或目标高度变化？
- 抓取角度和工具偏置由哪一层提供，机构轴方向、旋转正方向与零位如何定义？

这些问题只影响相应阶段的参数和验收标准，不改变九个工具独立入口及其架构边界。

## 9. N点标定第一阶段实施记录（2026-09-28）

VM 截图补充了界面基线：基本参数包括触发获取/手动输入、按点/按坐标、图像点/物理点/角度、平移/旋转次数、示教、物理坐标生成规则和标定文件；旋转次数旁的铅笔打开可编辑/导入/导出的标定点表。运行参数包括相机模式、相似/仿射/透视自由度及权重函数。结果显示独立页签。

已新增 `NPointCalibration` 插件、上述三页调试控件与点表窗口，点对跟随节点参数进入方案保存；工作流每轮取参数副本执行，示教触发上升沿或新的事件序号到来时提交一组点对，采满后用 HALCON 求相似/仿射/投影变换并输出误差，旋转点可求图像与物理旋转中心。本轮图像点还会转换为物理 X/Y 供下游绑定；调用方须检查 `CalibrationReady` 和 `HasConvertedPoint`。手动点表编辑采用复制后确认提交；“生成标定文件”显式写版本化 JSON，“更新文件”仅在求解完成且配置了路径时执行。点集改动与过期并发结果有版本检查。当前只实现固定上相机位、最小二乘；其他相机模式与 Huber/Tukey 在 UI 标记为待实现并在运行时拒绝，不静默替换算法。

这属于可验证的第一阶段，不等于完整 VM 功能或可直接发布的生产标定：尚缺物理位置与相机帧的通信时序核验、独立精度验证和发布/失效流程、生产抓取转换、其他相机模式及鲁棒权重算法。当前点表只在保存解决方案后持久化；意外退出前未保存的新增点不能承诺恢复。真实相机与机构现场验收、VS 设计时及可见运行时尚未完成。
