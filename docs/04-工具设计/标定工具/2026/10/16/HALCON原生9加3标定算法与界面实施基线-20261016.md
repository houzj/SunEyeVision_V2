## 3 坐标与样本契约

- `p=(u,v)`：Mark 中心图像坐标，u=列/X，v=行/Y，单位 px。
- `s=(Xs,Ys)`：同次曝光对应的 R 轴轴心绝对机台编码器坐标，单位 mm；不是 Mark、工件抓取点或吸嘴/TCP 坐标。
- `Theta`：R 编码器真实角度，单位 deg；不是图像中的 Mark 朝向。
- `phi=signR*(Theta-Theta0)`，Theta0 为平移参考R角，signR 为明确配置的正方向。
- `d=(dx,dy)`：参考R角下轴心指向Mark的偏心，单位 mm；不得直接当成TCP偏置。
- 最终映射 `q=A*p+t`：图像点到 Mark 绝对机台物理位置，满足 `q=s+R(phi)*d`。

首期仅固定上相机位、同一工作平面、同一图像域的平面仿射。暂不开放移动相机、投影变换、纯九点不求偏心等模式。默认9平移+3旋转，支持按已确认配置增加冗余样本；有效点不足不得靠占位零值或旋转次数为0绕过。

推荐在第5个平移点轴心XY处做旋转，并复拍Theta0姿态；点表记录参考姿态关联，用于复拍检查，而不是单纯依赖数组下标猜测。任意其他旋转轨迹需满足明确的固定轴心和参考对应条件，不由UI自动生成指令坐标冒充编码器回读。

手动点表可以没有帧时序证据，来源必须标为手动；自动样本需来自同一轮工作流的特征点、轴心XYR、唯一帧、事件/运动步和到位证据。缺证据则明确限制触发采集，不伪造“有效”。相机身份、尺寸、图像域及工位信息优先来自宿主/上游上下文；手动候选发布时仍需由真实验证工位确认环境。

## 4 HALCON原生算法流程

### 4.1 九点平移映射

检查平移样本的R角保持Theta0、有效点数、重复点和几何分布后，以 `VectorToHomMat2d(u,v,Xs,Ys)` 拟合辅助映射：

```text
H0(p) = A*p+b
b = t-d
```

H0仅表示参考R角下的轴心映射，不作为最终像素到Mark的绝对机台矩阵输出。

### 4.2 编码器角度求偏心

旋转阶段保持轴心XY固定。以 `AffineTransPoint2d` 转换每个Mark像素点，构造：

```text
(R(phi_i)-I)*d = H0(p_i)-s_i

[ cos(phi)-1   -sin(phi)   ] [dx] = [H0_X(p)-Xs]
[ sin(phi)      cos(phi)-1 ] [dy]   [H0_Y(p)-Ys]
```

用 `CreateMatrix / SolveMatrix / GetFullMatrix` 对全部有效旋转点做两参数最小二乘；角度进入三角函数前换算rad。数值求解交给HALCON，不再实现矩阵分解、正规方程求逆或自写IRLS。必须另外检查角度覆盖和方程可观测性：原生SVD可以返回秩亏问题的解，不代表采样合格。

### 4.3 合成最终映射

```text
t = b+d
q = H0(p)+d = A*p+t
```

由HalAdapter统一完成矩阵平移组合与点变换，对外只暴露数据契约，不暴露HObject/HTuple/HMatrix。图像X/Y、HALCON row/column和旋转正方向在边界统一适配；数值点变换不能无条件加半像素，图像/区域变换另按官方坐标约定适配，不复用位置修正AffineMatrix的语义。

### 4.4 唯一路线与删除项

唯一生产路线为九点仿射加已知编码器角偏心。HALCON联合8参数求解仅保留在既有验证证据中，不作为运行选项；三点物理圆拟合本轮不作为必需生产步骤，更不能在原始图像拟圆后直接变换圆心。若未来加圆轨迹诊断，须单独定义，不扩成本次隐式第二算法。

删除自写QR、稳健初值、IRLS及旧Huber/Tukey参数、权重系数、尺度下限、权重/尺度结果。无需替换上游已有HALCON特征定位。原生算子失败立即返回具体阶段及HALCON错误，不回退旧算法。

### 4.5 质量与结果有效性

逐点计算完整残差 `r_i=A*p_i+t-s_i-R(phi_i)*d`，显示X/Y、模长，统计平移/旋转/整体RMS及最大误差。算子成功、训练合格、独立验证通过、正式发布四种状态分开。

求解/候选门槛包括：数值有限、配置点数满足、平移几何有效、平移R角一致、旋转轴心不漂移、角度覆盖和方程可观测性满足、参考姿态复拍检查及现场设定的最大训练误差通过。缺复拍时显示未采集并提示补采，不显示通过。零偏心可数值恢复，但无法仅靠该Mark轨迹证明R方向正确，需报告校验限制，由独立验证与工位条件决定可用性，不能伪造旋转校验通过。

异常点保留并指明点号和原因，只允许用户明确停用或重采；不自动删点或放宽门槛。物理误差和配对阈值须由现场设定，图中的“待设置”不是默认已合格值。

点表/关键参数变更立即使旧求解和候选状态过期。按版本快照计算与提交，过期/取消结果不得写回；同一点集不重复写候选。工具执行、记录和文件操作防重入，并在可取消阶段检查取消；不承诺强制中断所有HALCON原生调用。

## 10 通用提示与文件契约

不再新增“求解成功”模态弹窗，成功/进度/未采满状态在结果区和状态栏显示。导入、求解、候选生成、验证和发布错误使用现有SDK主题化提示：标题、具体阶段、点号或文件路径、失败原因及一个确定按钮；恢复原内容，不用一串重复弹窗。其为通用错误提示，不新增独立配置窗口。

```text
+----------------------------------------------------+
| 标定操作失败                                       |
+----------------------------------------------------+
| 阶段：...    点号或文件：...                       |
| 原因：...                                          |
| 原点表/原正式文件未被替换。                         |
|                                           [确定]   |
+----------------------------------------------------+
```

文件记录明确的原生分阶段算法标识、新契约版本、坐标方向、单位、参考R角/方向、最终矩阵、偏心、环境、训练点和质量报告。保留数值含义一致的输出键；不暴露HALCON句柄，不把旧位置修正矩阵当标定矩阵。

候选状态为SolvedUnverified，训练质量通过后手动或自动更新旁路候选。正式状态为Verified，仅独立验证节点发布，绑定候选内容摘要、验证报告和环境。算法/版本不匹配明确要求重新标定，不静默兼容、不自动清空或覆盖用户旧数据。旧草稿导入、旧结果和失效绑定处理需有回归用例。

## 11 分层与实施顺序

| 层 | 职责与边界 |
|---|---|
| Plugin.SDK | 无HALCON/WPF依赖的样本、结果、环境和验证数据契约 |
| HalAdapter | 原生拟合、偏心求解、矩阵组合、点变换、数值诊断及确定释放资源 |
| N点插件 | 点表、步骤组织、几何/质量判断、快照提交和候选生成 |
| 验证插件 | 独立采样验证、摘要核验与发布，不重新求解训练标定 |
| UI | 参数绑定、编辑与展示，不调度工作流、不直接操作设备 |

涉及SDK、绑定、图像来源或发布依赖时先评估跨模块影响，不让插件引用UI宿主。现有工作流快照/版本提交机制继续使用，不新造第二套调度器或一键标定向导。

实施顺序：

1. 确定最小SDK契约及原生算法标识，封装HalAdapter唯一原生路线及定向测试。
2. 接入N点与验证节点，删除旧求解/权重路径，更新文件、输出及失效逻辑。
3. 实施NT01至NT03、VT01至VT03及P01至P10，复用SDK选择器/系统文件对话框；补通用错误提示。
4. 补采样来源证据与结果版本保护。上游接口未就绪时明确阻止伪自动采样，手动路径可先验证；不得声称已完成机构到位链。
5. 完成自动回归、全量Release及UI构建、VS设计时/运行时检查，再记录真实工位独立验证与抓取工艺验收。
