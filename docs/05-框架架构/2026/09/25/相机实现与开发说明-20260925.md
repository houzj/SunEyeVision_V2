# SunEyeVision 相机实现与开发说明

日期：2026-09-25

## 1. 总体结论

相机能力采用“SDK 契约、DeviceDriver 实现、上层通过契约调用”的分层方式：

```text
Plugin.SDK
  定义通用契约、数据模型和服务接口
          ↓
DeviceDriver
  实现发现、连接、采集、参数和厂商 SDK 适配
          ↓
App / UI / Workflow
  组装服务或通过契约调用，不直接依赖厂商 SDK
```

真实相机的厂商实现统一放在 `DeviceDriver` 层。`Plugin.SDK` 不依赖 `DeviceDriver`，UI 和工作流也不直接引用海康、Basler 等厂商 SDK。

## 2. 模块职责

### 2.1 Plugin.SDK：契约层

位置：`src/Plugin.SDK/Devices/Camera/`

负责定义跨厂商稳定的抽象：

- `CameraDescriptor`：设备描述、厂商、型号、序列号、IP、MAC、传输方式和协议；
- `CameraDeviceRef`：方案和工作流使用的稳定逻辑设备引用；
- `ICameraAdapter`：连接、断开、采集、连续采集、触发、参数和命令接口；
- `ICameraAdapterFactory`：根据设备描述创建适配器；
- `ICameraDiscoveryProvider`：发现设备；
- `ICameraCaptureService`：向上层提供统一采集服务；
- `CameraFrame`、参数模型、能力模型和连接选项。

契约层不能保存厂商 SDK 句柄、线程、连接对象或厂商类型。

### 2.2 DeviceDriver：核心实现层

位置：`src/DeviceDriver/Cameras/`

负责：

- 调用厂商 SDK 发现相机；
- 将厂商设备信息转换为 `CameraDescriptor`；
- 实现 `ICameraAdapter`；
- 管理 SDK 句柄和参数类型转换；
- 处理采集、触发、超时和厂商错误码；
- 实现适配器工厂；
- 管理运行时相机注册和连接会话。

当前正式运行时已接入海康 MVS GigE/USB3。模拟相机源码仅保留给独立测试，不属于正式运行时入口。

### 2.3 App：组装层

`CameraRuntimeComposition` 负责组装发现器、适配器工厂和运行时服务。宿主只依赖组合对象，不需要知道具体厂商 SDK 类型。

### 2.4 UI：管理界面层

UI 负责：

- 设备列表、添加、删除和重命名；
- 连接/断开 ToggleButton；
- 状态和错误显示；
- 打开现有预览窗口；
- 调用统一运行时服务。

UI 不负责厂商 SDK 调用，也不持有厂商设备对象。设备管理器窗口和预览窗口是临时视图，关闭视图不能自动释放方案级连接。

### 2.5 Workflow：业务调用层

工作流通过 `CameraDeviceRef` 和统一采集服务请求相机，不判断海康、Basler 或其他厂商。工作流执行层不直接访问 WPF 控件。

## 3. 当前运行时结构

```text
CameraRuntimeComposition
├── CameraDiscoveryCoordinator
│   └── ICameraDiscoveryProvider[]
├── CameraRuntimeManager
│   └── ICameraAdapterFactory[]
└── MvsCameraDiscoveryProvider / MvsCameraAdapterFactory
```

运行时核心对象：

- `CameraDiscoveryCoordinator`：并行调用发现器，并按稳定 `DeviceId` 去重；
- `CameraRuntimeManager`：注册设备、选择工厂、打开和关闭会话；
- `CameraSession`：持有一个实际连接和对应适配器；
- `ICameraAdapter`：封装具体厂商 SDK。

同一 `CameraDeviceRef` 在运行时只允许一个连接会话，避免预览、工作流和设备管理器重复打开同一相机。

## 4. 生命周期设计

### 4.1 发现阶段

发现器只搜索设备并返回描述，不创建长期 SDK 句柄：

```text
发现设备
  ↓
CameraDescriptor
  ↓
Runtime.RegisterDevices
```

### 4.2 添加和持久化

方案持久化设备身份和用户配置，不持久化 SDK 连接对象：

- `DeviceId`；
- 序列号；
- MAC 地址；
- IP 地址；
- 厂商和型号；
- 传输方式；
- 用户名称；
- `IsEnabled`、`AutoConnect` 等管理配置。

### 4.3 方案加载

```text
加载方案
  ↓
读取持久化相机列表
  ↓
重新发现真实设备
  ↓
按 DeviceId / 序列号 / MAC 重新绑定
  ↓
注册运行时设备描述
  ↓
按 AutoConnect 和 IsEnabled 恢复连接
  ↓
连接成功、失败或最多等待 10 秒后继续显示主界面
```

连接状态属于运行时，不属于持久化设备配置。设备管理器或预览窗口关闭不应改变已有连接状态；应用退出、方案切换、用户主动断开或设备删除时才释放连接。

## 5. 新增厂商相机的实现方式

以新增 Basler 为例，第一阶段可以放在同一个 `SunEyeVision.DeviceDriver` 项目中：

```text
src/DeviceDriver/Cameras/Basler/
├── BaslerCameraDiscoveryProvider.cs
├── BaslerCameraAdapterFactory.cs
├── BaslerCameraAdapter.cs
└── BaslerParameterMapper.cs
```

### 5.1 实现发现器

实现 `ICameraDiscoveryProvider`，调用 Basler SDK 搜索设备，并转换为统一 `CameraDescriptor`。发现器不应把 Basler SDK 对象暴露到上层。

### 5.2 实现适配器

实现 `ICameraAdapter`，封装：

- 打开和关闭设备；
- 单次采集和连续采集；
- 软件和硬件触发；
- 参数读取和写入；
- 参数能力和命令；
- 厂商错误码到 `CameraAdapterException` 的转换。

### 5.3 实现工厂

实现 `ICameraAdapterFactory`：

- `CanCreate` 根据厂商、协议、传输方式或元数据判断；
- `Create` 创建对应适配器；
- 不在 UI 中加入厂商判断。

### 5.4 注册运行时

在 `CameraRuntimeComposition` 中注册新的发现器和工厂：

```csharp
Discovery = new CameraDiscoveryCoordinator(new ICameraDiscoveryProvider[]
{
    mvsDiscovery,
    baslerDiscovery
});

Runtime = new CameraRuntimeManager(new ICameraAdapterFactory[]
{
    new MvsCameraAdapterFactory(mvsDiscovery),
    new BaslerCameraAdapterFactory(baslerDiscovery)
});
```

UI 的添加相机和设备列表不应为 Basler 增加专用分支。只要发现结果符合统一契约，就可以复用现有流程。

## 6. 参数兼容原则

不同厂商参数不能简单按字符串或布尔值强制转换。参数必须携带明确类型：

- Boolean；
- Integer；
- Float；
- String；
- Enumeration；
- Command；
- 厂商扩展类型。

例如 MVS 的 `17301505` 是 `PixelFormat=Mono8` 的枚举值，不是布尔值。类型转换必须由适配器和统一参数模型完成，UI 不得对所有参数无条件执行 `Convert.ToBoolean`。

## 7. 项目拆分策略

新增厂商时不要求每个相机独立项目。初期推荐：

```text
SunEyeVision.DeviceDriver
├── Cameras/Hikvision/Mvs
├── Cameras/Basler
└── Cameras/Daheng
```

当出现以下情况时再拆分独立项目：

- 厂商 SDK 依赖版本或运行时冲突；
- SDK 只能使用不同目标框架；
- 驱动需要单独发布或按需加载；
- 希望按授权或产品版本选择驱动；
- 厂商数量较多，主项目构建和部署成本明显增加。

拆分后可采用：

```text
SunEyeVision.DeviceDriver.Abstractions
SunEyeVision.DeviceDriver.Hikvision
SunEyeVision.DeviceDriver.Basler
SunEyeVision.DeviceDriver.Daheng
```

各厂商项目只依赖 SDK 契约和驱动抽象，UI 仍不直接依赖厂商项目。

## 8. 新增相机的验收要求

每个新增厂商至少需要验证：

1. 发现设备和稳定身份生成；
2. 同一设备多次发现不会重复；
3. 连接、断开和重复连接；
4. 单次采集和连续采集；
5. 软件触发和触发超时；
6. 关键参数读取和写入；
7. 设备管理器关闭不影响连接；
8. 预览窗口关闭不改变预览前连接状态；
9. 保存方案后重启能够重新发现并恢复；
10. SDK 缺失、设备离线、设备被占用时能够显示明确错误；
11. 方案加载时连接失败或超时仍能进入主界面；
12. 真实相机诊断测试和适配器单元测试通过。

## 9. 最终依赖边界

```text
Plugin.SDK
  ↑
DeviceDriver
  ↑
App 负责组装

Plugin.SDK
  ↑
UI / Workflow 通过契约调用
```

核心规则：

- 所有真实相机厂商实现放在 `DeviceDriver`；
- `Plugin.SDK` 只提供契约，不实现厂商逻辑；
- UI 只负责管理和展示；
- Workflow 只使用统一采集服务；
- 连接句柄只属于运行时会话；
- 方案只保存稳定身份和配置；
- 新增厂商优先新增适配器，不修改上层业务流程。
