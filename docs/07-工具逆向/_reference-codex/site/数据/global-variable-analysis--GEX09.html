GEX09 · 原版 · 迟到托管结果：入口没有按停止代次直接拒收

原件 CIL 与反编译体同时确认：MModuleManager_OnModuleResultCallBack 按 result.nModuleID 在 instance.AllModules 找模块；存在则进入 SetValue（Group 另有循环分支）。SetValue 对不同 ExecuteCount 的分支清旧 IO，再将 module.executeCount 直接赋为收到的计数并写入值。它检查“不相等”，不是“新计数必须大于旧计数”。源码路径推演：模块仍存在、当前计数 6、收到计数 5 时，该不同分支本身不会拒绝 5。此为静态条件推演，未执行原版回调实验，也不能证明原生停止上游必定仍会投递。

已删模块会因查找失败返回；SDK 已停止后是否还投递已排队结果需实际队列/事件生产端证据。托管结果镜像与原生全局存储不是同一写入点。
