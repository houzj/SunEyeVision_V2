GEX11 · 自研 SunEye · 接收变量是另一条路径，不能与普通参数混为一谈

RuntimeVariableReceiveService.ReadVariables 对有生产者的变量优先检查传入 nodeResults 且生产流程匹配，成功时用 OutputVariableResolver 读生产结果；否则有 runtimeValues 就按变量名读它；再否则交 inner.ReadVariables。随后检查非 null、Normalize 和类型。当前引用的引擎 ConvertNodesForExecution 构造 wrapper 时传 null runtimeValues 且没有 nodeResults 参数；方案批次管理器还在外层包 runtimeGlobals。因此应逐入口说明当前来源，不能因为该服务有 nodeResults 分支就声称引擎已向它注入所有本轮节点结果。

服务能力、调用者传参和实际消费者路径分别成立；接收工具具体输入／通信接收的完整操作验证仍独立。
