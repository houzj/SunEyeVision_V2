基础范围说明与设计参考（设计建议仍未实施）

变量定义 → 建立生产／消费依赖 → 捕获本次输入 → 执行生产节点 → 校验并发布运行值 → 消费者读取 → 退出与回收

先用一个例子看清难点

流程 A 测量出宽度 X，流程 B 根据 X 判断。关键不是“B 能否找到 X”，而是“B 找到的是 A 哪一轮的 X”。如果 A 本轮失败，B 继续读上轮的 X，类型和界面都可能正常，业务结果却已错配。以下例子用于解释，不是原版运行实测。

谁持有：定义、运行值、结果应当分开

变量定义保存 Id、类型、初值以及生产者／消费者关系；本轮运行值保存本次实际取到的内容；节点结果仍由执行结果对象保留。SunEye 的方案批次在 RunSolutionAsync 中建立 runtimeGlobals，ApplyProducedGlobalValues 刻意不修改 Solution.GlobalVariables.Value。WorkflowRunRequest 再复制字典容器交给本轮执行。容器复制不等于对象、数组或图像像素全部深复制。另外 GlobalVariable.Value 已有 ValueGate 锁；GlobalVariableManager 也有按名称增删读写。它们不单独构成跨流程运行值发布和批次一致性协议，不能说自研项目没有全局变量管理器。证据 GV09、GV10、GV13、GV16、GV17。

流程内：先让生产节点执行，再读取本轮结果

REA 的 WorkflowRunContext 持有本轮 records 和局部变量表。Update 先删除该变量旧条目，再尝试取已运行生产节点的输出；失败不保留该条目。跨流程 CallAsync 明确把调用方 WorkflowOutputs 映射为被调用方输入。SunEye 的局部依赖图会为同流程内的全局变量生产者建立节点前置关系；这证明执行顺序约束，不单独证明所有参数解析器会用当前节点输出刷新变量。后者仍需逐入口验证。证据 GV06、GV07、GV15。

跨流程方案批次：A 完成 → 发布成功输出 → B 再取值

SunEye RunSolutionAsync 编译方案依赖，从无生产绑定且绑定有效的变量初值建立 runtimeGlobals；BuildWorkflowPredecessors 只收集所选流程之间的全局变量依赖。循环每次选一个就绪流程并 await，再发布它的生产结果。发布时先 Remove 旧值，只有对应节点成功、结果 IsSuccess 且输出解析成功才重新赋值。整流程失败仍可能发布其中成功生产节点的值，后继流程也可继续运行独立节点；不能描述为“一处失败全部停止”。证据 GV09、GV10、GV14。

全部连续运行：不能直接套用上面的批次语义

SunEye StartAllContinuousRun 逐个调用 StartContinuousRun；其默认执行入口经 ExecuteWorkflowInternal 使用 _globalVariables，而不是自动共享 RunSolutionAsync 的 runtimeGlobals 和发布顺序。TryAcquireExecution 按 workflowId 防重复，不足以证明所有工作流全局串行。本次已引用路径尚未建立独立持续流程之间的同批版本读取／发布屏障；这是一项具体契约缺口，不能据此推断全项目不存在其它更新路径。证据 GV11、GV12。

后台和停止：取消请求、执行退出、禁止写回是三个时刻

REA RunCore 在 Task.Run 中执行，返回时检查 IsCurrentExecutionOwner 后才呈现；连续入口逐轮 await，Stop 请求取消。它证明界面后台执行及所有者准入，不代表独立后台服务或任意 native 调用立即可中断。SunEye StopAllContinuousRun 的引用方法发出 Cancel；单凭此方法不能证明全部任务已经退出、全部图像释放或所有延迟结果被拒绝。原版还存在 GlobalScriptStartContinueRun / GlobalScriptStopRun 与 Dispose(isTakeOver)→DestoryHandle 分支，接管与托管后台线程不是同一概念。证据 GV03、GV04、GV08、GV11。

建议的最小运行契约

责任设计建议
变量身份用稳定 VariableId 寻址；名称用于显示。定义中指定类型、单一生产者或明确的多写者仲裁。
发布记录建议保存 SolutionEpoch、RunId、BatchId、Version、Producer、Status、Payload；版本只是方案建议，未声称现代码已有。
一次读取消费者按所选策略捕获一致快照；同批依赖在调度层建立，不能只给共享字典加锁。
一次提交先在私有结果中构造完整值，再短时校验并发布；执行算法、等待相机或 await 时不持共享提交锁。多字段必须原子快照或事务提交。
取消与迟到停止／切方案先撤销旧发布资格，再取消并等待清理；发布时校验 epoch、run 和取消状态，拒绝旧任务迟到结果。
缓存和释放明确运行表、结果记录、消费者快照和显示各自的持有关系。图像选择不可变共享句柄＋租约或明确复制；替换字典条目仅移除一个引用，最后读者结束才能回收底层资源。跨轮缓存另设容量和淘汰规则。
