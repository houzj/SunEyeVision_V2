GEO31 · IMVSGroup(object) → VmModuleSet(object,typeName) → VmModule(object,typeName) → 按宿主类型构造SyncAddOneModule描述并登记模型

source-confirmed

现有VM.Core反编译体显示IMVSGroup(object param)把param和IMVSGroup类型名交base，VmModuleSet继续交VmModule。VmModule构造中VmProcedure宿主用SetNodeType=1及procedure.ID，IMVSGroup宿主用20及group.ID，VmSolution用1及10999；之后CreateToModuleSet构造同步添加描述，UTF8固定64字节模块名、256字节本地化显示名、WaitTime=5000，交mModuleManager.SyncAddOneModule，返回信息交Init(...,vmModuleSet)。构造末尾AllModules.AddOrUpdate并发ModuleAdded事件。只连接这些已见托管成员，不由通用反射工厂断言它实际选中了某个Cs派生构造。

父宿主对象、native请求父类型/ID、返回的module信息与AllModules注册是分开的阶段。

native ID来自SyncAddOneModule返回后Init使用，不是当前Guid；本切片没有取得该SDK/native接收体。

创建失败完整回滚/临时对象释放未由此保证；构造没有在所选代码段建立所有异常清理合同。

待核：下一明确接收成员是VM.PlatformSDKCS.ModuleManager.SyncAddOneModule及其PInvoke/native callee；本次不新取native体。

待核：VM.Core原bytes已按既有identity重新SHA校验，成员文本使用已有反编译源，未新做CIL逐指令绑定。

GEC01 · GraphEditorDocument.AddOwnedGroup / EnterOwnedGroup → 新node、独立body Guid及GroupOwnership

independent-implementation

AddOwnedGroup在EditProcedure草稿中先AddNode(workflow.subprogram)再EnterOwnedGroup。EnterOwnedGroup拒绝非Group模块或Disabled；已配置body必须严格等于(CurrentProcedureId,nodeId)所有者，否则拒绝旧跨流程调用。首次创建独立Guid的ProcedureDocument、GroupOwner和父节点Call；直接EnterOwnedGroup通过Edit的selectedProcedure选择body。AddOwnedGroup把这一步放在EditProcedure草稿中，外层EditProcedure提交不切换可见CurrentProcedureId，不能把两条入口混成都会自动进入body。CanAddOwnedGroup与EnterOwnedGroup分别核祖先深度，最大三层。OwnedGroups.Validate额外要求body只被一个节点引用且父节点确实指回。

当前owned Group body是独立ProcedureDocument，由(parent procedure ID,node ID)定位；不是只靠Name或显示文字。

名称同步在Edit流水线中按父node名称更新；稳定身份仍是ID。

创建与选中不创建独立solution scope，生命周期跟随当前solution及编辑模型。

待核：此为当前独立所有权模型，不冒充原版IMVSGroup/VmModuleSet对象布局。
