组合描述、PointSet与当前几何
原版已核片段当前独立实现

入口交来什么：复合描述按0x130步进，类型0/1/2进入typed数值/字符串分支；类型4为图像，不能补成PointSet。typed第六字节在复合入口固定1，正常独立设置的linked分支不可照搬。

具体复制哪一层：VAR_TYPE整段memcpy包含嵌套指针，只证明描述浅复制。图像type4的独立helper另申请buffer并memcpy字节；这两层复制不能混同。

谁仍持有：record+0x470保留复合描述数组，+0x468另持字符串描述。0x27080真实为SetGlobalValue发布体，只建立临时紧凑描述并交Batch，源record仍保留。

哪里缓存或保留：旧值删除成功门位于类型更新/分配前；本切片不证明分配或后续失败时恢复原类型和旧值。；计数与pointer分别复位；函数没有把+0x448复合标志清零，不能把它单独当完整record重置。；只确认record+0x470保留描述副本；payload究竟由哪个接收路径分配/移交，需要补生产体及ABI，不能用本地数组分配代替。；原record的+0x468及嵌套内容在这个发布循环保留；临时紧凑描述仅到batch返回。

退出到哪一步：0x25c40清record计数与指针；0x470数组沿cookie逐0x130元素析构，再释放外层。数值非空pointer delete[]；嵌套0x60描述内容只在+0x50非0门通过才释放。它不删除ModuleFrame typed主仓。

待核：复合memcpy输入嵌套地址的生产/转移与分配器协议尚缺，析构体不证明读者全部退出，也不能直接诊断double-free。

待核：图像helper新buffer/handle最终拥有者、PointSet生产与专用setter之外的原生写路径仍未知。

source-confirmed
