文本、字符串数组与byte变量
原版已核片段当前独立实现

入口交来什么：SetVarStringValue产生每项UTF8字符HGlobal和大描述；GlobalVariable wrapper复制0x60记录的pointer/len/size为0x10 STRING_UNIT，再交实际ModuleFrame BatchString。短文本/长文本SetVarValue仍是另外两条入口。

具体复制哪一层：wrapper只复制描述，未复制字符；已取BatchString接收体随后读各描述首pointer并按C尾零扫描构造局部字符串，再经00ffe0/006470对内部目的字符串memcpy字符、更新长度及尾零。实际字符复制已证，但不能把上游长度/容量字段推成此C字符串扫描的统一边界。

谁仍持有：源字符块、两级描述、接收端临时字符串与内部副本分开。typed string+8槽逐字符串清长度/首字符并清计数，保留分配；对象准备另经callable取得载荷。

哪里缓存或保留：这些是临时复制；字符串[]没有在此包装中保存永久native地址。；临时紧凑数组不是长期字符串cache，也不是所有字符串内容的deep copy。；linked记录是另一个保留容器，当前新取值不自动删除它；wrapper临时格式化string退出后析构。；内部字符串与临时字符串、上游描述数组各自持有；源码不支持把所有同名string当同一个缓冲。；新对象进入名称map；后续同名可复用共享对象，局部shared pair不等于新建底层载荷。；旧数组容量、string堆分配可在清空后继续保留。；准备门使正常后续调用复用已有返回指针；并非每次更新重新分配。

退出到哪一步：临时C字符串、紧凑描述、调用者字符块各自正常退役；强归零释放typed包装对象/名称/类型，弱归零释放控制块。字符串载荷及callable最终动态free仍未知，逻辑清空不是释放。

待核：Batch字符复制、逻辑清空和包装对象/控制块析构原体已取；剩余callable清理目标、内部字符载荷最后读者、尾零/分配失败域。

待核：短文本/长binary接收入口与linked消费租约仍各自待核。

VZ04 · BatchString接收体997c0 → 描述步长16字节→局部字符串→内部字符串记录副本

source-confirmed

接收体在正count循环中每次读取16字节描述的首pointer，再按尾零扫描构造局部字符串；还存在字节参数非零时向辅助列表复制字符串的分支。主分支按模块/名称取得字符串值对象后，汇编明确把当前索引和局部字符串作为参数交00ffe0。该体按索引选择已有或新增的内部字符串，再调用006470复制字符；006470在非同对象分支按实际字符串长度调用原IAT memcpy、更新长度并写尾零。00ffe0随后对临时字符串大容量块调用operator delete并重置它。此处释放的是临时字符串存储，不能当作调用者STRING_UNIT数组或其原pointer的释放。

类型、持有与复制

缓存与失效

退役与释放
临时字符串delete已见原IAT；内部目的字符串未来退役与嵌套消费者仍未知，不能从局部清理证明最后读者结束。
