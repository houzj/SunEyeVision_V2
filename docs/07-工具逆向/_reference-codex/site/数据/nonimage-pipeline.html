非图像数据：数值、文本、数组、变量与几何

先用五个问题读懂，再展开原版和当前的完整成员证据。VD是托管入口，VN是接收分发，VS是typed写入桥，VZ是ModuleFrame存储与退役；VX补复合描述，VP补值对象准备/控制块退出，VB补分派。早期片段的缺体问题仅按后续事实明确补充，不抹掉尚未证实的最后读者。

并排主题是研究对照，不证明原版与当前类型、对象、调用顺序或格式等价。

先分清：配置、运行值、显示文字

配置描述要怎样运行；运行值是本轮真正传给消费者的数据；显示文字可能只展示数组第一项。看到一个数值，不能据此判断完整数组只有一个元素。

数组要同时看元素类型和基数

原版变量描述含类型与数量，具体结果还要看status分支和转换体。当前数值向量NumberArray与“多个Number”是两种合同；PointSet、Point与Components也必须按各自成员核对，不能按中文名称对应。

变量身份包含作用域，引用描述不等于值副本

原版订阅携带来源模块ID、变量名和ALL索引描述。当前实现要分别追变量ID、流程作用域、生产者更新与端口投影；字典包装、数组复制和元素对象复制分别判断。

删除、改型、清结果各有自己的顺序

原DeleteVar先发送删除命令，再清理托管IO；ModifyType的所选路径先改托管节点或类型，再发送ModifyVar。临时传输块、变量存储、循环列表和旧结果的持有者分别退役，不能从一处清空推出全部数据已释放。

VD01 · 原VariableManager绑定的DataSource模块 → VarCount/GlobalValueList快照与显示值

source-confirmed

构造函数只在dataSource为VmModule时保存DataSource。GetAllVar(ref IMVS_VARIABLE[])通过DataSource.Params先取VarCount：只有正整数才读GlobalValueList，且非空、字节长度可整除IMVS_VARIABLE大小才覆盖调用者ref数组；不是数量相等校验，其他分支保留旧ref。List<VarItem>重载逐条附加元数据，int/float将native数组复制到byte[]再BlockCopy成数值数组，但显示Value只取第0项；string读取描述数组后，仅复制第0项指向的字符串payload作显示。不能把Value文本当成完整数组。

类型、持有与复制
变量身份=所属模块+变量名/Guid；VarItem的Value是展示字符串，ValueArray另有object属性，但所选GetAllVar没有把完整数值数组赋给ValueArray。
缓存与失效
GetAllVar是读取快照而非本地变量存储实现；ref数组未覆盖分支可保留调用者旧快照，list重载附加而非自动Clear。
退役与释放
已复制的标量数组/文本由GC持有；IMVS_VARIABLE内嵌pointer指向的原payload所有权未由结构快照获得。
