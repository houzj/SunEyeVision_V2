参数：定义、绑定与运行快照

原版事实、当前独立实现、拟议设计与未知分别保留。导航示意属于文档组织，不代表原程序的控件树或完整运行验证。

本页正文与分类来自拆分前页面。长原文已迁移到内容寻址证据页，原始 SHA 和返回路径仍保留。

参数怎样从界面进入执行？

先看四个时点，再分别展开原版和当前实现。配置值、输入来源、运行解析值和保存值不能当作同一份数据。

① 编辑的是配置，引用记录的是来源

数值、字符串等配置值与“去哪个上游取值”的绑定分开。原版值编辑经ModuleParam/SDK，输入引用走另一条订阅绑定链；当前JSON配置不能直接套作原版对象模型。

依据：SP02 / PS01 / PS02 / PS03 / PS04 / CP01

② 启动时复制配置，执行到节点时再解析输入

当前主流程启动前复制文档，执行器再复制节点参数；订阅值到节点执行时才解析。JSON隔离不等于图像像素深复制，也不等于所有节点的实际输入在同一时刻冻结。

依据：CP02 / CP03 / CP04

③ “有效参数”缓存不是成功运行的纯历史

当前有效参数在调用ExecuteAsync前缓存，失败也可能留下；读取时还会叠加后续编辑值。比较运行结果时，要同时注明配置版本、解析时点和缓存读取时点。

依据：CP05

④ 保存另走投影；原版默认值以实际初始化为准

当前插件可提供保存投影，再提交方案；原版图像源UI XML与算法XML的拼接默认值不同，不能仅用控件声明判运行默认。原版保存基类和SDK分发未闭合处继续保留。

依据：SP01 / SP03 / SP04 / SP05 / CP06

source-confirmed
