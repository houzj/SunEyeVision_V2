返回专题总览

① 点击停止：画面没动，是不是还在运行？

原版：已证片段与未知父级桥

停止入口先改执行控制；此处没有证明显示仓库或图像缓存被清空。

谁持有：原版全局连续标志、逐流程连续标志、显示仓库和图像载荷是不同责任。

已确认的收尾：StopRun直接请求停止；全局脚本停止、逐流程停止与属性通知有具体调用顺序和异常分支。

此后仍可能存在：这些停止体不能证明回调已排空、所有查询容器已释放或最后像素读者已退出。

待核：停止请求到同一帧生产者、回调和显示消费者全部退出的完整链仍未取得。

CR01 · 新一轮开始 / 停止 / 抛取消异常 → 隐藏旧结果视图与保存旧会话是两个动作

independent-implementation

BeginWorkflowResults增加过程执行计数，仅在count>1、workStatus非0且清旧结果偏好开启时，标记该过程及所调用子过程为cleared并清当前results视图；它不删除workflowSessions。RunCore返回session才StoreWorkflowCallResults覆盖对应会话并移除cleared标记。若Task.Run被取消或执行抛异常而没有返回session，catch只改状态文字，旧session仍在；偏好开启时可处于隐藏状态，未开启时也未由这个catch主动清除。工具栏停止只Cancel activeRun，FinishWorkflowRun清运行标记并Dispose该取消源，不清会话或插件scope状态。

representation：results是可见NodeRunRecord索引，workflowSessions是完整ExecutionSessionResult；隐藏索引不等于移除图像持有者。

cache：旧session可继续保持Nodes、WorkflowOutputs、WorkflowDisplays、LocalVariables和Calls中的PortValue引用；不能将空白显示当零像素缓存。

release：停止请求不等于清旧结果或FIFO；本轮没有新session时不会自动用空session覆盖旧session。

CR02 · GraphExecutor本轮取消 / 失败 / 跳过 → 本轮混合结果可替换上轮会话；旧插件状态另留

independent-implementation

GraphExecutor每轮新建records，不拿上一轮NodeRunRecord补失败节点。节点开始前发现取消会Record(Cancelled)且输出默认Empty；前驱失败或不可用会Record(Skipped)且输出Empty。单节点执行后取消/超时/异常与失败输出过滤按TD04生成本轮记录，已经成功完成的前序节点记录不因此统一清空。最终把全部本轮记录组成session，状态可为Cancelled/Failed/TimedOut。RunCore只检查owner、未以session成功作为发布前提，所以正常返回的取消/失败session也可替换workflowSessions，包含本轮早先成功节点图像与后续空输出。

representation：取消后保留的可能是本轮成功前缀，不是自动合并上一轮成功图像；失败记录与成功记录的图像持有不同。

cache：覆盖旧会话只移除该字典入口的旧引用，不清插件缓存、配置结果、调试记录或独立视图；新session本身仍可保留本轮成功图像。

release：清输出字典、返回取消状态、取消源Dispose均没有逐帧图像Dispose语义。
