⑤ 关闭主窗口：退出请求是否就是所有数据已释放？

原版：已证片段与未知父级桥

应用退出已追到Dispose(bool)向SDK提交销毁请求；请求之后的原生排空仍未知。

谁持有：显示仓库、控件转换位图、排队通知、查询页与native生产缓冲各有自己的寿命。

已确认的收尾：应用退出调用VmSolution.Dispose(isRunBackground)，其bool重载交DestoryHandle(0/1)；与SDKMode无参Dispose的DestoryThirdHandle等待路径分开。OwnerWin_Closed/DeInit及查询Release是其它独立的收尾片段。

此后仍可能存在：查询Release未在原列表内置零或清列表，返回码也未检查；不能据此称重复Release安全，更不能证明所有显示消费者已结束。

待核：主窗父级退出到所有图像读者和原生生产者结束仍未完成同实例证明。

CR06 · 切方案 / 关闭主窗 → 先阻止旧owner发布，scope等待租约；主窗关闭不等于全持有者清零

independent-implementation

切方案ReplaceExecutionScope先使执行owner失效、取消当前请求，显式Clear调试记录、configurationResults、workflowSessions、results等，再Dispose旧scope并创建新scope。scope.Dispose先closing并Cancel，只有取消完成且leases==0才Release；Release清state/services/参数字典，再逐个Dispose可释放资源，失败资源额外存failedResources。主窗关闭与切方案不同：DrainWorkflowBeforeClose先取消活动流程并等activeRun换出；独立调试session由OnClosing等停。OnClosed关闭owner/回调队列、关配置并Dispose scope，但该体没有Clear workflowSessions/results/configurationResults或逐个清控件图像。只可说关闭启动退役，不能说所有外部对象已同步归零。

representation：scope的租约控制state/services清理；NodeRunRecord与WPF/工具显示引用不由同一引用计数统一管理。

CR05 · 工具调试 / 普通配置自执行 / 关闭编辑器 → 停止调度与LastResult、Task结果、宿主缓存分别退役

independent-implementation
