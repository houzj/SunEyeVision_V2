当前图像：构造时复制，传递时保留引用

事实分类：independent-implementation；来源条目 DI06。

这些图像类没有 IDisposable；托管数组寿命由剩余引用和 GC 决定。模块 Dispose 不证明图像已回收，峰值内存和实际 GC 时刻未知。

DI06：完整行为、来源与未知

当前三种图像构造复制输入字节。GraphExecutor的nodeInputs[c.ToPort]=v及结果字典复制只复制PortValue引用；ToolDisplayFrame/ImageLayers可继续保留图像引用。不能将ReadonlyDictionary或ReadOnlySpan说成每一层都复制像素，也不能把模块Dispose当作这些托管图像的显式释放。

这三个图像类无IDisposable，托管数组寿命取决于剩余引用/GC

当前参数：配置快照与输入值是不同复制边界

事实分类：independent-implementation；来源条目 DP04。

连接输入与参数缓存不是同一份数据。ReadEffectiveParameters 复制缓存并覆盖相对 Seed 改变的字段；缓存不等同 native SDK 读回。

DP04：完整行为、来源与未知

GraphExecutor克隆参数JSON、ROI顶点/配置等；输入端口赋值复用上游PortValue。声明默认值在缺项时Clone，订阅解析后覆盖参数或输入。scope.RememberExecutionParameters克隆seed/applied两份；ReadEffectiveParameters复制缓存并覆盖相对Seed已改的配置字段，不把缓存视作native SDK读回确认。

原版三条释放边界：解除固定、关闭映射、外部指针

事实分类：source-confirmed；来源条目 DI01、DI02、DI03。

Dispose 不清旧指针字段，不调用 SharedMemObj.DisposeRes；不能把解除 GC 固定画成外部像素释放。共享映射重开前先销毁旧资源，原生生产者覆写协议与并发有效期未验证。

DI01：完整行为、来源与未知

ImageData setter保留传入数组引用并置SetByte；ImageDataPtr getter在SetByte时pin该数组并返回地址，随后置UnSet。反向getter在SetIntPtr时复制到新数组并置UnSet，但保留旧指针字段。两个表示不等于自动同步的不可变副本；不能据已有byte[]认定旧指针仍有效。

setter先Free旧pin；未在这里释放外部IntPtr

DI02：完整行为、来源与未知

SetDataPtrBySharedMem先释放旧pin，再GetDataPtr并取DataLen；共享对象为空则清指针长度。SharedMemoryItemVM.GetDataPtr在打开新映射前销毁旧资源。DisposeRes的返回值可被后一次关闭结果覆盖；本体不比较ExecuteCountExpected与Current，不能凭两个字段存在声称轮次门已执行。

DI03：完整行为、来源与未知

所选Dispose和终结器只在IsAllocated时Free GCHandle。它们解除托管数组固定，不等同外部像素地址释放或共享映射关闭。Dispose之后字段仍可能保存旧地址，不能继续把ImageDataPtr当有效租约；共享映射有其自己的GetDataPtr/DisposeRes/终结器路径。
