ModuleIdCondition

差异
  • 参数模型不同：原版是 dynamic + 内嵌 model，条件边界以 name_Min/name_Max/name_State 动态键存放；我方是强类型 ConditionRule（Name/RuleType/InputText/MinValue/MaxValue/Judgment/ExpectedText/ExecutionModuleId）
  • 结果模型不同：原版暴露 ModuStatus 与 BranchMatch（疑似单命中）；我方 ConditionResults 输出 NextNodeIds 列表 + MatchedRuleNames，支持多条规则同时命中并剪枝未命中分支
  • 条件表达式承载不同：原版条件通过 IfBranchText 字节与模型传输；我方 InputText 是唯一真相源（节点GUID.属性名 或 常量字面量），不设第二存储位
  • 控制信号契约是我方新增：IControlFlowResult 让引擎强类型读取 NextNodeIds，取代反射取 NextNodeId；原版无此接口，属我方宿主适配
  • 复制粘贴：原版 Paste 把条件引用从旧 ID 重映射到 NewIdList；我方依赖宿主的节点 ID 重映射机制，条件规则内的 ExecutionModuleId 是否同步重映射未在本工具内实现
  • 类型支持范围：我方只支持 Int / Double / String，其余 RuleType 直接抛 NotSupportedException（显式拒绝，不静默）；原版可选类型集合未证
