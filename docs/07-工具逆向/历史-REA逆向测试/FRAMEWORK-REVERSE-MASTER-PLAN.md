## 源码级优先原则

用户明确要求尽量通过REA取得原始源码，避免意图逆向。这是每个任务的首要执行标准：

1. 先确认原始程序版本、路径、SHA256/MVID或native映像身份。查已有同版本REA证据和反编译结果；可复用，但必须可追溯，不能因报告存在就视为完整源码覆盖。
2. 根据目标使用REA：托管程序集先静态身份/成员，再获取具体类型/方法的反编译与CIL；native定位入口、调用者/被调用者、反编译、交叉引用、字段与数据流；资源提取XAML/BAML/XML/字典及绑定。已有合适本地工具可用于具体反编译；不重复安装或大范围重扫。
3. 逐链追踪“入口/绑定→命令或事件→条件/状态写入→模型/身份→持久化→执行效果→错误/取消/释放”。控制流、参数、默认值、精度、顺序、对象所有权都应有原成员或指令证据；不能只复刻窗口外形。
4. 对反编译歧义核对原始CIL/汇编、调用约定、寄存器/栈参数及异常表。伪代码缺少参数不等于真实调用丢失参数；样本字节相似不等于格式语义已确认。
5. 运行取证用于验证源码分支、动态装配及native未知，不以截图或“常规产品应该这样”补规格。优先在明确函数和字段上设观测点，不做无目标点击。
6. REA受限时记录具体目标、函数/地址、工具覆盖/错误、已尝试入口及剩余问题；继续补静态调用者、CIL/资源或受控探针。仍缺证据的行为标unknown。确需独立兼容实现时单独标识理由和差异，不能标为VM行为。

每一条确认结论必须绑定原路径、精确类型/成员或地址/偏移、证据类型、产物哈希与操作记录。静态未发现不等于全程序不存在；运行成功也不等于分支全部覆盖。

## 范围和边界

main负责工具无关的壳、Tab/画布、工具发现与装载生命周期、Group/流程/方案所有权、流程级变量/数据消费、执行调度、历史与存储、最终集成。完整菜单入口的外部服务亦纳入清点：相机管理、通信、全局变量/触发、脚本、综合配置、运行界面、帮助/样例/最近文件/迁移等，按A05逐入口产生子任务，不能留在笼统“其他菜单”下。

tool-plugins负责工具算法及运行所需公共配置模型、模板、专用编辑器、ROI/参数交互、单工具会话和工具私有持久化。main只逆向消费边界并登记FCR，不实现第二份插件配置框架。工具线来信只计“待审证据”，不算main采用，不据此安排其任务或复制其未提交文件。当前四条标定交接均保持此状态。

本计划不新建工作树、不修改tool-plugins。后续若确需隔离开发，先沿用现有规则选择独立可审查改动；未经用户选择的插件合流、设备操作、其他任务进程和安装原件不纳入默认操作范围。现有逆向授权内的只读、可逆测试和main修复继续执行，不额外制造确认门槛。

## 每个任务的固定交付格式

所有包使用同一模板，缺项不得报告“已完成”：

- 身份：任务ID/子ID、main基线、原程序版本、输入路径/SHA256/MVID、REA Evidence ID与工具限制。
- 源码：确切类型/成员/地址/偏移，入口到副作用的调用图，分支/数据流、资源绑定、异常表及所有权；反编译不可靠处附CIL/汇编核对。
- 行为：逐条列source-confirmed、runtime-observed、independent-reconstruction、unknown；每条关联证据，不把四类混写。
- 对照：当前main实际代码/状态、差异、采用或暂缓原因、FCR生产者/消费者与版本兼容。
- 验证：输入/操作/预期来源/实测值/输出文件/失败与退出码；取消、故障、保存重开、执行与释放按相关分支覆盖。
- 产物：唯一报告 `docs/reverse/<任务ID>-<主题>.md`；探针 `tests/NativeEvidence/<任务ID>/`；raw日志/截图/样本/哈希 `analysis/full-audit/<批次>/<任务ID>/`。历史报告保留原路径，可引用不重复复制原件。
- 交付：改动文件、检查命令、提交SHA、未关闭子项、下一项依赖。没有产品改动也应交可复验探针/证据，不能只重复旧报告。

截图/导出/注入和调试帮助代码只留tests，不进产品。原件不修改；单操作保存使用独占副本和新文件名；不默认清零未知内存、放宽容差或吞掉不一致。native浮点误差须先定位首个分叉、运算顺序与精度，阈值依据独立记录。

## 状态、派工与证据门槛

2026-10-19全面对账：现有32包按固定3个具名验收单元映射为96项，源码/实现/验证分别严格计分，三层交集为综合达成率，完整包关闭率单列。权威定义、证据、失败、分母版本与剩余任务见 [成果对账](FRAMEWORK-PROGRESS-RECONCILIATION.md) 和 [数据矩阵](framework-progress-audit.json)。统计基础设施不新增逆向完成项，不把partial折半；新增范围必须保留分母版本变更，不能凭新拆报告抬分。

任务status允许planned、ready、running、evidence-ready、implementation-ready、verifying、closed、blocked。blocked必须写明实际缺失资源/证据/交付、已做工作和解除条件；可并行子项仍继续。JSON初始全部planned，表示本计划新任务尚未执行，不否定历史已实现子集。source/runtime/implementation/operation/differential分别维护，禁止用一个完成百分比折叠。

每批流程：主智能固定SHA与工作树状态→选择依赖满足的任务/子项→登记唯一负责人/文件锁/原机资源→并行取证→审查证据及反编译歧义→确认合同→仅证据充分部分实施→串行构建/实际操作→中文提交和更新台账/HANDOFF/验收源。下一批按未解决问题和依赖挑选，不按“再开四份报告”滚动。

若任务只需源码审查，可关闭其静态子任务；运行、产品或原生差分门槛仍开放。完整包closed须该包所有必需子项及其done标准满足。最终原生兼容声明必须列版本/格式/类型/操作覆盖矩阵；单元测试、WPF事件或原厂SDK返回成功均不足以证明完整等价。

冲突处理：同文件单一写入者、构建串行、原机实例/调试器独占，其他线可同时做离线分析。子智能不得修改他线文件或其他工作树、终止他任务进程。没有并行开发授权时不自行另开子智能；用户本轮要求制定计划，本次不自动启动执行批次或创建定时任务。
