## 3 启动时序（Program.cs `AppAfterStart`，第 204-246 行）

```
1. 自动加载/命令行方案加载（SystemConfigManager.IsAutoLoad 等条件）        ← 方案在这一步已确定
2. if (!flag && GuideHelper.IsGuideWindowShow() && !IsAutoLoad && !IsSdkMode && !IsTakeOver && 非受限用户)
       GuideWindow win; var r = WecPage(out win);     // 内部 BaseWindow.ShowDialog()，模态
       Log “GuideWindowShow close return value”
3. ToolBoxData.ChangePriorityByInfo();                 // 按 ToolBoxType 调整工具箱分类优先显示
4. MainData.IsNormalMode / IsIgnoreGlobalModule / 各种运行期配置初始化
```

关键点：**引导窗口是“覆盖在已就绪主界面之上的模态引导层”**，它出现在方案确定之后、主界面正常模式生效之前；关闭它只是继续第 3、4 步，不产生任何“新建方案”动作。

## 4 结论（原厂真实语义）

1. **引导页不能新建解决方案**：四张卡片不是“新建模板方案”，而是**选择工具箱优先分类**（`ToolBoxType`），写入配置后关闭。
2. **关闭引导页 ≠ 新建方案**：主界面在引导页出现之前就已经持有一个可编辑的工作区（自动加载的方案，或启动初始化的空白未保存方案），关闭后用户直接在该工作区编辑。
3. **最近方案 / 打开其他方案**：用所选方案替换工作区，然后关闭引导层。
4. **“不再显示”勾选语义是反向的**：勾选 = 下次不显示引导页。

## 5 我方现状差异（截至 20261117 构建）

| 项 | 原厂 | 我方 |
|---|---|---|
| 引导页出现时机 | 主界面已持有可编辑工作区之后 | **插件准入之前**以 `ShowDialog` 阻塞，关闭后才尝试建工作区 |
| 关闭行为 | 直接进入已有工作区 | 调 `NewEmptySolutionAsync()`；失败则留下“空壳主界面”，用户看到的是**无效解决方案、无法编辑工作流** |
| 卡片行为 | 写 `ToolBoxType` 配置 + 关闭 | 被我改成“新建空白方案”，方向错误 |
| 最近方案打开 | 替换工作区后关闭 | 同（基本一致） |
| 不再显示 | 勾选=不显示 | 同 |

**因此“关闭起始页后是无效方案、不能编辑工作流”是启动时序错误导致的，不是界面问题。**

## 6 修复方向（待实施）

1. **调整启动顺序**：服务初始化/插件准入 → 创建主窗口（隐藏）→ **建立可编辑空白工作区**（或加载自动方案）→ 再显示引导层（模态，盖在主界面上）→ 关闭/选卡片后只做收尾，不建方案。
2. **卡片语义改回原厂**：写入 `ToolBoxType`（General/Position/Defect/Recognition）配置，启动完成后据此调整工具箱分类优先显示；不再“新建方案”。
3. **失败兜底**：任何打开方案失败都保留当前空白工作区并明确报错，绝不进入空壳态。
4. 回归项：关闭引导页后可直接在流程1 拖入工具并执行；四张卡片分别影响工具箱优先分类；最近方案打开正常；`不再显示` 勾选生效。
