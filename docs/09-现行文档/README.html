现行文档层（09）

最后更新：2026-11-05

本目录回答一个问题：这件事现在是什么样、为什么这样、还没做什么。

每个主题一篇，不按日期下沉，不叠版本。

一、这一层解决什么问题

docs/01~06 是按「类型 + 日期」记的一次性文档：同一个事（相机、通讯、测量、渲染）被写成 10 到 50 篇按日期递增的方案，读者不知道该信哪一篇，也没人做过合并。

本目录把「现在是什么」抽出来，每主题一篇。历史文档原样保留在 01-06，作为演进证据，不再当现行结论使用。

层 目录 定位 能不能当结论
索引层 00-索引 文档索引 + 主题台账 只指路
历史层 01-方案设计 ~ 06-指南参考 按日期的一次性记录 不能，只作演进证据
工具证据层 07-工具逆向 / 08-工具预览 原件证据与调试窗预览 能作证据，不作设计结论
现行层 09-现行文档 每主题唯一权威说明 能
协作层 collaboration 交接、决策、证据、账本 流程凭据

二、统一骨架（每篇都必须有这 8 节）

# 主题名

> 最后更新：YYYY-MM-DD ｜ 状态：现行 / 部分未实施 ｜ 代码基线：commit

## 一句话结论
## 改前用户看到什么
## 改后应该是什么样
## 关键结构（图 + 表）
## 关键决策与理由
## 实施与验证状态（已做 / 未做 / 未验）
## 风险与遗留
## 历史演进（链接到 01-06 各版本）

硬性要求：

  • 开头 10 行内说清「这是什么、现在怎么样」，不铺垫背景。
  • 至少一张结构图（纯 HTML/CSS，零依赖，双击 file:// 可读）+ 至少一张决策表。纯文字大段不算合格。
  • 「实施与验证状态」必须三分：已做 / 未做 / 未验。没验的写未验，不写「已完成」。
  • 「历史演进」列出被合并的每一篇，读者要能追到原始方案。
  • 不复制历史正文，只写合并后的结论与理由。

三、怎么读

  1. 先看 docs/00-索引/主题台账.html，按主题找到对应现行文档
  2. 打开本目录对应篇，看「一句话结论」判断是不是你要的
  3. 需要原始证据时，从「历史演进」跳回 01-06 的具体篇

四、怎么维护

  • 已有主题：改本目录对应篇，不新建日期文档。
  • 新主题：若属已有主题范畴，并入该篇；确实是新主题，才在 01-方案设计 新建日期文档，然后在本目录补一篇现行说明。
  • 改完跑 docs/00-索引/生成主题台账.ps1 与 更新索引.ps1，台账「整合状态」会从「未整合」变「已整合」。
  • 状态口径：现行 = 代码与文档一致；部分未实施 = 方案已定、代码未全做；已废弃 = 方向已改，保留仅为追溯。
