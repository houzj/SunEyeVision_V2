日期：2026-11-14　用途：在继续修改前固定原厂状态边界、证据等级和本方差异。
分析范围：本地图像入口、Blob 输入、参数草稿、执行结果、结果显示层、ROI 编辑层、节点选择、调试窗口打开/关闭、重开、保存与退役。相机链路不在本批范围。

当前结论：问题不是单个形状按钮或单个红框控件的局部 Bug。当前本方把“节点实例重绑、结果发布退役、参数草稿接纳、ROI 编辑帧换代、窗口关闭”串成了同一条清理路径，导致未执行的参数/ROI 修改提前清掉上一次执行快照，导致结果层和文本层消失；同时结果投影层没有在窗口重开时自动恢复编辑会话和选中态。VM 将这些状态分开管理。

二、原厂四条关键状态边界

1. 参数草稿不等于执行结果

参数变化通过 P_ValueChanged 在非运行状态调用 UpdateModuleViewResultShow()。该方法从显示对象以 GetValue(uint.MaxValue) 读取最近可用结果，再重建图形，不触发一次新的 Blob 执行，也不把上一次结果清空。参数修改因此可以改变“下一次执行使用的草稿”，同时保留当前结果层和结果表。

原厂可观察语义：编辑阈值、查找个数、ROI 等参数后，未执行前，Blob 结果、文本、结果表和上一次图像仍然存在。

2. 结果图形层与 ROI 编辑层是两套消费者

RenderControlBase.UpdateShapesWithCallBackData 先清理 shapeBuffer/shapeList，再从当前回调结果重新绘制 Blob 矩形、质心点、轮廓点和文本。ModuleResultView.SetRoiVisible 只控制参数 ROI 在输入图上的可见性。结果层变换不会自动销毁 ROI 参数对象，关闭窗口也只是把 ROIVisible 设为 false。

本方目前把“结果发布退役”和“ROI 编辑帧退役”都挂在节点选择/窗口关闭的统一清理路径上。结果层清空后，ROI 仍可能只剩绿色/蓝色结果投影，橙色编辑控制点和命中状态没有恢复。

3. 执行完成后的重投影发生在结果回调末尾

原厂 ModuleResultView.OnModuleCallBackArrived 在结果交换、图像刷新、结果树刷新之后，检查 ROIVisible && !IsDragROI，再调用 ModuleSource.UpdateROI()。AlgorithmTabRoot.UpdateROI 读取参数中的 ROI 字节并对既有 ROI 对象调用 UpdateIROI。因此执行后的 ROI 位置来自参数几何重新投影，结果图形和 ROI 编辑对象不会混为一体。

4. 打开/关闭窗口只改变可见性，不改变结果快照身份

原厂打开参数页后设置 IsOpenParams=true，随后调用 ModuleResultView.SetRoiVisible()。关闭回调调用 SetRoiVisible(false)，但没有清空 ModuleResultView 的结果数据和图形缓存。切换到另一个真实模块或方案退役时才执行 DoSourceChanged、Dispose 和数据清理。

四、已经证实的根因

  1. 结果快照清理边界错误。 稳定节点 ID 的草稿重绑本应只替换参数/节点实例引用，本方却进入 RefreshFormalNodeSelection 的无条件清理，清掉上一次执行结果。
  2. 保留快照的租约层级错误。 调试快照被作为结果清理的附属状态管理。VM 的最近执行结果属于模块结果存储，编辑窗口关闭只解除编辑视图，不解除结果存储。
  3. ROI 选中态与 ROI 几何混淆。 参数中的 ROI 几何还在时，本方编辑会话/选中项可能已经退役，所以画面可见蓝色或绿色投影，却没有橙色控制点和命中路由。
  4. 编辑视图实例与结果视图实例没有统一稳定身份。 日志明确出现“节点实例或声明配置已变化，不能使用过期视图”。VM 的 ModuleResultView 在同一模块身份下复用显示装饰器，只有真实模块/方案切换才销毁。
  5. 把异步换代通知当成状态清理通知。 本方 ROI 帧换代通知已经补上，但它只负责重新借当前帧，不能承担结果快照保留、节点重绑和编辑选中态恢复。

六、证据缺口与本次不作猜测的部分

  • 已取得 VM 托管层、XML、结果视图和 ROI 更新顺序证据。原生 Process/ProcessOutput/LimitJudge 的内部参数布局和调用顺序仍受当前 REA Windows 提供方边界限制，不能从导出表猜测。
  • VM 是否在所有异常/取消执行中保留上一轮结果，需要补充原机运行证据。当前只把“成功结果在未执行编辑后保持”列为已证实。
  • 本方首个 ROI 自动选中策略没有 VM 直接证据，暂不把它当最终设计依据。重开后的选中态应由稳定 ROI 身份/参数对象恢复，不能用“取第一个 ROI”掩盖缺失的选中状态合同。

七、实施顺序

  1. 先拆分结果 publication、编辑会话、ROI 几何、ROI 选中态和节点实例重绑的清理职责。
  2. 把“同一稳定节点的草稿接纳/实例重绑”改为结果 publication 可继续消费的重绑定，不进入无条件清屏路径。
  3. 把调试快照保留挂到节点/流程/会话稳定身份和最近成功执行轮次，不挂到窗口对象。
  4. 窗口重开时按同一 ROI 参数身份恢复全部编辑 ROI 和选中状态，再由当前输入帧完成一次重投影；结果投影继续从上一轮结果快照读取。
  5. 完成后只做一次 Release 构建，人工验收覆盖“执行→改参数不执行→关窗→重开→命中旧 ROI→再执行→结果层替换→节点切换/方案关闭清理”。
