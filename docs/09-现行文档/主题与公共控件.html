主题与公共控件现行

最后更新：2026-11-05·状态：现行·代码基线：71da36329·合并来源：18 篇历史方案与测试报告（清单见文末「历史演进」）

一句话结论

主题只有一条装配链：AppResources.xaml 合并一次 SDK Generic.xaml，ThemeManager 把 Light/Dark 追加到 Application.MergedDictionaries 末尾，所有主题化属性一律 DynamicResource。工具和 SDK 控件禁止在自己元素级再合并 Generic——那是过去"外层暗色、内部亮色"拼接界面的根因。设计器靠 DesignTimeThemeResourceDictionary（运行时为空）单独拿样式。此链已闭环，并有人工验收确认。

改前用户看到什么

  • 切到暗色主题，工具调试窗里一块亮一块暗：外层面板是暗的，里面的 ROI 工具栏、输入框、分隔线还是亮的。
  • Visual Studio 里打开工具调试窗设计器，一片 XDG 错误（找不到 ThemeDividerBrushBrush、SegmentedToggleStyle），控件看不见。
  • 有的工具图标和按钮在暗色下几乎看不见（浅灰画在浅底上）。
  • 弹窗标题栏还是系统默认样式，和其他界面不像一套东西。
  • 各处零散 MessageBox.Show，样式不统一，也没法统一改。

改后应该是什么样

场景 期望行为
切换 Light / Dark 整窗立即重解析，不出现明暗拼接
打开工具调试窗设计器 无 XDG 错误，图标与样式可见
暗色下 ROI 工具栏 面板/边框/文字/按钮跟着暗，检测蓝和屏蔽橙保持业务语义色
新建工具 XAML 用 SdkThemeKeys 的 DynamicResource，不写死颜色
弹窗 标题栏接入主题，与主界面同一套外观

关键结构

装配链（唯一）

资源优先级（顺序决定一切）：

Application 末尾  Light / Dark     ← 覆盖
        ↓
Application 中    Generic → DefaultTheme  ← 兜底
        ↓
SDK 控件          DynamicResource 取值

设计时与运行时分离

时机 机制 规则
Visual Studio 设计器 工具根显式合并 DesignTimeThemeResourceDictionary；SDK 独立控件由 DesignTimeThemeLoader 注入 该字典运行时为空，不建立局部作用域
独立设计宿主（无 Application） 同上，固定 DefaultTheme 不依赖基类构造时机
运行时 宿主 Light/Dark 覆盖 禁止运行时 OnInitialized 注入 Generic

Key 命名规则

类型 后缀 例
Color *Color ThemeDividerColor
Brush *Brush ThemeDividerBrush
Style *Style SegmentedToggleStyle
Geometry *Path / *Geometry LinkIconPath

Color 与 Brush 不得共用同一 Key，不得出现 BrushBrush。

关键决策与理由

决策 理由 依据
只允许一个 Generic.xaml 装配入口 多个入口 + 元素级合并会让元素资源优先于 Application 资源，暗色被亮色兜底覆盖 20260915 §1
工具与 SDK 控件禁止元素级合并 Generic 正是这条造成明暗拼接；元素级资源优先级高于 Application 20260915 §1/§9
Light/Dark 追加到末尾而不是替换整个字典 WPF 合并字典后写覆盖前写，顺序决定覆盖关系 20260915 §4
一律 DynamicResource，不用 StaticResource 跨字典 跨字典 StaticResource 在 XAML 解析阶段求值，此时资源可能还没装配 20260915 §3.7
同一 Generic 字典内部允许 StaticResource 定义顺序明确、同一解析作用域，安全 20260915 §3.8
Key 必须表达资源类型，且不留旧名兼容别名 新旧名并存会让"到底该用哪个"永久存在 20260915 §5
设计期字典在运行时为空 若运行时也生效，会破坏宿主主题优先级 20260915 §3.3
业务语义色（检测蓝/屏蔽橙）不跟主题 它们是语义而不是外观，跟着主题变会失去辨识 20260915 §4.4
工具根必须在 XAML 里显式声明面板背景与主文字色 实测 15 个工具根背景透明、文字未绑定，才导致明暗拼接 20260915 复验补充
加自动测试守卫而非只写规范 规范靠人守不住，用测试禁止局部合并、跨字典静态引用、旧 Key 残留 20260915 §6.7

风险与遗留

  1. 架构守卫靠自动测试，测试本身就是维护点。 新增主题 Key 或新控件时如果没跑守卫测试，明暗拼接会复发——这条已被修复过一次（15 个工具根背景透明）。
  2. Generic.xaml 是单点。 它是所有 SDK 控件样式的唯一来源，改错影响全部工具。
  3. 设计期与运行时用不同装配路径，这是必要的（设计器没有宿主主题），但也意味着"设计器看着对"不等于"运行时对"，两个都要看。
  4. 业务语义色与主题色的边界需要人判断。 什么算"语义色"（检测蓝、屏蔽橙）没有机械规则，新增控件时容易误把装饰色当语义色保留。
  5. 审计覆盖不等于全量覆盖。 27 个工具 XAML 审计过，但 tools/ 下有 24 个项目，不等同于全部插件与全部控件页都验过。
