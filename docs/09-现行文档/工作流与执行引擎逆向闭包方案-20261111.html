工作流与执行引擎逆向闭包方案

本方案把工作流和执行引擎作为独立核心进行逆向复核。ImageSource + Blob 只作为真实工具载体验证核心合同，不要求先完成全部目录工具。

一、独立闭包边界

方案/流程身份
→
节点与连线图
→
输入绑定与快照
→
调度与执行身份
→
结果发布/阅读
→
取消、关闭、退役

工具算法只在执行节点的声明、输入、输出和宿主资源边界接入。引擎可以用最小测试工具或现有 ImageSource + Blob 验证，不依赖全工具迁移。

三、逆向实施顺序

  1. 冻结方案、流程、节点、连线、端口、绑定和结果身份合同。
  2. 沿 E0–E7 入口链核对创建、编辑、保存重开、节点切换和连线变更。
  3. 核对执行调度的快照边界、拓扑顺序、上游结果、变量和宿主输入。
  4. 核对单次、连续、停止、取消、失败、超时、重复执行和结果发布。
  5. 核对调试窗口、主窗口、方案切换和应用退出的关闭排空与退订顺序。
  6. 用 ImageSource → Blob 做一条生产链验证，再把引擎合同推广给其他工具。

四、独立验收矩阵

类别必须覆盖证据出口

执行拓扑调度、输入快照、结果发布、失败隔离、重复运行引擎探针 + ImageSource/Blob 载体
调试单次、连续、停止、取消、字段修改、迟到回调拒写正式窗口会话 + 调试会话合同
生命周期切节点、换方案、关闭窗口、关闭主程序、插件代次退役资源计数、退订记录、关闭排空结果
性能首屏、首轮、重复切页、调度延迟、关闭排空时间统一计时预算，不能代替 VM 等效结论

五、当前缺口

  • VM 原生 SelfRun 的上游准备、原生算法中止和设备服务释放尚无同版本运行证据。
  • 当前工作流引擎的源码链已具备独立分析条件，但原厂事件时序、结果回调线程和缓存策略需要集中取证。
  • 本次主窗口关闭阻塞已定位为异步子窗口关闭被同步检查，以及插件目录排空无限等待。修正已完成并通过全量 Release 编译，程序和自动测试尚未启动。
