新工具开发基线清单

日期：2026-11-17　参照样本：tools/SunEyeVision.ImageSource（输入类）、tools/SunEyeVision.BlobAnalysis（处理类 + 复杂结果投影）
用途：新增工具的照抄模板。契约矩阵、接入步骤、验收检查表三者配套使用，缺一项不算完成。
前提：框架侧已完成控制流语义（工具按分支序号声明走向）、契约兼容窗口（major 相等 + minor 区间）、结果声明式投影。

一、契约矩阵（按实现必要性分三级）

1.1 必需（缺一不可，否则工具无法准入或执行）

契约职责ImageSourceBlob
IToolDefinition<TSettings,TOutput>工具身份、Describe() 端口声明、Validate()、CreateSession()✓✓
IToolSettings<TSelf>Freeze() 冻结设置；冻结值才进入执行与持久化✓✓
IToolOutputToValues() 输出端口取值✓✓
IToolSettingsFields参数页字段、默认值、逐字段校验（SettingsSchema）✓✓
IToolCatalogProvider工具箱显示名、分类、描述、排序✓✓
IToolResultPresentationProvider结果投影声明（ResultProjectionDescriptor / ResultDisplayDescriptor），Runtime 侧可用、不依赖 WPF✓✓

1.2 呈现相关（有结果表/显示设置就要实现）

契约职责何时实现
IToolDisplaySettingsProvider呈现专用字段：随工具持久化，不是算法参数、不进调用输入工具需要“显示选项”类设置（如显示模式、颜色策略）
IToolResultDisplayProvider : IToolDisplaySettingsProvider在显示设置之外，把结果字段绑定到显示结果需要按要求显示（表格列/属性列表/叠加层）时
两条路径不是二选一随便挑：只是有显示选项 → IToolDisplaySettingsProvider（ImageSource 是这种）；还要把结果显示出来 → IToolResultDisplayProvider（Blob 是这种）。

1.3 执行期能力（按需，不实现即走缺省）

契约用途缺省行为样本
IToolExecutionInputs把输入端口/绑定值映射成设置，冻结一次复用需按实例参考，新工具若无输入端口映射需求可不实现Blob
IToolHostInputDeclaration声明“本次执行由宿主提供输入”（如本地图像/相机帧）不声明则宿主不准备输入ImageSource
IToolResourceFieldDeclarations声明资源字段（图像/区域等引用字段）不声明则无资源字段ImageSource
IToolExecutionFilter冻结设置下判定“本次是否执行”（纯判定，不取输入）不实现即总是执行（执行链按 is IToolExecutionFilter 判定）ImageSource
IToolRuntimeInitialization进程级一次预热（如原生平台装载）不实现即跳过预热，首次执行付成本两者
IToolParameterBindingNames为每个被引用字段提供绑定记录排序键—（引用记录顺序按工具声明）两者
IToolManualReferenceSources普通手动参数引用的可用来源—两者
IToolParameterReferenceBehavior参数被引用时的消费语义（不推断工具身份/UI 状态）—Blob
IToolDormantParameterDefaults参数停用时仍保留持久绑定，恢复后沿用—两者
IToolFieldTransitions字段联动（触发与效果同一次编辑生效）—Blob
IToolKnownSettingsValidation已知设置组合的显式校验—Blob
IToolResultGeometryOutput / IToolResultRecordOutput同一次成功调用产生的几何 / 文本记录—按需

1.4 分支能力（仅分支类工具需要）

工具在 Describe() 的 controlOutputs 声明分支（按声明顺序编号 0..n-1），执行结果用 ToolOutcome.SelectedBranches 返回选中的序号。宿主把序号映射到该节点的出边，未命中目标标 Skipped（不是失败，不参与合格判定）。 工具不需要知道节点身份，连线保持“节点对”语义——与原厂一致（选择在工具内、后继解析在执行器）。越界序号会判失败而不是静默跳过。

二、宿主侧契约（工具不实现，但要知道）

契约由谁实现说明
IHostInputPreparer / IPreparedHostInputs宿主一次冻结的宿主输入；即使执行未开始也会被释放
IHostInvocationGate宿主单次调用的准入闸门，过期身份拒绝迟到回调
IToolEditorContext宿主受限编辑能力；调试冻结作用域，正式执行不暴露
IResourcePathResolver宿主按冻结文档基准解析资源引用，不依赖 UI 或旧 SDK
IReadOnlyImage宿主借用的冻结图像；适配器必须给真实数据，不得用尺寸推导兜底

三、接入步骤（照抄顺序）

  1. 建两个项目：tools/<Tool>/Runtime（算法与契约实现，无 WPF 依赖）与 tools/<Tool>/Wpf（参数页/结果显示）；在 product/ToolComponents.props 登记两个组件。
  2. 实现 1.1 六个必需契约；Describe() 声明输入/输出端口（端口 id 即绑定名）。
  3. 按需实现 1.2 / 1.3；判断标准是“不实现会怎样”，矩阵里已写缺省行为。
  4. 实现工具契约版本：ToolComponentMetadata 的 contractMajor 必须等于 FoundationContract.Major，contractMinor 不得高于宿主；宿主接受 [OldestCompatibleMinor, Minor] 区间。
  5. 结果声明：给出 ResultProjectionDescriptor（字段投影）与 ResultDisplayDescriptor（显示需求）；需要显示的资源（region/outline 等）必须写进显示需求，否则结果页缺图。
  6. 原生平台预热（用到 HALCON 时）：实现 IToolRuntimeInitialization，内部调用 HalconPlatform.Initialise()；不得在预热里读用户图像、改设置或依赖执行身份。
  7. 写测试：Runtime 侧至少覆盖“正常输出、边界/空输入、参数校验失败、显示需求声明完整”。
  8. 重建顺序：先建测试项目 → 再建 src/UI（刷新 release-payload.json）→ 再 dotnet test --no-build。顺序反了会因载荷 SHA 不匹配导致测试加载失败。

四、验收检查表

#检查项通过标准
1工具箱出现启动后分类下可见，名称/描述/图标正确；不可用时隐藏而不是灰显
2拖入画布生成节点、参数页可打开、默认值符合声明
3参数页字段分组/显隐/联动与原厂对照一致；非法值有明确提示
4结果页结果表/属性列表有值；需要图形的（region/contour/point）能叠加；缺失字段显示为不可用而非 0
5单次执行节点状态成功、结果发布、耗时进探针（[Perf]）
6连续执行轮次推进正常、停止能排空、暂停/恢复可用
7保存/重开设置与显示选项往返一致；资源（图像/嵌入文件）能解析
8异常路径非法输入 → 明确诊断，不崩溃、不静默产出空结果
9生命周期重复执行不累积资源（[LifecycleProbe] 计数归零）
10分支（若声明）选中的分支执行、未选中为 Skipped、整轮仍判成功

五、已知限制（新工具不会碰到，但要知道）

限制原因（有代码依据）替代
工具目录不支持热插拔：加/换工具必须重启程序准入代次被三处持有：App.xaml.cs:311 进程级 pin、ServiceInitializer.InitializeSolutionManager 只初始化一次、MainWindowViewModel.Toolbox 只读属性；且发布时序为“先退役旧代次再发布”，中途失败无可回退重启程序（约 10 秒）
分支工具必须按序号声明，不能自选目标节点宿主映射出边，工具不接触图结构（与原厂一致：选择在工具内、后继在执行器）—
控制输出声明会改变 schema 指纹（仅当声明非空）指纹参与已保存方案的兼容判定；无分支能力的工具指纹保持不变，故不破坏既有方案—
算法性能上限受第三方库约束（如 HALCON 逐区域算子）逐 Blob 调用 45 次 vs 原厂原生一次遍历；按需跳过会破坏显示语义，批量算子不支持逐区域返回如需追平，需算法体原生重写（单独立项）
