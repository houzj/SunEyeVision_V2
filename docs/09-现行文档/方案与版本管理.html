方案与版本管理现行

最后更新：2026-11-05·状态：现行·代码基线：71da36329·合并来源：22 篇历史方案（清单见文末「历史演进」）

一句话结论

两件事分开说。版本：交付版本号只有一个真源 version.json，所有产物（主程序、SDK、全部工具）的 FileVersion / InformationalVersion 都等于它；AssemblyVersion 恒定 2.0.0.0，只作程序集绑定身份，绝不跟交付版本走。方案：方案文件必须能独立传递（任意路径可载入），资源文件单独传、单独重配，旧数据有迁移路径。

改前用户看到什么

  • 资源管理器里打开安装包，主程序是 2.0.0.1，SDK 是 1.0.0.0，工具各有各的版本号，售后问"客户装的是哪版"没法回答。
  • 某次改了版本注入之后，工具箱直接空了：18 个插件全部"契约不兼容"被拒载，日志 成功 0 个，未加载 18 个。
  • 方案拷到另一台机器打不开，因为它依赖固定路径下的资源文件。
  • 方案里引用的图片丢了之后，每次打开都报错，没有任何清理入口。
  • 关闭窗口时方案没落盘，或者状态（打开/关闭）记错了。

改后应该是什么样

场景 期望行为
看安装包里任意一个 dll 的版本 都是同一个交付版本号（如 2.0.0.1）
排查"这是哪次构建" InformationalVersion 带提交短 SHA
主程序大版本升级 不要求 18 个工具全部重编
方案拷到任意路径 / 另一台机器 能打开
资源文件缺失 有明确提示与清理入口，不每次报错
关闭窗口 按明确规则落盘，状态正确

关键结构

三个"版本"互不推导

词 大白话 持有者 变不变
交付版本 这批货是第几版（2.0.0.1） version.json 每次打包第 4 位 +1
契约编号 接口标准是第几版（2.0） ToolContractVersionAttribute + ToolContract 仅接口不兼容时变
绑定身份 程序集的身份证号（2.0.0.0） Directory.Build.props 2.x 内恒定

三者互不推导，唯一接触点是"宿主按契约编号决定放行/拒绝插件"。

一个 dll 里三个字段各放各的

字段 放什么 谁看它
FileVersion 交付版本 2.0.0.1 人：资源管理器、关于窗口、售后
InformationalVersion 交付版本 + 提交 SHA 2.0.0.1+4bfe67c5 人：排查"哪次构建"
AssemblyVersion 绑定身份 2.0.0.0 机器：CLR 程序集绑定

⇒ "统一"指前两个字段统一成产品版本；第三个恒定不动。 不是把三个合成一个。

方案文件与资源

归属 规则
方案文件 必须能独立传递；任意路径可载入；不依赖固定安装路径
资源文件 单独传递、单独重配；方案里存引用而不是内嵌二进制
失效引用 允许清理，不每次打开都报错
旧数据 有迁移路径，不做静默丢字段

关键决策与理由

决策 理由 依据
交付版本只有 version.json 一个真源 多处写版本必然漂移；发布流程要能自动推导 20260918 / 20260919
AssemblyVersion 恒定 2.0.0.0 事故实证：把产品版本注入 AssemblyVersion 使 SDK 主版本 1→2，18 个插件全部被拒载 20260919 §4
插件放行只看显式契约编号，不读 AssemblyVersion 否则主程序每次大版本升级都要求所有工具重编，"工具可独立迭代"失效 20260919 §4
工具与 SDK 版本默认跟随产品 单安装包单版本，售后一句话能说清 20260919 §6
单产物打包、自动推导 手工改版本号必然出错 20260919（承接 20260918）
方案文件可独立传递 方案是要交付给客户/另一台机器的产物，不是本地缓存 20261008 §2
资源单独传、单独重配 内嵌资源让方案体积膨胀且难以替换 20261008 §3
允许清理失效资源引用 缺失资源若每次报错，用户无法自救 20261008 §4

风险与遗留

  1. AssemblyVersion 是最容易被"顺手统一"的坑。 任何人为了"版本看起来一致"把交付版本注入 AssemblyVersion，都会重演 18 个插件被拒载。这条必须写进发布检查项。
  2. 契约编号变更需要人判断。 什么算"接口不兼容"没有机械判据，判错会导致老工具被放行或新工具被拒。
  3. 方案文件"可独立传递"依赖资源引用的相对化。 只要还有一处写死绝对路径，跨机器就断。
  4. 失效资源清理是手动入口。 用户不清理就会持续看到缺失提示。
  5. 发布流程与版本注入的具体实现分散在构建脚本里，改打包脚本时要同时检查 version.json、Directory.Build.props 与各 csproj 是否还有本地版本声明。
