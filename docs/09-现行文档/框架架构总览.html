范围呈现合同补充（2026-11-11）：原件范围组与两个数值端点具有不同显示名。现通过既有FieldLayout的PairDisplayName记录组标题，端点保留自身声明名称；Blob的27个范围从同版本XML与语言资源逐项迁入，公共控件不再根据中文文本推导标题。值、引用、执行及资源身份合同不变。全量Release0错误；人工外观/交互未验，不计作整链完成。

2026-11-11实机问题修正：参数组合的可选宿主输入与必选原件单选之间只适配编辑器默认值投影，正式字段身份与写入合同保留；底栏模板不再把祖先框架作为Content，改为直接绑定其命令；枚举候选扩展继承公共原件条目样式，避免宿主隐式样式覆盖原件呈现。最新全量Release0错误，运行和人工验收另列；按用户要求后续不控制桌面、不启动程序或测试。细节与未验项见原主审计方案和Blob控件依赖闭包台账，本批未改变架构完成口径。

四、工具控件重设计的原因

CodeBuddy 重设计的直接动因是控件较多时窗口首次打开慢、Tab 切换慢，以及当前整体界面与 VM 存在差异。架构评审必须覆盖三条链：

  • 打开链：模型构造、模板选择、资源加载、绑定和首帧显示。
  • 切换链：控件/模型复用、销毁重建、状态保存、重复解析/绑定和资源释放。
  • 对标链：VM 与当前实现的布局、参数分组、动态显隐、状态和关闭行为。

没有 VM 证据的缓存、异步或延迟加载只能标记为 CodeBuddy 候选，不能写成 VM 已确认机制。

工具调试窗口硬约束：按 VM 原厂完整组装链核对窗口创建、配置模型、模板/资源、绑定、命令、回调、Tab 复用、换节点关闭和释放。VM 原厂没有主题切换能力，SunEyeVision 不再设计运行时主题切换；只保留与 VM 装配链一致的固定主题资源。打开和 Tab 切换的流畅性必须由真实 VM 证据解释，不预先假设缓存、异步、虚拟化或延迟加载。
