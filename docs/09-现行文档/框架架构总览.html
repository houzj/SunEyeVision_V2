四、工具控件重设计的原因

CodeBuddy 重设计的直接动因是控件较多时窗口首次打开慢、Tab 切换慢，以及当前整体界面与 VM 存在差异。架构评审必须覆盖三条链：

  • 打开链：模型构造、模板选择、资源加载、绑定和首帧显示。
  • 切换链：控件/模型复用、销毁重建、状态保存、重复解析/绑定和资源释放。
  • 对标链：VM 与当前实现的布局、参数分组、动态显隐、状态和关闭行为。

没有 VM 证据的缓存、异步或延迟加载只能标记为 CodeBuddy 候选，不能写成 VM 已确认机制。

工具调试窗口硬约束：按 VM 原厂完整组装链核对窗口创建、配置模型、模板/资源、绑定、命令、回调、Tab 复用、换节点关闭和释放。VM 原厂没有主题切换能力，SunEyeVision 不再设计运行时主题切换；只保留与 VM 装配链一致的固定主题资源。打开和 Tab 切换的流畅性必须由真实 VM 证据解释，不预先假设缓存、异步、虚拟化或延迟加载。
