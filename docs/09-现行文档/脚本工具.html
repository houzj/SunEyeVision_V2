脚本工具部分未验

最后更新：2026-11-05·状态：部分未验·代码基线：71da36329·合并来源：14 篇历史方案（其中 2 篇实为误聚类，见文末说明）

一句话结论

脚本工具是「编译 → 常驻沙箱 → 每次新建实例」的执行模型：脚本代码编译一次后程序集常驻不卸载，每次执行只新建实例，从而让首次与后续执行耗时接近。引用用 BCL 白名单 + 宿主 API 类型锚定，不靠运行时反查。编辑器是 ScriptEditorCore（语义高亮 + 分析管道 + 补全）放在 CommonControl，工具侧只组装。能力已落地，但性能目标与人工验收没有记录。

改前用户看到什么

  • 同一段脚本，第一次执行 74ms，之后 2ms，差 70 多毫秒。工作流里脚本节点一多，第一轮明显卡。
  • 脚本里用 HOperatorSet / Mat，编译报 CS0246 找不到类型，或 CS0012 需要 mscorlib 引用。
  • 打字时编辑器一顿一顿，光标跟不上手；补全弹窗挡住正在写的代码。
  • 脚本的输入输出全是英文变量名，界面上看不出哪个是"圆心X"、哪个是"OK/NG"，改脚本时对不上号。

改后应该是什么样

场景 期望行为
连续执行同一脚本 首次与后续耗時接近（目标差异 ≤ 5ms）
改脚本代码后再执行 新代码生效，旧程序集被隔离，不混用
多个脚本节点（不同代码/引用） 各自独立沙箱，互不干扰
并发执行同一脚本 实例彼此隔离，结果不串
长时间运行 沙箱数量有上限，不无限增长
脚本里用 Halcon / OpenCvSharp 类型 编译通过，运行正确
打字 高亮与补全在后台增量计算，不阻塞输入
配置输入输出 变量名旁显示中文名，界面可读

关键结构

执行链

隔离单元是沙箱（ALC），不是实例。 程序集常驻，实例每次新建。代码变化 → 缓存键变化 → 新沙箱；旧沙箱等 LRU 淘汰，无需显式失效。

引用装配

  • 不用运行时反查已加载程序集。CLR 惰性加载时那些程序集可能还没加载，反查会落空。
  • mscorlib.dll 必须显式引用：halcondotnetxl.dll 是 .NET Framework 时代程序集，元数据引用 mscorlib 2.0.0.0；它不在 TPA 里，必须从 RuntimeEnvironment.GetRuntimeDirectory() 定位后 CreateFromFile。

编辑器分层

层 位置 职责
编辑器控件 CommonControl/ScriptEditorCore.xaml 文本编辑、渲染
语义高亮 CommonControl/SemanticHighlighter.cs 词法/语义着色

关键决策与理由

决策 理由 依据
沙箱按编译缓存键分组常驻 每次新建 ALC 会让用户代码 JIT 重新发生，这是 72ms 差异的主因 20260825
程序集常驻、实例新建 常驻省掉加载与 JIT；实例新建保证状态干净、并发安全 20260825
缓存键 = codeHash|宿主指纹|引用指纹 三维都变才需要新沙箱，改代码不误用旧程序集 20260825
LRU 上限 16 常驻必然占内存，加边界防泄漏 20260825
宿主引用用类型锚定而非运行时反查 CLR 惰性加载，反查依赖"恰好已加载"，不可靠 20260824（后修正）
mscorlib facade 显式引用 Halcon 程序集元数据依赖它做类型统一，缺了必报 CS0012 实施期修复
分析管道异步化 同步高亮在大脚本上阻塞输入线程，表现为打字卡顿 20260819~21
编辑器内核放 CommonControl 编辑器是被复用的控件能力，不该塞进单个工具 架构分层

未做

  • 本表基于代码存在性核对，没有逐项对照各方案的验收清单。以下能力未在代码中确认：
    • 沙箱池的 LRU 上限实际取值与淘汰策略是否按 16 执行
    • ScriptSandbox 的"同 key 换新程序集"热替换路径是否实现
    • 沙箱获取/加载异常时的临时沙箱回退是否保留

未验

  • 性能目标未验：方案目标是「首次 ≈ 后续，差异 ≤ 5ms（74ms → ~3ms）」，没有找到实测记录。
  • 沙箱数量上限下的长时间运行内存观察未做。
  • 并发执行同一节点的正确性未记录。
  • 脚本用 Halcon / OpenCvSharp 的真实执行结果（不只是编译通过）未做端到端验收。
  • 编辑器高亮/补全的目视验收（深浅主题下可读性）未记录。
  • 已知遗留：Script.Tests 曾有 10 个用例失败（AvalonEditTextContainer 命名空间迁移、SemanticHighlighter 源码路径），修复状态未确认。

风险与遗留

  1. 性能目标与实现脱节。 代码已经常驻复用，但没有任何实测数据说明"首次与后续接近"。在补上实测前，不能对用户宣称"脚本执行时间一致"。
  2. 常驻沙箱是内存换速度。 16 个沙箱各带一份程序集与 JIT 结果，长时间运行、多脚本节点的方案需要观察实际内存。
  3. 缓存键含"宿主指纹"。 宿主 DLL 更新后旧沙箱应失效，但如果指纹计算没有覆盖到具体程序集版本，可能用到旧宿主类型，表现为"改了宿主代码但脚本行为没变"。
  4. 引用装配依赖编译期类型锚定。 宿主新增可被脚本使用的公开类型时，必须同步在 MetadataReferenceProvider 里加锚点，否则脚本编译不到——这是个需要写进开发规范的隐性耦合。
  5. 编辑器跨项目共享。 ScriptEditorCore 在 CommonControl，脚本工具与可能存在的其他编辑场景共用，改动影响面比"只是个工具"大。
