订阅绑定与 ROI 几何部分未实施

最后更新：2026-11-05·状态：部分未实施·代码基线：71da36329·合并来源：18 篇历史方案（清单见文末「历史演进」）

一句话结论

绑定只认稳定身份（工作流 ID + 节点 ID + 输出字段 ID + 属性路径），不认名称、序号、显示文字或当前值。上游发生真的不适配变化时，直接解除受影响输入并要求重绑；改个名、挪个位置、值变了都不解绑。判定统一为三态：适配→保留，不适配→解绑，信息不足→保留但标记待校验并阻止执行。B1、B2 与 B3 核心已落地；B3 尚未接入窗口和执行入口，B4 增量索引未做。

改前用户看到什么

  • 上游工具改了输出类型，下游那个输入还显示着原来的字段名，执行时找不到就回显一串 GUID，用户不知道发生了什么。
  • 上游删了字段再新建一个同名字段，下游自动"接上"了，但其实两个字段毫无关系，跑出来是错的。
  • 改个节点名或者换个字段顺序，绑定全红、要求重新配一遍。
  • 接收工具从「设备模式」切到「变量模式」，两个模式各自有一个 out0，下游绑定悄悄指到另一个 out0 上了。
  • 删掉一条画布连线，用户手工设置的显式绑定跟着没了。
  • 关掉工具窗口再打开，失效的旧引用被控件又写回参数，解绑白做了。

改后应该是什么样

变化 期望行为
当前值 / 报文内容变了 保留绑定，下次执行取新值
节点名、字段名改了，或字段重排 保留绑定，只刷新显示
同一逻辑输出换了来源但消费规则仍适配 保留绑定，刷新类型与来源信息
类型、形状、元素路径、解释方式变了且不适配 解除所有受影响输入，要求重新绑定
字段删除 / 身份被替换 / 节点删除 解除该旧身份的全部绑定
删除后又新建同名字段 新身份，不自动恢复旧绑定
连接新增 / 删除 / 替换 按连接语义处理；删除连线只清它自己产生的自动来源，不动显式绑定
节点禁用或分支跳过 只更新本次执行有效性，不当作字段删除
契约信息不足、无法确认 保留引用 + 标记「已绑定（待校验）」，阻止执行，不是可执行兜底

关键结构

三态判定与影响传播

不得隐式转换、拼接、截断或修改解析模式来"让它适配"。

身份构成

对象 身份 明确不参与身份
来源 工作流 ID + 节点 ID + 输出字段 ID + 属性/元素路径 显示名、序号、控件文字
目标 工作流 ID + 节点 ID + 输入参数/输入行 ID 同上
全局变量 稳定变量身份 可修改的变量名
连接自动绑定 额外记录关联连接身份（AutomaticConnectionId） 第一候选来源

关键决策与理由

决策 理由 依据
绑定跟随稳定字段身份 名称会改、顺序会变、值会变，只有身份稳定 20261013 最终规则
不适配时直接解绑，不留失效引用 保留失效引用会让用户以为还能用，且会导致执行期找不到字段 20261013（取代早先"保留并要求修复"的建议）
解绑只清受影响输入，不清空其他合法绑定 一改就全红会让用户不敢动配置 20261013
只清受影响输入，不按同名字段自动重连 同名不同身份，自动重连等于猜 20261013
三态里"信息不足"必须阻止执行 待校验不是兜底，放行会产生不可解释结果 20261013（对齐禁止静默兜底原则）
删除连线不清显式绑定 连线与绑定是两件事，合并处理会误删用户配置 20261013 §连接与数据绑定
连接自动产生的绑定失去合法来源时清除而非换源 换第一个候选是猜测，用户无法预期 20261013 B1
显式数据绑定本身建立执行依赖 只靠画布连线决定执行顺序时，删线就断数据 20261013
拒绝候选变更时保持旧正式配置，不为消环删其他合法绑定 消环的代价不应是用户数据 20261013
引用索引是派生查询，不是第二套配置 两套存储必然不同步 20261013 §引用索引
撤销重做恢复整个已接受配置，不只画布 只恢复节点/连线会让绑定与配置错位 20261013 B3
恢复产生新版本，旧版本不重新成为当前 版本回退会破坏"运行中快照不变" 20261013 B3
接收节点统一维护逻辑输出行，切模式保留 FieldId 两套 out0 是身份混乱的根因 20261013 §接收输出身份优化

未做

  • B3 宿主整体接入：窗口与执行入口尚未调用网关。Default / Custom 窗口的统一执行与关闭校验、提交后草稿重绑、失效编辑器提示、CommandManager 事务历史都未接。
  • B4 增量索引：当前复查仍是扫描模型，不是带版本的增量索引。
  • B5 完整验收：全入口、全生命周期、UI 人工验收未做。
  • 外部拓扑或变量编辑尚未纳入网关。
  • 结果版本统一失效未做（设计结果与运行结果空间的版本联动）。

未验

  • Visual Studio 设计器、高 DPI 目视验收。
  • 用户多入口实际操作（单节点、工作流、主界面、图像预览四种触发）。
  • 真实旧方案兼容（不要求重建方案）。
  • 关闭窗口失败时"继续编辑 / 放弃未提交编辑"的实际交互体验。

风险与遗留

  1. 最大风险：能力做了但没接上。 B3 的核心与网关都有测试（135 项 + 127 项专项），但窗口和执行入口还没调用。这意味着用户当前体验到的是 B2 行为，不是 B3。任何"绑定原子性已解决"的说法都要先看这个接入是否完成。
  2. 实时写入架构下没有真正的草稿取消。 已写入参数的内容不会回滚，退出提示必须说明这个边界，不能自称"完整草稿取消"。
  3. 待校验态会让节点无法执行。 这是刻意设计（宁可拦住不猜），但需要可读的提示，否则用户会以为工具坏了。
  4. 候选列表为空 ≠ 字段已删除。 上游没执行、设备断线都可能让候选为空，据此解绑是错的。这条在实现里已有区分，但容易被后续改动破坏。
  5. 接收工具的模式切换身份已优化，但已失效的旧工程引用不会按 out0 名称自动迁移，开发期需用当前契约重新确认。
  6. 扫描式复查在方案变大后会变慢。 B4 未做，节点数多的方案每次提交都要全扫。
