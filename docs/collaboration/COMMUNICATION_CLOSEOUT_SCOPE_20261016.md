# 通讯整改收尾范围和验收清单

本轮目标是让现有通讯功能稳定、真实、可取消，不继续扩充通讯平台。此前逐场景修补缺少统一的状态转换验收，应改为按以下固定范围一次验收，发现可复现问题才修复。清单中的待检查项不等于已发现的缺陷，也不代表已经完成真实设备验收。

适用范围为当前已接入的TCP客户端、TCP服务端、UDP、串口、Modbus TCP/RTU、S7、OPC UA和CIP。未接入协议、新协议能力和标定不在本轮范围。

## 固定的交互约定

| 操作或条件 | 预期行为 |
| --- | --- |
| 禁用设备，不论AutoReconnect如何 | 撤销连接资格并取消旧任务，不再接受旧连接结果 |
| 再次启用且AutoReconnect开启 | 先完成必要的旧连接清理，再由唯一重连入口恢复，无需手动连接 |
| 再次启用且AutoReconnect关闭 | 不因重新启用而自动连接，用户可手动连接 |
| 已启用设备在断开时开启AutoReconnect | 自动开始重连 |
| 等待重连时关闭AutoReconnect | 立即取消等待和旧尝试，不能稍后生效 |
| 健康连接上关闭AutoReconnect | 不为关闭该选项强制断开当前健康连接 |
| 列表手动断开且AutoReconnect开启 | 按此前用户约定重新连接；列表开关仍只反映实际连接 |
| 列表手动断开且AutoReconnect关闭 | 保持断开 |
| 删除设备 | 永久撤销该对象的运行资格，排队开启事件不得恢复它 |
| 切换方案 | 旧任务失效，新方案同ID设备不能继承旧会话或旧错误 |
| 关闭通讯管理器 | 后台策略继续；重开不重复创建任务、不重置倒计时 |
| 自动重连连续失败5次 | 停止本轮重试并将AutoReconnect实际配置开关关闭，保留停止摘要和最后失败原因；窗口重开及迟到断线事件不能启动第6次；用户再次打开AutoReconnect即重置计数并自动开始新一轮，无需先关再开或手动连接；关闭后仅禁用再启用不自动重连 |

2026年10月16日用户追加五次上限及停止后开关同步规则，上表所有自动重连均受此约束。初次连接、手动连接和主动取消不计作自动重连失败。达到上限后更新当前方案内存中的既有autoReconnect设置，沿用原保存流程，不主动写方案文件、不新增配置字段；重新开启后的策略等待旧任务清理完成再开始，保持每设备唯一任务。

## 八类必要检查

| 编号 | 范围 | 一次验收应覆盖的边界 | 集中源码排查结论与运行验收状态 |
| --- | --- | --- | --- |
| C1 | 状态一致性 | 开关、状态灯、文字、倒计时、失败原因与实际会话一致；监听和端口绑定不冒充远端在线 | 源码排查完成，保留真实会话状态绑定，旧方案窗口不再更新新方案显示；实际灯、开关、倒计时待人工验收 |
| C2 | 生命周期与并发 | 初次连接、掉线、AutoReconnect开关、禁用再启用、窗口关闭重开、删除、切方案、快速交替和同ID隔离 | 源码排查完成，复核原去重、版本及所有者隔离；设备和旧方案取消源改为缓存令牌后及时释放；快速操作和晚到连接待人工验收 |
| C3 | 实时读写和失败隔离 | 界面与工作流使用同一有效会话；断线不能用旧值报成功；会话更换后的旧结果不得采用；协议拒绝不能一律等同断线 | 已补取消后结果复核、OPC UA写入会话校验、准备发送到实际提交的会话身份校验和设备令牌；实际读写及不确定写入待人工验收 |
| C4 | 重连后的任务恢复 | Modbus轮询、OPC UA订阅和周期读、接收事件、心跳恢复正确；同设备或同数据点不能重复工作；旧轮询不能覆盖新结果 | 已追踪停止后仍收尾的轮询，修复订阅失败清理和取消订阅本地状态、心跳重新启用恢复、自动响应禁用取消；真实恢复和去重待人工验收 |
| C5 | 超时取消和资源回收 | 服务端不可达、请求超时、端口占用、取消期间原生调用晚到；设备门、会话、计时器、接收线程和订阅不持续积累 | 已回收TCP服务端完成的接收任务，补原始发送及CIP退出超时、Modbus取消中止传输且等待旧I/O退出；长期任务/句柄/内存及慢驱动待人工验收 |
| C6 | 协议报文和数据契约 | TCP和串口分包/合包及结束符，UDP数据报边界；Modbus地址/数量/字节序；S7/CIP类型；OPC UA NodeId、值类型和质量；失败写入结果不确定时不得自动重放 | 源码排查完成，补TCP发送串行和半帧取消退出、Modbus读范围、CIP响应上下文/会话/选项校验，OPC UA非Good写响应不报成功；真实报文与设备兼容待人工验收 |
| C7 | 配置与绑定兼容 | 保存再打开、放弃修改、改名、删除、地址和协议变更后的应用边界；旧方案与输出身份不丢失；失效绑定明确显示 | 已保护旧窗口保存/放弃修改和事件/心跳/自动化配置写入归属，未改持久字段、输出身份和绑定格式；旧方案打开及保存回退待人工验收 |
| C8 | 诊断和界面响应 | 错误包含设备和原始原因；取消与真实连接失败可区分；等待可见；窗口和工作流不会因连接等待被同步阻塞；断线日志不无限刷屏 | 已把OPC UA同步浏览放到后台、释放浏览游标，高频FC03明细保留文件而不逐条刷UI，抑制取消后旧心跳/周期读错误；压力下界面响应和日志容量待人工验收 |

## 如何执行并结束本轮整改

先完成已明确授权的禁用再启用修复和Release构建，保留配置、绑定和输出契约。然后由人工按C1到C8核对实际使用协议：公共生命周期场景每个使用中的协议都覆盖，协议专项只检查对应协议；没有设备的协议记录为未验收，不冒充通过，也不为此重写驱动。

验收记录至少包含协议、设备、场景编号、最终设置、观察到的实际会话与界面状态、日志和结论。重点将快速切换、原生建连未完成时取消、服务器随后恢复、同ID切方案放在同一轮验收中，而不是每次新增一条改动后另起一轮范围。

只有可复现的卡死、错连或错写设备、旧值冒充成功、重复后台任务、取消后复活、原配置/绑定破坏等正确性问题继续阻塞收尾。完成修复后复核对应条目。其余体验改进进入后续清单，不阻塞回到视觉算法主线。

满足以下条件即可冻结通讯代码并回归主线：八类检查在实际使用范围有明确结论，严重问题已关闭，Release构建通过，部署文件一致，保留一份人工验收记录。未使用协议的运行验收状态单独保留，不承诺以后绝无问题；后续新需求不自动并入本轮整改。

## 不阻塞本轮的后续优化

- 可配置退避曲线、重连抖动和更丰富的统计图表。
- 批量读写、连接池、吞吐性能调优和更细的监控指标。
- 新协议、新PLC机型、新报文模式、通讯界面重新设计。
- 独立的自动化故障注入和长期压力验证体系，须另行获得运行授权。

生产部署的认证、证书、权限、日志脱敏和网络隔离必须按真实环境单独确认；它们不是可以忽略的安全问题，但本轮不擅自修改用户证书、服务器、安全策略或已有连接配置。当前匿名隔离环境能通信不代表生产安全验收通过。
