## 核心算法是逐工具对比重点

1. 先清点自研已存在有效执行路径的工具，以当前源码确认，不能用Tool声明、菜单或调试窗口存在代替实现。区分图像算法、几何计算、数据/控制工具；占位分支与真正调用分开。
2. 对每个已实现工具依次核：实际入口→输入准备→预处理→算子/公式与处理顺序→候选选择/后处理→结果与失败。包含被调用的自研公共算法/适配器，不能只停在插件的Run或DLL名字。
3. 参数逐项说明：类型、默认值、单位/坐标域、合法范围、分支与生效时点；参数声明与实际读取分开。标出未使用、被硬编码覆盖、不同模式含义不同及越界/空输入行为。
4. 输出逐项说明：类型、数量/排序、坐标与单位、质量/成功标志、空结果和失败值；图像、区域、模型、句柄的复制/借用/缓存/最终释放另列。
5. 与VM同功能原版材料对齐后比较核心步骤、参数语义与结果合同。资源XML/公开声明只能证明声明；恢复项目实现不是原版算法证据。只有native入口时明确“内部算法待核”，不得据算子名或同名工具认定等价。
6. 写清双方已证事实/未知、差异的实际影响、保留/整改/借鉴重做/混合/暂缓的选择、收益和代价、涉及的具体方法/字段/处理顺序及验收；目标质量优先，迁移成本另列，不默认保留自研。
7. 用适合关系的流程图、输入参数输出矩阵和算法差异表辅助阅读；图/文字同源，链接用人能理解的主题名，编号仅辅助检索。现有入口和锚点保持。
8. 正确性先于性能。用同图、同ROI/坐标、同参数含义与同精度目标规划对照样本；空图/越界/多目标/退化几何/失败/取消须有判据。未实际运行就标planned-not-run；不凭native、语言或算子品牌判断性能优胜。
9. 证据记实际文件、类型/成员、行号、SHA与复核边界。外部材料发生漂移时保留原分析基线，单列待复核；不为补文档自动新逆向或改产品。原49能力、41整改、42证据分母不随本批新增分析项改变。

## 每工具交付与状态

- 固定内容：源码身份、算法流程、参数矩阵、输出/失败矩阵、VM证据与局限、关键差异、推荐及替代代价、具体改法、未运行验收、资源/并发与未闭合项。
- 覆盖状态分别记录：自研核心已静态复核、原版声明已核、原版算法体已核、语义对比充分、样本运行验证。允许前几项完成而后项待证，不凑成“完整等价”。
- 清点表由真实源码产生，工具逐个补充；非图像算法工具明确类型，不虚构图像算子。既有文档结论与本轮新增结论分别记录。
- 更新后只运行相应文档保真、证据定位/漂移、链接、手机与打印验证；未经要求不构建或启动产品/VM/设备。更新DOC_SYNC_STATUS，交付本批覆盖、真实新增、待核与未运行项。
