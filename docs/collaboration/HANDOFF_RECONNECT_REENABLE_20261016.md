# 自动重连重新开启和快速切换去重交接

- 任务目标：断开设备关闭再开启AutoReconnect后自动恢复重试；快速切换合并最新设置，不能重复启动重连或被旧事件覆盖。
- 允许修改目录：UI通讯应用服务、本地协作记录。
- 已修改文件：src/UI/Services/Communication/CommunicationApplicationService.cs、CURRENT_TASK.md及本交接。
- 已完成：
  - 保留已断开设备重新开启时恢复重连资格、等待旧取消任务完成后启动重试的逻辑，所有已接入协议共用，不依赖通讯窗口保持打开。
  - 属性事件在应用服务锁内按设备合并为一个ConnectionPolicyUpdate，重复事件仅递增Revision，不再每个事件创建独立策略任务。该任务循环消费最新设置，没有新的切换时退出。
  - 获取设备串行门后、等待旧取消任务结束后检查策略对象和版本、设备身份及方案生命周期。已过期开启事件不能解除手动停止标记或恢复旧连接；旧版本结束后由同一处理任务消费最新版本。
  - 实际重连仍使用按设备唯一的_reconnecting登记，取消中的任务保留到原生资源和所有者清理结束；重新开启先等待其Task，再创建新重试，不并行重复建连。
  - 关闭仍立即取消当前重连令牌，继续使用上批适配器身份及所有者隔离；已有健康连接不因关闭开关而强断，之后手动断开保持断开。
  - 手动停止/删除使已排队策略失效，列表断开仍按用户当前AutoReconnect规则决定后续重连；方案切换清空旧策略登记，旧处理任务只条件移除自己，不能删除新策略。
  - 不修改设备配置、绑定、SDK、输出契约或标定；读取真实设备，不回退缓存，不自动重放业务写入。
