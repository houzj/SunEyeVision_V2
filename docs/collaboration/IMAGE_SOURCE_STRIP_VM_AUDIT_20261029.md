## 已确认

- 2026-10-29 用户实机反馈添加文件/文件夹弹出本地远程菜单与VM本地模式不同。复核原 `VMControls.WPF/ImageListPanelBase.cs`（SHA-256 `DF02FAA325BABECCDAC3F44D3ED1D750B59874DA466BC0FDF033F997898D4B79`）第214、719–748、1021–1055行：`Islocal` 表示非远程模式，两个主按钮在本地模式直接打开本地文件或文件夹选择；原XAML虽然有本地/远程Popup，不能把它当成本地按钮默认行为。本方主仓公共 `ImageSourceStrip` 源码候选已将两个按钮直接发送既有文件/目录导入请求并删除菜单及旧空处理器；状态错误仍走 `Status`。添加真实按钮请求回归候选，尚未构建运行或人工验收。远程模式行为不在本轮实现范围，不把本地行为推广为VM全部模式。
- 主界面空列表额外提示“请添加本地图像”由 `MainWindowViewModel.ImagePreviewSourceMessage` 两处设置，错误信息也使用该出口。需与工作流主界面线统一移除空列表说明并保留真正异常信息；本条是待集成，不代表主界面已修复。
- VM 主结果窗使用 `VMControls.WPF/LocalImageListView.xaml:84` → `ImageListPanel.xaml:190`。原件为横向虚拟化列表、72×52 缩略图，以及随范围自动显示的 10px 横向滚动条。`ImageListPanelBase.cs:529–545,1403–1449` 包含当前图像定位与可视范围加载。
- 本方 `ImageSourceStrip.xaml:163–238` 已有同源滚动条模板与虚拟化，不能简单判断为没有迁入控件。其展开高度是 125px；`ResultWorkspaceShell.xaml:156` 对容器施加 `MaxHeight=110`，存在15px高度冲突，是滚动条被裁切的具体可疑原因。VM 原主窗同样有 110px 上限，但原件的宿主组合不同；必须检查本方实际布局，不能只凭静态代码认定根因。
- VM 点击图像与 Ctrl/Shift 运行勾选是不同操作，从头执行重置起点及滚动位置；文件拖入是导入，不是排序。本方会话承担选择、勾选及资源加载，自动切换由工作流实际运行驱动；不能把缩略条运行勾选与结果源下拉中的图像叠层勾选混为一谈。
- VM 找到的 `ScrollViewer_PreviewMouseWheel` 为空且未挂在当前原 XAML；未证明自定义滚轮横移或拖拽排序。鼠标滚轮、轨道及 Thumb 逐态需实际验证。
- 用户的 Blob 对比截图进一步确认：本方输入源下拉显示 `output.image` 等内部 ID；应由同一正式输出名称合同提供可读名称，ID 仍作稳定身份。VM 的 ROI 区域类型、绘制/继承与形状组合尚未全部进入正式 Blob；不能以现有“检测区域来源”字段冒称对标完成。
