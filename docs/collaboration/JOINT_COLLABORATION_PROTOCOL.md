# 当前协作协议：VM优先与完整链交付

本协议适用于控件库、Blob及工作流独立分支，遵循项目根目录 AGENTS.md 和 [取证约定](EVIDENCE_AGREEMENT.md)。旧四路专项分工是历史，不是当前审批或写入安排；原目标与证据保留，不以协议更新代替产品交付。

## 职责与写入

- 主仓本对话是唯一写者，负责 Blob 所需公共控件、独立样例及按 S1 UI → S2 完整控件链 → S3 算法对标完成 Blob 整链；工作流对话在用户授权的独立 worktree 中是唯一写者，负责工作流、主界面、图像源运行消费和宿主接纳等其已授权范围。
- 本对话内部多线并行按 AGENTS.md 中用户持续授权执行，写入线使用独立分支/Worktree、共享文件指定唯一负责人，不恢复转发审批链；不按每次小改无限新增工作区。同一工作目录同一时间一个AI写入，其他AI可只读审查。工作流对话保留独立工作区，双方互不覆盖。跨AI交接依 AGENTS.md 记录基线、实际文件、中文临时提交及交接单；不得假设对方已同步未提交内容。
- 独立工作不以另一线回复或整个目标完成为前置条件。共享API或文件由约定的负责线明确用途、真实调用链、受影响消费者和基线并先行实施；另一线保留自己的增量并继续无冲突工作，双方在集成前集中核对并同步。

## VM基准与实施批次

- VM完整生产行为是设计及验收第一基准。先复用已有原源码、XAML、图标、模板、资源与递归依赖证据，核入口、组装、状态、数据流、所有权及退出；证据足够即实施，仅对具体影响决策的缺口补证。
- 每条链明确“VM证据 → 本方已有位置及行为对应 → 差异 → 直接复用/调整消费者/替换核心 → 生产验收出口”。不因类名不同否定正确能力；宿主只做必要非视觉适配，不复制VM业务全局服务，也不为统一外观重写正确节点或流程业务。产品使用SunEyeVision职责命名；原身份保留在Catalog与证据。
- 以完整控件组合或功能链为批次，集中形成设计和验收矩阵、成片实施，再集中验证；实施中只做必要定位，测试不通过才针对具体失败补证修复。只迁Blob实际需要的原控件及依赖，不等待整库迁完。用户指定屏蔽区多形状和平台必要差异明确记录。
- 用户要求优先收口时，已有基础的功能贯通生产链；缺基础的功能提供不可误用、明确标识未实现的入口并记录依赖，不能计为完整目标完成。原清单、失败和未知项保留，不把小补丁或测试数量当交付。

## 图像源与输出共享合同

- **图像源执行合同由工作流线牵头并在其独立分支实现。** 范围包括图像取用接纳、游标和运行/调试的消费链，以及为该链必要的 `Plugin.Contracts` / `Plugin.Runtime` 接口变更；工作流线无需等待本对话逐项批准即可依据现有VM证据推进。其独立分支是该工作区唯一写者；本对话继续负责 `Plugin.Wpf` 视觉组合与 Blob，保留主仓已存在的未提交改动，不在主仓并行改写同一图像源合同。这里的分工只约定责任，不会自动同步对方文件。
- **独立开发与集成分开。** 双方可以在各自worktree形成完整候选；如果共享接口需要修改，在本线记录修改、基线及消费者，不因对方未回复而停止其他不依赖该接口的开发。接入共同正式Release之前，集中核对两边差异、未提交工作、合同版本、所有消费者与同源产物，再安排合并和唯一构建窗口；不得覆盖任一方源码。确实无法完成的共享调用链明确记为待集成，不扩展成整个对话停工。
- **配置接纳回执**与**冻结图像读取接纳回执**是不同事实：前者须区分正式配置已提交与旧视图投影是否仍有效；后者须标明具体冻结图像及是否被读取消费。Task正常返回、选择变化或整轮算法成功均不能代替上述事实。
- 负责线实施共享接口前，应自行核定输入输出、稳定字段、帧/会话/运行/接纳身份、资源所有权和寿命、失败与取消、保存重开及全部生产/调试消费者；不能先造接口再猜用途。另一线的具体影响和未决差异记录下来，双方在正式集成前共同核对，无须把对方即时回复设为独立实施的前置条件。工作流线负责图像源执行和宿主接纳链，控件线负责缩略条交互、请求与显示适配；正式输出展示声明、来源树与结果树合同在集成前联合核实。
- 每次共享变更记录基线、未提交增量、影响消费者和冲突；同步、合并、构建、独测和人工验收分别记录。保留工具页管理本地图像目标，实际入口以VM证据和用户需求核定。

## 新基线去旧与合并门槛（2026-11-02）

- 最终新架构与 UI 以 VM 已证语义为第一基准；旧架构、旧公共可视库、旧 SDK 可视入口、旧参数/结果模型及旧接口/文件格式的兼容桥、回退和双轨，不作为新基线长期设计保留。历史由 Git 保留，不因旧测试或旧项目仍消费而维持错误入口。
- 逐条沿完整生产链判断：已有正确的非视觉能力按行为直接复用；切换须同步真实宿主和全部消费者，再移除旧路径。不能仅因类名/目录名看似旧就删除正确能力，也不能把旧可视控件搬家改名视为迁移完成。
- 基础暂缺或 Group/循环按用户决定暂停时，列清未实现语义、当前影响、依赖、唯一负责人、受保护入口、后续替换/移除位置。保护入口须不可误用，不保留自动回退到旧实现的成功路径；占位不得记为功能实现。保留完整原任务范围。
- 自动合并成功仅证明文本合并，不证明架构或行为符合新基线。发生冲突时以具体 VM 证据、当前业务需求及真实平台边界裁决，不能机械任选一侧或用兼容层消除冲突。
- 独立开发不因上述未来门槛停工；实际集成时由主仓集中审核、串行构建及同源验证，不强迫另一线为日常检查停工。

## 集成与验收

- 正式自动及人工验收使用主仓 `Release/SunEyeVision_v1.0.0/SunEyeVision` 同源版本；按规定串行构建与相称回归。仅新变更、新失败或未解决风险才重复测试，不把旧PASS套到新产物。
