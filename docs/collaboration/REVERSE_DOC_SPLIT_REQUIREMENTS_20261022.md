## 交付目标

1. 拆成独立可维护HTML，采用index导航及主题清单；不能只把超大页的内容隐藏成页签，所有正文/JSON仍塞在一个HTML中。
2. 采用中文专用目录隔离相关文档，再按主题/公共资源/证据/历史归档分类，避免docs根目录后续其它HTML混入。自研用户指定自研目录名为“自研架构文档维护”；逆向侧使用符合自身职责的中文目录名，不必照搬“自研”。
3. 首页按界面入口组织：主界面、工具窗口、运行与结果；提供可点击的界面位置示意，让读者能定位菜单/Tab/工具栏/画布/参数/图像/结果/日志等区域，选中后显示原版入口、当前实现、数据/Owner链、差异/取舍与证据链接。文件目录和进度作为辅助入口。
4. 同时覆盖既有页面的表达升级。不能拆后变成文字堆积，也不能仅添加装饰图或统一复制一张泛化架构图。

## 图与关系类型

| 要表达的关系 | 适配表现 | 必须标注 |
|---|---|---|
| 界面位置与文档 | 可点击热点示意、当前位置面包屑 | 导航示意非产品运行截图；原版/当前实现分别标识 |
| 执行和调用 | 时序/泳道/分支流程 | 入口、线程/边界、条件、执行副作用、失败/取消 |
| 状态变化 | 状态转换图 | 触发条件、真实终态、超时/隔离、未闭合边 |
| 数据流 | 分层流向图 | 定义/快照/当次输入/结果、字段身份、类型/形状/坐标域、复制借用 |
| 工程依赖 | 分层有向依赖图 | 引用方向、程序集/语言/原生边界；当前/拟议依赖分开 |
| 生命周期 | Owner树、持有关系、时间线 | 创建者、借用/复制/共享、最后读者、替换/归还/最终释放 |
| 双方差异 | 并列矩阵与相同入口对齐 | 原版事实、独立实现、已验证与未知、优缺点代价 |
| 证据与进度 | 证据链图与分口径统计 | 材料送达、原版核实、实现采用、运行验证分别计数 |

每图需标题、图例、事实级别、来源成员/文件SHA入口和正文解释；未知/条件边用虚线并标明条件。不能把未证明的关系画成确定事实，不能把原版静态池、copy/borrow、映射、Release finally、渲染仓位统一画成lease或native最终Owner。图和文字须同源生成并校验；SVG应可读可缩放，手机可横滑/放大，打印不能裁断或丢失图例。
