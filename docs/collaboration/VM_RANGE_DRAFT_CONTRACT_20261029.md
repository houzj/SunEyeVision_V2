# VM 范围编辑与正式草稿待落实合同

状态：源码候选和只读审查；未完成实现，未构建，未运行。VM 原范围左右订阅独立的依据见 `VM_RANGE_SUBSCRIPTION_HANDOFF_20261029.md`。

## 待证的交互反例和独立编辑问题

Blob 面积范围已接纳 `[100, 200]`，上限切到订阅但尚未选来源时，下限输入 `300` 的原厂最终行为**尚未实机确认**。原控件滑条、失焦与参数模型检查都保留跨端数值约束，且未按另一端订阅状态跳过；订阅后何时回读数值仍待核。因此不能把“300必须接纳”当作已证VM合同或验收通过条件。单端模式切换不应等待另一端选源、未完成编辑不可污染正式节点和最终捕获仍须检查，仍分别适用；不能用假引用、伪默认值、另一套参数权威模型或放弃最终语义校验绕过问题。

现有 `ToolSettingsEditSession` 对每次变动完整物化；`RuntimeNodeConfigurationControl.ValidateSettingsCandidate` 又对完整候选构造配置并校验。与此同时 `Changed` 直接调用整页 `TryCapture`，会处理另一端未提交原文；`HasPendingEdits` 仅检查错误，遗漏合法但尚未提交的原文。`DeclaredSettingsView` 当前明确将逐字段 `ValidateProposal` 置空，因此 settings 引用准入实际依赖宿主候选校验，不能直接删掉该校验。

## 待实施的职责划分

1. 保持 `FieldSettingsDraft` 的唯一私有字段表。增量接纳检查字段身份、类型、编辑模式、Required 和字段声明域；完整捕获另对同一快照执行可执行的整体语义校验。含引用的候选必须在运行时解析后继续检查其实际范围和业务约束。
2. 单次引用变更需单独按真实声明检查节点/作用域/输出/成员/索引/转换，不让未变化的失效引用或另一端待选状态妨碍本次修复。只读审查发现 `WorkflowBindingContext.ValidateTyped` 可复用字段编译检查，但其 scope 的 predecessors 为空，不能把它当完整依赖图校验；需在宿主保持文档、节点与草稿身份，并在最终提交保留全图校验。具体公开边界和锁/重入仍须先核源代码后实施。
3. 状态通知不主动 flush 全部控件。宿主读取已接纳快照时不得提交 pending 文本；正式确认、保存和调试才显式进行完整捕获。状态变化但快照未变应零写入，捕获或重绑回调不能向新会话发布旧候选。
4. 待编辑状态须覆盖合法数字原文、引用原文、未选来源、组合未完成、尚未投影的私有草稿和捕获失败；隐藏/卸载后仍可恢复的原文不能丢。查询 pending 本身不得写入、提交或触发弹层。
5. 图像源相机选择当前直接编辑共享 draft，并经 `ImageSourceParameterEditor.OnSourceChanged` 重新绑定通知；不能只监听普通字段的 writer。重绑是否影响其他原文需要单独验证，不能因接口新增就声称相机链路正确。

## 验收反例

- 两端镜像：另一端合法或非法未提交文本、待选引用、已选择引用和无常量备份时，本端输入/步进/选择来源只改本端；另一端原文与接纳值保持。
- 上述 Blob 面积反例应与原厂同状态实测后冻结期望，不预设300接纳或拒绝；来源选定后核实际投影。两常量逆序、来源过期、错误作用域/成员/索引/转换及运行时解析后逆序均按正式合同拒绝。
- 合法未提交文本使 `HasPendingEdits` 为真；取消/关闭/重新绑定不污染正式配置。状态通知零提交；保存、执行时的显式捕获仍检查全部字段。
- 引用准入、验证、文本变化和投影回调期间重绑/释放/重入不发布旧值；接纳后观察者异常不假报回滚。
- 在正式同源 Release 上执行相关回归、相机选择回归、VS 设计器和真实程序验收。用户试用冻结期间不构建、不替换运行程序。
