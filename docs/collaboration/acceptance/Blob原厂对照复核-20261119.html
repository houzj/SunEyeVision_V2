一、原厂长什么样，我们长什么样

原厂是四层，最后一层 Blob 用不上

① 平台界面　参数页引擎、模板库、结果视图、ROI 选择器——所有工具共用
② 托管桥接 XxxCs.dll　参数、结果、ROI 写值。全库只有 8 个工具有这层，Blob 是其中之一
③ 原生算法 XxxModu.dll　C++ 写的算法，一个工具一个 dll
④ 专属界面 XxxControl.dll　只有复杂工具才建，全库 72 个——Blob 不在其中

我们用 src/Plugin.Wpf 对第 ① 层，用同一个程序集对 ②③ 层，第 ④ 层本来就不该有。这一条对上了。

发布单元：原厂 12 个文件，我们 5 个源文件 + 2 个 XML

原厂目录（安装路径实采）

  • IMVSBlobFindModu.dll 243 KB　算法
  • IMVSBlobFindModuCs.dll 36.5 KB　桥接
  • IMVSBlobFindModu.xml 15.5 KB　模块运行配置
  • ...Algorithm.xml 10.6 KB　参数名 + 默认值
  • ...AlgorithmTab.xml 121 KB　页签布局
  • ...Cs.xml 41.2 KB　其实是文档注释
  • ...Display.xml 10.4 KB　16 个显示对象
  • ToolItemInfo.xml 0.2 KB　4 项元数据
  • 3 个 PNG 图标

  • BlobTool.cs 228 行　工具壳
  • BlobParameters.cs 约 1500 行　参数 + 页面装配
  • BlobRoi.cs 约 1100 行　ROI
  • BlobResult.cs 937 行　结果
  • BlobAlgorithm.cs 1290 行　算法
  • Resources/BlobParameters.xml　参数 + 页签（按方案合并）
  • Resources/BlobDisplay.xml　只有表格列
  • 图标在 src/UI/Resources/Toolbox/

文件数不是问题。清单第 198 行写得很清楚：工程数量、文件数量、类名属于实现细节，只要职责对得上就不算偏差。

二、四个真正的差距

差距 1：少了一个配置区（Tab_Image Display）

原厂的参数页 XML 里有四个分组：

原厂分组标记我们有吗
Tab_ROI AreaCanTriggerRun=TRUE有 基本参数 / ROI区域
Tab_Run ParamsCanTriggerRun=TRUE有 运行参数（我们拆成两组）
Tab_Check ResultSubscribeVisible=False有 结果显示（我们拆成两组）
Tab_Image Display无没有

差的是结果页里那块「图像怎么显示」的配置区。原厂把它当参数页的一个分组，我们没这个分组。

证据：docs/evidence/original-release-units/BlobAnalysis/IMVSBlobFindModuAlgorithmTab.xml

差距 2：Display.xml 被我们拿错用途了（最要紧）

原厂 Display.xml 装的是「显示什么」

  • 16 个显示对象：输入图、Blob 图、二值图、轮廓点、文本、结果列表…
  • 每个对象带颜色、线宽、透明度
  • 每个对象带 Mapping：映射到哪个参数或结果

我们的 BlobDisplay.xml 装的是「表格几列」

  • 一个 Table，10 个 Column
  • 序号、面积、周长、质心 X/Y、角度、长轴、短轴、圆形度、矩形度
  • 没有任何图形显示声明
结果就是：图形显示（哪 7 个组、什么顺序、什么角色）写死在代码 BlobDisplayUi 里，没走声明。原厂这块是声明驱动的。

差距 3：16 个显示对象，我们缺 7 个

输入图像平台视口承担 Blob 图像缺 二值图像缺 Blob 轮廓有 最大内接矩形有 ROI 区域有 轮廓点只有显隐开关 定位点（参考）有 定位点（运行）有 显示文本有 数据记录 1缺 数据记录 2缺 结果列表才当表格列 外部 ROI缺 输出掩膜缺 扇环有

证据：IMVSBlobFindModuDisplay.xml 的 16 个 <Object Name="...">

差距 4：ROI 那块，业务和编排混在一个类里

原厂分得很开

  • BlobFindRoiManager.cs 90 行　只给字段名
  • ROISelecter 2824 行　画、选、改都在平台

我们混在一起

  • BlobLocalRoiOwner 约 570 行
  • 既管编辑器、帧、会话，又直接算 ROI 模式、形状、屏蔽区
  • 内部还有 38 处直接调用 Blob 数据结构

本轮已经把「读文档、写文档、投影、形状转换」收进接口 INativeRoiEditDocument，但整体搬迁会把 Blob 业务带进平台，所以停在契约层。

三、已经对齐的六项

项怎么证明
四层结构，Blob 不该有专属界面原厂 72 个 Control 目录里没有 Blob
三个页签名称与顺序基本参数 / 运行参数 / 结果显示，与原厂三个 Tab 一致
四个分组对了三个见差距 1 的表格
ROI 的画、选、改在平台NativeRoiEditor + NativeRoiSession
参数类型由 C# 属性决定双方都靠属性反射取类型，XML 只给默认值
工具箱元数据与三个图标原厂只声明 4 项；三个 PNG 与本方图标体积一一对应

四、清单里写错的一个名字

清单说 IMVSBlobFindModuCs.xml 是「参数名 ↔ C# 属性映射文件」。打开一看：

<doc><assembly><name>IMVSBlobFindModuCs</name></assembly>
<members><member name="P:IMVSBlobFindModuCs.BlobFindParam.ThresholdType">

这是 C# 编译出来的代码注释文件，跟本方程序集旁边的 .xml 是一回事。它不承载任何配置，我们不需要造一个对应文件。
