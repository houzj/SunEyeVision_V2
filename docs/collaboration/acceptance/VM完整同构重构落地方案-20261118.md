# VM 完整同构重构落地方案

日期：2026-11-18  
基线：VisionMaster 4.4.0 Build20250516  
范围：当前产品登记的全部 18 个工具、公共窗口、参数页、共享控件、结果视图和生命周期

## 1. 目标和验收定义

目标是让自研工具从框架到工具 UI 组装链与 VM 原厂保持同构。这里的同构指职责边界、数据节点、参数页拓扑、模板资源、控件状态、命令入口、生命周期和结果组合方式与原厂证据一致。算法语言、宿主进程和无法复用的底层运行时差异单独记录，不用 UI 等价物掩盖。

每个工具必须达到以下三种状态之一。

| 状态 | 判定条件 |
|---|---|
| `NativeAligned` | 原厂来源已登记，代码边界已映射，静态对照通过，自动测试通过，Release 构建通过，Agent Desktop 人工实测通过 |
| `LegacyCompatibility` | 当前入口可用，但仍有旧参数链、旧控件或未完成原厂生命周期迁移，缺口有明确记录 |
| `EvidenceBlocked` | 缺少同版本原厂源码、配置、资源或运行证据，禁止自行补行为 |

当前 18 个工具中没有工具可以直接标记为 `NativeAligned`。工具状态矩阵以 `docs/evidence/tool-migration-matrix-20261118.json` 为准。

## 2. 强制证据规则

VM 原厂是已经经过完整测试的标准答案。任何代码修改必须先形成原厂与自研逐层差异记录。

### 2.1 证据优先级

1. 同版本反编译源码和 XAML
2. 同版本工具 XML、资源字典、程序集和配置
3. 原厂运行窗口、交互过程和结果截图
4. 原厂运行日志、动态探针和行为回执
5. 自研代码、测试和运行日志只能证明自研现状，不能替代原厂证据

### 2.2 每项修改必须记录

- 原厂证据文件、程序集、MVID 或 hash
- 原厂对象、方法、资源键或模板名
- 自研对应文件、类型、方法和资源
- 差异所在层级
- 修改前行为
- 修改后行为
- 自动验证命令和结果
- 人工实测步骤和截图
- 尚未确认的动态行为

没有证据的内容标记为 `EvidenceBlocked`。不以经验补全颜色、尺寸、状态转换、命令可见性、控件所有权和销毁顺序。

## 3. 原厂基线结构

### 3.1 普通工具链

普通模块的原厂链路已由 `FRAMEWORK-RECONSTRUCTION.md` 和反编译程序集确认。

```text
ModuleParam
  → AlgorithmTabRoot
  → ParamsConfigControlBase
  → ParamsTabUserControl
  → ParamListView
  → ParamUserControl / NameValueItem
  → UserTempConverter
  → DataTemplate
```

`AlgorithmTabRoot` 负责页签、分组、外部参数、选中页、订阅、ROI 桥接、窗口状态和底栏命令。`NameValueItem` 是数据节点，不是 WPF 控件。展示模板根据节点类型、状态和资源字典生成视觉元素。

### 3.2 复杂工具链

特征匹配类工具不能全部视为同一种工具。

```text
NativeToolWindowRoot
  → Tool-specific parameter root
  → Native parameter list
  → FeatureMatchCommonControl（有证据的工具才接入）
  → Tool-specific template dialog
  → Bottom command / help / close lifecycle
```

已确认的公共程序集和职责如下。

- `FeatureMatchCommonControl` 负责模型列表、创建、编辑、删除、排序、预览和公共资源
- `IMVSHPFeatureMatchModuControl` 负责特征匹配参数根、通用模板对话框和底栏命令
- `IMVSContourMatchModuControl` 负责金字塔特征匹配专用参数根和模板窗口
- `IMVSGrayMatchModuControl` 复用公共模型面板，但拥有独立参数和对话框
- `IMVSMarkFindModuControl` 使用独立面板，不能在没有证据时强行接入 FeatureMatch 公共面板

证据见 `docs/evidence/original-ui-architecture-audit-20261118.json`。

### 3.3 Blob 链路

原厂 `BlobFindRoiManager` 持有统一 `RoiManager`。ROI 类型、输入字段和几何值写回属于同一输入管理事务。

```text
AlgorithmTabRoot
  → input declarations
  → ROISelecter / NameValueItem data nodes
  → DataTemplate
  → RoiManager.InputItem(...).SetInputValue(...)
  → algorithm module
```

当前自研 `BlobUiComposition`、`BlobRoiUi`、`BlobLocalRoiOwner` 和 `NativeRoiUiDraftControls` 将数据、视觉和写回拆成多个接缝。这是 Blob 当前差异的主要结构来源。

证据见 `docs/07-工具逆向/decompiled/Managed/BlobFind/IMVSBlobFindModuCs/BlobFindRoiManager.cs` 和 `docs/evidence/blob-input-assembly-difference-analysis-20261118.md`。

## 4. 现有自研与原厂的全链路差异

| 层 | 原厂 | 自研当前状态 | 重构目标 |
|---|---|---|---|
| 工具登记 | 模块程序集、XML、资源和 `ToolItemInfo` | Runtime/WPF 双工程和组件登记 | 保留工程隔离，但登记原厂根、资源和证据映射 |
| 窗口根 | `AlgorithmTabRoot`、原厂 BaseWindow、底栏命令 | `RuntimeToolEditorWindow`、`NativeToolEditorFrame` | `NativeToolWindowRoot` 统一 Owner、命令、帮助、排空和释放 |
| 参数存储 | 参数值由引擎句柄、模块 ID、参数名唯一寻址 | draft、settings 对象、输入回调多处持有 | 平台 `ParameterStore` 统一读写，工具保留只读领域门面 |
| 参数定义 | 原厂参数定义 XML + 手写参数门面 | 每个工具自定义 XML 解析和领域设置对象 | 平台声明加载器统一解析，保留原厂定义与布局职责映射 |
| 页面布局 | `AlgorithmTabRoot` 直接建立页签、组和节点 | `DeclaredSettingsView` 组装 settings 页，再注入输入组合 | 单一参数根直接消费 settings 和 input declarations |
| 基础字段 | `NameValueItem` + DataTemplate | `DeclaredFieldRow` + `ParameterFieldHost` | 行只承载数据节点和状态，视觉完全由模板和资源生成 |
| 输入字段 | 与设置字段在同一参数列表 | `DeclaredInputFieldsView` 创建后迁移到外层 | `INativeInputComposition` 输出正式行，不保留嵌套参数列表 |
| ROI | 数据节点、统一 ROI manager、模板渲染 | StackPanel 装载外部字段控件 | `RoiGroupModel` + DataTemplate + 统一写回会话 |
| 引用会话 | 原厂参数节点状态和订阅命令由模板驱动 | `ParameterFieldHost` 延迟挂接，当前有 `_referenceSession=null` 缺口 | 引用会话与模板 Loaded/Layout/Unload 同代次管理 |
| 结果视图 | 平台 `ModuleResultView` 按数据类型组合图像、图表、表格 | 每个工具独立结果包装 | 平台统一结果区域，工具只交显示声明和结果 reader |
| 控件资源 | VM.PcUI、Apps.XmlUI、原厂 DataTemplate 和资源字典 | Native 资源迁移目录和自研注册入口并存 | 建立唯一 `NativeResourceRegistry` 和来源映射 |
| 控件命名 | 原厂名称包含来源语义，如 `HikHistogramSingle` | 共享层直接暴露原厂专名 | 原厂适配层保留原名，共享抽象层使用中性名 |
| 底栏命令 | 工具根和专用 BottomCommand 协作 | 宿主窗口和工具回调组合 | 声明式命令、禁用条件、进度和关闭结果统一 |
| 关闭释放 | 原厂窗口、模块会话、ROI、模型数据统一释放 | 多对象分别退订和释放 | `ToolWindowSession` 统一 generation、取消、排空、释放 |

## 5. 公共控件重构方案

### 5.1 控件分类

当前 `src/Plugin.Wpf/Controls/Native` 目录约有 603 个包含 class 声明的 C# 文件和 70 个 XAML 文件。这个数字包含模型、转换器、接口、资源适配器和 pending 文件，不能直接当成已完成共享控件数量。

平台层按以下分类建立清单。

1. 参数根控件
2. 字段行和字段模板
3. 数值、范围、枚举、文本和引用控件
4. 图像来源和输入引用控件
5. ROI 数据节点、ROI 模板和图像交互控件
6. 结果图像、直方图、表格和输出树控件
7. Tab、滚动、底栏、帮助、进度和关闭控件
8. 特征模型列表和模板对话框控件
9. 画布节点、端口和连线控件

### 5.2 命名边界

原厂专名只允许出现在适配层和证据映射中。共享抽象层使用中性命名。

```text
NativeHistogramSingle
  └─ adapter source: HikHistogramSingle

NativeRoiGroupModel
  └─ original source: ROISelecter / RoiManager
```

`ColorExtract` 可以继续使用 `HikHistogramSingle` 作为原厂适配实现，但公共参数页不应直接依赖供应商专名。

### 5.3 基础字段模板

每个模板必须登记以下内容。

- 原厂 XAML 或资源键
- 自研资源键
- DataContext 属性映射
- 常量/引用/未设置状态
- 输入提交命令
- 错误显示和禁用状态
- Loaded、Unloaded、Visibility 和关闭释放行为
- 自动测试和人工截图

## 6. 参数和输入重构方案

### 6.1 ParameterStore

建立平台级参数存储接口，按节点和参数名提供唯一寻址。

```text
ParameterStore
  Get(nodeId, fieldId)
  Set(nodeId, fieldId, proposal)
  Validate(nodeId, snapshot)
  Snapshot(nodeId)
  Import(nodeId, persistedFields)
  Export(nodeId)
```

现有 draft 先通过适配器接入，完成以下验证后再删除工具级重复存储。

- 常量、引用、变量和未设置往返
- 范围、枚举和类型校验
- 保存重开
- 执行快照只读
- 旧方案载入
- 失败提交不污染已接受值

### 6.2 单一参数根

重构 `DeclaredSettingsView` 和 `DeclaredFieldsView`，使 settings、input、ROI 和专用槽进入同一页拓扑。

- page、section、order 直接来自原厂声明
- 输入工厂只生成数据节点，不创建第二个参数列表
- `PageBuilt` 只提供通知和探针
- 捕获、校验、提交和释放只有一个入口
- 不再使用控件实例搬运作为最终组装策略

### 6.3 ROI 数据节点化

新建 `RoiGroupModel`，只包含模式、来源、几何字段和写回身份，不继承任何 WPF `UIElement`。

```text
RoiGroupModel
  → DataTemplate
  → DeclaredFieldRow / NativeRoiEditor
  → RoiSession
  → ParameterStore / RoiManager adapter
```

验收必须确认 ROI 代码不再通过 `Children.Add(外部字段控件)` 组装。

## 7. 结果视图重构方案

CodeBuddy 报告确认原厂 `ModuleResultView` 同时包含结果表格、直方图、数据表格和图像列表。当前已有部分反编译证据，但 `ModuleResultView` 的完整 XAML 布局、`GetDisplayList()` 返回结构和结果接口边界仍需补证。

在补齐这些证据前，结果视图只能标记为 `EvidenceBlocked` 或 `LegacyCompatibility`。

证据闭合后实现：

- 图像区
- 直方图区
- 统计表区
- 输出树
- 结果选择和图像叠加
- 结果类型到区域的分发
- 结果窗口关闭和资源释放

工具只提供 `ResultDisplay` 声明、数据类型、结果 reader 和工具专用渲染回调。

- 图像来源类

## 9. 代码级一一对照审核

每个工具建立代码对照表，至少包含以下列。

| 原厂项目 | 自研项目 | 对照内容 |
|---|---|---|
| 程序集和类 | 项目、类型和方法 | 身份和职责 |
| XAML 根 | 窗口和 UserControl | 参数根和布局 |
| 参数对象 | schema、store、draft | 字段所有权和读写 |
| `NameValueItem` | 字段状态和数据节点 | 状态和命令 |
| DataTemplate | 模板注册和资源 | 视觉和交互 |
| ROI manager | ROI model/session | 模式、写回和释放 |
| BottomCommand | 命令 presenter | 可见性、禁用和关闭 |
| result view | result projection | 图像、图表、表格和输出树 |
| close/dispose | session disposal | 退订、排空和迟到回调 |

审核规则如下。

- 原厂有而自研没有，必须登记缺口
- 自研有而原厂没有，必须说明平台差异或删除理由
- 原厂行为未取证，必须标记 `EvidenceBlocked`
- 不能以测试通过替代原厂对照
- 不能以截图相似替代所有权和生命周期对照

## 12. 失败处理

- 构建失败先区分代码错误、资产缓存 I/O 和目录权限
- 运行失败先看窗口组装探针，再看绑定、执行和释放阶段
- 截图差异先定位到资源、模板、参数根还是工具专用面板
- 原厂证据不完整时暂停该行为，继续完成不依赖它的静态映射
- 不通过临时占位、默认值或自研视觉替代来消除失败

## 13. 最终完成标准

只有以下条件全部满足，才可以称为完整同构迁移完成：

- 18 个工具都有明确状态
- 公共窗口、参数根、模板、资源、ROI、结果和生命周期合同已统一
- 每个工具的原厂和自研代码映射可逐项复核
- 自动测试覆盖完整生产链
- Release 构建通过
- Agent Desktop 原厂/自研人工对照通过
- 旧视觉链已在对应消费者迁移后删除
- 未确认行为仍被明确标记，没有猜测性实现

3. 两个工具的完整生产链自动测试通过
4. Release 构建通过
5. Agent Desktop 原厂/自研人工对照通过
6. 关闭释放和迟到回调探针通过
