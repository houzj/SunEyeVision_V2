动态参数子项合同设计

让工具的参数集合随保存状态变化：父项持有子项、增删命令、逐项持久化和可订阅端点。首个消费者是 PixelCount 阈值范围，后续 If 动态行复用。

VisionMaster 4.4.0 对照PixelCount设计稿2026-11-20

1. 原厂机制（证据）

IMVSPixelCountModuVAControl.dll（ilspycmd 11.2，BAML 已还原）：

  • PixelModuRangeConfigList : NameValueItem, IDynamicChild：ConfigList、AddCommand、DeleteCommand、DelEnable = Count > 1、上限 32。
  • 新增写 add_Threshold，删除写 del_Threshold_{n}；条数存 Threshold_nums。
  • PixelModuRangeConfigItem : IntegerBettween：两个 Integer 子项 min_Threshold_i / max_Threshold_i，默认 0/255/1。
  • Integer → ValueBase，含 IsSubA、TypeChangeCommand、SubData，端点可订阅。
  • 行视觉来自共享 IntegerBettween 模板；容器只提供标题、ItemsControl、增删按钮。

2. 目标合同

工具在已知当前设置快照时，可以给出额外的端口和呈现。宿主在“配置准入、参数页、执行快照”三处使用同一扩展结果。

public interface IToolDynamicSettings
{
    // declared: 工具静态设置契约；current: 当前字段快照
    ToolSchema ExpandSettings(ToolSchema declared, FieldSettings current);
    // 可选：扩展字段的引用行为与绑定名
    IReadOnlyDictionary<string, ParameterReferenceBehavior> DynamicReferenceBehaviors { get; }
}

端口身份

项规则
数量range.count，整数，默认 1，范围 1..32
端点range.{i}.min、range.{i}.max，i 从 0 连续
配对两个端点使用 PairWith 共用一行，行标题为序号
编辑模式Constant | Reference
持久化按字段 id 扁平保存；数量变化时裁掉越界端点

引用语义

  • 端点值与普通数值字段一致：接受引用会话，执行前由 ExecutionBindingPlan 编译。
  • 未解析引用按现有执行校验失败处理，不落回默认值。
  • 端点范围校验（0..255、下限 ≤ 上限）在编辑期和运行期各执行一次。

3. 宿主改造点

层改动
Plugin.Contracts新增 IToolDynamicSettings

4. PixelCount 映射

  • 设置模型：RangeCount + 端点数组（值或引用），不再使用 ThresholdRanges 字符串。
  • 页面：运行参数 页显示一个「阈值范围」组，行序号 0..n-1，底部 +/×。
  • 新增：数量 +1，端点默认 0/255；删除：数量 -1 并从末尾裁掉端点；DelEnable = Count > 1。
  • 执行：按数量读取端点，引用在运行期解析。

5. If 复用

If 的动态行是“名称 + 来源引用 + 范围 + 状态 + 模块”，同样需要动态数量和逐行端口。它能复用本合同的数量和扩展端口部分，行模板与命令由 If 自己声明，不复制 PixelCount 的容器。

6. 验收矩阵

项标准
端点订阅链接按钮可选择变量，保存重开后引用保留
增删上限 32，1 行时无删除，删除只作用于末行
执行常量与引用两种输入都产生正确阈值区间；未解析引用阻止执行
UI行外观、标题、命令条与原厂一致；参数页无多余页头
回归PixelCount 专项测试、ControlNamingProbe、Release 构建、Agent Desktop

7. 非目标

  • 不做旧字符串格式兼容。
  • 不把动态端口暴露为执行输出或全局变量。
  • 不做任意深度的嵌套动态结构；只支持一层子项集合。

风险：配置准入与参数页需要感知“结构变化”，当前节点配置是不可变快照。实现时必须明确重建时机，避免编辑中把正在使用的旧引用裁掉。
