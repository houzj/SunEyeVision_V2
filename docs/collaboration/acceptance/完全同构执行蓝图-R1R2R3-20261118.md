## R1. ParameterStore —— 平台参数引擎（对应原厂原生参数表）

### 目标
参数值只有一份，住在平台 Store；代码与界面都是"按名字访问的句柄"。对齐原厂 `ParamItem.Value`（`IMVS_Get/SetParamValue`，C# 零副本）。

### 新增文件
1. `src/Plugin.Contracts/Parameters/IParameterStore.cs`

```csharp
public interface IParameterStore
{
    T Get<T>(Guid nodeId, string name);
    void Set<T>(Guid nodeId, string name, T value);          // 内部做范围校验，越界抛异常
    IReadOnlyParameterView Snapshot(Guid nodeId);            // 只读视图（算法执行用）
    string Export(Guid nodeId);                              // 序列化（方案 JSON 片段）
    void Import(Guid nodeId, string json);
    event Action<Guid, string>? Changed;                     // (nodeId, paramName)
}
```

2. `src/Plugin.Infrastructure/Parameters/ParameterStore.cs` — 实现：`Dictionary<(Guid,string), object>` + 类型转换 + 范围校验（范围来自声明 Schema）。

### 改造文件
| 文件 | 改动 |
|---|---|
| `DocumentSession.Persistence.cs` | 参数读写改走 Store（JSON 格式不变） |
| `BlobSettings.cs` | 降级为 `IReadOnlyParameterView` 的强类型门面（不再持有值） |
| `BlobSession.cs` / `BlobAlgorithm.cs` | 接收 `Snapshot`，不接收 Settings 对象 |
| `DeclaredFieldRow` / `FieldRowModel` | 写值转发 Store；读值从 Store |

### 验收
- 方案 JSON 与当前格式**逐字节兼容**（旧方案可开）
- 界面改值 → 代码 `store.Get` 立即一致（结构保证，非代码保证）
- 越界写抛异常（对齐原厂 `VmException(-536870130)`）

## R2. FieldRowNode —— 参数行数据节点（对应原厂 NameValueItem）

### 目标
行 = 数据节点（唯一、常驻、轻）+ 模板生成的 UI（可丢弃）。**这是"打开慢、首次切页慢、双父级、防御代码"的总根源。**

### 新增文件
1. `src/Plugin.Wpf/Fields/FieldRowNode.cs` — 从 `DeclaredFieldRow` 构造函数抽出**全部数据职责**：
   字段 id、Port、状态（`DeclaredFieldState`）、条件（`_fieldConditions`）、可见性逻辑（`IsFieldActive`）、订阅关系、范围校验。
   实现 `INotifyPropertyChanged`。**纯数据，不继承任何 UIElement**。
2. `src/Plugin.Wpf/Fields/FieldRowNodeHost.cs` — 轻量呈现器（对应 `RoiFieldRowPresenter` 模式）：`Content = 从 Node 生成的行 UI`，模板调用，独占创建。

### 改造文件
| 文件 | 改动 |
|---|---|
| `DeclaredFieldRow.cs` | 构造函数只接收 `FieldRowNode`；UI 部分（`LeftRightControl`/模板选择/`ProjectTemplate`）保留但**不接线**（接线在 Node 上） |
| `DeclaredFieldsView.cs` | `_fields` 改存 `FieldRowNode`；`ComposeInputEditor` 创建 Node（Node 唯一 → 天然幂等，删除防重复抛异常） |
| `DeclaredInputFieldsView.cs` | `TakeField`/`AddAfterField` **删除**（ROI 走 RoiGroupView，不再流转行） |
| `BlobUiComposition.cs` | 删除 `SkipRoiComposition`；ROI 段保留（已同构） |
| `ParameterFieldHost.cs` | 会话条件改查 Node 状态 |

### 删除（防御代码，完成 R2 后全部不需要）
`EnsureAttachable` 的同页幂等判断、`_pendingPageActions` 重放机制、`QueueContent`、`_pendingContent`。

### 性能验收（对齐原厂"行本来就轻"）
- 打开参数窗 **< 800ms**（当前约 2-3s）
- 首次切页 **< 100ms**
- Node 构造 = 纯字段赋值（微秒级）；UI 生成 = 模板实例化（毫秒级）
