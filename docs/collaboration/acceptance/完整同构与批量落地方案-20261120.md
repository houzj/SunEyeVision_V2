# SunEyeVision 工具同构与批量落地方案

## 总体目标

建立一套与 VisionMaster 原厂参数页、控件模板、工具组装、结果显示和生命周期对应的平台架构。

当前先稳定两个基线工具。

- ImageSource
- BlobAnalysis

后续工具按相同架构逐个恢复和迁移。

算法库允许使用 HALCON 或 OpenCvSharp。工具的参数语义、页签、分组、端口、结果结构、交互逻辑和生命周期保持原厂对应。

## 一、证据优先规则

每个工具先建立原厂证据包。

证据优先级如下。

1. 原厂反编译程序集和调用链
2. 原厂参数 XML、结果 XML 和资源
3. 原厂运行窗口和交互截图
4. 原厂固定样本运行结果
5. 本方源码和现有测试

没有证据的行为记录为“运行未确认”，不自行设计替代逻辑。

每个工具必须生成差异清单，覆盖工程结构、程序集和资源、页签和分组、字段顺序、字段显隐条件、控件模板、ROI 和资源挂载、输入输出端口、结果显示、底栏命令、执行、取消、关闭和释放。

## 二、统一平台目标结构

```text
src/Plugin.Wpf/
├─ Controls/Native/Composition/ParameterPresentation/
│  ├─ ParamListView
│  ├─ ParamUserControl
│  ├─ ParamGroup
│  ├─ ParamItemTemplate
│  ├─ ParamItemStyle
│  └─ CollectionViewSource
├─ Presenters/
│  ├─ Parameters/
│  ├─ Regions/
│  ├─ Results/
│  └─ Commands/
├─ Adapters/
│  ├─ Fields/
│  ├─ References/
│  ├─ Resources/
│  └─ Devices/
└─ Themes/Native/
```

平台层负责 Tab 集合和页面生命周期、CollectionViewSource、分组和字段顺序、ParamItemStyle、ParamUserControl、公共字段模板、数值、枚举、布尔和引用控件、ROI 组装、AssistGroup、结果树、图像叠加、底栏命令、执行会话、关闭退订和资源释放。

工具层只负责工具入口、字段和端口声明、工具参数语义、ROI 和资源身份、结果声明、算法调用、工具专属资源和算法适配接缝。

## 三、ImageSource 复核范围

相机管理层与原厂存在设备范围差异，本轮先闭合本地图像链路。

```text
本地图像文件
  → ImageSource 参数页
  → 统一图像帧
  → 图像输出端口
  → 灰度图像输出端口
  → Blob 输入引用
  → 执行和结果显示
```

ImageSource 必须复核图像来源页签和分组、文件导入控件、图片列表、当前帧选择、图像和灰度图像输出、引用候选和引用回读、换图和删除、清空和重新打开、保存重开、下游 Blob 引用、关闭时的帧租约和事件退订。

相机发现、设备连接、触发、曝光和多相机专属参数放入独立设备管理层，标记为后续范围。

## 四、Blob 全链路目标

### 基本参数页

覆盖图像输入、ROI 区域、ROI 创建、屏蔽区创建、位置修正和 AssistGroup。

位置修正模式必须对应原厂。

| 模式 | 显示内容 |
|---|---|
| 按信息 | 修正信息 |
| 按点 | 基准点、基准角度、基准尺度X/Y、运行点、运行角度、运行尺度X/Y |
| 按坐标 | 基准点X/Y、基准角度、基准尺度X/Y、运行点X/Y、运行角度、运行尺度X/Y |

ROI 输入由 NativeRoiGroupComposer 统一创建，工具参数 XML 不再声明重复静态 ROI 行。

### 运行参数页

按原厂 AlgorithmTab.xml 复核阈值方式、极性、低阈值和高阈值、软阈值、查找个数、面积筛选、轮廓输出、Blob 图像输出、二值化图像输出、高级筛选、排序特征、排序方式、连通性和输出限制。

每个字段的默认值、范围、单位、引用能力和显隐条件必须与原厂一致。

### 结果显示页

按原厂 Display.xml 和 AlgorithmTab.xml 复核结果判定、Blob 数量判断、面积判断、总面积判断、质心判断、角度判断、中心点判断、Box 宽高判断、周长判断、长短轴判断、圆形度和矩形度判断、图像显示、Blob 框、ROI、轮廓、位置修正点、文本显示和结果树。

### 执行和释放

验证执行一次、连续执行、停止执行、参数确认、参数取消、切换页签、重复打开、换节点、关闭窗口、关闭主程序、ROI 绘制取消、资源租约释放、引用退订、迟到回调拒写和 DLL 文件再次覆盖。

## 五、工具恢复和批量迁移

工具按相似性分批加载。

第一批为 PixelCount、FrameMean、IntensityMeasure，复用数值、枚举、范围和结果表模板。

第二批为 ColorExtract、DivideImage，复用图像来源、ROI、范围和图像结果模板。

第三批为 ContourMatch、GrayMatch、MarkFind，复用模板资源、匹配参数、运行结果和图像叠加模板。

第四批为 BlobLabels、If，复用结果判定、条件输出和多状态显示模板。

每个工具执行固定流程。

1. 恢复原厂证据包。
2. 生成页签和字段映射。
3. 生成端口和结果映射。
4. 创建单项目工具结构。
5. 删除旧参数视觉链。
6. 接入统一平台。
7. 接入算法适配层。
8. 运行静态映射检查。
9. 执行 Release 构建。
10. 使用 Agent Desktop 验证。
11. 验证关闭和资源释放。
12. 更新迁移清单并闭口。

## 六、算法一致性方案

本方使用 HALCON 或 OpenCvSharp 实现算法。每个工具建立固定样本集，对比输出数量、区域和轮廓、面积、中心点、角度、宽高、筛选结果、状态判定、输出图像和结果树。

几何结果采用原厂允许的像素和角度容差。边界值、空结果、异常输入、ROI 继承、取消和重复执行单独测试。

- 未确认行为已记录

## 2026-11-20 原厂工具工程结构与本方目标结构纠偏

本轮直接核对 VisionMaster 4.4.0 安装目录中的 Blob、ContourMatch、FrameMean、PixelCount VA、ColorExtract、DivideImage 等发布目录。原厂共同发布单元为算法 DLL、Cs 桥接 DLL/XML、Algorithm.xml、AlgorithmTab.xml、Display.xml、ToolItemInfo.xml，部分工具额外带 Control.dll、Librarys.Config 和状态图片。该目录体现发布职责边界，不要求本方复制原厂程序集数量，也不允许创建伪造的 Algorithm.dll 或 Bridge.dll。

本方目标统一为每工具一个产品项目。项目内部按 Algorithms、Parameters、Results、Editor、Resources 划分职责。公共参数页、页签、字段模板、ROI、AssistGroup、结果树、图像叠加、底栏和窗口生命周期继续由已经验证的 Plugin.Wpf 链路负责。工具层只提供工具身份、参数、端口、结果声明、资源身份、算法会话和有证据的专属 Editor 接缝。HALCON/OpenCvSharp 通过独立适配层接入，算法调用可以组合多个库操作，但工具不管理第三方原生库生命周期。
