一、强制复核原则

  1. 先收集同版本原厂反编译源码、配置、模板和资源，再分析当前实现。
  2. 每个差异必须记录原厂路径、定位、证据等级、当前消费者和修复边界。
  3. 没有证据的动态行为标记为 unconfirmed，不得凭自研现状补齐。
  4. 自动测试证明本方实现稳定，不能替代原厂证据。
  5. 不新增第二套参数页、控件模板、结果视图或生命周期链。
  6. 测试失败先定位入口、模板、绑定、组装、执行或释放阶段，再决定是否改代码。
状态含义使用规则
verified有直接原厂证据，当前实现已复现允许进入实现和合并门禁
derived由多条直接证据推导必须记录推导链
inferred合理推断但缺少直接证据只能进入验证清单
unconfirmed证据不足禁止作为设计依据

可称为“框架同构”

同构目标修正

同构的目标不是“做出功能相同的另一套框架”
目标是保持原厂已经取证的职责边界、数据流、组装关系、资源所有权和生命周期。语言、程序集名称和算法实现语言可以因本方运行环境不同而变化，但不能因此改变原厂的架构职责。
原厂事实同构目标不能做的替代
原厂平台统一参数根和 DataTemplate本方由共享参数根和模板注册承接每个工具再写一套参数页
原厂 ROISelecter 是数据节点本方 ROI 必须是数据模型加模板用 StackPanel 搬运外部字段控件
原厂 FeatureMatchCommonControl 是共享面板ContourMatch、GrayMatch 按证据共用同一公共边界两个工具复制两套模板列表和 Dialog
原厂 MarkFind 使用独立 Control本方保持独立适配边界为了目录统一强行套 FeatureMatch
原厂 ModuleResultView 按数据类型组合显示本方结果容器必须支持组合显示用每工具一个表格包装器替代
原厂工具有专属 Control 时才保留专属 UI本方专属 WPF 只承接有证据的差异以“方便实现”为理由新增专属 UI

因此，当前目标结构应以原厂程序集和公共组件边界为准。工程数量、文件数量、类名和语言属于迁移实现细节，只有在不改变原厂职责的前提下才能调整。

发布单元级同构目标

纠正
原厂目录树是部署和消费边界。此前的 Runtime + Wpf 源码树不能直接称为原厂同构。源码可以因语言和宿主不同而拆分，但最终必须生成与原厂职责等价的模块发布单元、独立声明文件和资源入口。
原厂发布事实本方必须对应的目标允许的差异
IMVSBlobFindModu.dllBlob 算法运行单元和独立算法资源本方算法语言可不同，但不能把算法职责塞入 WPF
IMVSBlobFindModuCs.dllBlob 参数、结果、ROI 和 SDK/宿主桥接单元程序集名称和宿主接口可不同
IMVSBlobFindModu.xml工具身份、依赖和模块元数据文件文件名可不同，但发布包中必须有等价声明
IMVSBlobFindModuAlgorithm.xml参数定义文件不能只由 C# 默认值替代
IMVSBlobFindModuAlgorithmTab.xml页签、分组、控件类型和顺序文件不能未经证据合并进参数文件
IMVSBlobFindModuCs.xml参数名、桥接属性和类型映射文件映射格式可不同，职责不能消失
IMVSBlobFindModuDisplay.xml结果显示和数据类型声明不能用工具级结果表包装器替代完整声明
ToolItemInfo.xml工具箱、节点形状、图标、分类和端口元数据宿主存储格式可不同，消费边界必须保留

算法与适配层边界

类型适配层只负责图像、区域和结果类型转换、第三方资源所有权、初始化、释放和异常边界。算法实现层可以直接使用 HALCON 或 OpenCvSharp 的处理方法，但必须作为独立算法实现边界存在。

工具入口 → 工具专属算法实现层 → 类型与资源适配层 → 第三方算法库

工具入口工程不能直接管理第三方库、原生 DLL、初始化和资源释放。算法实现层也不能承担工具参数页、窗口生命周期或工作流调度。

算法实现差异规则

原厂工具使用海康自研算法库，本方工具可以使用 HALCON 或 OpenCvSharp 完成同等算法应用。该差异只属于底层算法实现和第三方库依赖差异。HALCON 和 OpenCvSharp 必须通过独立适配层接入，工具不能直接管理第三方库、原生 DLL、初始化和资源释放。

工具入口、参数语义、页签分组、端口、输入输出、结果结构、资源所有权、窗口组装和生命周期仍必须按同版本原厂证据逐项对应。没有原厂证据的行为标记为未确认，不自行设计替代。
