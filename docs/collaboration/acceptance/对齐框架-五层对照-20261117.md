# 与原厂「完整对齐」的五层框架（2026-11-17）

> 背景：用户明确要求对齐范围不止 UI，而是**架构设计 / UI 组装 / 交互 / 算法实现**的完整对齐。
> 本文定义五层对齐口径、每层的取证方法、当前进度与阻塞项。

## 1 五层对齐定义

| 层 | 对齐内容 | 判定依据 | 取证手段 |
|---|---|---|---|
| **L1 架构与契约** | 工具 schema 组织方式、字段角色模型、端口/引用规则、显示声明模型、方案 schema 与兼容策略 | 与原厂模块的 XML/托管定义结构等价；存量方案可加载、可演进 | 反编译 + `*AlgorithmTab.xml` + 方案文件结构比对 |
| **L2 UI 组装** | 参数页页签/分组/行、控件类型、默认值、显隐联动；结果显示行与顺序 | 逐字段逐行等价（命名、顺序、默认值、控件） | 双端截图 + a11y + 原厂 XML `DefaultValue/MinValue/MaxValue` |
| **L3 交互** | 双击打开/关闭、切换页签、值提交时机、引用选择、ROI 绘制、撤销重做、连续执行 | 操作路径和结果一致，无异常、无残留状态 | agent-desktop 脚本化操作 + 日志断言 |
| **L4 算法实现** | 同输入同参数下输出数值、极值/边界行为、错误诊断 | 整数/计数必须相等；浮点几何 ≤0.5px、≤0.5°；分数 ≤0.01 | 同图双方执行对照（原厂 `Execute` vs 我方 Runtime Session） |
| **L5 结果呈现** | 结果列集合与顺序、判定三态、显示项、文本/图形样式绑定 | 列/项集合与顺序一致，样式角色绑定一致 | 结果页截图 + 结果 schema 对照 |

## 3 阻塞项：字段级对齐会被「未知字段」拦死（L1 架构缺口）

**现象**：按「对齐原厂」把 Blob 结果页多出的「质心」显示行移除（同时移除 `presentation.graphics.centroids.*` 声明 + `display.centroids` 常量），构建通过、单测 109 项全通过，但**存量方案打不开**：

```
方案打开未接纳：Unknown Runtime field: display.centroids.ng
(tool=BlobAnalysis; known fields=input.image,input.pose,input.roi.local,...)
```

**原因**：方案文件里保存了该工具的显示设置字段；字段声明一旦移除，加载器把存量方案中的同名设置判为「未知字段」并**整份拒绝**。

**结论**：这是架构层问题，不是 Blob 一个工具的问题。**任何字段增删（改名/合并/移除）在现有实现下都会砸掉存量方案**。要做「完整对齐」，必须先补兼容机制，否则只能永远保留历史字段。

**已采取动作**：本轮改动已回滚，Blob 恢复原状（Build 0 错误、方案可正常加载）。

**建议的兼容机制（三选一，建议 A）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A 未知字段容忍 + 丢弃告警** | 加载时未知字段不拒绝方案，记 `WARN` 并丢弃；保存时不再写回 | 中；需在加载器加白名单/容错开关，风险可控 |
| B 字段别名/迁移表 | 维护 `old-id → new-id` 映射，加载时迁移 | 中高；长期最干净，但要建迁移框架 |
| C 版本化 schema + 升级器 | 方案 schemaVersion 驱动升级 | 高；最正规，工程量最大 |

## 4 每层的执行顺序（建议）

1. **L1 兼容机制**（方案 A）——不解锁它，后续所有字段级对齐都会砸存量方案
2. **L2 剩余 10 个工具**逐字段对照（已有成熟流程：双端截图 + `press pagedown` 滚动）
3. **L3 交互**：双击/关闭/切页签/连续执行 → 12 工具一次跑完（DEF-001 已修，不再丢会话）
4. **L5 结果呈现**：列集合与顺序、显示项对比
5. **L4 算法**：合成图 + 原厂同图执行，按容差判定（最耗时，放最后）

## 5 判定口径（沿用用户裁定）

- 显示名不一致 → **按原厂改名**
- 结果显示项顺序/集合不一致 → **对齐原厂**
- 参数页主题 → 保留浅色（已裁定，非缺陷）
