# 工具 UI 全量架构重构：目标驱动落地方案

日期：2026-11-18  
目标范围：当前仓库已登记、可加载或已实现的全部工具  
执行原则：原厂证据先行，公共架构先行，工具代码批量迁移，验证证据闭环

## 总目标

建立一套可以承载所有当前工具的原厂化 UI 装配架构，并完成工具代码级迁移。最终每个工具都必须进入明确状态，`NativeAligned`、`LegacyCompatibility` 或 `EvidenceBlocked`。不允许出现未知工具、未登记工具或没有差异记录的工具。

## 目标分解

### 目标 G1：全量工具账本闭合

交付工具清单和迁移矩阵，来源包括组件登记、工具目录、Runtime 注册、WPF Editor 注册、工具箱映射和测试项目。

完成证据包括：

- 工具 ID、显示名、Runtime 入口、Editor 入口和组件登记完整。
- 每个工具都有原厂证据路径、自研消费者路径和当前状态。
- 工具数量与组件登记、工具箱和测试项目能够交叉核对。
- 没有 `Unknown`、`PendingOwner` 或空迁移状态。

### 目标 G2：公共 UI 架构闭合

先完成所有工具共同依赖的装配层。

- 工具窗口根、标题、帮助、Tab、底栏和关闭退订
- 单一平面参数页宿主
- 图像、ROI、引用和常量输入行装配
- 参数组、模板行、范围行、枚举行和状态行
- 公共控件目录、资源注册和本地化资源入口
- FeatureMatch 模板面板与配置窗口适配边界
- 生命周期、资源借用、关闭排空和迟到回调保护

完成证据包括框架级编译、框架测试夹具、控件树快照、关闭释放探针和 Release 构建。

### 目标 G3：代表工具验证架构

从不同装配模式各选一个代表工具，验证公共架构能够覆盖全部类型。

- 纯参数工具：FrameMean
- 图像/ROI 工具：BlobLabels
- 模板匹配工具：ContourMatch
- 动态分支工具：If
- 专用控件工具：ColorExtract

代表工具通过后才开始大批量迁移。代表工具只调整适配器和声明，不复制第二套公共视觉链。

### 目标 G4：全量代码级迁移

对每个工具同步迁移以下内容：

- Runtime 参数模型和执行入口
- 输入/输出契约和资源声明
- 结果字段、结果表和图像叠加声明
- WPF Editor 入口和公共装配适配器
- 原厂模板、控件和资源映射
- 保存重开、取消关闭、换节点和资源释放
- 工具定向测试和 Release 载荷登记

迁移按照装配模式批量执行，工具之间复用公共框架，不逐个复制视觉代码。

### 目标 G5：全量验收闭合

所有工具完成静态映射、代码级测试、Release 构建和 Agent Desktop 真实窗口复核。

- `NativeAligned` 工具完成完整验收。
- `LegacyCompatibility` 工具有隔离入口、差异列表和明确迁移顺序。
- `EvidenceBlocked` 工具保留可运行旧入口，并明确缺失证据。
- 全量矩阵中不存在未知状态。

## 高效落地策略

### 策略一：先建立唯一事实账本

先生成全量工具矩阵，再允许任何代码迁移。矩阵字段固定为：

`ToolId`、显示名、Runtime 入口、Editor 入口、原厂程序集、原厂参数根、原厂公共控件、输入模式、模板模式、结果模式、当前入口、目标适配器、状态、阻断原因、测试、Release 快照、责任批次。

矩阵变更必须和代码入口、证据文件和验证日志同时更新。

### 策略二：按装配模式并行，而不是按工具重复劳动

公共框架完成后，迁移工作按模式分组。

- 纯参数组装批次
- 图像/ROI 输入批次
- FeatureMatch 模板批次
- 动态字段和分支批次
- 专用图像/结果控件批次

同一批次共享适配器、控件、资源和测试夹具，减少重复实现。

### 策略三：先完成最小闭环，再扩展细节

每个工具迁移顺序固定为：

1. 项目入口和组件登记
2. Runtime/Editor 结构
3. 窗口根和 Tab
4. 基本参数和输入组装
5. 运行参数和结果页
6. 保存重开与关闭释放
7. 原厂控件细节和特殊交互

前一步没有通过，禁止进入下一步。

### 策略四：证据阻断时停止编码

缺少同版本原厂反编译、配置或运行证据时，工具进入 `EvidenceBlocked`。记录缺失项、需要的取证入口和恢复条件，不用自研近似控件填补空白。

### 策略五：兼容入口隔离迁移风险

公共架构迁移期间，未迁移工具通过 `LegacyCompatibility` 入口继续运行。兼容入口与新架构隔离，禁止新旧参数状态、窗口生命周期和视觉模板互相穿透。兼容入口只作为临时承载，不计为最终对齐。

## 里程碑与闸门

### M0：全量清单

闸门：所有工具都有唯一 ID、入口、状态和证据位置。

### M1：公共架构

闸门：框架级控件树、平面参数页、输入/ROI 组装和关闭释放测试通过。

### M2：代表工具

闸门：FrameMean、BlobLabels、ContourMatch、If、ColorExtract 的框架适配通过，5 种装配模式均有真实快照。

### M3：批量迁移

闸门：每个工具都有代码级迁移提交、定向测试和状态更新。

### M4：全量验证

闸门：全量 Release 构建通过，所有工具都有 Agent Desktop 复核结果和差异清单。

## 工具覆盖策略

### NativeAligned

新公共框架承载，原厂结构、控件、资源、交互、生命周期和 Release 证据闭合。

### LegacyCompatibility

旧工具通过隔离兼容宿主继续运行。记录旧入口、已知差异、阻断原因和迁移顺序。该状态不能作为 UI 对齐完成。

### EvidenceBlocked

原厂证据缺失或动态行为尚未确认。停止推测性编码，保留当前入口和证据缺口，补证后重新进入迁移队列。

## 每个工具的固定验收包

- 静态原厂来源清单
- 自研项目入口和消费者映射
- 页面/Tab/分组/控件/资源矩阵
- 输入、ROI、引用和结果链说明
- 模板或特殊窗口说明
- 定向测试日志
- Release 构建日志和载荷哈希
- Agent Desktop 窗口快照和截图
- 关闭、退订、迟到回调和资源释放记录
- 未确认行为和后续恢复条件

## 禁止事项

- 公共架构未通过前继续做工具局部视觉优化
- 用单个工具的自研实现反推原厂公共机制
- 为不同工具复制多套参数页和输入列表
- 用占位控件替代缺失原厂证据
- 只完成 Tab 名称就宣称工具 UI 对齐
- 把 LegacyCompatibility 或 EvidenceBlocked 计入 NativeAligned

## 最终收口

所有已实现工具都有唯一迁移状态。公共架构、代表工具、批量迁移和全量验证四个里程碑全部通过。全量 Release 程序能够启动，工具窗口能够打开，工具关闭后资源能够释放，所有差异都有证据和状态记录。
