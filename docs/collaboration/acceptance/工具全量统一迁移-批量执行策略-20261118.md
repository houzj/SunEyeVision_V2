# 工具全量统一迁移批量执行策略

日期：2026-11-18  
目标：18 个已登记工具统一使用原厂 page/section/row 参数页架构，完成 UI、功能、生命周期和 Release 验证。

## 执行原则

1. 原厂证据先于代码。每个工具必须有静态源码、原厂配置或原厂运行截图中的 page、section、order、控件、专用组装和生命周期证据。
2. 公共链一次实现。输入页、参数根、行模板、范围、引用、ROI、结果树、底栏命令和释放合同只在 `Plugin.Wpf` 公共层实现。
3. 工具只提交声明。工具 Runtime 提供字段、输入、结果、专用组装声明和行为回调，不再创建第二套参数列表。
4. 不保留生产兼容回退。正式节点入口只走 `FlatNative`。缺少映射或专用接缝时阻断组装并进入缺口清单。
5. 批量门禁。每一批只在静态映射、结构测试、状态测试和 Release 构建都通过后进入下一批。

## 统一生产链

`ToolSchema → NativeInputPlacementMap → DeclaredInputFieldsView → DeclaredSettingsView → DeclaredFieldsView → NativeParameterPage → 专用组装接缝 → IToolSettingsView → RuntimeToolEditorWindow`

正式输入字段必须登记 `NativeInputPlacement(FieldId, Page, Section, Order)`。输入编辑器安装到外层参数页后，必须注册为外部字段锚点，专用 ROI、模板和辅助组装只能通过外层 `DeclaredFieldsView` 接缝插入。

## 批次划分

### 批次 A：公共链和基础输入

工具：`ImageLoad`、`FrameMean`、`DataClassification`、`MachineLearningClassifier`、`If`。

门禁：一个 `ParamListView`、字段编辑/引用/提交、页签切换、关闭退订、映射审计通过。

### 批次 B：标准图像与测量

工具：`ColorExtract`、`DivideImage`、`IntensityMeasure`、`PixelCount`、`CircleCircleMeasure`、`PointPointMeasure`。

门禁：数值/范围/枚举控件、图像输入、结果字段、保存重开和执行回执通过。

### 批次 C：定位和匹配

工具：`ContourMatch`、`GrayMatch`、`MarkFind`、`CircleFind`、`LineFind`。

门禁：模板/特征窗口、ROI、模型列表、创建编辑回滚、结果叠加和专用帮助入口通过。ContourMatch 与 GrayMatch 共享 FeatureMatch 公共面板，MarkFind 保持独立专用面板。

### 批次 D：Blob 复合组装

工具：`BlobAnalysis`、`BlobLabels`。

门禁：ImageSource、ROI 继承、位置修正、屏蔽区、运行参数、结果判定、结果显示、专用 ROI/辅助控件全部通过。Blob 当前的 `input.roi.area-type` 缺口必须在这一批闭合。

## 每批固定流水线

### 1. 静态映射生成

- 从 Runtime schema 读取输入/设置/结果声明。
- 从原厂证据登记 page、section、order、模板键、资源键和专用接缝。
- 生成 `docs/evidence/<batch>-placement.json`。
- `NativeInputPlacementMap` 和专用接缝完整性测试必须 0 缺口。

### 2. 公共结构测试

- 页面只存在一个正式 `ParamListView`。
- 输入字段在外层参数页可见并可作为后续专用组装锚点。
- 不存在嵌套 `DeclaredInputFieldsView` 视觉树。
- 隐藏锚点、惰性页和重复切换不重复创建字段。

### 3. 工具契约测试

- 字段编辑、引用、范围、枚举、ROI 和专用控件写回同一个 draft。
- `TryCapture` 统一验证 settings、输入和专用组装。
- 旧代次事件不能写新 draft。
- 关闭顺序覆盖输入、ROI、引用窗口、执行会话和结果 reader。

### 4. 自动化生产链

固定脚本完成插件准入、打开 `11111`、加载方案、选择节点、打开窗口、切换页签、执行交互、保存重开和关闭。脚本只使用 Agent Desktop CLI，不使用 computeruse。

每批脚本输出：窗口控件树、字段清单、页签清单、组装探针、错误日志、关闭后的资源计数和截图路径。

### 5. Release 和人工视觉验收

每批先执行定向 Release 构建，再执行完整 `SunEyeVision.slnx` Release 构建。Agent Desktop 复核原厂与自研的窗口尺寸、Tab、section、字段顺序、专用控件、结果显示和关闭释放。

## 并行策略

- 公共框架只有主线修改，避免多个分支同时改 `DeclaredSettingsView` 和 `DeclaredFieldsView`。
- 每个批次的工具证据整理、Runtime 声明核对、WPF 组装接缝整理和测试脚本可以并行。
- 汇合顺序固定为证据 JSON → 公共映射测试 → 工具接缝 → 工具测试 → Release 构建。
- 任一批次出现结构门禁失败时，只修公共接缝或该批次统一适配器，不继续扩展单工具视觉补丁。
