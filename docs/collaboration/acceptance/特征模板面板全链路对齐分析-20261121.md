## 二、三层归类

### 控件层
- `SuperImageButton` 三态 ✓ 已迁移
- `ListView` + `GridView` + `GridViewColumn` ✓ WPF 标准 + 本方 ListView 已迁移
- `ListViewStyle1` ✓ 已迁移（CrosshairSettingsResources.xaml:7）
- `TextBoxControlTemplate1`、`ImageButtonStyle`、`NormalCheckBoxStyle` — 需确认
- **结论：控件层能力齐全，不是问题根因**

### 框架层（2 个差异）
1. **面板高度铺不满**：原厂面板铺满 tab 内容区（约 380px）；本方通过 `AnchoredSettingsContent`（`ContourMatchParameterEditor.xaml.cs:61`）挂进**字段行宿主**（`DeclaredFieldsView.AddAfterField`），行高由内容决定，不会 Stretch。
   - 这是框架 `AnchoredSettingsContent` 的机制，非面板内部 xaml 问题。
   - 对比：本方截图面板只占上半（~190px），下方空白是宿主的。
2. **宽度补偿**：宿主给面板的宽度窄于整页 → 之前用 `Width=396` hack 补偿。

### 组装层（本方可修，是主因）
| 项 | 原厂 | 本方 | 差异 |
|---|---|---|---|
| 列表实现 | GridView 3列(28/92/106) + 列头Collapsed | 裸 ListView + 手写 Grid 项 | **组装方式不同**——导致列表项对齐/列宽/无列头表现不同 |
| 列表项高 | ItemContainerStyle Border Height=30 白底 | ModelRow Grid Height=30 白底 | 接近 |
| 列表选中色 | #F2F4F7 | 无 | 缺 |
| 列头 | GridViewColumnHeader Visibility=Collapsed（显式隐藏） | 无列头（因为没有 GridView） | 视觉相同但机制不同 |
| 操作按钮 | ImageButtonStyle + Tag 三态 | IconButton 手写 Button | 接近 |
| 勾选框 | NormalCheckBoxStyle + IsSelected 绑定 | 裸 CheckBox 未绑 IsSelected | 缺绑定 |
| 预览图 | 绑定 ImageSource，选中时真实图 | 固定占位图 | 缺数据绑定 |

## 三、结论
- **列表头问题**：原厂根本没有可见列头（Collapsed），本方也没有 → 视觉一致。用户感知的"列表头差异"其实来自**列表项的结构/对齐**（GridView 列 vs 手写 Grid）和**数据绑定**（原厂有模板行，本方空）。
- **面板高度问题**：框架层 AnchoredSettingsContent 机制所致，本方面板内部改不出来。
- **真正要修的**：组装层——用 GridView 重写 ListView（列宽 28/92/106、列头 Collapsed、ItemContainerStyle 选中色），补勾选框绑定、预览图绑定。

## 四、实施清单
1. 组装层：ListView 改用 GridView 3 列 + GridViewColumnHeader Collapsed + ItemContainerStyle（选中色/白底/Height30）
2. 组装层：勾选框绑 IsSelected、预览图绑选中模型
3. 框架层：面板高度——评估 `AdditionalPageContents` 替代 `AnchoredSettingsContent`（需确认不破坏页内顺序）
