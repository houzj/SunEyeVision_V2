# DEF-001 · 关闭工具参数窗口导致主窗口关闭、应用退出（P0）

- **等级**：P0（阻断）
- **发现时间**：2026-11-17 11:19:50
- **命中清单项**：D4-12（关闭参数页不崩溃、主窗存活）、D8-06（关闭工具窗后主窗存活）、O10-04（关闭工具窗不退出应用）
- **涉及工具**：`ImageLoad`（基线标杆工具）——说明**不是单个新工具的缺陷，是外壳层问题**
- **环境**：主仓 Release `cebbe12bc`，构建 11:14:23

## 1 现象

打开基准方案 `11111.solution` → 双击「图像源1」节点打开参数窗口 → 点击参数窗口右上角关闭（✕）→ **主窗口随之关闭，进程退出**。

**附带观测**：参数窗口是**独立顶层窗口**（`list-windows` 显示 `1 图像源1`，bounds `159,420 420x500`），主窗口 bounds 为 `-117,-222 1600x900`（非最大化）。

## 5 待验证的根因假设（按可能性排序）

1. **`Application.Current.MainWindow` 指向被工具窗口覆盖**：`ShutdownMode` 在运行期被设为 `OnMainWindowClose`（`src/UI/App.xaml.cs:744`），若 `MainWindow` 属性在工具窗口显示期间被改写为该窗口，关闭它即触发关机。
2. **工具窗口与主窗口的 Owner 关系反向**：关闭 owned window 时误触发 owner 的关闭（需核查 `RuntimeToolEditorWindow` 的 Owner 赋值与 `MainWindowRuntimeEditing` 的创建点）。
3. **`ShutdownMode` 在窗口切换期间被临时改为 `OnMainWindowClose`**，且恰好有一个 `OnClosed` 事件触发关机判定。

## 6 影响

- 所有 12 个工具的参数页「打开→关闭」路径不可用于自动化验收（每次关闭都丢失会话）
- 用户侧表现为「改完参数关窗，整个程序消失」，属于最影响使用的缺陷
- E2 冒烟闸门在此项**判不通过**，E3 单会话批量验收**被阻断**

1. 在 `MainWindow.OnClosed` 与 `Application.Exit` 处加**调用栈取证**（临时日志），复现并定位真正的触发点

4. 复跑 D4-12、D8-06、O10-04、O3-16
## 8 根因（已验证）

`src/UI/App.xaml.cs:744`（`ShowMainWindow`）把 `ShutdownMode` 设为 **`OnMainWindowClose`**：

```csharp
ShutdownMode = ShutdownMode.OnMainWindowClose;
```

而 `Application.Current.MainWindow` 在运行期可能指向**非外壳窗口**（欢迎页 / 工具参数窗口）。当它指向参数窗口时，WPF 认为"主窗口被关闭"，直接触发应用关机；主窗口随后收到 `WM_CLOSE`（栈证据：`Window.WmClose` → `MainWindow.OnClosing`），进而 `MainWindow.OnClosed` 里的显式 `Shutdown()`。

这解释了为什么：
- 日志顺序是「工具窗 ReleaseView → 主窗 MainWindow.Closed → application-exit」
- 关闭栈是 `WmClose` 而非代码里的 `Close()` 调用
- **基线工具（图像源）同样复现**，与具体工具实现无关

## 9 修复

`src/UI/App.xaml.cs`：

- `ShowMainWindow` 中 `ShutdownMode` 改为 **`OnExplicitShutdown`**（退出仍由 `MainWindow.OnClosed` 的显式 `Shutdown()` 承担，行为不变）
- 同一处补 `Application.Current.MainWindow = mainWindow`，把"主窗口"身份固定在外壳上，避免被欢迎页/参数窗占用

附带可观测性（长期保留）：`MainWindow.OnClosing` / `OnClosed` 记录调用栈，今后同类"误关闭"可直接定位触发者。
