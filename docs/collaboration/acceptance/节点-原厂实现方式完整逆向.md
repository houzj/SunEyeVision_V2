# 节点视图：原厂实现方式完整逆向（两层模板机制）

> 证据：`decompiled/WpfControls/base/diagramitemtemplate.xaml`（1864 行）
> 关键行：926（Square）、1125（NORMAL）、1346（PROCESS）、1635（GROUP）、1782（NONE）、1789–1848（模板选择）

## 1 结论先行：原厂是「两层选择」

```
第 1 层  ModuleDisplayType  →  选哪个 ControlTemplate（模板族，尺寸与布局不同）
第 2 层  TargetDisplayType  →  在模板内部换 Path 几何（形状不同）
```

这两层是**独立**的，不能压成一层。

## 2 第 1 层：模板族（Style 触发器选 Template）

`DiagramItem` 的 Style 默认：

```xml
<Setter Property="Template" Value="{StaticResource NORMAL}"/>          <!-- L1789 -->
<Style.Triggers>
  <Trigger Property="local:DiagramItem.DisplayType"
           Value="{x:Static DataForUI:ModuleDisplayType.FUNCTION}">
    <Setter Property="Template" Value="{StaticResource Square}"/>       <!-- L1804 -->
    <Setter Property="FrameworkElement.ContextMenu" Value="{StaticResource SquareOperateMenu}"/>
  </Trigger>
  <!-- FUNCTIONADORNER / TIMER / TIMERADORNER 同样用 Square（L1808/1812/1816） -->
  <Trigger … ModuleDisplayType.PROCESS>   → Template = PROCESS（140×120，L1820）</Trigger>
  <Trigger … ModuleDisplayType.GROUP>     → Template = GROUP（L1833）</Trigger>
  <Trigger … ModuleDisplayType.NONE>      → Template = NONE（空模板，L1848）</Trigger>
</Style.Triggers>
```

`MODULE`（普通算法工具）不换模板，走默认 `NORMAL`，但同一 trigger 里还会挂：

```xml
<Setter Property="local:DiagramItem.IsModuleForbidden" Value="{Binding IsForbidden}"/>
<Setter Property="local:DiagramItem.IsModuleFailed"   Value="{Binding IsLoadFailed}"/>
<Setter Property="local:DiagramItem.RunState"         Value="{Binding DecorateSource.IsRunOK}"/>
<Setter Property="FrameworkElement.ContextMenu"       Value="{StaticResource NormalOperateMenu}"/>
```

### 2.1 五个模板的基准尺寸与内部结构

| 模板 | `PART_View` | 内部结构（关键差异） |
|---|---|---|
| **NORMAL**（L1125） | **110 × 30** | 图标左对齐 `Margin=4,0`；`Grid Margin=26,0,0,0` 内放「编号 + 名称」；状态条 `Canvas Width=26` 靠左 |
| **Square**（L926） | **40 × 40** | 图标 **顶部居中** `Margin=0,4`；`Grid Margin=0,18,0,0` 内**只有编号**（无名称）；状态条 `Canvas Height=22` 靠上 |
| **PROCESS**（L1346） | **140 × 120** | 两行布局（`Row 30 + *`）+ 圆角 3 的背景 Border，内容更复杂（缩略/状态区） |
| **GROUP**（L1635） | **110 × 40** | 组合节点，内部有 `ContentPresenter cp` + 循环背景 `GroupCirculationBackground` |
| **NONE**（L1782） | — | 空模板（`<ControlTemplate … />`），用于隐藏的辅助项 |

共同结构（NORMAL/Square）：

```xml
<Grid Name="PART_View" Width="…" Height="…">
  <Rectangle Name="Rec" Fill="#00FFFFFF" Margin="-10"/>                     <!-- 命中区透明底 -->
  <Path Name="itemBorder" Margin="0.2" Style="{StaticResource NormalModulePathStyle}">
    <DropShadowEffect Color="#FF121111" ShadowDepth="3" Opacity="0.45"/>
  </Path>
  <Canvas Name="StateFlag" …/>                                              <!-- 状态条 -->
  <Image Name="LogoIm" Stretch="None" Source="{Binding StateImagePath}"/>   <!-- 图标（默认白色状态图） -->
  <Path Name="errorBorder" Visibility="Collapsed" Stroke="#FF636468" StrokeThickness="2"/>
  <Grid …>编号（横向模板还有名称）</Grid>
  <ContentPresenter Name="leftConnector"/> … ×4                              <!-- 悬停时注入端口 -->
</Grid>
```

## 3 第 2 层：模板内部按 `TargetDisplayType` 换几何

NORMAL 模板内（L1167–1183）：

| TargetDisplayType | 几何 | 附加 |
|---|---|---|
| DEFAULT | `NormalModulePathStyle` | 110×30，r=4 |
| IMAGE | `ImageModulePath` | 110×30，r=15 胶囊 |
| **IFBRANCH** | **`IfBranchPath`** | **同时 `PART_View.Height = 40`** |
| FUNCTION | `FunctionModulePath` | 40×40（注：FUNCTION 通常已走 Square 模板） |
| TIMER | `TimerModulePath` | 40×40 |
| SHELL | `ShellModulePath` | 110×30 |
| COMMUNCATION | `CommuncationDataPath` | 110×30 |

Square 模板内（L962–965）同样有 FUNCTION / TIMER 的几何切换（用于 FUNCTIONADORNER 等仍在 40×40 容器内的场景）。

## 4 数据来源：谁提供这两个类型

| 层 | 属性 | 来源 |
|---|---|---|
| 第 1 层 | `DisplayType`（`ModuleDisplayType`：MODULE/FUNCTION/TIMER/PROCESS/GROUP/NONE/…ADORNER） | 节点装饰器 / 模块种类 |
| 第 2 层 | `TargetDisplayType`（`DiagramItemSubDisplayEnum`：DEFAULT/IMAGE/IFBRANCH/…） | 模块目录声明 `ToolItemInfo.xml` 的 `<displayType>` |

## 5 我方当前实现 vs 原厂

| 维度 | 原厂 | 我方现状 |
|---|---|---|
| 结构 | `DiagramItem : Control` + 5 个 `ControlTemplate` + Style 触发器选模板 | 单个 `DataTemplate` 内联 `Border`，靠 `DataTrigger` 改几何 |
| 模板族 | 有（NORMAL/Square/PROCESS/GROUP/NONE） | **无**，只有一套 |
| 尺寸 | 由模板 `PART_View` 固定 | 由投影 `VisualWidth/Height` 计算 |
| 形状 | 模板内 Path.Data 切换 | 同一 Path 切换（结构对，但受限于单模板） |
| 类型 | 两层（DisplayType + TargetDisplayType） | 一层（`Catalog.NodeDisplayType`） |

**这正是"改了样式不生效"的根因**：原厂把「尺寸/布局」放在模板层，我把它们塞进同一模板的属性计算里，模板内又改几何，两者互相牵制（例如 IFBRANCH 需要同时改高度与几何，而高度写死在投影、几何写在模板，任一侧失配就退回矩形外观）。

## 6 按原厂方式改造的步骤

1. **把节点视觉从 DataTemplate 内联改为 Control + ControlTemplate**
   - 新增 `NodeView : Control`（等价 `DiagramItem`），`DefaultStyleKey` 指向自定义 Style
   - 目录：`src/UI/Features/WorkflowUI/Canvas/NodeView.xaml(.cs)`、`Themes/NodeView.xaml`
2. **拆出 3 个必需模板**（先 NORMAL / Square / PROCESS；GROUP 与 NONE 后续）
   - `NORMAL`：110×30，图标左 + 编号名横排
   - `Square`：40×40，图标上 + 编号下
   - `PROCESS`：140×120，两行布局
3. **Style 里按 `NodeKind` 选模板**（对齐 `ModuleDisplayType`）
   ```
   FUNCTION/TIMER → Square；PROCESS → PROCESS；其余 → NORMAL
   ```
4. **NORMAL/Square 模板内部再按 `NodeDisplayType` 换几何**（已有 7 个几何资源直接复用）
   - IFBRANCH 在模板里改 `PART_View.Height=40`，与几何同一层，避免跨层失配
5. **投影只提供数据**：类型、名称、编号、状态；不再计算尺寸
6. **端口层随模板**：端口挂 `PART_View`，模板切换自动跟随

## 7 与现状的兼容策略

- 现有 12 个工具全部是 `MODULE` 类（NORMAL 模板），重构后外观不变，只是实现方式换成模板族
- `IMAGE`/`IFBRANCH` 等仍由 NORMAL 模板内部触发器控制（与原厂一致）
- 方案文件无需迁移（数据未变，仅视图实现方式改变）
