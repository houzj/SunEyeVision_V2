# 不同节点用不同样式：原厂设计与我方差异（设计层 → 细节层）

> 证据：`decompiled/WpfControls/base/diagramitemtemplate.xaml`（1864 行）+ `DiagramItemSubDisplayEnum.cs`
> 对照：`src/UI/Features/WorkflowUI/Canvas/WorkflowCanvasControl.xaml`、`DocumentCanvasProjection.cs`

## 1 设计层：原厂用「显示类型枚举 + 模板族」驱动样式

### 1.1 类型枚举（`DiagramItemSubDisplayEnum`）

```csharp
public enum DiagramItemSubDisplayEnum
{
    DEFAULT,        // 标准矩形
    IMAGE,          // 图像专用：胶囊
    IFBRANCH,       // 条件分支：六边形 + 加高
    FUNCTION,       // 方形功能节点
    TIMER,          // 圆形定时节点
    SHELL,          // 壳形（斜角）
    COMMUNCATION    // 通讯/数据：左右尖角六边形
}
```

节点的显示类型**不由画布决定**，而是节点自身属性 `TargetDisplayType`（来自工具的目录声明），模板用 `DataTrigger` 切换几何：

```xml
<DataTrigger Value="{x:Static local:DiagramItemSubDisplayEnum.IMAGE}" Binding="{Binding TargetDisplayType}">
  <Setter TargetName="itemBorder" Property="Path.Data" Value="{StaticResource ImageModulePath}" />
</DataTrigger>
<DataTrigger Value="…IFBRANCH…">
  <Setter TargetName="itemBorder" Property="Path.Data" Value="{StaticResource IfBranchPath}" />
  <Setter TargetName="PART_View" Property="FrameworkElement.Height" Value="40" />   <!-- 该类型改高度 -->
</DataTrigger>
```
（`diagramitemtemplate.xaml:1167-1183`）

### 1.2 模板族：4 套基准尺寸

原厂不是「一套模板改形状」，而是**4 个模板**，按节点体量分：

| 模板位置 | `PART_View` 基准尺寸 | 承载类型 |
|---|---|---|
| L927 | **40 × 40** | FUNCTION、TIMER（方形/圆形小节点：图标在上、编号在下） |
| L1126 | **110 × 30** | DEFAULT、IMAGE、SHELL、COMMUNCATION（横向：图标左 + 编号 + 名称） |
| L1347 | **140 × 120** | 大节点（组合/子流程类） |
| L1636 | **110 × 40** | 条件分支专用横向模板 |

IFBRANCH 在 110×30 模板内被额外抬到 **40 高**（L1171），所以最终也是 110×40，与 L1636 模板一致。

### 2.1 填充（所有类型共用同一套）

`NormalModulePathStyle` 的 Fill 是 5 段垂直渐变：

```
#FAF7F5 (0) → #F3F6F5 (0.47) → #ECEDF0 (0.82) → #EBE6E2 (0.97) → #EB6600 (1.0)
```

最后一段 `#EB6600` 让节点**底边出现一条橙色细线**。阴影独立于样式：`DropShadowEffect Color=#FF121111 ShadowDepth=3 Opacity=0.45`。

### 2.2 内容布局随模板族变化

| 模板族 | 图标位置 | 文字位置 |
|---|---|---|
| 110×30 / 110×40（横向） | 左对齐，`Margin=4,0,0,0`，图标 20×20 | 编号与名称横排，`Grid Margin=26,0,0,0`，12px Bold，#4C4C4C |
| 40×40（方形） | **顶部居中**，`Margin=0,4,0,0` | 编号在下方，`Grid Margin=0,18,0,0`，12px Bold |

## 4 关键结论：先对齐「类型判定」，再对形状

形状本身只是查表；真正的分歧在**谁决定类型**。原厂是工具目录声明 `TargetDisplayType`，我方是 `Catalog.NodeDisplayType`（`DocumentCanvasProjection.NodeDisplayType`）。

目前我方 12 个工具的声明值：

| 工具 | 我方声明 | 原厂实测形状 | 结论 |
|---|---|---|---|
| 图像源 | IMAGE | 胶囊 | ✅ |
| 颜色抽取 | IMAGE | 胶囊 | ✅ |
| 条件分支 | IFBRANCH | 六边形 110×40 | ✅（本轮修正） |
| 轮廓匹配 / 灰度匹配 / 图形定位 / Blob分析 / Blob标签 / 亮度测量 / 像素统计 / 帧平均 / 划片拆分 | DEFAULT | 矩形 110×30 | ✅（帧平均/划片拆分本轮由 IMAGE 改回） |

即当前 12 个工具的类型已与原厂一致；剩余差距是**其它类型（FUNCTION/TIMER/SHELL/COMM）尚未实现**，一旦接入对应工具就会暴露。

## 5 实施顺序（按依赖）

1. **类型→模板族路由**：`NodeDisplayType` 决定用「横向 110×30/40」还是「方形 40×40」模板
2. **补 40×40 模板族**：方形几何（FUNCTION/TIMER）+ 图标上/编号下布局
3. 补 SHELL / COMMUNCATION 几何到横向模板
4. 补 140×120 大节点模板（组合/子流程）
5. 逐工具核对 `NodeDisplayType` 是否与原厂模块一致（需要各模块声明证据）

12 个工具中**只有「图像源」是胶囊（IMAGE）、「条件分支」是六边形（IFBRANCH）**，其余 10 个全部是标准矩形（DEFAULT）。
