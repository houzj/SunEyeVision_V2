# 轮廓匹配前置：项目结构与 UI 装配架构审计

日期：2026-11-18  
范围：VisionMaster 4.4.0 Build20250516 的轮廓匹配原厂组件与 SunEyeVision 当前工具框架  
状态：框架重构前置，暂停轮廓匹配局部视觉优化

## 结论

当前自研工具的参数页面由通用元数据渲染器承载，原厂轮廓匹配由工具专属参数根、特征匹配公共控件、工具专属对话框和资源字典共同装配。两者的职责边界、输入行装配方式、模板生命周期和窗口根对象都不一致。

在公共装配链没有重新对齐前，继续修改轮廓匹配字段、面板或模板样式只能把当前嵌套装配固化。现有轮廓匹配局部改动保留在工作区，暂不作为完成结果，也不继续扩展。

## 原厂结构

### 项目与资源层

- `IMVSContourMatchModuControl` 是工具专属 WPF 组件程序集。
- `paramstabcontrolhppyramidfeaturematch.xaml` 是参数页根，使用 `ParamsTabControl4FeatureMatch` 和 `ParamsConfigControlBase`。
- `hppyramidfeaturepatmatchdialoguistyle.xaml` 提供轮廓匹配专属参数根模板、图像区、工具栏、模型列表、配置参数和底部布局。
- `datatemplate/paramusercontroldatatemplate.xaml` 注册轮廓匹配专属底栏数据模板。
- `themes/generic.xaml` 把轮廓匹配控件样式接入 WPF 主题。
- 特征模板面板复用 `FeatureMatchCommonControl` 的 `FeatureMatchConfigPanal` 和 `FeaturepatMatchConfigPanalData`，轮廓匹配只提供金字塔模型类型和文件扩展名等适配。

### UI 与状态层

- `HPPyramidFeaturepatMatchDialogUI` 承担模板配置窗口的图像、掩膜、模型生成、匹配中心、撤销重做和关闭结果。
- `PyramidFeaturepatMatchConfigPanalData` 承担模型列表、导入导出、模型创建/编辑生命周期和模型数据回写。
- 原厂模板配置窗口由 `CreateModel` 创建，尺寸为 900×534，窗口内容是 `HPPyramidFeaturepatMatchDialogUI`，不是参数页中的普通字段行。
- 参数窗口、特征模板公共面板和模板配置窗口是三个不同的装配层级。

## 当前自研结构

### 项目层

- Runtime 与 WPF 分成两个工具项目。
- `ContourMatchEditorFactory` 作为 WPF 入口，被宿主 `RuntimeNodeConfigurationControl` 创建。
- Runtime 通过 `ToolSchema`、`FieldPresentation` 和 `FieldLayout` 描述设置字段。
- WPF 由 `DeclaredSettingsView`、`DeclaredFieldsView`、`DeclaredFieldRow` 和 `DeclaredFieldTemplateRegistry` 统一生成参数页。
- 输入由 `DeclaredInputFieldsView` 生成，再作为一个组合行注入 `DeclaredFieldsView`。
- `ContourMatchTemplatePanel` 当前是工具内自定义组合，负责模型列表、文件操作和模板入口。

### 当前已观察到的装配结果

- 基本参数页的图像输入和 ROI 控件位于嵌套输入列表中，外层参数页仍保留自己的分组行。
- 隐藏字段作为分组锚点时，外层组的可见性刷新与输入组合生命周期没有统一收口，可能出现空分组或重复标题。
- 特征模板页同时包含通用字段行和工具自定义模板面板，二者没有原厂 `FeatureMatchConfigPanal` 的共同生命周期。
- 宿主负责通用参数视图、输入组合、工具面板和执行草稿的接缝，工具自身无法表达原厂的参数根和模板配置窗口边界。

## 必须先修复的结构差异

| 层级 | 原厂 | 当前自研 | 影响 |
|---|---|---|---|
| 参数窗口根 | 工具专属 `ParamsTabControl4FeatureMatch` | 宿主通用 `DeclaredSettingsView` | 标题、帮助、Tab 根和窗口状态边界不同 |
| 参数页容器 | 单一原生参数列表承载分组和行 | 外层参数列表嵌套输入参数列表 | 产生多余分组、空锚点和层级错位 |
| 输入装配 | 输入行直接属于原生页分组 | `DeclaredInputFieldsView` 作为组合行注入 | 输入、ROI、引用和分组生命周期分离 |
| 特征模板面板 | 公共 `FeatureMatchConfigPanal` + 工具数据适配 | 工具自定义 `ContourMatchTemplatePanel` | 模板列表、编辑、文件、状态和资源边界不一致 |
| 模板配置窗口 | 独立 900×534 专属对话框 | 宿主面板回调或临时组合 | 图像区、工具栏、参数区和关闭回写无法同源 |
| 资源注册 | 工具程序集主题、公共 FeatureMatch 资源和专属 DataTemplate | 通用注册表加工具注入 | 复杂控件只能靠局部补丁进入页面 |
| 状态模型 | 工具专属 VM、命令、集合和窗口状态 | 通用字段状态加宿主回调 | 交互状态和工具生命周期边界不同 |
| 证据范围 | 轮廓匹配专属原厂组件和 FeatureMatchCommonControl | 主要引用通用参数框架 | 用通用框架推导原厂行为会越过证据边界 |

## 框架先行目标结构

### 公共窗口根

建立一个原厂化的 `NativeToolWindowRoot`，统一承载标题、帮助、Tab 根、底栏命令、关闭退订、在飞等待和资源释放。工具适配器只提供工具身份、页签清单和命令回调。

### 平面参数页

建立单一 `NativeParameterPageHost`。输入图像、ROI、引用、常量字段和工具组合都以同一页的原生参数行加入分组，不把输入列表作为另一个参数列表的单行嵌套。隐藏锚点只提供结构身份，不留下可见空组。

### 原厂公共模板匹配面板

建立公共 `NativeFeatureTemplatePanel` 和 `NativeFeatureTemplateDialog`。公共层提供模型列表、排序、删除、选择、图像区、掩膜工具栏、缩放工具栏、配置参数区和底栏。工具适配器只提供模型数据类型、文件扩展名、图像/ROI来源、创建和回写回调。

### 工具适配边界

轮廓匹配适配器只保留以下内容。

- 金字塔参数声明和运行参数声明
- 原厂模型数据编码与解码
- 图像、ROI 和位置修正的正式输入身份
- 模板生成、保存、载入、编辑和回写回调
- 结果字段和结果显示声明

工具适配器不再自行创建第二套参数列表、第二套模板列表或第二套底栏视觉。

## 实施顺序

1. 冻结轮廓匹配局部视觉改动，保留工作区，不再增加工具专用补丁。
2. 完成原厂组件、公共 FeatureMatch 组件、资源字典、参数根和模板配置窗口的静态映射清单。
3. 在 `Plugin.Wpf` 建立公共窗口根、平面参数页宿主、输入行装配器和模板匹配公共面板。
4. 建立框架级测试夹具，验证页签、分组、输入行、组合控件、关闭退订和资源释放，不依赖具体工具算法。
5. 用轮廓匹配作为第一 个消费者接入公共结构，只调整适配器，不再写工具专属第二套视觉链。
6. 通过原厂/自研同尺寸窗口快照、控件树快照和关闭资源探针后，才恢复轮廓匹配的字段和样式细节优化。

## 完成门槛

- 原厂与自研的窗口根、参数页根、输入组装、特征模板公共面板和模板配置窗口均有静态来源与消费者映射。
- 基本参数页不再出现嵌套输入列表导致的多余标题、空分组或重复锚点。
- 特征模板创建窗口由公共模板配置控件承载，轮廓匹配只提供模型和数据适配。
- 工具关闭、取消、保存、重开、输入切换和迟到回调都沿同一生命周期合同收口。
- 框架级 Release 构建和 Agent Desktop 控件树验证通过后，才重新开始轮廓匹配局部 UI 对齐。
