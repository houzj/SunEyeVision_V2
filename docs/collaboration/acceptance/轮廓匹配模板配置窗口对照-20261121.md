# 轮廓匹配模板配置窗口对照（2026-11-21）

## 原厂证据（静态，hppyramidfeaturepatmatchdialoguistyle.xaml + HPFeaturepatMatchDialogUI.cs）

- 窗口 900×534；布局 Grid 20*/7*，顶部工具条 40px，底栏 35px
- 顶部：选择当前图像(95)、选择其他图像(95)、模板存图(Toggle)、保存工程(SuperImageButton)、全部屏蔽(Toggle)
- 图像区工具条：Arrow/hikSector/hikCoverCircle/hikFrame/hikPolygon/hikCross + 擦除/画笔/生成模型/清除/撤销/重做/缩放
- 右侧：列表 + 配置参数 GroupBox（8 行 × 2 列，ComboBox Width=100）
- 底栏：匹配中心 FixX/FixY + 锁定 + 确定
- 图像选择实现（HPFeaturepatMatchDialogUI.cs:897-960）：
  - 当前图像 = GetCurImage 从模块关系链取上游数据 + InitData/DoClear
  - 其他图像 = GetMono8ImageDataByFileDialog 弹文件对话框选图

## 本方现状（ContourMatchTemplateConfigWindow.cs）

已对齐：窗口尺寸、20*/7* 布局、顶栏结构、ROI 编辑器、训练参数 8 字段、底栏 NativeMatchCenterBar。

本轮改动：
- 分组标题 `Tab_Match Params` → `配置参数`（原厂资源键的中文）
- 选择当前图像 → 借宿主当前帧 + `_frames.Refresh()`（对应原厂 GetCurImage+InitData+DoClear 语义）
- 选择其他图像 → 明确提示（框架不支持外部图像注入，见缺口）

## 缺口（需框架支持，非工具层能补）

| 功能 | 原厂 | 本方限制 | 归属 |
|---|---|---|---|
| 选择其他图像 | 弹文件对话框读图，设为 CurImage | `NativeRoiEditHost` 只认 `NativeRoiFrameSource` 借帧，契约明确 cannot choose or publish images；不能注入外部图像 | 框架层 ROI 编辑器契约 |
| 模板存图 Toggle | 控制模板是否保存图像数据 | 本方 ModelData 只序列化几何，无图像字段；需 schema + 序列化格式改动 | 工具数据契约 |
| 全部屏蔽 Toggle | IsUsePenCommand 切换笔刷/屏蔽模式 | 本方 ROI 编辑器 mask 组固定，未暴露模式切换 | 框架层 ROI 编辑器契约 |
| 图像区工具条按钮 | 擦除/画笔/缩放/撤销重做等 | 平台 NativeRoiEditHost 已提供绘制/撤销/重做/缩放，但本方未逐项核对按钮可见性/图标对齐 | 待逐项核对 |

## 判定

工具层已做的部分构建 0 error、30/30。剩余缺口属框架契约层，不是"装不上"——是框架当前不支持。
按三阶段铁律，需回到工程结构阶段扩展契约后再补功能；不应在工具层伪造实现。
