# 工作进度清单

本文件是**统一格式的进度清单**，用于把"某条线做到哪一步"从对话上下文里挪到磁盘上。

## 写法约定

- 每条线各自维护 `docs/collaboration/bus/progress/<lane>.md`，只写自己那份。
- 中心维护本文件，只做汇总与裁决，不改各线的明细。
- **每次落盘或构建之后更新一次**；**一轮结束前必须更新**（这是"能不能被看见"的唯一保证）。
- 只写可核验的事实：文件路径与行号、构建/测试的实测数字。不写"已完成大部分"这类无法核验的话。

## 清单模板（复制到 `progress/<lane>.md`）

```markdown
# <lane> 进度

更新时间：YYYY-MM-DD HH:MM
当前卡：T-0000（状态：claimed / done / blocked）

## 一、已完成（可核验）
- [卡号] 事项 —— 证据（文件:行 / 构建数字 / 测试结果）

## 二、进行中
- 下一步具体做什么，预计产出是什么文件

## 三、阻塞（需要裁决）
- 卡号 + 问题 + 需要谁决定什么 + 你倾向哪个选项

## 四、实测数字
- 构建：命令 + 结果（错误数/警告数/耗时）
- 测试：命令 + 通过/失败数

## 五、未验项
- 没验什么，缺什么条件

## 六、越界与夹带（有则写，无则写"无"）
- 未经批准的删除/移动/重命名
- 构建副产物（如 packages.lock.json）及其性质
```
