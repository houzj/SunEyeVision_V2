# B08 Blob 图像与二值图：静态证据和占位边界

## 已确认的原始证据

- VM 4.4 `D:/Program Files/VisionMaster4.4.0/MVDAlgorithmSDK/Includes/Algorithms/BlobFindCpp.h` 的 `IBlobFindResult::GetBinaryImage` 注释为输入图像的二值化结果；`GetBlobImage` 注释为目标连通域绘制结果。两者是不同接口，注释没有给出逐像素规则。
- 原始 `Applications/Module(sp)/x64/Location/IMVSBlobFindModu/IMVSBlobFindModu.xml` 分别声明 `BinaryImageComb` 与 `BlobImageComb`，各自包含图像、宽、高、像素格式字段；这些字段均为 `IsForce=false`。该声明不提供具体运行时像素格式。
- 原模块 `CIMVSBlobFindModu::ProcessOutput` 静态反编译见 `analysis/full-audit/b08-geometry-output-20261031/0x180020310-180020310.c`，原指令见同名 `.asm.txt`。两个独立条件分别经虚表偏移 `+0x18`、`+0x20` 调用，并将返回值交给 `FUN_18001d980`；原 PE 字符串分别为 `BinaryImage/Width/Height/PixelFormat` 与 `BlobImage/Width/Height/PixelFormat`。结合头文件虚函数顺序，支持对应两路图像输出；虚表对应关系依赖所分析二进制与头文件 ABI 一致。
- `MVDAlgorithmSDK/MVDTools/ExportMVDCode/components/data/moduleio/IMVSBlobFindModu.xml` 将各自 PixelFormat 映射到各自图像对象的 `GetPixelFormat()`；不能由此推断某个固定格式。
- 已有 `analysis/full-audit/b08-owned-runtime-20261030/b08-observations.json` 未找到上述图像字段，不能用作图像像素或 Domain 的验证。

## 当前证据不能确定的具体行为

1. BlobImage 是否只绘制筛选通过的连通域，及每个像素的具体取值、通道和格式。
2. BlobImage 与 BinaryImage 的逐像素关系，包含被筛掉区域、空结果及边界情况。
3. 输出是否保留输入图像 Domain、怎样表达区域外像素；`GetDomainIndex` 是连通域位置索引，不能证明输入 Domain 被保留。

上述结论限于本次检查的头文件、模块 XML、已有输出桥反编译及样本；不能声称已穷尽所有原生库实现。若后续获得能定位图像生成函数的具体调用边或可用隔离环境，再针对该点补证。

## 自研占位建议（不是原版行为，尚未实施）

为便于架构评审，可把两路图像建成独立的可选输出，并各自携带实际宽、高、像素格式；BlobImage 的绘制规则、筛选关系及 Domain 策略由独立图像结果生成适配层提供，暂标 `自研假设：仅绘制筛选通过的连通域，区域外为背景`。这是可替换的设计建议，并非 VM 的已证实规则；实际像素值、格式与 Domain 策略在实现前还须由实现方明确。影响下游显示、图像连接、结果导出及依赖像素或 Domain 的工具；替换位置为 Blob 图像结果生成适配层，接口不应把假设写死为 VM 合同。

当取得可运行的隔离副本时，可用多个独立连通域、选择性筛选及非矩形 Domain 样本，逐像素保存两路结果和格式/Domain 元数据作差分。此次未运行原机或 SDK，未改动产品及插件工作树。
