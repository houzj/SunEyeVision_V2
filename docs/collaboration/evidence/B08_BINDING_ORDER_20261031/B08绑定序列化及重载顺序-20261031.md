## 名称树和字节比较器补证

`1800bd110` 的原指令 `1800bd228–248` 将管理器 `+0x10` 与目标模块 ID 传 `18007d980`，后以返回对象和目标参数名调 `1800202d0`；新名称分支 `1800bd34b` 调 `18007db20`，后者同样调用 `1800202d0` / `180020a60` 并在未找到时插树。`18007d980:18007d98a–9c4` 对外树按 ID 搜索并返回匹配外节点 `+0x28` 的地址；而导出 `1800bf230:1800bf2a8–2ac,1800bf3ae–3b5` 从同一管理器 `+0x10` 读取外节点的 `+0x28` 来遍历内层树。因此在同一管理器、同一目标模块且通过筛选时，插入所使用的内层名称树与导出所遍历的内层树是对应结构；并不说它就是执行容器，执行容器须另核。

`1800202d0:180020324–350` 以两名称的较小字节长度调用 `1801e92c0`，前缀相同按长度比较。新取 `1801e92c0` 只有 `JMP qword ptr [0x1802048a8]`；独立静态解析原 PE 导入表确认该槽为 `MSVCR120.dll!memcmp`。该比较不做大小写折叠或文化规则；正常字符串树的中序遍历是以**所存字节**按字典序比较，较短前缀排前。原托管 `VmParamSubManager.cs:46–53` 将目标 `paramName` 经 `UTF8GetFixLenBytes(paramName,128)` 填 SDK 记录；只有经该入口且后续转换未改变字节时，可描述为 UTF-8 字节排序，不能以托管入口推断其他原生调用均是 UTF-8，更不能默认 Unicode 本地化或大小写不敏感排序。导出仍按模块/来源映射筛选，无法用此结论覆盖被过滤项。

## 对多参数失败与迁移的边界

保存侧按树遍历形成的记录，重载侧按文件记录次序依次调用绑定插入；名称树与比较器已在补证中定位，**仍须核对执行时消费队列的构造动作**，才能定论正常重开后哪些参数会先消费。已有单条样本无法说明“schema 字段顺序”“绑定顺序”或“JSON 排序”等效。若导入遇到某条插入失败，前面成功项未在上述循环看到直接回滚，但调用者的外层清理及并发仍未核，不能承诺最终保留。

建议实施侧在拿到执行容器的精确结论前，保留绑定的独立身份及可重放顺序，不把本地 JSON 按字段名重排冒称原厂一致；若当前必须选择其他排序，标为独立适配，并用至少两个目标名与相反建立顺序、含中途失败、替换和删除重绑、保存重开进行受控差分。此文的树遍历观察不代替比较器语义或原机多绑定实验。
