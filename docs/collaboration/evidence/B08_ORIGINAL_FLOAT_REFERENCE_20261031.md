# B08 浮点绑定索引与文本写入

范围限定原 VM 4.4 x64 `ModuleFrame.dll`、类型 2 的浮点参数分发和来源类型 3 的变量读取；未运行 SDK/VM，不能外推其他来源、数据类型或认定实际用户实例已走到该路径。原件 SHA-256 `45C57BC46F72FD1F9E0B3A6F9183FF974D14590CFD05ECF4E9FA97A4FF95AE9B`。

## 调用和索引

既有 `0x1800b9c70` 的类型 2 分支到 `0x1800ba590`；`ba590:0x1800ba5cd–600` 初始化四字节浮点和状态，调用 `0x1800bb8f0`，返回非零即走错误退出，不进入此项后续参数写入。`bb8f0:0x1800bb9e6–9f2` 将来源记录 `+4` 交给同一个 `0x1800bca20`，并保存其 EAX；`0x1800bba2e–3b` 把该值通过 R9D 传给 `0x1800ca720`，备选/回退调用也使用它。这个限定路径的 ALL、固定、动态索引解析复用 [整数索引报告](B08整数绑定索引解析静态追踪-20261031.md)：内部 tag 1 得 0，tag 2 得记录整数，tag 3 从动态索引来源第 0 项取整数；动态索引来源读取失败返回 0，之后目标来源仍可能读取成功。SDK 到内部 tag 的正常路径见 [SDK 序列化](B08-SDK索引序列化字段证据-20261031.md)。

## 浮点元素及错误

`ca720 → f61e0 → 0x18000fd90`。`fd90` 原指令将索引作为有符号整数，检查负值、数据对象和数量；成功从 `*(对象+0x48) + 8 + 4*index` 复制 4 字节。负索引或非空数组越界返回 `0xe0000014`；数据对象为空或数量为零返回 `0xe0000314`。名称查找未命中等其他位置也可能返回 `0xe0000314`，不能仅凭错误码判断缺失原因。外层 `ca720` 另有空输出、找不到模块及对象的错误分支；`bb8f0` 保存最终返回码，`ba590` 检查错误。类型/缓冲实例的选择与所有异常条件仍按具体调用路径核对。

## 精度及写入

`ba590:0x1800ba80d–81c` 使用 `MOVSS` 加载四字节浮点，将其经 XMM3 传给 `0x1800bc730`。后者调用 `sprintf_s`，原件格式字节为 `%f`，再把生成的字符串及长度传给 `0x1800bc8a0` 进入通用参数写入链；这不是直接把原浮点位传给目标 setter。该文本格式可能改变精度；输出的精确小数位、区域设置及特殊值需要限定 C 运行库环境后验证。现有 [B08 执行订阅注入边界](B08执行订阅注入边界-20261030.md) 记录 `bc8a0` 后续 setter 边；该静态调用不保证每个目标实例成功设置。
