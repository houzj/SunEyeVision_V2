# B08 界面解绑、生命周期及类型边界

固定证据为本工作区原始反编译源码与 VM 4.4 资源，未执行原 VM/SDK。已有 `LowThreshold` 整数实测是**直接 ParamSubManager API**，不等同触发 UI 的 IsSubA setter；本页描述条件性源码行为，不泛化其数值结果。

## 控件到解绑、回读与写回

1. `Apps.XmlUI/styles/paramusercontroldatatemplate.xaml:550–560,576–592,802–812,821–837` 整数/浮点单端和双端将控件 `IsSubscribeLeft/Right` 与对应 `IsSubA` 双向绑定；控件类型变化事件调用 `TypeChangeCommand`。`ValueBase.TypeChangeExecute`（ValueBase.cs:257–260）只发 `OnIsSubChanged(IsSubA)`，不能把事件本身等同删除或重排。UI 标志的赋值次序由 WPF 绑定及控件事件决定，不能由 XML 文本单独保证。
2. `ValueBase.IsSubA`（27–72）新旧相同则返回；变化后先改本地 `IsSub`。切 false 时，**只有**目标模块存在、`_SubData` 已实例化且 `CurValueA` 非空，才令 `_SubData.CurValueA=null`、设 `IsGetFromModule=true`、调用 `GetParamUnit()`，再设 false；其后写 `vmModule.UserData["@"+ComName]` 并通知 IsSubA。try 包围上述操作、捕获异常，不检查 `GetParamUnit` 返回码；异常可能使后续写 UserData 和标志复位未执行。`ButtonSelecter.CurValueA` 经 trigger→`SetModuleParamBindOperation` 空值分支执行 `DelModuleParamBinding` 然后 `SetLinkWithVarNull`，该分支 `flag2=false`，不能用 UI 标志 false 推断底层解绑成功。具体 setter 回滚和变量侧发送条件见 [双端值链](B08双端切回常量与读值静态链-20261030.md)、[删除及通知](B08解绑关系删除和后续通知静态边界-20261030.md)。
3. `NameValueItem.GetParamUnit`（1034–1086）先判断 AccessMode 包含 r，否则 -2；再经 `userStringData[ComName]` / `ModuleParam` 的配置 Getter 得到字符串并 Check，再更新 Value/OldValue。读取外层异常给 -1；校验/赋值的内层 catch 先报告失败并调用 `SetParamUnit()`，若后续没有抛出仍走成功回调并返回 0。不能将返回 0 简化为新值肯定被应用，且异常分支可能写回。直接参数 Getter 和 `VM_M_GetString` IO 订阅分开。
4. `ValueBase.SetInit`（251–255）只清 isInit 与 `_SubData` 引用，不调用删除、GetParamUnit、设置默认或重置参数。`AlgorithmTabRoot.CopyParamsWithOpen`（1264–1290）先按相应条件调用 `SignalBindOperation` 同步目标绑定，再 `SetInit` 以便重新初始化；`UpdateRunParamStatus`（1313–1346）只对找到的订阅项调用 `SetInit`。这些是缓存失效及同步路径，不能把它们描述成恢复常量。
5. `AlgorithmTabRoot.Dispose`（1558–1561）方法体只设置 `IsSubscribeInWindow=false`；该属性 setter（387–406）改变窗口标记、`HasSubscribeInWindow` 并通知选择控件，方法体不直接枚举解除所有绑定。此结论只限该 Dispose 与 setter 的可见代码；宿主关闭及其他生命周期清理仍需按调用者分别核证。显式恢复默认按钮 `Button_ResetAlgoParams.ClickCommandCmdExecute`（35–63）在用户确认后**先** `ResetRunParamBind`（遍历订阅项将 `IsSubA=false`），再 `owner.ResetParam()`，最后设置 `_IsResetAlgoParamsing` 并 `GetItemsValueUnit`；它是独立重置入口，不是普通 `SetInit` 或每次控件关闭。

## 不同类型边界

| 类型 | 原源码可确认 | 不能从整数样本推广的部分 |
|---|---|---|
| Integer | 继承 ValueBase，默认 ComType `int`；常规模板有订阅切换，值通过 int 解析和范围校验。 | 原厂直接 API 的 LowThreshold 37→173→解绑173 样本不证明 UI 切换及异常分支。 |
| Boolean | 继承 ValueBase、未覆写 ComType，故默认 `int`；`Value` 以 `bool.Parse`（非空）处理，专有 ValueChangedCmdExecute 与 GetParamUnit 有自己的门。标准 `Boolean` / `Boolean_sub` 模板只显示开关和 ValueChangedCommand，**未提供 IsSubA 或 SubData 切换**；如另一个宿主使用其他模板需另证。 | 不能仅因继承 ISubInfo 就声称 Blob `SelectByArea` 普通窗口能订阅；bool 与整数数值/失败行为、执行效果尚无同条件实测。 |
| Float / double | 此范围内 `Float : ValueBase` 的 `CurValue`、`CurValueA` 使用 CLR `double`、setter 按 `DecimalDigits` 舍入；其 `ComType` 明确是 `float`，Value setter `double.Parse`。`VmParamSubManager.GetVarType` 同时有 `float` 和 `double` 分派，但这不证明该 Float 模板订阅 `double`。 | 不能将 CLR double 直接认作原参数订阅类型 DOUBLE，或从整数实测推算小数精度、范围校验、回读及失败。实际 double 使用何模型/模板及 native 执行需逐实例取证。 |
| String | 独立继承 NameValueItem 并实现 ISubInfo，不是 ValueBase 子类；`String` 模板 859–881 含 IsSubA 切换、SubData、失焦命令。切 false、模块与非空 `_SubData` 满足时也先清关联再回读，但其后直接检查 `CurValue.ByteCount()>MaxLen`，成立时 UTF-8 字节处理、赋 `CurValueA` 并调用 `ValueChangedCmdExecute()`，可能继续 `SetParamUnit` / `PreExecuteRun`。setter 外层 catch 会记录异常；这一检查自身未先检查 `MaxLen>0`。 | **不能**套用整数直接 API 解绑保留最后值：字符串长度、UTF-8 截断/边界、回读失败及 UI 写回可能影响结果。上面是源码条件，不保证每次切换都触发或截断成功。 |

`GetVarType`（VmParamSubManager.cs:196–205）支持 `int/float/string/double` 映射，不等于四类都走相同执行算法或都已有 UI 模板和运行验证。具体 Blob `SelectByArea` 的原普通模板与资源见 [布尔订阅证据](B08-Blob布尔订阅与成员名称证据-20261030.md)。

## 可迁移决策与缺口

保留独立标志、绑定身份、删除调用、回读状态与异常写回；不得以取消 UI 订阅或 SetInit 当成功删除证明。对字符串保留长度校验和实际写回路径；对双端保留逐子项行为。已运行整数结果可用于相同直接 API 条件，不扩为 String/Boolean/Double。未核 UI 实例完整关闭调用者、GetParamUnit 的所有运行态异常与其他派生类的覆写；未执行原机差分。
