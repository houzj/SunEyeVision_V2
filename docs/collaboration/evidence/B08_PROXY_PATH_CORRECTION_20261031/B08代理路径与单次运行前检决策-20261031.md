# B08 ProxyPath 与单次运行前检决策

本次仅只读原指令、现有本机日志及历史清单，没有运行 SDK、改写共享清单、复制或修改厂商库。本报告更正此前把 `180018980` 当作仅用于日志的结论：此前伪代码省略了第三参数，导致漏掉实际字段写入。

## 已证路径

`VM_PROXY_Init → 1800480c0 → 18003c600`：原 `18003c6c4–6ce` 将对象 `+0x118` 地址通过 R8 传入 `180018980`。被调函数保存 R8，正常成功分支经 `GetModuleHandleA("ModuleProxy.dll")`、`GetModuleFileNameW` 获取该模块路径，去掉末级文件名、转换 UTF-8，再经 `18000fb70` 赋给该字段。此前本线宣称此调用不写字段是错误的，现予更正；完整汇编、PE 导入和 SHA 见 [公开初始化与实写](B08代理公开初始化与ProxyPath实写-20261031.md)。

限定模块名成功命中、路径未截断且转换成功时，资源线程以该实际加载模块目录拼接 `\..\..\ModuleProxy\ImageSourceTempPath.txt`。`GetModuleHandleA` 若返回 null，后续 `GetModuleFileNameW` 的 null 句柄语义不同；异常、路径重解析和同名模块歧义不得归入上述成功结论。PlatformManager 存在影响代理加载目标的配置；尚未证明当前 SDK 正式公开参数能在本次约束下提供独占清单。用户禁止复制厂商程序或库、替换原二进制及修改共享清单，不能将这些动作当作默认隔离方案。

## 清单不等于清理目标范围

`180036e40` 从历史清单读取整行路径，解析末级 `VM%dImgSrcTemp`，以原进程快照辅助函数判断；快照失败也返回 false，将历史路径加入待删除队列。资源线程的递归清理使用历史行原路径，不将其强制约束在清单目录。因此即使能把清单位置指到自有树，也必须单独证明所有历史行和递归目标的实际解析范围、重解析点行为和进程身份。只将 exe/输出放独占目录不够。

## 主线提供的单次前检：有限价值与缺口

技术总监线只读快照显示原安装 `Applications/ModuleProxy/ImageSourceTempPath.txt` SHA-256 `ABC3F631D0E717C273FBA53FCDB40A3705684FEF58B42F868A195497400F7823`，仅一行指向其已结束 PID 127868 的测试缓存；本线独立只读复核同一 SHA 及该目录存在。该线核对十份有事前 SHA 的正式证据未变，缓存缺少事前逐文件基线。该快照能缩小**当时**可见历史行，不能保证资源线程稍后读取时清单未被并发更新、旧 PID 未复用、访问失败不被误判，亦不能凭路径字符串前缀排除目录内 junction 或其他重解析。

一次性前检若要用于决策，至少需要：明确实际加载 DLL 与解析后的清单身份；核对清单全部行、各目标最终路径和递归子项以及文件所有权；确认历史目标确为已授权可清理的测试缓存，且没有其他任务在使用；防止前检与原线程读取之间清单被修改，并处理快照失败、PID 复用和重解析。当前尚无证据证明这些约束能以原公开接口原子实施；来自另一聊天的“该缓存属于本线”是归属线索，不能自行撤销用户“不干预其他任务临时文件”的限制。用户此轮只要求评估，未批准清理指定目录。

## 决策与最小未证边界

在历史清单及其全部递归目标能够受控、且不触及其他任务目录之前，不再启动原 SDK；这不是宣称正式隔离不可能。继续追平台 ProxyPath 配置从公开初始化参数到实际 LoadLibrary 的入口、同名 DLL 实际解析和规范化，并确认是否存在正式支持的互斥/独立清单机制。若最终采用一次性窗口，必须先确认上述目标归属和授权及检查到执行的并发保护；无此证据不把前检当作保证。源码、成功分支和可能风险分别见 [实写报告](B08代理公开初始化与ProxyPath实写-20261031.md)、[独立前检审计](B08代理ProxyPath真实赋值与前检边界-20261031.md)、[历史清理](B08原SDK历史图像临时目录清理风险-20261030.md)。
