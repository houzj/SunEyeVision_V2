# B08 前驱、画布连接与订阅依赖

适用范围：原 VM 4.4 已留存托管反编译源码、原 SDK 包装和两个既有本机样本日志。本轮没有启动 SDK/VM、未更改产品或其他工作树。以下区分可确认的托管调用与 native 内部尚未覆盖的分支。

## 原图、前驱和候选

1. `VM.Core.VmModule.GetPreModules`（VmModule.cs:3953–3956）直接返回 `PreModules`，不是递归计算的列表。首次访问 NextModules/PreModules 会调用 `LoadNextAndPreModules`（:494–522、2120–2163）：收集同父 `VmModuleSet.Modules` 的节点 ID，调用 `ModuleManager.GetMultiModuleConnect`，根据每条结果中的 `anNextModuleId` 在同一父集合内定位目标，填源 `_NextModules` 和目标 `_PreModules`，再登记集合变化处理。`ModuleManager.cs:1136–1159` 调 SDK `IMVS_GetMultiModuleConnect` 并释放动态内存。这是 SDK 连接表驱动的托管模型，不等同纯粹枚举所有画布项。SDK/native 返回的所有内部关系来源尚未逐分支关闭。
2. `VmModule.GetFrontParamItems`（:3959–3991）沿 PreModules **递归**去重，再在父节点存在且非 VmSolution 时加入父节点；不能将直接 PreModules 等同全部传递前驱。对于 `GetFrontIOWithLeafItemsByName`（:4049–4075），又附加 ID 13000 全局变量和对应容器局部变量，父模块取 Inputs、其他项取 Outputs，最后按组合类型、`CanSubscribeA && Visible` 筛选。`GetFrontParamItemsOperation.Operate` 调该方法将候选写入目标（GetFrontParamItemsOperation.cs:22–50）。因此变量/父容器等独立来源并非都要求是画布前驱，且该具体 IMAGE 组合路径与其他来源树不能混为一谈。
3. `Apps.XmlParser.ParamTab.VmModuleExtern.GetFrontFilterTree`（:190–263）以模块传递前驱为基础；依据参数可额外纳入自身或容器内部子项、外部 `TRIGGER_STRING`、本地/全局变量及空项，并对 Holder 显示名称排序。不同调用者的选项不同，不能把该路径宣称为仅显式图边、全局所有节点或某个固定顺序。

## 画布边与数据订阅的已证操作

1. `VmModuleBaseDecorator.AddConnection`（:1098–1119）将目标添加到 `source.NextModules`；允许 `isAutoLink` 且目标不是流程时，再调用 `AutoLinkData`。它先创建控制连接，再可选自动订阅，不是先因数据订阅必然生成边。`VmModule.NextModules_CollectionChanged`（:2469–2516）新增时调用 `ConnectOneModule(source.ID,target.ID)` 并将源放入目标 PreModules；删除先 `DisConnectOneModule`、移除前驱，再对目标调用 `UnSubModule` 和 `ModuleOperate`。`VmConnectionDecorator.DeleteConnection`（:174–202）由画布移除 `source.NextModules`。其他代码、SDK API 也能触发连接；不能把所有前驱都等于某次鼠标拖线。
2. `VmIO.RelateIO` setter（VmIO.cs:121–210）记录撤销并调用 Root.UnSubscribe/Subscribe；`VmModule.Subscribe`（:1823–1851）叶节点构造订阅/发布结构并 `ModuleManager.SubscribeResult`，组合按子项递归。该**已读托管调用体**没有调用 NextModules.Add / ConnectOneModule。`SetModuleParamBindOperation.Operate`（:30–120）按常量、全局字符串或变量来源调用 `ParamSubManager.SetModuleParamBinding`，后者把目标/来源/索引打包送 ModuleManager；这些已读方法也没有直接增图边。不能仅凭这段托管代码排除 SDK 内部、native 回调或另一个宿主自动修改连接。
3. 移除连接后 `UnSubModule`→`UnSubPreModule`（VmModule.cs:1982–2078）按剩余传递前驱检查 IO.RelateIO 并在条件满足时清除；`TRIGGER_STRING`、常量、父/自身、特殊 ID/变量等有具体例外，`VmModuleSet` 和普通节点分支不完全相同，不可统一写成“删除边清除所有订阅”或“绑定永久独立”。该段专门检查 IO，不证明参数绑定清理等价。

## 已有原机样本：两种操作可以分开

技术总监线 `B08OriginalBinding-20261030` 样本中，原 ModuleFrame.log 443–481 行分别记录 Blob id 2 的 InImage 四叶到图像源 id 0 的订阅成功；该日志全文未出现 `VM_M_ConnectModule(srcId=0,dstId=2)`。此样本后续整数绑定读取 `0xe0000314`，并非成功 Blob 流程，不可用它证明该订阅能产生正确流程执行，亦未在此样本读取 SDK 返回的连接表。日志 SHA-256 `72ADC20F9BCCE23D74A552E724166EBDD6929C33F954FCECE641356B158E2BE7`。

成功 `attempt03` 探针源码 :75 先设置图像组合 `RelateIO`，:79–81 单独将 Blob 加入 ImageSource.NextModules；日志 445–481 行为四叶订阅、499 行单独出现 `VM_M_ConnectModule(srcId=0,dstId=2)`。这是同一流程中两种调用分别可发生的证据，**不是 native 所有路径都不会根据订阅派生调度关系的证明**。源码 SHA-256 `255FB3248F02A473AC3F9DA303B8E73A1FC2521490867A44D9A725FCE59BCDA0`；日志 SHA-256 `5822DC82C927059191DA71E4775E2E4C292670224F3ACA656E7600E7C573A613`。

## 可实施边界

原前驱候选的基础是 SDK 返回的模块连接与其传递闭包，并允许上述单列来源；普通图边添加可触发自动订阅，数据订阅和参数订阅的已核入口本身不直接创建图边。实施端允许非后继节点且自动创建数据依赖，是其自身架构策略，不能直接标为原厂完全一致。若要证明**仅**显式边构成全域 SDK predecessor，仍须追 `IMVS_GetMultiModuleConnect` native 实现与订阅处理/异步回调，并在隔离条件满足后比较订阅前后返回记录；当前先不要把未证的绝对结论写成规格。
