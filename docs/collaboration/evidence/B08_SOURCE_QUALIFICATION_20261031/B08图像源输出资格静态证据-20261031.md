# B08 图像源输出 IO 来源资格：原件有界证据

本报告只读 VM 4.4 原始 ImageSource XML 与托管反编译，未启动原 VM/SDK。它解释普通参数来源树中如何消费输出元数据；图像输入专用组合选择器、底层所有订阅校验和设备行为不自动等同该树。

## 原件声明与内存消费链

安装 `Applications/Module(sp)/x64/Collection/ImageSourceModule/ImageSourceModule.xml:45–70` 的 Output 声明 `ImageData` IMAGE 组合及 Image/Width/Height/PixelFormat，另有 `ImageDataMono8` IMAGE 组合及对应四叶。组合和各叶均声明 `IsArray=false`，叶为 `IsForce=true`；另外有 CurImagePath/CurImageName、FrameNum、LostFrameCount、LostPacketCount、GetCameraFailCount、SNCode、ModuStatus、ModuRunTime。`ModuStatus`、`CurImagePath`、`CurImageName` 的 XML 是 `CustomVisible=false`；该 XML 输出段未显式给它们 `Visible=false` 或 `CanSubscribe=false`。这里仅是**原 XML 静态内容**，不能据此推定 SDK 实际输出 extra data 完全一致。

普通 `VmModule.Init`（VmModule.cs:1753–1762）先 `InitIO`；后者在缺项时加入四个 `fArrivalTimeStampLow`、`fArrivalTimeStampHigh`、`fLeaveTimeStampLow`、`fLeaveTimeStampHigh` 输出，类型 float，`CustomVisibleA/CanSubscribeA/Visible/VisibleInResultTree=false`（3299–3323）。来源树另按上述四个**精确名字**排除，即使属性改变仍有名称过滤。时间戳不是图像源 XML 输出段中的四个声明，不应仅依赖 XML 漏项来排除。

`VmModule.Outputs`（316–333）初次访问且 `!VmSolution.IsLoading` 时先置 `outputs_IsLoaded=true`，再 `InitOutputDynamicIO`。后者查询 `ModuleManager.GetModuOutputIOInfo(ID)`；此托管方法（ModuleManager.cs:1863–1882）调用 `IMVS_GetModuOutputIOInfo(handle,id,2,...)`，将非空指针转 `IMVS_MODULE_IO_INFO_LIST`，并对错误码抛异常。`InitOutputDynamicIO` 捕获异常记日志，不在此方法体内回退 XML；已置 loaded 标志意味着这一 getter 本身不会每次自动重试。由 SDK 返回的 `IMVS_MODULE_IO_INFO_LIST` 经 `InitDynamicIO`、`AnalysisIOInfo` 建 `VmIO` 树；SDK 生产该元数据的原生装载/合并路径尚须独立核证，不可把 XML 值直写为现场 SDK 实际返回值。

## 资格字段与条件

普通 `VmIO` 字段初值（VmIO.cs:47–76,524,644）：`CustomVisibleA=true`、`Visible=true`、`VisibleInResultTree=true`、`CanSubscribeA=true`、`IsPrivate=false`。`AnalysisIOInfo`（VmModule.cs:2371–2456）先以 UTF-8 解码 name/type/extra，普通名构造 VmIO，首尾 `%` 构造 DynamicVmIO；集合已有同名直接返回，不更新已有项。额外信息按分号（无分号时按空格）拆为 key=value，`InnerAnalysisIOInfo` 对 `CanSubscribe` / `Visible` / `VisibleInResultTree` 调 `bool.Parse`，空值默认 true。叶 `nDataType=1` 除上述字段，还解析 `CustomVisible`、`IsForce`、`IsPrivate` 等，其中 IsPrivate 的空值默认 false；组合 `nDataType=2` 仅走 InnerAnalysisIOInfo，按 `nNum/pstCombInfo` 递归孩子，不在该组合分支解析 IsPrivate 或 CustomVisible。非空无效布尔字符串可能抛异常，由外层初始化捕获；该路径可能已有部分元素，不能称一定全量成功或自动修复。

`VmModuleExtern.GetOutputTreeNode`（VmModuleExtern.cs:1113–1165）的**普通参数**来源资格为 `GetAllLeafIO` 的叶，`ValueType.Contains(TypeName)` 精确匹配，且 `CanSubscribeA && Visible && !fTimeStamp.Contains(Name)`；非目标父模块还要求 `!IsPrivate`。其查询本身不检查 CustomVisibleA、VisibleInResultTree、IsForce、IsArray，也没有运行成功/最近图像是否可用的检查。父模块分支使用 Inputs 而非 Outputs，并不排除 IsPrivate；函数最外层仍先看来源 Outputs.Count。具体不同选择器不要套用此重载的过滤。若 SDK extra data 在所读实例中将普通路径/图像源 CurImagePath 的 `CustomVisible=false` 保留下来，但其他字段仍默认，则该条件下它**仍可进入** string 普通参数来源树；XML 不证明这几个运行字段的实际值或各来源前序可达。

`VmModule.IOData_Undo/Redo`（5397–5467）是已有运行变化路径：分别查询订阅、移除动态输出、`SetModuOutputIOInfo` 后用传入 info 重建并调用 Done_IOData；它证明历史操作中 SDK 结构与树可被替换，不证明 ImageSource 指定模式、图像格式或每次执行都会触发这条路径。ImageSource 相关参数、原生回调到此路径的边、动态输出合并与旧订阅重建行为尚未闭合。不要把首次 XML 与运行变更视为静态一成不变，也不要根据可能变化强行生成虚构字段。

## 迁移建议与缺口

数据模型至少保留每个 SDK 输出节点的完整 identity/name/type/父子结构、CanSubscribe、Visible、IsPrivate、CustomVisible、VisibleInResultTree、IsForce 和数组信息，按入口各自的已证谓词投影，不能用 UI 显示标志一项替代来源权限；时间戳名单独处理。动态更新时按已证操作传递刷新和失效，未确认的具体 ImageSource 触发、节点复用及跨重开行为标为未知。

尚需：ImageSource 原 XML 的解析/合并到 `IMVS_MODULE_IO_INFO_LIST.szExtraData` 的确切服务端调用及覆盖顺序、ImageSource 两 IMAGE 组合在运行实例中真实 extra 数据与结果回传；是否存在模式驱动资格变化，以及该事件到托管更新的具体边。当前缺原机实例级证据；已有用户截图与产品自测都不能替代。原 SDK 共享临时目录隔离未完成，本轮未运行。
