# B08 来源资格与前驱：统一实施决策

范围为 VM 4.4 普通参数来源树，结合 Blob、ImageSource 原资源和托管消费链；IMAGE 组合选择器、自动订阅及其他专用树须按各自入口核对。只读静态分析及既有真实样本日志；本次未运行 SDK，未修改产品。

## 先构造当前 IO，再按调用入口筛选

`VmModule.Outputs` 首次获取时，在方案非加载中先将 `outputs_IsLoaded=true`，再 `InitOutputDynamicIO → GetModuOutputIOInfo(ID) → InitDynamicIO → AnalysisIOInfo`。查询异常被记录，不能把残缺/空列表等同模块无输出，也不能假定 getter 自己自动重试。输出可经 `IOData_Undo/Redo → SetModuOutputIOInfo` 修改并重建；原 XML 是声明证据，不能无条件作为运行实例的最终清单。

SDK 返回的 `szParamName`、`szParamType`、`szExtraData` 经 UTF-8 解码，叶节点和组合按 `nDataType` 分支处理，组合递归构造父子关系，同集合已存在同名节点在该方法直接跳过。`VmIO` 初始 `CanSubscribeA=true`、`Visible=true`、`IsPrivate=false`；extra 中对应键可覆盖，空白解析按各键默认，非空非法布尔值可能抛异常。已核 `nDataType=1` 叶处理 `IsPrivate`、`CustomVisible` 等；组合分支处理基础键，包括 `CanSubscribe/Visible`，但不在该分支处理 `IsPrivate`。应保持来源、失败及覆盖次序，不将缺字段、无值和解析错误混成 false。

普通参数 `GetFrontFilterTreeOperation → VmModuleExtern.GetFrontFilterTree → GetOutputTreeNode` 以候选模块的叶 IO 为单位，要求类型集合包含 `TypeName`、`CanSubscribeA`、`Visible`，排除四个精确时间戳；非目标直接父模块还要求非 `IsPrivate`。目标直接父模块用 Inputs 且该分支不排 IsPrivate；父 Group 的 LoopIndex、变量、外部字符串和空项有独立条件。先筛叶再按实际父链组织树；不能把父组合的 Visible 简化成对所有子叶的自动继承。

`CustomVisible`、`VisibleInResultTree`、`IsForce`、`AllowAutoSubscribeByOther`、`IsArray` 与上述手工来源筛选是不同字段；所核表达式未以它们剔除叶。自动连接另有 `AutoSubscribeByOther` 等条件，不可把自动连接规则套给手动来源。模块/叶的稳定身份与本地化展示文本分开；这些适配身份不冒称 VM 的 GUID 合同。

四个时间戳 `fArrivalTimeStampLow/High`、`fLeaveTimeStampLow/High` 由 `InitIO` 在缺同名项时预置为 float，并显式关闭可见/订阅；普通来源树另按名字排除。若已有同名项，初始化跳过，不应假定所有时间戳都从这一支创建。

## 两个工具的具体证据

| 原件声明 | 已知边界 | 实施含义 |
|---|---|---|
| Blob `Area` 为 float 数组叶、`TotalArea` 为 float 叶、`CentroidPoint` 为组合 | 原 XML 声明不是 SDK 每次返回值的运行证明 | 以 SDK 当前树、类型与叶标记筛选；数组本身不由此入口排除 |
| Blob `Output Position Correction Info` 及相关组合、叶的 XML `Visible=false` | XML→SDK 返回结构的原生产与覆盖顺序尚未闭合 | 不把可见标记换成 CustomVisible；实际叶返回后按该叶 `Visible` 判定 |
| Blob `OutputMask` 各叶 `AllowAutoSubscribeByOther=false` | 该标记属于自动订阅，普通手工来源表达式不检查它 | 不仅因它为 false 就排除手动来源 |
| ImageSource `ImageData` / `ImageDataMono8` 为 IMAGE 组合；`CurImagePath`、`CurImageName` 等 XML 为 `CustomVisible=false` | 不是 `Visible=false` 的证据，SDK 返回可能覆盖 | 不把结果树显示偏好当作普通参数来源资格；IMAGE 组合入口另行按其合同处理 |

原 SDK `IMVS_GetModuOutputIOInfo@18064e220 → 180626c60 → 18066f910` 已追至请求码 `0xbd3`、动态键 `DynamicOutData` 和 `PF_M_GetBinaryData`；平台生产/解析 XML 的具体分支及运行时覆盖尚未闭合。已核导出在转发前覆盖 R8，目标函数不读取入口 R8，不能仅凭托管端传入的 `nDataType` 声称 native 依此值分流。完整 ABI 和哈希见 Blob 分册。

## 前驱与两类边

`VmModule.GetPreModules` 直接返回 `PreModules`；`LoadNextAndPreModules` 依据 SDK `GetMultiModuleConnect` 返回的连接表填充后继及前驱。`GetFrontParamItems` 再递归去重并附非 Solution 父模块。画布 `AddConnection → NextModules.Add → ConnectOneModule` 建控制连接，并在 `isAutoLink` 条件下另外尝试自动数据订阅。

已核 `VmIO.RelateIO → SubscribeResult` 与普通参数 `SetModuleParamBinding` 方法体不直接调用 `NextModules.Add/ConnectOneModule`。已有真实样本中图像订阅与 `ConnectModule` 是可分开发生的操作；这不证明 SDK 原生层或回调永不创建隐式调度关系，也不证明 SDK 连接表全由鼠标画线构成。删除控制边时原版存在按剩余前驱、父节点、常量、变量等例外清除 IO 订阅的条件，不等于无条件保留或删除全部订阅。

迁移时将**来源候选资格、显式控制边、数据/参数订阅与运行调度依赖**分别建模。主仓允许非后继节点并自动建立数据依赖属于其自身策略；在原生连接表及调度回调未闭合前，标为独立适配，不称原版全域等价。需要原机验证时，先确保共享 ImageSourceTempPath 历史清理隔离，再在同一方案记录订阅前后 `GetMultiModuleConnect` 与实际调度；本次不启动 SDK。
