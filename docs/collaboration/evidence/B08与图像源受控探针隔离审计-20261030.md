## 当前观察与缺口

`Get-Process` 的当前可见名字未包含 `VisionMaster` / `VisionEditor`，可见 `MVDLogServer`、`MvLogServer` 等；部分进程 `Path` 不可读。`Get-CimInstance Win32_Process` 返回拒绝访问；`netstat` 对 `:5556` 没有输出。上述仅为当前受限视图的快照，不能证明其他会话无相关 VM 实例或无共享服务，也不能识别全部组件的所有者。

阻止立即运行的是具体未证链：`IMVS_PF_CreateHandle` 默认空路径是否建立或复用共享服务、`IMVS_StartGlobalScript` 的启动/复用/关闭归属、`Dispose` 的销毁范围、服务端方案与临时文件的实际根目录，以及隔离进程能否在无需用户现有许可或服务的情况下读取图像路径/参数值。这些不是证明它必定会干扰；是不能据现有证据排除干扰。这里并不要求默认复制整套安装，是否可直接只读引用安装 DLL 须在上述边界查明后决定。

## 最小可执行路线

1. 只读追 `IMVS_PF_CreateHandle`、`IMVS_StartGlobalScript`、`Dispose/DestroyHandle` 到服务和路径判定，确认能否给本任务专用实例使用受控地址及进程所有权。
2. 新建本任务专用 app base、`.config`、方案副本、图像样本、日志和输出；启动前记录这些真实绝对路径及摘要，确保构造器清理只落在该基目录。原安装 DLL 若按只读路径使用，其资源、授权、日志和服务作用域仍需单独核实。
3. B08 使用不同标记的原字面值、绑定源值、最后执行值，记录解绑前后、错误/取消、索引及保存重开的回读；图像源使用可区分文件 A/B/C 和慢步骤，记录选择、请求返回、执行计数、发布及回写的时序。须使用真实消费者，不能用自行模拟值替代。

在步骤 1 的作用域或许可无法独立确认时，不启动目标，集中报告不能证实的具体入口；只在确需人工配合时申请一个空闲、可识别且独占的 VM 实例及其方案路径，不要求结束或接管现有用户程序。未取得实测结果前，不对解绑值或快速切换调度下结论。

## 避免显式启动脚本的最小候选

可以设计独立进程，直接使用 `analysis/decompiled/iMVS-6000PlatformSDKCS.PublicAudit/iMVS_6000PlatformSDKCS/ImvsPlatformSDK_API.cs:105–120` 中公开的 `IMVS_PF_CreateHandle_CS` 和相应原生函数，不加载依赖 `VM.PlatformSDKCS.CVmObjectBase` 的 VM.Core 托管宿主，也不调用 `IMVS_StartGlobalScript`；测试方案、图像和输出使用新建的独立目录，退出只调用该进程自己的 `IMVS_PF_DestroyHandle`。这是**候选实验设计，尚未运行或验证是否足以实现所需 UI/参数回读**，并非建议规避许可。

原 PF 创建自身的 `180630c20 → 18063dbf0` 经 `socket(AF_INET, SOCK_STREAM)`、`bind` 端口 0、`getsockname` 取得系统选择的端口并关闭 socket；`1806165e0` 再将 `127.0.0.1` 和返回端口传给 `180662b90`。这支持它没有直接沿用原主程序配置中的固定 5556，但 socket 被关闭后才再次使用端口，存在竞争窗口；运行时后续究竟成功绑定哪个对象还未证。`18063dbf0` 汇编 SHA-256 `6614159723C84936584F5BF8FDC4D8EA130E208C740F11080B1B5F60F19B61A0`。

## GS_M_Init 的具体副作用与当前注册

原 `Applications/GlobalScript/GlobalScript.dll` SHA-256 `4E25BDBD550CC1901C90612E22F309BB67119755494C2DEE8A741381666E6F05`。离线汇编 `GS_M_Init`（`180001a10`）调用 `180007fe0`，该函数先 `CLSIDFromProgID("GScriptComponent.GScriptCom")` 并 `CoCreateInstance`；失败分支构造 `cmd.exe /c ... Framework64/v4.0.30319/Regasm ... GScriptComponent.dll /tlb ...`，调用 `ShellExecuteExW` 后 `WaitForSingleObject`，再尝试 COM 激活。故激活失败时存在执行注册工具、修改 COM 注册和等待外部进程的真实静态路径，不是可以靠捕获普通错误码完全避免的假设风险。对应汇编 SHA-256 分别为 `21C8F9923EF9F5E85F3C71AD717B9B97009545C5948C0F918B96DD9510FD2872`、`514BC611EAA470C335596CA080EC5E899CDC992E560176799C12D9C86C3F1B16`。

只读查询 64 位 `HKCR/GScriptComponent.GScriptCom/CLSID` 得到 `{3FF87FA1-4D8A-4A2B-ACCE-7D49422EFEA5}`；`InprocServer32` 的 `CodeBase` 指向原安装 `Applications/GlobalScript/GScriptComponent.DLL`。注册项存在不保证 COM 激活成功，也不证明 fallback 不会发生。没有调用 COM、Regasm 或修改注册表。

成功激活时原托管源码 `GScriptCom.Init → GlobalScript.Init(DLL) → GlobalManager.StartByDll` 创建管理器并启用一次性五秒定时器；若 `bNeedLoadDefaultScript` 未在时限内被清除，定时器调用 `LoadDefaultSolution → initSourceAndStartScript → readDefaultScript`，随后可能编译和更新备份。DLL 模式 `UserGlobalScriptManger.AppBaseDirectory` 来自其执行程序集目录而非探针 exe 目录；只读盘点发现原安装 `Applications/GlobalScript/VM.GlobalScript.Support.dll` 同目录存在 `GlobalScript.txt`（2944 字节）。因此独立 exe 基目录不能阻止在该路径读取或处理默认脚本；不能把五秒内发送自己的 LoadSolution 当可靠隔离，亦不凭此声称用户脚本一定被执行。源码 SHA-256：`GScriptCom` `E04C69FA6BB9FD105DEE87929188D19E266D4F7CD5068AA1E6B51FF9C0557E11`，`GlobalScript` `A8BA36CAA09DD2B9D87EF42FB387B7F442564E89CA0BF279586604620D218C91`，`GlobalManager` `0ABDBECC0F1A3BBFAF1E4FD01679C330C279FD7A5E0EACC8B4A1E3EB9DAAB183`。

当前实际阻碍因而具体为：原已注册 COM 路径指向原安装脚本支持程序集和现存默认脚本，且注册失败 fallback 会启动 Regasm；不能保证“原安装只读、不启动或处理用户脚本、无全局注册变化”。继续推进需要受控的 COM 激活路径或经原代码证明的无副作用抑制机制；如果必须采用独立 COM 注册，需先确定对现有用户与其他任务无影响及授权范围，不能擅自覆盖机器注册。无证据支持直接原安装 PF 探针可满足这些条件。
