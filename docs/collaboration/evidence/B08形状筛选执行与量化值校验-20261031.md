# B08 形状四参数：执行入口及量化值校验

本次只追已定位调用与四项跳表，不运行原 VM/SDK。结论限 `MinCircularity`、`MaxCircularity`、`MinRectangularity`、`MaxRectangularity`，且依赖实际创建的目标对象与静态核对的类型 `0x12d` 句柄一致。

## 运行入口与参数消费

原 Blob 模块 `ProcessAlg@0x18001fec0` 调算法实例 vtable `+0x78`；`MVDBlobFindCpp.dll` 已核对象表 `0x180009c08+0x78` 的静态值是 `0x180003540`。该函数组装输入后调用 `MVD_Algorithm_Process(handle,0x12d,...)`。原 `MVD_Algorithm_Process@0x1800152b0` 在句柄和全局状态满足时转入句柄 vtable `+0x18`；已核 Blob 句柄表 `0x181eb6598+0x18=0x18003f940`。该函数先调用 `0x180007120` 处理有变更标志的名称记录，再在 `0x12d` 分支调用 `0x1800414f0`，后者调用 `0x1805fd2c0(...,0x32,...)`。这是明确的执行链，静态可达不等于某次真实调用已发生。

`0x180007120` 遍历待更新项，并将记录的 8 字节对交给回调；此路径的候选回调 `0x1805fccd0` 用记录编号进入跳表。按原 PE 读取 `0x18160a4e4 + (编号-0x20001)*2`，目标为 `0x180600d19 + 表项`，四项分别落到：

| 参数 / 编号 | 跳表项 | 目标 | 失败码 |
|---|---|---|---|
| MinCircularity / `0x20618` | `0x18160b112` = `0x084d` | `0x180601566` | `0x1010111b` |
| MaxCircularity / `0x20619` | `0x18160b114` = `0x083e` | `0x180601557` | `0x1010111c` |
| MinRectangularity / `0x2061b` | `0x18160b118` = `0x0820` | `0x180601539` | `0x1010111e` |
| MaxRectangularity / `0x2061c` | `0x18160b11a` = `0x0811` | `0x18060152a` | `0x1010111f` |

四个目标指令均对 ECX 执行 `CMP ECX,0x64; JBE 0x18060289a`，后者返回 0；不满足时各返回上表错误码。`JBE` 是无符号比较，因而这个**量化整数参数校验**接受 0–100（含端点），不等于 Blob 特征值最终的上下限比较。前面文本/float 到整数的 `0.01` 缩放及 `±0.5` 指令边界见 [量化报告](B08形状四项量化与消费边界-20261031.md)。

## 尚未闭合

`0x1800414f0 → 0x1805fd2c0` 是已识别的具体运行入口；本轮只读取该目标尝试因 Ghidra 大函数处理超过两分钟且无产出，已停止本次自有离线分析进程，保留现有证据，没有停止其他任务。尚未取得此目标内的实际 Blob 特征比较指令。因此当前条件下**最终比较单位、是否含上下限、特征值的舍入均无法确认**；不能把参数 0–100 校验写成最终筛选规则。该目标仍是具体可追入口，并非断言整个二进制不可逆向。若业务需先推进，应将比较规则封装在可替换的自研筛选适配器中并明确标记假设。
