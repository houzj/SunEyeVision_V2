## 决策影响和下一最小取证

### 新补：整数绑定成功与失败实际调用链

用户提供的原机日志提到 `CModuleParamBindingHandler::GetBindingInt(LowThreshold,0)` 返回 `0xe0000314`；日志由技术总监转述，此文件没有读取原始日志或声称其现场条件。针对同 SHA 原 `ModuleFrame.dll` 的离线指令，在正常对象、已登记绑定路径追到：

1. `1800ffd00:18010004d–65` 传模块 ID 调 `1800b98c0`（现有反编译日志字符串为 `CModuleParamBindingHandler::ProcessModuleParamBindings`）；仅 EAX=0 才调用任务对象 vtable `+8`；非零跳至 `18010006e` 错误处理，跳过该次任务 vtable `+8`。不能未经对象身份证明直接将任务虚方法等同 Blob Process。
2. `1800b98c0` 按模块查绑定记录并逐项 `1800b9c70`；该项失败时停止该列表并返回错误，已先成功的其他项没有由这段代码证明回滚。
3. `1800b9c70` 类型为 1 的分支调 `1800ba0e0`。原 `1800ba0e0:1800ba139–1cb` 调 `1800bb4d0`（GetBindingInt 分支）并测试 EAX；非零时直接返回错误，**没有进入此项后续 `1800bc680` 写路径**。这不证明其他线程或之前的执行没有写入缓存。
4. 读取成功时原 `1800ba34c–355` 把该整数、目标参数名和模块 ID 传 `1800bc680`，后者格式化文本传 `1800bc8a0`，`1800bc8a0:1800bc909–91c` 将长度、值、名称和模块 ID 交 `180043120`。该函数 `1800433ca–435` 在找到普通模块及 `+0x128` 工具对象非空分支调用其 vtable `+0x18`；与 Blob 实例的 SetParam 及算法 setter 桥接见 [Blob 具体对象](B08-Blob低阈值原生参数对象追踪-20261030.md)。因此**成功读取且命中该 Blob 实例的正常分支会尝试写低阈值参数**；setter 仍可能返回错误，不能保证一定修改成功。
5. `1800bb4d0` 的来源类型为 3 时调用 `1800ca500` 读取；后者原 `1800ca54b–569` 在外层按 `param_2` 键查找未命中时返回 `0xe0000314`。该函数还有其他调用者/路径，日志中的具体来源 ID 及是否命中这个返回点仍需现场参数或调用链确认；不可仅从错误码断言是哪个来源项缺失。`0xe0000314` 不是这里已证明的名称叶不存在；不同失败代码和其他来源类型不应混合。
