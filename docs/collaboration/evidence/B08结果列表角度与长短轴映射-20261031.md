# B08 Result List：角度和长短轴映射

只读 VM 4.4 原资源、托管反编译、原 Blob 模块及 SDK 头文件；未运行原 VM/SDK。结论针对默认 Display 配置和已核正常输出路径，动态修改、同名冲突和原机显示仍需分别核验。

## Result List 到输出名

原 `IMVSBlobFindModuDisplay.xml` 的 `Result List` 的 `Colume.Value` 为 `Area,Perimeter,CentroidX,CentroidY,Angle,LongAxis,ShortAxis,Circularity,Rectangularity`。`FeatureBase.Init` 将 Colume 的 Value 按逗号分为 `ValueArray` 并标记 `IsColumeMappingFlag`；`FeatureBase.GetValue` 对每个列名调用 `GetMapIO(name).GetValue(executeCount,index)`；`Feature.GetOutputFilter` 进入 `VmModule.GetIO(name)`，其优先查输出，`VmIOCollection.GetIO` 通过名称缓存或递归查找。`ModuleResultView.RefreshDataListResult` 以相同列序将 `DataList.Colume` 显示。故在默认配置、无同名覆盖且相应 IO 可获取时，Angle/LongAxis/ShortAxis 列分别取同名输出，不是按显示标题猜测。

原 `IMVSBlobFindModu.xml` 中唯一精确名 `Angle` 是 `MinBoudingRect → Angle` 叶；另有独立顶层 `BlobAngle`，以及顶层 `LongAxis`、`ShortAxis`，四者均 float 输出。故默认 Result List 的 **Angle 是外接矩形 Angle，不是 BlobAngle**。原 `IMVSBlobFindModuCs.xml` 将 BlobAngle 描述为“主轴角度”；不要将其与列表 Angle 自动混同。

## 原生结果如何供值

`Process@0x18001fa80` 调 `ProcessOutput@0x180020310`。已取反编译中每个 Blob 的 `Angle` 由结果对象取得 box 对象（vtable `+0x60`），再调用 box vtable `+0xd0` 取四字节值，输出名 `Angle`；`BlobAngle` 则直接调用 Blob 项 vtable `+0x40` 取值。`LongAxis`、`ShortAxis` 分别调用 Blob 项 vtable `+0x38`、`+0x30`，按数组索引复制四字节值；这段复制没有显示除 2 或乘 2。`BlobFindCpp.h` 的 `IBlobInfo` 接口分别声明 `GetBoxInfo`（最小面积外接矩形）、`GetAngle`、`GetLongAxis`、`GetShortAxis`；长短轴描述为最小外接矩形的长轴和短轴。虚表位移和该接口的对应需以同版本实例对象为前提，不代表实机已测。

`IMvdRectangleF` 头文件描述矩形角度范围 `(-180,180]`，顺时针为正、逆时针为负；这是矩形接口合同。头文件相关注释未明确写出角度单位，且尚未核实所有结果对象的坐标轴、归一化和实际显示，故此处不把单位或每种退化形状的角度写成已验证事实。若运行实例确按该矩形接口供值，上述方向/范围是原接口声明，不等于已完成原机差分。

**长短轴半长还是全长仍未确认。** 头文件只写“最小外接矩形长轴/短轴”，没有明确半长或全长；模块复制链没有额外倍乘也不能证明 getter 内部定义。应在可替换的结果转换处保留明确假设，而不是将外接框宽高、椭圆半轴或 HALCON 算子结果直接冒充原值。
