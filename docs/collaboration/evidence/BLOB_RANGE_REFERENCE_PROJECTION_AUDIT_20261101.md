## 已证差异

- 原VM的 between 滑块比较其当前 StartValue/EndValue；这两项绑定各端模型 CurValueA。夹值函数不主动查询订阅源；何时回读及本次夹值所见模型值尚未完全确定。见 D:/MyWork/REA逆向测试/docs/joint-audit/B08双端订阅夹值回读时机补证-20261101.md。
- 本方 NativeRangePresenter.cs:340 接纳常量时将订阅对端视为null，ValidateEndpointBinding:282–287只对常量对端设置边界。NativeNumericCommit.cs:216–220 在订阅模式不投影宿主当前值到 StartValue/EndValue；DeclaredFieldState.cs:21–33 的宿主当前值读取主要用于切回常量。因此即使已有运行回读，隐藏端也不保证随之更新。
- 移植控件 SliderArrangeBase.cs:1058 起仍有 Dispatcher 延迟跨端比较，:1211–1244 失焦/箭头也比较隐藏端数值；接纳校验与控件夹值可能使用不同边界。延迟夹值与正式变化通知路径要分开判断。DeclaredFieldState.cs:162 的接纳只安装提案字段，本端编辑不会直接把对端引用改成常量。

## 结论及影响

这是已识别的静态投影与校验策略差异，不是已复现的参数写错、订阅覆盖或VM最终数值行为。当前取证条件下无法确认原订阅值何时回读；本方运行解析与非法范围保护暂按现实现明确作为宿主适配，不冒称VM等价。影响范围为左右端单独或同时订阅时的输入、箭头、滑条、失焦及后续执行；现有已接纳字段及引用身份必须保留。可替换位置为订阅结果到参数模型的回读/通知适配及NativeRangePresenter投影，不能仅把对端null改掉即宣称完成。

后续定向验证：整数面积[100,200]上限订阅待选、解析50、解析500；下限输入300分别经过失焦、箭头、Dispatcher及捕获，记录可见值、提案、正式值、引用身份和切回常量。左右镜像、两组浮点及禁用/恢复时排队动作同批覆盖；必要时向既有逆向负责人追原宿主或使用受控原机。原厂行为未证不代签，本方现行值来自同版正式来源的规则保留。
