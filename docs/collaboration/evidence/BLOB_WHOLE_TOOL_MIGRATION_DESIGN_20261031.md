## 统一实施设计

1. 以原96资源条目、8共享组及全部输入/输出节点为原始索引，建立三页字段—条件—引用—正式配置—冻结值—算法消费—输出/显示的一对一或明确组合映射；每行标明证据、实际现状、复用/修改/替换、未实现及验证出口。原结构与显示不需要复制厂商目录或命名空间。
2. 以单一正式Blob设置/输入/输出和宿主事务为主线，集中处理参数、可见性、默认、范围、引用解析、执行前校验、快照、复制历史与保存重开；移除与正式字段重复的临时状态。原件与现有行为冲突时以证据及用户明确扩展为准，不保留双轨。
3. 在同一批确定输入帧、区域/屏蔽/位姿、各阈值模式、孔洞、连通、筛选、排序/限数、判定、输出图像/特征及资源释放的完整调用链；已证事实与本方假设在策略边界标识，未知条件下不可误用，不将SDK样例顺序写成已证VM内核顺序。
4. 正式页面、来源树、结果表、图文层和工作流/调试消费者均使用同次冻结配置和同次结果身份；资源reader及晚到事件必须可退役。缺其他基础的功能保留具体未实现语义、影响、依赖及替换位置，不为本批扩建其他基础，不让占位输出被引用或误用。
5. 逆向负责人集中补可追缺口。已有原生Process、ProcessAlg、MVD算法入口和ProcessOutput定位；大函数内部阈值/填孔/排序、输出图像Domain及结果内存所有权未闭合。依用户授权之外不得启动原机；需要隔离的原机样本及副作用单列，拿不到证据时保留明确假设与保护。
