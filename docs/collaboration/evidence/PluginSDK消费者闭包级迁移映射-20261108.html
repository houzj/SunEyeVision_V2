Plugin.SDK 消费者闭包级迁移映射

基线：feature/param-window-datatree，最近产品提交 75f422886。本报告只描述正式源码现状和迁移目标，不把历史 SDK 源码恢复为兼容层。

当前事实：正式扫描确认 20 个工具项目仍有 src/Plugin.SDK/SunEyeVision.Plugin.SDK.csproj 项目引用。src/UI 和 src/Plugin.Editing.Wpf 没有旧 SDK 项目引用，但保留少量旧命名空间级历史消费。ImageSource 和 BlobAnalysis 不在这 20 个项目中，已作为新合同基线。

闭包级替换规则

旧类型或资源替换决策验收出口
ToolDebugControlBase、旧命令、旧回调删除旧窗口继承链，使用 RuntimeToolEditorWindow + RuntimeNodeConfigurationControl + 工具 IToolSettingsView。首次打开、当前页就绪、Tab 复用、换节点、回执、关闭、退订、迟到回调拒收。
ToolParameters、ConfigSetting、ParamBinding改为声明式 ToolSchema、FieldSettings、ParameterPresentationTree 和引用字段会话。保留正确业务字段，不保留旧对象双轨。常量/引用切换、候选源、未解析文本保留、保存重开、撤销重做和执行快照。
RoiShape、MeasureGuideParameters先映射完整几何/资源/坐标/释放闭包，再接 Plugin.Wpf.Presenters.Regions 和测量模板槽。不能把旧模型改名后继续消费。ROI 创建、引用、位置修正、图像域、结果图形和关闭释放。
ToolResults、DisplayCollector、ResultPresentationConfig运行结果迁到新 Output/Publication/Reader 合同，显示通过 Plugin.Editing.Wpf 结果模型和 Plugin.Wpf.Presenters.Results 绑定。资源必须由结果 Owner 管理。结果发布、显示配置保存重开、reader 租约、结果失效、取消和关闭。
LabeledControl、旧主题和旧程序集 URI不恢复兼容入口。已有新控件闭包直接迁入 Plugin.Wpf，缺口记录为阻塞项。源码、XAML、资源键、程序集身份和发布依赖清零。

实施顺序与删除门槛

  1. 当前 ImageSource→Blob 基线保持冻结，作为统一窗口、参数、结果和 Owner 合同。
  2. 先补 ImageFilter、ImageThreshold、Morphology 的 Runtime/WPF 闭包设计，再选择一个工具贯通完整生产链。
  3. 通信、测量、控制流/脚本、标定/匹配按组迁移，每组完成后固定提交和回归。
  4. 每个项目的 ProjectReference、XAML 命名空间、资源 URI、旧基类和旧测试引用全部清零后，才从门禁清单移除。
  5. 全部 20 个正式消费者清零后，才删除旧 SDK 目录和旧发布程序集。

本报告不表示任何旧工具已经迁移。它把下一批需要实施的代码闭包、目标位置、阻塞证据和验收出口固定下来，避免以命名空间替换或单个控件通过冒充完整重构。
