VM 与 CodeBuddy 重构计划对齐审计

审计日期：2026-11-09　范围：启动→方案管理器→方案加载→工具参数窗口→Tab→执行回调→换节点关闭　当前产品：ImageSource、BlobAnalysis

一、审计结论

采用方向：VM 的参数窗口确实是“参数模型树 + WPF DataTemplate/ParamUserControl + 统一 Tab/分组宿主”。CodeBuddy 提出的数据树、模板注册和 Tab 选择复用方向可以作为目标。

拒绝的过度结论：不能仅凭反编译静态结构断定 VM 的动态性能预算，也不能因为本方存在命令式行装配就直接删除 DeclaredFieldsView。Blob 的 ROI、运行参数、结果显示和外部锚点是独立的重型组合，必须先纳入模板槽和所有权合同，再替换旧生成层；否则会把正确的 VM 控件和完整生命周期一起删掉。

当前落地：ImageSource 与 BlobAnalysis 已接入统一参数树、模板槽和生命周期。ImageSource 单页直接完成；Blob 首选页在隐藏状态完成后窗口才显示，其余页按 VM 证据支持的同一数据树/模板注册链在首帧后的空闲阶段逐页预热并缓存，Tab 只在未预热时承担该页的唯一首次物化，重复切换不重建。窗口等待 IToolSettingsViewReady 后显示，换节点沿租约、代次、退订、迟到回调拒收和 Dispose 释放。正式准入探针 722ms，其中组件加载 264ms。

三、CodeBuddy 候选方案与立即调整

CodeBuddy 结论证据判断立即调整
“命令式装配是性能根因，模板化可以直接消除卡顿”方向合理，因果过度。WPF DataTemplate 仍会实例化视觉树；现有 Blob 专用组合也不是普通字段行。先保留当前生产链，建立模板注册表/字段树契约和实例计数；完成 ImageSource/Blob 等价快照后，再按段替换生成层。
立即新增 DeclaredFieldTree、DeclaredTemplateFieldsView，删除 DeclaredFieldsView目标形态正确，但直接删除会断开 ROI、范围对、引用、显示组合、结果页和资源释放。把现有 ParameterPresentationTree 作为唯一数据树入口；模板注册表先承接字段编辑器和重型组合，旧宿主只在迁移段保留，禁止建立第二套参数模型。
Tab 切换只改 SelectedIndex，完全零构建VM 静态处理器未见主动重建，但不能证明所有视觉树在打开时已经生成。当前 ImageSource 单页直接完成；Blob 先完成选中页，其他页在首帧后的空闲阶段沿同一模板链预热并由 _builtPages 缓存。未预热页首次点击仍会有一次真实物化成本，已在探针中单独记录；重复 Tab 只选择已缓存页。该策略是当前对 VM 静态证据最保守的落地，不宣称 VM 动态等效。
把所有隐藏页放到后台/Idle 预热即可对齐 VM没有 VM 动态证据支持；此前本方实测会造成窗口跳变或首切卡顿。Idle 只用于首选页已就绪后的后续页预热，不承担窗口首显；首选页和所有点击中的页都有显式同步完成/错误门禁，已建页通过缓存复用。后续仍需用 VM 同场景动态证据决定是否进一步改为全量模板预建。
旧 Plugin.SDK 应立即删除活动方案消费者为 0、目录条目为 0；历史 20 个旧工具源仍保留在历史层。当前产品可以继续不引用旧 SDK；历史工具按 VM 重建后逐批迁移，不能把历史源文件删除冒充迁移完成。

四、下一批代码切换点（一次成片实施）

  1. 数据合同：扩展 ParameterPresentationTree 成为页、分组、字段、高级状态、显隐条件和字段身份的唯一只读树；补充字段覆盖与配对拓扑契约测试。
  2. 模板注册：在 Plugin.Wpf 建立按字段编辑类型、VM Native 控件类型和重型槽分类的模板注册表。普通字段模板直接复用逆向控件；ROI、范围对、图形/文本显示、运行/结果组合只作为显式槽，不复制 Blob 业务。
  3. 宿主替换：将 DeclaredSettingsView 的页选择和外部槽接缝切换到树/模板宿主，先覆盖 ImageSource，再覆盖 Blob；切换前固定字段 ID、结果 reader、回调和资源 Owner。
  4. 旧链退役：模板宿主的字段覆盖、保存重开、显隐联动、换节点关闭和迟到回调拒收通过后，才删除对应的 _pageBuilders/_positions/_visibility 分支；不留双轨实现。
  5. 统一验收：使用正式 Release 记录启动准入、方案管理器可操作、方案遮罩、节点窗口可见、首次/重复 Tab、换节点、关闭和资源释放。VM 动态时间若未取得，单独标记，不用本方读数代替。

五、当前未确认项

  • VM 同版本首次打开、重复 Tab、跨节点切换的 UI 线程动态时间线。
  • VM 是否在同节点复用视觉树/模型，及其缓存边界。
  • VM 动态资源合并、模板实例化和结果 reader 的确切释放顺序。
  • VM 真实外部 SDK 发布包、模板、发布目录和外部工程接入方式。

本审计不把静态逆向推断写成动态事实；代码切换以现有两工具生产链为单一基线，完成一个完整宿主后再推广历史工具。
