二、VM 外部应用完整链路（可迁移的静态事实）
----------------------------------------------

外部应用启动
→ 引用 VM.Core + VM.PlatformSDKCS + 所需 VMControls 视图程序集
→ VmSolution.Load(solutionPath, password)
→ VmSolution.Instance 建立方案身份
→ 按名称取得 VmProcedure / Module / Group
→ 将 VmMainViewConfigControl、VmFrontendControl 或 VmRenderControl 嵌入宿主
→ 需要结果时启用模块/流程回调并 Run
→ 从 ModuResult/Procedure 读取图像、参数和结果
→ 退订回调、DisableModulesCallback、解除 ModuleSource/视图绑定
→ CloseSolution / DestroyGroup / Dispose

这条链与当前 SunEyeVision 的对应关系：
- VmSolution.Load/CloseSolution ↔ DocumentSessionManager 的打开、提交、关闭会话。
- VmProcedure.Run ↔ Execution 的流程运行接口；输入必须是快照。
- ModuleResultCallBackArrived ↔ 当前 ToolSession/ResultReceipt 回调；必须有代次和退订门禁。
- VmRenderControl.ModuleSource ↔ 当前结果显示源与 ResultResourceOwner；关闭时先解除显示源再释放 reader/图像资源。
- VM 外部 SDK 的能力应通过独立 Platform SDK 门面暴露，不把 UI、Application、Persistence 内部类型直接暴露给外部工程。

三、对当前 PluginDevKit 的纠偏
------------------------------

PluginDevKit 当前只覆盖“工具作者/插件作者”方向：Contracts、Runtime、Wpf、RuntimePlugin.Template、WpfTool.Template。它不能宣称等同 VM.PlatformSDKCS，也不能以模板构建通过代替 VM 外部应用 SDK 证据。

最终应拆成两个公开发布边界：
1. SunEyeVision.PlatformSdk：外部软件控制方案、流程、节点、模块结果、回调、前端/渲染宿主的稳定门面；内部通过 Application/Execution/Persistence 适配，不公开内部实现类型。
2. SunEyeVision.ToolSdk：工具作者使用的 Runtime/Wpf/控件模板与算法适配合同；仅在 VM MVDAlgorithmSDK 对应的模板、资源和程序集闭包完成迁移后扩展。

四、当前代码落地顺序
----------------------

已落地：
- 默认启动顺序：快速启动阶段→方案管理器可操作→选择方案→主工作区轻量壳与加载遮罩→发布准入→方案会话→节点窗口隐藏组装→首个参数页就绪→Tab 复用→关闭释放。
- ImageSource 与 BlobAnalysis 已脱离旧 Plugin.SDK，Runtime/Wpf 单链和重复 Tab 复用已通过正式 Release 生产探针。
- 其它旧工具不进入当前发布扫描、预加载、工具箱或启动准入。

立即按本证据执行：
- 保持现有 ToolSdk 单链，不再添加第二套参数编辑器或旧 UI 兼容桥。
- 新增 PlatformSdk 只做外部应用门面和样例验收合同；不把 VM 具体程序集名称复制进 SunEyeVision 产品程序集。
- PlatformSdk 先覆盖 Open/Close solution、流程 Run/Stop、模块结果订阅/退订、渲染源绑定/解除和资源释放；保存、Group、连续运行和设备控制在同一门面逐项接入。
- 发布目录分为 sdk/platform/net9.0 与 sdk/tool/net9.0；每个目录配 manifest、依赖清单、模板和外部工程验收脚本。
- 在真实 VS 外部启动/附加验收完成前，SDK 只记为“静态边界已确认、外部工程未闭口”。

结论
----
VM 的“外部软件二次开发 SDK”和“算子/工具作者 SDK”是两条不同产品线。当前重构不能把 PluginDevKit 继续作为唯一 SDK 结论；产品主线应先保持两工具的 VM 参数/窗口/生命周期单链，再将外部 PlatformSdk 门面按上述静态事实接入。
