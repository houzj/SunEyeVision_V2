1.5 崩溃报告格式逐字段 观察到

文件名：<进程名>-<yyyyMMdd>-<HHmmss>-<4位序号>.txt（例：VisionMaster.exe-20260520-104419-0446.txt）。
内容结构（前 12 行原文）：

ModuleProxy 2025-03-31 15:09:51 PlatformManager 2025-04-23 19:47:22 clr 2025-03-20 07:09:23 iMVS-6000PlatformSDK 2025-04-29 13:55:54 ExceptionCode : STACK_OVERFLOW CallStack: Frame 0: ModuleProxy.dll! VM_PROXY_SetSDKCallBack Frame 1: ModuleProxy.dll! VM_PROXY_SetSDKCallBack ...
区段含义价值
头部 4 行 模块名\t\t\t时间崩溃瞬间各模块的编译/加载时间戳（不是发生时间）可直接判断"用户是否混用了不同版本的 DLL"（时间戳不一致即为混装）
ExceptionCode :异常类别（本机实例为 STACK_OVERFLOW）栈溢出 ≠ 空引用，定位方向完全不同
CallStack: + Frame N: dll! 符号纯文本调用栈，无需 pdb 与调试器运维/现场可直接回传；这是最有价值的差异点
对本方的直接借鉴：我方现有日志体系（LogInfo/LogError + 文件）覆盖"运行期事件"，但没有"崩溃时落一份可读文本栈"的机制。 建议：AppDomain.CurrentDomain.UnhandledException + Dispatcher.UnhandledException + TaskScheduler.UnobservedTaskException 三处统一写一份 <exe>-yyyyMMdd-HHmmss-####.txt（含程序集版本表 + 异常类型 + Exception.StackTrace 文本）。不需要生成 .dmp。

1.6 自动加载方案的四个字段 观察到

<?xml version="1.0" encoding="UTF-8" standalone="yes" ?> <Root> <AutoLoadSolutionInfo> <Solution IsAutoLoad="0" Path="" Password="" SoluExecuteState="1" /> </AutoLoadSolutionInfo> </Root>
字段本机值含义为什么值得学
IsAutoLoad0启动是否自动加载方案开关与路径分离，关掉不必清空路径
Path空方案文件路径可为空 = 未配置
Password空方案密码关键：原厂方案可带密码，自动加载必须能提供。我方方案格式若无密码概念，则"开机自动运行"场景无法对齐
SoluExecuteState1加载后是否直接执行把"加载"与"运行"分开配置 —— 这正是我方 AGENTS.md 里"运行/停止不进撤销历史、加载 ≠ 执行"的同一思想
