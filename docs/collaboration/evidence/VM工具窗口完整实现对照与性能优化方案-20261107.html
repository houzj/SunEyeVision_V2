当前可成立的性能根因假设

  1. 参数模型、Group、模板和控件树被重复构造或重复绑定。
  2. Tab 切换重建视图，而 VM 可能只切换已装配的视图状态。
  3. 资源字典、DataTemplate 或 XML 默认值在每次打开/切换重复解析。
  4. 动态显隐和外部槽更新触发整棵控件树刷新。
  5. 执行结果、图像或设备状态被同步查询到 UI 线程。
  6. 关闭退订不完整造成旧回调、旧 reader 或旧视图继续参与新节点。

以上均为待测假设，不能标为 VM 已确认机制。

优化方案与验收顺序

  1. 先建立同版本 VM 与当前实现的事件时间线、UI 线程耗时、视图/模型实例数、模板解析次数和资源加载次数。
  2. 把参数模型、视图装配、执行会话和结果显示拆成可观测阶段，确认每阶段是否重复执行。
  3. 按 VM 证据决定同节点 Tab 的复用边界；没有证据前不新增缓存或虚拟化。
  4. 按 VM 证据决定跨节点关闭顺序，保证退订、迟到回调、reader 和图像资源有明确 Owner。
  5. 完成首次打开、同节点 Tab、跨节点、返回原节点、关闭释放五个场景的 VM/当前对照后，再冻结 Plugin.Wpf 和工具 Wpf 结构。

未确认项

同节点复用、跨节点销毁、Loaded/DataContext/BottomCommands 运行时顺序、首帧耗时、UI 线程阻塞、缓存/异步/虚拟化机制、VM 运行时主题切换入口。

按 VM 行为的迁移决策

入口/宿主迁移组装职责并重构宿主接缝；AlgorithmTabRoot/GroupLinkItem/模板/资源职责直接迁移；绑定显隐保留父链和触发器；Tab复用与跨节点销毁先取VM实例运行证据；执行层不访问WPF；关闭按退订→等待在飞→释放reader/视图/资源顺序实现。VM同节点复用、跨节点销毁、Loaded/绑定回调、执行回调、reader最后释放及缓存/异步/虚拟化仍未有同版本运行证据，当前不得写成已确认。可回填框架总览：VM静态链为入口→呈现工厂/设置视图→ModuleParam/AlgorithmTabRoot→ParamsConfigControlBase→ParamsTabUserControl→ParamListView/ParamUserControl→UserTempConverter+paramusercontroldatatemplate.xaml→Tab/GroupLinkItem/底部命令/外部槽；SunEyeVision迁移该声明驱动组装并在消费者迁移后删除旧模型、重复窗口壳和旧可视桥。

完整回填段落（框架架构总览）

VM 普通工具窗口的静态完整组装链为：入口选择 → 工具呈现工厂/设置视图（IToolPresentationFactory → IToolSettingsView）→ ModuleParam/AlgorithmTabRoot → ParamsConfigControlBase → ParamsTabUserControl → ParamListView/ParamUserControl → UserTempConverter 与 paramusercontroldatatemplate.xaml → Tab、GroupLinkItem、底部命令和外部槽。已有静态材料固定 VisionMaster 4.4.0 Build20250516@1555331 及控件/资源程序集 SHA；AlgorithmTabRoot 负责页签、分组、外部参数、命令、选中页、窗口尺寸、订阅与 ROI 桥接，GroupLinkItem 克隆公共组并设置父链，模板字典按参数类型分发控件。SunEyeVision 应直接迁移上述声明驱动的组装、父链、模板和资源职责，以单一契约和非视觉宿主适配承接当前字段与执行；在消费者映射和保存重开闭环完成后删除旧模型、重复窗口壳和旧可视桥。当前 VM 仍未取得同版本运行证据的项目包括：首次打开的真实构造顺序与首帧耗时、同节点 Tab 是否复用视图/模型、跨节点退订与销毁顺序、Loaded/DataContext/绑定回调、执行回调与结果 reader 最后释放，以及缓存、异步、虚拟化或延迟加载机制；这些不得写成 VM 已确认行为。当前 SunEyeVision 的 ToolDebugSession、ToolEditorHost、ModuleExecutionScope 仅代表本方适配实现，不能冒称 VM 等价。完整链路验收必须分别记录 VM 静态/运行证据、本方运行时、自动测试、VS 设计器和用户人工验收。
