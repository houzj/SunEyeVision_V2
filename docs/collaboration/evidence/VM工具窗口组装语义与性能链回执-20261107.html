性能链：能解释什么，不能解释什么

  • 可确认：参数 UI 是声明驱动的；类型到 DataTemplate 的映射、GroupLinkItem 的公共组展开、父链与 Trigger 声明会影响装配工作量。不同工具 XML 控件数量差异是可测的潜在线索。
  • 可推断但未证：首次打开慢可能来自 XML/Group 展开、DataTemplate 选择、控件树构造和资源合并；只能作为待测假设，不能写成 VM 真实优化机制。
  • 未知：是否一次性创建、同节点是否复用视图/模型、Tab 切换是否按需装配、跨节点是否先销毁旧树、是否存在缓存/异步/虚拟化、首帧瓶颈究竟在 XAML、绑定、资源还是算法，当前均无 VM 运行证据。

对当前 SunEyeVision 设计的直接影响

  1. 可以采用“入口→呈现工厂→AlgorithmTabRoot/模型→ParamsTabUserControl→DataTemplate/GroupLinkItem→绑定/命令”的适配检查框架。
  2. 不能预先实现或宣称缓存、异步、虚拟化、延迟加载；也不能因本方 Tab 复用设计而称 VM 同态。
  3. 现行架构文档可登记上述 VM 静态组装链、版本/SHA 和明确未知边界；删除旧模型或改变窗口所有权前仍需同版本构造/切换/关闭运行证据。

下一项最小动态取证：固定一个普通 XML 工具和一个含 GroupLinkItem 工具，记录首次打开、同节点 Tab 切换、跨节点切换、返回原节点、关闭时的窗口/视图/模型实例数、Loaded/Unloaded、绑定回调、资源加载和首帧时间；不预设任何缓存或异步机制。
