1.3 卡尺族：一个工具 + 两种 ROI 形态（观察到）

IMVSCaliperModu.xml 的 Input 类 Category 实测（逐行取自原件）：

<Category Name="Input">
  <Combination Name="InputImage" Style="IMAGE">
      Filter InImage(image, IsForce=true) InImageWidth(int) InImageHeight(int) InImagePixelFormat(int)
  <Combination Name="InputROI" Style="ROIBOX">                    ← 直线卡尺形态
    <Combination Name="ROI CenterPoint" Style="POINT">
        roicenterx / roicentery / roiwidth / roiheight / roiangle     (全部 float, IsForce=false)
  <Combination Name="InputROIAnnulus" Style="ROIANNULUS">          ← 弧形/环形卡尺形态
    <Combination Name="ROI Annulus CenterPoint" Style="POINT">
        roiAnnulusCenterX / roiAnnulusCenterY / roiAnnulusInnerRadius
        roiAnnulusOuterRadius / roiAnnulusStartAngle / roiAnnulusAngleExtend
  <Combination Name="Position Correction Info" Style="FIXTURE">
    <Combination Name="Fixtured Point" Style="POINT">
        FixtureInitPointX / FixtureInitPointY / FixtureInitAngle
        FixtureInitScaleX / FixtureInitScaleY                        (期望位姿)
    <Combination Name="Unfixtured Point" Style="POINT">
        FixtureRunPointX / FixtureRunPointY / FixtureRunAngle
        FixtureRunScaleX / FixtureRunScaleY                          (运行位姿)
<Category Name="Output">
    ModuRunTime(float) ModuStatus(int) EdgeStatus(int, IsArray=true) CaliperEdgeNum(int)

三条可直接用于我方设计的结论：

  1. ROI 形态用 Style 区分，不用独立工具：ROIBOX 与 ROIANNULUS 同时挂在同一个卡尺工具上，由绑定哪一组决定"直线卡尺"还是"弧形卡尺"。对我方 T-LINECALIPER/T-CIRCLECALIPER/T-ARCCALIPER 三个待办工具的直接启示：先论证为什么拆三个；若沿用原件思路，应做「一个卡尺工具 + ROI 形态（矩形/环形/扇形）」。
  2. ROI 是"标量字段集合"而非不透明对象：矩形 roi 展开为 5 个 float，环形展开为 6 个 float，全部 IsForce="false"（可绑定也可不绑定）。这与我方 RoiShape[] 抽象形成对照：原件按字段绑定粒度更细（可只绑 roiangle）。
  3. 位置修正用独立 FIXTURE 端口 + 期望/运行两组位姿：FixtureInit*（标定期望）与 FixtureRun*（运行时实际），各含 X/Y/Angle/ScaleX/ScaleY。这解释了我方"标定板/夹具/仿射"为何在原件里是工具输入而不是全局设置。

1.6 我方三类卡尺待办的可支撑结论

我方待办原件对应可支撑的实施判断仍缺
T-LINECALIPER 直线卡尺IMVSCaliperModu + InputROI Style=ROIBOX（5 标量）ROI 字段集：center X/Y、width、height、angle；输出含 EdgeStatus[]（逐边状态数组）与 CaliperEdgeNum卡尺内部投影/边缘极性算法（G4）
T-ARCCALIPER 弧形卡尺同一模块 + InputROIAnnulus Style=ROIANNULUS（6 标量：中心 X/Y、内外半径、起始角、角度跨度）不需要独立模块，只需换 ROI 形态与字段集同上；另 AngleExtend 的符号/范围语义未知
T-CIRCLECALIPER 圆卡尺无直接对应。原件有 IMVSCircleFindModu(37 KB)、IMVSMatrixCircleFindModu(38 KB)、IMVSHoughCircleFindModu(不存在)圆卡尺可能应参照「圆查找 + 环形 ROI」组合，而非卡尺模块需 R3/R4 或厂商文档确认；本批不臆定
位置修正/夹具Style="FIXTURE"（Init/Run 各 5 标量）夹具应作为工具输入端口（期望位姿 + 运行位姿），不是我方全局配置Angle/Scale 的复合顺序（先旋后缩？）未知
