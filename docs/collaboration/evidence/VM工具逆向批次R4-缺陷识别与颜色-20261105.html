0 结论摘要

问题档位结论
R4 实物有多少观察到 清单声明 52，实物 24（DefectDetection 14 + Recognition 4 + DeepLearning 0 + RegisterLearning 0 + ColorProcessing 6）。
缺口 28 个全部集中在深度学习系（DeepLearning 14 + RegisterLearning 6 + Recognition 里 8 个 Cnn*/OcrDl）。
为什么差这么多推断 清单里这 20 个深度学习模块的类型列都是 NORMAL（与已安装模块相同），但 DeepLearning/RegisterLearning 两个分类目录整目录不存在，全盘也搜不到任何 *Cnn* 目录。
→ 结论：清单是"完整产品目录"（含按授权/选装裁剪的部件），不是"本机已安装清单"。这与 R2 记录的"声明≠实物"是同一件事的正确解释。
工具箱准入判据是什么观察到 ToolItemInfo.xml。本批唯一反例：IMVSMarkInspModu 有 11 个文件、Control.dll、18 MB 的 .dll，却没有 ToolItemInfo.xml → 不进工具箱。
其"VA"版 IMVSMarkInspModuVA 有 ToolItemInfo.xml(priority=1) → 进工具箱。
因此 R4 计数分两层：模块目录有效 24 / 工具箱条目有效 23。
专用编辑器比例观察到 带 *Control.dll 的 10/24 = 41.7%，是 R3（20.6%）的两倍。
按分类：Color 3/6=50%、Recognition 2/4=50%、Defect 5/14=36%、ImageProcessing(R3) 5/21=24%、SplitCombination(R3) 0/6=0%。
→ 越偏"算法专有"，越倾向写专用编辑器；越偏"通用图像算符"，越靠参数页。
缺陷结果的公共字段族观察到 DefectDetection 12 个模块（除 Group/趋势类）统一输出：FlawNum、DefectType、DefectSize、DefectArea、CaliperStart、CaliperEnd、EdgePointStatus/Num，多数还带 BlindPolygonString。
→ 这 8 个字段构成"缺陷判定标准结果族"，跨工具同构。
成对边缘范式观察到 EdgePair 系列统一输出 Edge0Point/Edge1Point/EdgeMiddlePoint + 宽度统计 WidthPairNum/MaxWidth/MinWidth/AvgWidth/EdgePairWidth。
→ "双边缘对"是缺陷检测的原厂主模型，单边缘（LineEdge/CircleEdge）是其退化形态。
输出端口是否有"泄漏"观察到 有，且集中在 2 个趋势分析模块：IMVSEdgePosTrendAnalyModu/IMVSEdgePairPosTrendAnalyModu 的结果里混入算法参数：
Edge_Polarity、EdgeDist、Edge_Score、Edge_Point_Search_Status、RunParam_EdgePoint0（端口命名也用下划线）。
→ 这是"参数直接当结果暴露"，与我方 OutputVariable（业务结果 ≠ 参数）的设计相反，属反面案例。
全局 Style 库核对观察到 本批复核 Combination.xml 唯一 Style = 44（R2 记 45，差 1，原因未定位，以本批可复跑命令为准，R5 收口时统一）。
本批用到但全局库没有的 Style：GENERALINFO（0 命中）、DEBUG（0，R3 已记）；CLASSINFO 则在库中（2 命中）。
颜色工具的形状能力观察到 Color 6 个模块里 4 个支持 InputROI/ROIBOX + InputROIAnnulus/ROIANNULUS 双 ROI；ColorSegment 输出 ClassInfo/CLASSINFO（分类信息组合端口），ColorMeasure 固定输出 C1/C2/C3 三通道统计。
本批对我方的可用度观察到 低。我方 tools/ 现有 24 个工具中，缺陷检测 / 识别（OCR/条码）/ 颜色测量三类完全没有对应实现。
本批价值在于：先固定"缺陷结果族"与"成对边缘"两个数据模型口径，等真要建这批工具时不用重新取证。
