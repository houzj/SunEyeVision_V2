Communication 有什么特征观察到 5/5 = 100% 带专用编辑器；全部无图形输出端口（仅 ReadDatas/SendDatas 收图像作数据源）；结果以 StrResult/ResultHex/AssembleResult 等文本/十六进制为主。
→ 与 R3 的 ModuRunTime/ModuStatus 约定一致（本批 58 个模块全部有这对字段）。
计算类有没有"成对"范式观察到 有。IMVSLineAlignModu/IMVSMultiPointAlignModu/IMVSSinglePointAlignModu 统一输出 DeltaX/DeltaY/DeltaTheta；
SinglePointGrabModu/SinglePointRectifyModu 统一输出 OffsetX/OffsetY/OffsetR + InitPoint。
→ "对齐偏差"和"点位定位偏差"是两个独立的结果族，字段名不通用。
标定类的规模在哪里观察到 IMVSNImageCalibModu 结果 29 个字段、IMVSNPointCalibModu/TranslationCalibModu 各 24 个 —— 全库单模块结果字段最多的类型。
→ 标定不是"点一下出个矩阵"，而是多步采集 + 多状态机 + 多误差量。
前批数字勘误观察到 ① R2 记"全局 Style 45 种"，本批用去重命令复核 = 44，差异未定位，以 44 为准；
② R2 记"Location 声明 33"，清单实测 34（R2 的 33 = 其批次范围内的 Location 28 + Measurement 5，口径不同，非错误，但今后须注明"批次范围声明数"而非"分类声明数"）。
本批对我方的价值观察到 三个可直接用的判断依据：
① 要不要专用编辑器：按分类先验（Logic 95% / Communication 100% → 必须；SplitCombination/ImageGeneration 0% → 不必）；
② 工具的端口形态：图像流（IMAGE/ROI）vs 数据流（无端口）是两类不同工具，不能共用同一套宿主接缝；
③ 清单不是需求清单：191 是产品全量目录，本机可用 159，规划时不能用 191 当工作量。
