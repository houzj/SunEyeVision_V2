0 结论摘要

问题档位结论
准入元数据有几层观察到 三层，粒度不同、作用不同：
① 分类级 <分类>\ToolGroup.xml（15 个，129–208 B）：name / priority / 可选 priorityStrategyInfo；
② 工具级 <模块>\ToolItemInfo.xml（159 个，约 228–317 B）：name / priority / toolTip / helpUrl；
③ 清单级 Applications\ModulePathGenerate.txt（191 行）：模块名 # 路径 # 类型。
什么决定"能拖出来"观察到 ToolItemInfo.xml。反例两个：DefectDetection\IMVSMarkInspModu（18 MB dll、有 Control.dll、无 TI）与 Global\ProcedureComm（4 文件、无 TI）
→ 文件全 ≠ 能上工具箱；只有 TI 才是工具箱准入凭证。
分类显示名与目录名一致吗观察到 不一致，三处：目录 Location → 显示 Locating；Logic → LogicTools；DefectDetection → Defect Detection（带空格）。
→ 目录名是技术身份，ToolGroup.xml/name 是用户可见名，两者解耦。
分类顺序怎么定的观察到 priority 值 1–14 + 20：Collection 1 / Location 2 / Measurement 3 / Recognition 4 / DefectDetection 5 / 6 空位 / Calibration 7 / Calculation 8 / ImageProcessing 9 / ColorProcessing 10 / SplitCombination 11 / ImageGeneration 12 / Logic 13 / Communication 14 / GroupTools 与 UserTools 均 20。
还有场景权重？观察到 有，且只 4 个分类带：Calculation=Position:3.5;Recognition:4.5、DefectDetection=Defect:1.5、ImageProcessing=Defect:1.75、Recognition=Recognition:1.5。
格式 场景名:浮点权重，分号分隔。推断 用于按场景调整工具箱内的推荐排序（同一分类在不同场景下不同权重）。
工具身份靠什么观察到 方案文件 ProcedureInfo.xml 的 Module 节点同时带 Index（序号）+ Guid（32 位无连字符实例号）+ Name（类型名=目录名）：
<Module Index="0" Name="ImageSourceModule" Type="0" IsSlave="0" ServerAddr="" ModuleFile="" DisplayName="图像源1" EnableModule="1" EnableCallBack="1" Guid="48D45181B7A444AF926E032F9E142D57"/>
加载前有校验吗推断 未见独立校验清单/校验文件（无 hash 清单、无签名清单文件）。存在的准入门槛是：Server\PlugAuthorization.dll(7.0 MB)、EncRuntime\、三种授权安装脚本（狗/远程狗/软授权）。
→ 推断 准入以授权 + 文件存在性为准，不做逐模块签名校验。
加载失败怎么表现观察到 方案级：WARN Load Warning，Failed Module Num:4 后继续（见方案版本文档 §1.4）。
进程级：崩溃时落 <exe>-时间-序号.txt 文本栈（见启动时序文档 §1.5）。
模块级（单个 dll 加载失败的具体日志行）本批未取证。
GroupTools/UserTools 是什么观察到 空分类：两目录下各有 ToolGroup.xml（priority=20），但子目录 0 个，且不在 ModulePathGenerate.txt 里。
→ 是用户扩展入口（预留分类位），不是内置工具分类。
我方 ToolGroups.xml 算原厂机制吗观察到 不算。 机制是自建的（单文件、复数名、带 SchemaVersion、含 Icon/HoverIcon/IconKey，原厂没有这些字段）。
但顺序值有原件依据：我方 Order = 1,2,3,4,5,7,8,9,10,11,12,13,14,20,20，与原厂 priority 逐一相同（含"6 缺位"） → 分类顺序可标"与原厂一致"，文件格式不可标"原厂依据"。
我方 release-payload.json 对应原厂什么观察到 功能上最接近 ModulePathGenerate.txt（都是"应存在哪些模块"的清单），但语义相反：
原厂清单是产品全目录（191，含未安装），我方 expectedPluginAssemblies(22) 是必须存在的强校验。不能互相套用（把 191 当期望值会误判 29 个为缺失）。

1.2 工具级：ToolItemInfo.xml 四字段 观察到

<?xml version="1.0" encoding="UTF-8"?> <ToolBoxItemData> <name>IMVSBinaryModu</name> <priority>0</priority> <toolTip>IMVSBinaryModu</toolTip> <helpUrl>GUID-DBCA7DED-F21F-44EB-BA0A-1D61CB7CDE45</helpUrl> </ToolBoxItemData>
字段取值规律用途
name= 目录名（= 模块类型名）工具箱条目名 / 方案 Module@Name
priority分类内序号，非全局唯一；同一分类内可重复（如 Logic 多个 100）分类内排序
toolTip多为 <模块名>，少数带后缀 _Tip（如 IMVSImageFilterModu_Tip、Image Buffer、Light）悬停提示（值可以是本地化键，非纯文本）
helpUrlGUID-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX（8-4-4-4-12）指向官方帮助索引（不是 URL，是 GUID 键）

priority 非唯一性的实证：Logic 分类里 DataClassificationModule/DataFilterModule/DataSortModule 均为 100；Global 里 ImageCollectDalsaModu/ImageCollectIKModu/DynamicParamCameraModule 均为 100。推断 同值时的次序由目录枚举或名称决定，未知。

2 原件 vs 我方对照（定位校正）

项原件我方定位结论
分类元数据每分类一个 ToolGroup.xml（name/priority/可选 strategy）src/Plugin.SDK/Metadata/ToolGroups.xml 单文件 <ToolGroups SchemaVersion="1">，14 个 <Group Name Order Icon HoverIcon IconKey/>机制自建。可标"顺序与原厂一致"，不可标"格式源自原厂"（我方多出 Icon/HoverIcon/IconKey/SchemaVersion，原厂无）
分类顺序值priority：1,2,3,4,5,7,8,9,10,11,12,13,14,20,20（缺 6）Order：1,2,3,4,5,7,8,9,10,11,12,13,14,20,20（缺 6）逐一相同，含"6 缺位"这一非平凡特征 → 可确认为有原件依据的顺序对齐（观察到的字面一致）
分类显示名Locating / LogicTools / Defect Detection（英文，且≠目录名）中文：定位 / 逻辑工具 / 缺陷检测取值不同，语义对应。表述应为"分类语义与原厂对应，显示名为我方中文本地化"，不能写成"沿用原厂分类名"
空分类GroupTools/UserTools：有 ToolGroup.xml、0 模块、priority 20"自定义组工具"/"自定义工具"，Order 20对齐（含 order 20 与"无内置模块"两点），可标注
工具级元数据ToolItemInfo.xml 4 字段（name/priority/toolTip/helpUrl GUID）ToolAttribute（代码特性，随程序集编译）载体不同：原件元数据可在不重编译下改（改 XML 即生效）；我方须改代码重编。不是缺陷，但"运维可调性"是原件的优势，文档中应如实写差异而非"等价"
帮助链接helpUrl = GUID-... 键，指向官方帮助无对应我方无此能力，不要说"已对齐"
模块清单ModulePathGenerate.txt：产品全目录 191，含未安装release-payload.json：payloadSchemaVersion:1 + expectedPluginAssemblies 22 个 + runtimeFrameworks语义相反：原厂=全量参考清单（不承诺都存在，191 vs 实物 162）；我方=发布强校验清单（缺一即失败）。禁止把 191 当我方期望值（会误判 29 个缺失）；也禁止说我方 release-payload.json 是"对齐原厂清单"
payloadSchemaVersion无对应字段（原厂无 payload 概念）整数 1纯自建，与原厂 CurrentVersion="V4.4.0"（产品串）不是同层概念，不可互相引证
实例身份Guid + Index 并存本批未核对我方节点身份实现待核：若我方只有序号，则复制/合并会撞号（原件的 Guid 正是为此）
给文档线的三条硬结论（可直接引用）
① 可标"原厂依据"：分类顺序值（含 6 缺位）、空分类 order=20、分类语义集合（14 个内置 + 2 个用户扩展）；
② 只能标"自建"：ToolGroups.xml 的文件形态与字段、release-payload.json 全部内容、ToolAttribute 载体；
③ 不得标"已对齐"：helpUrl 帮助键、工具级元数据的热可改（不重编译）、实例 Guid（未核）。
