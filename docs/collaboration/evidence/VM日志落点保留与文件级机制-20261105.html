0 结论摘要

问题档位结论
日志写在哪观察到 安装目录内 Applications\log\，按子系统分 11 个目录（不是单一大文件）：Exception / FrontendUI / GateWay / GateWayUI / GlobalScript / ModuleProxy / Modules / ModuleUI / SDK / Server / UI。
保留多久、多大观察到 本机实测总量 ≈293 MB。滚动按大小（RollingStyle=Size），不按日期（尽管配置里留了 DatePattern 参数）。
阈值分档：10 MB（GateWayUI / UI）、20 MB（Modules / Server / ModuleProxy）、40 MB（SDK）。
配置从哪来观察到 每个子系统各自的 Apps.BaseLog.config，框架是自研的 Apps.BaseLog（log4net 风格 API）。目录内找到 6 份日志配置，其余子系统没有外置配置（阈值不同，说明在 DLL 内或别处）。
配置与实测对得上吗观察到 对得上，这是最有力的交叉验证：GateWay\Apps.BaseLog.config 写 MaximumFileSize="10MB" + MaxSizeRollBackups="5"，实测 GateWay.log + .1...5 共 6 个、大文件恰好 10,485,xxx B。
日志级别怎么定观察到 每子系统独立：GateWay=all（最低门槛，全记）、GlobalScript=info；另有独立工具 Tools\LogLevelAdjustmentTool 用于调级别。
日志格式观察到 %date{yyyy-MM-dd HH:mm:ss.fff} %-5level [%thread] [%class::%method@%L] %message%newline%newline
→ 含毫秒、级别、线程、类::方法@行号；每条消息后跟两个换行（条目间空一行）。
偏好（默认保存目录）观察到 App.ini 全文只有一段一条：[DefaultSection] SaveSol=C:\Users\houzhongjie\Desktop。INI 格式、无注释、无版本号。
偏好（自动加载方案）观察到 Server\AutoLoadSolution.cfg：IsAutoLoad="0" Path="" Password="" SoluExecuteState="1" —— 开关 / 路径 / 密码 / 加载后是否执行。
方案版本观察到 方案包内 ProcFile\ProcedureInfo.xml 的 <Version CurrentVersion="V4.4.0" />（产品串）。详见 VM方案格式版本与兼容迁移-20261105.html。
恢复回收有吗未知 未发现"下次启动恢复未保存方案"的配置或索引文件。可见的是 4 处临时目录只写不清：Temporary\FeaturepatMatch_0..15+.xml（按序号递增）、TempImage\OU3LNB8Q（8 位随机名）、ImageTemp\VM32616ImgSrcTemp（实例号前缀）、ProjectParam\Designer\。
→「有临时文件」≠「有恢复机制」，两件事本批未能闭合后者。
我方最该拿走的推断 三点：①按子系统分目录 + 每目录独立滚动（一条业务链出问题只看一个目录）；②大小滚动 + 备份数上限（不按日期，磁盘可控）；③格式里带类::方法@行号（现场可定位到代码行）。
不该学的：日志写在 Program Files 内（需管理员权限）、临时文件永不清理。

1.2 权威配置：GateWay\Apps.BaseLog.config 全文 观察到

<configuration> <configSections><section name="Apps.BaseLog" type="Apps.BaseLog.Config.Log4NetConfigurationSectionHandler, Apps.BaseLog"/></configSections> <Apps.BaseLog> <appender name="RollingLogFileAppender" type="Apps.BaseLog.Appender.RollingFileAppender"> <!--日志路径--> <param name="File" value=".\log\GateWayUI\GateWay.log"/> <!--是否追加--> <param name="AppendToFile" value="true"/> <!--编码--> <param name="Encoding" value="utf-8"/> <!--log保留天数--> <param name="MaxSizeRollBackups" value="5"/> <!--文件名固定--> <param name="StaticLogFileName" value="true"/> <!--文件名格式--> <param name="DatePattern" value="yyyy-MM-dd".log""/> <!--按大小滚动--> <param name="RollingStyle" value="Size"/> <param name="MaximumFileSize" value="10MB"/> <layout type="Apps.BaseLog.Layout.PatternLayout"> <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} %-5level [%thread] [%class::%method@%L] %message%newline%newline"/> </layout> </appender> <root> <!--(高) OFF > FATAL > ERROR > WARN > INFO > DEBUG > ALL (低) --> <level value="all"/> <appender-ref ref="RollingLogFileAppender"/> </root> </Apps.BaseLog> </configuration>
参数值实测吻合说明
File.\log\GateWayUI\GateWay.log✔ 文件存在相对路径（相对 exe 工作目录），因此日志必然落在安装目录
AppendToFiletrue✔追加，不覆盖
Encodingutf-8✔ 可正常按 UTF-8 读与 paraCfg.xml 的 GBK 形成对比
MaxSizeRollBackups5✔ 实测 .1...5 共 5 个注释写"log保留天数"但实际按个数——注释与语义不符
StaticLogFileNametrue✔主文件名固定，不随时间变
DatePatternyyyy-MM-dd.log✘ 未生效RollingStyle=Size → 日期模式被忽略（配了但不用）
RollingStyleSize✔按大小滚动
MaximumFileSize10MB✔ 实测 10,485,760 B1 MB = 1,048,576 → 10 MB = 10,485,760 ✔
levelall—最低门槛，全量记录；注释给出了完整级别序
conversionPattern见上—毫秒 + 级别 + 线程 + 类::方法@行号；双 %newline
注释与语义不符两处（读配置时易误判）：①MaxSizeRollBackups 注释为"log保留天数"，实际是备份文件个数；②DatePattern 配了但 RollingStyle=Size 使其不生效。看配置不能只看注释。

2 原件 vs 我方对照

原件事实我方现状结论 / 建议优先级
日志按子系统分目录（11 个），各自滚动我方统一 LogInfo/LogError 单通道 + 单文件（本批未核对我方具体落点）值得借鉴：至少把「UI / 执行引擎 / 插件 / 通信」分开，出问题只看一个目录。但不必做 11 个，按我方实际子系统划分即可P2

格式含 [%class::%method@%L]我方 LogInfo 是否带调用方信息本批未核建议：日志带类/方法/行号，否则现场只能靠猜P2
日志目录在 Program Files 内我方数据根可配置（App.ini 的 [Data]，见 T-0002）不要学。Program Files 需管理员权限写，UAC/虚拟化会带来"日志神秘丢失"—
临时文件永不清理（序号无上限增长）本批未核对反例。应设上限 + 启动清理超期项，且清理失败要记 Warning（与 T-0001 的 C2/C4 同向）P2

未发现"崩溃恢复未保存方案"机制我方是否有类似机制本批未核不得声称原件有此能力；若我方要做，属自建，需自行设计落点与清理—
