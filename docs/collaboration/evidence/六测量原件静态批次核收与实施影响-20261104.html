# 六测量工具静态批次证据与未闭合边界

范围：VM 4.4.0 的 P2P、P2L、P2C、L2L、L2C、C2C。仅对原文件和自有副本做静态 XML、托管源码、原生反编译与必要指令核对；未启动原 VM/SDK。本报告把界面声明与算法生产分开；未证条目保留具体入口及自研适配边界，不把合理几何公式标为原厂实现。

## 父分类、组合输入和绑定行为

六工具 `ChooseCoordinate` 均声明 `ImageCor=1`、`SpecCor=2`；此处仅是枚举名称/值，不能由名称推导矩阵方向。`OutputAngleRange` 均声明 `RangeSegment=0`、`RangeLinear=1`，默认 1；六种工具的角度包装行为见下文。

P2P 的 `InputWay/InputWay1` 分别在整点和 X/Y 输入之间切换；P2L/P2C 首点相同。P2L 的 `InputWay2` 为 0 整线、1 两点、2 四坐标；P2C 的 `InputWay2` 为 0 圆、1 圆参数。L2L 两线、L2C 线和圆、C2C 两圆的具体 InputWay、对应目标及 `DoInitOperaion` 全列于 JSON，不将其缩成所有工具统一模式。

L2L/L2C/C2C 的 `SourceSelect` 声明 0 订阅、1 绘制。三个 XML 的 `CurValue` 触发项无比较值时调用 `RoiDisplayOperation`，值 1 时分别隐藏两组输入 Category、显示 ROI Category 和 `RoiType`。`Trigger.OnTrigger` 在 `Value == null` 时执行其操作；触发变化也需要考虑 `ReOnTrigger` 对先前生效操作的恢复，不能只看值 1 时显示一项而忽略其他项。原 `RoiDisplayOperation.Operate` 调 `IModuleResultView.SetRoiVisible()`，不能根据名称断言清除 ROI。

P2P/P2L/P2C 的两个不同分类中有同名 `OriginPoint`。`Setter.GetTargetObj` 先在离触发器最近的 Category 按名称寻找，找不到再调用 `AlgorithmTabRoot.FindBaseNodeByName`；全局查找按 Tab 遍历先返回首个结果。为此配置保持父级身份，不能把所有同名节点压成一条。`ChooseCoordinate` 触发 `OriginPoint` 可见性，`OriginPoint` 的 `GetSelectedFilterOperation` 初始化查询模块输入 `CalibMatrix`，回写订阅名称；不能据此把它误认为输入点本身或直接等于矩阵数值。

`HiddenOperation` 通过目标 `CustomVisibleA=false`；`ValueBase.CustomVisibleA` 在节点和直接父 Category 的 `IsDeleteSubscribeA` 均允许、且已存在非空订阅时清 `_SubData.CurValueA` 并触发回读。`ButtonSelecter` 继承 `NameValueItem` 的基本可见 setter，没有该 `ValueBase` 覆写；`CategoryHiddenOperation` 只设置 Category 的 `CustomVisibleA`，该属性实现未逐个清子节点。因此不能概括为“隐藏必清所有绑定”或“切模式必保留所有绑定”。进一步事件与撤销异常路径需按具体实例追证。

## 输入与无图边界

P2P/P2L 的输入资源 `InImage` 声明 `IsPrefer=true`；P2C/L2L/L2C/C2C 声明 `IsForce=true`。六个 `CalibMatrix` 均声明 `IsForce=false, IsArray=true`。精确每项及组合归属见 JSON，强制/优先标志本身不等于一次具体运行结果。

P2P `GetProcessInput@18000a360` 和 P2L `GetProcessInput@18000a380` 所核函数体读取坐标/线端点，没有调用图像获取；相应 `Process@18000b330/18000b910` 先读可选标定，再读输入，条件满足时 `ProcessAlg → LimitJudge → ProcessOutput`。这表明这些函数入口没有图像参数读取；不证明框架预检、所有错误分支及真实宿主均允许无图。

P2C `GetProcessInput@18000a620 → 180007d00 → 180007c00`，C2C `18000baa0 → 1800080c0 → 180007fc0` 在已核订阅路径先调用 `VM_M_GetImage("InImage")`；获取函数返回非零直接向上返回，随后还读取图像宽、高、像素格式并检查可用状态。L2L/L2C 的订阅 `Process` 经 `GetProcessInput`，图像读取错误进入失败分支；绘制模式走 `FindProcess`。只凭 XML 不足以推断返回码、空指针但返回成功等全部边界；对四个 IsForce 工具的全部缺图行为仍需沿 VM_M_GetImage 与框架预检继续追。

## 标定输入和已核输出时序

六个模块的原 `Process` 导出体均可在 `analysis/full-audit/measure-six-static-20261104/<工具>/named/` 查阅；P2L `Process@18000b910` 在 `ProcessAlg` 之前调用 `GetProcessCalibMatrixInput@180009e70`。后者读 `CalibMatrix` 数组并设置模块矩阵状态，通过标定变换对象写入；源码中输入数量及错误分支需结合原汇编，不可假设所有长度都安全。相应矩阵传入后，由 `CalibTrans@18000a0d0` 调其标定对象的参数、执行和结果接口，不能仅从此层确定矩阵的乘法约定。

P2L `ProcessOutput@18000ae50` 的所核分支：矩阵有效且选择字符串与原文件字节 `"2"` 精确匹配时，先发布 9 个 `MeasureCalibMatrix`，再对线起点、线终点、输入点调用 `CalibTrans`；投影点也按该条件变换后输出。随后 `P2LAngle`、`P2LDistPerpend`、`P2LDistMin`、`P2LDistMax` 从结果对象分别取值发布。点线最小/最大分别来自结果 vtable `+0x20/+0x28`，投影来自 `+8`；**不能仅凭这些名称断定是线段端点距离、无限直线还是别的定义**。P2P `ProcessOutput@18000aba0` 同样在特定条件下转换输入两点和结果中点；角度及距离从结果对象另取，不能假定它们根据转换后的输出坐标重新计算。具体变量/寄存器以每份 asm 为准。

P2C `ProcessAlg@18000ae70` 构造圆对象并向原工具的参数对象分别输入圆和点，`ProcessOutput@18000b260` 从不同结果访问器发布近/远距离，`P2C1Distfarthest` 对应 vtable `+0x20`；其数值生产公式、点在圆内与同心边界仍未闭合。

C2C `ProcessAlg@18000c5c0` 依次创建圆 1、圆 2 并交给相应原工具参数接口；`ProcessOutput@18000cb00` 按结果 vtable `+8/+0x10` 分别发布 `PointInter1/2`，并可对两点做标定变换；模块没有在所核发布代码中对两点排序。`C2CType` 只在结果状态非零且 type 非零时发布，索引 1–5 的文本依次为 `Inside/Inscribe/Intersect/Circumscribe/Outside`；这里是模块的文本映射，具体容差、内外切定义、距离公式及两个交点的生产顺序仍需追原 SDK。

### 六种工具的角度范围包装

P2L `MVDP2LMeasureCpp!180001c30`、P2C `MVDP2CMeasureCpp!180001c10`、C2C `MVDC2CMeasureCpp!180001da0` 将原 `MVD_Algorithm_Process` 返回角度写入结果前检查参数：码 0 时将 float 角度提升为 double，执行 `fmod(angle,180)`；小于 -90 时加 180，大于或等于 90 时减 180，再转 float。有限角度结果落在 `[-90,90)`，例如 +90 归到 -90；码 1 分支直接使用原算法返回角度，不在这些包装函数中归一。P2L/P2C/C2C 模块 `SetParam(OutputAngleRange)` 所核分支将输入 1 传为 1，其余传为 0。此处只证范围包装，**不证明内核角度的起点、方向、单位之外的有效范围或 from/to 次序**；NaN、无穷、负零及异常不归入有限数结论。

P2L/C2C 所用 PE 中 `1800036a8/6b0/6b8` 的 double 常量分别是 `90/-90/180`，P2C 对应 `180003690/698/6a0`。包装 DLL 身份分别为 `94797F06457A551C963C76A22DD9B81B534D155926099F2EC0613308B358F3F2`、`B71ACA26E06D38435743DF3D123C3914F251CC18B2B74424BB505A4CCB490069`、`FE28C5F1796D73EA53FA217DF0316EA787CFCBD8584D7ADCACA669244BD37608`；对应原指令及 C 在 `analysis/full-audit/measure-six-static-20261104/{P2L,P2C,C2C}-wrapper/addresses/`。这三条 wrapper 分别向内核请求类型 `0x195/0x194/0x191`；内核返回的数值来源尚需继续追。
