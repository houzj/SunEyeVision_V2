发布、重载与失败策略

  1. 门外读取载荷并校验所有文件、真实 Runtime 声明、桌面 Editor 工厂和分类；插件构造/回调、日志及外部枚举不得在 publication gate 内执行。捕获当前状态版本和尝试序号。
  2. 准备失败时旧已发布活跃代及桌面视图保持完整；失败诊断属于该次尝试，不能把旧 active 标成新成功。锁内核尝试、owner、版本、desktop pin，任何变更则丢弃候选。
  3. 得到 transition 后阻止新的 pin/提交并令旧代退休；锁外发送退役通知和等待 invocation、reader、编辑视图与 node reader。成功锁内一次发布完整新 admission；非 owner 卸载不得清掉当前代，旧 owner 不得清除新代。不得把手工 timeout 当可强制卸载。
  4. 旧代已不可逆退休后若发布失败，不能假装回滚到旧 active：按代次原子撤去该已退役对象并保留错误，可重试重新加载；不能出现旧目录+新 metadata/authority 混代或公开一个已退役快照为可用。通知/日志回调异常与已提交事实分开聚合或记录。
  5. 用户窗口关闭先撤消费并排空结果/reader，再放 DesktopHostPin、await manager 卸载；取消关闭或释放失败须保在用代及窗口，不能无界等待后强制释放。现有主窗真实出口与 NumericModelRead 所有者为必测，不假设新 API 自带完成。
