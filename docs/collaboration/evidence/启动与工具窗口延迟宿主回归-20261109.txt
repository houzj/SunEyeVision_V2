启动与工具窗口延迟宿主回归（2026-11-09）

实现变更
- `MainWindow` 的 XAML 只保留 VM 启动壳、顶部栏、状态栏和布局槽位；画布 Tab 树、结果图像/结果树、工具箱分别由 `DeferredWorkspaceHostControl`、`DeferredImageResultHostControl`、`DeferredToolboxHostControl` 承载。
- 发布准入、服务和方案会话完成后，`MainWindow.InitializeWorkspace` 只调用一次宿主 `Initialize`，随后创建现有 `ShellWorkspaceControl`、`ImageResultControl` 和 `ToolboxControl`。参数模板、Tab 复用、回调退订、关闭释放代码未复制或改写。
- 该结构对应 VM 已确认的“方案管理器/加载遮罩先可见，编辑器视觉树随后装配”顺序；不把启动页当长耗时容器。

限制与未确认
- 该回归没有冒充 VM 同机动态 UI 线程耗时；VM 目前有静态启动顺序和官方样例证据，尚无同版本动态计时。
- 当前启动方案是 VM 语义对齐的延迟宿主，不是临时占位 UI；后续工具继续沿同一宿主和 Plugin.Wpf 控件合同迁移。
