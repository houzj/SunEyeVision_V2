唯一 ToolConfiguration、DocumentSession 与准入视图

实施前整体设计 · 基线 95ba00f6f81066e9740705dc0bca730e8493e599 · 2026-11-03。本文不是已实施声明；UI 投影由界面线审查。Group 与循环新增暂停。

Domain 只保存一份工具配置；正式文档会话提供方案和节点归属、目录代次与运行 owner 的可信证据。准入视图不能由配置自身证明所属文档，也不能因当前值变化把后续合法运行判为过期。

对象唯一职责
ToolConfiguration不可变版本含 ToolId、Fields、CurrentValues、ParameterBindingOrder 和仅内存的字段 revisions；字段与嵌套值深冻结。常量权威在 Fields，当前值仅承载引用参数已接纳值且不得持有调用资源；同会话复制、草稿和运行快照携 revisions，加载从 0 开始。
DocumentSession正式打开或新建时拥有唯一实际文档，持有既有执行 owner 与准入目录，协调编辑、历史、成员归属和作用域。DocumentEditSession 的编辑 SessionId 与结果所用 ExecutionOwner.Id 分别保留。
AdmittedNodeView会话核验后签发的只读视图，关联节点对象、作用域、目录代次、定义和配置版本；不是持久化实体或第二张可写表。CurrentValues 更新时重新取配置版本但复用已准入 definition，不按旧配置引用长期拒绝后续运行。
定义与资源沿用 RuntimeDirectorySnapshot.CreateDefinition 的 ToolId、类型、schema、宿主声明检查及 AcquireInvocation、reader 和资源释放；跨程序集只开放受控入口，不复刻准入、不增加同义 owner，值变化不重建模块。

V3 配置 JSON 只写 ToolId / Fields / CurrentValues / ParameterBindingOrder；不写 revision、目录、准入视图或 owner。旧格式继续明确拒绝，失败不改源文件。

2. 会话与可信作用域（目标签名）

sealed class DocumentSession {
    Guid EditSessionId { get; } // 现编辑 SessionId 语义

    internal RuntimeDirectorySnapshot Directory { get; }

签名是待审目标而非当前 API。Scope 与视图仅由会话构造，不允许公开伪造或设置目录；访问级别随实际程序集边界确定。

  1. OpenScope 捕获实际文档对象、文档 ID、流程对象和 ID、目录及 owner；要求会话开放、owner 未退役、目录有效，流程对象和 ID 在文档内各唯一。
  2. 每次读取重验文档和流程身份、原对象成员关系、目录和 owner 同一对象与生命周期；节点 ID 重复明确拒绝，只有当前流程确无节点才返回 null。
  3. 存在节点时以会话持有的可信目录解析声明、核 ToolId、配置和代次；错代、缺配置、未准入或目录退役均明确失败。禁止从节点或配置自身取得目录作为自证。
  4. 跨异步在副作用、安装和调用接纳前复验；删除后同 ID 新节点不是旧实例，不能接收旧回调或旧结果。撤销按既有实例与历史语义处理，不以 ID 相同代替对象校验。

正式运行快照和私有草稿不是实际文档成员：由已验证会话与原节点派生，携带来源身份和受控凭据；对原对象、scope、代次及声明重新校验，不能将快照伪装成文档成员。

3. 正式运行与私有草稿是不同协议

路径必须保持不可做
正式接纳CaptureParameterValueAcceptance 捕获 owner、真实节点实例和不含实时值的 ConfigurationIdentity；回调核执行身份、实例仍属文档和声明身份；准备不可变候选，在 identity 门禁内比较本次 store baseline 与 prior 配置对象，安装前重验以防重入。不能按运行开始时的配置对象引用或字段 revision 做长期 CAS，否则第一次接受值后后续运行被误拒。
私有草稿合并MergeCurrentValues 逐引用字段比较 opening revision 与值；草稿和正式均变且值不同才冲突，同值可合并；草稿未改则采用最新正式值，接纳后按原语义更新 revision。不能把草稿三方合并改造成正式接纳规则，也不能私有调试直接覆盖正式值。
历史PreserveCurrentValuesFrom 保留仍有引用身份的实时值；常量编辑是权威。运行不写编辑历史；显示样式变化与执行配置身份变化保持区分。撤销重做不能回放旧运行值，也不能因为纯显示变更错误退役 publication。

6.2 准入工厂与定义缓存

决定：保留 Plugin.Runtime 的 RuntimeDirectorySnapshot.CreateDefinition(string toolId) 为 internal，使用受控的 InternalsVisibleTo("SunEyeVision.Application") 授权唯一 Application 程序集；强签名时按实际项目密钥配置完整公钥。Runtime 不引用 Application，不新增 public 反射构造或通用注册入口。Application 仅会话准入内部调用该现有方法，继续执行 ToolId、SettingsType、OutputType、Input/Settings schema 与 HostDeclarations 全部检查；创建时短期 AcquireInvocation 的 using 原样释放。实际调用也各自使用现有 public AcquireInvocation 并按原所有权释放。

会话私有 definition 缓存键为 会话实例 + RuntimeDirectorySnapshot 对象与 Generation + ToolId + 已冻结声明指纹；目录来自正式会话而不是节点或 state。缓存只存通过该目录校验的 definition/只读声明，不持有 invocation lease、reader 或运行资源；不以配置对象引用、CurrentValues 或 revision 作键。配置值替换不触发重新创建；目录更替、声明改变或会话退役清空缓存，不能跨会话复用。缓存命中时仍先校验 scope、目录 active、owner 未退役与同代声明，调用再单独接纳 lease；遇到退役竞态按现 Runtime 门禁拒绝，不扩大生命周期。

6.3 ToolConfiguration 与成员校验

Domain ToolConfiguration.Fields 的确切类型是 SunEyeVision.Plugin.Contracts.FieldSettings。复用其声明端口、Freeze、Capture 与 Apply，不再加可写 IDictionary 字段存储；唯一 CurrentValues、内存 revisions 和 binding order 随不可变状态整体替换。深冻结及资源禁止沿 FieldSettings / ValueRules，不能另造并行字段投影表。

FindNode(scope,nodeId) 必须先检查 session 开放、document ID 与对象、捕获的 owner 和 directory 实例及 active、流程 ID/对象成员唯一；这些条件不成立均抛诊断。然后按 scope 的流程查节点：重复 ID 抛错，确实没有才返回 null；若存在再核唯一实际节点对象及 session 准入声明、ToolId 和目录代次。不允许提前按缺节点返回 null 而掩盖失效 scope。

7.1 入口的可编译闭包

  1. 打开/新建：Persistence 解析中立 V3 → Application 按正式目录验证声明并建立唯一 DocumentSession / 定义缓存 → UI 读取同一节点对象；解析不得通过从 state 自带目录或首节点推断信任。
  2. 编辑：UI 获取 session 的 scope → Application 生成 draft、冻结、校验、事务接受与历史；已有正式字段唯一权威，异常不部分安装。
  3. 保存：Application 对会话与参与者一致性核验 → Persistence 原子写 V3，错误不覆盖源；重新加载配置 revision 为 0，重建新会话并使旧作用域失效。
  4. 执行与调试：Application 验证成员及配置 → 捕获带同代 definition、现有 owner / 身份和受限能力的不可变执行上下文 → Execution + Runtime 获得逐次调用 lease → 正式值接纳或私有草稿合并 → 完成/取消释放。不能让 Execution 反向引用会话。
  5. 查询与结果：Application 的 provider 逐次验证 scope 后提供声明；结果使用现行 ExecutionOwner.Id，节点删改和关闭拒绝陈旧结果，订阅随会话关闭释放。

联编审计必须逐项目验证：Contracts 无 Domain / SDK / Runtime 反引；Domain 不引 WPF / SDK / Runtime；Runtime 不引 Application；Execution 不引 Application / WPF；Persistence 不引 Application；Application 能访问唯一 internal factory；UI 与所有活跃调用无旧 SDK 查询接口。再执行本文第 5 节的同载荷集成回归，补并发 retirement 命中缓存、定义创建计数与查询 scope 先验负例。

8. 精确依赖闭包裁决（覆盖前文有冲突的初稿）

本节为最新裁决：INodeInfoProvider 与 IWorkflowConnectionProvider 位于 Application.Queries，不在 Plugin.Contracts；查询实现也位于 Application。Domain、Execution 和 Persistence 均不引用查询服务。以下签名为设计目标，尚未编译或实施。

8.1 唯一规范写入与严格读取

RuntimeFieldJson.Write 目前被 ConfigurationIdentity、CurrentValuesIdentity、CurrentParameterIdentity、BindingOrder 和 RuntimeDebugInvocation 的输入身份使用；整文件搬进 Persistence 会造成 Domain / Execution 反向引用。决定把写入和语义比较唯一实现提取到 SunEyeVision.Plugin.Contracts.ParameterSettingCanonical；严格读取保留 Persistence，以捕获的已准入声明和引用行为校验，不在 Contracts 引用 definition、directory 或 reader。BindingReferenceSerializer 中写入引用与变量表达式所需的纯编码也纳入同一个 Contracts 写入闭包；其读取与版本/行为校验由 Persistence 委托，不能再保留第二套输出编码。

namespace SunEyeVision.Plugin.Contracts;
public static class ParameterSettingCanonical {
    public static void Write(Utf8JsonWriter writer,
        IReadOnlyDictionary<string, ParameterSetting> fields);
    public static byte[] Encode(IReadOnlyDictionary<string, ParameterSetting> fields);
    public static bool Equivalent(IReadOnlyDictionary<string, ParameterSetting> left,
                                  IReadOnlyDictionary<string, ParameterSetting> right);
}

Write 与 Encode 同一实现；Equivalent 按同一规范字节语义比较。字段 ordinal 排序、引用/变量递归、显示表达式、常量记录/序列、OriginId、转换及既有版本字段的字节形状必须与现实现一致；未设置值缺席、非有限数与资源常量拒绝。Persistence 的 V3 写入直接调用该 Write，读取后的重序列化验证也调用它；不复制 codec，不把整套 RuntimeFieldJson 或 BindingReferenceSerializer 留两份。声明与校验仍由会话准入：FieldSettings.Declarations 只是深冻结快照，绝不能单独证明目录代次或插件已准入。

9. 租约、保存声明与读取闭包的可编译裁决

9.1 现有调试链证据

RuntimeDebugInvocation.Capture 当前收本地、跨流程和显示候选的 Func<...,DeclaredOutputSnapshot?>。CaptureCoreHeld 先读发布对象、校验正式 owner / 节点 / schema、AcquireReader 并二次对照同一发布对象；reader 保存进 invocation._readers，输入值借用它。预览还在 Current 回调核来源对象、执行身份、配置和变量；显示来源通过 ResultDisplaySourceSet 建立 value-only readers，避免递归 display 租约。ExecuteAsync 的 finally 或未启动 Dispose 释放 readers / generation / preparer；运行中 Dispose 明确拒绝、必须等待排空。原理与执行顺序必须保留，不能只返回裸 Snapshot 或复制图像像素替代。

9.3 保存资源不是执行资源句柄

当前 SolutionResourceResolver 按 ResourceFieldDeclaration(FieldId, Purpose, Cardinality) 从配置字符串或字符串序列检查、重定位方案路径；声明可延迟引用，文件缺失按原诊断处理。Domain.Persistence.DocumentPersistenceCapture 中资源条目只包含 workflowId、nodeId、toolId、字段 ID、Purpose、Cardinality、冻结的路径文本/表达式及源基目录，字段值仍以唯一 ToolConfiguration.FieldSettings 为权威，清单是捕获时只读派生快照。不得放 IResourceHandle、IReadOnlyImage、reader、输出资源、native handle 或执行租约；如果未来方案确需存图像字节，应单独定义资源资产存储与所有权，本批不假装路径引用等于图像保存。

资源声明由 Application 在可信会话准入后从当前 RuntimeDirectorySnapshot.GetResourceFields 捕获并与 tool/字段身份匹配；Persistence 只消费完整不可变字段声明和资源清单做路径检查/重定位，不能接收 RuntimeDirectorySnapshot 或从清单反向证明插件准入。节点被替换或代次在捕获期间变化则拒绝快照；保存后的外部文件检查和原子替换继续现门禁与 hash 校验。资源清单不复制或托管图像文件。

9.5 UI 变更集与补充验收

界面线提议 DocumentSession.Changed 于提交后发布不可变 DocumentChangeSet(EditSessionId, Revision, Origin, ChangedNodes, RemovedNodes, ChangedConnections, executionInvalidatedNodes)；节点变更含真实对象及 ChangedAspect，连接移除含旧端点。布局/样式通知与执行失效分离；同一节点配置版本替换复用 wrapper，同 ID 新实例退役旧 wrapper；结果身份仍使用 ExecutionOwner.Id。此变更集须由主线与 UI 线共同冻结，不能另建 UI 权威 registry。
