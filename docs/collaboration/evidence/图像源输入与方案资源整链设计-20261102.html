三、拟定唯一合同与职责

职责合同数据与验证生命周期与禁止项
准入与身份目录 generation + ToolId + 配置 schema 身份 + frozen settings；声明字段、类型、目的及重名均在发布前校验。请求使用 DocumentSessionId / RunId / ScopeId / NodeId / 原始 RequestId。已退役、跨代、身份不符或缺失能力一律失败，不按显示名称、程序集文件或 SDK 类型猜测；承载能力必须由同代已准入定义提供。
工具调用准备工具声明可选的调用输入准备能力：接收冻结设置与受限的宿主可用服务、资源基址、取消及身份；返回经 schema 校验的输入值和单次调用租约。IToolExecutionInputs 当前只选择/校验配置相关输入，不隐式扩成宿主采集能力；ToolCapabilities.ResourceKeys 不足以表示此合同。无该能力的 Blob 不走任何图像源分支；本地读取接纳作为受限服务发生在工具实际接受读取时。请求不得保留 UI 可变对象或完整服务定位器，准备不触发隐式运行。
资源引用声明每个工具从设置声明 field-id、标量/序列形状和 file-read/file-write/directory-read；校验 FieldId 与设置 schema 的类型匹配。由方案持久化在冻结常量上遍历；引用、表达式保留不重写并标延后。另存只重定位相对常量引用，绝对路径不改；缺文件保留引用并给诊断；错声明或错误形状拒绝且不覆盖原文件。删除现有 ToolType 硬编码；本批不实现附件打包。
宿主资源本地图像轮次管理与相机适配由宿主按受限服务提供；相机 typed snapshot 必须包含实际像素布局与 Domain。正式游标按根流程/代次/轮次，调试游标按 execution owner 隔离。借入 CameraFrame 调用方持有；自采帧在取得独立快照后释放。输入快照由单次租约释放，输出 scope 与 reader 独立，reader 可跨运行存活；失败和清理异常都保留。
结果与编辑Schema/设置/结果均来自同一准入定义；展示和编辑根据实际能力投影。用户已要求统一 VM 逆向控件；窗口事务和 UI 组合由另一完整链负责。此批不引入第二套草稿提交、旧 SDK 参数或兼容界面；共享字段、宿主消费和调试工作树只由一个指定负责人集成。
实施前冻结：能力枚举的位置、工具工厂实例创建/释放、接口版本、服务数据类型与失败诊断尚须由主线核准。先在同一设计审查中核对 Blob、ImageLoad、图像条、调试、方案保存和正式加载消费者及引用生命周期；不要先发布新接口再寻找用途。新的合同不得使 Plugin.Contracts/Runtime 反向依赖 Workflow、WPF、SDK 旧可视或具体工具程序集。

五、整批切换顺序与文件边界

  1. 主线统一冻结声明与身份合同、消费矩阵和测试构造；核对目录代次和资源所有权、与编辑窗口线协定唯一文件写者。
  2. 同一批替换 ImageLoad 工具能力、正式/调试调用与票据消费，删除 ImageSourceInvocationInputs 旧产品调用路径及 WorkflowRunRequest.SourceInputs 类型特例，转换正式调用方、调试和资源回收。不可先并入无消费者的空能力。
  3. 同批替换方案检查、恢复与另存为声明遍历；图像条、就绪与执行投影迁到新声明，解决共享编辑文件冲突后统一落地；删除旧工具名/旧 SDK 参数恢复分支。
  4. 重新构建正式 Runtime 和 Editor 组件及 Release，按同一新基线封包；验证 ImageLoad 与 Blob 的端到端、无 WPF 与 WPF 宿主；失败保留日志。旧 SDK 的错误入口退出由 Git 保存，不加回退。
