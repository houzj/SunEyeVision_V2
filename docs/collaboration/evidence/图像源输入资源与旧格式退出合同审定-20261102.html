一、已审定的真实消费者和缺口

领域现有真实入口必须保持与退出
ImageLoad 调用WorkflowExecutionManager.LocalImages.cs 生成冻结轮次 → WorkflowRunRequest.SourceInputs → WorkflowExecutionEngine → AlgorithmNode.Runtime → ImageSourceInvocationInputs；调试 RuntimeDebugInvocation → ImageSourceDebugCursor。正式游标按 workflow/generation/iteration，调试游标按 owner；节点绑定和准备值冲突拒绝；退出工具名判断、专属 SourceInputs 和旧 SDK 路径接口。
ImageLoad 本地读取ImageSourceSession.Execute 要求 input.local-address 存在，但实际打开文件使用 ILocalImageReadContext.AcceptLocalImage() 返回地址。不能改成直接信任输入字段而跳过票据；一次请求接受后推进，未接受不推进；过期身份不可调用；现有结束回调恰好一次。
BlobBlobTool 的 IToolExecutionInputs 选择/验证 ROI 等配置相关输入；WorkflowImageInputId 提供已有回退。无宿主准备能力时不调用图像源服务，不更改活动输入选择、工作流图像回退、绑定与结果资源。不得把原接口扩成隐式采集。
结果资源ToolRuntimeExecutor 拥有 session；AlgorithmNode.Runtime / RuntimeDebugInvocation 持准备输入和前驱 reader；GenerationResourceOwner 与 DeclaredOutputSnapshot 管发布结果。输入租约和输出 reader 分离。成功输出已转交后若清理失败，回收未可返回结果；直接别名只释放一次，不声称任意嵌套别名已支持。
资源/方案SolutionResourceResolver.Inspect/RebaseCopy 识别 ImageLoad 与旧 NPointCalibration；SolutionRepository.LoadCandidate 在反序列化/ValidateTools 前执行适配和资源检查。先严查现行格式/工具准入，再取同代声明检查；另存和恢复不覆盖原文件。旧参数分支随旧格式入口退出。

二、建议冻结的唯一声明合同

准入时
定义与组件身份一致；冻结输入/资源声明并校验字段类型、重复及指纹。
冻结一次调用
同代 schema、配置和 RunIdentity；受限服务与宿主游标共同形成请求。
准备与执行
值合并冲突拒绝；工具真正读取才消费票据；租约贯穿执行。
结束与排空
会话、输入租约、回调和 reader 按各自归属释放；结果租约另持代次。
声明/动作精确语义
HostInputDeclaration（提案）每个具备宿主输入的已准入定义提供稳定能力 ID/版本、可产出的 input port ID 和 TypeRef、所需受限服务身份；声明须不可变、确定性排序、无重复、字段确属 Describe().Inputs 且类型相同。运行时值只允许声明的子集；输入与绑定重复一律拒绝。
ResourceFieldDeclaration（提案）每项含唯一 settings field ID、目的 FileRead/FileWrite/DirectoryRead 及标量/序列；只能对应 IToolSettingsFields.SettingsSchema 的 Text 或 Sequence<Text>，shape 与声明严格一致。ImageLoad 的 local.paths 与 local.selected 为 FileRead 文本序列；Blob 当前无需声明资源路径。不能拿 Capabilities().ResourceKeys 或字段显示名推断。
声明指纹与工厂目录发布时冻结声明及规范指纹，与 ToolId、组件身份、运行/设置 schema 指纹共同绑定 generation；RuntimeDirectorySnapshot.CreateDefinition 每次创建后重核全部指纹。声明校验失败不发布半代次。能力实现仅能从已准入定义获得，不扫描任意 DLL。
准备与作用域独立准备接口接收不可变设置/身份、已校验的输入需求、取消令牌和只开放该声明列出的受限宿主能力；返回 schema 校验的字段子集、只读单次调用能力和可异步结束的租约。Contracts/Runtime 不依赖 Workflow、WPF 或旧 SDK；宿主相机/本地序列适配放基础设施，由受限服务执行，不把服务定位器或 UI 对象传入工具。
本地接纳保留当前 AcceptLocalImage 的实际读取边作为新声明能力的语义：一次同身份接受返回实际地址；未接受不消费；接受后失败/取消不撤销；重复请求幂等；退役/取消/跨代迟到不可接受。input.local-address 与接纳地址如何消除重复或严格一致由同批工具/调用方唯一决定，不保留两种读取语义。
准备/执行/清理准备失败不得进入算法，已获得资源逐一释放；冲突在调用前报错。正式和调试共享准备契约但使用独立 cursor owner。完成回调需至多一次；取消时禁用迟到回调并排空；清理异常不得掩盖主异常。前驱 reader、相机借入/自采帧、输入快照、输出 scope 和 generation lease 的所有者/释放顺序分别验证。
字段策略仅 Constant 设置可按声明检查和重定位；绝对路径原样、相对路径按方案基址；空字符串沿现行规则保留；不存在读资源记录警告并保留引用，FileWrite 不做存在性判失败。Reference/Variable/表达式不擅自改写，保留并标延后；声明或 JSON 形状错误拒绝、源文件不变。
开放但必须实施前裁定：1）实际能力类型名、版本及有限宿主服务契约由主线与 Blob/图像源一起定；2）同一请求重试和 receipt/owner 的精确转移表需以既有自研行为测试锁定，不能冒称 VM 并发语义；3）当前本地地址重复字段如何唯一化；4）直接别名已测，第三方嵌套别名及未实装硬件不扩展；5）设备/图像引用表达式的后续支持未证。以上均不可通过旧链回退掩盖。

SolutionRepository.LoadCandidate / ReadFrozenCandidate现行代码先 SolutionCompatibilityAdapter.Prepare、Inspect，后 ValidateTools；调整为先版本/结构及同代目录验证，再在同代快照内构造严格候选并按声明检查。旧版本、缺版本、旧字段和旧别名明确拒绝；源文件零写入，不扫描历史自动转换。
SolutionSnapshot.PrepareJson/PrepareSession / 保存只从本会话捕获一次不可变快照，严格核查现行格式和已准入工具后才进行 SolutionFileCommit；写目标/恢复备份的失败继续保留原哈希和旧备份，不复用旧转换逻辑。
SaveAsSolution、CopySolution、RebaseCopy源（包括非当前方案）先按当前格式和目录完成校验，再按声明克隆/重定位、原子创建目标；验证失败源及既存目标均不变，后续切换失败只回滚本次创建目标，原会话不切换。
RestorePreviousSave只接受同现行格式、同方案身份及当前准入目录的恢复候选；通过资源与结构检查后方可原子替换；错误/旧备份保留当前方案与备份两者字节。
LoadMetadata、ApplicationDataLocationService、UpdateMetadata纯目录扫描发生在目录未准入前，只可严格校验格式头及元数据；不把元数据成功作为工具完整准入证明。任何会改写方案的元数据入口须执行完整现行格式、身份和准入验证，避免绕过旧格式拒绝并覆盖文件；不可用项安全展示诊断或跳过，不能伪装已打开。

不能盲删现行校验：SolutionCompatibilityAdapter 同时负责重复键、未知字段、身份和连接、设备与变量形态校验；SolutionLegacyBindingMigration.Prepare 在非旧格式也调用 RuntimeInputBindings.Validate。将现行规则迁入唯一严格验证器，删除旧版本归一、别名/默认补丁和格式提升，再退出旧类；不能因类名含 Legacy 而丢失有效验证。新现行磁盘版本号由主线在共享合同冻结时确定，旧版本不得兼容读取，也不得伪装成新版本。
