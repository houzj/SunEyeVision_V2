1. 同一套公开合同，两种引用方式

Contracts 与 Wpf 保持两个 DLL，不合成一个 DLL。未来可以统一打成一个开发包分发；包内依然保留分层程序集和完整传递依赖。纯 Runtime 工具不因开发包的存在被强制引入 WPF、HALCON 或窗口宿主。

2. 公开与内部边界

角色允许的直接依赖约束
工具 RuntimePlugin.Contracts；按算法需要的中立适配层和算法依赖输入、参数、能力和输出由公开声明表达。不得引用 UI/App、Application、Execution、Persistence、旧 Workflow 或旧 Plugin.SDK。
工具 WPF 组件本工具 Runtime、Plugin.Wpf；其公开签名所需的合同依赖专属界面通过公开工厂与编辑呈现合同接入，不反向取得宿主内部服务或会话实现。
Plugin.Editing.Wpf是否属于公开开发面，按实际公开接口及传递签名审定不因它存在就要求所有工具引用；宿主内部编辑适配不无差别加入开发包。
框架宿主内部应用、执行、持久化及基础设施按组件声明、能力和身份提供输入、变量、设备资源与结果消费；不按具体工具名或具体工具类型写接入特判。
