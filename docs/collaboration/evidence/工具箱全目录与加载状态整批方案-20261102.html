工具箱：完整目录与真实加载状态

用户决定：完整 VM 工具目录显示，未实现或加载失败变暗禁用。本文是 UI 整批方案，候选已在独立工作区集中实施、正在验证；只复用现有数据源，不扩展插件基础，Group 新增迁移暂停。

现有数据与证据

来源已核对事实不能推断
VmToolCatalog.json15 类、143 项、21 条非空 ToolId 映射，当前映射无重复，143 个图标文件存在；vm-catalog-provenance.json 记录还原目录来源。文件存在不等于来源覆盖所有原厂版本或映射准确，更不等于工具已部署。
ToolGroups.xml15 个预置分类、排序及 normal/hover 资源；asset-provenance.json 保留来源与 SHA。分类声明不代表存在 Runtime。
product/ToolComponents.props本基线产品声明 ImageLoad 和 BlobAnalysis 两个 Runtime，均配 Editor。清单是构建配置；当前进程真正准入或失败状态仍以运行目录/注册结果为准。
ToolDirectoryCatalog / ToolRegistry目录只收已准入运行组件；ToolRegistry.GetToolMetadata 可能失败；启动准入失败时目录可能为 null。缺目录不代表分类和 VM 图标应隐藏；启动错误也不能误判成可执行。
VM ToolBoxData.cs / ToolBox.xaml.cs分类来自各 ToolGroup.xml，悬停/展开时按目录 ToolItemInfo.xml 惰性读取；折叠、来源变化会清理项事件。此为静态证据。目录存在与加载成功不是同一状态；本方以用户确认的完整目录显示规则为准，不声称原厂内部实现与本方相同。

状态显示操作与原因
无 ToolId 映射原件图标 + 名称、变暗禁用；说明“未实现/未映射”。
映射但未部署／目录不可用同上禁用；区分未部署与目录不可用，不冒称加载失败。
已准入但元数据/加载失败同上禁用；显示失败原因，失败不可进入拖放或执行路径。
已准入且获取元数据成功原件图标正常启用并使用唯一正式 ToolId；目录/注册状态更新须检查旧快照失效。
实际组件不在 VM 清单待现有组件和产品策略核查不静默丢失：真实已准入组件在其分类以“已部署，未匹配目录”独立显示并使用自身正式身份；未核 VM 原条目仍禁用，绝不凭名称关联。

完整验收出口

紧凑/展开及跨间隙悬停，15 类/143 项在目录 null、有两工具、部分加载失败情况下的显示与排序；启用态与两种禁用原因，工具项点击和拖放、右键三入口一致；恢复/失效后无陈旧可操作项；运行/编辑锁定、图标及亮暗主题；异常不会向插件发误用请求。真实 WPF 宿主、完整目录与模拟目录验证，用户人工验收及主线集成单列。既有测试中对旧 ToolDirectoryCatalog 构造签名的断言需先评估是否仍适用，不以陈旧断言冒充现行事实。

已将两条由原件和产品源码确认的 ImageLoad、BlobAnalysis 映射标注可用，其余 19 条尚未确认且保护禁用；143 项目录对全部原厂版本的覆盖、后续组件映射仍需核验。现有插件目录没有变化通知；目录替换后旧引用在操作入口拒绝，分类重新交互时刷新；已打开页面不承诺即时自动变暗。以上不要求为本批开发插件基础，缺证和缺基础标注占位。
