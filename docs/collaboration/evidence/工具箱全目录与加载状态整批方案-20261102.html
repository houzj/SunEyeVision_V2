现有数据与证据

来源已核对事实不能推断
VmToolCatalog.json15 类、143 项、21 条非空 ToolId 映射，当前映射无重复，143 个图标文件存在；vm-catalog-provenance.json 记录还原目录来源。文件存在不等于来源覆盖所有原厂版本或映射准确，更不等于工具已部署。
ToolGroups.xml15 个预置分类、排序及 normal/hover 资源；asset-provenance.json 保留来源与 SHA。分类声明不代表存在 Runtime。
product/ToolComponents.props本基线产品声明 ImageLoad 和 BlobAnalysis 两个 Runtime，均配 Editor。清单是构建配置；当前进程真正准入或失败状态仍以运行目录/注册结果为准。
ToolDirectoryCatalog / ToolRegistry目录只收已准入运行组件；ToolRegistry.GetToolMetadata 可能失败；启动准入失败时目录可能为 null。缺目录不代表分类和 VM 图标应隐藏；启动错误也不能误判成可执行。
VM ToolBoxData.cs / ToolBox.xaml.cs分类来自各 ToolGroup.xml，悬停/展开时按目录 ToolItemInfo.xml 惰性读取；折叠、来源变化会清理项事件。此为静态证据。目录存在与加载成功不是同一状态；本方以用户确认的完整目录显示规则为准，不声称原厂内部实现与本方相同。

临时节点与正式节点的额外差异

原件 ToolItemGrid 创建 DiagramItem 并为其设置 VmModuleDecorator，预览与画布节点走同一原件节点类型。当前 WorkflowDragDropHandler.ShowTempNode 手工组装 Border、Image、TextBlock，图标来自 ToolItem.IconSource；正式画布的 VmNodeItems 使用 WorkflowNode 数据模板，图标通过 ToolNodeIconConverter 按 ToolType 查询目录。因此两者的模板、图标解析、全局序号和状态表现并非同一实现，不能称为完整原件移植。已依据原件 ToolItemGrid.cs、diagramitemtemplate.xaml 和 VmModuleDecorator.cs 把预览接入正式 VmNodeItems 数据模板：使用仅展示的临时 WorkflowNode，隐藏序号、使用工具名和正式节点图标转换器；不加入方案、创建运行组件或写入撤销历史。图像源和 Blob 原件预览均为 110×30、整体透明度 0.7；预览坐标、热区条件、图标来源和 DPI 像素一致仍需同态核验，不能声称全链完成。独立 Release WPF 宿主测试 4 项通过（toolbox-preview-visual-20261102.log），包括实际渲染树中的名称和隐藏序号、重复拖动会话及画布进出事件；自然 OLE 拖放仍未验证。

分类会话补充：本方 Open 在分类 Enter 或焦点事件发生时重复设置同一 SelectedCategory，会重建 Tools 集合；如果焦点路由从工具项回到分类，可能移除已按下的拖动源。现对相同分类保持集合和控件身份，同时在退出或不合格按下时清理待拖动状态；实际焦点路由是否触发过该竞争尚未取得运行证据，属于风险修正，不能断言是用户故障根因。对应回归已准备，待统一构建。
