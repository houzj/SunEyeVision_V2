几何与 SDK 边界

Workflow/Workflow.cs 的连接持有 System.Windows.Point 路径与箭头等状态；WorkflowNode.cs 暴露 Point 位置。应逐项区分持久化布局坐标与纯视图临时几何，领域只保中立坐标值及可持久数据，WPF 点、路径、箭头和命中在 UI 转换；迁移须同步序列化、复制和手动路径历史。不能直接删除路径或把新 Point 名称当中立实现。

SDK 退出候选仍有非视觉设备/日志/查询类型消费；SDK 可视删除不等于所有 SDK 公共模型都应搬走。逐一按用途迁到正式合同或适配实现，确认调用方和资源生命周期后删除旧入口；不保留旧 SDK 模型的别名或反射回退。

实施依赖与唯一负责人建议

  1. 主线先冻结方案/流程身份、可信目录代次、变更/历史版本、运行与结果 reader 所有权、相机租约和失败合同；应用与领域同一批切换，不以 UI 另造接口自证。
  2. 领域线负责工作流模型、执行与持久化中立类型及算法；应用线负责方案会话、图命令、执行编排和结果会话唯一合同；UI 线负责 Shell/Canvas/编辑器/视觉与其适配；设备线负责相机资源提供。公共合同由主线指定唯一写者，其他线只按已固定签名接线。
  3. 先以根流程图操作 + 编辑/保存 + ImageLoad→Blob 真实运行贯通首批，再切显示/相机桥。各批覆盖可回滚、重做、取消关闭和资源排空；不以编译或少量单元测试代替生产宿主。
Group / 循环继续暂停且原源码保留；通信旧绑定、连续/停止等缺基础入口按现有受保护占位，不扩展。当前文档是可审查边界，不代表迁移完成；按原计划回填已实现/待实现及设计器、人工与真实硬件未验。
