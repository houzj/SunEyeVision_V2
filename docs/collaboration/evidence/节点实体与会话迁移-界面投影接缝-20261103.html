节点实体与会话迁移：界面投影接缝

设计审计 · 2026-11-03 · 主线基线 95ba00f6f；与本工作区 8e84f8622 的相关源码差异仅 WorkflowJsonConverter 有限值检查。本文是拟议设计，非 VM 原件内部机制；不修改产品/Release，Group 暂停。

一条权威，两个生命周期

方案 DocumentSession
SessionId + 可信目录代次
→
唯一 Domain 流程/节点/连接
定义、配置、布局及持久身份
→
UI 会话内投影
引用同一实体，持有纯界面状态
正式执行 owner / 当前节点实例
→
现有 WorkflowContext 结果与 lease
→
现有 NodeResultManager / 结果视图借用

投影不是第二份可写定义：名称、坐标、启用、路径、配置、引用的 getter 读取唯一实体；写入只经应用命令/DocumentSession，提交成功后投影响应变化。选中、悬停、拖动预览、视口只属 UI；不为它们新建节点注册表或结果仓库。同方案/同流程 ID 不是实例资格，替换或删除重建时旧实例与旧回调必须退役。

现状：真实持有者和订阅

状态 / 唯一归属当前入口和直接写入迁移约束
定义、位置及 Runtime 配置
DocumentSession / 领域定义		Workflow/WorkflowNode.cs：PositionX/Y、Width/Height、RuntimeConfiguration、SelectedDisplayReference；Workflow.cs：连接 ID、端口和 ManualPathPoints。MainWindowViewModel.cs CreateWorkflowTab 直接 SetContent 共享集合；加载的 FromBase 若非 UI 子类会创建复制并替换，InitialPresentationMaterialization 保护替换。取消为表现而复制并替换实体的路径；原唯一实例留于会话，投影按实例创建并销毁。必须同批迁所有依赖引用相等的命令、候选、调试、保存和历史；不能仅改类继承。
节点选择/可见/编辑 UI 态
每个工作区投影		WorkflowNode.cs 的 IsSelected、IsVisible、Status、DebugWindowType/Style、StyleConfig 等混放；WorkflowNodeModel.cs 继承并用 new 转发 InputSource、LastResult、OutputCache。写入集中在 WorkflowCanvasControl.xaml.cs/WireEditing/Clipboard、NodeInteractionHandler、SelectionHandler、NodeSelectionService、BoxSelectionHandler、CanvasHelper、MainWindowWorkflowSearch 与 MainWindowViewModel / CanvasClipboard。选择可独立存在于每个工作区；样式/模板查同代目录与主题，窗口由原件编辑宿主组装。NodeStyle、WPF 类型不可进入领域；定义读写与可视状态不要形成双向镜像。
连接临时路由 / 显示
UI 每视口投影及 ConnectionPathCache		Workflow.cs 现含 Source/Target/ArrowPosition、ArrowAngle、PathData、PathPoints、PreviewPathPoints、选择/悬停/可见；ConnectionPathCache 写箭头和 PathPoints，WireEditing 写 Preview；ConnectionCreator、ConnectionDragHandler、ConnectionManager、ConnectionPathService 写端点。ManualPathPoints 是正式保存值，不是缓存。缓存复用现有计算、失效、平移与路由；绑定从投影读几何/箭头/预览。端口、正式折线只由图事务修改；移动清折点和 Undo 恢复保持原语义。
运行状态 / 正式结果
执行会话 + WorkflowContext		WorkflowExecutionManager 更新 uiNode.Status、清 LastResult/OutputCache；NodeResultManager 经执行身份 TryPublish → WorkflowContext.SetNodeResult，后者替换时 Retain 新结果并释放旧 lease；Get/Remove/Clear 管理结果。OutputBindingChangeService 与 ConnectionBindingPolicy 仍直接清节点缓存，MainWindowRootWorkspace 删除也清缓存。拆除定义中的运行/缓存字段时，上述消费者必须同批改为应用事件及同一 WorkflowContext；只对真正执行输入/依赖变化退役受影响节点与下游，不能因布局/显示风格变更退役。
输入列表 / 预览资源
会话内 ImageInputSource + 图像条		WorkflowNodeModel.EnsureInputSource 从 ImageSourcePolicy 正式字段创建源；MainWindowViewModel.UpdateDataAnalysisControl/输入源逻辑选择并绑定；MainWindowImageSourceEditing 经配置写入事务；ImageSourceStripSession 订阅源和每行、缓存缩略图，Dispose 对称解绑。正式文件引用/当前配置只由会话持有；图像条游标、缩略图、挂起导入属 UI/输入会话。切换、删除、重开取消后台回调并释放缩略图；不把 Bitmap 或 reader 写入 Domain。
正式/私有结果呈现
视图借用，绝不成为执行源		MainWindowResultPublication 捕获方案、节点、流程、输出选择代与真实 snapshot；ResultWorkspacePresenter、ResultImagePane、ToolResultViews 按 publication 和 reader 保活；ProductionEditorContext 拥有私有 DebugOwner / DebugResults，MainWindowRuntimeEditing 在关闭恢复生产。私有调试、正式运行、历史结果身份不能互换；编辑窗口关闭、切节点、重开和迟到回调按 session、实例、owner 和实际快照核对，按借用→释放顺序关闭。

订阅、写入和刷新顺序

  1. 打开：DocumentSession 通过可信目录原子接纳方案 → 为当前流程每个实体实例构造轻量投影 → 订阅其定义/集合变化 → 与 tab、图层、Source 列表绑定。投影建立不得替换定义、改变 Dirty 或运行历史。
  2. 图手势：视觉鼠标坐标与临时预览 → 唯一应用命令，带当前 session/流程/实体实例和事务版本 → 验证全部节点、边、路径与自动绑定 → 原子应用 → 一个正式历史条目 → 发布变更及影响集 → 投影更新，ConnectionPathCache 对相关节点/边标脏。失败恢复图、配置、手工路径和序号，无半发布。
  3. 配置与 CurrentValues：编辑器保持现有 ProductionEditorContext 和唯一 DocumentEditSession 草稿/提交。正式运行在 owner、当前实例、冻结配置身份及运行门禁内，对当前 store 与 prior 配置对象做安装 CAS；不得按运行开始时的 CurrentValues 引用/修订号错误拒绝后续运行。私有草稿按打开时字段 revision+值，与正式值三方合并，同值允许；未确认或非同代拒绝。运行接受不进入 Undo，历史恢复保留运行当前值。
  4. 结果：正式执行依赖变化/删除先退役节点执行身份及下游，再替换/释放 WorkflowContext 所持 reader；已借 reader 用自己的 lease 存续直至释放。纯移动、手动路径、缩放和样式不退役生产结果；绘制预览只刷新视觉。新私有调试可暂时投影私有快照，关闭只在仍为当前节点/流程/会话时恢复正式快照并退役私有 owner。
  5. 切流程/方案或关闭：先阻止新命令与迟到回调，解绑节点/连接、图像条、编辑器和结果视图订阅并释放各自借用；运行停止/排空后由会话回收源和目录。关闭取消或失败保留原会话和资源，绝不强卸载在用 reader。

订阅与缓存核查点

WorkflowTabViewModel.SetContent 更换节点/连接集合并重建命令；WorkflowCanvasControl.GeometryTracking 对集合、每节点/边 PropertyChanged 做绑定和解绑。ConnectionPathCache.SubscribeToNodes 当前以匿名处理器订阅集合，后续切换投影时须明确可解除订阅或由其宿主寿命约束，不能假定销毁一定完成。ImageSourceStripSession 同时订阅源与行并在 Dispose 解绑；迁移需测删除、重复打开和迟到事件。MainWindowDocumentHistory 监听历史、安装 BeginHistoryMutation 门禁，并根据 LastInvalidatedNodes 退役结果，不能将所有历史事件当执行配置变更。

旧 OutputCache / LastResult 在节点上的用途需逐个消费者核实后退役；现有 WorkflowContext 已拥有正式结果及 lease，不再创建新的同义缓存。当前旧缓存引用不等于正式执行结果所有权。
