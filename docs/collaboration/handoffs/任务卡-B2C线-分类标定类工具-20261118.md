## 二、强制工作流

> 用户强制门槛：先原厂取证 → 差异确认与实施设计 → 实施 → 测试 → 真实程序自测 → 中文提交。取证未完成不得编码。

1. **自主原厂取证**：读 `_reference-codex/site/工具/<原厂页>.html`、`decompiled/ModuleControls/<原件>/`、`tools/<目录>/` evidence.json / parameters.json / algorithm-semantics.md。固定 UI 面字段、页签、分组、结果列；标定类额外记录坐标相关字段语义（即便未确认也登记为未确认）。结论附路径 + 方法/行号；未确认项单列。
2. **独占资源纪律**：动态/native 取证同一时间只允许一条线占用，开跑前在交接单登记占用时间；静态自行阅读。
3. **UI 对齐设计**：对照 ToolboxDisplayCatalog.json、zh-cn.xaml、"新工具基线清单"，定 UI 面。UI 按 VM 原件迁移，不自行近似绘制。
4. **实施范围**：分类类仅对已取证充分的做 UI 骨架（Runtime + Wpf）；标定类本阶段不建 Runtime 算法实现，只输出 UI 设计稿与依赖清单。
5. **测试/自测/提交**：分类类按完整闭环（含 agent-desktop 真实程序自测）；标定类本阶段产出设计与依赖清单即可，不声称完成。
6. **提交**：中文 Conventional Commits，message 写 UTF-8 文件后 `git commit -F`。
