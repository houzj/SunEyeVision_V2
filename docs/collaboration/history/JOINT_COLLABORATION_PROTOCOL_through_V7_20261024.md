# 自研与 VM 取证协作协议

版本：2026-10-24 / V7。范围：SunEyeVision_V2 与统一 REA/VM 取证项目。tool-plugins 仅保留历史证据与交接资源，不再独立派工。
状态：自研主控本地采用；其他对话接收和采用状态单独登记，文件落地不等于全员已接收。

## 交付经理的计划与交付责任（V7，优先于历史条款）

交付经理对已批准范围内的计划兑现和验收收口负责。派工、转发、登记和催促是手段，不能作为任务完成的依据。

- 派工必须明确原任务ID、责任人、输入依赖、交付物、验收条件、目标完成时间及下一检查点。执行者应反馈可行性和估算依据；无法可靠估时的任务须给出调查时限和重新估时节点，不得长期填写“工作中”或“待定”。
- 管理完整交付的依赖和关键路径，先推进就绪任务。维护整体交付预测及其假设，不以单个测试包的时间代替整体时间，不通过缩小范围或降低标准兑现时限。
- 发现预计延期即主动协调任务顺序、输入、资源及修复复测。保留原目标、偏差、原因、处理措施、新预测和对最终交付的影响；不能覆盖旧时间或只顺延截止时间。时间要求不能替代真实测试与验收。
- 唯一进度总账为 `docs/collaboration/DELIVERY_LEDGER.json`：沿原批准ID记录未开始、实施中、已实现待独验、独验中、已验收、阻塞；证据不足的单列待核。排除项不进入交付分母。子测试和有限缺陷不等于原整项已验收，状态引用各责任人的权威证据。
- 对任务持续负责至固定源码与产物、独立验收、缺陷复测、文档同步及审核材料齐备；收到不等于核收，构建通过不等于交付通过。开发与测试直接协作，交付经理核对下一动作确已发生。
- 对话和主文档同步汇报同一事实：总范围及状态数量、本次实际变化、关键剩余任务及负责人/时间、偏差与处置、是否具备最终交付条件。检查点、重大偏差、验收结果或交付节点到达时主动汇报，不只提供文档路径；无新结果不重复发送流水。
- 主控保留架构与范围取舍、决策审批和最终审核；普通排障、缺输入、排队和跨角色协调由交付经理处理。涉及范围、验收标准或重大风险取舍时，携事实、建议和时间影响升级，不自行修改授权。

本条完善既有岗位职责，不新增角色、批次、产品范围或定时任务。

## 1. 指挥关系

用户决定产品目标、优先级和重大架构取舍；主控负责方案设计、决策审批和最终审核；交付协调负责已批准范围的日常派工、依赖、送验、修复复测与文档同步。用户直接向其他对话下达的明确指令优先，冲突必须报告，不擅自覆盖。
VM取证负责人统一组织有范围的源码与实机取证，覆盖所有工具插件；插件项目退出独立供给。各成员可按用户已授权分工直接交接和反馈，不自行扩大产品范围或新增批次。
主控可在用户已授权的范围内安排任务；跨聊天消息必须有用户明确授权。本协议不单独视为向全部对话发消息的授权。无授权时使用本地任务卡，由用户交付或明确授权发送。

## 3. 按开发问题取证，不以整项目恢复为前置

先查自研源码、官方开发文档和现有逆向产物，再提出会影响设计决策的未知问题。
逆向深度依次为：接口/行为确认、局部函数链、必要的跨模块链。能回答当前问题即停止；原生间接调用等确需扩大范围时，报告第一断点、影响和新增范围，由主控在授权范围内决定。
任务必须区分证据提取、恢复软件实现、自研产品实现；取证任务默认不承担后两项。不得用命名、截图、常识或恢复项目测试代替原版代码证据。未知不得写成VM不支持。

## 4. 任务卡最低字段

每批唯一taskId，并登记：需求/待决策问题、请求方及执行对话、优先级、基线提交或dirty文件SHA、输入材料、允许读写目录、禁止事项、要求的函数和调用链、交付材料、验收标准、停止条件、依赖及下一责任人。
每次只安排有限批；不得自动递归下钻。若投入界限已到但证据未齐，交付已证明内容和精确断点，不伪造完成。已有同问题任务复用原编号，避免重复派发。

## 5. 证据包及闭环

证据包包含原始程序集/版本/哈希、类型/方法或原生地址、反编译实现位置、相关调用者与被调者、状态/数据变化、资源Owner及正常/失败/取消路径、可证明结论、未知和证据SHA。缺少的字段标不适用或待核实及原因。
流程：主控确定待决策问题 → 交付协调安排依赖 → VM负责人组织源码/实机取证并核收 → 统一证据交付 → 主控作设计决定 → 已批准实施与独立验收 → 自研主文档同步。
派发、接收、材料交付、证据核实、设计采用、产品实施、运行验证、文档同步、独立审核是不同状态。材料交付不自动增加核实计数；独立审核按风险和任务要求启用，不让所有小任务必须等待全员审核。
退回沿同一编号，具体指出缺项。未通过验收的材料保留，但标局限；不自动进入产品。

## 6. 设计与实施

按目标架构质量决定设计，不默认保留自研，也不默认照搬VM。每项记录：自研事实、VM原版事实、差异、选择（自研整改/借鉴重做/混合/新增/暂不能判断）、依据、代价、合同和验收用例。迁移步骤与目标设计分开。
讨论和文档授权不等于产品改动授权。需要用户确认的架构批次确认后才写产品。自研只采用适合自身需求的设计，不依赖VM加密狗或直接迁移厂商二进制。
按AGENTS执行构建和相关运行验证；手工、设备、设计器或ABI验证未执行必须单列，不能被静态检查或文档验证替代。

## 7. 汇报与退出

每轮报告本批任务已验收数/固定总数、本轮增量、证据已核实/部分/未核实数、产品实施及验证数、文档同步水位、阻塞及下一责任人。分母变更须说明，不将三项目不同分母平均为总进度；没有冻结总分母时明确总完成率不可计算。
分析交付、关键证据闭合、产品实施分别统计。任务验收满足即结束；待后续需求项进入待办，不因此无限续跑。无定时任务、无后台轮询、无跨对话自动级联。

## 10. 按复杂度自主使用子智能体（用户授权，2026-10-22）

各角色可在主控已派发任务的范围内，自主判断是否使用及如何分工多个子智能体，不必逐次请求许可。简单或强依赖串行任务可单独完成；复杂且可独立核验的源码追踪、测试分析、证据复核可并行。此授权不恢复已暂停的大目标、不启动待命批次，也不授权额外创建用户对话或跨聊派生任务。

父对话是本任务唯一交付负责人：限定每个子任务输入、输出、允许读写路径、依赖和停止条件，避免重复逆向/重复构建；检查子智能体原始证据与结论，统一解决冲突，不能把子智能体自报通过直接当验收通过。按实际并发槽和任务依赖安排，不以子智能体数量衡量进度。

同目录仍只允许一个产品代码写入者，其他子智能体只读分析/评审；需要并行产品开发时遵守AGENTS，使用独立分支或Worktree，父角色审查后集成。测试/文档产物并行写入也必须独占文件/输出目录；共享构建、测试产物和运行窗口串行协调。子智能体继承本任务全部设备、配置、证据及权限边界。父对话到交接点前应收敛所有子任务并记录未完成项，停止后不得留子线自行续跑。

- 测试负责人可拆分样本、静态复核、保存/非法输入/兼容等任务，统一报告；共享UI交互串行。子任务不自动扩大业务目标或取得产品写权。
- 主控继续下一批分析或已授权开发；阻断反馈优先入修复队列，一般反馈排队。代码修订产生新构建身份再回归，不覆盖旧报告结论。
- 测试结束由主控收回报告、处理本批问题、同步文档并向用户说明闭环/未闭环原因；派工不等于验收完成。当前补充已通知独立测试角色，其他角色接收状态另记。

## 2026-10-23 测试调度纠偏：按就绪与资源派工

- 优先级在已就绪任务间适用。队首缺固定包或输入时，标“待输入”，不能独占整个测试队列、阻止已授权的后续就绪任务。
