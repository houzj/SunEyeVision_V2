## 二、agent-desktop 自测配方（已验证可用）

命令入口：`E:\SunEyeVision_V2\.tools\agent-desktop\agent-desktop.cmd`（PowerShell 里 ref 必须加单引号）

```powershell
# 0) 健康检查
& $ad status                     # 期望 accessibility=granted, platform=windows

# 1) 启动正式 Release
$exe = "d:\MyWork\SunEyeVision_V2\Release\SunEyeVision_v1.0.0\SunEyeVision\SunEyeVision.UI.exe"
Start-Process $exe

# 2) 取窗口（app_name 用 list-apps 得到的精确名，如 SunEyeVision.UI.exe）
$j = (& $ad list-windows | Out-String | ConvertFrom-Json); $j.data | Where-Object app_name -like "*SunEye*"

# 3) 抓交互树（大窗口必须给足 --timeout-ms，否则 ref 不唯一）
& $ad snapshot --window-id <id> -i --compact --timeout-ms 8000

# 4) 语义点击（按钮/列表项等有名字的元素）
& $ad click '@sX:e6'             # 例：欢迎页最近方案条目

# 5) 画布节点等“同名同卵”元素：ref 无法区分（AMBIGUOUS_TARGET），
#    改用 include-bounds 取屏幕坐标后物理点击。
#    关键：focus-window 与 mouse-click 必须写在同一条命令里，分两次调用会被其他窗口抢走焦点，点击落空。
& $ad snapshot --window-id <id> --include-bounds --timeout-ms 8000   # bounds 已是屏幕坐标（窗口在 0,0 时与截图 1:1）
& $ad focus-window --window-id <id>; Start-Sleep -Milliseconds 400; `
  $ad mouse-click --xy <中心x>,<中心y> --count 2 --headed            # 双击打开参数页

# 6) 取证据
& $ad screenshot --window-id <id> <输出.png>
```

**已知限制（当前）**：
- 画布节点在无障碍树中是 `CanvasNodeProjection` 同名行，语义 ref 不唯一；必须用坐标物理点击，且**坐标以截图为基准重新校准**（窗口位置变化会使缓存坐标失效）。
- 参数页是否成功打开，以 `%LOCALAPPDATA%\SunEyeVision\Logs\suneye.log<日期>.log` 中 `ToolWindow stage=CreatePresentation` / `参数页组装失败` 判定，不只看截图。

## 三、REA 取证配方

```powershell
$env:GHIDRA_INSTALL_DIR = "E:\SunEyeVision_V2\.tools\ghidra\ghidra_12.1.4_PUBLIC"
$env:JAVA_HOME = "E:\SunEyeVision_V2\.tools\jdk25\jdk-25.0.5.0.2+1"
# 托管程序集：先判是否托管
rea inspect-managed-artifact <dll> --format json      # classification.status
# 非托管：导出表 → 目标函数反编译
rea inspect-native-exports <dll> --format json
rea decompile <dll> <addr> --format json
# 托管源码级：ILSpy（已安装 ilspycmd）
ilspycmd -p -o <输出目录> <dll>
```

- **人工验收统一使用主仓 Release**：`D:\MyWork\SunEyeVision_V2\Release\SunEyeVision_v1.0.0\SunEyeVision\SunEyeVision.UI.exe`
- 其他 worktree 的 Release 只用于本线自测，不作为交付或人验依据
- 交付时须写明构建时间与提交号，人验前先核对是否为主仓最新构建

## 五、判定标准（任一条不满足即未闭环）

1. 构建：全量 Release 0 错误
2. 单测：该工具测试项目全通过
3. 真实程序：工具箱可见 → 拖入画布 → 参数页可开且无 `参数页组装失败` → 结果显示正确
4. 日志：无新的 ERROR、无兜底告警
5. 证据：截图/日志片段写入交接单，commit 已产生

## 七、呈现层五项契约（运行时崩溃的四种已知原因）

| # | 契约 | 缺失后果 |
|---|---|---|
| P1 | 参数页实现 `IToolSettingsViewReady`（`ReadyTask => Task.CompletedTask`） | 宿主就绪判定缺失，生命周期错序 |
| P2 | 绑定前设 `InputSection`（有图像输入时必填） | `An input content section is required.` |
| P3 | 图形分组字段 `DialogGroup`+`DialogTitle` 同时给，`visible` 设 `DialogPrimary` | `A grouped style requires an explicit group and title.` / 启动失败 |
| P4 | 分组内字段被 `GraphicDisplays` 完整消费 | `图形角色必须完整消费分组，不能遗漏或隐藏额外字段。` |
| P5 | `DecimalPlaces: null` 的坐标字段用 `TextDisplays` 注册为文本坐标；释放用组合式 Dispose | `不限固定小数位仅适用于原订阅同槽数值文本。` |

## 八、队员自检的边界（能做什么、不能做什么）

**允许**
- 读本工作树内一切代码与文档、原厂反编译证据（静态取证自行完成）
- 在自己工作树构建、跑测试、改自己工具的代码与测试
- 用 agent-desktop 对自己工作树的 Release 做**单工具冒烟**（打开参数页→切页签→关闭→看日志），但必须在交接单登记"占用开始/结束时间"，同一时段只允许一条线占用
- 提交到自己的分支

**禁止**
- 改 `src/**`（含 `Plugin.Wpf` 公共控件）、改其他工具目录、改 `.gitignore`、改主仓任何文件
- `git push`、`git merge main` 到主分支、改写他人提交历史
- 用"经验/标准语义"替代取证；把未确认项写成已确认
- 自检未过就汇报"已完成"；或跳过 S3/S4 用"编译应该没问题"替代
- 同时跑 Ghidra / 原厂程序动态取证（独占资源，需登记并与他线错开）

## 九、主线验收（与队员自检分开计）

队员自检通过 ≠ 合并通过。主线在合并前必须完成：
1. 集成后全量 Release 构建 0 错误
2. 全部测试项目通过（列出总数）
3. agent-desktop 冒烟：新工具参数页可开、三个页签可切、关闭不崩、状态栏与日志无 ERROR
4. 账本记账 + 提交合并
