# VM 同构 UI 完整链路差异与优化方案

日期：2026-11-18  
证据基线：VisionMaster 4.4.0 Build20250516 反编译程序集、XAML、资源清单和已采集运行窗口

## 结论边界

当前自研软件已经具备统一窗口入口、声明式参数 schema、WPF 参数行、结果声明和工具插件准入。现状与 VM 的差异集中在对象边界、参数根组装、原厂模板资源、复杂工具专用窗口和生命周期归属。现有证据足以确定迁移边界和实施顺序，不能据此推断尚未取证的动态算法行为。

VM 原厂是经过测试的标准答案。每项代码修复必须先绑定原厂源码、配置、资源或运行证据。没有证据的行为保持 `EvidenceBlocked`，禁止用自研等价行为冒充原厂。

## 端到端链路对照

| 链路层 | VM 原厂证据 | 当前自研实现 | 已确认差异 | 优化方向 |
|---|---|---|---|---|
| 工具准入 | 工具模块程序集、`ModuleParam`、工具资源和 `AlgorithmTabRoot` | `PluginManager`、Runtime/WPF 插件登记、工具 schema | 自研登记已统一，原厂模块资源和控件根尚未完整映射 | 建立工具级证据清单，登记程序集、资源字典、根控件、页签和动态证据 |
| 窗口根 | `ParamsTabControlBase`、`AlgorithmTabRoot`、原厂 `BaseWindow` | `RuntimeToolEditorWindow`、`NativeToolEditorFrame` | 原厂参数根同时拥有页、分组、外部参数、底栏、帮助、订阅和释放，自研由窗口、参数视图、工具组合对象分担 | 建立 `NativeToolWindowRoot`，统一 Owner、窗口命令、关闭排空、帮助、进度和释放 |
| 参数 schema | 原厂参数对象、`NameValueItem`、`FieldType`、`GroupLinkItem` | Runtime `ToolSchema`、`FieldPresentation`、`FieldLayout` | 自研声明已结构化，部分原厂展示类型、父组克隆和动态键语义还没有一一映射 | 将展示类型、状态、命令、父组和动态字段作为正式 schema，不从基础数据类型推导控件 |
| 页签拓扑 | `AlgorithmTabRoot`、原厂 `ParamsConfigControlBase` 和各工具 XAML | `DeclaredSettingsView`、`DeclaredFieldsView` | 当前页组装曾依赖 `PageBuilt` 和二次 page 推导，输入页与设置页可能分离 | page/section/order 由原厂声明直接生成唯一参数根，`PageBuilt` 只做通知和探针 |
| 输入字段 | 原厂输入 declaration、`ParamListView`、ROI manager | `DeclaredInputFieldsView` 再迁移到外层字段页 | 原先形成嵌套 `ParamListView` 和第二套字段状态链 | 以 `INativeInputComposition` 输出正式字段行，输入和 settings 共享同一个字段所有者、捕获和释放事务 |
| ROI | `BlobFindRoiManager` 持有统一 `RoiManager`，通过 `InputItem.SetInputValue` 写回 | `BlobRoiUi`、`BlobLocalRoiOwner`、输入工厂和外层锚点分担 | ROI 模式、输入字段和算法回写边界曾拆开 | 统一 ROI session、输入身份、模式切换、图像借用、写回和释放代次 |
| 普通控件 | 原厂 `DataTemplate`、`ParamUserControl`、`NameValueItem` 模板 | `DeclaredFieldTemplateRegistry`、字段行和原厂资源迁移 | 公共模板已接入，工具专用模板和资源覆盖不完整 | 建立唯一 `NativeResourceRegistry`，每个模板保留原厂来源和消费者映射 |
| 特征模板 | `FeatureMatchCommonControl`、`FeaturepatMatchConfigPanalDataBase`、工具派生 panel 和独立 dialog | ContourMatch/GrayMatch/MarkFind 各自局部面板 | 公共面板、模型列表、模板 dialog 和工具适配器尚未形成统一边界 | 仅对有证据的工具建立 `NativeFeatureMatchPanel` 和 `NativeFeatureTemplateDialog`，MarkFind 保持独立 |
| 结果页 | 原厂结果树、图像预览、叠加和文本资源 | `IToolResultView`、结果声明、`ResultWorkspace` | 自研结果契约已存在，原厂结果树和图像叠加动态时序仍需工具级核对 | 每工具绑定输出树、显示资源、选择状态、叠加和结果 reader 的证据 |
| 执行接缝 | 原厂窗口通过模块会话、输入管理器和结果管理器交互 | 自研 UI 通过 draft、执行服务、结果发布回调交互 | 分层方向正确，但输入编辑、结果刷新和 UI 代次的时序还存在偏差 | UI 只提交和订阅，执行层只读正式快照，所有回调带 generation/session 校验 |
| 底栏命令 | 原厂 `HPBottomCommand`、`GMBottomCommand`、帮助和关闭命令 | 宿主窗口和工具回调组合 | 命令禁用、进度遮罩和关闭排空未完全按工具映射 | 将底栏命令作为窗口根声明，逐工具核对命令可见性和禁用条件 |
| 生命周期 | 原厂 dialog、module、ROI manager、model data 同一窗口事务释放 | `RuntimeToolEditorWindow`、`DeclaredSettingsView`、工具 composition 分别释放 | 多代次和迟到回调边界容易分裂 | 建立统一 `ToolWindowSession`，打开、绑定、提交、执行、取消、关闭、排空和释放有一套合同 |
| 异常 | 原厂对话框取消、模型回滚、输入拒绝和关闭处理有明确入口 | 自研通过异常、诊断弹窗和 draft 错误返回 | 错误阶段可观测性已增加，但不少工具仍缺入口到释放的完整探针 | 为每个窗口记录入口、模板、绑定、组装、执行、结果、关闭和释放阶段 |

## 推荐的完整实现链路

### 第一层，证据注册

每个工具建立一份机器可读证据清单，至少包含程序集、MVID/hash、XAML 根、资源字典、页签、分组、字段、模板、外部槽、底栏命令、运行截图和未确认项。没有对应证据的字段或行为不能进入 `NativeAligned`。

### 第二层，公共窗口根

实现并统一使用 `NativeToolWindowRoot`。它拥有原厂窗口尺寸和 Owner、参数根、结果根、帮助、底栏、执行会话、关闭排空和资源释放。工具只提交声明、资源身份和行为回调。

### 第三层，单一参数根

由 `AlgorithmTabRoot` 对照物生成唯一 page/section/group/row 树。输入、ROI、设置字段和专用槽都进入同一 `ParamListView` 语义。嵌套输入列表只能留在 `LegacyCompatibility`，迁移工具不得继续使用。

### 第四层，原厂模板和资源

以 `DataTemplate`、样式和资源键为主入口迁移控件。字段类型只负责数据和校验，模板负责视觉和交互。每个模板建立来源、绑定名、状态触发器、命令和释放回调映射。

### 第五层，复杂工具适配器

ContourMatch 和 GrayMatch 仅在公共面板证据成立时共享 `FeatureMatchCommonControl`。模型创建、编辑、取消回滚、加载、删除、排序、预览和模板窗口通过工具适配器接入。MarkFind 使用独立适配器。Blob 使用统一 ROI manager 语义接缝。

### 第六层，运行和结果

运行层只接收正式快照和资源引用。UI 不调度算法。结果层按原厂 output tree、图像叠加、文本和选择状态发布。输入变化、结果变化和关闭回调都必须校验 session/generation，迟到回调拒绝写入。

### 第七层，验证闸门

每个工具按以下顺序验收。

1. 静态映射覆盖
2. 原厂运行窗口和自研窗口 Tab/分组/控件对照
3. 字段编辑、枚举、数值、范围、引用和 ROI
4. 结果树、图像叠加、帮助和底栏命令
5. 执行、取消、保存重开、换节点和异常
6. 关闭退订、迟到回调拒写和资源释放
7. Release 构建和 Agent Desktop 运行验证

## 当前优先级

### P0，公共框架

- 完成 `DeclaredSettingsView` 和 `DeclaredFieldsView` 的单一参数根组装。
- 以原厂证据闭合字段模板会话、引用窗口、数值编辑和 Loaded/Layout 生命周期。
- 统一输入、ROI、结果、关闭和释放代次。

### P1，Blob

- 修复已探测到的 `ParameterFieldHost._referenceSession=null`。
- 重新验证图像来源、ROI、Mask、位置修正、结果显示和保存重开。
- 通过完整 Blob 过滤测试后再标记状态。

### P2，轮廓匹配

- 先对齐基本参数 Tab 和特征模板 Tab。
- 依据原厂 `FeatureMatchConfigPanal`、派生 panel、模板 dialog 和资源完成组装。
- 不把 GrayMatch 或 MarkFind 的未经证实结构强行套用到 ContourMatch。

### P3，批量工具迁移

按证据矩阵逐工具迁移，统一构建、脚本化运行和截图对照。每批只在静态证据、运行证据和 Release 证据同时满足时更新状态。

## 禁止事项

- 没有原厂证据时自行设计控件样式、端口交互、状态颜色或生命周期。
- 继续保留第二套参数视觉链作为最终实现。
- 把兼容回退标记为原厂对齐完成。
- 把历史 Release 构建结果当作当前未提交工作区的验证结果。
- 把静态反编译结论扩大为未观察到的动态行为。

## 最终交付状态定义

- `NativeAligned`：原厂来源已登记，静态和运行对照通过，生产链和 Release 验证通过。
- `LegacyCompatibility`：仍保留旧接缝，行为有明确范围，尚未达到原厂同构要求。
- `EvidenceBlocked`：缺少同版本原厂证据，代码和行为不作猜测。
