十工具 VM 证据驱动复核与修复计划

目标是逐工具还原 VisionMaster 4.4.0 的节点、端口、参数窗口、结果页、运行状态、连线和生命周期。每项修改必须能回指原厂证据，证据不足时登记为未确认并保持现状。

一、证据规则

等级证据支持范围
A反编译源码、程序集成员、模板和资源，含版本、文件身份及定位结构、字段、模板、绑定、状态机、调用链和资源消费
B原厂配置、ToolItemInfo、模块 XML、方案文件、资源键工具身份、字段声明、端口、默认值、组装顺序和显示资格
C原厂运行截图、Agent Desktop 观察、操作前后状态实际外观、动态交互、状态变化、窗口行为和时序

优先级为 A、B、C。截图不能单独证明内部实现。每条结论标记为 VM 已证、推断、未确认或自研假设占位。没有足以支持决定的证据，不修改产品代码。

  1. 工具身份、版本、程序集和目录
  2. 节点形状、图标、状态色、尺寸、文字和选中态
  3. 输入、输出、控制端口的方向、数量、位置和命中区域
  4. 连线创建、删除、重连、非法连接和路由
  5. 参数窗口入口、页签、分组和正式控件
  6. 字段类型、默认值、范围、枚举、引用和校验
  7. 图像、ROI、继承和资源状态
  8. 结果声明、结果树、结果显示和 OK/NG
  9. 执行前、执行中、成功、失败、取消和未执行状态

  11. 关闭退订、迟到回调、在飞等待和资源释放
  12. Release 构建、Agent Desktop 运行观察和同态截图

2 基础处理与测量ColorExtract、DivideImage、FrameMean、IntensityMeasure、PixelCount图像源、范围/枚举控件、输出声明、状态和结果树五工具完整打开、编辑、执行、显示、保存重开和释放

六、当前落地顺序

  1. 固定 main 当前提交和工作区状态。
  2. 读取 If 的 IfModule/IfBranch 反编译资料、配置和运行观察。
  3. 读取 BlobLabels 的原厂模块资料和本方完整消费者。
  4. 只对证据支持的差异做最小补丁，逐补丁构建。
  5. 启动正式 Release，用 Agent Desktop 执行固定脚本并保存观察结果。
  6. 第一批通过后进入第二批，未确认项单独登记。

七、完成定义

十个工具分别有完整证据台账、差异矩阵、精确变更、Release 构建记录、Agent Desktop 运行记录和未确认项。静态证据、自动测试、运行观察和人工视觉验收分别记录。

八、工具全表面复核

调试窗口只是参数与运行链的一部分。每个工具必须逐面核对以下入口，定位匹配类额外核对模板、模型和搜索区域生命周期。

表面复核内容证据出口
工具箱分类、卡片、图标、名称、提示、拖入/点击创建原厂配置、运行截图、创建日志
节点画布形状、尺寸、端口、命中、选中、禁用、状态、重命名、复制、删除原厂截图、Agent Desktop 操作和节点快照
参数配置基本参数、运行参数、结果判断、底栏命令、正式控件、默认值和校验AlgorithmTab、模板、参数窗口截图
资源编辑图像源、ROI、继承、位置修正、模板/模型训练、文件选择、资源替换和释放原厂配置、静态源码、运行操作和资源日志
运行界面执行按钮、连续运行、取消、状态栏、OK/NG、耗时和错误运行前后截图、日志和迟到回调检查
结果区域图像叠加、结果树、结果表、历史结果、字段顺序、帮助页Display XML、运行截图、结果快照
持久化保存、重开、复制、换节点、版本迁移和缺失资源方案文件、重开日志、字段回执
生命周期关闭、退订、在飞等待、资源释放和再次打开REA/Agent Desktop 日志、释放探针

定位匹配类 ContourMatch、GrayMatch、MarkFind 还必须单独登记模板创建、模型保存、模型加载、搜索区域、训练/运行切换、匹配结果叠加、模型文件更换和失败清理。没有这些证据时，不得以节点或参数页通过代替工具完成。

九、当前阶段的审核边界

本阶段先做单工具功能性审核。每个工具独立完成工具箱创建、节点配置、参数编辑、资源编辑、保存重开、单工具运行、自身结果查看和关闭释放。输出树、图像叠加、运行界面、帮助内容先检查单工具入口和基本可用性。

需要多个节点协作的输出消费、图像源传递、ROI/模板跨工具继承、分支联调、结果联动和完整工作流回归，等十个工具完成单工具收口后再启动。当前记录为待联调，不把它们当作本阶段缺陷。
