控件身份与统一架构链路复核

本复核不看外观相似度，只看两件事：页面是否由公共参数链组装，页面上的控件是否使用原厂对应控件的迁移件，而不是工具手写替代。原厂依据为 VisionMaster 4.4.0 的模块控制 DLL 反编译模板与运行窗口截图；本方目标结构使用 SunEyeVision 职责命名，不保留原厂产品名或品牌名。

统一链路基线

AlgorithmTab 声明 → 公共参数树/字段 → DeclaredSettingsView
→ 行模板（ParamItemStyle / ParamUserControl）
→ 专属控件只以“外部内容槽/接缝”形式挂入

结果页基线：DisplayOptionsFactory → NativeGraphicStylePresenter（原厂 ImageViewConfig 模板）。

本轮新增的共享控件：NativeCommandSelector、NativeColorRangeList，均在 src/Plugin.Wpf/Presenters/Parameters/。

命名与品牌约束

新增共享控件与数据类型使用职责命名：NativeCommandSelector、NativeColorRangeList、ColorRangeValue、ColorRangeSpace，不含原厂产品名或品牌名。

本轮同时把共享直方图控件 HikHistogramSingle 更名为 HistogramSingle（文件、x:Class、类型名同步），调用方仍只依赖共享控件。

仍保留的原厂命名：IMVS_PATMATCH_POINT_INFO、MVBPATMATCH_EDGEPOINT_OUT，属于其它批次的匹配交互结构体，本轮未改动，登记为命名债务。

结论

FrameMean 运行参数与 ColorExtract 运行参数的专属区域已从工具手写改为共享控件，并按原厂模板组合；工具层只保留命令/区间语义与提交接缝。

仍存在的差异：ColorExtract 的 RoiSelectControl 行未接入；IntensityMeasure 与 ColorExtract 的基本页 ROI 组未接入；ColorExtract 结果页缺 TextDisplayGroup。这些是接线/能力缺口，不是本轮共享控件问题。

未确认项保持登记：原厂运行窗口逐项视觉对照（本轮已补命令页与颜色页）、FrameMean 相机回调时序、ColorExtract 滑条编辑保存重开。
