# 原厂工具工程结构分析与 SunEyeVision 目标结构

> 版本：2026-11-20  
> 范围：BlobLabels、ContourMatch、GrayMatch、MarkFind、ColorExtract、DivideImage、FrameMean、IntensityMeasure、PixelCount、If，以及 ImageSource/BlobAnalysis 两个已验证基线。  
> 规则：原厂证据决定职责、数据、页签、控件、端口、结果和生命周期。本方允许的实现差异只有底层算法库。没有证据的行为标为“未确认”。

## 1. 原厂事实

### 1.1 发布目录是职责边界

VisionMaster 4.4.0 的工具不是一个只含单一 DLL 的模块。已安装模块目录中可直接观察到以下共同发布单元。

```text
<类别>/IMVS<Tool>Modu[VA]/
├─ IMVS<Tool>Modu[VA].dll
├─ IMVS<Tool>Modu[VA]Cs.dll
├─ IMVS<Tool>Modu[VA].xml
├─ IMVS<Tool>Modu[VA]Cs.xml
├─ IMVS<Tool>Modu[VA]Algorithm.xml
├─ IMVS<Tool>Modu[VA]AlgorithmTab.xml
├─ IMVS<Tool>Modu[VA]Display.xml
├─ ToolItemInfo.xml
├─ IMVS<Tool>Modu[VA]Control.dll       （有专属控件证据时存在）
├─ Librarys.Config                    （有额外依赖配置时存在）
├─ IMVS<Tool>Modu[VA]_NormalLogo.png
├─ IMVS<Tool>Modu[VA]_StateLogo.png
└─ IMVS<Tool>Modu[VA]ImageEnable.png
```

已核实的原厂目录包括：

- `Location/IMVSBlobFindModu`
- `Location/IMVSContourMatchModu`
- `Location/IMVSGrayMatchModu`
- `Location/IMVSGrayMatchModuVA`
- `Location/IMVSMarkFindModu`
- `Location/IMVSBlobFindLabelsModu`
- `Measurement/IMVSPixelCountModuVA`
- `Measurement/IMVSIntensityMeasureModu`
- `ImageProcessing/IMVSFrameMeanModu`
- `ColorProcessing/IMVSColorExtractModu`
- `SplitCombination/IMVSDivideImageModu`

目录清单是发布职责证据。它不是要求本方复制同样的程序集数量，也不是要求本方创建名为 `Algorithm.dll` 或 `Bridge.dll` 的空壳。

### 1.2 原厂单元到职责的事实映射

| 原厂单元 | 已确认职责 | 本方必须保留的职责 | 本方不应照搬的内容 |
|---|---|---|---|
| `...Modu.dll` | 算法运行单元、模块执行入口 | 工具算法入口、输入消费、结果生成、状态和错误边界 | 海康自研算法二进制和同名 DLL |
| `...ModuCs.dll` | 托管参数、结果、ROI、模块桥接 | 参数模型、结果模型、ROI/资源身份、宿主调用接缝 | 原厂私有类型名称和内部序列化实现 |
| `...Modu.xml` | 模块身份、输入输出、端口和依赖 | 工具身份、端口、输入输出和资源声明 | 只依据类名猜端口 |
| `...Algorithm.xml` | 参数身份、类型、默认值、范围和枚举 | 参数声明与默认值、边界、枚举和保存语义 | 把截图文字手工写成另一套字段 |
| `...AlgorithmTab.xml` | 页签、分组、字段顺序、模板类型、组链接和底栏 | 页签/分组声明、字段顺序、显隐、ROI、AssistGroup、命令身份 | 工具自己绘制公共参数行 |
| `...Display.xml` | 结果显示类型、结果树、叠加物和文本 | 结果声明、结果树、图像叠加和显示资源身份 | 用参数页字段推断结果显示 |
| `...Control.dll` | 原厂专属动态/复杂控件 | 只有有反编译或运行证据时保留专属 Editor 接缝 | 为普通字段另造自研控件 |
| `ToolItemInfo.xml` | 工具箱名称、分类、图标和注册元数据 | 产品工具注册、图标和分类映射 | 只注册程序集而遗漏工具箱身份 |
| `Librarys.Config` | 模块专属依赖装载配置 | 仅在本方确有对应依赖时登记适配器配置 | 把第三方库配置放进工具业务层 |

### 1.3 原厂与本方算法库的边界

原厂 `...Modu.dll` 的算法实现是海康自研库。本方使用 HALCON 或 OpenCvSharp 属于允许的实现差异。适配层负责第三方句柄、类型和生命周期接入。工具算法层可以组合多个 HALCON/OpenCvSharp 操作，但不得自行初始化、加载或释放原生库。

“能运行”不等于“算法等价”。每个工具必须单独取得固定原厂输入输出样本，比较状态、数量、数组顺序、区域覆盖、几何量、浮点误差、异常输入、空输入、取消和重复执行。没有原厂黄金样本时，算法状态只能是 `unconfirmed`。

## 2. 适合本方的目标结构

### 2.1 单项目原则

每个工具采用一个产品项目，同时承载运行、参数、结果、工具资源和有证据的专属 Editor。公共参数页、页签、ROI、AssistGroup、结果树、图像叠加、底栏和窗口生命周期继续由已验证的 `Plugin.Wpf` 公共链负责。

```text
tools/
└─ SunEyeVision.Tool.<Tool>/
   ├─ SunEyeVision.Tool.<Tool>.csproj
   ├─ <Tool>Tool.cs                 工具身份、能力、注册和运行入口
   ├─ Algorithms/
   │  ├─ <Tool>Algorithm.cs         工具算法编排，不直接管理 DLL 生命周期
   │  ├─ <Tool>Session.cs           一次执行的输入快照、状态、取消和诊断
   │  └─ <Tool>HalconAdapter.cs     （使用 HALCON 时的类型/调用适配）
   ├─ Parameters/
   │  ├─ <Tool>ParameterDefinition.cs  XML 声明加载和字段映射
   │  ├─ <Tool>Settings.cs          参数值、默认值、校验和持久化
   │  ├─ <Tool>Fields.cs             只读字段/端口投影，不绘制控件
   │  └─ <Tool>Roi.cs                ROI、继承和资源身份
   ├─ Results/
   │  ├─ <Tool>Output.cs             运行输出和状态
   │  ├─ <Tool>ResultProjection.cs   结果树/叠加数据投影
   │  └─ <Tool>Display.cs            Display 声明和显示数据
   ├─ Editor/
   │  ├─ <Tool>EditorFactory.cs      统一参数窗口的工具接缝
   │  └─ Views/                      仅有专属控件证据时使用
   └─ Resources/
      ├─ <Tool>.xml                  工具身份、输入输出和依赖声明
      ├─ <Tool>Algorithm.xml         参数身份和类型
      ├─ <Tool>AlgorithmTab.xml      页签、分组、顺序、组链接和命令
      ├─ <Tool>Display.xml           结果显示声明
      ├─ ToolItemInfo.xml            工具箱注册元数据
      └─ <Tool> 专属图片/模板         仅限原厂证据覆盖的资源
```

`Algorithms`、`Parameters`、`Results` 和 `Resources` 是工具差异边界。`Editor` 只放专属控件接缝，不得持有公共窗口生命周期。普通字段、枚举、数值、范围、引用、ROI 和底栏命令不在工具里写第二套视觉链。

### 2.2 项目依赖方向

```text
SunEyeVision.Tool.<Tool>
  ├─ Plugin.Contracts
  ├─ Plugin.Wpf                  参数声明和公共 Editor 接缝
  ├─ HalAdapter.Runtime           或 OpenCvSharpAdapter.Runtime
  └─ 第三方算法包（仅通过适配层引用）

Plugin.Wpf
  ├─ Plugin.Contracts
  └─ 公共模板、ROI、AssistGroup、结果树、生命周期
```

工具项目不得反向引用宿主 UI、不得直接创建 WPF 窗口、不得直接加载或释放第三方原生 DLL。`Plugin.Wpf` 不引用具体工具。

## 3. 原厂职责到本方文件的精确映射

| 原厂证据 | 本方落点 | 验收证据 |
|---|---|---|
| `...Modu.xml` | `<Tool>Tool.cs`、`Parameters/<Tool>ParameterDefinition.cs` | 输入、输出、端口和工具身份逐项映射 |
| `...Algorithm.xml` | `Resources/<Tool>Algorithm.xml`、`Parameters/Settings.cs` | 默认值、范围、枚举、保存重开 |
| `...AlgorithmTab.xml` | `Resources/<Tool>AlgorithmTab.xml`、`ParameterDefinition.cs` | 页签、分组、字段顺序、显隐和组链接 |
| `...Display.xml` | `Resources/<Tool>Display.xml`、`Results/Display.cs` | 结果树、叠加物、文本和状态 |
| `...Cs.dll/.xml` | `Parameters`、`Results`、`Algorithms/Session.cs` | 托管类型、生命周期、错误和回执 |
| `...Control.dll` | `Editor/Views` 的专属接缝 | 反编译类型或运行窗口证据 |
| `ToolItemInfo.xml` | `Resources/ToolItemInfo.xml`、产品注册 | 工具箱名称、分类、图标、唯一入口 |

## 4. 四批工具的目标落点

| 批次 | 工具 | 主要原厂专属边界 | 目标结构处理 |
|---|---|---|---|
| 第一批 | PixelCount、FrameMean、IntensityMeasure | PixelCount 范围列表、FrameMean 三态命令选择器、测量结果表 | 复用公共数值/枚举/范围/结果表，专属控件只保留有证据项 |
| 第二批 | ColorExtract、DivideImage | 颜色范围/通道、图像来源、ROI 和图像结果 | 复用公共图像来源/ROI/范围/图像结果模板 |
| 第三批 | ContourMatch、GrayMatch、MarkFind | 模板资源、特征模板/灰度模板/特征模型、匹配结果和叠加 | 模板资源由工具持有，公共页负责挂载和生命周期 |
| 第四批 | BlobLabels、If | 结果判定、条件输出、动态条件行和多状态显示 | BlobLabels 复用判定模板。If 只有在动态字段/端口/序列化证据闭合后接入专属动态面板 |

## 5. 结构迁移门禁

一个工具只能按以下顺序迁移，不能用“已加载”代替“已同构”。

1. 固定原厂目录快照、文件哈希和 XML/托管类型证据。
2. 建立原厂职责矩阵，区分运行、桥接、参数、页签、显示、控件和注册。
3. 建立本方单项目目录和项目依赖，保留原厂职责边界。
4. 将页签、分组、字段、组链接、端口和显示声明迁入资源驱动链。
5. 仅对有证据的专属 `Control.dll` 建立 Editor 接缝。
6. 通过公共参数页静态映射、产品注册和 Release 构建。
7. 用固定样本做原厂与 HALCON/OpenCvSharp 结果对照。
8. 验证执行、取消、重开、换节点、关闭、退订和资源释放。
9. 把仍未确认项登记到工具清单，未闭合工具不能进入下一工具。

## 6. 当前结论

- 原厂事实是“单工具发布目录内的多职责发布单元”，不是“本方必须多项目复制”。
- 适合本方的目标是“每工具单项目 + 原厂职责分区 + 公共框架承载公共 UI 与生命周期”。
- 本方与原厂唯一允许的实现差异是算法库。工具身份、参数语义、页签、分组、控件归属、端口、结果和生命周期必须逐项对应。
- PixelCount 可作为单项目样板，但当前 `goldenCases` 为空，算法等价仍未确认。四批工具不能以共享组装烟测作为最终同构结论。
- 后续代码迁移应先完成每个工具的原厂工程结构矩阵，再批量生成单项目骨架，最后按工具逐项补齐资源和算法证据。
