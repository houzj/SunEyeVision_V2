# 模块结果树「递归遍历自动生成」最终优化方案

## 🔄 改前 → 改后 → 依据

### 改前（开发者视角）
每写一个工具，要想在「模块结果树」里看到图像宽高、Blob 面积、圆心半径，就得在 `GetPropertyMap()` 里**手动平铺子字段**。比如 `ImageLoad` 平铺了十几条宽高/通道数，`BlobAnalysis` 平铺了 9 条平行数组（`BlobAreas[]`/`BlobCentroidXs[]`…）。而这些信息，对象自己本来就知道——`HalImage.GetMonitorFields()` 早就返回了 `宽度/高度/通道数`。**同一份信息写两遍，改一处忘另一处就出错。** 更糟的是 Blob 那 9 条数组在树里当前只显示 `面积: double[5]`，根本看不到每个 Blob 的具体值。

### 改后（开发者视角）
工具结果类**只声明一级变量**（`输出图像`、`Blob详细`、`是否通过`）。运行后结果树**自动展开** `输出图像→宽度/高度/通道数`、`Blob详细→[0]面积/周长/中心…`、`圆→圆心X/圆心Y/半径`。**宽高/面积/圆心全都不用再 map 映射**。加新类型只要让它实现 `IMonitorable`（或是个普通带属性对象），树就自动长出来。

### 依据
- **项目已有 `IMonitorable` 递归协议**（`IMonitorable.cs:11-18`）：注释明确定义为"递归调用 `GetMonitorFields()` 生成树，字段值可为标量/IEnumerable/IMonitorable 自身（递归）"。图像、区域、Circle2d/Line2d/RotatedRect2d 等十余类型已实现，基础设施齐备，只是模块结果树没接上。
- **VisionMaster/VisionPro 业界做法**：结果树对复杂变量自动展开子字段，开发者只声明顶层变量；子字段展开由引擎基于类型契约自动完成，不靠每工具手写平铺。

## 问题分析

### 需求拆解
- **表面需求**：节点树用递归遍历生成，不再对宽高做 map 映射。
- **根本问题**：`GetPropertyMap` 一肩挑两职（输出变量契约 + 树结构），导致复合对象的子字段既在对象内部定义（`IMonitorable`）、又在 `GetPropertyMap` 平铺，双重维护、易错、且当前数组类子字段根本没展开。
- **问题分类**：架构冗余 / 职责未分离（契约 ≠ 展示结构）。

### 架构分配检查
- 最自然归属层：UI 展示层（结果树生成逻辑）。
- 已有类似机制：**有**——`IMonitorable` 递归协议已存在且被十余类型实现，仅结果树未接。
- 不改是否可覆盖：**否**——硬编码平铺无法自动适配新增几何/复合类型。
- 是否改变分层边界：**否**——契约 SSOT 不变，仅结果树展示层改用递归。

### 方法对比（≥3 候选）
| 维度 | 方案 A（推荐·递归） | 方案 B（静态结构注册） | 方案 C（维持平铺） |
|------|------|------|------|
| 实现 | 运行期递归 `RuntimeValue`（IMonitorable→数组→反射兜底） | 注册类型→子字段静态结构 | 继续手写平铺 |
| 架构一致性 | ✅ 复用已有 IMonitorable | ⚠️ 与 IMonitorable 重复 | ❌ 双重维护 |
| 复杂度 | 低（一个递归 builder） | 高 | 低但重复持续 |
| 维护成本 | 低（加类型只需实现/反射） | 高 | 高 |
| 长期 ROI | 高 | 中 | 负 |

**结论**：方案 A。

## Bug 模式分析
- **当前问题**：子字段在 `IMonitorable` 与 `GetPropertyMap` 两处重复定义；Blob 平行数组在树中不可见具体值。
- **真因分类**：架构冗余（职责未分离）。
- **同类潜伏点**：所有 override `GetPropertyMap` 的工具结果类（ImageLoad/BlobAnalysis/Threshold/Morphology/ImageFilter…）都存在"平铺复合对象子字段"的重复。
- **治本点**：树展示结构自动从 `RuntimeValue` 派生，而非手写。系统性架构问题，非孤例。

## 解决方案

### 方案概述
将「模块结果树的展示结构」从「`GetPropertyMap` 平铺」改为「运行期对 `RuntimeValue` 递归遍历」。`GetPropertyMap` 职责收敛为**仅输出变量契约 SSOT**（一级变量），不再承担树结构描述。

### 核心原则（贯穿所有工具）
> `GetPropertyMap` 只声明**一级变量**（图像/区域/统计单值/数组对象）；所有子字段由对象自身 `IMonitorable` 描述、递归自动展开。开发期、不考虑绑定、零兼容直接砍。

### 技术方案 1：新增递归节点构建器（UI 层）
在 `MainWindowViewModel.cs` 内实现 `BuildMonitorSubtree`，替换 3934-3985 行逻辑：

```csharp
private const int MaxRecursionDepth = 10;
private const int MaxChildCount = 1000;
private static readonly Dictionary<string, string> PropertyChineseNameMap = new()
{
    ["Width"] = "宽度", ["Height"] = "高度", ["X"] = "X", ["Y"] = "Y",
};

private static ModuleResultNode BuildMonitorSubtree(
    object? value, string displayName, string? sourceNodeId,
    int depth = 0, HashSet<object>? visited = null)
{
    var node = new ModuleResultNode
    {
        DisplayName = displayName,
        IsGroup = true,
        IsExpanded = depth < 2,
        SourceNodeId = sourceNodeId,
    };
    if (value == null) { node.IsGroup = false; node.DisplayValue = "--"; return node; }
    if (depth >= MaxRecursionDepth) { node.IsGroup = false; node.DisplayValue = FormatTypedValue(value, value.GetType()); return node; }

    visited ??= new HashSet<object>(ReferenceEqualityComparer.Instance);
    if (!visited.Add(value)) { node.IsGroup = false; node.DisplayValue = "(循环引用)"; return node; }

    // 1) IMonitorable 优先
    if (value is IMonitorable m)
    {
        foreach (var (fn, fv) in m.GetMonitorFields())
            node.Children.Add(BuildMonitorSubtree(fv, fn, sourceNodeId, depth + 1, visited));
        return Finalize(node, value);
    }
    // 2) 集合（排除 string）
    if (value is System.Collections.IEnumerable en && value is not string)
    {
        int i = 0;
        foreach (var item in en)
        {
            if (i >= MaxChildCount) { node.Children.Add(new ModuleResultNode { DisplayName = "…已折叠", IsGroup = false, DisplayValue = "超过上限" }); break; }
            node.Children.Add(BuildMonitorSubtree(item, $"[{i}]", sourceNodeId, depth + 1, visited));
            i++;
        }
        return Finalize(node, value);
    }
    // 3) 反射兜底（外部类型如 OpenCvSharp.Size：Width/Height）
    var props = value.GetType().GetProperties(BindingFlags.Public | BindingFlags.Instance)
        .Where(p => p.CanRead && p.GetIndexParameters().Length == 0);
    foreach (var p in props)
    {
        if (node.Children.Count >= MaxChildCount) break;
        var pv = p.GetValue(value);
        var cn = PropertyChineseNameMap.TryGetValue(p.Name, out var n) ? n : p.Name;
        node.Children.Add(BuildMonitorSubtree(pv, cn, sourceNodeId, depth + 1, visited));
    }
    if (node.Children.Count > 0) return Finalize(node, value);
    // 4) 叶子
    node.IsGroup = false;
    node.DisplayValue = FormatTypedValue(value, value.GetType());
    return node;
}

private static ModuleResultNode Finalize(ModuleResultNode node, object value)
{
    if (node.Children.Count == 0) { node.IsGroup = false; node.DisplayValue = FormatTypedValue(value, value.GetType()); }
    return node;
}
```

`UpdateModuleResults` 运行期分支改为：
```csharp
foreach (var e in group)
    currentParent.Children.Add(BuildMonitorSubtree(e.RuntimeValue, e.DisplayName, nodeId, depth: 0));
```
设计期（`RuntimeValue == null`）走同一方法 → 顶层叶子 `--`，不递归（YAGNI）。

### 技术方案 2：各工具结果类清理（GetPropertyMap 收敛）
- **删除**所有"仅为了树展示而平铺的复合对象子字段 entry"。
- **删除**对应的冗余派生计算属性（如 Blob 的 9 个 `BlobAreas` 等）。
- **保留**真正的一级变量（图像/区域/统计单值/数组对象）。
- 对未实现 `IMonitorable` 的复合类型（如 `BlobResult`），补 `IMonitorable` 实现。
