# 词汇表（数组优先）作为全链路统一类型真相源 — 最终方案设计

## 🔄 改前 → 改后 → 依据（说人话）

**改前（你现在的痛点）**
你的词汇表 `SdkTypeVocabulary` 是一套"数组优先"的统一编码（7 个词目，单值=长度 1 数组，对齐 Halcon tuple 语义）。但 5 条链路各说各话：
- **属性映射**：复杂对象被静默打成 `Collection` 杂项（`ToolResults.cs:613-619`），绑不了全局变量。
- **模块结果树**：数组被拆成 `[0][1]…` 多行（`MainWindowViewModel.cs:4042-4052`），不认词汇表。
- **绑定树**：数组反过来说"可选取第 i 个"（`[i]` 子节点 `:426-453`），复杂对象集合靠反射偷偷平铺成"面积[]"列（`:457-618`），绕过统一契约。
- **工作流引擎**：只看 CLR 类型，转换失败静默跳过（`ParameterResolver.cs:188-193`）。
- **目标参数筛选**：硬编码白名单含已删 `byte`/`char`（`TargetParameterViewModel.cs:470-476`）。

**改后（你点开软件看到什么）**
- 跑完 Blob 检测，**结果树里"面积"是一行 `Double[3]`**（不是 3 行 `[0]~[2]`），点开可看每个值预览。
- "面积[]"在绑定树里能**直接勾选绑到全局变量**——不再需要先手动平铺。
- 工作流上游 `double[]` 绑下游 `double[]` 直接贯通；**类型真对不上时，开发期契约测试就报错**，运行时不该再触发。
- 5 条链路消费**同一份 `GetOutputVariables()` 变量清单**，数组永远被当"一个 N 格标准箱"。

**依据（业界怎么做的）**
- **Halcon HDevelop**：tuple 语义（单值=长度 1 数组），变量窗口按语义类型统一渲染 [tuple 官方文档](https://docs.mvtec.com/hdevelopevo/24.11-preview/content/halcon_script/expressions/ch_language_expressions_tuples.html)、[变量窗口 6.21](http://www.labviewx.com/MVTec/HALCON-23.05-Progress/doc_zh_CN/html/manuals/hdevelop_users_guide/hdevelop_gui_0115.html)。
- **海康 VisionMaster**：全局变量跨流程共享，工具输出经变量绑定 [全局变量与全局模块](https://blog.csdn.net/MVExpert/article/details/125561042)。
- **Cognex VisionPro**：ToolBlock 输入输出端子契约化数据类型 [CogToolBlock 端子详解](https://developer.baidu.com/article/details/3260460)。

## 问题分析（Phase 0）

- **表面需求**：词汇表数组优先，但 5 条链路没适配。
- **根本问题**：**输出契约类型未在设计上归一化到词汇表**——工具可随意吐出词汇表容不下的"裸复杂对象"，下游各自反射分裂类型认知。
- **问题分类**：架构冗余（两套平行类型展开/投影）+ 设计缺陷（类型失配在源头未归一）。
- **架构分配**：最自然归属 = Plugin.SDK 类型契约层（`SdkTypeVocabulary` + `GetOutputVariables`），SSOT 已存在，仅下游未消费。

**当前 bug**：复杂对象/数组在结果树与绑定树表现不一致，工作流静默降级。

**真因分类**：**设计缺陷 + 契约漏洞**（类型认知无统一真相源，且输出契约未强制归一）。

**同类潜伏点**：

**治本点（修正后）**：修复"**输出契约类型未在设计上归一化到词汇表**"这一源头——建立类型契约 + 开发期校验，让"词汇表容不下的类型"在设计期就不可能出现；而非运行时报错兜底。

## 解决方案

### 设计契约（硬约束，取代"运行时报错"）
> 任何工具 `GetPropertyMap()` 声明的输出属性，其 CLR 类型必须且仅须满足其一：
> 1. **词汇表词目**（含数组化：`double[]`/`string`/`IVisionImage`/`IVisionRegion`/`AffineMatrix`…）
> 2. **`IMonitorable` 单对象**（字段可投影为词目）
> 3. **`List<T>` 且 `T:IMonitorable`**（集合，可投影）
>
> 不满足的在设计阶段不允许存在：改类型（如 `double[,]`→`double[]` 展平）/ 实现 `IMonitorable` / 拆字段声明。

### 技术方案
1. **实施第 0 步：输出类型收敛盘点** — 反射遍历所有工具 `GetPropertyMap()` 声明的属性 CLR 类型，产出"设计收敛清单"，对每个裸复杂对象在设计上收敛。
2. **词汇表扩容（SdkTypeVocabulary）**：`ToTypeVocabulary` 增加 `List<T>` 归一分支（取元素类型再归一），确保 `List<string>`→`string[]`→"String"；确认 `IVisionRegion[]`→"Region" 已覆盖。
3. **SSOT 派生升级（ToolResults.GetOutputVariables）**：对 `List<T:IMonitorable>` 属性，产出父容器变量（中性显示名，如"Blob详细"）+ 投影子变量（面积[]/周长[] 等 `double[]`，`GroupName`=父）；**删除 `:613-619` 的 "Collection" 静默分支**——未知类型（非词目、非 IMonitorable）改为派生阶段直接暴露（开发期契约测试必先拦截）。
4. **绑定树改造（DataSourceQueryService）**：`GetNodeOutputProperties` 改为遍历 `GetOutputVariables()` 产出 `AvailableDataSource`；**删除** `[i]` 子节点（:426-453）、反射式 `AddCollectionProjectionColumns`（:457-618）、`GetPropertyValue` 的 `catch{}`（:515-532，改为向上传播）。
5. **结果树改造（MainWindowViewModel）**：`BuildMonitorSubtree`/`FormatTypedValue` 改为基于 `GetOutputVariables()` 的 `OutputVariable`（带 `VariableType`），数组显示"词目[N]"一行 + 预览，不拆 `[i]`；复杂对象集合节点展示 SSOT 投影字段；删纯反射兜底；保留"点开展开为 [0]~[N]"的纯可视化详情（不参与绑定契约）。
6. **目标参数筛选（TargetParameterViewModel）**：删 `IsBasicType` 硬编码白名单（含 byte/char），改 `SdkTypeVocabulary.ToTypeVocabulary(type) != null`。
7. **工作流引擎（ParameterResolver）**：绑定匹配改用 `VariableType` 词目比较（tuple 语义：`double` 与 `double[]` 同归 "Double" 可互绑）；`ConvertValue` 失败**抛 `InvalidOperationException`** 中断（删 :188-193 静默降级）。

### 实施步骤
0. 输出类型收敛盘点 + 收敛裸复杂对象
1. 扩容 `SdkTypeVocabulary.ToTypeVocabulary`（`List<T>` 归一）
2. 升级 `ToolResults.GetOutputVariables`（集合投影派生 + 删 Collection 静默分支）
3. 改造 `DataSourceQueryService`（消费 SSOT + 删 `[i]`/反射投影/`catch{}`）
4. 改造 `MainWindowViewModel` 结果树消费 SSOT
5. 改造 `TargetParameterViewModel` 删 `IsBasicType`
6. 改造 `ParameterResolver` 词目匹配 + 报错优先
7. 契约测试 + 全量构建 + 端到端冒烟
