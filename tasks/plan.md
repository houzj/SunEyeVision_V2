# 主工作区 VM 对照与 ImageSource-Blob 完整链路计划

## Overview

沿 VisionMaster 原件的完整入口和生命周期，对照修复 SunEyeVision 主工作区。第一条生产闭环为 ImageSource → BlobAnalysis，覆盖参数、ROI、执行、结果、持久化、方案重开、取消关闭和资源释放。所有结论以同版本 VM 的源码、模板、资源或运行证据为依据。

## 当前批次：ROI 完整生产链根因收口

本批次不把“按钮可点”作为独立交付。已用最小回归证明本方五个 ROI 形状 ToggleButton 首次绑定时全部被置为不可用，根因是 NativeRoiEditor.RequestCommand 把加载暂态直接暴露为 WPF CanExecute，且命令没有 CanExecuteChanged 通知。按 VM 原厂命令入口语义修正后，按钮状态和矩形绘制命令回归通过。后续必须沿完整链验证帧借用、会话、参数写回、结果重投影、保存重开和关闭释放。

本批次统一链路合同：

ROI 按钮 -> RequestCommand -> PrepareInteraction -> BlobLocalRoiOwner.Activate -> NativeRoiFrameSource.Borrow -> NativeRoiSession -> BeginEditing -> DrawRequested/RoiEditProposal -> input.roi 草稿写回 -> ResultWorkspacePresenter 当前帧重投影 -> 正式执行快照 -> 结果发布 -> 保存重开 -> 取消关闭和租约释放。

每个边界都必须记录成功、无帧、帧退役、取消和提交失败证据。不可绘制时要给出 VM RoiDrawTips 语义的用户反馈，禁止静默返回。

## Architecture Decisions

- 以方案编辑会话作为生命周期边界，参数输入在执行开始时快照传递，运行结果与编辑状态分离。
- ROI、结果显示和持久化使用统一字段身份、资源身份和执行代次，避免界面状态绕过正式合同。
- UI 负责原件化组装和交互，执行层只消费快照，不访问 WPF 控件。
- 先完成 ImageSource → Blob 的垂直链路，再扩展主工作区其他工具，避免局部控件通过冒充完整生态完成。
- 每阶段都保留原件证据、源码改动、构建结果、自动验证和人工验收边界。

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| VM 动态证据缺失 | 可能把本方行为误当原件语义 | 先补同版本源码、模板、资源或运行证据，再实施 |
| ROI 视图与执行字段身份分裂 | 参数能显示但执行不生效 | 统一字段身份、提交代次和快照入口 |
| 持久化只保存界面值 | 重开后状态漂移 | 从方案文件到工作区恢复做完整往返验证 |
| 关闭时仍有活动资源 | 迟到回调和进程退出异常 | 按任务、结果发布、视图、会话顺序排空并验证 |

## 2026-11-15 状态边界重构批次

**原厂证据结论**：VM 的 `imageListCombobox_SelectionChanged` 只更新当前显示对象；自动切换/运行模式属于图像源运行策略；`ModuleResultView.UpdateROI` 和结果视图继续持有上次正式结果，参数/ROI 编辑不重放执行，也不因编辑清空结果层。节点或方案身份切换、关闭释放和下一次正式执行才替换/释放结果发布。

**本批实现**：
- ImageSource 所有正式编辑入口在提交前续租当前已完成结果快照；
- 文档通知处于 ImageSource 接纳窗口时跳过结果发布退役与清空；
- 接纳完成后只刷新配置、缩略图和就绪状态；
- 结果发布仅由正式执行结果替换，身份切换/方案关闭仍按边界清理；
- 探针不进入正式载荷。

**验收矩阵**：自动切换、运行模式、运行勾选、显式缩略图、Blob 参数、ROI 修改均在“不执行”条件下保持上次图像/图形/文本/结果表；重新执行整体替换；切节点、切方案、关闭重开正确清理并重建。

## 2026-11-15 公共执行链常驻化批次

### 目标

按 VM 已确认的服务端常驻、模块预加载和运行请求复用语义，重构本方公共执行链：方案打开后建立方案级运行时；配置版本未变化时复用不可变执行计划、调度器和工具会话；每轮只捕获输入/变量增量并重置运行态；配置、节点、方案或目录身份变化时原子失效并释放。

### 设计合同

- `SolutionRuntime` 是方案编辑会话的唯一执行宿主，拥有执行计划、调度器、节点会话租约和结果发布边界；UI 不进入该对象。
- `ExecutionPlan` 以方案会话、流程结构代次、节点配置身份和运行目录身份组成键；命中时不得重新捕获 GraphState、依赖边、控制边和节点快照。
- 每轮运行只创建 `RunState`、输入/变量快照和结果容器；运行结束后清理 RunState，保留方案级运行时。
- 方案编辑、节点/连线变化、工具目录退役、方案切换和关闭会使计划失效；失效先停止并排空运行，再释放计划和会话。
- 结果发布仍由执行轮次原子替换，编辑和导航不触发执行计划失效；取消、异常和迟到回调不能写入新会话。

### 实施顺序

1. 在 Application/Execution 层建立方案级运行时和执行计划合同，先接入现有 `DocumentSession`，不改 UI。
2. 将 `CaptureRunBatchCore` 拆为“计划命中/构建”和“每轮输入捕获”，保留现有隔离与所有权校验。
3. 将 `DocumentRunBatch` 的单轮 `WorkflowExecutionEngine` 改为运行时持有的可重置调度器，确保并发、取消、连续运行和关闭边界不变。
4. 将 ImageSource/Blob 工具会话接入计划节点租约，按配置身份失效；结果发布继续使用现有快照合同。
5. 增加公共执行链探针，分别记录 plan-hit/plan-build、run-state、input-capture、dispatch、tool-session、result-build、publish 和 retirement。
6. 全量 Release 构建；只做与执行链直接相关的定向验证，人工验收覆盖首次/后续、连续运行、取消、参数修改、节点切换、方案关闭。

### 当前已知风险

- 当前 `workflow-snapshots` 探针包含完整流程图和依赖结构构建，不能只缓存 `ExecutionNodeSnapshot`。
- `engine-build-result` 首轮仍包含结果来源捕获和输出聚合，调度器常驻后必须确认资源租约和结果身份不会跨轮泄漏。
- VM 的服务端动态 RPC 跟踪尚未取得；本批只迁移已由服务配置、反编译入口和本方运行证据共同支持的生命周期语义，不声称协议等价。
